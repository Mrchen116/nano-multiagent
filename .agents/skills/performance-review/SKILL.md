# Performance Review

先明确本次要改善的用户结果、测量边界和必须保持的行为，再选择有解释力的指标。输入包括目标/负载、基线与候选版本、环境和已有测量；设计阶段检查方案，实施阶段检查实际收益，不能混称。

- 沿实际路径定位代价；区分端到端时间、模型活动、等待、重试与并行工作，不相加重叠时长。查询次数、扫描行数、内存峰值等用于解释机制，不自动等于用户收益。
- 在可比较的输入、配置、数据规模与运行环境下对照基线和候选，说明冷/热状态、缓存、样本及波动；补跑以解决具体不确定性，不固定无限 benchmark。已有充分证据可复用。
- 同时核对结果、顺序、权限、生命周期、取消/恢复等本次可能受影响的不变量。不能通过减少必要工作、丢历史或缓存实时授权来制造加速；具体边界以项目契约为准。
- token 区分输入、缓存输入和输出；墙钟时间、工具次数和模型费用分别说明。没有计费或同条件对照时，不推导费用或确定节省比例。

返回测量范围与方法、前后结果、行为证据、归因依据及限制。只有相关目标与不变量均有证据才判通过；缺测量写未验证，单次偶然成功不证明稳定收益。仅报告有依据的瓶颈和回归，不自行改实现、起生产实验或增加交付门禁。
