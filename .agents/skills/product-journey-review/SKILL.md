# Product Journey Review

从用户目标和预期结果组织连续任务，判断真实产品能否完成。输入为本次问题/场景、受审版本、相关 runbook、测试身份与授权、已有证据及缺口；不以实现者成功叙述替代判断。

## 观察方法

- 把相关场景合成有意义的旅程：真实入口 → 操作与关键状态 → 可观察结果 → 必要恢复。只覆盖本次问题，不机械逐条重跑完整产品或客户端矩阵。
- 独立阅读决定性运行产物或亲自执行必要路径，确认真实结果、身份和版本。源码、内部函数返回、单测绿和进程存活都不能代替公开交付。记录已观察行为与尚未确定的原因，不用猜测根因改变判据。
- 复用 caller 准备的隔离环境和可信构建；先确认服务与产物对应受审版本，陈旧或无法证明时才重建相关服务。Nano 运行入口见 [worktree runtime](../../../docs/development/worktree-runtime.md)，适用团队任务使用其中的固定日常模板；不为不涉及团队的局部问题启动整套团队。
- 在专用测试身份与资源中按已有授权执行必要产品写入；可调整隔离临时测试配置，不改受审源码、受版本控制配置、生产现场或扩大外发范围。缺前置报告具体缺口，不自行降低标准。清理自己启动的进程。
- 若本次还需判断信息组织或交互成本，由 caller 组合前端体验能力，共享一次操作与画面；本能力不把功能成功推成体验通过。

## 结果与完成

按问题记录预期、实际路径与观察、证据/限制及 pass/fail/inconclusive；不适用项说明范围依据。期望未出现为 fail，必要观察缺失为 inconclusive，不能按轮次降低标准。

发现问题给出复现条件、用户影响、与改动的关系（direct/suspected-regression/unrelated-existing/unclear）及建议：修实现、修设计或范围外调查。已明确的设计问题可直接建议改设计；原因不清时保留观察交 owner 判真。范围外现象不自动扩大本次需求，也不擅自外发 issue。

阻塞路径或实质妨碍目标的问题必须关闭；可选局部改进与纯偏好分开。覆盖本次所需结果后结束，向 caller 返回证据与结论，不自行新增阶段、写多份报告或 push。已有用户验收和未失效旅程可以保留，必要独立观察不能用作者口头确认替代。
