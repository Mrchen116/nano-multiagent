## 操作权重

**情境。** feat-657 需要两种停用场景：暂时不用一个 Agent，以及在 Work 中发现危险动作后紧急停止。旧 iOS 原型把配置开关、详情/Work 的同义按钮及设计说明拼在一张卡里。审查曾认可，用户否定后才撤回。

**错误判断 → 纠正。** “每个入口都覆盖了功能”被误当作方案完整。修订原型按真实页面分开：配置页一个 Toggle；详情和 Work 各自只有一个对应动作，状态变化时原位变成重新启用或重试；设计解释放在产品区域外。该纠正有独立原型走查记录，不能据此声称原生产品已验证。

10 月 26 日用户又指出真实列表里一排红色停用按钮抢眼。这条反馈证明列表的动作权重有问题，但本案例没有其最终修复效果证据，不能把某个菜单方案标成已验证答案。

**适用边界。** 判断动作在当前任务里的频率与紧迫性。浏览多个对象时，重复的强烈动作可能淹没身份和状态；正在处置风险时，紧急动作应直接可达。不要从“列表按钮太抢眼”推成“危险操作一律隐藏”，也不要从“单页不要重复同义控件”推成“其他使用场景不能有入口”。

**观察办法。** 用正常数量的列表项看第一眼读到什么；进入处理任务的页面，实际找到并执行该动作。比较触发前后是否仍明确是哪个对象、现在什么状态、下一步能做什么。

## 文字删留

**情境。** feat-652 用户要求去掉大按钮、空白和解释性废话。Agent 随后删掉 Feature 的用途说明，还只显示“跟随节点”，让人不知道自己开启了什么、当前到底使用哪种策略。

**错误判断 → 纠正。** “少字就是简洁”没有区分重复信息和决策信息。最终设计明确删除重复用途说明，同时保留特性用途、依赖限制及重要后果；“跟随节点”从真实继承配置展示具体策略，未知时表达未确认。创建和编辑共用这个字段，避免只修用户截图里的页面。

文字对照：`跟随节点` → `跟随节点（实际策略）`；没有可信读数时表达“策略未确认”，不能填一个看似合理的默认值。Feature 的标题若不足以说明开启后的行为，就保留一句有信息量的用途说明，不用大段实现解释。

**适用边界。** 删留依据是这段信息是否影响辨认、选择或理解后果。不要为了复用本例给每个控件补说明，也不要把隐私、依赖、未知状态当装饰删掉。整体精简的任务要看相关创建/编辑入口；局部任务无需扩成全产品改版。

**观察办法。** 不借助源码知识，读者能否解释开启后的变化、当前实际值和未确认之处？检查同一选择在相关入口是否仍表达同样含义。

## 阅读路径

**情境。** feat-589 要从委派位置进入子 Agent 的某次执行。初稿另建简化默认轨迹，把原生明细放到另一入口；后来又把“选中本次执行范围”实现成过滤其余历史。用户两次纠正。

**错误判断 → 纠正。** 新导航能力不自动要求重建阅读主体；聚焦某段也不必删除周边上下文。最终设计保留一个原生派生视图，在完整历史中设置该次执行的选区，范围外淡化，沿原有表格/详情检查；逐级返回保留父级的阅读状态。

**适用边界。** 先确认用户需要定位、比较、筛选还是切换数据集，再选交互。明确要求“只看失败记录”时过滤可以正确；检查一段执行的前因后果时，删掉范围外内容可能破坏任务。既有视图有实质问题时可以改进，不把沿用当绝对要求。

**观察办法。** 从真实发起位置走到目标，检查关键上下文是否仍可读，再返回；验证是否需要重新搜索、恢复滚动位置或猜测被隐藏的信息。仅看到新的跳转按钮不足以证明路径成立。

来源：[feat-589 最终设计与原方案撤销](../../../../docs/changes/archive/feat-589-subagent-trajectory-navigation/design.md)、[实际导航模型](../../../../packages/trajectory-ui/src/client/navigation-model.ts)。本例讨论产品阅读语义，不把该 unit 的特定 UI 分叉许可推广到其他模块。

## 状态与布局

**情境。** feat-645 用户需要短暂的依赖提示。最初做成必须手动关闭的提示，随后改成会自动消失的 Toast，却插在工具列表内：出现时挤走下一项，消失后仍留占位。已有审查只确认“没遮住控件、会消失”，遗漏了这个问题。

**错误判断 → 纠正。** 反馈可见不代表反馈不打断操作。修订为脱离文档流的浮层，出现/消失不改变工具坐标与面板高度；后续还修正了窄画布越界。独立原型走查和布局数据分别记录了这些结果。

**适用边界。** 瞬时确认通常不应挤动正在操作的内容。需要用户解决的字段错误可以留在字段旁，持续状态也可能应占据稳定位置；不要把所有提示都改成自动消失的浮层。浮层还须避免挡住目标、越界或抢走焦点。

**观察办法。** 连续操作并看提示前、显示中、消失后的同一位置；必要时测相邻控件坐标辅助判断。在会挤压内容的宽度重复关键操作，不能用一张静止图证明整个反馈过程。
