# 首文档内容边界

- 用户场景保留意图和使用过程；新功能描述目标体验，内部重构描述需要保持的回归基线。
- 验收用 `### Requirement: …` 和 `#### Scenario: …`，包含 WHEN/THEN，需要前置状态时加 GIVEN。覆盖已确认的正常、失败、边界与空态，不为每项强造无关异常。
- 终端用户验收不写内部函数、日志、协议字段或“调用了某符号”；用户原话中的实现保真要求保留并交给 design 的 `[worker]` 标准。
- bug RCA 区分症状、原因、证据和仍未知的部分。保住原功能意图与不变量；已有可靠调查可直接引用。回归时区分功能最初引入点和坏行为引入 commit，不编造流程责任。
- refactor 写迁移与兼容边界；perf 写有来源、测量条件和目标的 benchmark。
- 有实际依赖或 issue 时写 Relations：Depends on / Blocks / Related / Closes / Refs；没有就省略，不为填表搜索全部 issue。
- 首文档不能暗改已确认范围。需要改变用户决定时带事实和推荐重新对齐。
