### R119.2 发送链路稳态化：成功真实往返，失败明确反馈
- Context:
  - 接手时 `milestone/M119` 已有 `3a6dcb4` / `6c6ff30` / `308b704` 三个提交，但 worktree 还残留未提交调查改动：`src/IM/ws/gateway_handler.py`、`tests/im_service/unit/test_gateway_handler.py`、`tests/im_service/integration/test_gateway_websocket_api.py`。
  - 现象确认：前端已具备草稿保留与失败提示，但当 gateway websocket 已断而连接表尚未清理时，`send_json()` 会直接抛异常，HTTP 入口会退化成 500 风险；同时前端还会把原始 `503 (target_node_id is not connected)` 直接暴露给用户。
- Decision:
  - 后端：在 `GatewayHandler.push_relay_message()` 捕获 broken websocket 的 `RuntimeError/WebSocketDisconnect`，立即 `disconnect()` 并返回 `False`，让消息路由稳定降级为现有 503 + `relay.failed` / `conversation.notice` 事件，而不是冒泡 500。
  - 前端：在 `MessagePane.toErrorMessage()` 将原始 `target_node_id is not connected` 归一为面向用户的 `No relay node is available. Connect an online node and retry.`，保持草稿不丢失。
  - 验证：补一条前端单测锁定 raw 503 文案归一，再用本地 Python Playwright + 真 IM 后端 + websocket responder 跑成功/失败双链路并落截图。
- Rationale:
  - 退出条件要求的是“真实往返稳定 + 失败可解释”；因此要同时修两个层面：一是 broken socket 不能再打穿成 500，二是即便收到 503 也要被前端翻译成用户能执行的提示。
