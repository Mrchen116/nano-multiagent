### R16.1 全局能力收口（`/v1/capabilities` + `/v1/openapi.json`）
- Context:
  - 现状仅有 `GET /v1/health`，缺少蓝图要求的 `GET /v1/capabilities` 与 `GET /v1/openapi.json`。
  - 模型能力来源在 `llm/model_registry.py`，工具能力来源在 `ToolRegistry.list_specs()`，需要统一聚合并暴露 HTTP 入口。
- Decision:
  - 在 `model_registry` 新增可枚举接口：`list_supported_providers` 与 `list_provider_models`。
  - 在 `global_routes` 新增 `build_capabilities_payload`，统一组装 active provider/model、provider->models 能力矩阵与 tools 列表。
  - 新增 `GET /v1/capabilities` 与 `GET /v1/openapi.json`（均鉴权），`health` 保持公开不变。
- Rationale:
  - 能力聚合函数独立化后，unit/contract/integration 可直接复用，避免路由层重复拼装逻辑。
  - `/v1/openapi.json` 直接复用 `request.app.openapi()`，避免维护双份 schema。

### R16.2 HTTP-only 薄 CLI（`sdk.client + cli.main`）
- Context:
  - 仓库内缺失 `sdk/cli` 目录，无法满足“CLI 仅经 HTTP 调用 server”的蓝图约束。
  - 需要在不接触 runtime 内核代码的前提下，补最小可用命令：`health/create-session/send-message`。
- Decision:
  - 新增 `src/nano_multiagent/sdk/client.py`：统一封装 HTTP 请求、鉴权头、request_id 与错误映射。
  - 新增 `src/nano_multiagent/cli/main.py`：`argparse` 薄命令层，仅调用 `ServerClient`，输出 JSON。
  - 新增 async transport bridge，兼容 `httpx.ASGITransport` 在同步 CLI 测试链路下的调用与关闭。
- Rationale:
  - 将协议细节收敛在 SDK，CLI 只负责参数解析与结果渲染，可直接满足 HTTP-only 边界与可测试性要求。
  - 使用 `run_cli(..., client_factory=...)` 便于 integration 场景注入 app，避免引入运行中 server 进程依赖。
- Evidence:
  - Tests:
    - Red: `pytest -q tests/unit/test_sdk_client.py tests/unit/test_cli_main.py tests/contract/test_cli_http_only_contract.py tests/integration/test_cli_http_flow_integration.py` -> `ModuleNotFoundError: nano_multiagent.sdk/cli`
    - Green: 同命令 -> `7 passed`
    - Gate: `pytest -q` -> `221 passed, 3 skipped`
  - Entry:
    - CLI `health/create-session/send-message` 均输出 JSON，`send-message` 支持 `--session-id` 或 `NANO_MULTIAGENT_SESSION_ID`。
    - contract 测试确认 `cli/sdk` 源码不包含 `agent.runtime` 直连 import。
