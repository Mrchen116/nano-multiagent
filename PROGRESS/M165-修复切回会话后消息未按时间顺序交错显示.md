## 实施记录
### R1 排序语义收口
- Context: 现有 `mergeConversationDetail()` 会把历史接口返回的 persisted messages 与 query cache 中的 SSE/local messages 做去重合并，但 `mergeMessages()/upsertMessage()` 只保留插入顺序，不会在合并后再按 `created_at` 统一排序。
- Decision: 在 `src/IM/frontend/src/features/chat/chat-workspace-page.tsx` 提炼 `sortMessagesChronologically()` 与 `normalizeConversationDetail()`，并让 `upsertMessage()`、`mergeMessages()`、`createConversationPlaceholder()`、`mergeConversationDetail()` 全部收口到同一稳定排序语义。
- Rationale: 历史 reload 时，服务端通常只返回持久化消息，而先前缓存里的 synthetic agent progress/report message 仍会被 merge 回来；只有把“去重”和“按时间稳定排序”绑定在同一 helper 上，才能避免再次进入会话时按 sender 分堆。
- Evidence:
  - 新增测试：`chat-workspace-page.test.ts` 中 `keeps cached relay messages interleaved when reloading persisted history`。
  - 断言点：合并 persisted user history 与 cached synthetic agent message 后，消息顺序稳定为 `user -> agent -> user`。

### R2 会话重载渲染回归
- Context: 用户实际反馈发生在“进入会话 -> 收到 agent 进度/回复 -> 切走 -> 再进入”路径，而不是单次初次加载。
- Decision: 在 `chat-workspace-page.test.ts` 增加路由级回归测试，使用真实 `QueryClient` + `RouterProvider` 模拟进入会话、接收 `relay.report`、离开到 `/chat`、再次进入 `/chat/conv-1`。
- Rationale: 直接覆盖 React Query cache 与路由复进入路径，才能证明历史加载与本地/SSE 状态合并后仍保持同一排序语义。
- Evidence:
  - 新增测试：`renders re-entered conversations in chronological order after history and SSE state merge`。
  - 断言点：DOM 中 `.whitespace-pre-wrap` 消息内容顺序稳定为 `First user turn -> Agent reply between the two user turns -> Second user turn`，重进会话后仍不变。
