# M128 - 离线与不可用失败体验统一

## Goal
统一 Web IM 在 unbound、offline、unavailable 三种失败状态下的产品级反馈，让用户在浏览器内得到一致、可执行、无需依赖终端日志的说明。

## Scope
- Web IM composer 的失败态文案与展示统一。
- unbound / offline 预阻断与 unavailable 发送失败反馈统一到同一产品心智。
- README、operator runbook、frontend README 对齐同一失败行为。
- 通过前端测试与浏览器可见证据记录至少一个 unavailable 场景。

## Steps
1. 审查当前 Web IM 对 unbound、offline、unavailable 的 helper text / placeholder / send error 分裂点。
2. 收敛 `resolveSendAvailability` 与发送失败文案，定义统一 failure banner 语义。
3. 更新 MessagePane，在 composer 上方呈现统一的 `Chat unavailable` 可执行卡片，并保留 unavailable 重试草稿。
4. 更新 Vitest 覆盖 unbound、offline、unavailable 三类可见行为。
5. 更新 README、`docs/operator-runbook.md`、`src/IM/frontend/README.md`，确保文档只描述预禁用 composer + 同步失败卡片行为。
6. 记录 M128 验收证据并完成里程碑提交。

## Exit Criteria Mapping
- Exit 1: 前端测试覆盖 unbound/offline/unavailable 可见反馈，composer 禁用与失败提示一致。
- Exit 2: 三份用户文档统一描述 `Chat unavailable` 体验。
- Exit 3: `ACCEPTANCE/M128-browser-evidence.md` 记录至少一个 unavailable 浏览器可见场景与执行命令。
- Exit 4: 文案明确告诉用户下一步动作，不要求查看终端日志。
