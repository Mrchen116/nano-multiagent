## 目标
让 Web IM 在“消息已发送、Agent 正在处理、处理失败、恢复重试”这些关键阶段使用用户可理解的表达，并给出明确的下一步动作，同时保持 SSE / 实时事件链路不变。

## 已知问题
1. `delivery_status` 虽然已有标签映射，但仍偏底层术语，缺少解释性上下文。
2. Agent 处理失败与用户发送失败在消息区里缺少区分，用户难以判断该重发消息还是重试请求。
3. 现有恢复动作主要停留在 composer banner，消息气泡本身缺少“发生了什么 / 下一步做什么”的说明。
4. 需要确保这类 UX 打磨不破坏现有实时事件归并与 usage 刷新链路。

## Scope
- 提升消息气泡状态 copy 的可理解度与分阶段解释。
- 为用户发送失败与 Agent 处理失败补充不同的恢复文案。
- 保持既有 SSE 事件归并、实时刷新与 usage invalidation 逻辑。
- 补前端测试覆盖关键状态与恢复路径。
- 更新 `TASKS/PROGRESS` 并记录验证结果与 commit。
