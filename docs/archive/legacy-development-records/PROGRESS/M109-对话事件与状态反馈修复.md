## 2. 最终结论
1. `node.delivery_receipt` 与 `node.report` 已桥接到 `/im/v1/conversations/{id}/events`，会话 SSE 不再只有 `message.sent/message.delivered` 两态。
2. 用户可见进度状态现已暴露为 `accepted / processing / completed / failed`，并通过 `progress_state` + `semantic` 字段说明含义。
3. `message.delivered` 不再在消息创建时提前写入；现在只在真实处理完成时落库，语义补充为 `agent_run_completed`。
4. 节点断开导致的 relay 失败会写入 `relay.failed` 与 `conversation.notice`，并包含可执行 guidance，用户可在会话上下文内理解失败原因。
5. 本次未编辑 `data/dev-tasks.json`，符合限制。

## 3. Roadpoint 记录

### R1 修正 conversation SSE 进度事件语义
- Context:
  - M106 已确认真实产品缺口：receipt/report 只停留在协议层和内存快照里，没有进 conversation SSE。
  - 旧实现还在消息创建时立即落 `message.delivered`，对用户造成“已处理完成”的误导。
- Decision:
  - 保留 `message.sent` 表示 IM 持久化完成。
  - 在 `GatewayHandler` 中把 `node.delivery_receipt` 映射为 `relay.accepted / relay.completed / relay.failed`，把 `node.report` 映射为处理中事件。
  - 仅在 `delivery_receipt=completed` 时追加 `message.delivered` 并更新消息 `delivery_status=completed`。
- Rationale:
  - 这样能把“持久化成功”“Gateway 接单”“处理中”“完成/失败”拆开，符合 M106 批判里要求的用户心智模型。
- Evidence:
  - Tests: `PYTHONPATH=src pytest -q tests/acceptance/test_im_gateway_real_acceptance.py tests/im_service/integration/test_gateway_websocket_api.py` → `5 passed in 0.81s`
  - Entry: acceptance 现在断言事件序列为 `message.sent -> relay.accepted -> relay.processing -> relay.completed -> message.delivered`。
  - Entry: `message.delivered` 事件 payload 带 `progress_state=completed`、`semantic=agent_run_completed`。
- Rollback:
  - 可回退到本 milestone 开始前的 `f3e2f69`，或回退到仅测试失败的红态提交后重做。
- Commits: C1=未单独拆分，C2=本 milestone 实现提交，C3=本 milestone 文档提交
- Next:
  - 若后续补前端，可直接消费 `progress_state/semantic/guidance` 渲染消息状态线。

### R2 补齐会话上下文失败反馈
- Context:
  - M106 指出 `target_node_id` 未连接时只有 HTTP 503，没有会话内失败解释。
  - 失败反馈需要在用户已发送消息的上下文里可见，而不是停留在 API 错误层。
- Decision:
  - 在 `create_message` 的 dispatch 失败分支调用 `gateway_handler.record_relay_failure(...)`。
  - 该路径持久化 `relay.failed` 与 `conversation.notice`，并写入 guidance：`检查目标节点连接状态后重试，或切换到在线节点。`
  - 同时把对应消息 `delivery_status` 更新为 `failed`。
- Rationale:
  - 这样即使前端只消费 SSE，也能把失败与原消息绑定，支持后续做失败卡片、重试按钮、节点切换提示。
- Evidence:
  - Tests: 同上 focused gate 全绿。
  - Entry: `tests/im_service/integration/test_gateway_websocket_api.py::test_message_post_to_disconnected_node_persists_actionable_failure_events` 断言 `relay.failed`、`conversation.notice`、`progress_state=failed` 与 guidance 全部存在。
- Rollback:
  - 若失败反馈语义需重做，可保留成功路径桥接逻辑，仅回退 disconnected-node failure branch。
- Commits: C1=未单独拆分，C2=本 milestone 实现提交，C3=本 milestone 文档提交
- Next:
  - 后续可继续补 `node.report(status=failed)` 的 richer guidance 和节点诊断链接。
