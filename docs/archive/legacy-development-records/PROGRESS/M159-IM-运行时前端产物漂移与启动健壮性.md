## 根因判断
- IM 服务之前把 frontend dist 解析为单一路径；一旦 `IM_FRONTEND_DIST_DIR` 或显式传入路径指向某个 milestone worktree 的 `src/IM/frontend/dist`，该路径会在 app 初始化时被当作唯一前端壳来源。
- 当历史 worktree 被删除后，这个路径会变成悬空目录；此前入口安装逻辑仍继续使用该路径拼接 `index.html` / `favicon.svg` / `assets`，导致 `/` 或 `/chat` 无法再拿到有效壳文件，运行期表现为首页失效。
- 问题本质不是某个单一 milestone 路径写错，而是运行时缺少“当前有效仓内 dist / 回退策略”的二级解析模型。

## 执行策略
1. 先在测试侧补上 frontend dist candidate 与 stale dist 回退场景，锁住回归面。
2. 再把 IM 前端入口改为按请求时解析首个可用 dist 文件，而不是在启动时把旧 worktree 路径永久绑定死。
3. 最后跑聚焦测试，记录证据与回滚点。

## 进度

### R1 根因建模与候选链设计
- Context:
  - `_resolve_frontend_dist_dir()` 只返回单一路径，不足以覆盖“旧 worktree 已删、当前仓仍有 dist”的真实运行场景。
- Decision:
  - 在 `src/IM/app.py` 中新增 `_discover_repo_root()`、`_resolve_frontend_dist_candidates()` 与路径归一化逻辑。
  - 候选顺序定为：显式参数 -> `IM_FRONTEND_DIST_DIR` -> 当前模块旁 `frontend/dist` -> 当前 repo root 下 `src/IM/frontend/dist`。
- Rationale:
  - 保留显式配置优先级，但不再把它当作唯一真相；当前仓内可交付 dist 应始终成为有效回退来源。
- Evidence:
  - `src/IM/app.py`
  - `tests/im_service/unit/test_app_factory.py`

### R2 入口解析按请求时动态回退
- Context:
  - 旧实现对 `index.html` / `favicon.svg` / `assets` 使用启动时快照；worktree 后续被清理时无法恢复。
- Decision:
  - 入口响应改为每次请求动态查找首个存在的 `index.html`。
  - `favicon.svg` 与 `/assets/*` 改为统一走候选链解析，而不是只 mount 单一 assets 目录。
  - 保留所有 dist 都缺失时的 307 dev-server fallback。
- Rationale:
  - 这样即便主路径在 IM 进程存活期间失效，只要当前仓还有有效 dist，`/` 与 `/chat` 仍可稳定打开。
- Evidence:
