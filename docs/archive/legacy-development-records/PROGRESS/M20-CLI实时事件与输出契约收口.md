### R20.2 REPL 默认 async events 实时展示（含去重与 run_id 过滤）
- Context:
  - 需在不改内核前提下，让 REPL 默认可视化 run/tool/text 中间事件，并保证不会串入其它 run 的历史事件。
  - `ServerClient` 原先只支持同步 `send_message`，缺少 async run + SSE 事件消费能力。
- Decision:
  - 在 `http_client` 增加 `send_message_async/get_run/stream_session_events`，并在客户端解析 session SSE。
  - 在 `commands.py` 新增 REPL 异步发送路径：
    - 默认优先 async（若 client 不具备 async 能力则降级同步，兼容旧 stub）；
    - 按 `event_id` 去重，按 `run_id` 过滤，只展示当前消息对应 run 的事件；
    - 输出 `run/tool/text` 预览，并汇总 text_delta 生成最终 assistant 消息 payload。
  - 保持单命令模式不变，仍输出单 JSON。
- Rationale:
  - 通过客户端轮询 run + session events，可以在 CLI 层收口实时展示，不触碰 runtime/server 内核逻辑。
  - 去重与 run_id 过滤可避免 SSE 历史回放造成“重复打印/串线”。
- Evidence:
  - Tests:
    - Red: 
      - `PYTHONPATH=src pytest -q tests/unit/test_cli_main.py -k "uses_async_events_with_run_filter_and_dedup"` -> failed
      - `PYTHONPATH=src pytest -q tests/integration/test_cli_http_flow_integration.py -k "streams_async_run_tool_and_text_events"` -> failed
    - Gate: `PYTHONPATH=src pytest -q tests/unit/test_cli_main.py tests/unit/test_sdk_client.py tests/unit/test_cli_managed_server.py tests/integration/test_cli_http_flow_integration.py tests/contract/test_cli_http_only_contract.py` -> `47 passed`
  - Entry:
    - REPL 可展示 `[run ...] status=...`、`[tool ...] start/output`、`[text] ...`；
    - tool 输出优先展示 `output.text` 预览；
    - 单命令 `send-message` 输出契约保持纯 JSON。

### R20.3 CLI 事件消费容错与回归加固
- Context:
  - R20.2 后失败 run 报错已可见，但错误文本不含 run_id，排障时需要人工从事件行关联，定位成本高。
  - 需确保失败路径仍给出 timeout 建议且 REPL 可继续交互。
- Decision:
  - 失败 run 报错统一补充 `run_id=<...>` 前缀，保留原错误 payload 文本（含 code/message/root_cause）。
  - 新增 unit + integration 回归：
    - unit 断言失败输出含 run_id 与 timeout 建议；
    - integration 断言真实 HTTP 链路下失败消息仍包含 run_id + root_cause。
- Rationale:
  - 将 run_id 放入错误正文，可直接与服务端日志/事件流关联，减少诊断往返。
  - 保留原错误 payload，避免丢失上游失败细节。
