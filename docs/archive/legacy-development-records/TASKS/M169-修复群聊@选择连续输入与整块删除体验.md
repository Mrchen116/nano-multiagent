# M169 Task — 修复群聊@选择连续输入与整块删除体验

- 已确认约束：仅在该 worktree 实施修复；不修改 `data/dev-tasks.json`
- 用户最新真实缺陷：
  - 在群聊 composer 中，先输入普通文字再输入 `@` 时，Agent 选择菜单不再出现。
  - 选择某个 Agent mention 后，如果想删除该 mention，只能逐字符回删，不能按一个整体 token 删除。

## 目标
修复 Web IM 群聊 composer 的 mention 交互：用户在已有前置文本后继续输入 `@` 时仍能稳定弹出并筛选 Agent 候选；已插入的 mention token 在回删时按整体删除，达到商业产品级编辑体验。

## 明确问题
1. 当前 mention query 识别只覆盖有限输入态，连续正文 + `@` 的场景没有稳定保留 picker 交互。
2. 当前 composer 把 mention 只当普通字符串，回删时没有 token 级删除语义。
3. 现有测试只覆盖开头输入 `@a` 和基本选择，没覆盖正文后 mention、二次 mention、token 整块删除。

## Scope
- 修复群聊 composer 的 mention query / picker 打开逻辑，兼容正文后输入 `@`。
- 为已插入 mention token 增加回删时的整块删除语义。
- 补充前端测试，覆盖正文后 mention、选择后继续输入、Backspace 整块删除。
- 更新 `TASKS/M169-*.md` 与 `PROGRESS/M169-*.md`，记录证据与回滚点。

## 非目标
- 不修改 `data/dev-tasks.json`。
- 不改动后端 mention 规范化或 gateway 路由逻辑。
- 不引入新的富文本编辑器抽象。
