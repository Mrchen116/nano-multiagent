# IM web-chat-ux Specification (delta for bugfix-549)

## ADDED Requirements

### Requirement: Web IM 未发送输入按会话隔离

Web IM SHALL 为每个会话保留各自一份尚未发送的输入框内容，包括文字、待发附件，以及仍开着的 `@mention` / slash 状态。切换到没写过的会话时输入框是空的；切回原会话才恢复该会话自己的未发送内容。刷新或关闭页面后不要求恢复。

#### Scenario: 切到未写过的会话时输入框为空
- **GIVEN** 终端用户在会话 A 的输入框写了还没发的文字或挂了待发附件
- **WHEN** 用户打开另一个从未写过的会话 B
- **THEN** B 的输入框是空的，也没有 A 的待发附件

#### Scenario: 切回原会话时恢复未发送内容
- **GIVEN** 终端用户在会话 A 写了还没发的内容后打开了会话 B
- **WHEN** 用户再打开会话 A
- **THEN** A 的输入框仍是刚才那份未发送文字和待发附件
- **AND** 若用户在 B 另写了一份，两份互不影响

#### Scenario: 移动端回到会话列表再进入仍按会话恢复
- **GIVEN** 终端用户在移动端会话 A 写了还没发的内容
- **WHEN** 用户返回会话列表后再进入会话 A
- **THEN** 输入框仍是刚才那份未发送内容

#### Scenario: 发送结果只影响提交的那一会话
- **WHEN** 某一会话发送成功
- **THEN** 只清空该会话自己的未发送内容
- **AND** 发送失败时该会话的文字和附件仍留在原处，方便就地重试

#### Scenario: 蒸馏预填只进入目标会话
- **WHEN** 蒸馏成功并为新的执行会话预填 prompt
- **THEN** 预填进入该目标会话的输入框，不写入其他会话正在编辑的内容
