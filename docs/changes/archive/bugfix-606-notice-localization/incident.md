# bugfix-606: 实时自进化通知按所选语言显示

## 原始报告与确认

> 另一问题是为啥中文+英文，而不是按当前选的语言？

用户截图同屏出现“· 后台自进化：记忆已更新”与“· background self-evolution review: skills updated”。

> 所以对应的修复是
>
> 1. 私聊也发送前复核
> 2. 不中英文混用
>
> 分别用快速修复的方式完成。

第一项独立记录为 bugfix-605；本项采用用户明确选择的快速开发方式。

## 现象与根因

2026-10-14 生产会话中，两条通知在数据库里均有完整 system_notice。首次 message.created 却没有该元数据；后端随后补发 message.reconciled，而前端重建消息遗漏 system_notice。历史加载可本地化，实时消息退回英文存储正文，造成同屏混用。

## 目标与边界

后台自进化 system 行无论首次实时到达、重放、刷新还是语言切换，均按当前界面语言显示，保留更新对象和产生时来源快照。普通历史 system 正文仍按原内容显示；不翻译 Agent 正文，不改飞书通知语言契约。隔离浏览器又观察到左侧摘要显示英文，故一并让该通知摘要使用同一当前语言。

## 验证与状态

保护两个不同失败 seam：真实 IM 进程的首次 WS 事件与幂等持久快照；前端完整 reconciled 快照的字段保留。复用既有 notice 组件的中英、群/单聊、语言切换与历史 fallback 测试。修复前，新增服务端场景在首次事件缺失元数据处失败，前端既有快照测试扩展在元数据丢失处失败。

自动化检查、浏览器检查和独立审查记录见 design.md 与 code-review.md。2026-10-14，用户查看候选后确认：“这两个都可以合入。”据此记录快速开发验收通过并授权合入；该确认不包含生产部署。
