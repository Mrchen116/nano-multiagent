# im/conversations-messages Specification delta

## ADDED Requirements

### Requirement: Agent 协作私聊可发现、可只读回看

#### Scenario: 已有和新会话
- **WHEN** 双方 owner 查询列表、历史或接收实时更新
- **THEN** 同一协作只出现一次，已有历史无需重建，消息保留实际作者。

#### Scenario: 观察不影响通信
- **WHEN** owner 查看或离开协作私聊
- **THEN** 不新增成员、消息或运行，两个 Agent 原有通信继续。


## MODIFIED Requirements

### Requirement: Agent 私聊的投递记录不授予管理者聊天访问权
Agent 私聊的投递回执不授予成员资格。原聊天允许实际成员及双方符合账号、空间和实际归属条件的真人 owner 读取；观察者不能写入。全局 Work 的已记录内容仍按工作视图契约展示。

#### Scenario: 工作记录链接到 Agent 私聊
- **WHEN** owner 从工作记录打开自己 Agent 与另一个 Agent 的同空间私聊
- **THEN** 有观察资格时可读取同一历史，但不成为成员；无观察资格的账号即使持有回执 ID 仍返回 404。

#### Scenario: 复用旧的随机归属私聊
- **GIVEN** 旧私聊恰含两个身份与实际 owner 可核实的同空间 Agent
- **WHEN** 有资格的 owner 刷新聊天列表
- **THEN** 可读取原 conversation id 和已有消息，无需重新发言、重建或加入真人成员；不从旧 conversation owner 推断观察资格。


### Requirement: IM 托管聊天附件按会话成员关系读取

普通新上传和 Agent 图片均是受保护聊天资源；URL 不授予读取资格。IM 自身托管的旧公开上传在部署时按文档一次性转换其原消息关联与引用，新版本只提供目标格式的资源服务。

#### Scenario: 普通图片与文件上传
- **GIVEN** 用户已参与一个聊天
- **WHEN** 用户上传普通图片或文件并发送消息
- **THEN** 具有当前会话读取资格者可正常预览和下载；公开群对有效公司成员可读，私密群和普通私聊仅成员可读，恰含两个同空间 Agent 的私聊也允许双方有效 owner 按统一观察资格读取，未登录或无读取资格者持相同 URL 不能读取；全局 Work 可见不改变来源附件资格。

#### Scenario: 旧公开附件经部署转换后继续回看
- **GIVEN** 旧消息保存了本 IM 的公开上传 URL
- **WHEN** 部署 agent 按迁移文档转换历史引用并升级，有读取资格与无读取资格者分别打开同一历史附件
- **THEN** 有资格者从原聊天的新受保护引用读取同一字节，无资格者无法读取；旧关联文件不丢失，没有消息关联的历史文件不再公开。
- **AND** 单独保存的旧 `/im/uploads` URL 不再提供文件、别名或重定向服务。

#### Scenario: 引用与 fork 不产生访问旁路
- **GIVEN** 用户持有自己无权读取的聊天附件 URL
- **WHEN** 尝试将该 URL 关联到自己的会话
- **THEN** 不会因此取得附件访问权；有来源访问权的合法 fork 则保留独立附件关联，删除源聊天不破坏 fork 回看。


### Requirement: 私聊提供会话菜单

#### Scenario: 从菜单访问会话操作
- **WHEN** 具有成员写入资格的用户在桌面或手机打开私聊顶部的会话菜单
- **THEN** 可选择重命名，并可继续进入原有 Agent 配置（该会话有对应 Agent 时）


### Requirement: 私聊可以按会话修改标题

#### Scenario: 修改已有私聊名称
- **GIVEN** 具有成员写入资格的用户打开一条自己可访问的私聊
- **WHEN** 用户修改会话名并保存
- **THEN** 聊天列表与聊天顶部展示新名，刷新后仍保留
- **AND** 消息记录和该会话的继续聊天能力保持

#### Scenario: 外部私聊后续同步保留手动改名
- **GIVEN** 用户已在 IM 中为外部渠道映射的私聊修改会话名
- **WHEN** 外部渠道后续消息再次同步到这条私聊
- **THEN** 用户设置的会话名保持，消息继续正常显示

#### Scenario: 同一 Agent 的其他会话保持原名
- **GIVEN** 用户和同一个 Agent 有两条私聊
- **WHEN** 用户修改其中一条的会话名
- **THEN** 另一条会话名和 Agent 名称不变

#### Scenario: 取消或提交空名称
- **WHEN** 用户取消改名或输入纯空白
- **THEN** 原标题保留；纯空白不能保存

#### Scenario: 保存失败可重试
- **WHEN** 保存会话名失败
- **THEN** 显示失败反馈并保留输入供重试，不把未保存的名字展示为已生效
