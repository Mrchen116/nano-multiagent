## 已确认范围

用户确认恢复已对齐的 CC 上下文投影，并以固定 Codex 上游完整机制为依据核对移植。只保留 Nano 真实消息入口、身份来源、工具与执行环境所必需的适配，不以移植之名增加自定义授权机制。

CC 的必要消息适配是：用户原话通过 Inbox 工具结果进入会话，审核需保留实际读到的该结果及可信来源；实际发送回执用于区分提议已送达与仅被受理。普通工具返回正文仍按 CC 处理，当前有效历史与压缩边界不改变。不是把审核规则 prompt 替换为 Inbox 内容。

PA 额外的外部请求检查和非主人私聊的外发披露检查，与普通工具审批职责独立。保留这些现有检查、可信本人私聊豁免及 observer 背景边界，不因恢复 CC/Codex 而将其删除、关闭或并入工具审批。

Agent 解读：先撤掉普通工具审批独立拉取全库授权证据的行为，核对两套策略与各自固定参考的差异；未经证明的实现等价不能以现有绿测或同名 prompt 代替。这里的保真指机制和判定语义，DSH 公开接口上的实现语言与真实宿主能力需作最小映射。

## 影响与根因

普通全局/单聊天审核没有这条 PA 专属注入。PA 的安全工具及可信主人消息可能继续成功，需要分类器的普通动作却不可用，造成“能聊天但不能办事”。

`policy/approval.ts` 为普通受审动作主动调用 `pa.authorization`。CC 在 transcript 追加完整包；Codex 将它放入必须完整保留的 planned_action，因此历史预算恢复也无法解决这个额外包过大的问题。实际生产只验证了 CC 失败，Codex 影响有当前代码路径依据。

feat-616 新增独立授权通道，后改为原始主人私聊；bugfix-621 扩展飞书主人；feat-623 扩展为所有可访问主人原文及所涉聊天完整历史。设计和测试着重来源、授权变更与原文存在性，缺少对主会话压缩边界和最终审核请求的检验。详见 [调查复盘](../feat-623-pa-message-context/retro-pipeline-rootcause.md)。

## 修复方向与非目标

- 普通工具审批只消费当前有效执行上下文与明确的必要宿主事实；不另外捞取全库授权，不重新注入已压缩的历史。
- CC 回到已确认的规则、投影、两阶段与失败分流；Codex 按 feat-615 固定上游核对完整机制，记录每项必须保留的适配及依据。
- 保留 PA 独立入站/出站检查与原业务约束，不能因其中存在证据需求而污染工具审批输入。
- 不通过换模型、增大声明窗口、关闭审批、重试相同超长包或新增摘要/授权记忆服务处理。
- 不包含生产部署、重启、修改用户 Agent 策略，以及替用户补写日记或创建日历。
- 不扩大为 PA 独立消息审查的策略重写；如其现有证据链另有问题，明确报告，不用工具审批修复冒充已解决。

## 验收标准

### Requirement: 长期 PA 历史不使普通工具审批超限

#### Scenario: 小动作与大量库内历史
- **GIVEN** PA 有长期跨聊天记录，当前有效会话和待执行动作能够放入审核窗口
- **WHEN** 执行已获授权的普通文件操作或命令
- **THEN** 不因重新加载库内历史导致审核不可用；审核使用当前实际可见授权、来源与动作进行判定。

#### Scenario: 压缩后的工作延续
- **WHEN** 主会话已压缩并继续执行受审动作
- **THEN** 审核沿用有效摘要与后续输入，不从数据库重放压缩前原文；证据确实不足时遵循所选上游策略，不虚构授权。

### Requirement: CC 保留必要 Inbox 适配

#### Scenario: Inbox 原话与实际发送
- **WHEN** 主人通过 Inbox 交办或回复一个已发送提议
- **THEN** CC 审核可见实际读取的原话、发送者、聊天与真实投递状态；工具结果中的身份自称不成为真人授权，恢复历史不升级为新授权。

### Requirement: Codex 保持固定上游机制

#### Scenario: 连续动作与预算压力
- **WHEN** 选择 Codex 并连续执行动作、发生父上下文更新或审核预算不足
- **THEN** 按固定上游机制处理证据保留、审查复用、调查与恢复；不能因为 Nano 额外全量授权包而让有界历史策略失效。

### Requirement: PA 消息安全检查保持独立

#### Scenario: 外部直接请求与观察背景
- **WHEN** 非主人直接向 PA 提出请求，或 PA 仅观察主人与他人的交流
- **THEN** 前者继续经过现有注入/套取信息检查，后者继续作为不可信背景，不逐条当作 PA 请求进行检查或自动发拒绝警告。

#### Scenario: 私人工作与对外披露
- **WHEN** PA 执行私人工作、向真实主人私聊回复，或向其他人/群发送内容
- **THEN** 私人工作遵循普通工具审批，真实主人私聊保持既有免披露复审边界，其他受众继续经过独立披露检查；工具审批结果不能替代披露结论。
