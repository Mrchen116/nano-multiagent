# bugfix-640: PA 披露审核复用有效上下文

## Relations

- Related: feat-616、feat-623、bugfix-626（PR #375）。

## 原始报告与澄清

用户对方案的决定：

> 我觉得有点难搞，我倾向于复用原本的codex普通工具审查的机制的玩法，直接取PA的上下文（里面自然有他去查看对应群聊的记录，以及我的授权原话），补充上你这里的“目标受众”，以及把规则变成本审核设计的规则，是不是就基本等价，又简单

用户授权实施与验收：

> 好，就按这个方案，把需要改的地方和规则整理成设计文档，明确哪些直接复用 Codex、哪些做最小适配。设计好，开始实现，实现完要用本真实聊天在测试服务做验证。

已确认：沿用 PA 实际有效上下文和历史恢复；复用现有 Codex 普通工具审核的会话、增量和预算；补充服务端受众；替换披露规则。不要另建授权记忆、数据库检索链或执行运行时。文档使用简单、明确的中文。

## 现象与复现

2026-10-23，主人在 PA 私聊先要求推荐处理方法，再说“替我在群里回复下”，最终明确“直接放行吧，你帮我去发”。PA 准备向研发群回复已讨论的受限清理方案。完整与缩短版本均未发出。

生产 Mini 基线 `e54d7d2d84495747a3eba1809a0195e53b77db0c`；最后一次操作返回 `unavailable`，原因为 `Complete review evidence exceeds the reviewer context window`，无消息回执。只读取生产记录，未改生产状态。

待发正文 220 字符；IM evidence 5,475,904 字符，其中 authorization 5,339,127 字符：512 条主人消息、154 条 guard 消息及 53 个会话的完整历史。单个无关会话占 3,589,281 字符。已有估算 1,368,983 tokens 尚未包含运行上下文和策略；审核模型窗口为 258,400 tokens。缩短正文不能解决证据体积。

## 影响范围

长期使用 PA 后，对外消息和共享任务可能在调用审核模型前失败。主人已经明确授权也无法完成。主人私人回复不受该披露检查影响。本次观察没有未授权发送、重复发送或数据损坏。

## 根因分析（RCA）

IM `PersonalActions.prepare` 收集全部已读消息、全部先前披露，并调用 `PersonalAgents.authorization`。后者收集所有可访问主人消息，再展开相关会话的全部历史。PA 还追加运行时有效上下文。独立审核一次性发送整个 JSON，超窗直接失败。

这条证据链没有复用普通 Codex 审核的增量会话和预算。feat-623 扩大了历史证据；PR #375 只移除了普通工具审核中的数据库授权历史，独立披露审核仍保留它。之前的验证未覆盖长期使用积累的大库和真实外发。

## 范围与修复方向

修改 IM 动作证据、PA 到运行时的审核接线、DSH 内现有 Codex 审核适配。复用现有准备、审核、提交、回执协议。输入风险分类不变。无前端改动，不部署生产，不执行真实聊天中的清理指令。

### Requirement: 已授权的群回复可以完成
#### Scenario: 真实聊天重放
- **WHEN** 在隔离测试服务重放本次建议、群上下文及主人明确代发授权
- **THEN** PA 将符合已讨论约束的回复发送到测试目标群，产生真实消息回执，主人可以得知发送结果。
- **AND** 大量无关历史不再使这次审核超窗；同一发送重试不重复发布。

### Requirement: 披露边界继续有效
#### Scenario: 超出授权与未知受众
- **WHEN** 待发内容含未授权私有信息，或目标受众无法确认
- **THEN** 内容不发出；主人得到具体原因或必要的新授权问题。
#### Scenario: 上下文恢复
- **WHEN** PA 换窗后继续任务
- **THEN** 按正常历史恢复取回原始授权和相关背景；摘要、记忆、他人自称授权不能独立放行，原始证据不足时不发送。
#### Scenario: 审核期间发生变化
- **WHEN** 主人新增约束、受众改变、来源权限改变或 payload 改变
- **THEN** 旧审核不能直接提交；需要以当前事实重新核对。
