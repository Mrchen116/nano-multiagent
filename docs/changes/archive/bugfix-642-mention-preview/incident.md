# bugfix-642: 会话预览中的第二个 mention 显示原始标签

## 原始报告

用户：
> 第二个mention要显示啊，前端bug

随后选择：
> 走快修

附件：`codex-clipboard-befc3094-3146-45cb-847a-e9d3690b100a.png`（本次会话附件，不提交截图）。截图中正文正常显示两个 mention，会话列表显示第一个人名和第二个原始标签。

## 现象与根因

当两个 mention 的 wire 文本超过 120 字符时，IM 写入的 `last_message_preview` 在第二个标签内截断。前端只能识别完整标签，无法从被裁掉的 target_id 恢复人名。`messaging.ts` 的写入截断可追溯到 `ebd3411e44`；既有 sidebar 测试的两个短 ID 未触及这一边界。

预览本应是可阅读的消息摘要；必须保留正文、当前参与者名称解析、附件文件名、系统通知和预览长度限制。修复覆盖已有会话刷新，不修改持久消息正文。

## 验收范围

### Requirement: 多个 mention 的会话预览可读

#### Scenario: 两个人名出现在预览开头
- **WHEN** 消息开头连续提及两位参与者，且标签因 ID 长度超过预览限制
- **THEN** 会话列表按顺序显示两位参与者的人名，不露出原始标签；窄列表仍使用正常的视觉省略。

#### Scenario: 刷新已有会话
- **WHEN** 用户刷新曾出现截断标签的会话列表
- **THEN** 预览从完整消息恢复人名，正文保持原样。
