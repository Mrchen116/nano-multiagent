## 现象与复现

打开 Web `/settings/agents`，每个自有 Agent 均带红色「停用」按钮和独立「已启用」状态行；打开任一详情后，窄侧栏重复这些控件，名称被挤短，默认状态继续在详情标题下占行。

影响限于 Web 展示密度与操作层级，没有数据丢失或启停协议错误。

## 根因

生命周期 UI 将每行导航同时作为操作面，给正常启用状态、已停用状态与异常状态使用相同的独立提示容器。它满足逐 Agent 管理入口与状态可见性，却没有区分默认状态、低频管理操作与需要处理的异常，导致重复控件抢占空间。

保留原生命周期的不变量：真人管理权限、独立即时提交、离线停止意图、停止确认后才能启用、旧工作不自动恢复，以及设备在线与 Agent 启停状态的区分。

## 最终用户结果

- Web 列表与详情侧栏只承担浏览和导航，不逐项展示启停按钮。
- 默认已启用状态不单独提示；已停用状态在名称旁以紧凑标签显示，不增加列表行高。
- 详情页沿用同样的标题旁标签；启停操作集中在详情页，按钮使用「停用 / 启用」。
- 停止中、停止未确认和读取失败仍可识别；需要说明或重试时，详情页保留对应反馈与入口。
- 本次只改 Web UI，不改变原生 iOS、运行时、权限、API 或任务恢复行为。
