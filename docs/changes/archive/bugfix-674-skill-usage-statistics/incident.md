# bugfix-674: Skill 使用统计独立于调用样本

## Relations

- 架构审查基线：`a89b778de4dda56da933a12e5b59bcf81c207cb1`；审查报告提交 `a34af8473` 中第 01 项。
- 实施准备基线：`ff326c351d104447028f4b185740ab6d6be55de6`。
- Current：[Skill 使用统计 API](../../../specs/im/agents-nodes.md)、[知识维护能力](../../../specs/gateway/agent-capabilities.md)。

## 原始报告与澄清

- 用户：“Skill 统计需要独立于最近调用样本，这个统计是不是不开skill自进化也会有”
- 已核对并答复：使用记录不依赖 skill_creation；关闭自进化仍受统计缺陷影响。
- 用户：“这问题也修下”
- 历史口径澄清：“旧版已经丢失的调用明细无法完整恢复。历史统计你倾向怎么处理？”
- 用户选择：“展示从修复后开始的新统计”。
- Agent 解读：新增统计从修复后实际记录的首次调用开始，明确起点；不把旧总量或截断样本回填到新统计。

## 现象与复现

隔离目录使用真实 KnowledgeFiles.use() 各记录 61 次：本地累计 use_count=61、30 天 heatmap 合计=60；共享 Skill 累计和 heatmap 均为 60。前端额外将 30 天数据补成 365 天，并把未覆盖日期标成零调用。当前代码基线仍含同一实现。

## 影响范围

正常使用 Skill 的普通/Global/PA Agent，开启或关闭 Skill 自进化均受影响。超过证据保留窗口后，统计失真；共享 Skill 的 Agent 统计会随着其他使用者挤出样本而消失。修复涉及统计持久化、运行时归属、IM 投影与客户端展示，选择 Full bugfix，单 milestone。

## 根因分析

使用计数、日趋势与历史证据缺少职责区分：session_refs 仅留 60 条，却被重新计数为趋势和共享 Skill 的累计数。共享归属还依赖临时查询原始会话；前端把数据窗口之外的日期补零。旧测试只覆盖 20 次计数/去重和 UI 元素存在。

## 范围与非目标

保留现有调用触发和去重、F4 阈值、复盘证据与归档行为；新增统计不能改变模型信息、工具或复盘安排。旧记录原样保留但不纳入新统计。不开新数据库，不提高样本上限，不回放真实会话或触碰生产数据；不实施本次审查其他候选。

## Requirements

### Requirement: 新使用统计独立于证据截断和自进化
- WHEN 一个 Agent 在关闭 Skill 自进化时成功使用同一 Skill 超过 60 次
- THEN 累计数与对应日期趋势完整计数，重启后保持；重复事件按既有去重规则只计一次。
- WHEN 多个 Agent 使用同一个共享 Skill，较早使用者的引用已被挤出样本
- THEN 每个 Agent 仍可查看自己的新累计与趋势，不混入其他 Agent 的调用。

### Requirement: 仅展示修复后的新统计
- WHEN 读取已有旧版记录但还没有新调用
- THEN 不展示旧计数为新统计，明确尚无新调用。
- WHEN 出现修复后的新调用
- THEN 仅从这些调用累计，并显示统计起点；旧样本仍供原有历史引用与知识维护使用。

### Requirement: 日期窗口与计数口径清楚
- WHEN 用户查看 Web 或 iOS Skill 使用统计
- THEN 累计数表示统计起点之后的使用，趋势表示服务端明确日期窗口内的新使用；窗口/统计起点之前不呈现为有依据的零调用。
- WHEN 用户查看窄屏或空状态
- THEN 仍能辨认统计起点、窗口与暂无新调用；不把 30 天趋势标成全年历史。

## 修复方向

在现有使用记录内保存按产品 Agent 归属的独立累计及日桶，原子地随有效使用更新；样本继续有界保留。新统计界面明确首次计数时间及 UTC 日期窗口。
