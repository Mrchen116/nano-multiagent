# bugfix-685 全局消息搜索逐会话查询

## 原始报告

> 修复全局消息搜索枚举全实例会话、逐条鉴权并提前装配可读会话详情。10 个可读群，limit=1、零命中，额外 1,000 个无权私群使一次搜索由 122 增至 4,122 条 SQL。入口 apps/im-server/src/messaging.ts 的全局搜索，访问真值在 conversation-access.ts。尽量复用既有鉴权逻辑，验证命中、排序、游标翻页、类型筛选、摘要、只读观察、公开群和禁止访问的边界逐项等价，加入不可读会话时消除逐个 SQL。

用户选择快修，以正常体验等价和可审 PR 为交付范围。用户未亲测修复。

## 复现与影响

在 `7e79e9b79` 的内存 SQLite 上，经 Fastify 注入请求执行登录用户的全局搜索。在 10 个已加入的私群中搜索不存在的词，页长设为 1。加入 1,000 个未加入的私群后，返回正文均为空，整条路由的 SQL 计数从 124 增至 4,124。每次都读取了 10 个会话详情。计数含 fixture 解析用户的两次查询，扣除后与原报告一致。

[feat-680](../feat-680-agent-conversation-search/design.md) 要求各页按当前登录用户的读取资格搜索，类别过滤先于分页。原实现先列出实例中全部会话 ID 再对每条调用详情鉴权，对可读会话还要读取详情来判断分类，最后才匹配消息。同步数据库工作随无关数据增长，空结果请求也承担这部分成本。

## 修复与验证

候选范围、观察权限复用和前后对照见 [事后设计](design.md)。本次调整登录用户搜索的取数成本。无对外契约增量。
