# bugfix-687 事后设计

本文依据 `7e79e9b79..35d689c05` 的实际实现整理。产品代码仅涉及 IM Gateway 对在线节点心跳的处理。

## 候选选择和读取

`gateway.ts` 用上报节点限定 active PA 绑定，按绑定的 Agent 找到持久化的生命周期。启用时，只要该绑定存在属于当前代次的 pending 或 received 观察，就调用既有的 `PersonalAgents.wake` 一次。查询对所有事件类型使用相同条件，存在多项可读事件时也只选中一次绑定。

`agent-lifecycle.ts` 的 `lifecycleAllows` 决定代次资格。SQL 与其保持相同的数值匹配规则，缺失字段和 JSON null 只兼容第 1 代。检查 JSON 类型防止 SQLite 将字符串或布尔值隐式当成数字。

`personal-agent.ts` 继续在实际读取时检查绑定授权、代次、来源和消息可见性。心跳只发出重读提示，模型消费的消息与提醒仍由读取端组装。

## 失败、兼容与回滚

候选查询不写表。当前代次处理失败，事件留在原队列，后续在线心跳继续重试。旧记录保留原始状态。修复无需迁移或重写数据，回退中心代码会恢复修前的空唤醒。

## 产品契约与证据

本次按授权快速修复并验证至可审 PR。现有“重新启用保留资料且不自动恢复旧工作”契约已覆盖产品预期，故无 canonical spec delta。复现、前后对照、正向场景与证据边界见 [修复记录](fix.md)。
