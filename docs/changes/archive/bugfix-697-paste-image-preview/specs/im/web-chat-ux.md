# IM web-chat-ux Specification (delta for bugfix-697)

## MODIFIED Requirements

### Requirement: Web IM composer 输入框随内容自动增高

聊天输入框 SHALL 随显式换行与自然换行自动增高；手机最多约四行、桌面最多约五行后在输入框内部滚动，删减内容后缩回，避免无限占据聊天阅读空间。

#### Scenario: 输入多行文字时 composer 增高
- **GIVEN** 终端用户在 composer 中输入文字
- **WHEN** 文字因显式换行、自然换行或可用宽度变化超过一行
- **THEN** composer 自动增高以展示更多内容
- **AND** 增高到最大行数后不再继续变高,内部可滚动

#### Scenario: 长草稿反复编辑后文字与光标保持对齐
- **WHEN** 用户输入、删除或重新编辑包含中英文、路径及提及的长草稿，使输入框发生软换行或内部滚动
- **THEN** 可见文字、提及高亮和原生编辑光标保持对齐，不因滚动条出现或消失产生额外空位
- **AND** 用户输入的空格与换行、原生中文组合输入和编辑行为保持原样

### Requirement: Web IM 聊天输入框支持把剪贴板图片加入待发附件

桌面端用户可以把剪贴板中的一张或多张图片直接粘贴到聊天输入框，并沿用既有附件的上传、待发、删除、发送与失败反馈能力；不包含图片的剪贴板内容继续由浏览器按原生编辑语义处理。

#### Scenario: 粘贴图片进入待发区
- **GIVEN** 终端用户已聚焦桌面 Web IM 聊天输入框
- **WHEN** 用户粘贴一张或多张图片
- **THEN** 图片立即在输入容器的待发区按剪贴板顺序显示本地预览或固定位置占位，不等待上传结果；用户可继续输入、追加粘贴和移除
- **AND** 上传中在图片卡片上显示蒙层与加载圈，不额外显示上传数量或“完成后可发送”等说明文案；成功后在原卡片移除上传状态
- **AND** 上传未完成时不发送当前消息；多个上传完成的先后顺序不改变附件的展示和发送顺序

#### Scenario: 图片带有文本或网页表示
- **GIVEN** 终端用户已聚焦桌面 Web IM 聊天输入框
- **WHEN** 用户粘贴同时包含图片与文本或网页表示的剪贴板内容
- **THEN** 图片显示为待发附件，输入框不额外插入伴随文本、网页地址或替代文本

#### Scenario: 纯文本或非图片内容保持原粘贴行为
- **GIVEN** 终端用户已聚焦桌面 Web IM 聊天输入框
- **WHEN** 用户粘贴的剪贴板内容不包含图片
- **THEN** 输入框保持浏览器原有粘贴行为，待发附件区不新增附件

#### Scenario: 图片被拒绝或上传失败
- **WHEN** 用户粘贴的图片不符合当前附件限制或上传失败
- **THEN** 原卡片及本地预览保留，就近显示简短原因、适用的重试/倒计时和移除操作；详细原因仍可访问，不重复弹出全局上传错误
- **AND** 重试和成功在原卡片更新，文字及其他附件保留；已移除项不会被晚到结果重新加入
- **AND** 不静默忽略失败附件发送；明确选择仅发送文字时，未发送附件继续保留
