## 现象与证据

2026-11-03 用户使用 Air 浏览器、Air Gateway、Mini IM 和公网 HTTPS/WSS 入口；生产代码基线为 `70ee96ab7e344078e1b72afd75cd8d057b7f95d4`。本次文档基线为 main `26ed162c5e998ffafb3f9ca335f6663dee496aa7`，涉及的配置、工作、轨迹关键文件相对生产基线无差异。以下单次观测不是延迟分布或未来性能保证：

- 配置页刷新时全表单只读。关联同一请求的中心/节点日志：中心 3.834 s，节点检查 2.844 s，其中目录构建 0.510 s；另一次中心 6.152 s、节点 2.199 s。多个检查约 7 s 超时，部分未到 `preview.start`。曾在已登录、暖缓存浏览器单次测到重新加载后约 3.8 s 可操作。
- 工作记录接口多次约 32–43 s，单响应解压约 3.1 MB；一次 36.08 s 中浏览器记录 stalled 20.00 s、等待首字节 9.87 s、下载 6.21 s。同一次诊断约五分钟捕获 80 条匹配工作请求，部分重叠；DevTools 与测试本身可能影响结果。Mini 只读直接查询与解析 128 条明细约 14 ms，为独立测量，不能代表服务端请求耗时。当前一次只读数据库查询，99 条工具项 payload 合计约 3.78 MB，最大约 339 KB；这些是后续采样，不等同前述 3.1 MB 响应。
- 原生轨迹报告 `trajectory_read_failed: trajectory_slow_consumer`。会话原始记录一次采样约 1.67 MB、345 条；隔离副本首两批约 1.01 MB 和 0.75 MB，在本机分别约 28 ms、7 ms。打开流后延迟 4 s 读取成功、5.5 s 报相同错误；该离线实验并非生产实况。生产浏览器另一次观察超过 120 s 仍处连接/加载状态，未捕获用户原错误的逐跳时序。
- 工作页曾报告“正在补齐”，但随后节点生产、确认序号和中心接收序号均为 143288，待恢复项为 0；不能把之后仍有积压当作事实。

## 影响与范围

用户难以编辑配置、查看工作或追踪真实执行，延迟和失败出现于真实跨机网络下。没有证据表明配置或轨迹原始数据被损坏。此 unit 覆盖配置读取与编辑、工作首页及详情、原生轨迹读取及它们竞争资源时的用户体验与对应只读诊断。用户的数据、权限、完整历史和正在运行的 Agent 不因测试或修复丢失。

## 根因与未决证据

1. 配置：状态查询立即过期，返回前台触发读取；读取期间 `isFetching` 直接令表单只读。配置候选依赖节点能力检查，该检查包含隔离进程准备、启动、通信和清理；已见启动到检查前超时，但未证实特定底层耗时原因。保存冲突、离线和未确认操作的保护不能因此被削弱。
2. 工作：周期与事件会触发刷新，首页携带各轮首批完整明细；查询取消信号没有传给实际 fetch。隔离查询库实验中六次刷新造成七个并发物理读取，与浏览器观测到的大量重叠请求一致。尚未将浏览器 stalled 的每一段明确归因于某个连接或代理。
3. 轨迹：节点队列中的批次自生成起有 5 s 消费期限，即使查看端尚在传输或启动；单次大结果需要多批。隔离副本可复现超时错误。用户该次生产错误究竟在哪一跳消耗五秒仍未观测；不能把工作请求归因为已证明的唯一触发因素。

## 用户可观察的验收

### Requirement: 配置可及时查看与可靠编辑

#### Scenario: 打开与后台刷新
- **WHEN** 用户打开在线 Agent 配置、离开再返回，或当前信息在后台刷新
- **THEN** 已确认的信息及时可见；一般后台刷新不反复让无关操作失效，并明确区分正在确认的信息。
- **AND** 编辑草稿不会被刷新悄悄覆盖，保存仅在信息与版本满足既有安全契约时提交。

#### Scenario: 节点不可用或操作待确认
- **WHEN** 节点断线、权限变化、版本冲突或已有操作结果尚未确认
- **THEN** 保留草稿与最后确认信息，清晰说明状态；不能保存时阻止提交，不伪称已生效。

### Requirement: 工作记录及时可用且明细完整

#### Scenario: 进入、刷新与查看长记录
- **WHEN** 用户打开或返回包含多个轮次及大工具结果的工作页，并展开记录或关联执行
- **THEN** 首屏及时出现且操作响应，能继续读取完整参数、结果、状态和统计；正常更新不导致请求无限堆积或反复重置浏览位置。
- **AND** 刷新、断线恢复和切换轨迹后，来源、归属与历史仍准确，未确认的信息明确标识。

### Requirement: 原生轨迹及时可读且不丢历史

#### Scenario: 加载与继续查看大轨迹
- **WHEN** 用户在真实跨机网络中打开主执行或继承大量历史的子执行，并查看更早记录
- **THEN** 及时出现可检查的真实轨迹，完整记录、来源、搜索、时间轴和附件的既有权限与能力保持可用；正常传输或查看较大的数据不会被当作慢消费者而中断。

#### Scenario: 真正断线或访问失效
- **WHEN** 节点失联、权限撤销、浏览器离开或用户重试
- **THEN** 状态准确、读取和资源得到释放，不将陈旧数据伪装为实时，不重复执行 Agent 工作。

## 验证边界

采用隔离身份、工作区、数据、配置、端口和进程，使用经授权的 Mini 独立测试 IM、Air 测试 Gateway、真实浏览器和实际跨机网络；是否另配隔离公网入口及证据能力需在设计前核实。采用合成但按观测到的记录规模与大结果分布构造的数据，不复制生产聊天、密钥或运行数据。记录基线与修复后同环境、同数据、多次冷/暖加载的首屏与可操作时间、失败率、请求并发、字节及各跳耗时；记录测量方法和环境。验收目标与网络波动条件由设计明确并避免将目标伪称为已测结果。对真实慢读、连接中断、恢复、资源释放、权限、长记录完整性与生产隔离做回归。

## 修复方向

分别缩小工作首屏数据与刷新负载、分离配置读状态与操作准入、调整原生轨迹背压和可恢复读取，并建立不记录正文或凭据的逐段诊断。方案须基于公开 DSH 接口，不通过修改或 fork DSH 实现；具体接口、资源上限及权衡由设计确定。
