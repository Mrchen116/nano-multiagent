# Work 与原生轨迹加载增量

## ADDED Requirements

### Requirement: 已保存工作记录独立于配置确认加载

#### Scenario: 直接打开 Work
- **WHEN** 用户打开工作页，包括配置能力暂不可确认时
- **THEN** 直接读取并展示真实已保存的工作摘要，不等待配置或节点能力检查。
- **AND** 从配置切换工作后再返回，未提交草稿保留；隐藏的配置不重复挂载工作或轨迹读取。

### Requirement: 工作概览按需读取完整过程

#### Scenario: 大量工具记录
- **WHEN** 用户打开含大工具结果的工作页
- **THEN** 首先可见真实轮次摘要、状态和统计；展开时可以按需查看完整过程与工具参数、结果及来源，不因摘要省略而丢失。
- **AND** 刷新和切换视图保留阅读位置，失败时可重试，既有客户端完整读取契约不变。

## MODIFIED Requirements

### Requirement: 原生轨迹在查看时读取，连接状态如实呈现

#### Scenario: 按需读取历史并接收新增记录
- **WHEN** 用户进入原生轨迹并向前查看历史
- **THEN** 加载该执行所在节点的真实记录，支持继续读取更早内容和接收真实更新。
- **AND** 新增内容不强行改变检查旧记录的位置；离开视图后停止该视图的更新读取。

#### Scenario: 子执行刚启动但继承历史较大
- **GIVEN** fork 子执行继承了父级的上下文快照、模型和工具记录
- **WHEN** 用户打开该子执行的原生轨迹并继续向前读取
- **THEN** 可以完整检查继承历史和本次新增记录，不因单页内容总量较大而中断。
- **AND** 大型单条记录保留完整内容；离开或失去访问资格时停止读取并清理未完成内容。

#### Scenario: 节点不可读取或更新中断
- **WHEN** 打开时节点不可读取，或查看中连接中断
- **THEN** 显示相应不可用或中断状态，已加载内容不被误认为正在更新，已保存的工作记录仍可回看。
- **AND** 恢复读取不会重新执行任务，也不伪造完成、耗时或未报告的统计。

#### Scenario: 普通慢速传输与大批次
- **WHEN** 用户读取跨多个批次的主或子执行，并在正常网络延迟或短暂停顿后继续
- **THEN** 可按真实顺序继续检查完整历史及新增事实，不因固定短期限将正常传输误报为慢消费者；大型正文可继续分页读取且不被删减或截断。
- **AND** 真实积压超出边界或连接中断时明确提示；取消、离开和资格失效仍停止读取，不保证无界缓冲或断线无缝恢复。

#### Scenario: 配置了普通公网代理的节点读取轨迹
- **WHEN** 控制连接与轨迹专用读取连接访问同一 IM
- **THEN** 两者采用相同的节点网络代理与直连规则，连接准备有界失败；读取不授予额外访问资格，也不激活执行。
