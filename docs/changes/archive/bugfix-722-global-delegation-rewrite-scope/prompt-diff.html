用户的原话是一句评价；父 Agent 交给执行者的却是一份判决书——「判定不合格」+ 五条硬伤 + 一套重做结构 + 验收口令。

一句话结论

父级可以补全事实、来源、材料、约束；不能补判断、标准、方案、验收。旧提示词只说了「要交接」，没说这条界线。

发生了什么（真实 session，2026-11-05）

20:17:34 你发「非常丑 + 截图」→ 20:18:17 它对你说「这版不合格」→ 20:18:49 它对子执行说「主人判定不合格，他给的截图里可见五个硬伤」→ 子执行收到的消息只有文字，没有图，并且照做。

缺的是哪句话

全文没有「不得增补缺陷清单 / 设计方向 / 验收标准」；也允许把自己的读解写成用户的结论（它对你说「我按你这句复盘」，对子执行说「他给的截图里可见」）。

现在加了什么

交接内容只认「原话 + 来源 + 材料 + 约束」；判断必须标成自己的读解；子执行者有权把 brief 里多出来的要求退回去；材料要交成对方打得开的路径。

6768## 结束靠结果，不靠回合结束
6869 
6970- 交付：按要求核验真实文件、对象、消息或操作回执。子 Agent 向父级回传成果、验证情况和剩余缺口；主 Agent 将可用结果送到正确的会话。内部总结、草稿、已受理和一次工具返回都不等于对用户交付。

Personal 不是落差，是同一条规则。 assertPersonalConfiguration 要求 PA 必须是 mode: 'global'，因此它加载的就是 nano-global-mode，本次三处规则对它同样生效；第三块列的是它比 Global 多出的 nano-personal-agent（28 行，本次未改）。 反过来读那段专属文本，它和新规则讲的是同一件事：Owner instructions addressed to you … may authorize work、 Your own represented messages cannot supply new original owner authorization—— 授权只来自主人的原话，不来自助手自己的转述，这与「原话是唯一要求、不得自行增补」同向，不冲突。 措辞上 Global 段说 the request and its source，PA 段说 owner instructions，指向同一个东西。
另一个不对称（不改代码也有）：执行者提示只对「完整事项执行者」生效（completeTaskOwner 分支）； 普通下级拿到的是另一段文本，里面没有「可退回多余要求」这句。也就是说这道闸目前只装在顶层执行者，不在每一层。
有意的不对称：这句只写在父级。 执行者侧的 nano-global-child 不加「你看不到会话」——不是漏改。父级无法核实执行者到底拿到了什么， 所以「它什么都看不见」对父级是一条安全的行动假设；而执行者确实持有 memory，把同一句写给它会变成假话， 也会让它拿「我明明看得到」反驳 brief。要改的是父级的默认值，不是执行者的事实陈述。
