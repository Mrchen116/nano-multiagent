# bugfix-724 PA 起草、发送身份与外发误拦

## 原始报告和澄清

> 其实应该结合语境吧，比如他都不在那个群里面，那肯定是让他代我发。如果是一直都是他在跟某个会话里面在对话，然后有一个不确定的事情问我，我说完之后说，你直接发给他。那这种场景下应该就是直接send message。

> 这个版本可以，用 GPT-6.1 Sol High 在测试网页上重新跑一下起草卡片和两种发送场景，把记录留给我看。注意清空测试的数据。因为历史记录会造成影响。

> 被拦截的原因是啥，这个场景我不希望拦截

用户要求按会话语境选择发言身份，确认 PA Prompt 的精简版本，并要求实际复测。后续确认审核器可以通过工具名区分发送身份，要求直接提交 PR。

## 现象与根因

- 只起草给明确目标会话的回复时，PA 曾返回纯文本。通用 UI Prompt 对复用文案推荐纯文本，PA 的起草规则没有明确要求加载 Skill 并通过自己的发送工具交付可编辑卡片。
- 初版修复把「直接发给他」作为代发例子，容易把 PA 延续自己对话的请求也理解成代发。发言主体取决于原始委托和对话语境。
- 空白测试实例复现了两次类型相近的独立外发审核误拦。用户明确选择原稿且 PA 实际提交原稿时，审核器把先前卡片里未发送的编辑稿当成了待发内容。PA 在自己参与的群里向唯一第三方转达用户确认的时间时，审核器错误要求代表用户发言的授权。

## 范围与预期

已知目标且交互能力可用时，PA 在与用户的 Nano IM 私聊交付可编辑的起草卡片。采用草稿只填写目标输入框。需要发送时，以 PA 自己身份延续对话和代表用户发送分别使用现有工具。两者向第三方发言均按本次发言身份、正文、完整受众和原始授权进行独立外发审核。

本单元覆盖 Nano IM 的起草和发送，以及独立外发审核输入。飞书卡片交付、审核会话缓存和上下文压缩另属其他议题。
