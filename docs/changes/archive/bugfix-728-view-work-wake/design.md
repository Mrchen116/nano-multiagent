## 最终结构

### 组件与职责

- `message-pane.tsx`：仅对既有 View Work 入口追加该消息 ID，保留 Agent 选择与可见资格。
- `WorkRecords.view`：在已获授权的 Agent 内，从持久 `message_sent` 事实解析真实主执行与轮次；`focus` 仅为定位元数据，不改变正常主执行列表、排序或页范围。
- `WorkRecords.turns`：沿用原有最新优先、`before_turn` 排他续页；撤销首版的 inclusive 目标上界，避免截去目标之后的轮次。
- `AgentWorkPanel`：按消息 ID 隔离查询缓存；在正常最新优先列表中自动加载摘要页至目标，保留其间所有较新轮次及“更早轮次”分页。目标属当前主执行时关闭旧子面板，属历史主执行时使用既有关联执行面板而不替换当前主列表。展开对应轮次，完整首批过程就绪后滚动一次，后续同步不打断用户阅读或重新展开用户折叠的记录。
- `Turn`：沿用 summary / 按需 items，程序展开也会读取过程；以回复入口 token 限制一次滚动。该token在新消息锚点或重新从聊天进入时更新，内部工作记录/原生轨迹replace切换不更新，避免重开用户折叠目标、抢走返回时的阅读位置。

### 调用链与数据流

聊天回复 → `/settings/agents/<agent>?view=work&message_id=<message>` → 已有授权 Work API（附同一消息 ID）→ Agent 范围内投递事实 → `focus={session_id,turn_id}` 和正常最新摘要页 → 必要时顺序补载摘要页至目标（不丢弃较新记录）→ 展开 → 真实 items → 滚动到目标。

消息锚点不作为查询范围或过滤器。列表始终保持原有完整顺序与可达性；初次只按需补载至目标，更早记录沿用“更早轮次”，不会为定位自动读取所有正文。目标滚动保留72px上方阅读余量，使邻近折叠轮次仍可辨认。`查看最新轮次` 清除定位锚点；主执行当前状态与最近用量仍取当前主执行，不把历史已完成唤醒误报为当前空闲。历史主执行被保留时亦可经真实投递事实在关联执行面板定位，当前主执行列表不被更换。

### 状态、数据与兼容性

- 复用历史 journal，无需新加消息列、回填、时间邻近匹配或 LLM 内容推断。
- 不含 `message_id` 的既有 Work 请求和历史分页契约不变；旧客户端无需升级才能继续读取。
- 找不到关联时返回 `focus: null`，仍显示已有记录，并提示“该回复的工作记录尚未同步或不可用。”后续 Work 同步可重取并定位；读取失败沿用既有重试。
- 资格沿用 `registerWorkRoutes.profile`：有效 Global profile、空间资格及 PA 本人限定。消息锚点不会授予原聊天/附件权限，也不会触发 Agent 执行。

## 关键决策

| 决策 | 原因与约束 | 代码定位 |
|---|---|---|
| 从实际投递事实反查，不新增来源字段 | 既有历史已经具备精确关联；避免只修新消息和猜测同名唤醒 | `apps/im-server/src/work-records.ts` |
| focus与列表范围分离，在正常列表补载至历史目标 | 用户真实试用否定首版从目标开始造成的截断；所有新旧轮次必须保留正常可达性 | `WorkRecords.view`、`AgentWorkPanel` |
| 首批过程就绪后只滚动一次 | 浏览器实测发现空摘要尚无足够高度，提前滚动会无效；同步更新不应拉回正在阅读者 | `Turn` focus effect |
| 回复入口token不随内部视图切换更新 | 独立审查确认直接用每次location.key会在native往返时重开已折叠目标并抢滚动；仅新回复入口重新应用定位 | `AgentWorkPanel.replyNavigation` |
| 不增加原型/大改布局 | 明确的导航恢复目标，沿用现有 Work 卡片与工具显示即可 | Web 真实浏览器验证 |

## 失败路径、风险与回滚

- 消息先于 Work 同步、旧记录缺少关联：说明未知而非猜测；同步/可见恢复后继续既有读取。
- 节点离线：已保存 Work 仍可读，活动状态仍降级未知；不要求在线重新执行。
- 大过程：保留既有 items 分页，初次只读取所展开目标的首批；完整后续内容仍由“加载更多过程”取得。
- 回滚代码即可，未改 schema 或写入格式；已保存聊天和 Work 不受影响。

## 与初始意图的差异

首版错误地将“定位”实现为从目标开始的历史切片，用户真实试用后明确更正“Work永远全量，只展开目标”。修订将消息关联降为展示定位元数据，不再改变列表范围。保留必要的“尚未同步或不可用”提示和“查看最新轮次”出口；不新增发信、配置或访问权限。
