# bugfix-734: 临时磁盘写入失败后恢复 Agent 执行

## 原始报告

> 为啥没回复
>
> 但是现在已经磁盘不满了呀，为啥不能恢复。其他软件都可以恢复
>
> 那修这个问题吧

> 我要的不是你一直检查，然后自动续跑，而是正常的激活，比如用户发消息了，heartbeat了，如果已经可写了，就应该可以正常工作

## 现象 / 复现

Air 上的「禅」在 2026-11-09 10:23 和 10:24 收到两条交办。IM 已确认投递，Inbox 仍未消费。原生会话第 266、267 轮均在模型调用前因同一个模型运行记录临时文件的 `ENOSPC` 结束。检查时已有约 21 GiB 可用，工具记录观察也仍抛出原先的写盘错误。

验收时在隔离运行时让模型和工具记录写入暂时返回 `ENOSPC`，再恢复可写。空闲期间不启动磁盘恢复检查或补跑失败轮次。新的用户消息或下一次符合原调度条件的 Heartbeat 应在同一进程内正常执行。保留既有 Inbox 待读语义和 Work 记录。

## 根因

Nano 的模型运行记录写入保存第一次异常，随后所有写入都在访问存储前抛出该异常。工具记录则继续把操作接在一个已经拒绝的 Promise 上。两条链路都没有机会重新写入。模型的 pre-step 需要持久化成功才继续，Work 观察同样依赖工具记录。

[Agent 能力契约](../../../specs/gateway/agent-capabilities.md)依赖已持久化的轮次证据，[Heartbeat 契约](../../../specs/gateway/heartbeat-cron.md)规定激活时机。恢复需要保留落盘检查和已有激活规则。

## 本次审查安排

| 问题 | 能力 | 证据 |
|---|---|---|
| 写入失败后能否继续，记录与 Work 是否完整 | change-code-review | 同进程写入失败与恢复回归 |
| 磁盘恢复后只在正常激活时继续工作 | change-code-review | 隔离 DSH 测试保留真实用户消息入口和 Heartbeat 调度入口，核对空闲期间没有补跑 |

## 修复

模型运行记录和工具展示记录保留未落盘的快照，在正常执行时通过持久化检查重新写入。Work 观察只等待现有写入结果。原有激活条件、Inbox 摄取和调度保持不变。

## 验证

- 在独立 DSH 子进程注入模型运行记录的 `ENOSPC`。恢复磁盘后，空闲时没有额外模型调用或补发唤醒。新用户消息与下一次 Heartbeat 分别在同一进程内正常执行。
- 工具已执行而结果快照写入失败时，Work 查询报告当前写入失败。下一次正常激活后可观察到原工具结果，工具执行次数为一。
- 验证使用受控模型响应，覆盖实际运行时、定点文件写入故障、Inbox 消息入口及 Heartbeat 调度入口。
