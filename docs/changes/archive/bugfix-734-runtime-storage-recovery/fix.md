# bugfix-734: 临时磁盘写入失败后恢复 Agent 执行

## 原始报告

> 为啥没回复
>
> 但是现在已经磁盘不满了呀，为啥不能恢复。其他软件都可以恢复
>
> 那修这个问题吧

## 现象 / 复现

Air 上的「禅」在 2026-11-09 10:23 和 10:24 收到两条交办。IM 已确认投递，Inbox 仍未消费。原生会话第 266、267 轮均在模型调用前因同一个模型运行记录临时文件的 `ENOSPC` 结束。检查时已有约 21 GiB 可用，工具记录观察也仍抛出原先的写盘错误。

验收时在隔离运行时让模型和工具记录写入暂时返回 `ENOSPC`，再恢复可写。后续执行和 Work 读取应继续，已接收且因写入失败在模型调用前中止的交办应自动重新唤醒，用户无需重发。保持现有会话和投递去重语义。

## 根因

Nano 的模型运行记录写入保存第一次异常，随后所有写入都在访问存储前抛出该异常。工具记录则继续把操作接在一个已经拒绝的 Promise 上。两条链路都没有机会重新写入。模型的 pre-step 需要持久化成功才继续，Work 观察同样依赖工具记录。已投递的 Inbox 唤醒在本次故障中以错误结束，现有恢复只重试已中断的唤醒。

[备用模型契约](../../../specs/gateway/agent-capabilities.md)依赖已持久化的轮次证据，[Global 输入恢复契约](../../../specs/gateway/global-agent.md)要求保留未读输入及稳定身份。恢复需要保住落盘检查，并以原生证据区分尚未进入模型的失败唤醒和可能已经执行的工作。

## 本次审查安排

| 问题 | 能力 | 证据 |
|---|---|---|
| 写入失败后能否继续，记录与 Work 是否完整 | change-code-review | 同进程写入失败与恢复回归 |
| 原交办能否续跑，已处理交办是否被重复执行 | change-code-review、agent-context-review | 原生唤醒证据、恢复后模型实际收到的原消息、Inbox 恢复回归 |

## 修复

模型运行记录和工具展示记录保留未落盘的快照，由后续持久化检查重新写入。Global Inbox 在本地写入检查通过后，沿原有恢复通知身份续跑未读交办。只自动重试在模型消费前以 `ENOSPC` 结束的唤醒。

恢复通知沿用原唤醒的接收时间，提交时检查已有的停止边界。其他 Agent 的恢复仍在进行时，保留已安排的重试，等这次恢复完成再尝试。

## 验证

- 在独立 DSH 子进程注入模型运行记录的 `ENOSPC`。修复前磁盘恢复后原交办仍未读；修复后保留原输入和会话，以一次恢复唤醒交付原消息。
- 工具已执行而结果快照写入失败时，Work 查询先报告写入失败。恢复后原有调用与结果都可读取，工具执行次数为一。
- 两项验证使用受控模型响应，覆盖实际运行时、存储和宿主 Inbox 逻辑。
- 确认故障期间主动停止后，恢复可写也不会重新接受旧唤醒。另一个 Agent 仍在恢复时，定时器到期不会丢掉重试。
