# bugfix-735: 纯 UI 消息的提示、搜索和审核投影

## Relations

- Depends on: bugfix-733
- Related: bugfix-729

## 原始报告

用户对 Web 新消息提示、关键词搜索标注「要修」，对 PA 审核上下文标注「修掉」；聊天列表预览问「不空的话，显示啥？有什么好主意」，复制和群聊 @ 均标注「先不管」。

## 现象与根因

- Web toast 将非空正文当作有效完成的判据。纯 UI 卡片已经公开交付，但没有提示；部分已完成卡片直接以创建事件交付。
- Web 与 Agent 历史查询只匹配正文，卡片中的公开可读文本无法通过关键词回找。依赖 bugfix-733 返回命中的纯 UI 消息。
- PA 输入和出站审核直接把含渲染字段的交互对象序列化给审核模型。审核需要完整源码和替换引用；宿主仍需要完整冻结协议来校验和交付。

## 目标与验证

沿用既有 Web 提醒身份、去重和当前会话策略，纯 UI 使用本地化类型标签。Web 和 Agent 搜索匹配公开卡片初始视图的常用文字和数据标签，旧卡片也可回找；搜索不执行动作、不查询私有状态或沙箱页面。PA 两种审核保持源码和必要替换关系，去掉渲染字段。此次不改会话列表的摘要、复制或提及语义。

用现有通知、聊天历史和审核 fixture 复现并验证，检查权限、分页、持久数据升级和模型可见结果。独立审查核对最终契约。

## 修复

- Web 使用终态卡片事件或已有完成事件生成提醒。只有卡片而无正文时使用本地化类型标签。去重、来源和列表预览规则沿用既有路径。
- IM 使用已有 OpenUI 初始求值提取公开文字，单独持久化 `search_text`。按词匹配正文或卡片文字，片段取自实际命中的字段。新建、替换、fork 复制均携带投影；旧库首次打开时自动回填，无法解析的旧卡片仍保留原文。检索不读取私有草稿、不执行卡片动作。此加列和回填随 IM 启动执行，无单独部署迁移步骤。
- PA 在输入审核的当前消息、历史及引用和出站待审动作上复用模型卡片投影。冻结的交付协议、权限和提交校验不改。

## 验证

- 前期复现：相同词分别放在消息正文和卡片时，Web 搜索和 Agent 搜索只命中正文；Web 的空正文提醒分支跳过纯卡片，审核投影包含渲染字段。
- Web toast 与去重相关 26 项通过，覆盖 Agent 和代发身份，不向侧栏写入类型标签。IM 历史和卡片定向 30 项通过，覆盖可见字段、旧卡片升级及隐藏动作、无效表格列和未使用图表数据排除。PA 输入模型请求与 native 出站审核请求均保留完整源码和替换引用，无渲染字段。
- 本机并行全量运行有与目标无关的超时和 UI fixture 失败，原始日志 `/tmp/nano-735-im.log`、`/tmp/nano-735-web.log`。PA capability inspector 用例在本分支和未改动的 #484 基线均在检查过程失败（`/tmp/nano-735-pa.log`、`/tmp/nano-735-pa-base.log`）。远端整套 CI 为完整交付检查，不把定向通过视为本地全量通过。

## 会话列表预览补充

用户查看截图后确认补上普通会话列表的纯卡片预览。搜索片段来自实际命中的卡片内容，列表预览使用本地化「互动卡片」及卡片已有的首个可见标题。服务端与可搜索文本一起回填旧卡片标题，Web 和 iOS 共用会话接口返回的标题。正文和附件文件名仍优先。

IM 定向 45 项、Web 定向 49 项通过。隔离 IM 上通过 Gateway 消息通道发送无正文卡片，Web 左栏实时显示有标题和无标题两种预览，点击会话可打开原卡片。iOS 与 Web 共用接口，真实界面走查覆盖 Web。
