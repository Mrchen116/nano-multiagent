## 根因

feat-615 移植了同步 Guardian 的判定策略、预算与审核会话机制，并沿用 Nano 在子 Agent 首次挂载时保存的委派证据。后续审核从旧快照及子 Agent 自身历史组装。父 Agent 在启动后收到的真人授权、限制和撤回只能通过转述到子 Agent，丢失宿主确认的原始身份。审核策略拒绝将转述提升为真人许可，符合其信任边界。

参考 Codex 的固定基线 `806d9732c9` 已包含上游 #39975。MultiAgent V2 每次审核尝试从所属根会话取有界原始证据，并检查审核期间授权变更。Nano 应让仍在运行或恢复执行的原生子 Agent 在下一次 Codex Auto 审核时看到所属根会话已经接收的原话。若审核期间该证据变化，旧判定失效，以新证据作有界重审。继续保留身份、消息来源、范围、顺序与预算约束，其他会话、父级转述和工具正文不获得新的授权资格。范围限于 Codex Auto 工具审核。

## 本次审查安排

|---|---|---|
| 新授权及后续撤回何时到达子 Agent 审核器，来源和范围是否可信 | Agent Context | 隔离 DSH 捕获实际 reviewer 输入，核对原始 Inbox 消息、时序与授权变更后的工具结果 |
| 作用域、审核复用与失效、旧记录兼容 | 独立代码审查 | 核对最终 diff、契约和原生回归 |

## 修复

- Codex Auto 用运行时已验证的绑定查找原生子 Agent 的根会话，复用原始指令投影和整条消息预算。保留委派快照作为历史证据。CC、DSH 和 PA 外发审核沿用各自路径。
- 审核缓存关联实时根证据。根证据改变后重新组装，模型返回后再次核对，发现变化沿用有界重建流程。保留现有原始动作与取消边界。
- 审核审计写入后、交给原生工具执行前再次校验。若期间出现新证据，将过期裁决替换为无结论，恢复计数并停止待执行动作。

## 验证

- 隔离 DSH 真实子 Agent 和 Inbox 工具，受控审核模型。修前第一条审核输入缺少子 Agent 启动后读到的用户原话。修后审核输入包含真人消息的 ID 和身份，排除另一根会话的授权及父级转述，第一条动作执行一次。
- 第二条审核进行中，由根 Agent 读取撤回消息。首次 allow 失效，重审收到按顺序保留的许可和撤回，返回 deny，无第二次工具副作用。
- 分别暂停 allow 和 deny 的审核审计落盘返回。根 Agent 在这时收到撤回，校验返回无结论，无第二次工具副作用。过期裁决只保留一条无结论记录，拒绝计数不增加。
