# bugfix-740 Agent 重连后保留已确认的停用状态

## 原始报告

> 你看，实际上不行啊，有bug

关联 [用户反馈中的排查](codex://threads/01a18c12-8a97-7783-a6c8-30aca57c6e05) 与 [feat-738](../feat-738-agent-permanent-deletion/spec.md)。

## 现象与复现

生产中，用户停用普通或 Global Agent，中心显示已停用并接受永久删除。节点重新同步后却报停止未确认，永久删除和重试都失败。只读核查表明中心已确认停用版本 2，节点保存了同一执行实例的已停止凭证，但节点状态为 `stop_unconfirmed`。该删除操作未进入节点清理台账。

隔离复现先持久化同一实例的停止确认，再重连并令重复的停止请求超时。节点把状态写回未确认，中心仍保留确认，删除前的节点校验于是失败。

## 根因

节点重新收到停用快照时总会再次发起停止，即使对应停用版本和执行实例已有本地停止凭证。它用重复调用的结果覆盖本地观察，而中心拒绝同一版本从已停用降回未确认。

修复需要让重连后的节点保留或恢复有证据的确认。缺少凭证、执行实例不符或尚未确认的停用仍须完成受管清理才能删除。原删除范围、历史保留和其他 Agent 的运行不受影响。

## 修复

节点同步停用状态时，同时核对版本、执行实例和本地停止凭证。已有凭证可让节点保留或恢复确认。只有中心确认时，节点先维持停止中，沿用受管停止流程。旧版凭证可能记录共享管理进程，仍可通过原有流程确认；新凭证和上报使用同一执行实例。过期的异步结果不得覆盖新版本的凭证。

## 验证

修复前，重连复现与两个缺少匹配凭证的边界回归失败。修复后，节点生命周期、中心生命周期与原生 DSH 删除共 19 项测试通过，节点类型检查通过。验证使用隔离 fixture；生产核查只读。
