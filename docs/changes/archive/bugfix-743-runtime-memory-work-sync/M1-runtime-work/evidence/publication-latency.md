# 公开发信的本地账本取证

生产对照样本从工具发起到中心写入耗时 46.73 秒，从写入到工具成功耗时 51.10 秒。同期同一轮的 DSH 内部 Agent 投递耗时约 169 秒，该调用不经过 IM。公开发信旧路径在 relay 前和收到回执后各执行一次全会话事件读取；同步读取和解析位于 Gateway 事件循环中。这里验证并移除了全读，不能从现有日志归因两个长间隔的全部时间。

隔离对照用同一份预先落盘的合成账本：16,543 条记录，112,466,674 字节 JSON；三次调用真实 `GlobalAgent.call` 和 `NodeStore`，每次使用立即返回的模拟 relay 回执。数字只计 Gateway 本地发送及回执处理。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 三次发送的全会话读取 / 定点读取 | 6 / 0 | 0 / 3 |
| 请求 relay 前 | 101–128 ms | 0.22–1.40 ms |
| 即时回执后 | 118–440 ms | 0.06–0.90 ms |
| 两段合计 | 247–541 ms | 0.29–2.30 ms |
| 首次发送期间 RSS 净增 | 535 MiB | 0.83 MiB |

`EXPLAIN QUERY PLAN` 确认按 `(session_id, callId)` 使用 `runtime_tool_call_lookup`。已有账本首次开库时同步建索引，此样本为 53.2 ms（对照开库 1.9 ms）；这个一次性成本没有计入每条消息。上述 RSS 只是一份隔离进程的测量。真实 IM 回归用 Gateway 产品路由和 WebSocket relay 入库，重复调用只产生一条消息和一份归到原轮次的 Work 回执。

另在隔离 DSH 子进程中，用受控 provider 及约 94.8 MB 的冷子会话日志重复调用原生 `send_message({agent_id,message})`。两次都打开日志，工具完成耗时 128 ms、104 ms，其中打开日志读取约 90 ms、74 ms，子会话接收确认约 3 ms、2 ms。该条件下未复现 169 秒，且不会命中上述 Gateway 索引。生产条件中的运行时争用和排队仍待实际观测。本次未部署。
