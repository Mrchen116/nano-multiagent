# bugfix-756 · 父检查器退出后回收临时检查进程

## 原始报告

> Nano 的临时进程回收按刚才验证的方案修，补回归测试，跑过后提 PR。

## 现象 / 复现

停止正在跑本地 CI 的 714 执行者后，外层作业结束，Nano 临时 DSH 检查进程仍在独立进程组中运行，已被系统接管。隔离复现使用真实 ConfigurationInspector 加载阻塞事件循环的插件，等待检查启动后终止其父进程。父进程退出，检查进程仍存活。

macOS 和 Linux 上，父检查器退出后，Nano 必须回收该临时检查进程组，即使插件阻塞事件循环。无需启动新检查器才能停止进程。正常超时和取消、持久执行进程、下次启动清理检查目录及拒绝回收身份不明进程的保护继续成立。本次修复覆盖使用独立 POSIX 进程组的能力检查路径。

## 根因

独立进程组使 Nano 可以隔离并定向回收检查进程及其插件子进程。正常收尾由父检查器的 finally 负责。父检查器异常退出时，检查进程的管道关闭和 deadline 回调依赖可能已被插件堵塞的主事件循环。原流程等新检查器按记录的进程身份回收，单次 CI 中断后可能没有下一次启动。

## 本次审查安排

| 必须回答的问题 | 能力 | 验证方法 |
|---|---|---|
| 父进程退出时能否回收卡住的检查进程组，同时保留常规检查与恢复边界 | 独立代码审查 | 真实进程红绿回归，现有检查器测试及规范对照 |

## 实现

- 仅在 POSIX 临时能力检查进程启动时预加载独立 watchdog 线程。它定期比较父 PID，发现父检查器退出就终止当前检查进程组，插件阻塞主线程也不影响检测。
- 检查进程在 RPC 失败、stdin 关闭或 deadline 时退出前回收自己的进程组。父检查器保留协议取消的宽限时间，随后向整组发出终止信号，避免先结束检查进程及其 watchdog，再等待处置仍存活的插件子进程。
- 父检查器异常退出时保留磁盘上的检查目录记录，由新检查器按原身份规则回收。持久执行进程沿用原启动和退出行为。

## 回归

真实父检查器、检查进程和同组插件子进程覆盖三种退出时机。插件仍能响应事件、插件阻塞主线程、以及父检查器发出第一次进程组信号后被中断。每种用例都验证两个进程退出，并验证后续检查器清除旧目录、恢复新检查。既有用例继续覆盖超时、取消、正常完成和拒绝回收身份不匹配的进程。
