# 模型送达回执的一次性迁移

本文件仅在用户授权部署包含本修复的版本时执行，不授权当前会话修改生产。中心与全部节点必须配套升级；旧节点把持久入箱直接上报 sent，不能与新语义混跑。

## 旧状态与目标

旧中心的 Global Agent 收件人 status=1 不能证明模型已收到提醒；节点未消费 Inbox 对应的 sent 也不能作为证据。迁移将这些历史未读送达事实退回待送达，保留 status=2 的已读及真人、single_thread 收件人状态。节点保存恢复标记，随后用新冻结快照重新提醒模型，取得有效模型响应后再推进 sent。脚本不删除消息、Inbox 内容、会话历史或工具执行记录。

执行工具是 `scripts/migrate_model_delivery_receipts.py`，仅 Python 标准库，选择 `--kind center` 或 `--kind inbox`；各库用 `model-delivery-receipts-v1` 标记保持幂等，不在每次启动时重复整理历史。节点的正常恢复逻辑消费一次性恢复标记。

## 执行顺序

1. 按当前舰队配置定位实际中心 SQLite 和每个节点 Inbox SQLite，不照抄历史机器路径。记录目标提交及各服务版本。
2. 停止全部旧节点服务与所属 DSH／工具进程，再停止中心。确认没有旧进程可以继续提交 sent。按部署 runbook 备份这些数据库及 SQLite WAL/SHM 的一致快照，记录位置及校验信息。
3. 对每个库先运行 `python3 scripts/migrate_model_delivery_receipts.py dry-run --kind KIND --database DB`，保存候选计数；这里 KIND 与 DB 必须替换为对应类型与已核实路径。
4. 对同一组库运行 `python3 scripts/migrate_model_delivery_receipts.py apply --kind KIND --database DB --writers-stopped`。每个库在单事务中更新状态和版本标记；跨库没有总事务，全部完成前保持停机。
5. 对所有库执行 `verify`，确认标记存在；核对真人与已读记录数量没有变化、消息内容与条数未变。重复 apply 应返回 changed=0，不再次降级后续已验证送达。
6. 安装同一目标版本，先启动中心再启动节点；核对运行时健康与连接，观察既有未读消息自然恢复，不为了验收额外向生产发送测试消息。

## 中断、失败与验证

某库事务失败可修正环境后对同一库重试；已完成库按标记跳过。启动前如任一必需库不能完成，保持服务停止，不让部分旧版本写回。若决定回滚版本，在全部写入停止时整组恢复迁移前备份，不能只回退二进制或单边数据库。

隔离环境中的迁移回归必须覆盖旧 SQLite、已读和真人保留、事务失败及重复执行；模型收件与 Inbox Read 回归使用本 unit 的真实 DSH／受控 provider 证据。正式部署只核对计数、标记、只读小样本和服务健康；记录恢复后的自然回执变化，不要求用户重新交办。没有额外生产写入测试不视为迁移缺项。

执行版本、对象范围、备份位置、计数与结果写入受保护的本地部署记录，不提交原始数据库或消息内容。
