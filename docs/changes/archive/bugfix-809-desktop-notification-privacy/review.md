# bugfix-809 通知隐私审查

独立 change-code-review 对 `1bdc4646c..6e8940cec` 审查了两端投递、点击、宿主留存和身份切换，并在 `6f68075ff` 对三项问题做了定向复核。以下问题均已关闭。

| 首轮发现 | 修复及复核依据 |
| --- | --- |
| P1，旧 Windows toast 仅带路由，可在 B 的冷启动或常驻进程中激活 A 的目标 | 解析器要求路由和作用域同时存在，宿主在当前会话下匹配后才导航。使用旧链接、跨账号和跨服务链接回归。 |
| P2，macOS 退出后点击通知时，常驻 delegate 收不到启动载荷 | 在 Tauri 启动前注册 AppKit 启动观察者；冷、热通知使用同一校验。窗口尚未就绪时，目标先进入待导航队列。签名测试应用的原生启动通知回调已用合成载荷验证。 |
| 系统历史清理依赖旧预览日志存在 | 启动时独立检查本应用的系统历史，保留当前作用域；切换身份时撤回旧历史。隔离宿主跳过系统历史清理，保护已安装应用的数据。 |
