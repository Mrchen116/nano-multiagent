# bugfix-810 桌面受管节点监督与登录自启

## 原始报告

> 健康常驻节点每轮结束3秒后新拉Node完整inspect及通读日志、探测worker/Chrome。改轻量，实计进程/重读次数，保持崩溃恢复；区分会话内手动停止和下一次启用自启的系统登录，避免随便重开窗口就复活；注册/注销系统自启失败应如实反馈、设置页与托盘勾选同步。

## 现象与根因

基线 1bdc4646c。feat-790 引入的监督循环（c75e0415e）把正常运行期间也存在的 gateway 状态文件用作异常标记。每次循环都启动 local-admin inspect，重新读取 gateway.log 并探测 Worker、Chrome。持久手停标志会跳过所有启动检查，包括登录项以 --background 拉起宿主的那一次。设置页读取节点偏好，托盘读取系统登录项，两边还会忽略系统写入错误。

## M1-fix 验收

复用 macOS socket 和 Windows 命名管道检查健康节点。保留首次版本检查、绑定身份、节点异常恢复与手停意图。用隔离节点在监督循环边界计数，核对设置与托盘的共同写入路径、操作失败后的实际状态，并在原生 runner 回归。

## 修复

- 受管宿主按当前服务及登录账号执行首次版本核对。节点运行期间通过原有 Unix socket / Windows 命名管道发送 local.ping。IPC 中断时才调用带 owner 和 PID 出生时间校验的轻量 inspect；诊断页仍可读取日志、探测 Worker 与 Chrome。兼容旧 bundle 的 inspect 入口。
- 登录项的 --background 启动可以恢复手停节点。普通窗口重开继续尊重手停标志。Windows 登录任务已先恢复节点时，宿主只清理旧手停意图。宿主将启停、配置保存、自启开关与关闭串行化。
- 设置与托盘显示当前连接的有效登录状态，依据为系统 Desktop 登录项与连接的自启偏好，以及 Windows 上该连接自己的登录计划任务。启停失败保留原状态并提示原因。其他服务的绑定和计划任务维持各自的登录设置。
- 本次对应现有 [Desktop current spec](../../../specs/im/desktop-client.md) 的登录自启、手动启停、异常恢复及受管更新场景，无新协议或数据迁移。

## 验证

macOS 原生宿主与隔离的真实 Gateway / DSH。修复前冷启动的 inspect 读取了一次 gateway.log；随后 11 秒记录到 4 个新 inspect PID，其中 3 次整文件读取在观测窗口内完成。修复后首次轻量检查只启动 1 个进程，日志读取为 0；随后 11 秒内两个计数均为 0。

可从仓库根目录运行 `node apps/desktop/tests/node-lifecycle.mjs <宿主可执行文件> <已构建的源码或解包目录>`。用例在已绑定的临时连接中断言健康期 10 秒零子进程及日志读取、杀死网关后恢复新 PID、冷启动时版本不匹配重启、设置页错误反馈与实际状态、手停后禁用登录 / 普通启动保持离线及启用登录恢复。两端候选构建均调用此用例。Windows 另使用该连接的 DesktopGatewayHost 核对真实 Task Scheduler 注册与注销登录触发器。

实际系统注销登录和原生托盘鼠标交互未在本机执行。登录项实参由隔离宿主复现，设置页收到托盘事件后的勾选变化由前端交互测试验证。平台与整合范围见 [review.md](review.md)。
