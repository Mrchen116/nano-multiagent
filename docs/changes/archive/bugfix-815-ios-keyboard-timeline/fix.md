# bugfix-815：iOS 键盘收起后聊天底部留白

## Relations

- Related: [bugfix-763 原生聊天阅读连续性](../bugfix-763-ios-chat-continuity/design.md)

## 原始报告

> 输入法展开又折起就变成这样了，ios版本。快修模式弄一下，不需要给我亲测。

截图显示原生会话的最后一条消息与输入区之间出现大块留白。按快修实施，由 Agent 验证。

## 现象与根因

键盘收起会扩大聊天视口。尾部有可能仍停在较小视口中的位置，最后一条消息可见，但和输入区之间有大块空白。iPhone 17 Pro 模拟器用合成消息观察到相同留白，出现在首次进入时，键盘往返后自行恢复。键盘收起后仍留白的状态通过原生滚动几何回归测试构造。

bugfix-763 用最后一条消息的实际位置判断尾部是否可见。这个判断也被用来停止跟随最新的自动校正，漏掉了尾部已经可见但与展开后视口底部脱离的情况。

## 事后实现

在跟随最新且消息列表可滚动时，用同一份原生快照读取末条消息和有效视口。若尾部已经可见但间距超过布局预留量，用现有 UIKit 位移校正将它对齐到底部。间距由消息间隔、尾部标记高度和内容边距共同确定。尾部离屏时沿用消息跳转，历史阅读沿用其阅读锚点。短会话使用现有顶部对齐。

本次只改 iOS 原生聊天布局，可通过回退实现提交恢复原行为。没有数据迁移。现行 [iOS 聊天阅读连续性](../../../specs/im/ios-client.md#requirement-原生聊天阅读连续性) 已规定键盘和输入区变化时维持跟随最新，本次无长期契约增量。

## 验证

- Agent 在独立 iPhone 17 Pro 模拟器中打开 40 条合成消息的原生会话并展开、收起系统键盘。修复前，三个阶段的底部间距依次约为 206、29、29 pt。修复后均为约 29 pt。
- 两条消息的短会话在同一模拟器中完成键盘往返，消息位置维持顶部对齐。
- 原生回归测试构造键盘收起且仍沿用旧偏移的状态，验证消息保持可见，底部间距从 329 pt 恢复至 29 pt。见 [ChatScrollPolicyTests](../../../../src/IM/ios/Tests/ChatScrollPolicyTests.swift)。
