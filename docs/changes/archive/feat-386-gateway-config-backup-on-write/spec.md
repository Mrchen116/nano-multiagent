# feat-386: Gateway 配置写前自动备份

## Relations

- Related: bugfix-362-im-ghost-agent-reconcile

## 原始需求

> 这个写前备份很好，做这个需求

（承接上文对话：Gateway 的 `save_local_config` 是整文件重写——每次在前端新建/改 agent 都会把整个 `~/.nano-assistant/config.yaml` 重写一遍，注释会被抹掉；若哪次在不该用默认配置的上下文里跑了 Gateway 并触发一次 save，主 config 会被静默重写覆盖，无备份、无法恢复。`code_review` agent 的丢失即最可能源于此类静默覆盖。用户认可"写前备份"作为护栏：覆盖前先把旧文件存成备份，即使被误写，上一版永远能捞回来。）

## 澄清记录

- Q1: 备份保留策略——只留最近一份（单个 `.bak`，每次覆盖）还是带时间戳的多份历史（保留最近 N 份）？
  A(原话): 同意你的
  Agent 解读: 采纳推荐——带时间戳的多份备份，保留最近若干份，超出自动清理。理由是单份备份扛不住"连续两次误写"（第二次坏写会把备份也污染），多份能按时间挑回想要的版本。具体保留几份属实现细节，留给 design。

- Q2: 备份适用范围——只给主配置 `~/.nano-assistant/config.yaml` 备份，还是所有被写的 config（含 worktree 一次性副本 `.gateway-config.yaml`）都备份？
  A(原话): 对
  Agent 解读: 采纳推荐——只给主配置备份；worktree 里的一次性 `.gateway-config.yaml` 副本不备份（它本就是临时拷贝、e2e-down 即删，备份纯噪音）。"哪份算主配置"的判定逻辑属实现细节，留给 design。

- Q3: 备份失败（磁盘满 / 无权限）时——让本次配置保存（前端那次新建/改 agent）也失败并报错，还是照常保存只是没备份成？
  A(原话): 按你设计，我没思考
  Agent 解读: 用户授权按推荐定。采纳——备份失败则本次保存失败并报错，把 agent 创建/编辑操作挡下来。理由：备份的价值就是"覆盖前留后路"，若备份没写成却照样覆盖，等于在最高风险时刻（磁盘异常态）无保护地抹掉旧配置，正是要防的场景；宁可这次编辑失败、用户看到明确报错去处理，也不让"静默覆盖且无备份"重演。

## 用户场景

运维这台 Gateway 的人（也就是在 Web IM 前端建/改 agent 的你）有一份长期维护的主配置 `~/.nano-assistant/config.yaml`，里面是 agent 名单、模型 provider、注释等手工内容。

今天的隐患：每当在前端新建或编辑一个 agent，Gateway 会把整个主配置**全文重写**一遍落盘。正常情况下这只是"加一个 agent、重排字段、抹掉注释"，问题不大；但一旦某次 Gateway 在不该用主配置的上下文里跑起来（漏传 `--config`、或被错误地以默认配置启动），又恰好触发一次写盘，主配置就会被静默覆盖成一份不完整的版本——丢 agent、丢注释，且**没有任何可恢复的旧版本**。`code_review` agent 的消失最可能就是这么来的：覆盖发生时无人察觉，事后也捞不回来。

变更后要达到的体验：**主配置每次被写盘前，旧内容先被存成一份带时间戳的备份**。这样即便某次写盘把主配置写坏了，运维的人也能从备份目录里找到覆盖前的那一版，原样恢复——丢失从"不可逆"变成"随手可捞"。备份会保留最近若干份、自动清理老的，所以连续两次误写也不会把后路一起埋掉。万一连备份都写不出来（磁盘满 / 没权限），这次保存宁可直接失败报错，也绝不在没有后路的情况下覆盖主配置。

worktree e2e 跑批用的那些一次性配置副本（`.gateway-config.yaml`）不在此列——它们本就是临时拷贝、跑完即删，不需要备份。

## 验收标准

### Requirement: 主配置写盘前自动留一份可恢复的备份

#### Scenario: 编辑 agent 触发主配置写盘
- **GIVEN** 主配置 `~/.nano-assistant/config.yaml` 已存在且有内容
- **WHEN** 运维的人在前端新建或编辑一个 agent，使 Gateway 写盘主配置
- **THEN** 写盘完成后，备份位置出现一份新备份，其内容与"本次写盘前"的主配置完全一致
- **AND** 主配置本身按预期更新成功

#### Scenario: 主配置被写坏后从备份恢复
- **GIVEN** 某次写盘把主配置覆盖成了不想要的版本（如丢了某个 agent）
- **WHEN** 运维的人查看备份位置
- **THEN** 能找到覆盖前那一版的备份，可原样恢复回主配置

### Requirement: 备份保留最近多份并自动清理

#### Scenario: 多次写盘后保留时间戳历史
- **WHEN** 主配置被连续多次写盘
- **THEN** 备份位置保留最近若干份带时间戳的备份（而非只有最后一份）

#### Scenario: 备份数量超过上限
- **GIVEN** 备份份数已达到保留上限
- **WHEN** 又发生一次写盘并产生新备份
- **THEN** 最旧的备份被自动清理，备份份数维持在上限内

### Requirement: 备份失败时保护主配置不被无后路覆盖

#### Scenario: 写备份失败（磁盘满 / 无权限）
- **GIVEN** 备份位置无法写入（磁盘满或权限不足）
- **WHEN** 运维的人编辑 agent 触发主配置写盘
- **THEN** 本次保存失败并给出明确错误
- **AND** 原主配置文件保持不变，未被覆盖

### Requirement: 首次写入与一次性副本不产生多余备份

#### Scenario: 主配置文件尚不存在时首次写入
- **GIVEN** 主配置文件还不存在（首次启动 / 首次落盘）
- **WHEN** Gateway 首次写盘主配置
- **THEN** 正常写入成功，不因"无旧文件可备份"而报错，也不产生空备份

#### Scenario: worktree e2e 写一次性配置副本
- **GIVEN** 在 worktree 内以 `--config .../.gateway-config.yaml` 跑 Gateway
- **WHEN** e2e 过程中该一次性副本被写盘
- **THEN** 不为该副本产生备份文件

## 范围与非目标

- 在范围：
  - 主配置 `~/.nano-assistant/config.yaml` 写盘前的自动备份（带时间戳、多份、自动清理）。
  - 备份写失败时让本次保存失败并报错、保护原文件不被覆盖。
- 非目标：
  - **不做** "Gateway 在 worktree 下落到默认主配置就拒绝启动" 的硬护栏（上文讨论过的另一可选层，本期不做）。
  - **不做** 保留主配置里的 YAML 注释——全文重写仍会抹注释，本期只保证"覆盖前有备份可捞"，不改 `save` 的序列化行为。
  - **不做** 备份的 UI 展示 / 前端恢复入口——恢复是运维的人在文件系统层手工操作。
  - **不做** 对 worktree 一次性副本 `.gateway-config.yaml` 的备份。
