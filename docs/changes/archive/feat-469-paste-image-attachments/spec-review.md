# Spec 评审：feat-469

**结论**：Approved

## 核实台账

| 原子 | 核实动作 | 结论 + 证据 |
|---|---|---|
| Requirement「聊天输入框支持把剪贴板图片加入待发附件」 | 是否挂有 Scenario、是否收口核心能力 | ✓ 挂有「粘贴单张截图」「粘贴同时带有文本表示的图片」「一次粘贴多张图片」3 条 Scenario，覆盖图片进入待发区、混合内容判定和多图边界。 |
| Scenario「粘贴单张截图」 | WHEN/THEN 结构、THEN 是否用户可观察、是否可追溯 | ✓ 结构完整；THEN 为“图片出现在 composer 的待发附件区”“用户可以删除该图片或将其随消息发送”，均是用户可观察结果，并对应用户场景“截图随即出现在 composer 的待发附件区”“可以删除误粘贴的图片”。 |
| Scenario「粘贴同时带有文本表示的图片」 | 红线、混合内容边界、叙事追溯 | ✓ THEN 为“图片进入待发附件区”“输入框不额外插入网页地址、替代文本或其他伴随内容”，没有协议或内部实现条目；对应用户场景“同时携带图片和文本表示……以图片附件为本次粘贴结果”。 |
| Scenario「一次粘贴多张图片」 | 红线、多项边界、叙事追溯 | ✓ THEN 为“所有合规图片按剪贴板中的顺序出现在待发附件区”，是用户可观察结果；对应用户场景“一次粘贴包含多张图片时，所有合规图片按剪贴板顺序进入待发区”。 |
| Requirement「普通文本粘贴行为保持不变」 | 是否挂 Scenario、是否覆盖回归边界 | ✓ 挂有「粘贴纯文本」「粘贴非图片文件」2 条 Scenario，既覆盖原始纯文本诉求，也覆盖非图片剪贴板边界。 |
| Scenario「粘贴纯文本」 | 红线、原始诉求追溯 | ✓ THEN 为“文本按浏览器原有行为插入当前光标位置”“待发附件区不新增附件”，直接对回原始需求“剪贴板为纯文本 → 保持现有文本粘贴行为不变”。 |
| Scenario「粘贴非图片文件」 | 红线、异常输入覆盖 | ✓ THEN 为“不把该文件加入待发附件区”“输入框的普通粘贴行为不被阻断”，是用户可观察的异常输入结果；对应范围“纯文本和非图片粘贴回归保护”。 |
| Requirement「粘贴图片与其他附件入口共享限制和失败反馈」 | 是否挂 Scenario、是否覆盖成功与失败 | ✓ 挂有「粘贴合规图片」「粘贴图片被拒绝或上传失败」2 条 Scenario，覆盖一致状态、校验拒绝、上传失败及部分成功保留。 |
| Scenario「粘贴合规图片」 | 红线、原始诉求追溯 | ✓ THEN 为“与通过其他附件入口加入的图片呈现相同的待发状态和删除能力”，是产品可见结果；对应原始需求“chip 列表可见、可删除”及“共用同一份校验”。 |
| Scenario「粘贴图片被拒绝或上传失败」 | 红线、失败态与部分失败覆盖 | ✓ THEN 为“显示可理解的失败反馈”“失败项不进入待发附件区，已经成功加入的附件继续保留”，均可由用户观察；对应用户场景“某张上传失败，已成功的图片仍保留，失败项给出明确反馈”。 |
| 澄清 Q1 | A 段是否保留用户原话、结论是否被后文贯彻 | ✓ A 为用户原话“中途我不会任何介入不用问我任何问题”，保留口语颗粒；Agent 解读仅说明自主收口，未冒充原话。 |
| 用户诉求「输入框聚焦时用 Ctrl+V / Cmd+V 粘贴图片」 | 用户场景与验收是否有落点 | ✓ 用户场景写“光标仍停留在……输入框中”“按下系统粘贴快捷键”；Scenario「粘贴单张截图」以输入框可编辑为 GIVEN、系统粘贴快捷键为 WHEN。 |
| 用户诉求「图片成为 pending attachment，chip 可见、可删除」 | 验收是否完整覆盖 | ✓ Scenario「粘贴单张截图」明确“图片出现在 composer 的待发附件区”“用户可以删除该图片或将其随消息发送”。 |
| 用户诉求「纯文本保持原粘贴行为」 | 正常与附件误判是否覆盖 | ✓ Scenario「粘贴纯文本」同时断言文本插入光标位置和附件区不新增附件。 |
| 用户诉求「图片与拖拽/选择器共用格式、大小限制」 | 合规与拒绝两侧是否覆盖 | ✓ Scenario「粘贴合规图片」引用“当前附件格式和大小限制”；Scenario「粘贴图片被拒绝或上传失败」覆盖不符合当前附件限制的结果。 |
| 用户诉求「图片粘贴沿用失败反馈」 | 上传失败、部分成功、可继续操作是否覆盖 | ✓ Scenario「粘贴图片被拒绝或上传失败」要求可理解反馈并保留已成功附件；用户场景明确用户可继续编辑或重试。这里的“重试”可由再次执行粘贴动作满足，未要求新增专用重试控件。 |
| 工作流指令「中途不介入、不提问；code-review 只用一个 subagent」 | 是否误写成产品验收、是否被记录 | ✓ 原话完整保留在【原始需求】；不属于产品能力，未爬入【验收标准】。Q1 对“不提问”作了流程解读；code-review 数量由 orchestrator 执行，不应成为本 spec 的产品 Scenario。 |
| 范围「桌面浏览器中的图片粘贴」 | 范围是否有无歧义验收落点 | ✓ 范围明确收口为“桌面浏览器中、聊天输入框聚焦时通过 Ctrl+V / Cmd+V 触发的图片粘贴”，与用户场景“桌面系统”“系统粘贴快捷键”和 Scenario「粘贴单张截图」完全一致，不再含缺少验收落点的移动端承诺。 |
| 范围与非目标 | 是否明确、是否与原始需求自洽 | ✓ 在范围列出图片/伴随文本、多图顺序、附件一致性及回归保护；非目标明确排除主动读取剪贴板、权限、非图片附件、服务端协议和 composer 重做，与 issue 的事件式粘贴边界自洽。 |
| Relations | 是否有依赖/关联落点 | ✓ 明确写有“Closes: #202”“Related: feat-340”。 |
| 文档完整性与自洽 | 是否残留 TBD/空占位、是否混入实现验收 | ✓ 无 TBD、待澄清或空 Q/A；用户场景、验收标准、范围与非目标均有实质内容；实现提示仅作为【原始需求】原话保留，没有爬入验收标准。 |
