# feat-510: 统一工具审批模型

## Relations

- Related: refactor-476

## 原始需求

> 当前agent审批工具调用复用的agent自己的模型，我想改为所有统一用一个模型，通过配置文件来控制

## 澄清记录

- Q1: “所有统一”要覆盖整个共享内核（Coding CLI、PA 的 Web IM / 飞书 / heartbeat / cron / 子 Agent），还是只覆盖 PA 下的多个 Agent？
  A(原话): 我指的是PA产品，因为配置文件对应的是这个产品的。内核可以考虑是支持两种模式，指定某个模型，或复用agent自己的模型
  Agent 解读: 产品目标只要求 PA 的所有 Agent 可统一使用一个审批模型；Kernel 提供显式指定审批模型与复用当前 Agent 模型两种能力，Coding CLI 是否指定由其自身产品配置决定。
- Q2: PA 配置没有指定审批模型时，应该怎么处理？
  A(原话): 好
  Agent 解读: 用户接受推荐：未配置时继续复用各 Agent 自己的模型；只有显式配置审批模型时，PA 的所有 Agent 才统一使用该模型。
- Q3: 如果配置的审批模型没有出现在 `llm.providers` 模型列表中，PA 应该拒绝启动，还是静默回退到 Agent 自己的模型？
  A(原话): 对
  Agent 解读: 用户接受推荐：PA 启动时校验显式审批模型；未注册时拒绝启动并明确指出配置错误，不静默回退。
- Q4: 统一审批模型是否只用于“自动判断这次工具调用允许、拒绝还是转人工”的模型调用，而 Agent 的正常回复、工具执行后的继续推理仍使用 Agent 自己的模型？
  A(原话): 对
  Agent 解读: 用户接受推荐：专用审批模型只负责自动权限分类，不改变 Agent 的正常对话、工具执行及工具结果后的续跑模型。
- Q5: 运行过程中专用审批模型超时或调用失败时，要不要临时回退到 Agent 自己的模型？
  A(原话): 不回退，选啥模型就是啥模型
  Agent 解读: 显式选择审批模型后，该选择不可被运行时错误降级；失败进入既有权限失败处理，不改用 Agent 模型或其他模型。
- Q6: 修改 PA 配置里的审批模型后，是重启 Gateway 才生效，还是运行中自动热更新？
  A(原话): 好
  Agent 解读: 用户接受推荐：审批模型随 PA 顶层 LLM 配置在 Gateway 启动时生效；修改后需重启 Gateway，不为该配置单独增加热更新。

## 用户场景

运维者在一个 PA Gateway 中配置了多个 Agent，各 Agent 可以使用不同的对话模型。当前自动工具权限分类会复用发起工具调用的 Agent 模型，因此同一套权限规则会分散到不同模型上执行，成本、速度和判断表现也随 Agent 配置变化。

运维者希望能在 PA 配置文件中选择一个已注册模型，专门承担这个 Gateway 内所有 PA Agent 的自动工具权限分类。无论工具调用来自 Web IM、外部渠道、后台任务还是 Agent 派生运行，只要进入自动权限分类，都使用同一个专用模型；各 Agent 的正常对话和工具结果续跑仍使用自己的模型。

该配置是可选的。未配置时继续保持当前行为，由权限分类复用每个 Agent 自己的模型。显式配置后，选择就是硬约束：配置错误时 Gateway 不启动，运行中模型调用失败时也不改用 Agent 模型或其他模型。

## 验收标准

### Requirement: PA 可统一指定自动工具权限分类模型

#### Scenario: 不同对话模型的 Agent 共用专用审批模型
- **GIVEN** PA 注册了模型 A、B、C，两个 Agent 分别使用 A 和 B，配置文件选择 C 作为专用审批模型
- **WHEN** Gateway 重启后两个 Agent 分别触发需要自动权限分类的工具调用
- **THEN** 两次自动权限分类都使用 C，不使用 A 或 B

#### Scenario: 所有 PA 运行来源遵守统一选择
- **GIVEN** PA 已选择专用审批模型 C
- **WHEN** Web IM、外部渠道、heartbeat、cron 或 Agent 派生运行触发自动工具权限分类
- **THEN** 对应分类均使用 C，不因入口、Agent 或运行来源改变模型

#### Scenario: 专用审批模型不改变 Agent 对话模型
- **GIVEN** Agent 使用模型 A，PA 使用模型 C 进行自动权限分类
- **WHEN** Agent 完成权限判断、执行工具并继续回复
- **THEN** 只有自动权限分类使用 C，Agent 的正常回复与工具结果续跑仍使用 A

### Requirement: 未指定专用审批模型时保持现有行为

#### Scenario: 配置省略审批模型
- **GIVEN** PA 配置文件没有指定专用审批模型，两个 Agent 分别使用模型 A 和 B
- **WHEN** 两个 Agent 分别触发自动工具权限分类
- **THEN** 分类分别复用 A 和 B，Gateway 正常启动和运行

### Requirement: 显式审批模型必须真实生效且不静默降级

#### Scenario: 配置未注册的审批模型
- **GIVEN** PA 配置文件选择的审批模型不在 `llm.providers` 已注册模型中
- **WHEN** 运维者启动 Gateway
- **THEN** Gateway 拒绝启动，并明确指出审批模型配置无效

#### Scenario: 专用审批模型运行时不可用
- **GIVEN** PA 已选择专用审批模型 C
- **WHEN** C 的自动权限分类调用超时或失败
- **THEN** PA 不改用 Agent 模型或其他模型重试分类
- **AND** 该次工具调用进入既有的权限失败处理：有人值守时转显式审批，无人值守时遵守已有 unattended fallback

### Requirement: 审批模型随 Gateway 重启切换

#### Scenario: 修改配置后重启
- **GIVEN** 当前 Gateway 使用审批模型 C，运维者把配置文件改为模型 D
- **WHEN** Gateway 尚未重启
- **THEN** 当前进程继续使用 C
- **WHEN** 运维者重启 Gateway
- **THEN** 后续自动权限分类统一使用 D

## 范围与非目标

- 在范围：PA 配置文件可选的统一审批模型；PA 所有 Agent 和运行来源的自动工具权限分类；未配置时复用 Agent 模型；启动校验、运行时不回退和重启生效语义；Kernel 能按消费者选择使用显式模型或当前 Agent 模型。
- 非目标：改变 Coding CLI 的现有模型选择；提供每 Agent 审批模型覆盖；在 Web IM 增加审批模型设置界面；改变 Agent 正常对话模型；修改权限规则、分类提示、人工审批卡片或 unattended fallback；运行中热更新该配置。
