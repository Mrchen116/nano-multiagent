## 用户场景

S1：用户在内部 IM 或飞书让 Agent 展示页面截图、已有图片或生成的图表。Agent 用可用工具取得图片，在解释中自然穿插图片。用户在电脑或手机里直接看到内容，无需去 Agent 所在机器寻找文件，也不需要再要求它执行一次渠道专属发送。

S2：用户从飞书发起请求，在飞书原聊天和内部 IM 影子会话看到同样的图文内容；从内部 IM 的影子会话发起请求时，回复只在内部 IM 出现。带运行信息页脚的飞书回复也能展示图片。群聊和中间说明沿用既有回复规则。

S3：用户刷新页面、切换到手机，或 Agent 所在节点重启后，仍能查看已经交付的图片。原截图被删除或覆盖不改变历史回复。内部 IM 暂不可用时，飞书仍能收到图片，IM 恢复后补齐对应历史。

S4：图片无法读取、格式不支持、超限或上传失败时，用户仍能阅读其余说明，并在图片对应位置看到明确失败提示。无图片回复、代码示例中的图片语法以及既有用户发图体验不受影响。

S5：机器截图可能含私人信息。内部 IM 中这类图片仅对有权查看对应会话的用户开放；未登录或其他用户拿到图片地址，也不能直接查看。Agent 不能利用回复图片语法额外读取本来无权读取的文件。

## 验收标准

### Requirement: 当前会话能够接收 Agent 图文回复

#### Scenario: R1-S1 跨机器查看本地截图
- **GIVEN** Agent 已通过可用工具取得其运行机器上的 PNG、JPEG 或 WebP 图片
- **WHEN** 用户在内部 IM 请求展示该图片
- **THEN** 用户在电脑和手机的同一聊天中直接看到保持原始比例的图片
- **AND** 无需访问 Agent 机器或手工上传文件。

#### Scenario: R1-S2 保持图文顺序与纯图片回复
- **WHEN** Agent 回复包含前文、两张图片及图片之间和之后的说明，或仅包含一张图片
- **THEN** 用户按回复中的顺序看到内容，每个引用位置展示一次图片
- **AND** 纯图片回复不增加无意义正文，图片可放大审阅。

### Requirement: 飞书和内部 IM 保持既有路由与呈现规则

#### Scenario: R2-S1 飞书原聊天与影子会话
- **WHEN** 用户在飞书私聊或按既有触发规则在群聊请求图片回复
- **THEN** 原飞书聊天和内部 IM 影子会话呈现等价的图片及说明
- **AND** 普通富文本回复与开启运行信息页脚的回复都能显示图片，中间可见图文说明也沿用原聊天投递。

#### Scenario: R2-S2 影子会话内部入口不回写飞书
- **WHEN** 用户在内部 IM 的飞书影子会话请求图片回复
- **THEN** 图片和说明只出现在内部 IM，不向飞书原聊天另发消息。

### Requirement: 已交付图片稳定可回看

#### Scenario: R3-S1 历史不依赖原文件和节点在线
- **GIVEN** 用户已在内部 IM 收到图片回复
- **WHEN** 原文件被删除或覆盖，Agent 节点重启或离线，用户刷新页面或重新登录
- **THEN** 用户仍能查看交付时的同一张图片。

#### Scenario: R3-S2 IM 暂不可用时飞书继续工作
- **GIVEN** 飞书可用而内部 IM 暂不可用
- **WHEN** Agent 响应飞书请求并回复图片，随后内部 IM 恢复
- **THEN** 用户先在飞书收到图片，恢复后在影子会话看到对应图文历史
- **AND** 影子会话不因恢复重复出现同一气泡。

### Requirement: 图片准备和失败不破坏正文

#### Scenario: R4-S1 图片加载过程
- **WHEN** 内部 IM 正在接收含图片的回复而图片尚未就绪
- **THEN** 已到达的正文可阅读，图片位置显示加载状态，随后显示图片或明确失败状态
- **AND** 不闪现本机文件路径或破图图标。

#### Scenario: R4-S2 单图失败或超限
- **WHEN** 某张图片丢失、不可读、格式不支持、超过单图 10 MiB，或一次回复引用超过五个不同图片来源，或上传图片失败
- **THEN** 相应位置显示图片未能展示的原因，正文和其他可用图片继续呈现
- **AND** 不声称失败图片已经发送，不无限加载。

#### Scenario: R4-S3 原有消息行为不回归
- **WHEN** 用户接收纯文字、可获取的公网图片回复或包含图片语法的代码示例，或向 Agent 发送图片
- **THEN** 原有文字与图片能力保持可用，代码示例保持原文且不触发图片发送。

### Requirement: 图片遵循会话访问范围与文件权限

#### Scenario: R5-S1 私密图片不可通过地址越权查看
- **GIVEN** 用户在内部 IM 收到本次能力托管的图片
- **WHEN** 未登录用户或无权查看该会话的其他用户尝试打开其图片地址
- **THEN** 不能查看图片；有权用户可正常查看。

#### Scenario: R5-S2 图片语法不能额外取得文件权限
- **WHEN** 回复引用 Agent 无权读取、未准备为可交付产物的本地文件
- **THEN** 该文件不会被自动展示或发送，用户得到可读的图片失败说明。

## 范围与非目标

- 在范围：当前会话的普通 assistant 图文气泡（中间与最终）、飞书 Post/运行信息卡片、内部 IM/影子会话、PNG/JPEG/WebP 本地图片、既有公网/data 图片兼容、图片快照与恢复、受保护读取、加载/失败/放大体验、产品提示。
- 首版每气泡最多五个不同图片来源、单图最多 10 MiB；重复引用同一图片可在不同位置展示，但不重复保存或上传。
- 非目标：新增截图或图片生成工具、视频/音频/通用文件平台、跨会话 send_message 的新图片协议、历史公网附件迁移、外部图片 key 跨 Bot 迁移、为模型历史重新注入视觉输入、重做聊天 UI。
- 持久性保证针对已托管资源及已保存待恢复输出；磁盘损坏、主动删除会话或数据、从未保存成功的截图不在恢复保证内。沿用既有外部 provider 投递语义，不承诺跨系统绝对 exactly-once。
