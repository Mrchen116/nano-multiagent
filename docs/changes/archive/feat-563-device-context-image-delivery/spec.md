## 用户场景

1. 用户在自己的电脑或手机与远端 Agent 聊天，要求查看 Agent 生成的网页。Agent 知道执行机器、IM 服务、当前聊天和用户访问端不是天然同机；依据已有访问条件给出预览方式，对未知可达性如实说明，不把本机地址冒充用户可用链接。
2. Agent 在获准的项目目录生成截图，用户要求直接发图。Agent 使用原文件即可交付，无需为发送再复制到隐藏的固定目录。系统继续保护文件读取与外发边界，聊天成员获得可稳定回看的图片。
3. Agent 提交五张截图，其中一张来源不合法或无法读取。系统先向 Agent 解释失败及如何修正；Agent 修正后交付完整图文。用户不会先收到缺图的成品声明、内部失败占位文本或重试产生的重复气泡。
4. Agent 无法恢复交付时，用户收到 Agent 对未完成事项的清楚说明，不会被告知图片已发送或可以点击不存在的图片标题。普通回复和全局 Agent 的显式发送、Web IM 与飞书遵循同样的交付承诺。

## 验收标准

### Requirement: Agent 获得足够的设备与访问关系上下文

系统 MUST 向 Agent 提供当前执行设备、工作区、IM/聊天入口与已知访问关系，并区分已知条件与未知的用户设备可达性；不依赖模型猜测或写死个人生产 IP。

#### Scenario: 用户从另一台设备请求网页预览
- **GIVEN** Agent 在远端机器生成网页，用户从另一台设备聊天，存在已知可用的访问入口
- **WHEN** 用户要求查看效果
- **THEN** Agent 提供与已知访问条件相符的入口和必要说明，不将远端机器的回环地址当作用户可直接访问的入口。

#### Scenario: 访问条件未知
- **GIVEN** 当前上下文无法确认用户设备可达预览服务
- **WHEN** 用户要求查看效果
- **THEN** Agent 明确说明访问条件尚未确认，选择可交付截图或提出必要的访问条件确认，不把猜测的 IP 链接宣称为已可用。

#### Scenario: 更换执行节点
- **WHEN** 相同任务由另一执行设备上的 Agent 处理
- **THEN** Agent 给出的文件位置和访问说明对应实际执行设备，不沿用上一台机器的地址与路径。

### Requirement: 获准的本地图片不受固定交付目录限制

Agent MUST 能提交获准读取与外发的真实本地图片，文件位于工作区内或外都不以是否复制到 exports 为交付前提。引用文件本身不授予新增权限。

#### Scenario: 从原项目目录发送截图
- **GIVEN** 截图位于获准访问与发送的项目目录，包含工作区外的目录
- **WHEN** 用户要求 Agent 直接发送截图
- **THEN** 用户在原聊天中看到图片和对应说明，无需手动搬文件、访问 Agent 机器或打开临时预览服务器
- **AND** Agent 无需先将文件复制到固定交付目录。

#### Scenario: 无权发送的本地文件
- **WHEN** Agent 尝试发送未获准读取或外发的本地图片
- **THEN** 图片不会泄露给聊天成员；Agent 得到失败反馈并可按现有权限流程处理，而用户不会收到内部图片失败占位文本。

#### Scenario: 成功图片长期回看
- **GIVEN** 图片已经成功交付
- **WHEN** 原文件移除或执行节点离线后，聊天成员重新打开历史
- **THEN** 仍能看到交付时的图片，非成员仍不能通过同一图片地址读取图片。

### Requirement: 图片交付失败先返回 Agent 处理

准备与上传失败 MUST 返回给发送 Agent，说明失败对象、具体原因和可行的修正方向，不能通过替换图片为内部错误文本完成发送，也不能将未完成交付报告为成功。

#### Scenario: 五张截图中一张准备失败后恢复
- **GIVEN** Agent 准备发送五张图文，其中一张图片无法交付
- **WHEN** Agent 首次发送并根据失败反馈修正重试
- **THEN** 用户最终收到顺序正确的完整图文；准备失败期间不收到含内部错误占位的消息或宣称五张图已送达的不完整成品
- **AND** 重试不会重复发布同一份图文。

#### Scenario: 网络或本地来源错误可由 Agent 修正
- **WHEN** Agent 提交不能交付的回环地址、无法读取的文件或上传失败的图片
- **THEN** 发送 Agent 获得能区分失败原因并指导下一步行动的反馈，可改用获准本地原文件或其他有效来源恢复交付
- **AND** 用户消息正文不出现“（图片未能展示：图片来源不可用）”及同类内部交付错误。

#### Scenario: 无法恢复交付
- **WHEN** Agent 经处理仍无法完成图片交付
- **THEN** 用户收到 Agent 对未交付事实及可行下一步的清楚说明，不收到已发送成功的虚假承诺或要求点击不存在图片的提示。

### Requirement: 不同发送入口保持一致的交付语义

#### Scenario: 普通回复与显式发送跨渠道一致
- **WHEN** Agent 通过普通回复或向已有聊天显式发送图片，目标为 Web IM 或已支持的飞书聊天
- **THEN** 成功时用户看到顺序正确的图文；准备或上传失败时由 Agent 接收并处理，不把内部错误占位发布到聊天
- **AND** 保持既有目标聊天路由、成员权限和飞书影子历史的访问边界。

## 范围与非目标

在范围：

- PA Agent 的设备、工作区和访问关系上下文，覆盖普通回复与全局 Agent 的显式发送。
- 本地图片交付摆脱固定 exports 目录前提，同时沿用必要的读取与外发权限检查。
- 图片准备/上传失败向 Agent 回传、修正重试、真实成功反馈与最终未完成说明；用户不再承担内部错误恢复。
- 保持现有图片格式/大小/数量约束、图文顺序、持久回看、权限和目标路由；技术方案留给设计阶段。

非目标：

- 自动部署网页、开放端口、配置隧道或让任意用户设备自动加入 Tailscale；设备上下文不等于自动获得网络连通性。
- 放开任意文件读取/外发权限，或以允许内网 HTTP 图片抓取代替正式本地产物交付。
- 扩展到任意文件类型的全新交付产品，或改变 coding CLI 的产物体验。
- 承诺图片交付后浏览器断网、登录过期等所有读取故障均由 Agent 自动修复；本 unit 针对发送阶段错误，不取消既有客户端访问权限与必要读取重试。
- 回写或自动重发历史失败消息、部署或重启生产服务。本阶段仅建立 Full 需求首文档。
