## 澄清记录

1. 用户明确选择：在已有 Work 页面切换到具体执行的 DSH 原生轨迹视图，切换后再向对应 Gateway 现场读取。
2. Agent 解读：现有 Work 的主／子执行关系提供选择入口；概览与原生轨迹是同一工作的两种查看方式。用户最新授权已扩展到完成实现、验证并保留隔离测试服务供其回来直接体验。
3. 沿用当前契约：[IM Agent Work](../../../specs/im/agent-work.md) 允许有效公司成员查看全局 Agent Work，管理与审批仍依原有 owner 边界；原聊天和受保护附件继续按成员关系访问。本功能不另行改变这组权限。
4. Agent 设计范围：网页 Work 中只读检查执行过程，覆盖主执行及已有的关联执行；节点不可读取时提供真实反馈，已保存的工作记录仍可查看。iOS 新界面、执行控制与旧 Python 轨迹转换不在本期范围内。

5. 用户纠正：原生界面的信息完整性和交互本身是目标，不接受按 Work 摘要重新拼一个相似轨迹。时长、轮次、调用及搜索必须保留；检查器按原生记录类型显示系统提示词、工具目录、来源、原始内容、参数、结果、Schema、用量、选项和计时等适用信息。
6. 最终交付以真实测试服务上的官方组件和真实 DSH 会话为准；固定数据原型只说明外层嵌入，不能作为原生保真或产品验收证据。

## 用户场景

### U1：从整体进展深入一次执行

用户打开全局 Agent 的 Work，先看到熟悉的工作记录。在需要调查一次任务的执行细节时，切换到“原生轨迹”。页面读取该执行所在节点的真实记录，展示 DSH 的轮次、步骤、模型与工具活动、时间概览和记录检查器。用户不必离开 IM、寻找本机文件或登录另一套 DSH 页面。

### U2：查看委派工作并回到主执行

用户在 Work 中选择某个 subagent 或 Workflow 关联执行，再切换查看它的原生轨迹；始终知道自己在看哪次执行、它来自哪个主 Agent。切回工作记录或返回主执行时，不丢失已有查看位置，也不混入其他执行的结果。

### U3：在运行中观察并回看历史

执行仍在进行时，用户看到实际新增的记录；检查旧记录时，新内容不会强行把阅读位置拉回尾部。历史较长时可以继续向前读取。失败、取消、压缩和未报告的统计保持真实语义，用户能检查已有输入、输出及可展示的思考。

### U4：节点暂时不可读取

用户进入原生轨迹时节点离线，或查看中连接中断。页面明确说明暂不可读取或更新，不把旧画面当成当前在线事实，不显示虚构的完成。用户仍可切回已有工作记录；连接恢复后可以重新读取同一执行。

### U5：共享查看保持既有访问边界

有效公司成员查看他人的全局 Agent，仍能检查其 Work 与原生轨迹；这不会取得发送指令、审批、取消执行或修改配置的权限。原聊天和受保护附件仍遵循原来的访问规则。退出登录、换账号或资格被停用后，已打开的轨迹也不再继续返回数据。

## 验收标准

### Requirement R1：在 Work 内切换查看方式

#### Scenario R1.1：从工作记录进入原生轨迹
- **WHEN** 用户打开全局 Agent 的 Work 并切换到“原生轨迹”
- **THEN** 在原页面看到当前执行的 DSH 原生轨迹界面，以及清楚的执行名称、归属与读取状态。
- **AND** 返回“工作记录”后仍能继续原有的工作查看，不改变 Agent 的执行状态。

#### Scenario R1.2：尚无执行
- **GIVEN** Agent 尚未产生可查看的执行
- **WHEN** 用户选择原生轨迹
- **THEN** 页面显示“暂无可查看的执行”，不生成一条新执行来填充页面。

### Requirement R2：主执行和关联执行定位准确

#### Scenario R2.1：查看已选关联执行
- **GIVEN** Work 中已有主执行和一个关联子执行
- **WHEN** 用户选择子执行后进入原生轨迹，随后返回主执行
- **THEN** 每次显示的是所选执行自身的真实轨迹，并能辨认子执行与主 Agent 的关联。
- **AND** 快速切换时迟到的内容不会出现在另一执行的画面中。

#### Scenario R2.2：两种查看方式保留选择
- **WHEN** 用户在同一执行的工作记录和原生轨迹之间往返
- **THEN** 保留所选执行，以及各自已有的阅读位置。

### Requirement R3：原生轨迹按需读取并支持连续检查

#### Scenario R3.1：按需进入
- **WHEN** 用户只浏览工作记录，随后才进入原生轨迹
- **THEN** 原生轨迹在进入后才开始读取，并明确显示加载过程。
- **AND** 离开该视图后不再继续接收该视图的轨迹更新。

#### Scenario R3.2：历史与实时过程
- **GIVEN** 所选执行有较长历史并正在产生新记录
- **WHEN** 用户打开轨迹、向前查看历史并停留检查旧记录
- **THEN** 能继续读取更早的记录、看到真实新增内容，阅读位置不会被新内容强行拉回尾部。

#### Scenario R3.3：检查真实记录
- **WHEN** 用户选择原生轨迹中的模型、工具、压缩或终态记录
- **THEN** 可检查已有输入、输出、可展示的思考及已报告统计和时间信息。
- **AND** 未报告的数据保持未知，进行中、失败、取消与完成可以区分。

#### Scenario R3.4：原生工具条和联动完整
- **WHEN** 用户切换“时长”、折叠／展开“轮次”与“调用”，或搜索已加载记录
- **THEN** 保持 DSH 原生的等宽／时长投影、轮次与助手下工具调用折叠、搜索及输入／模型／工具三轨联动。
- **AND** 点击时间条会定位并选择同一条记录，打开对应检查器；原生支持的时间区间聚焦和缩放保留。

#### Scenario R3.5：完整模型可见输入和类型化检查器
- **GIVEN** 原生日志包含系统提示词、上下文注入、工具 Schema 和请求统计
- **WHEN** 用户查看完整轨迹并分别选择系统、上下文、助手、工具和请求记录
- **THEN** 这些记录按原生轮次／步骤与实际发生顺序显示；仅包含工具调用的助手消息仍可见。
- **AND** 适用检查器保留完整原文、来源、系统提示词及变更、当时的工具目录与 Schema、工具参数／结果、模型选项、用量和计时；不以当前配置填补缺失历史。
- **AND** 桌面检查器可以关闭和调整宽度，窄屏使用官方响应式检查方式，完整内容不会被永久截断。

### Requirement R4：读取失败和节点离线真实可辨认

#### Scenario R4.1：打开时无法读取
- **GIVEN** 对应节点不可连接、执行记录不存在或读取失败
- **WHEN** 用户打开原生轨迹
- **THEN** 看见对应的不可用或失败说明和适用的重试入口，仍可返回已保存的工作记录。

#### Scenario R4.2：查看中断开及恢复
- **GIVEN** 轨迹已经显示
- **WHEN** 节点或连接中断，随后恢复
- **THEN** 中断期间明确标记已加载内容不再更新，恢复后可以重新读取同一执行。
- **AND** 不因为查看或恢复轨迹而重新运行 Agent 或重发原任务。

### Requirement R5：查看权限沿用 Work，查看不会变成控制

#### Scenario R5.1：公司成员查看他人工作
- **GIVEN** 查看者为有效公司成员，且不是 Agent 管理者
- **WHEN** 查看该全局 Agent 的原生轨迹
- **THEN** 可以查看同属该 Agent 的执行，但不能通过该界面发送指令、处理审批、取消执行或修改配置。
- **AND** 点击原聊天或受保护附件仍遵循原有成员访问规则。

#### Scenario R5.2：失去访问资格
- **WHEN** 查看者退出登录、切换账号或被停用
- **THEN** 已打开的轨迹停止更新并清除当前账号的显示内容，之后不能继续读取旧轨迹或附件。

## 范围与非目标

- 在范围：Web 全局 Agent Work 的查看方式切换、主／关联执行定位、DSH 原生只读轨迹、按需历史与实时更新、失败与离线状态、既有查看权限和附件访问约束。
- 非目标：重做整个 Work 或 DSH 工作台；iOS 新轨迹界面；从轨迹发起执行、审批、取消、配置或模型变更；向 IM 持久复制完整原始轨迹；旧 Python 轨迹转换；修复 #331；新增业务调度或第二套执行引擎。
