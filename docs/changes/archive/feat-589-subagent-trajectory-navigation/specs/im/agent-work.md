# Agent Work 执行范围导航增量

> Target: docs/specs/im/agent-work.md

## ADDED Requirements

### Requirement: 从真实发起位置进入子 Agent 的本次执行

#### Scenario: 主动委派和后台维护
- **GIVEN** 主执行真实发起普通子 Agent、fork、记忆整理或技能复盘
- **WHEN** 用户阅读该发起位置
- **THEN** 能辨认用途、普通／fork、主动／后台及真实状态，并直接进入对应本次执行，不依赖顶部名称列表。
- **AND** 后台用途来自真实发起事实，不从内部标签或 UUID 猜测。

#### Scenario: 并行、重复唤起与嵌套
- **WHEN** 用户从并行发起点或同一子会话的不同唤起记录进入，或继续进入下一层委派
- **THEN** 按真实执行身份区分各次范围及父级来源；驻留期间继续收信不被虚构为新的执行。
- **AND** 刷新后仍可从持久发起记录进入同一次执行。

### Requirement: 本次范围忠于真实执行且保留完整检查

#### Scenario: 默认聚焦一次执行
- **WHEN** 用户进入已有真实边界的子执行
- **THEN** 同一个原生派生轨迹视图的时间概览自动选中本次起止，关联本次输入、模型请求、工具、输出与结束状态，可直接定位起止。
- **AND** 进入子执行时加载完整会话轨迹，保留 fork 继承历史及其他执行；仅以原生时间轴选区和区间外淡化标识本次范围，不过滤记录。

#### Scenario: 运行与异常状态
- **WHEN** 子执行正在运行、完成、失败、取消，或边界缺失、连接中断
- **THEN** 依据真实记录呈现状态；启动工具返回不代表执行结束，未报告的终点或结果不推测。
- **AND** 运行中范围延伸到真实最新记录，不强制移动旧记录的阅读位置；中断不被显示为实时更新，恢复读取不重跑任务。

#### Scenario: 检查全部原生明细
- **WHEN** 用户在原生派生视图中在完整轨迹中检查本次选区或其他历史
- **THEN** 保留既有官方轨迹检查能力，完整明细可达，来源与当前查看范围明确。
- **AND** 使用同一套原生组件，用户可直接调整或清除选区；顶部当前执行同步所查看的会话。

### Requirement: 父子导航保持阅读上下文与只读边界

#### Scenario: 返回发起位置
- **WHEN** 用户从子执行返回父级或从多层嵌套逐级返回
- **THEN** 恢复对应父级发起位置，以及原滚动、缩放和选择，可以继续原上下文。

#### Scenario: 跨屏与身份变化
- **WHEN** 桌面或窄屏的有效 Work 查看者进入、检查并返回子执行
- **THEN** 均能完成完整只读旅程，不要求为 Agent 管理者，不取得执行控制或额外附件权限。
- **AND** 离开 Work、退出登录、切换账号或访问资格失效时，相应读取停止并清除旧身份内容。
