# feat-604: 账号与策略的完整设置体验

## 原始需求

> 整个IM中，账号和策略，两个页面还没完成现代化的UI UX设计，还是毛坯状态，其他基本是了。对吧

> 那就把账号和策略这两个页面也做一下现代化 UI/UX 设计，和其他页面统一起来，信息架构和交互也一起理顺，不要只是换个皮。

## 澄清记录

无需新增问题。上下文是已实际查看的线上 Web IM 账号、策略和电脑页面。用户授权同时理顺信息架构与交互；本次覆盖 Web 桌面和手机布局，不扩展原生 iOS 或运行策略执行能力。

Agent 解读：沿用当前 IM 克制的青绿色强调、白色内容区、清楚的标题层级和自然导航；以用户目标重新组织内容，不保留重复设备清单和没有上下文的配置字段。

## 用户场景

用户从个人菜单或“我的账号”进入账号页，辨认当前登录身份、修改显示名，理解个人空间与团队资格的区别。需要连接或管理电脑时直接前往电脑页；没有电脑时得到可执行的引导。加入团队、等待批准或团队资格停用不应被误解为个人空间不可用。

团队管理员进入策略页，先判断实际附件存储是否接近上限，再查看服务和成员用量。历史策略预设与实际生效的限制明确区分，管理员可以维护这些预设但不会误以为保存等于运行时应用。普通团队成员可以阅读预设，不能修改或查看管理员容量明细。

两页的用户均能在桌面与手机上读懂主次、找到返回入口。修改后明确知道未保存、提交中、保存成功或失败；失败与后台刷新不丢失草稿，修正后可以重试。

## 验收标准

### Requirement: 账号页聚焦身份与空间，关联管理有明确去向

#### Scenario: S1 身份与资料编辑
- **WHEN** 用户进入账号页并修改显示名
- **THEN** 用户能辨认当前显示名与登录用户名，用户 ID 收入次级账号详情，不占用可编辑表单。
- **AND** 保存成功后资料与个人菜单同步更新，刷新后仍保留，成功反馈明确。

#### Scenario: S2 电脑管理与空状态
- **WHEN** 已连接电脑或尚未连接电脑的用户查看账号页
- **THEN** 页面以简洁摘要与明确入口引导至电脑管理，不重复设备列表、版本和诊断信息。
- **AND** 尚未连接时可继续助手设置；已有电脑时不无条件突出首次设置。

#### Scenario: S3 团队资格
- **WHEN** 未加入、待批准、有效成员、管理员或团队资格停用的用户查看账号页
- **THEN** 页面清楚呈现对应资格与下一步，并区别个人空间可用性；管理员可进入成员管理。

### Requirement: 策略页支持准确判断实际状态和预设用途

#### Scenario: S4 容量与预设分层
- **WHEN** 管理员进入策略页
- **THEN** 先看到实际服务附件用量、剩余空间和上限，上传中的占用计入判断，成员用量可按需查看。
- **AND** 策略预设按运行、安全、附件与留存分组，有单位与解释，并明确尚未接入执行，不声称保存即生效。

#### Scenario: S5 只读成员
- **WHEN** 普通有效团队成员进入策略页
- **THEN** 页面明确说明只读权限、以可读方式显示预设，不提供保存操作或管理员容量明细。

### Requirement: 修改流程清楚且可恢复

#### Scenario: S6 放弃与合法输入
- **WHEN** 用户编辑资料或策略预设后放弃修改，或输入空白显示名、空模型名、非正整数限制
- **THEN** 放弃恢复原值；无效输入在保存前有明确反馈，不提交无效值，未修改时不能保存。

#### Scenario: S7 保存失败与后台刷新
- **WHEN** 修改后保存失败或页面在后台重新加载数据
- **THEN** 草稿保持可见，失败可重试；提交期间不会产生重复保存，成功后退出未保存状态。

#### Scenario: S8 加载与容量故障
- **WHEN** 页面资料、预设或容量读取失败
- **THEN** 相应区域明确显示失败与重试入口，不无限显示加载，不把容量未知当作零用量，也不阻断无关区域。

### Requirement: 继承 IM 体验并适应设备

#### Scenario: S9 桌面、手机与语言
- **WHEN** 用户在桌面、手机窄屏或中英文环境使用两页
- **THEN** 标题、内容、状态与主要操作层次清楚，与电脑等既有页面一致；手机自然切为单栏，主要操作和返回入口可触达，不出现横向溢出。
- **AND** 可通过键盘操作，表单有明确标签，反馈可被辅助技术感知。

## 范围与非目标

- 范围：Web IM 账号与策略页的信息组织、导航、视觉、编辑反馈、容量展示和中英文响应式体验，以及相应行为契约和验证。
- 非目标：原生 iOS 改造；新账号安全功能；修改团队权限或审批；运行时应用历史策略；新增后端配置平台、存储配额编辑或附件清理功能；合并和生产部署。
