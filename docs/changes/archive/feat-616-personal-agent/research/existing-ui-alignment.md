实际读取并在隔离本地页面渲染当前仓库的 `AppShell`、`ConversationSidebar`、`MessagePane`、`global.css`、移动端判定 hook。通过 React Query 缓存提供合成会话；未修改这些产品组件。临时页面位于 `/tmp/feat616-ui-baseline-20261019/`，本轮在 8767 端口观察。它验证真实组件的布局和样式，不代表连接真实后端的产品验收。

| 现有结构 | 原型处理 |
| --- | --- |
| 桌面 48px 顶栏：nano IM、聊天/任务/智能体、用户菜单 | 保持位置、顺序、颜色和层级；增加个人助手快捷入口 |
| 左侧 262px 消息列表、搜索、会话分类、生成 skill | 保留消息列表用途；增加固定 PA 会话，移除全局左侧功能导航与目标列表 |

本轮核对桌面、自适应、768 和 390 宽度。原型是 HTML 示意，未替换为正式 React 页面；任务页与智能体页为导航背景示意，不构成重设计方案。原生 iOS 未做设备验收。

## 实际交互结果

- 林悦会话 → 让 PA 帮我回复 → 放入输入框 → 以本人身份发送。草稿可编辑；切到 PA 再回来仍保留，且不带入其他收件人输入框。
- 已授权观察的演示消息到达 → PA 私下提出接手 → 用户交办一次 → 自动整理公开资料。搜索、整理与内部协作不新增审批。
- PA 带推荐理由询问案例选择 → 选零售 → 自动准备演示页面与清单 → 具体材料分享一次确认 → 继续协调，不再逐条审批。
- 到达下一次跟进时间 → PA 自行复查；林悦确认时间与材料 → 更新原任务、停止该目标提醒，另一行程目标继续。
- 手机上列表可回到 PA；目标摘要、详情与输入框可达，底部导航仅在列表出现。
- 走查修正：原先返回列表会重置当前目标，已移除该重置；不同会话和目标各自保留草稿。
