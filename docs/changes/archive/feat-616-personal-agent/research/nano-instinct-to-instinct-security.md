# Instinct-to-Instinct：跨个人代理的隐私与授权边界

研究截止：2026-10-16。对象是 Noah Shinn 创办的 Instinct（Spear Street Technology），不是 AMD Instinct、兽医软件或第三方 open-instinct 克隆。本文专门调查个人代理之间的 Trusted Person network；不把 10 月 group agent 的规则自动套到 I2I。

## 结论

**I2I 确实增加了一条重要安全边界：别人自己的代理可以向你的代理提出请求，而你的代理掌握你的私有信息和操作能力。允许连接、允许询问、允许披露和允许执行必须分别成立。**

公开材料能支持：可信联系人准入、连接明确批准、按关系配置分享范围、文件原件直接进入接收代理工作区，以及部分用户经历的信息分享确认。不能据此证明权限均为确定性代码执行，也不能证明每次分享都有人确认、私有记忆不会进入 peer 会话、撤销会清除已送到对方的数据。

实际 I2I 相关负面例子是“惊喜被告诉男友”。它支持保密意图处理会出错；公开记录不足以证明系统绕过某个具体 ACL，更不是任意用户私有数据可被任意陌生人读取的证据。

## 1. 一手证据与版本顺序

### 2026-09-09：Trusted Person network 首次公告

[创始人原帖](https://x.com/noahrshinn/status/2097794967574028448)；[可读取镜像](https://twiscan.com/en/x/noahrshinn/2097794967574028448)。公告描述代理间协调，先早期访问、随后逐步铺开。限定可通信对象为 Trusted Person network；列举配偶、家人、同事和可信专业联系、小型本地商家。

原文短引：“Your Instinct will only be able to communicate with those in your Trusted Person network.”

这是一条**I2I 准入宣称**。它不说明所有 email、网页、文件入口也只接收可信人内容，也不定义可信联系人有权索取哪些字段。

### 2026-09-23：邀请链接与原文件传输

[创始人原帖](https://x.com/noahrshinn/status/2102896414514688212)；[镜像](https://twiscan.com/en/x/noahrshinn/2102896414514688212)。官方说收到邀请链接的人可发连接请求，连接仍需用户明确批准；链接能重建、旧链接能作废。另新增 PDF、图片、表格等文件直接传输：接收代理拿到工作区中的原文件，能分析、修改、继续用于工作。官方称传输文件采用发送者与接收者之间的端到端加密。

原文短引：“Every connection request still requires explicit approval on your end.”

没有公开的密钥管理、接收身份绑定、协议签名/重放保护规范。公告中作废的对象是**邀请链接**，不能解读成取消已有关系，或召回已接收文件。文件加密也不是文件内容安全验证。

### 2026-09-28：创始人详述分关系分享

[Colossus 原节目及日期、章节](https://colossus.com/episode/instinct-the-personal-agent/)，EP493，主持 Patrick O’Shaughnessy。官方章节 00:07:15 是可信网络，00:23:25 是敏感数据安全。[公开转录辅助核对](https://pod.wave.co/podcast/invest-like-the-best-with-patrick-oshaughnessy-48a998b1-8bc3-4e91-9c00-6d2f4d646fdd/noah-shinn-building-instinct-the-personal-agent-invest-like-the-best-ep493)。官方完整文本要求登录，本次未登录；转录由第三方提供，时间点可能因广告而偏移。

创始人描述不同联系人的不同权限：配偶可广泛分享；同事可限于工作日历及部分邮箱资料，其余排除。对方探询其他信息时，自己的代理会告诉自己。他把技术可见范围与社会信任共同描述为保护。另描述输入内容过滤、独立监控系统可拦截行动。

这是产品设计陈述，不是权限引擎实现证明。尤其“给一天权限”出现在**主持人的设想**中，不宜列为已上线的权限到期机制。访谈笼统说用户能收回数据控制，也没有说明 I2I 已送出副本如何处理。

### 2026-10-02：直接使用观察，存在分享确认

[Julia Kruslin：17 things I did with Instinct in September，第14项](https://aiforoperators.substack.com/p/17-things-i-did-with-instinct-in)。她请求自己的代理连接朋友代理，两者交流并向她转述；她报告涉及分享访问权或信息时，需要她先同意。

原文短引：“Anything that shared access or information needed my yes first.”

这是真实使用者报告，能支持**至少在她的配置和这些任务里存在确认**。文章没有完整策略配置、每次会话日志或对抗测试，不能推广成所有用户所有关系所有信息的强制逐次确认。作者同时提供邀请，属于体验文章，不是安全审计。

## 2. 已有具体失误：惊喜在代理之间流转后被说破

[Luba Yudasina 原帖，2026-09-15](https://x.com/LubaYudasina/status/2099658011748729059) 描述让自己的代理联系男友代理安排惊喜，并展示男友代理给他的消息。[转帖镜像可核对发帖文字及日期](https://twiscan.com/en/x/yoheinakajima)。[Business Insider 记者 Julia Pugachevsky 的 9 月 27 日报道转载](https://www.aol.com/articles/couples-using-viral-ai-agent-090001000.html) 描述她希望了解男友空闲时间和约会喜好，结果透露过多。

证据限制：本次读取了原帖文字的转帖镜像及记者报道，未成功读取完整原始截图；没有双方全量提示、权限、内部调用、修复状态。因此不还原具体哪一步、哪句原文越界，不声称当前版本可复现。

**分析：**这不需要陌生黑客，也不需要突破沙箱。A 的代理想替 A 保密，B 的代理却有向 B 汇报的正常动机。即使双方都“忠于主人”，整体也可能违反 A 的用途限制。可信关系未必解决“对方代理可以知道，但对方本人暂时不能知道”的冲突。安全设计应让发送者在传递前明确知道，是否存在、能否承诺这种接收方保密语义。

## 3. 应分别审查的五种权限

以下是本文分析框架，不是声称 Instinct 已实现的 schema。

1. **连接权限：**这个身份能否联系我？公告明确有连接审批。
2. **请求权限：**它可以请求什么任务？认识对方不意味着对方能修改我的日程或付款。
3. **读取权限：**我的代理为这个任务能访问哪些自己的数据？不能把自己的代理平时可读范围直接当成 peer 请求可读范围。
4. **披露权限：**答案或文件能发给哪个人/代理，允许哪些字段、用途和期限？读取某份邮件并不等于可以发送全文或派生摘要。
5. **执行权限：**谁的日历、资金、账号被操作，谁批准？A 对自己代理的指令不是 B 的授权。跨人协调不能自动把 A 的“请订好”升级成 B 的付款许可。

连接审核、关系 grant、任务批准可以共存。现有资料不足以判定默认 grant、每种动作的确认阈值，或自然语言如何转换成不可绕过的策略。不能把 founder 的“可配置范围”简化成“只靠一句系统提示”，也不能反向推定有完整硬 ACL。

## 4. I2I 特有风险与公开证据缺口

以下均为根据已公开能力推导的威胁模型，除惊喜案例外，不是发现了可复现的 Instinct 漏洞。

### 4.1 身份真实，不等于请求有权

可信朋友可能被盗号；可信代理可能读取恶意邮件或文件后转发污染内容。即使消息签名有效，也只说明它由该主体发出，不说明 owner 真批准了该请求。需核对 owner、agent、具体任务与当前 grant 的绑定，以及撤销和重放控制。

官方另有 [9月23日安全说明](https://x.com/noahrshinn/status/2102896837522804954)（[镜像](https://twiscan.com/en/x/noahrshinn/2102896837522804954)），描述沙箱、短期本地凭据和 identity-signed tool execution。这不是 I2I 消息认证协议的公开规范，也没有交代账户失窃后的 peer 信任恢复流程。

### 4.2 代理转述容易抹掉来源和授权等级

“我的主人说你的主人已同意”仍然是 peer 的声明。接收方若把它当作本人的确认，就会形成授权混淆。必须保留“谁说的、为谁、原始哪项许可”的可验证上下文。未找到公开 I2I 消息封装、签名字段、owner approval proof 或权限扩大防护测试。

### 4.3 文件传输扩大输入与副本边界

原文件进入接收工作区后，除了潜在恶意指令，还可能含有隐藏工作表、批注、修订记录、元数据等发送者未打算分享的内容。加密保障传送保密性，不删除这些内容，也不阻止收件代理将文档中的命令当成指令。

公开公告支持接收后分析/修改/持续使用，但未交代文件信任标签、自动执行限制、嵌入链接处理、文档内容进入长期记忆的策略。没有找到 I2I 附件注入的公开可复现实验。邮件注入旧案例不能直接充作这条链路的已验证漏洞。

### 4.4 A→B→C：关系信任不能自动传递

A 信任 B、B 信任 C，不表示 A 同意 C 获得 A 的资料。风险不只原文件转发，也包括 B 把 A 的数据概括进另一任务。应检查对来源、收件对象、用途限制的跟踪，以及转发是否重新征求 A 同意。

未找到官方多跳协议、委托链、不可再分享标记或跨代理派生信息控制规范。不能把自动协作能力本身当作任意多跳传递已经发生的证据。

### 4.5 私有记忆进入 peer 上下文的边界未知

[Supermemory，9月20日黑箱记忆研究](https://supermemory.ai/blog/reverse-engineering-instinct-memory/) 推测 Markdown 记忆、one-pager 与回顾注入；作者明确未查看源码，且是相关商业产品团队。该研究没有展示 owner 会话与 peer 请求处理上下文的对照。

因此不能确认“对方直接看到 one-pager”，也不能确认“peer handler 永远不加载私有记忆”。真正要核实的是：peer 请求先进入一个最小上下文的处理器，还是私有大上下文的个人代理？如果秘密已在上下文里，仅拦截新的 memory read 工具调用不足以阻止输出泄露。这是条件性分析。

### 4.6 窄字段仍可累积推断

即便只分享空闲时间，长期或高频询问也可能推断工作习惯、旅行或个人活动。应区分 free/busy、事件名、原因、位置，而不是仅有 calendar 一个宽范围。未看到 I2I 的字段粒度、查询预算、异常探询限制或最小答案策略公开说明。

### 4.7 撤销、到期和历史副本是不同问题

需要分别核对：取消邀请链接；删除可信联系；收窄某个 grant；终止进行中任务；到期授权；删除已送文件；清除对方记忆中的派生摘要。

现有一手公告只明确说明旧邀请链接可作废；访谈没有给出上述操作的一致性和时延承诺。已送出的信息不能因为上游断开连接就被假定从对方工作区、聊天、记忆、备份或再转发副本中消失。是否提供任何受控召回/删除机制未知。

## 5. 从公开证据可以给出的安全判断

- **有保护证据：**不是任意 agent 自由连接；有审批；有关系范围描述；有一位用户的任务分享确认体验；有官方监控与文件加密宣称。
- **有局部失败观察：**I2I 惊喜协调中发生不符合保密意图的披露。范围很小，不能扩大成任意私密数据泄漏。
- **没有足够证据：**代码级权限隔离、peer 专用上下文最小化、可验证委托链、文件注入抵抗、多跳控制、撤销传播、密码学身份生命周期和当前版本攻击成功率。
- **不采用的替代证据：**第三方 open-instinct 仿制项目的 PERMISSIONS、协议结构、before-tool 钩子等属于该项目自己的设计；不能拿来回答商业 Instinct 怎么实现。二手文章建议 mTLS，也不表示 Instinct 用了 mTLS。

## 6. 最值得向供应商核验的事项

1. 一个具体授权能否显示为“对方账户ID＋字段＋动作＋用途＋有效期”，而非仅自然语言备注？谁有权修改它？
2. peer 消息、附带文件能否改变 grant 或产生本人批准？owner 与 peer 在工具层如何区分？
3. peer 请求处理会话实际载入哪些私有 memory/one-pager？被拒任务会不会仍读取私有数据？
4. 每次披露是在模型内判断，还是另有模型不可修改的策略检查？摘要、附件、网页链接均覆盖吗？
5. 收到的文件会不会被写进长期记忆？其指令等级和来源标签是否在后续任务保留？
6. 是否允许再转发、代理代问、替第三人协调？如何追踪最初数据主体的授权？
7. 收窄权限或断开联系后，正在生成的答案、排队发送、定时任务怎样处理？已送副本如何处理？
8. 有无当前版本、针对 I2I 的独立对抗评估，包含成功/失败样本、配置、日期和明确分母？

实用建议：在上述边界未验证前，先只给具体任务所需的最小信息，例如候选时间而不是整个日历、筛选后的文档而不是原始综合文件。对敏感内容明确对象和用途并逐次审阅；不要以“可信联系人”或“端到端加密”替代披露审查。这是依据公开证据缺口给出的保守建议，不是断言其实现不安全。

## 方法说明

仅研究公开网页、创始人发布、公开访谈与第一人称使用记录；没有登录、联系第三方或攻击线上服务。原 X 帖部分无法直接抓取，使用可核对原帖ID的镜像，并保留原链接。查找中未发现公开完整 I2I 协议/权限模型或足以独立复现的 I2I 注入测试；“未发现”不等于不存在。报道与产品持续变化，所有结论以所列日期和证据层级为限。
