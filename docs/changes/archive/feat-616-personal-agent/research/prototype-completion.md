## 阅读与操作组织

- 默认先看到熟悉的 IM 和本人专属私聊。两条有具体下一步的消息分别呈现：观察发现林悦在等回复；林悦直接问 PA 时，需要本人具体确认可分享内容。没有新请求门户、第二套待办或内部执行域导航。
- 固定主导航显示自定义 PA 名字与角色；聊天列表仍为现有消息列表。窄屏从列表的五个主入口进入全宽聊天，聊天内隐藏底栏，返回回到列表。主导航的长名称截断但有完整标题，聊天标题和详情允许换行。
- 草稿、分享确认和任务写回均保留上下文：用户先读明来源/受众/后果，再确认明确动作。关闭/返回不等于发送，取消不丢原聊天草稿。
- 外部真人与 Agent 用普通 DM；群中用原生 @。外部只看到本聊天的消息，没有本人观察设置、私有任务或 Work 入口。本人批准的精确回复以同一 PA 身份回到原 DM/群。
- 异常注入、身份切换、首次/既有用户起点全部放在产品外的折叠演示区。产品内使用自然状态文案，不要求用户理解模型 scope、policy revision 或内部工具。
- 外层持续标明“现有背景 / 此次增量 / 仅演示”和“视觉未验证”。连接与模型准备、完整现有任务图、专业 Agent 新建配置等只保留上下文，不冒充已重做的完整产品。

## 供独立审查的短路径

1. 保持默认本人视角：打开回复草稿，编辑后关闭，再打开；放入输入框触发原草稿与附件冲突，选择追加，确认没有自动发送。返回来源聊天/本人私聊，内容仍属于原会话。
2. 外层选“新用户”：名字留空一次，填长名字和目标；下一步核对观察与联系说明；返回/稍后继续后内容保留。在创建前注入“下次创建回执丢失”，创建后注入断线/重连，产品内“重新确认结果”继续同一次创建。进入私聊时第一条目标是待发送草稿。
3. 外层选“林悦 · 普通 DM”：保持普通聊天结构，提出继续索要私人安排。切回本人视角，“查看要分享的内容”核对请求人、收件人、内容和用途，确认后切回外部查看原会话回复。未确认前外部没有时段。
4. 群 @ 同样操作。本人打开群分享确认后，外层注入新增成员，旧确认失效；按当前信息重新准备，再次核对完整受众。发送后再变成员，收据仍保留当时受众。
5. 从“任务”打开助手准备的结果，修改→查看写回内容。正常确认后原任务显示待确认、负责人陈同学、真实 PA 执行者。重置后在预览阶段注入“原任务被他人关闭”，出现冲突，不覆盖原任务。
6. 设置→观察范围，注入下一次清理暂未完成再排除来源；观察旧建议立即失效、清理仍显示进行中。单独触发完成回执才变为完成。暂停观察后注入本人已回复，恢复补读才合并为已处理，且不自动完成任务。
7. 检查 1440、768、390 与容易挤压的 360px，以及长名字、键盘、滚动、关闭/返回。**此步尚未执行，不能从 DOM 通过推断成立。**
