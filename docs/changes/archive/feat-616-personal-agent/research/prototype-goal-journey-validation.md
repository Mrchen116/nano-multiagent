# 目标推进版原型 · 真实走查与录屏

> 此为历史目标流程验证。全局导航、布局和本页旧视频已被[现有 UI 对齐走查](existing-ui-alignment.md)替代，不作为当前外观方案。

日期：2026-10-19。范围是 feat-616 的设计与静态交互原型，未实现或验证真实后端、模型、外部消息发送和后台调度。

## 这次改变了什么

原来逐条建议、普通搜索审批、专业任务批准和手动转交结果的流程，改为同一目标持续合作。PA 承接目标后自行准备；案例选择是业务决定，材料外发是新增披露；两者之后均自动继续。发送材料仍是“等确认”，直到对方确认时间与内容才完成原任务。

普通工具权限与普通 Agent 相同，不新增 PA 审批。已有目标允许的协调、复查和原任务更新不会每次重新请示。第三方索取无关私人日程时，PA 直接守住边界并继续协调。

## 实际浏览器操作

在 Codex 内置浏览器打开 `http://127.0.0.1:8766/prototype.html`，通过界面点击/输入操作。外层选择器改变内层 iframe 的真实 CSS viewport，1440 在当前浏览器面板中缩放展示；390 为移动 Web，并非原生 iOS 验证。

| 旅程 | 观察结果 |
| --- | --- |
| 390 首次启用：空名提交 → 填名字和目标 → 创建 | 空名不能创建；一次提交后自动开始资料整理，不要求再次发同一目标 |
| 自动准备 → 选择案例 | 没有搜索许可或内部委派许可；只出现带推荐理由的业务选择 |
| 稍后决定 → 模拟时间到达 | 其他准备保留，原决定恢复，不产生另一任务；独立审查后修正为16:00到达再次稍后17:00，到期后18:00，不再承诺旧时间 |
| 选择零售 → 成果回流 → 打开成果 | 自动显示演示页面和提纲，可打开实际示例内容；不要求把结果重新提供给 PA |
| 群新增成员 → 材料分享 | 明示新受众，具体文案和附件可核对；一次确认后持续跟进 |
| 未知回执 | PA 自动核对同一次发送；用户可以回私聊，无需承担查询职责；未创建重复发送记录 |
| 暂缓演示 → 群确认到达 → 恢复 | 外部原群保留确认；恢复后核对并自动完成，第二个行程目标不受影响 |
| 16:00复查 → 外部请求无关日程 | 在已授权范围自行协调；对无关日程直接说明边界，没有新增审批待办 |
| 节点离线 → 重连 | 明确无法执行后台跟进，保留目标；重连继续同一目标 |
| 外部确认 → 原任务 → 另一目标 | 原任务完成、负责人仍是本人；行程继续有独立下一次建议时间 |
| 1440 / 768 / 390 布局 | 桌面侧栏、窄屏导航、消息区独立滚动、全高详情面板均实际观察；390确认按钮可达，长内容在面板内滚动 |

作者另核对 JS 语法。没有沿用旧 R6 VM 测试计数作为新版通过证据。独立 reviewer 的观察与问题记录在 `../design-review.md`。

## 走查中直接修正的问题

- 稍后提醒与后续跟进均按当前模拟时间计算；17:00才发送材料则18:00复查，摘要、等待卡、任务、详情使用同一安排。
- 完成卡放在历史记录之后；返回目标直接定位最新进展，避免旧的“未确认”成为最后一条。
- 第二目标的补充保存在自身记录里，不混入演示目标。
- 暂缓期间到达的确认先出现在原群，PA恢复后再核对，不凭空丢失外部事实。
- 新增群成员在确认后仍保留在受众和群标题，不在发送后消失。
- 未知回执原先仍需要用户点“核对”；改为自动核对，回私聊不影响继续。
- 私人准备不提前把共享原任务显示为已写入结果；明确分享后才进入共享协作结果。

## 证据边界
