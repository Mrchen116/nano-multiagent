## 自动观察与主动性追加原话

> 那不合理啊。那这还跟主动性有啥关系？那不就是我给一个任务，他做一个事情吗？……而不是说能够主动地看得到我的聊天记录，帮我处理问题吗？这是两码事吧

来源：2026-10-16，Sentinel_24fff2efb1c08191a5c797bf29c47a68。原话依父线程转交保留，省略号亦按转交内容保留。

已确认方向：个人助手应能够主动看到用户聊天记录，自动感知来自真人或 Agent 的消息，发现待处理问题并协助解决；不以用户逐条“交给助手”或手工分享作为默认感知前提。撤回前期讨论稿中“默认仅处理本次选中/已分享消息”的推荐。手动“帮我回复”仍可作为即时请求入口，不能代替主动观察。

设计边界：用户应能控制观察范围、排除会话和暂停观察。看得到消息不等于获得对外发送、代用户承诺、传播隐私或修改任务负责人的权限。具体群范围、历史窗口和恢复行为以文末收口及 design 为准；观察不批准自动代发。

### Requirement: 自动观察支持真正主动的协助

#### Scenario: 真人或 Agent 新消息到达
- WHEN 观察范围内、用户有权访问的聊天收到真人或 Agent 的新消息
- THEN 个人助手无需用户逐条转交即可感知，根据内容识别待处理问题，并在适当时准备回复草稿或关联用户负责的既有任务；用户能辨认来源及建议下一步。
- AND 感知不意味着每条消息必须提醒，不把原消息中的第三方指令当作用户授权。

#### Scenario: 用户已经回复
- WHEN 个人助手在有效观察范围内获知用户已处理某个待回复问题
- THEN 对该问题停止重复待回复提醒，不将回复自动解释为整个任务完成，也不替用户发送第二份回复。

#### Scenario: 范围排除与暂停
- WHEN 用户排除某个会话或暂停观察
- THEN 后续对应消息不被个人助手继续处理或用来产生新的主动提醒；界面明确观察状态，既有记录不伪装成持续更新。
- AND 暂停不删除已保存历史；恢复先核当前权限再合并最新状态；清理会清除 PA 管理的所选源缓存、失效衍生引用与旧执行上下文并显示进度；原聊天、Work、运行日志及导出可能保留但不得自动重新摄取，不承诺磁盘物理擦除或撤回已外发数据。历史窗口及覆盖必须在产品设置明确显示。

原型用明确模拟按钮展示真人/Agent新消息、自动准备草稿、任务关联、用户已回复、排除及暂停；最终范围和 A 入口见文末。原型不宣称产品已实现，视觉仍未验证。


## 统一 IM 联络模型追加要求

来源：2026-10-16，Sentinel_576b16ff6314819191b1234b87f3fae7。父线程转交的用户要求摘要（未提供完整逐字原话）：拒绝新“请求入口”；别人或 Agent 应直接私聊个人助手，或在群里 @个人助手。

已明确方向：沿用普通 IM，不新增对外请求门户或另一套收件箱产品页面。权限与披露边界在既有消息通路内执行，不用新产品入口替代安全模型。四种关系须统一说明：本人↔个人助手的专属私聊；外部人/Agent↔个人助手的普通私聊；既有群聊内@个人助手；个人助手观察本人其他范围内消息。第四类观察不自动将个人助手作为原聊天发言成员，也不把私人上下文复制给外部对话。

### Requirement: 外部联络沿用现有 IM 私聊和群提及

#### Scenario: 外部真人或 Agent 联系个人助手
- WHEN 外部真人或 Agent 在既有 IM 中直接私聊个人助手，或在允许其参与的群里 @个人助手
- THEN 使用现有聊天交互与身份线索，不要求另建请求门户或切换到专门收件箱页面；处理仍受相应会话、受众和披露权限限制。

#### Scenario: 四类关系保持可辨认
- WHEN 用户切换本人专属私聊、外部与 PA 私聊、群 @PA，或查看 PA 观察本人其他消息形成的建议
- THEN 能辨认当前发言者、可见受众和信息来源；外部视角不显示 owner 私聊、其他会话或私有任务细节。

原型外层“视角”控制仅为比较四类关系的演示控制，不是产品新增导航。外部联络场景沿用同样的聊天列表、消息区和输入框；自动观察、草稿审核、任务协助仍回到本人的 PA 私聊。具体建联、群成员资格、披露和代发遵守文末收口与 design。

### 现有 UI 与需求范围纠正（2026-10-19）

用户原话：

> 你的UI和我原本的差异很大吧，你决定从上面挪到左边？

> 那就按我现有的UI改回去，本需求就做spec中我说的，真正把每个人的PA做到良好的交互体验

本次纠正撤销原型擅自新增的左侧全局导航，不是撤销 PA 的主动性和持续协助。沿用现有 IM 导航、聊天列表、消息与输入框及手机列表/会话切换方式；只加入每位用户固定可命名 PA 的入口、本人任务协助、辅助回复、主动观察、必要决策与持续跟进。不扩展为全 IM 改版、新任务中心或专业 Agent 管理重做。

### Requirement: 个人助手增量融入现有 IM

#### Scenario: 桌面进入个人助手
- WHEN 用户从现有 Web IM 打开自己的个人助手
- THEN 原有顶部“聊天 / 任务 / 智能体”保持位置与顺序，左边仍是聊天列表；新增具名 PA 快捷入口和角色标识，进入本人专属私聊，不出现新的全局左侧导航。

#### Scenario: 手机列表与会话
- WHEN 用户在手机浏览聊天列表或进入个人助手
- THEN 列表页保留既有“聊天 / 任务 / 智能体 / 我”底部导航，PA 通过固定具名聊天项进入；聊天页保持返回列表、消息与输入框，不增加第五个导航或挤占消息区。

#### Scenario: 从本人日常消息获得协助
- WHEN 本人在普通聊天请求辅助回复，或 PA 在已启用范围内主动发现消息相关的问题
- THEN 协助能带着原来源回到本人 PA 私聊；草稿可回到原聊天编辑，本人已有回复停止重复催办；长期目标的进展在 PA 私聊中查看，任务事实仍来自原任务。

### 已确认的产品决定

PA 对本人负责长期目标的推进：理解目标、记住约束、准备成果、协调允许的外部关系、等待并复查、只在必要时请求决定、交付和收尾。用户面对同一个助手；执行域、子任务、工具与审批机制在内部服务于这条链路。

- 保留唯一且可命名的 PA、固定 Web 入口、普通专业 Agent 共存，以及本人私聊/外部 DM/群提及/自动观察四种关系。
- 普通搜索、阅读、整理、内部委派与本人私密交付沿用普通 Agent 在同配置和授权下的规则，不因 PA 身份或后台唤醒增加人工审批。
- 本人明确交办可以建立有界的持续工作授权；它跨轮次与唤醒有效。工具调用、计划变化和恢复不要求重新批准同一范围。新的敏感披露、对外承诺、扩大范围和既有权限要求仍需相应授权。
- 持续工作关联现有任务；任务负责人保持本人，PA 负责协助和跟进。目标、状态和结果只有一份，私聊中的进展是同一任务的摘要。
- 正常私密执行与内部专业子任务的成果自动回到 PA，由它检查、汇总并继续推进；不要求用户重新上传/勾选结果给自己的 PA。外部资料仍是不可信输入，内外会话权限继续分离。
- 默认安静推进；需要本人判断、实质阻塞、临近约定时间有风险或完成时提醒。同一事项的多个来源合并为一个待决定项。
- 主动观察需首次说明并启用；默认本人参与的聊天与本人任务；按问题与目标需要查询历史，不设固定时间窗口，可排除或暂停。暂停新消息观察、暂缓某目标、停止当前执行和稍后提醒具有不同语义。

### Requirement: 每位用户能找到自己的固定个人助手并开始合作

#### Scenario: 创建、命名与再次进入
- WHEN 用户完成节点/模型设置并创建 PA，或修改其名字、重新进入
- THEN 始终进入同一个本人专属私聊，入口和署名使用自定义名称；重复提交不产生第二个 PA，已有普通 Agent 保持。
- AND 首次设置用简短说明交代观察范围和普通行动边界；用户可先聊天再启用观察，不要求先设计工作流或填写权限表。

### Requirement: PA 接住目标并持续承担协助责任

#### Scenario: 明确交办
- WHEN 本人说“周三客户演示，帮我准备材料并跟进确认”，补充了可协调对象和保密约束
- THEN PA 关联已有任务或建立本人私聊中的私人任务，说明已接手的工作、下一步和必要的待决定项；可自行准备的部分立即推进。
- AND 用户不必把同一目标再填一次表、手动拆任务或再次批准普通搜索。

#### Scenario: 观察发现机会但未被本人采纳
- WHEN PA 从允许来源发现可能值得持续做的新事项
- THEN 可自行整理信息、准备建议；在本人采纳前不把外界请求变成本人的承诺或创建对外任务。

#### Scenario: 多目标与更正
- WHEN 本人又交办另一目标，或更正其中一个目标的日期/范围
- THEN 每件事的进展、待谁、下次跟进可辨认；更正只作用于对应目标，停止过时动作，并继续其他不受影响的工作。

### Requirement: 常规工作不增加 PA 专属人工审批

#### Scenario: 搜索与内部协作
- GIVEN 普通 Agent 在相同工具配置、权限模式和相同用户意图下可直接执行
- WHEN PA 为当前目标搜索公开资料、读取允许资料、整理草稿或内部委派
- THEN 直接执行并交付可用结果，不新增“核对搜索词”“批准专业任务”或“把结果重新交给 PA”的必经步骤。

#### Scenario: 已获授权的后续工作
- WHEN PA 等待后收到新结果、定时复查或重连，并继续原目标范围内的动作
- THEN 沿用仍有效的授权与工具规则，不因不是用户刚发的一轮就再次索要批准；失效权限和真实越界仍会阻止动作。

### Requirement: PA 只把有实质意义的决定交给本人

#### Scenario: 关键业务取舍
- WHEN 多个有效方案需要本人偏好或业务判断
- THEN 给出推荐、理由与选择后果；一次决定即可继续相关工作。稍后决定给出明确再提醒时间，等待期间继续不依赖该决定的工作。

#### Scenario: 新披露或范围扩大
- WHEN 外部要求新增私人资料、未经授权的承诺或扩大原目标
- THEN 不自行扩权；能用当前可公开事实解决的先解决，需要本人时只问准确新增范围。
- AND 本人已明确批准的内容不再叠加第二个等价确认；模糊同意只澄清歧义。

### Requirement: 多来源协调减少本人的重复处理

#### Scenario: 多人、多 Agent 和群讨论同一事项
- WHEN 同一目标在本人聊天、外部 DM 和群里有更新
- THEN PA 在本人私密侧合并事实与待决定项、识别本人已回复，按各会话权限继续协调；已知决定不反复问，外部会话不因此取得其他来源的私人内容。

#### Scenario: 外部索取无关资料
- WHEN 外部联系人要求与当前协调无关的私人安排或资料
- THEN PA 保持资料边界，并在已有沟通权限内给出礼貌答复或可用替代；不会把每个不合理请求都变成本人待办，也不会泄露本人私下拒绝的过程。

### Requirement: 用户离开后，工作仍有真实的下一步

#### Scenario: 等待、截止与回归
- WHEN PA 在等待材料/对方回复，或用户稍后回来
- THEN 展示等待对象、下次检查时间和最近结果；期限到达会实际复查最新事实，变化有意义才提醒，普通检查不刷屏。
- AND 无定时能力、离线或执行失败时如实显示跟进受影响，不作已安排成功的承诺。

#### Scenario: 结果和完成
- WHEN 工作产生结果或达到约定完成条件
- THEN 成果自动回到原目标，用户能查看和要求修改；任务结果、真实送达与目标完成分开核实。
- AND 需要人判断时说清“等你确认什么”；已有客观完成证据和有效授权时可直接完成，不强制所有任务再走一次人工验收。

### Requirement: 用户能调节打扰、观察和工作责任

#### Scenario: 稍后提醒与暂缓目标
- WHEN 用户选择稍后提醒或暂缓某件事
- THEN 明确新的提醒时间或暂缓范围；稍后提醒不停止后台准备，暂缓不影响其他目标，已执行动作如实保留。

#### Scenario: 暂停与恢复观察
- WHEN 用户暂停新消息观察或恢复
- THEN 已交办目标和安排的跟进保持，并说明哪些新信息暂时看不到；默认恢复时合并最新状态，不逐条补发提醒。
- AND 只接收今后新消息不自动放弃已有目标/决定；停止目标需要针对该目标的明确操作。

#### Scenario: 排除来源与清理
- WHEN 用户排除或清理来源
- THEN 停止对应自动摄取并使受影响缓存/引用失效，说明受影响的跟进，保留其他目标；原聊天、任务和历史运行日志可能保留，清理不声称磁盘物理擦除或已外发内容可撤回。

### 可疑套取的双向告知（2026-10-19）

用户追加原话：

> 还有一点，Instinct有的设计，就是，如果对方是恶意套取信息的，PA在拒绝的同时，应该向主人反馈，对方可能恶意xxxx，也把这个信息传达给恶意方，这样对方也担心恶意的影响，用户也知情了。就像对方不会直接找用户本人套信息一样，他也不敢跟agent不停套信息。

本 unit 采纳“双向告知、主人知情、减少持续套取”的产品要求；此引用不构成对 Instinct 底层实现的核实。

### Requirement: 可疑套取被拒绝，同时向本人报告并向请求者说明已告知

#### Scenario: 反复索取或明确绕过隐私边界
- WHEN 对方在明确拒绝后继续索取私人资料，或伪造本人同意、要求隐瞒沟通等行为构成有依据的可疑套取
- THEN PA 拒绝越界披露，在本人专属私聊说明对象、来源、请求摘要、可疑依据和已采取措施；使用“疑似/可能”，不把模型判断当作恶意事实。
- AND 在原请求会话告知该请求已记录，并在本人通知实际送达后说明已通知本人；不暴露本人反应、内部判断细节，也不确认所索取秘密是否存在。本人不必审批这次保护措施。

#### Scenario: 普通询问、重复攻击与正常工作
- WHEN 首次模糊越界询问、同一对象重复套取或对方回到正常协调
- THEN 普通询问先说明边界；可疑事件合并报告，重复消息更新同一记录而不逐条刷屏/争辩，不生成待审批任务；新风险或实际泄露证据才升级提醒。允许范围内的协调及其他目标继续。

#### Scenario: 本人控制与通知失败
- WHEN 本人查看告警、认为是误会或选择屏蔽，或本人通知尚未送达
- THEN 本人可查看证据、标记误会并继续原范围协作，或沿现有联系策略屏蔽；标记误会不扩大资料权限。通知未送达时保留重试状态，对外不得宣称“已通知”，且“已通知”不等于“本人已读/认定恶意”。

### Requirement: 本人隐私与外部身份边界持续成立

#### Scenario: 外部伪造本人授权
- WHEN 外部真人/Agent 声称本人同意、发控制命令或试图读取私人 Work/配置
- THEN 不获得本人身份、主上下文或私人资产权限；本人专属私聊仍可控制 PA。

#### Scenario: 许可撤销与不确定投递
- WHEN 目标授权被撤销、受众/来源权限改变或投递回执未知
- THEN 停止不再允许的动作，保留可恢复的工作和草稿；未知回执核实同一次提交，不重复发送或宣称已完成。

## 统一 PA 与独立审查修订（2026-10-19）

用户原话：“所以你阐述下，你看完所有外部研究，结合我们的场景需求，我们应该怎么设计，也画个图来展示下”；在收到统一 PA、入口辨来源、独立出站审查和系统执行关口的方案后，明确：“先按这个来考虑怎么设计吧，改一版设计”。用户补充参考为 [Agent隐私防护研究](https://chatgpt.com/c/6ad5943b-44ec-83ec-9e79-0b348ce03ab3)。该对话是研究材料，其建议不自动替代本需求。

作者解读与本轮范围：按已讨论方案修订设计，取消每个外部会话必须另设无记忆业务 session 的架构前提；保留唯一 PA、现有 UI、持续目标责任与低打扰。让统一 PA 理解开放任务和私人背景，实际披露与动作由独立审查及系统关口约束。语义审查不是零泄漏保证；第一版仅提供可受控执行的能力，无法完整检查实际外发的任意脚本/插件不自动装配，普通非 PA Agent 不改变。不新增逐工具人工审批，不用全部拒绝换取安全。

### Requirement: 私人背景可用于完成开放目标，但外部请求不产生主人权限

#### Scenario: 跨聊天协调与自然表达
- WHEN 本人交办包含多源资料和外部协调的开放目标
- THEN PA 可利用相关私人背景持续判断和工作，用户无需把每次外部请求翻译成固定数据接口或在多个助手之间搬运资料；对外仅交付获准内容，不开放私人执行记录。

#### Scenario: 外部说法进入长期记忆
- WHEN 外部声称本人已授权，或材料/子任务结果包含对本人偏好与权限的说法
- THEN 可以作为带来源的待核事实保留，不能因摘要、压缩或后续会话变成本人的决定、许可或系统规则。

### Requirement: 外发检查自动执行并尽量保持目标推进

#### Scenario: 有安全替代的越界草稿
- WHEN PA 的待发内容泄露预算底线、私人日程原因等未获授权的信息，但仍可安全协调
- THEN 发送前拦下并自动减少披露或改写，经重新检查后继续；不把这次修正交给本人逐条审批，也不对外展示被拦草稿或理由中的秘密。

#### Scenario: 目标必需的新授权与审核不可用
- WHEN 目标确实需要新的披露/受众/承诺，或检查所需服务/证据不可用
- THEN 前者提出有具体范围与业务后果的本人决定；后者保留待处理动作和恢复状态，不能让本人“批准系统没检查的内容”来冒充通过。无关索取可直接拒绝，其他目标继续。

#### Scenario: 改变出口或逐步套取
- WHEN 信息通过附件、共享任务、其他 Agent、工具请求或多轮多渠道被传出
- THEN 同样检查实际收件人、内容和既有披露；不能通过更换工具、内部转发、先流式显示或重新包装调用绕过阻断。

#### Scenario: 发送前内容或权限变化
- WHEN 审查后正文、附件、收件人、群成员或有效许可改变
- THEN 对变更后的操作重新检查；未知送达核实原操作，用户看到真实状态，不重复外发。

作者解读：新消息处理可选择私密草稿、在有效授权内明确标记的 PA 代发，或不回复；不是每条新消息都要求用户选择。历史查询是常备只读能力，范围为本人参与过且当前仍可读取、未排除的群聊/私聊记录。首次整理与后续查询均不设固定时间窗口；不要求用户逐条转发或重新审批。现有平台实际保留和可读取范围决定覆盖，不承诺访问已删除或未接入渠道的历史。

### Requirement: PA 能按需查询本人可读的历史聊天

#### Scenario: 查询更早的约定
- WHEN 本人询问去年某群或私聊中的约定，或 PA 为已交办目标需要核实旧消息
- THEN 自动定位会话并按关键词、人物、时间检索及阅读上下文，不受固定时间窗口限制；回答附原会话、作者、时间和可定位的消息出处，不能以摘要冒充原话。

#### Scenario: 暂停观察与历史可见范围
- WHEN 暂停新消息观察后本人要求查旧消息，或查询涉及已退出、排除、删除或无权的来源
- THEN 暂停本身不关闭按需查询；每次按本人当前可读范围及 PA 排除规则取资料，退出但本人仍可读的历史可查，否则说明不可读。未覆盖、未找到与权限不足分别说明，不声称查遍全部。

### Requirement: 新消息协助保持真实发送身份和本人阅读状态

#### Scenario: 草稿、代发或不回复
- WHEN PA 收到别人发给本人的消息
- THEN 可准备仅本人可见的草稿、按有效协调授权自动代发，或不回复；草稿由本人点击发送时为本人消息，代发在原会话向双方明确标记 PA 身份，不冒充本人、不因每条消息重复审批。
- AND 观察或历史查询不改变本人的未读/已读状态；历史内容和外部请求不建立新的 owner 授权。

## 范围与交付

本轮重设计覆盖 Web IM（含窄屏）的连续原型、技术设计和 delta；原生 iOS 新导航、互联网匿名/跨公司联邦、生产部署不在范围。执行仍使用 DSH；原有任务、普通 Agent 与既有渠道保持其契约。

设计需要证明：一件目标从交办、准备、必要决策、对外协调、等待复查到完成；另一件目标可独立推进；用户离开、稍后提醒与暂停观察都不丢责任。录屏必须来自实际浏览器交互，明确标注模拟事件和未连接后端；不能把原型视频称为真实 Agent 能力测试。

Gate 1：本次用户已明确同意目标推进方向并授权修订，无待选 UI 方案。Gate 2 对新版本重新独立审查；历史审查与模型资源缺口保留，不据此宣布产品可实施或已完成。
