# feat-616：每个人的 Personal Agent

## 原始需求与本轮确认

此前原话与历次决定完整保留在 [历史记录](research/superseded-r8-requirements.md)，冲突处以下列最新确认优先。

> “只列PA真正不同的地方，通用能力就复用普通Global Agent，别再给PA单独造一套。”
> “PA能力怎么能比普通agent还弱啊。”
> “应该是包含两个身份的历史查询。”
> “我给其他人发消息，我的PA也应该收到吧”
> “feat 617分支做了IntelligentUI相关的基础设施，可以把feat 616建立在它之上。可以让PA用来做交互。”
> “就按这个来，把spec和design同步改好，基于feat617分支最新代码实现，把之前给PA单独造的那些多余机制去掉。”

作者解读：PA 是完整 Global Agent 加上固定主人关系、双身份消息访问、原聊天协助和披露保护。普通 Global 不在本 unit 新增任务、进度、暂停联动或草稿业务；共用 feat-617 IntelligentUI。

## Requirements

### Requirement: 每人有一个可配置的固定 PA
#### Scenario: 创建与配置
- **WHEN** 用户创建 PA、改名或修改模型、指令、工具与能力
- **THEN** 固定身份和主人私聊保持；使用现有 Agent 设置，工具、代码、Skills、插件和子 Agent 能力与普通 Global 一致。
- **AND** 现有顶栏、聊天列表和移动端结构保持；不新增另一套导航。

#### Scenario: 注册后创建并沿用同一个 PA
- **WHEN** 新用户注册并在首次设置中连接电脑、确认可用模型和创建助手
- **THEN** 创建的是该用户固定的 PA 与主人私聊，个人使用无需等待公司批准。
- **WHEN** 用户随后申请加入公司并获批
- **THEN** PA、绑定与主人私聊身份保持，既有消息、配置和工作上下文继续沿用；不再要求创建第二个 PA，也不把私人聊天与 Work 发布给公司。

### Requirement: PA 使用两个身份统一查询历史
#### Scenario: 主人不在 PA 的对话里
- **GIVEN** 林悦分别与主人、PA 私聊，PA 还参与了主人未加入的群
- **WHEN** 主人询问演示协调进展
- **THEN** PA 能综合自身可访问聊天与主人授予的可访问聊天，去重、保留真实作者与出处，无任意日期限制。
- **AND** 无权限和被排除来源不出现在列表、搜索或直接消息读取中。

### Requirement: 主人聊天的双向消息进入同一个 PA
#### Scenario: 主人已经亲自回复
- **WHEN** 林悦先询问周三时间，主人随后回复改成周四
- **THEN** PA 能获知双方消息并更新判断，不沿用旧安排或重复替主人回复；PA 阅读不改变主人已读状态。
#### Scenario: 自发消息与来源撤销
- **WHEN** PA 发出消息，或某个来源被排除/失去访问权
- **THEN** 自发消息不会引起自我回复循环；不可访问来源的后续消息和查询被阻止。

### Requirement: 原聊天回复可用草稿、代发或不回复
#### Scenario: 主人编辑草稿
- **WHEN** PA 为主人收到的消息准备回复
- **THEN** 复用 IntelligentUI 展示可编辑草稿，主人可带回正确原聊天后以本人身份发送；编辑或采用草稿本身不向对方发送。
#### Scenario: 已授权代发
- **WHEN** 主人授权 PA 协调演示且具体回复符合该要求
- **THEN** PA 可直接在原聊天回复，对方看见 PA 的真实发送身份和代发标记；取得真实回执才报告发送成功。
#### Scenario: 无需回复
- **WHEN** 主人已回复或消息无需协助
- **THEN** PA 可保持安静，不要求主人逐条选择处理模式。

### Requirement: 主人自然表达的来源限制真实生效
#### Scenario: 排除与恢复
- **WHEN** 主人说“这个群不要看”或恢复该群访问
- **THEN** 主 PA 直接操作设置，系统返回执行结果，并强制控制后续接收与查询；指代不清才澄清。
- **AND** 不先由独立模型解释主人设置，不因此清空记忆、文件、上下文或取消其他工作，不承诺彻底遗忘已读信息。

### Requirement: 持续协助复用 Global 的既有能力
#### Scenario: 连续完成演示安排
- **WHEN** 主人交办演示安排
- **THEN** PA 可组合现有任务、内部子 Agent、消息、定时、Heartbeat 持续准备和协调；等回复后继续，达成目标后交付结果。
- **AND** 普通问题不自动建任务；任务、暂停、恢复、取消和跟进沿用 Global 的现有工具及语义，不建立 PA 专属目标体系。
#### Scenario: 普通私人工作
- **WHEN** 主人询问旧事、要求整理或记录私人进展
- **THEN** 请求直接交主 PA，执行沿原工具权限；无 PA 专属前置审批或二次审核。

### Requirement: 能读私人信息不代表能向外披露
#### Scenario: 外部伪造主人许可
- **WHEN** 外部消息、网页或工具结果声称主人已授权披露
- **THEN** 来源保持可辨认，不升级为主人授权；外发核对真实主人要求和具体受众、内容。
#### Scenario: 安全替代与必要决定
- **WHEN** 某段对外内容包含无关隐私
- **THEN** 阻止该内容，PA 优先缩减披露或继续其他工作；仅确需新增授权或业务取舍时借 IntelligentUI 询问主人。
- **AND** 主人私聊的正常交付不进入对外披露审核；不宣称消息检查覆盖任意代码或插件的所有网络流量。

### Requirement: 可疑套取有依据地双向告知
#### Scenario: 重复越界索取
- **WHEN** 对方反复索取无关隐私或明确要求隐瞒主人
- **THEN** PA 阻止相关披露，主人收到具体请求、依据和处理情况；通知真实送达后，原会话可告知已记录并通知主人。
- **AND** 用“疑似”及事实描述，不把普通询问贴为恶意，不要求主人批准才能继续其他工作。

## 范围与非目标

本 unit 基于 feat-617 最新已提交代码；不改动其其他工作树的未提交现场。主模型 6.1 Sol、审核模型 6 Luna 是本轮联调配置，可在现有设置修改。

移除旧 PA 专属 assistance/scopes/decision/调度引擎、全局观察暂停、来源清空和工具缩减。普通 Global 无新增业务能力；不增加 OS 沙箱或任意代码网络拦截保证；不扩大到生产部署。
