# IM conversations-messages Specification (delta for feat-617)

## MODIFIED Requirements

### Requirement: 交互确认保留真实用户、原回复与选择语义

明确提交 SHALL 形成当前登录用户的会话消息，携带原回复与实际选择；私聊自然文字可携带后台上下文供接收Agent判断，保留原文；群聊私人未提交状态仅对本人可见，普通文字不得共享。重复提交不得创建重复输入或重复调度。

#### Scenario: 群中不同成员调整
- **WHEN** 两位成员分别调整同一卡片，随后其中一位提交
- **THEN** 草稿互不覆盖；公开结果明确属于提交人，原卡片作者 Agent 获得其选择上下文。

#### Scenario: 多次探索与请求幂等
- **WHEN** 用户继续探索同一回复并发送另一个明确请求，或因网络重试同一次请求
- **THEN** 新请求可独立保存；同一幂等键和语义返回原结果，不重复调度；同键不同语义明确冲突。
- **AND** 被替代或 fork 的旧版本不接受新的业务请求。

#### Scenario: 增量更新保持完整历史
- **WHEN** Agent 对自己的同会话交互回复发送增量修改
- **THEN** 新消息保存校验后的完整版本，旧消息仍可读；失败或重试不会产生半条或重复版本。

#### Scenario: 私聊自然追问与群聊明确提交
- **WHEN** 用户修改卡片后发送普通文字
- **THEN** 私聊Agent可按原话判断是否使用发问时后台状态；群聊所有Agent和其他成员均不获得未提交状态。
- **AND** 群聊只有明确提交动作才公开本人快照，不将普通发言自动定向卡片作者。


## ADDED Requirements

### Requirement: 自然消息的交互背景保持准确且不改变路由

#### Scenario: 发问后继续操作与网络重试
- **WHEN** 用户在私聊参考交互内容自然发问，随后继续修改或因网络重试
- **THEN** 接收Agent可取得发问时的背景快照，之后的状态不改旧输入；同一次请求不重复入队。

#### Scenario: 私聊背景与群聊隔离
- **WHEN** 私聊消息带有后台交互背景，或用户在群内正常发言
- **THEN** 私聊背景只交付卡片作者，不进入公开消息或确认结果；群聊不携带后台背景，接收规则沿原消息，只有明确提交后才共享。
