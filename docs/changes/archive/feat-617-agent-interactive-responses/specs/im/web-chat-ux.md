# IM web-chat-ux Specification (delta for feat-617)

## MODIFIED Requirements

### Requirement: 交互内容保持聊天阅读与操作连贯

Web IM SHALL 在对应 Agent 回复中呈现交互，用户可操作或自然打字继续，不管理后台保存和附带模式。

#### Scenario: 自动保存与自然提问
- **WHEN** 用户调整控件、刷新或继续打字
- **THEN** 本人状态在后台保存恢复；正常成功无保存提示、选择附带横条或Detach。普通本人消息只显示原话；私聊后台携带发问时状态，群聊只有明确按钮提交才共享快照，明确请求仍显示实际发送结果。

#### Scenario: 手机与桌面
- **WHEN** 用户在桌面或手机阅读和操作交互回复
- **THEN** 字段、主要动作和聊天输入可读可用，不因卡片宽度或内层滚动妨碍主对话。

#### Scenario: 生成与渲染失败
- **WHEN** 回复正在生成或交互无法渲染
- **THEN** 用户能识别运行状态，已可读内容不无故消失，失败时仍能阅读摘要并继续打字。

#### Scenario: 私人状态与真实失败
- **WHEN** 用户重新打开会话、两台设备同时修改或发送失败
- **THEN** 恢复本人状态；冲突和未知结果明确反馈、保留当前编辑和原请求快照，不能静默覆盖或重复发送。


## ADDED: 面板自适应消息布局

### Requirement: 消息随聊天面板和内容伸缩

#### Scenario: 宽面板上的交互与宽内容
- **WHEN** 用户在桌面打开含交互回复、代码或表格的聊天
- **THEN** 宽内容可使用消息面板扣除边距与头像后的空间，不受普通气泡固定百分比或交互卡片固定窄宽度限制；交互回复不再叠加外层灰色气泡，仍保留发送者、时间与消息操作。

#### Scenario: 短消息、长文与手机
- **WHEN** 用户阅读不同长度的消息或缩窄面板
- **THEN** 短消息按内容收缩，长文字在超宽面板保留阅读上限；手机不额外预留固定比例空白，代码表格必要滚动限制在各自区域，不撑宽页面或遮挡输入。
