## 澄清记录

- 用户最新明确要求：先在模拟器验证并提 PR，合入后再更新手机；当前交付不要求用户登录手机，不以物理安装阻塞 PR。沿用原生客户端与已有交互协议，不增加付费开发者要求。需求没有待定项。
- 前一轮审查已确认：原生客户端不读取通用交互回复，待确认发送仅在内存保存，重试时重新转换提及可能与新服务端不可变请求校验冲突。

## 用户场景

用户在手机阅读 Agent 的交互解释、修改参数、填写选择并明确要求 Agent 继续；这些操作与 Web 的同一条回复保持业务语义。普通聊天可带上相关私人选择，其他人不能看到私人草稿。网络中断、进程被系统终止后，重新打开可以确认原次发送，避免重复交办；成员改名不会让重试失效。最后在用户当前手机安装更新并实际打开。

## 验收标准

### Requirement: 原生交互回复可阅读、探索与继续

#### Scenario: 阅读和本地探索
- **WHEN** 用户打开包含现有通用交互回复的聊天并修改输入、选择或参数
- **THEN** 卡片在原生聊天内呈现清楚的内容层级、控件与结果，计算、条件、图表和列表随操作更新，不为纯本地探索发出新聊天请求。
- **AND** 窄屏、大字体时主内容和操作仍可达，原有文字摘要、附件和审批不丢失。

#### Scenario: 明确请求继续
- **WHEN** 用户点击卡片中继续会话的动作
- **THEN** 原作者收到用户当时的完整选择与明确请求；一次动作在网络重试后仍只有一条用户消息，之后可以发起新的动作。
- **AND** 已连接的会话查询可读当前有权查看的消息；未连接的工具不伪装成功。

### Requirement: 私人交互状态与权限一致

#### Scenario: 恢复私人编辑
- **WHEN** 用户修改卡片后离开并重新进入，或另一设备已更新同一卡片草稿
- **THEN** 恢复本人保存的选择；并发冲突提示读取最新内容，不静默覆盖其他设备的编辑，不向其他用户公开草稿。

#### Scenario: 发送带相关背景的文字
- **WHEN** 用户在私聊操作卡片后发送普通文字
- **THEN** 原有手写文字保持，相关私人选择随该次文字发送；群聊不会暗中附带私人编辑，改变选择不会改写已发送的内容。

#### Scenario: 历史、只读与无法呈现的内容
- **WHEN** 用户阅读只读观察聊天、已替代或分支历史卡片，或无法呈现的卡片
- **THEN** 历史和文字摘要仍可读，禁止无权发起的新请求，错误有明确恢复入口，不影响其余聊天。

### Requirement: 不确定发送跨重启恢复且不重复

#### Scenario: 已保存但返回丢失后重新打开
- **WHEN** 文字、附件或卡片动作已保存，但手机未收到确认并被终止，用户重新打开 App
- **THEN** 核对并展示原次发送的结果；仍未知时可按同一次发送重试，不产生重复消息或重复交办，原有待发内容保留。
- **AND** 从未确认发送的草稿不会自行发出，后续新草稿不会被旧发送的迟到确认清空。

#### Scenario: 提及成员发生变化后重试
- **WHEN** 一次带提及的发送结果未知，成员名称或名单更新后用户重试
- **THEN** 继续确认原次发送，不因成员变化出现请求内容冲突，也不改变原来的提及对象。

#### Scenario: 退出、切服务或撤销权限
- **WHEN** 用户退出账号、切换服务或失去聊天访问资格
- **THEN** 旧待发记录、私人编辑及迟到请求不能进入新会话或绕过撤销后的权限。

### Requirement: 模拟器验证后交付 PR，合入后更新手机

#### Scenario: 交付可合入版本
- **WHEN** 完成模拟器真实客户端检查、相关回归和重新打包
- **THEN** 提交可审查的 PR，版本与已验证代码可追溯；手机安装等待合入，不要求用户现在登录。

#### Scenario: 合入后安装
- **WHEN** PR 已合入并更新用户当前 AltStore 管理的 Nano IM
- **THEN** 用户手机能打开新版，现有同网续签方式仍可使用；此验收在合入后执行。

## 范围与非目标

- 在范围：原生交互回复、现有交互状态与动作协议接入、普通与交互发送持久恢复、不可变请求兼容、版本标识、回归验证、IPA 与用户设备更新。
- 非目标：新增 Agent 工具、改变服务端授权或执行运行时、重做聊天布局、付费签名和 APNs、自动合并 PR、修改生产数据。
