# feat-652 — Agent 设置区契约增量

## MODIFIED Requirements

### Requirement: 每个 Agent 可独立选择自动审批策略

Agent 创建与配置页提供 CC、Codex 和跟随节点选项。简短说明帮助用户理解策略区别；明确保存后从下一轮任务生效。该选择不改变执行模型、已有聊天历史、工具权限或其它 Agent。空选择沿用节点既有配置，旧客户端省略字段不清除已保存选择。

#### Scenario: 独立选择并持久化
- **WHEN** 用户给两个自有 Agent 分别选择 CC 和 Codex 并保存、刷新
- **THEN** 各自保留选择，并可切回另一策略或节点继承。

#### Scenario: 下一轮采用选择
- **WHEN** 用户在既有聊天期间成功保存策略
- **THEN** 进行中的整轮与已发出的人工审批保持原请求；下一轮任务采用新策略，聊天历史保留。

#### Scenario: 保存未成功
- **WHEN** 节点离线、版本冲突或应用结果尚未确认
- **THEN** 按既有配置 operation 语义显示失败或待确认，不宣称候选策略生效；恢复后可继续操作。

#### Scenario: 继承项显示实际策略
- **WHEN** 用户在创建或配置页查看“跟随节点”选项
- **THEN** 选项同时显示节点为该工作区实际提供的继承策略，不从 Agent 显式覆盖或模型名称推断
- **AND** 未取得该信息时明确未确认；离线保留的值遵循最后确认信息的标记与只读限制。

### Requirement: 桌面 Agent 页面提供连续导航，并保护新建草稿

桌面端从 Agent 列表或节点入口进入新建页，以及打开或切换既有 Agent 详情时，保持 Agent 导航栏。详情请求处于 loading 或 initial error 时，导航栏仍可用，内容区显示局部 loading/error 状态与可重试操作；移动端保持单栏流程。用户一旦编辑新建表单，任何站内离开操作都必须先确认，避免草稿因误触丢失。

#### Scenario: 桌面端两个新建入口保持 Agent 导航
- **WHEN** 用户在桌面端打开 `/settings/agents/new` 或 `/settings/nodes/{node_id}/agents/new`
- **THEN** 新建页显示已有 Agent 的导航栏，并可在未编辑表单时直接切换
- **AND** 移动端仍只显示单栏创建流程

#### Scenario: 桌面端详情切换期间保持 Agent 导航
- **WHEN** 用户在桌面端打开或从一个 Agent 切换到另一个 Agent，详情请求处于 loading 或返回 initial error
- **THEN** Agent 导航栏保持可见且可切换，内容区仅显示该 Agent 的局部 loading/error 状态
- **AND** error 状态提供重试操作，移动端仍只显示单栏内容

#### Scenario: 有草稿时确认站内离开
- **GIVEN** 用户已编辑新建 Agent 表单但尚未提交
- **WHEN** 用户通过 Agent 导航、取消、应用导航、用户菜单或浏览器后退离开页面
- **THEN** 页面要求确认退出，取消确认后保留当前草稿
- **AND** 用户确认后才进入原目标

#### Scenario: 响应式切换保留编辑现场
- **GIVEN** 用户正在创建或配置 Agent，或填写已打开的通道连接表单
- **WHEN** 窗口宽度跨过桌面与移动布局边界
- **THEN** 当前草稿与仍适用的已打开表单保留，不因布局切换被重置或自动提交。

### Requirement: Agents 列表可辨认归属设备，状态由头像角标表达

Agent 目录、详情与创建页导航中的条目沿用同一设备名称优先级，与电脑页的别名或设备名一致；在线状态由头像角标表达。桌面将设备与稳定标识紧凑排列，移动端保留归属标注；不因节点离线丢失已知设备名称。个人助手公开联系人未提供设备信息时不伪造归属。

#### Scenario: 多设备与别名
- **GIVEN** 当前账号有多台设备且各有若干 Agent，其中设备可设置别名
- **WHEN** 查看 Agent 目录或详情、创建页的导航条目
- **THEN** 可辨认 Agent 的名称与已知设备归属，设备名称与电脑页一致。

#### Scenario: 离线与窄屏
- **WHEN** 已知归属设备离线，或用户在移动端查看列表
- **THEN** 已知设备名仍可见，在线状态与归属信息分别表达，长文本不挤出主要操作。

## ADDED Requirements

### Requirement: Agent 概览与会话页展示真实已知信息

概览反映已保存配置；会话页只从当前用户已经有权查看的会话中列出与该 Agent 关联的聊天，不扩大读取权限。页面区分已确认空结果、加载和读取失败，保留必要的只读、权限与操作后果说明。

#### Scenario: 从概览进入配置
- **WHEN** 主人打开 Agent 概览
- **THEN** 可查看已保存的身份、模型与工作区信息，并进入配置；不把未保存草稿或历史读数表述为当前运行事实。

#### Scenario: 查看关联聊天
- **WHEN** 主人打开 Agent 会话页
- **THEN** 页面按最近活动列出用户可见且与该 Agent 关联的聊天，可搜索标题并进入原聊天；消息预览将 mention 转成可读名称。
- **AND** 查询失败提供重试且不伪装为没有聊天，成功但无匹配时显示空结果。
