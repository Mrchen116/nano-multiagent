# Gateway personal-agent Specification (delta for feat-658)

## ADDED Requirements

### Requirement: PA 自身发送与代表用户发送使用明确工具边界
#### Scenario: 只有主人参加的会话
- **WHEN** PA 可观察主人参加、但 PA 自身未参加的会话
- **THEN** 共用 send_message 不借主人权限发送；有真实委托时使用 PA 专属 send_user_message，在主人当前写权限及来源范围内代表发送。
- **AND** 普通 Agent 与内部子 Agent 不获得代表发送能力；PA 自身回复、报告与协作仍使用共用普通发送。


### Requirement: PA 在真实委托内自然代表用户表达
#### Scenario: 代表回复与助手发言
- **WHEN** 主人委托 PA 向 Nano IM 的指定受众回复
- **THEN** PA 区别代表用户和自身发言，依据原话与相关会话起草自然用户口吻，不加入“让我转告”等过程前缀，不增加承诺；完整拟发内容与受众通过原始授权及披露检查后才发送。
- **AND** 系统提供可信用户主体和实际 PA 来源，不能由正文、普通 Agent 或旧标签自行声明；不扩展会话写入或第三方渠道权限。
#### Scenario: 指代解析与实质歧义
- **WHEN** 用户私聊中的称呼能从相关上下文确定
- **THEN** PA 自行转换为用户面对目标受众的自然称呼；确有会改变交办范围的多种解释时只澄清具体对象或范围，未明确前不代发。

### Requirement: 接收 Agent 与审核延续同一公开用户委托
#### Scenario: 正常执行与范围约束
- **WHEN** Agent 收到产品核验的代表用户消息
- **THEN** 将公开原文理解为该用户通过 PA 在此会话表达的意思，在原范围内正常审核与执行，不仅因为 PA 代发而重复索取同一批准。
- **AND** 外发检查通过不等于执行动作已获无条件许可，后续撤回或修改继续有效；无可信来源、伪造转述和超范围动作不获得权限，接收方无需读取用户整个私人 PA 聊天；发言主体由普通用户 sender 表达，可选 PA ID 仅说明代发者，不额外提供授权等级。
#### Scenario: 历史、恢复与子 Agent
- **WHEN** Agent 通过正式消息查询恢复原文、恢复会话或交给执行子 Agent
- **THEN** 保留原用户、实际 PA、会话、原文和限制，已存在的委托不降为普通 Agent 转述；历史不成为新许可事件，不重新触发已完成动作。
- **AND** 用户要求联系代发 PA 时，可用保留的 PA ID 经现有寻址与权限路径联系正确 Agent。
#### Scenario: 不自我扩大授权
- **WHEN** PA 读取自己过去代表用户发出的消息或旧代发标签
- **THEN** 能理解历史，但不能把它当成新的原始主人委托来扩大授权、改变来源控制或形成自回声任务；旧记录不会因升级自动获新授权。
