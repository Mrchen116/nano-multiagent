# 给本地 coding agent 的实施指令

请在 nano-multiagent 仓库中实施这份通用 Personal Agent 升级，设计包目录名为 `nano-pa-general-v2`。先定位已提供的目录或压缩包并读取 README.md、GENERAL_PA_BLUEPRINT.md、design/01-current-state-and-gaps.md；再按当前工作读取其他文件。本次是实现交办，不是只要评审或再写一份建议。

## 已明确的产品决定

我要的是通用长期 PA，不是 coding manager。它应能在工作和生活多个领域理解用户、记住并真正使用偏好/关系/决定、主动发现可帮的事并准备成果、在授权内持续工作、跨 IM 关联信息、少打扰但不失联，且让我能看懂、纠正和停止。

我提供开发场景只是举例。保留一个可续用内部执行者负责独立长任务，但不要把整套 PA 架构围着 change-* 开发流程设计。开发 Skill 是可选领域方法；通用能力不依赖开发工具或外部账号已连接。

沿用现有 IM/Global、Task、原生子 Agent、KnowledgeRuntime、Heartbeat/schedule、Skills、权限审核和 Work 轨迹，不建设平行 Goal/Task/记忆维护 daemon，也不加一套繁重用户流程。观察到用户承诺可研究、准备、记为私人关注，不自动获得代发或交易授权。

## 必须交付的功能闭环

1. 通用 PA 默认提示、按角色装载的观察/记忆/执行指令、12 个按需 Skill。原导出名 personalAgentDefaultInstructions 保持。默认服务指导仍是可修改/清空的配置，不将同一服务文案偷偷塞到固定层。新版 prompt 必须与真实能力面相符，禁用 Skill/tool 不得绕过。

2. 记忆从小型概要扩展为受控记录、索引和有界投影；现有文件与工具兼容，不保留双权威写入。明确记住/纠正/忘记走快路径，普通整合复用现有后台维护。同步 PA 路径的 memory/combined prompt、工具说明、ReviewFiles、生命周期、压缩与最终上下文装载。按场景检索个人偏好，旧数据来源无法恢复就标明不确定，不编造消息 ID。

3. 主动性采用两条路径：已委托工作主动继续；未交办的用户承诺/具体机会先核对、私人准备，再执行或提议。实现最小私人 attention 与反馈，链接 canonical Task，不擅自把用户负责人改成 PA。来源/时间/身份/已完成状态核对、候选去重、稍后、忽略、主题抑制、实际通知回执、无变化静默必须闭环。

4. 充分使用 IM 自动观察，不要求我手动转发，不以屏幕监控为前提。保持当前 participant/observer 与十分钟批次语义；直接请求可立即读相关背景。root Inbox 消费与 observer research cursor 分离。观察者没 root 读取权限时，用受控只读查询代理或冻结的最小输入，不提升成主人身份。partial/failed read 不算完整覆盖。

5. 多事项执行保留原负责人和真实执行 ID，追加更正、获取结果、取消/恢复、重启以及投递按回执判断。活跃 child 与 Task doing 的协调不重复实施，也不因错误抑制导致永久失联。保留 Task waiting 的真实 schedule 校验，不用假 waiting 或空定时器逃避续推。

6. IM 中的结果、建议和记忆可理解、可修改、可停止。复用现有交互 UI，不让采用草稿等于发送，不让旧卡和重复点击产生重复副作用。用户能查正在替我做、需要我决定、为我留意、记住了什么及来源，不增加空卡式重型工作台。生成产物必须真实可访问；检查现有发布/上传入口，缺失则补最窄受控能力，不把本地路径当交付。

7. 保留固定身份/来源、原始授权、独立对外披露、代表用户发送与停用规则。观察者只读必须有执行 guard；个人记忆不能进全局共享 Skill；任务 child 不默认继承无关私人历史和访问权限。通用 shell/plugin 的泄露面不能靠 send_message reviewer 假装被保护。

## 工具和机制约束

阅读 design/05-tools-and-integration.md。新增名只是提案：先实现实际注册、schema、权限、幂等/版本、Feature、持久恢复和错误语义，再向模型宣布。优先扩展已有 memory/Work/Task/配置；personal_context 是组合读取，personal_attention 是发现/反馈，不是新数据库引擎或执行授权。

外部日历、邮件、预订、浏览器、文件等按实际能力接入。已有 lark-* 等资源先复用。没有真实账号就交付 IM 内可用服务和诚实降级，把外部实接单列，不假装全域都已可执行，也不要因某个域缺账号而停止全部核心实现。

默认不买服务、不提交表单、不发真实外部联系、不扫描未许可账号、不在生产写测试消息、不 merge/deploy。沿用当前仓库正常开发及 PR 规则；没有新的发布授权不要替我扩大上线范围。

## 实施与验收

按 design/07-rollout-and-validation.md 的 M1/M2/M3 纵向切片推进；可以依据当前 workflow 调整单元划分，但不能只完成提示词就报整个升级完成。

将 evals/scenarios.yaml 的 58 个场景接入现有测试入口。先做列出的 smoke，再覆盖受影响场景和全量要求；确定性层验证 source/权限/幂等/版本/游标/取消/回执，行为层用真实模型与真实 IM 验证偏好实际使用、主动准备、正确静默、变更转交、真实交付。用包内合成 fixture，不引入生产隐私。最终模型输入和真实轨迹是证据，类型检查、源码字符串或“LLM 说通过”不能替代。

核心行为至少进行多次重放，并与相同模型/工具配置的旧行为比较，报告成功率、重复提醒、错误记忆和资源消耗；若旧版本无法完整比较，说明原因，不编造提升百分比。evals/summarize_results.py 只是汇总器，不是已实现的 runner。生成 actual-results.jsonl 只能填真实结果，未运行/外部阻塞必须分开。

前端按既有参考案例、体验契约、原型与真实浏览器路径验收。不要默认做大面积空白仪表盘，不要用按钮下的多余解释堆满界面，不额外增加新的 UX 门禁角色。安全、Context 和代码审查按仓库现有机制复用，不自行设立更多重复审批。

迁移必须幂等、可回滚、不覆盖我的自定义 prompt/Skill、不能丢新记忆。验证关闭新 Feature 后的行为与旧记录兼容；按既有 deployment-prompt 规范提供隔离验证过的一次性迁移步骤。
