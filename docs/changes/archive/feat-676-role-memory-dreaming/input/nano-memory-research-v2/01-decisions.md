# 对本轮六个疑问的决策

## 一、MEMORY.md：两种画像，不用标题数量判断价值

竞品并非都拥有复杂标题：Instinct 被观察到的 one-pager 有三个大块；Muse 归档的初始 MEMORY.md 是 Facts/Preferences/Commitments；Raft 入口也是 Role/Key Knowledge/Active Context。真正重要的是内容选择、完整条件、更新和读取规则。上一版“高频背景＋当前背景＋导航”过于抽象，无法确保写入 PA 的关系、主动性校准和专家的职业经验。

决定：共用注入机制，分开 PA 与专家入口模板。入口是工作简报，不复制岗位权限，不保存秘密，不复制整个任务账本。

| PA 入口 | 独立专家入口 |
|---|---|
| 主人的生活与工作背景 | 专业职责与适用边界的背景 |
| 当前目标与持续事项 | 当前项目与工作焦点 |
| 重要关系与协作网络 | 合作者、团队与协作接口 |
| 稳定偏好与现实约束 | 领域环境与正式资料 |
| 主动性与决策校准 | 已验证知识与判断要点 |
| 沟通、渠道与表达习惯 | 协作约定与验收习惯（注明范围） |
| 近期纠正与服务经验 | 近期纠错、失败教训和未决问题 |
| 详细记忆导航 | 专业知识与工作历史导航 |

无材料就省略对应内容，不用臆测填表。每条常驻概括必须能指向完整正文或原始证据，不能将条件截掉。后台生成器不得全量重写后把已确认的小众约束挤走。

本轮不把 8 栏等同于必须增加常驻预算：沿宿主可配置预算试跑，关键条件必须保留；超限时移走完整低优先级细节，不能截半句。模板文件中的注释和占位符不进入生产。

## 二、目录：共同文档机制，两个角色 profile

沿现有 workspace/.nanoassistant/memory，根级名称与用途由产品的 memory Skill 固定，不由每轮模型自由发明。

共同部分为实体、当前知识、按事项的背景、历史与归档；PA 以主人世界和生活时间线组织，专家以领域知识与工作记录组织。具体树见 design/layout-and-documents.md。

撤销 cases 作为必建类别。竞品的情景材料确实存在：Instinct 的 timeline/comms、Raft 的 work-log、Codex 的 rollout_summaries，但不应把这些等同于同一个 cases API。Nano 使用明确时机：PA 的重要个人／关系／计划变化写入当天时间线；专家某项工作完成、形成重要验证结果或收到改变判断的反馈时，更新同一工作记录。普通消息、重试噪声、无知识增量的例行工作不写。Dreaming 可以补漏，不要求主 Agent 在一开始预判是否值得成为“案例”。

## 三、单篇笔记：借鉴 Instinct 的文档头，不采用统一原子事实

新建文档有 id/type/aliases，正文依用途不同。id 是稳定文档标识，不是授权，不是每句话的主键。普通 Markdown 相对链接就能导航；初版不以额外 Wiki-Link 解析器为前置。一个文件保存一组需要共同理解的内容。身份型文档优先绑定真实产品标识；同名不合并。

PA 人物页解释“此人与主人是什么关系”；专家人物页解释“此人与我怎样合作”。偏好页记录范围、例外、理由；知识页记录结论、证据和反例；历史记录记录当时发生什么，不冒充当前状态。模板详见 templates/documents。

## 四、消费与写入规则必须出现在系统指导

常驻的短指导给出记忆根、角色、读取触发、写入触发和证据边界；详细目录与编辑方法放 nano-memory Skill。不能将“何时想起去读记忆”仅藏在尚未加载的 Skill 里。

正常问答若当前信息足够就直接回答；提到旧人/旧事/偏好/项目或可复用经验而上下文不足时，主动找并读完整相关章节；重要外部状态仍回原系统。明确纠正即时更新，普通可长期使用信息也可主动保存。所有行为依实际工具、允许来源和用户禁用项，不因固定提示扩权。

入口刷新依据当前文件版本，普通文件已保存即为当前知识；Git 失败需明确版本记录状态。写入保护、版本冲突与来源验证可以加在原文件链路，不必复制一套五合一 Memory API。

## 五、Dreaming：只做记忆整理与反思，不偷换成主动研究

Dots 的 Dreamer 读取连接器、父会话与笔记，在 agent_notes 保留发现并通知父级，但禁止直接改 user_notes/action_items。它是背景研究者，不是 Nano 记忆库的主写入器。采用其检查点、来源、后续核实和有变化才报告的实践，不照搬它的账号扫描范围或权限。

Muse 文档把 upkeep、关系维护、夜间反思分开；Claude Code 的用户本机调研把近期抽取与跨会话 dream 分开。Nano 初版可以用一次有界整理作业完成补漏、归纳和压缩入口，不增加六七类常驻 Agent。

自动条件：enabled、非停止态、有新的合格材料、距上次成功自动整理达到默认 24h；这是运行间隔不是连续空闲 24h。优先在主 Agent 对话安静约 10 分钟后的安全边界开始。持续工作时可从已落盘配对边界取得快照，后台低优先级处理，不截断主模型/工具、不等整个 Global session 结束。资源不足就延期、显示积压，不承诺准点。手动整理可绕过周期，但不绕过锁、权限和预算。

## 六、Global 历史：按事件范围，不按结束的会话数

当前 Nano 使用的 rc.5 换窗引擎保留原始持久事件。window 是模型可见窗口，既不是一次业务任务，也不是新的长期 Agent。history 只查已经离开活跃上下文的记录，而且工具作用域是自己的 session；把父会话 window ID 给新 Dreamer 不能自动获得读取权。

宿主需要只读历史适配器，把本主体上次处理点之后的持久原始输入、实际发送和关键工具/子执行结果，按有限范围导出到维护作业。当前窗口与旧窗口都能进入输入，不能只调用 archived history，更不能每次用当前可见上下文覆盖全历史。

最小进度状态是每条原始源流的 last_processed_seq/revision，而非“已经梦过几个 session”。读取、筛选、已处理、保留成记忆是不同状态。未读/失败/预算外片段保留待处理；无价值但已核对的片段可以不写笔记而前移处理点。换窗、fork 的继承历史、重复 Inbox 返回必须按原始来源去重。

完整输入、过程与验收见 design/global-dreaming.md。

## 不改变的边界

不改 Task 的根负责人；不重新绑定每个 child；不引入 personal_context / personal_attention；不把专家变成某个请求者的 PA；不把当前原生 notes 工作便笺等同于跨事项长期记忆；不自动重写全部旧库或启用生产维护。
