# 目录与正文规范

根目录固定：`<长期 Agent 配置 workspace>/.nanoassistant/memory/`。不是当前请求者路径，不随子 Agent cwd 变化，不在外部再套一层 agentId。Git 如采用独立子仓库，必须从业务仓库递归提交/发布中排除，不自动 remote/push。

## 两种目录 profile

### PA

```text
memory/
  MEMORY.md
  entities/
    people/             # 包括有价值的主人背景页、家人/同事；按真实主体区分
    agents/             # 独立专家，不是临时执行线程
    organizations/
    conversations/      # 会话用途与重要线程导航，不是消息副本
  knowledge/
    facts/              # 主人的相关生活/工作环境等当前理解
    preferences/        # 含沟通、主动性、日常和领域偏好
    decisions/          # 跨事项需要独立保存的决定及理由
  workstreams/          # 主人的长期目标/计划/项目背景；不管理 Task 状态机
  timeline/
    daily/              # YYYY-MM-DD.md，只记重要变化，空白日不创建
  archive/
  .git/
```

### 独立专家

```text
memory/
  MEMORY.md
  entities/
    people/
    agents/
    organizations/
    conversations/
  knowledge/
    domain/             # 领域知识、术语、已验证理解
    environments/       # 环境/系统/版本的相关约束
    collaboration/      # 工作方法的判断依据、分受众协作经验
    decisions/          # 跨项目需要独立保存的决定/取舍
  projects/             # 项目背景、约束、正式材料入口
  work-history/         # <真实task标识或稳定事项标识>.md；同项继续更新
  archive/
  .git/
```

这些是允许的标准位置，不要求预建空树。实例文件和下一级主题由 Agent 创建；创建前搜已有实体/别名。一级目录扩展通过产品约定修改，不由一次普通记忆写入决定。

项目内决定优先在项目文件，人物专属约定优先在人物文件。独立 decisions 页用于确实需要跨处引用的决定，不对所有决定另建文件。一个知识内容只有一个主要维护位置，其他位置链接。

不设 cases；不复制 Instinct 的 comms 全线程摘要或 active/completed Task 管理。需要回忆交流就引用现有 IM；一份重要交流的持久理解可以归其主题或日期记录。

## 每篇文档的共同外壳

新建页面建议包含三个字段：id/type/aliases。id 在该库稳定唯一；身份型页尽量用真实产品实体标识构造文档标识。type 说明这篇文档的用途，不要求正文都是一个事实。aliases 是检索线索，不能把同名人合并。

用普通 Markdown 相对路径链接，保留 id 用于重命名/去重；不以 [[id]] 的新解析服务为前置。需要按 id 寻址时，可按文件名约定与 glob/grep 查找。

来源在相关段落/脚注使用真实 locator；同一次交流可章节级引用，混合来源不要伪造一个来源支持整篇。普通正文自由叙述、列表或表格。没有必要为每个事实重复 metadata。

## 类型、正文和明确写入点

| 类型 | 建议正文 | 写入/更新点 |
|---|---|---|
| PA 人物/组织 | 当前背景；与主人的关系；重要共同经历；已确认偏好与沟通；目前相关事项入口；来源/不确定性 | 确认身份/关系变化；实际合作影响未来判断；不为每个出现的名字建档 |
| 专家人物/Agent/组织 | 已知职责/专业；合作接口；分人和分项目的要求；经历与证据；局限/未知 | 实际协作、明确交接、更正；不把当前请求者变成主人 |
| 会话 | 真实标识；用途；重要讨论入口；惯例与受众提示；最近确认时间 | 实际使用该会话、用途或关键线程变化；当前成员/权限仍查宿主 |
| 偏好 | 当前偏好；适用范围/例外；原因；应用方式；来源与纠正 | 明确偏好/纠正；反复观察只可标推断；一次选择不泛化 |
| 领域知识/环境 | 结论/术语；环境版本与前提；证据；反例/限制；如何核实与应用 | 经执行/文档验证的新增认识或失效；不复制整份代码/官方文档 |
| 决定 | 问题；考虑方案；实际选择与确认者；理由；范围/生效条件；重审触发；来源 | 真实作出或撤回重要决定，不把助手建议写成已决定 |
| workstream/project | 目标/背景；角色/责任入口；约束；关键决定；材料/Task入口；未决问题（as of） | 明确目标/约束/决策变化；即时状态不在这里独立维护 |
| PA 日期记事 | 每个重要事件一个小节：何时、谁、事实变化/实际结果、关联页和来源 | 关系/计划的真实变化、重要决定、明确反馈或具有后续影响的结果；普通闲聊不写 |
| 专家工作记录 | 工作目标和上下文；关键选择/尝试；可验证结果；反馈；得到/推翻的认识；复用范围和来源 | 工作完成/重要里程碑、原因得到验证、明确反馈改变原判断；同项更新，不每次重试新建 |

时间线是“过去发生什么”，实体/知识是“现在怎样理解”。不要把日记里的旧状态拿来覆盖当前主题页。

## 关于“什么时候记工作历史”

主 Agent 不必预测某件工作最终是否伟大：到已验证结果、里程碑或有意义反馈这一可观察点再决定。若整项工作完全例行、无新决定/教训且原 Task 足以恢复，就不建立记录。Dreaming 在持久事件中补检漏写；不是强制每项任务写复盘。

## 当前文件、版本与人为编辑

当前已保存 Markdown 是知识正文。所有普通工具读同样的文件。宿主以内容版本/哈希避免覆盖刚变化的文件；Git 自动记录受控修改，但不把“是否提交”变成文件可见性开关。人工编辑不能被后台覆盖；存在版本冲突时停止该改动并重读。

多文件修改必须有受控应用/回执，或明确部分成功并修复，不宣称 Git 自带工作区事务。只读操作不重写文件。清除历史需要另行受控维护，不将普通删除称为彻底遗忘。
