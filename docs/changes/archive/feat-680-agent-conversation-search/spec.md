# feat-680：Agent 聊天历史搜索

## 原始需求

> 现在的conversation搜索算法是啥

> 一个真正商业的IM，他的会是啥样的

> 是不是还会按时间优先搜最近的

> 所以我觉得现在的`conversations search`需要优化提升，要做真正的IM的好搜索，才能让agent能非常好的回溯到之前的一些聊天

## 澄清记录

- Q1：这次希望 Agent 搜索覆盖到什么程度？这会决定验收范围和后续方案。选项包括先做好关键词全文搜索，或同时支持语义搜索。
  - A1（用户原话）：我觉得是先做最ROI高基础能力，你觉得哪些能力是
- Q2：建议首期包括五项：中文和多关键词搜索；相关性与时间排序并能切换；聊天、发送人和时间组合过滤；搜索结果回到原文和上下文；分页、空结果和权限可信。语义搜索、附件内容检索和面向人的全局搜索界面放到后续。是否按这五项作为首期范围？
  - A2（用户原话）：可以，就按这五项作为首期范围，先把需求文档收敛好。

## 背景与现状

用户希望 Agent 在协助跨聊天工作时，能凭有限线索可靠地回溯原话和上下文。这里的「商业 IM 的好搜索」是体验目标，不要求复刻某个产品或其内部算法。

当前 `conversations search` 对消息正文做连续子串匹配，可按聊天、发送者和时间等条件过滤；结果按消息存储顺序倒序，没有多关键词组合或相关性排序，已有分页和原消息链接。实现见 [`work.ts`](../../../apps/im-server/src/work.ts)。聊天列表的前端搜索是另一入口，本期不以它代替 Agent 的历史搜索。

当前 PA 规格要求历史查询覆盖主人与 PA 参与且当前可访问的聊天并集，保留真实作者和出处，不设置任意日期窗口；来源排除对历史查询生效。聊天历史查询不消费 Inbox 或改变人的已读状态。分别见 [PA 历史查询](../../specs/im/personal-agent.md#历史查询同时覆盖主人和-pa)、[来源限制](../../specs/im/personal-agent.md#来源限制与风险提醒明确)和 [历史读取消费语义](../../specs/gateway/global-agent.md#inbox-读取与聊天历史读取具有不同的消费语义)。这些既有约束在本期继续成立。

## 用户场景

- 主人让 PA 找“项目发布、周四、方案”相关的讨论，但记不清原句或在哪个聊天里。PA 能组合关键词在当前允许访问的聊天历史中查找，不需要把三个线索恰好拼成原话；如果主人记得准确短语、编号或错误码，PA 也能精确查找。
- 主人想知道最近关于发布的讨论，或追溯一条很早的决定。PA 可以优先看相关内容，也可以按最新排序；不指定时间时旧历史仍在搜索范围内。记得群聊、发言人和大致时间时，PA 可以组合这些线索缩小范围。
- 搜索命中后，PA 能辨认是谁在何时、什么聊天里说的，并回到原消息及其前后文，再向主人解释和引用。结果很多时可继续查看，不把第一页当成全部；无匹配、范围受限或查询不可用时，不把未查全说成确实没有。
- PA 查询主人和自己可访问的聊天时，仍遵守主人排除来源的设置和当前权限；普通 Agent 仍限于其可访问范围。搜索和后续读取不改变人的已读状态，也不消费 Agent 的 Inbox。

## 验收标准

### Requirement: Agent 可使用关键词回溯消息

#### Scenario: 中文多关键词
- **GIVEN** 可访问的历史中有一条中文消息包含“发布”“周四”“方案”三个线索，它们不是作为一个连续短语出现
- **WHEN** 主人要求 Agent 使用这些关键词查找相关讨论
- **THEN** Agent 能找到该消息并辨认它是匹配结果，无需猜出整句原话

#### Scenario: 精确短语和标识
- **GIVEN** 可访问历史中存在准确短语或项目编号、错误码，另有内容相似但不包含该准确文本的消息
- **WHEN** 主人要求 Agent 按准确文本查找
- **THEN** Agent 能找到包含准确文本的原消息，并能区分仅内容相似的消息

### Requirement: Agent 可按相关性或时间查看完整允许范围内的结果

#### Scenario: 相关性优先
- **GIVEN** 可访问历史中有一条较早的消息明确包含用户提供的多个搜索线索，另一条较新消息只包含其中一个线索
- **WHEN** Agent 以默认方式搜索这些线索
- **THEN** 结果优先呈现与查询更相关的内容，并考虑消息的新近程度；较新的弱匹配不会仅凭时间自动压过较早的明确匹配

#### Scenario: 最新优先与旧历史
- **GIVEN** 可访问历史中不同时期都有符合条件的消息，包括较早的消息
- **WHEN** Agent 选择按最新时间查看匹配结果
- **THEN** 较新的匹配先出现，较早匹配仍可继续查到；未指定时间范围时不默认排除旧历史

### Requirement: Agent 可组合已知条件缩小搜索范围

#### Scenario: 聊天、发送人与时间组合
- **GIVEN** 多个聊天、发送人和时间段中存在相同关键词
- **WHEN** 主人要求 Agent 查找指定聊天中某位发送人在指定时间范围内的消息
- **THEN** Agent 得到同时符合这些条件的结果，能排除不符合条件的同词消息

### Requirement: Agent 可核实原消息及上下文

#### Scenario: 从命中回到原文
- **WHEN** Agent 找到一条相关消息并需要确认其含义或向主人引用
- **THEN** 它能辨认真正的发送者、时间和来源聊天，取得可定位的原消息，并能继续查看其前后对话
- **AND** 向主人说明事实时能指向可供主人访问的原消息；仅 Agent 可访问的来源按既有规则如实说明

### Requirement: 搜索结果完整性和访问边界可辨认

#### Scenario: 多页结果
- **GIVEN** 符合条件的消息多于一次返回的数量
- **WHEN** Agent 查看首批结果并继续查找
- **THEN** 它能知道还有后续结果并继续查看，直至查完或明确停止；不会把首批结果当成全部匹配

#### Scenario: 没有匹配与未查全
- **WHEN** Agent 在可查询范围内搜索无匹配，或搜索因范围受限、历史不可用等原因未能查全
- **THEN** 它能区分无匹配与未查全，并向主人如实说明已知范围或限制，不把未查全说成不存在

#### Scenario: PA 双身份和来源排除
- **GIVEN** 主人与 PA 各有符合条件的可访问聊天，其中一个来源被主人排除
- **WHEN** PA 搜索聊天历史
- **THEN** 它能发现允许访问的主人和 PA 来源中的匹配，不能取得被排除来源的结果；保留真实作者和来源

#### Scenario: 权限变化与续查
- **GIVEN** 搜索尚有后续结果，期间某个来源被排除或访问权限被撤销
- **WHEN** Agent 继续搜索或尝试读取该来源的原消息
- **THEN** 不再取得当前无权访问的内容；其他仍可访问的结果继续遵守原有权限

#### Scenario: 不消费未读
- **WHEN** Agent 搜索消息并读取命中消息的上下文
- **THEN** 主人的聊天已读状态和 Agent Inbox 的未读消费状态不因这次历史查询推进

## 范围与非目标

- 在范围：面向使用 `conversations` 的 Agent 改善消息正文检索、组合过滤、相关性与时间排序、来源与上下文回查、分页和可信的范围/状态表达；保留现有访问与未读边界。使用现有产品可查询到的聊天历史，不承诺本期接入外部平台尚未同步的历史。
- 非目标：语义搜索、附件内容检索、面向人的全局搜索界面；不以引入特定搜索引擎或复刻其他 IM 为验收目标。技术方案、接口形式、搜索策略和验证方法由后续设计确定。
