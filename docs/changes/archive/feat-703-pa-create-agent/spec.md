# feat-703: 在与 PA 的聊天中按明确要求创建 Agent

## 原始需求

> 我觉得PA应该能够帮我创建agent，这样我能在跟他的聊天中创建agent

## 澄清记录

- Q1：这里的 Agent，我理解是创建后会出现在 Agent 列表、可以长期聊天和配置的独立助手，对吗？
  - 用户回答：对，创建长期使用的独立 Agent
- 用户补充：指的是在我明确要求的时候，它能够帮我去创建。
- Q2：没指定电脑时，默认在 PA 所在电脑创建；明确指定其他电脑时按指定执行，指定电脑离线也不擅自换机。这个默认符合预期吗？
  - 用户回答：符合，需要在创建的时候问清楚我相关选项。需要创建1个skill和多少个工具？这工具能不能渐进式披露？毕竟平时用不到

- 范围收口：用户选中方案“1 个按需 Skill + 1 个固定短定义的 agent_creation 工具。详细选项通过 options 的结果按需返回，创建和状态查询共用这个入口；使用前后不增删工具 schema。这样可以把详细操作信息渐进披露，同时保持工具前缀稳定，无需为一个低频能力引入通用搜索系统。”
  - 用户决定：算了，本需求只做这个吧。这些通用能力后续考虑

Agent 解读：本需求是给 PA 增加按主人交办创建独立 Agent 的能力。创建须来自用户明确要求；普通需求讨论、助手建议和观察到的聊天内容不能自行触发创建。创建前需与用户问清相关选项，不能仅凭“帮我创建”就静默决定全部配置；已有明确选择不重复询问。用户接受推荐或默认配置后即可执行，不额外要求重复批准同一次创建。本次按用户选中的方案收口为 1 个按需 Skill 和 1 个固定短定义的 agent_creation 工具；详细配置选项通过 options 结果按需取得，创建和状态查询共用此入口，使用前后不动态增删工具定义。通用工具渐进披露能力留待后续独立考虑。本方案保持本功能的工具前缀稳定，不承诺服务端实际缓存命中率。

## 现状依据

- [IM Agent 与节点契约](../../../specs/im/agents-nodes.md)已定义在本人已绑定、在线节点上创建 Agent、配置职责与能力、取得真实创建结果及处理未确认结果的行为。
- `apps/im-server/src/control-routes.ts` 的现有节点下创建入口经配置操作创建 Agent；当前需求是在与 PA 的聊天中完成这一用户目标。
- [Gateway PA 契约](../../../specs/gateway/personal-agent.md)区分主人直接交办与观察内容；观察到的消息不自动成为控制命令。

以上是现状依据，不表示聊天创建能力已经实现，也不约定本需求的内部接口形态。

## 用户场景

### 明确交办后完成创建

用户与自己的 PA 聊天，明确说“帮我创建一个负责英语口语练习的 Agent”。PA 根据本轮及相关对话理解用途，帮助形成新 Agent 的名字和职责。创建前，在聊天中把相关配置选项和推荐值说明白，与用户确定后再创建；包括目标电脑、工作方式、模型、职责说明、Skills、工具及相关运行能力，其他适用配置按需展开。目标电脑默认推荐 PA 所在电脑，用户可以另选。已有明确选择不重复询问，用户可明确接受默认或推荐配置，无需逐项重新填写整张表。

创建完成后，PA 在当前聊天说明创建了哪个 Agent、负责什么、位于哪台电脑，以及如何开始与它聊天。用户能在现有 Agent 列表中找到它，之后可以长期聊天并通过现有配置页维护它。

### 低频能力按需进入

平时与 PA 处理其他事情时，不展开 Agent 创建指导或创建向导。用户提出创建需求时，PA 才按需取得创建指导和操作信息，再查询真实可选配置并与用户确定；用户无需学习额外工具命令。

### 讨论不自动创建

用户只是讨论“是不是需要一个英语口语助手”、表达需求，或 PA 提出创建建议时，不发生创建。用户之后明确说“那就创建吧”，可以承接刚讨论的对象与要求执行，不要求重新复述全部内容。若用户在执行前撤回创建要求，PA 遵从撤回。

### 创建受阻时如实说明

没有可用电脑、目标电脑离线、名称或其他配置存在冲突，或者创建结果尚未确认时，PA 在当前聊天说明真实状态和下一步。结果未确认不能报告已经创建，也不能因重复尝试而给用户创建多份相同助手。

## 验收标准

### Requirement: 用户明确交办是创建的前提

#### Scenario: 根据明确要求创建
- **GIVEN** 用户有可创建 Agent 的在线电脑，创建所需信息已经充分
- **WHEN** 用户向自己的 PA 明确要求创建某个独立 Agent
- **THEN** PA 在这次聊天中完成创建，无需用户另去创建页操作或重复批准同一次创建。

#### Scenario: 普通讨论与观察不触发创建
- **WHEN** 用户仅讨论是否需要某类助手、PA 提出建议，或 PA 从观察聊天中得知某种需求，尚无用户向 PA 提出的明确创建要求
- **THEN** 不创建新的独立 Agent。

#### Scenario: 承接讨论中的明确要求与撤回
- **GIVEN** 用户与 PA 已讨论清楚准备创建的 Agent
- **WHEN** 用户明确要求按讨论内容创建
- **THEN** PA 能承接已有内容，不要求用户重新填写相同信息。
- **WHEN** 用户在执行创建前撤回要求
- **THEN** PA 不继续创建。

### Requirement: 从用途描述得到可长期使用的独立 Agent

#### Scenario: 创建结果可找到、可聊天、可配置
- **WHEN** PA 成功完成用户交办的创建
- **THEN** 当前聊天说明新 Agent 的名字、职责、所在电脑和使用入口。
- **AND** 用户能在现有 Agent 列表找到该 Agent，与它聊天并通过现有配置页维护；它是长期存在的独立助手。

#### Scenario: 创建前问清相关选项
- **WHEN** 用户明确要求创建 Agent，但相关配置选择尚未对齐
- **THEN** PA 在聊天中说明真实可用的相关选项与推荐值，与用户确定后再创建，不静默替用户决定全部配置。
- **AND** 已明确的信息不重复询问；用户可直接接受默认或推荐配置，无需逐项填写整张表。

#### Scenario: 默认电脑可辨认并允许另选
- **WHEN** 用户尚未指定创建电脑，PA 与用户对齐创建选项
- **THEN** PA 推荐自身所在电脑并说明该选择，用户可以指定其他本人可管理电脑。
- **AND** 用户指定的电脑不可用时说明原因，不擅自换机。

### Requirement: 创建指导与操作信息按需披露

#### Scenario: 普通聊天与创建请求
- **WHEN** 用户与 PA 处理无关事务
- **THEN** 不自动进入创建向导或展开详细创建指导。
- **WHEN** 用户提出创建 Agent 的需求
- **THEN** PA 能按需取得创建指导及所需操作信息，并继续完成选项对齐与创建，用户无需额外学习命令。

### Requirement: 创建遵守已有管理范围并报告真实结果

#### Scenario: 无可用电脑或配置不被接受
- **WHEN** 用户没有可用电脑、目标电脑离线、目标不在其管理权限内，或创建配置被拒绝
- **THEN** PA 说明未能完成创建及具体原因，不宣称创建成功，也不擅自换到其他电脑创建。

#### Scenario: 结果未确认与继续处理
- **WHEN** 创建已发起但结果暂时无法确认
- **THEN** PA 明确告知尚未确认，后续确认或继续处理同一次请求时不会创建重复助手。
- **AND** 只有取得真实成功结果后才报告创建成功。

## 范围与非目标

- 在范围：用户与自己的 PA 聊天并明确要求时，创建本人可管理节点下的长期独立 Agent；必要澄清、创建结果和使用入口反馈；沿用既有创建与管理边界。
- 非目标：PA 根据观察或推测主动创建 Agent；新增临时执行子 Agent 机制；扩展为聊天中的 Agent 修改、删除、迁移或批量管理；替代既有 Agent 配置页；通用 Tool Search、Skill 与工具动态加载联动，以及 personal_sources 等其他低频工具的披露改造。本需求不以 DSH 升级为前置工作。
- 本文只收口需求。内部工具、权限接入、配置选择与创建结果恢复的具体方案留给设计阶段。
