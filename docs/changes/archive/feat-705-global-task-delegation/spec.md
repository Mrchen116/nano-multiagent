## 用户场景

### 一项完整工作由一个执行者负责

用户向“禅”交办“拉取 DeepSeek Super Agent，并与我们的 Global Agent 对比”。主 Agent 理解原始请求、实际来源和已有约束，确认后把完整目标交给一个内部执行者。执行者自行选择阅读顺序、调查方法、是否再安排下级及如何整合结果，负责交回完整比较成果和必要依据。主 Agent 不同时阅读两边代码重新做一遍研究，也不自行制定技术拆分和额外验收清单。

主 Agent 核对返回成果是否回应用户要求、是否有明确缺口及可用依据；内容矛盾或不足时交回原执行者补齐。需要用户选择、补充材料或处理权限时，执行者内部报告已有结论及具体问题，主 Agent 向用户沟通，收到答复后交回原执行者。接单回应、必要进度、问题和实际结果均由主 Agent 向用户发送，执行者不能绕过主 Agent 与用户对话，内部回传不是公开交付。

### 执行期间接新工作，补充仍回原事项

事项 A 在执行时，用户提出无关的事项 B、询问状态或纠正 A。主 Agent 及时接住这些输入：B 若需独立执行则另行委派，日常短问直接处理；A 的更正、答复和后续修改交给 A 的原执行者，而不是重开重复研究。仅仅话题相近的消息不自动并入 A；不能确定归属且会影响实际执行时才澄清。执行者仍能工作而无新决定时，不要求主 Agent 反复回复“继续”或检查进度。

### 贯穿一天的日常交流留在主 Agent

用户早上说精神不好，中午反馈分享材料做完，傍晚问“我还有什么 todo”，晚上说跑了两公里。PA 沿用同一人的上下文直接交流、查询相关信息和处理小事，把新的完成反馈用于后续回答，不把整天定义成一个持续运行的执行任务，也不为每句话创建执行者或持久 Task。需要后续跟进的小事沿用当前可用的安排；本阶段不改变 Task 创建及调度规则。已有获准定时关心仍通过现有安排发生，没有新帮助价值时保持安静。

日常交流中若出现“帮我整理一份完整分享材料”这样的独立交办，PA 将该事项交给一个执行者，同时继续其他日常对话。该事项的补充回原执行者；用户的倾诉、愿望、自述进展或对外承诺本身不自动成为新的执行授权。

### 委派事项的结果、阻塞与接续仍归同一主 Agent

执行者在既有范围内自行推进，缺少只能由父级取得的聊天事实、用户决定或权限时，向主 Agent 内部提出具体请求。主 Agent 处理必要协调，向用户提出具体问题，再把有效答复交回原执行者；不接手重复调查。普通进展不需要父级回复“继续”。

用户在聊天中更正、停止或明确接续一个委派事项时，主 Agent 沿已有原生父子机制定位原执行者，传递有效要求并处理对应执行范围。其他独立事项不被重开或无条件停止；已发生动作按真实结果保留。原执行者确实不可接续时，主 Agent 说明原因和保留成果，再明确接手安排，不静默复制工作。

执行者完成后向主 Agent 回传完整成果、必要依据和真实缺口。主 Agent 核对成果是否回应原要求，缺口交回原执行者补齐；可用成果向用户实际交付。用户不需要分别与内部执行者沟通，也不因为内部派发成功就被告知整个事项完成。

### fork 默认关闭，明确选择仍能使用

新建普通 Agent、Global 或 PA 时，fork 仍在可选工具中，但默认未选中。没有显式工具名单的运行配置采用同一默认值。用户明确选择后，沿现有保存和生效规则开启；关闭后也按现有撤回规则生效。用户已保存的名单不被升级静默改写，Goal 的三个工具仍独立选择。

开启只使该主会话可调用既有 fork，不附带新的工作要求或取消流程。一级执行者的 fork 可用性取决于 DSH 工作工具及原生限制，与主会话是否开启无关。各类原生结果按真实语义表达，不将受理当完成。

## 验收标准

### Requirement: Global 与 PA 将完整独立事项交给一个内部执行者负责

#### Scenario: 整项交办与内部再分工
- **WHEN** 用户交办需要独立调查或制作成果的完整事项
- **THEN** 用户在工作视图能辨认一个负责该完整事项的内部执行者，其下级分工由该执行者组织。
- **AND** 主 Agent 不把这项完整目标拆给多个直接执行者后同时亲自重复调查，也不替执行者预设技术实施方案或新增用户未要求的范围。

#### Scenario: 返回结果不足或执行能力不可用
- **WHEN** 返回成果遗漏原要求、依据不足或存在矛盾
- **THEN** 主 Agent 把具体缺口交给原执行者继续处理，不自行重做同项调查，也不将不完整成果描述为全部完成。
- **WHEN** 当前没有可用执行能力或原执行者确实无法继续
- **THEN** 用户得知具体受阻情况及已有成果，不因派发失败而收到完成声明，也不发生未说明的重复执行。

### Requirement: 委派期间主 Agent 继续处理独立输入并保留原事项归属

#### Scenario: 新工作与原事项更正
- **GIVEN** 事项 A 已由内部执行者承担
- **WHEN** 用户提出独立事项 B，或补充、更正 A 的要求
- **THEN** B 能被接住并按其性质直接处理或独立委派；A 的补充进入原执行者负责的事项，不重开同一份工作。
- **AND** 不能只因话题相近就把新交办并入 A，用户不需要为了内部委派重新复述已有背景或重复批准同一授权。

#### Scenario: 内部普通进展无需父级续令
- **WHEN** 执行者仍能在既有范围推进，只产生普通进展或受理回执
- **THEN** 工作继续，无需主 Agent 逐步批准；用户不会因此收到重复进度、重复成果或例行“收到、继续”转述。

### Requirement: 日常交流由主 Agent 直接延续

#### Scenario: 一天内的小事与状态变化
- **WHEN** 用户在一天的不同时段闲聊、反馈状态或完成情况、回顾经历、查询待办及交办几步可完成的小事
- **THEN** 主 Agent 直接处理并承接已有上下文，后续回答考虑新的完成反馈和当前状态。
- **AND** 不将整天包装成一个执行任务，不为每条消息创建执行者或持久 Task，也不把自述、倾诉和观察内容当作新的交办。

#### Scenario: 日常中出现独立交办
- **WHEN** 日常交流中用户另行交办一项需要独立调查或制作成果的完整工作
- **THEN** 该工作交给一个执行者负责，日常交流继续由主 Agent 接住；后续相关修改仍由原执行者承接。
- **AND** 已有定时关心和授权内日常安排继续使用，没有新帮助价值时不重复催问或播报。

### Requirement: 主 Agent 处理必要决策并完成实际交付

#### Scenario: 决策与最终结果
- **WHEN** 执行者提出确需用户决定的具体问题，或交回可用完整成果
- **THEN** 主 Agent 在正确聊天提出必要问题或交付结果，用户答复回到原执行者；常规实施选择仍由执行者处理。
- **AND** 结果交付回到事项的正确来源聊天，不被最近一个聊天覆盖；内部回传、执行者空闲和状态通知不能代替公开交付。
- **AND** 完成与待确认依据实际成果及既有规则表达，不新增强制用户验收阶段；失败或未知回执不能声称已送达，也不重复已确认交付。

#### Scenario: subagent 始终通过 Global 与用户沟通
- **WHEN** subagent 需要向用户确认、汇报进展、解释阻塞或交付成果
- **THEN** 由 Global 在正确会话与用户沟通，用户的答复通过 Global 交回原执行者；subagent 不直接向用户发消息、另开会话或通过其他工具绕过这一入口。
- **AND** 用户无需管理内部执行者；查看工作轨迹不产生另一个需要用户维护的对话入口。

### Requirement: 更正、停止与明确接续作用于原委派事项

#### Scenario: 更正或停止一个独立事项
- **GIVEN** A 与 B 分别由不同内部执行者承担
- **WHEN** 用户在聊天中更正或要求停止 A
- **THEN** 主 Agent 将新要求交到 A 的原执行者，并沿现有管理机制处理相应执行范围；不重新创建一份 A，也不无条件停止 B。
- **AND** 已发生动作保留真实结果，不声称已回滚；普通进展或晚到成果不能自行恢复用户已停止的事项。

#### Scenario: 明确接续与原执行者不可用
- **WHEN** 用户明确要求继续原事项
- **THEN** 主 Agent 优先联系原执行者，传达当前要求并承接已有成果，无需用户重新交代整个背景。
- **AND** 原执行者确实不可接续时说明具体原因和接手安排，不把新执行者冒充原执行者，也不静默从头重复工作。

### Requirement: 一级执行者独立获得工作能力，二级沿用原生子 agent

#### Scenario: 主会话关闭 fork，一级仍可组织下级
- **GIVEN** Global／PA 主会话未启用 fork，且其普通工具勾选仅满足主会话的实际需要
- **WHEN** 它将完整事项交给一级 subagent
- **THEN** 一级以 DSH 默认工作能力为基础独立执行，能使用原生 fork 和可用的子 agent 管理能力，不因主会话未勾选这些普通工具而失去执行能力。
- **AND** 内部消息只发直接父级或下级；二级沿用 DSH 普通子 agent 机制、深度和权限，不获得 Global 产品入口或用户沟通权限。

#### Scenario: 初始上下文与责任不串层
- **WHEN** Global 创建一级执行者，或一级再创建二级执行者
- **THEN** 各层沿用 DSH 基础工作及委派上下文；一级收到完整事项和端到端责任，二级收到父级分配的子目标。
- **AND** 普通二级只用 DSH 原生子 agent 上下文与父级交办，不加 Nano 身份或一级职责；普通子会话不复制根 Persona、根历史或整份 Inbox，需要用户信息或决定时逐级回到 Global。fork 保留其原生父上下文继承语义。

### Requirement: 主会话 fork 默认关闭并允许用户显式选择

#### Scenario: 新建与无显式选择
- **WHEN** 用户新建 Global、PA 或 SingleThread Agent，或运行配置没有显式工具选择
- **THEN** fork 默认不启用，仍可在现有工具选择中找到，不因可用就自动执行。

#### Scenario: 手动开启与关闭
- **WHEN** 用户在现有工具配置中选择或取消 fork 并保存
- **THEN** 按既有工具选择与生效规则采用该设置；开启后可使用原生 fork，关闭后不能继续调用已撤回的能力，不增加硬禁止或额外审批开关。
- **AND** 此开关只作用于该主会话，不改变一级执行者按 DSH 使用 fork 的能力或原生深度、权限；Goal 三项独立选择不受该设置影响。

#### Scenario: 保留已有选择和一次性语义
- **WHEN** 已有保存工具选择的 Agent 升级或恢复
- **THEN** 原名单保持，不静默改写用户选择；fork 是否可调用取决于当前有效设置。
- **AND** 开启只增加原生工具，保持原有返回模式，不增加专门提示词、清理轮次或取消机制。

## 范围与非目标

- 在范围：普通 Global 与 PA 的主从职责、完整事项委派、执行者内部进一步分工、主 Agent 继续接新输入、同事项更正及接续、聊天内的停止协调、日常小事直接处理、唯一用户沟通入口及真实交付。
- 在范围：统一受影响的默认提示与相关随包工作方法，避免主从职责指引相互冲突；保留用户自定义配置，设计说明既有 Global/PA 会话如何采用新分工。
- 在范围：按角色装配一级工作能力与二级原生子 agent；明确各层初始上下文、内部回传和恢复。主会话 fork 按现有 Goal 方式默认关闭，覆盖新建／无显式选择的各模式主 Agent；保留显式开启、已有保存选择及原生语义，一级不沿用此开关。
- 非目标：本阶段不改 Task 的创建条件、图结构、状态、看板、调度、执行者绑定、自动续推、暂停恢复或流转事件链路；不新增示例中的 task_graph delegate 动作或接单联动工具。
- 非目标：新工单系统、第二套执行循环、临时 subagent 长期成员化、SingleThread 职责和交付方式调整（仅追加统一 fork 默认值）、子 Agent 产品聊天或主人代发权限扩展、原生委派深度及授权范围扩展。
- 当前 Task 自动续推主会话的行为保留；本阶段不承诺 Task 会自动唤醒对应 subagent，也不把 Task 驱动的无人值守持续执行作为本阶段跑通条件。已有 Task 的授权、归属与交付规则继续生效；不得为跑通委派而静默改 Task 状态、关闭功能或修改生产配置。
- 本文收口当前阶段需求；模型可见指引、已有原生委派与返回模式及会话生效边界由后续技术设计确定。尚未修改产品代码或部署。

## 后续 Task 改造记录（用户暂缓）

此部分保留用户已经提出的目标及尚未实施的设计方向，不属于上述当前阶段验收；恢复该范围需用户后续明确要求，不能因本阶段采用 subagent 就顺带实施。

1. Task 让用户看到所有已接下的完整执行事项：哪些在做、哪些在等、等谁或缺什么、哪些需要用户决定、有哪些可用成果。真实业务状态与原生执行状态分开，不因主 Agent 空闲就认为没有工作。
2. Task 不应仅在用户明确说“创建任务／保存计划”时出现。完整独立交办进入 Task，已有同项记录则沿用；确有持续跟进责任的小事也可按实际需要记录。倾诉、状态反馈和观察到的承诺不自动成为执行授权，不为每条聊天或每个下级执行者机械建 Task。
3. 接单、Task 记录与对应首层执行者应联动，避免漏记已开始工作、重复创建 Task／执行者或显示已执行却无人承担。Task 的产品负责人仍是 PA／禅；计划、人工负责事项和无需独立执行的小事可以没有 subagent。完整事项的首层执行者自行管理下级分工，不按任务图节点数量机械派工。
4. Task 的持续推进对象应是对应原执行者：doing 且仍有合法下一步、无真实阻塞、执行者已经停止一轮时续接原执行者；正在运行、已有有效待处理输入或仍有下级／工具结果将唤回时不重复启动。真实故障不能伪造成 waiting、完成或用户暂停，也不反复唤醒主 Agent 做同一调查。
5. waiting 表达真实业务等待而非内部执行者工作中；沿用有效安排与复查。暂停、关闭、改派、权限变化和明确恢复要落到对应执行范围，其他独立事项继续。重启或恢复优先承接原执行者与已完成成果，不重复从头执行。
6. Global 对 Task 的开始、等待、恢复、提交成果、完成、暂缓、关闭、改派及需处理异常保持了解，复用可靠的事实补齐与消费链路。需要沟通的成果、问题和故障能使它接续处理；普通步骤与无变化检查不逐条打扰主 Agent 或用户。
7. 全部用户提问、进度、阻塞和最终交付均通过 Global；subagent 永远先向 Global 内部回报，用户答复再由 Global 交回原执行者。看板与轨迹不是另一个用户—subagent 对话入口。内部回传与状态通知不等于公开送达，成果仍交付到正确所属聊天。
8. 上轮模拟曾提出扩展现有 task_graph 增加 delegate 动作：接收原始交办来源，创建或复用 Task，启动后台可接续 subagent 并保存关联。这是候选接口示例，尚未定稿或实现；本阶段不新增该动作，后续设计需整体确定 Task 与执行者的联动方式。
