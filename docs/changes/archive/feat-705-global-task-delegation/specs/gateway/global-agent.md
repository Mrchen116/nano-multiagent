# gateway global-agent Specification (delta for feat-705)

> 目标：`docs/specs/gateway/global-agent.md`。仅当前主从职责，不包含暂缓 Task 改造。

## REMOVED Requirements

### Requirement: 主 Agent 统筹工作，并偏向按需委派执行

## ADDED Requirements

### Requirement: 主 Agent 将完整独立事项交给单一内部执行者负责

主 Agent 与其 subagent 共同构成 IM 中一个独立、负责的角色，内部委派不转移对外的工作和交付责任。它与人和其他 IM Agent 平等协作，持续承担配置中的职责与目标，结合相关聊天、记忆与执行结果，在职责和权限内主动开展有价值的工作并接续已有事项；主会话是这个角色的对外表达与内部委派入口。普通 Global 与 PA 使用同一分工，具体服务对象和职责由各自角色配置确定，不因使用 Global 执行模式统一变成组织专家。

#### Scenario: 完整交办与内部再分工
- **WHEN** 用户向 Global 交办需要独立调查、制作成果或持续执行的完整事项，或 Global 根据既有职责和权限开展这类事项
- **THEN** 主 Agent 将整项目标及有效约束交给一个内部执行者负责到底，该执行者自行组织必要下级并整合成果。
- **AND** 主 Agent 不同时重复调查或替执行者预设实施方案；返回有缺口时交回原执行者补齐，不将派发当作完成。

#### Scenario: 日常交流和小事直接处理
- **WHEN** 用户闲聊、反馈状态或进展、回顾日常、查询待办或交办适合直接完成的小事
- **THEN** 主 Agent 直接承接上下文并处理，不因跨一天、跨消息或全局模式就强制创建 subagent。
- **AND** 日常中另有完整独立交办时只将该事项委派，不把整天包装成持续执行任务；倾诉和观察不自动成为交办。

#### Scenario: 多项独立工作与原事项更正
- **GIVEN** A 已由一个内部执行者承担
- **WHEN** 用户补充 A 或提出独立事项 B
- **THEN** A 的有效补充交回原执行者，B 可直接处理或由自己的执行者推进；主 Agent 继续接新输入，不为 A 重开重复工作。
- **AND** 用户可在现有工作视图辨认各事项的委派、结果和执行范围；普通内部进展不需要主 Agent 逐步批准或逐条转发。

#### Scenario: 必要问题与交付
- **WHEN** 执行者需要用户决定或交回完整成果
- **THEN** 由主 Agent 在正确原聊天提出问题或交付可用结果，有效答复回到原执行者；内部受理和完成通知不能替代实际交付，也不导致重复发言。
- **AND** subagent 始终通过主 Agent 与用户沟通，不另开用户对话或通过其他工具绕过该入口。

#### Scenario: 原执行者更正、停止与明确接续
- **WHEN** 用户在聊天内更正、停止或明确接续一个委派事项
- **THEN** 主 Agent 沿已有原生机制处理原执行者和对应范围，保持其他独立工作；不把中断受理描述为已经停止，不把晚到成果当恢复授权。
- **AND** 原执行者不可接续或当前能力不足时说明真实原因与保留成果，不冒充已执行、不静默复制工作；已发生副作用按真实结果保留。

#### Scenario: 外部通信能力不等于派工权限
- **GIVEN** 用户未授予对其他 IM Agent 的任务分配权限
- **WHEN** 用户要求该数字人完成一项工作
- **THEN** 它可处理日常小事或内部委派，不因能够向其他 IM Agent 发消息就默认将工作分派给对方。

## MODIFIED Requirements

### Requirement: 全局 Agent 在任务执行期间主动沟通

#### Scenario: 简单请求直接交付
- **WHEN** 用户提出简单请求
- **THEN** 直接发送结果，不单独发送受理确认或回答预告。

#### Scenario: 接到真人任务
- **WHEN** 全局 Agent 读取到真人交办的长任务，且用户未要求不回复
- **THEN** 系统要求它在开始或委派主要工作前，向原会话简短说明具体事项与预期结果；已授权的工作不因这次告知等待再次批准。

#### Scenario: 职责内主动开展工作
- **WHEN** 全局 Agent 准备在既有职责和权限内主动开展较大事项，且用户或既定指引未要求静默
- **THEN** 主 Agent 在开始或委派前，向相关工作会话简短说明具体事项与预期结果，再继续已授权的工作，不将告知变成额外审批。
- **AND** 消息受众与私有信息边界保持，日常小事直接处理，执行中的普通进展不逐条外发。

#### Scenario: 长任务过程更新
- **WHEN** 全局 Agent 处理长任务或多步骤任务
- **THEN** 系统要求它通过显式消息发送对用户有用的成果、影响交付的重要变化、需其介入的阻塞或约定节点更新，合并内部阶段进展；用户主动询问状态或明确要求汇报频率时及时回应并遵守约定。
- **AND** 确认和进度通常为一两句话，避免重复状态、工具日志或空闲播报；用户明确不回复的要求仍受尊重。
- **AND** 确认和进度不代表最终结果已交付，内部草稿不算向用户更新。

#### Scenario: 内部进展无需父级介入
- **GIVEN** 主 Agent 已委派工作，执行者可按当前授权和要求继续
- **WHEN** 收到普通进展或受理回执，且没有新决定、更正或需要持久保存的状态变化
- **THEN** 不回复“收到/继续”、不重复交办，不因这条消息自动重读或改写工作笔记，也不逐条转述给用户；可按现有规则私有收尾。
- **AND** 执行者自行完成常规步骤和可恢复问题，将发现汇总在成果中；不逐步汇报等待批准继续，按原生模式报告成果，主 Agent 不因随后完成通知重复回复或向用户交付。

#### Scenario: 必要沟通和最终交付保持
- **WHEN** 用户首次交办、主动询问状态、提出更正/停止/接续，或工作出现需上级处理的阻塞、影响交付的重要变化、约定汇报节点或最终成果
- **THEN** 按实际来源及时处理、联系原执行者或向用户反馈，保留所需授权、状态和真实投递检查；普通进展的静默不吞掉这些必要行动。
- **AND** 内部阶段进展合并到用户有价值的更新，执行者所需的新资料或决定由父级明确返回；不增加固定限频或消息丢弃规则。
