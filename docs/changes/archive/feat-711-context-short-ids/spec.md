## 澄清记录

- 原实现采用会话内递增短编号；2026-11-05 用户后续要求改为每个新窗口独立从 1 开始，避免永续 session 的编号不断增长。2026-11-05 用户进一步明确“不需要！不用兼容旧版本”；仅保证新规则下的引用稳定，不实现旧版本编号迁移。
- 前序讨论要求尽量还原 Codex 的模型可见效果，适配 DSH 公开架构。预算工具默认只呈现剩余预算与估算语义。
- 控制消息不需可引用，不恢复 Agent name 或 developer role；不扩大跨会话权限，不恢复 Skill 全文。此前方案的旧 Notes 编号兼容明确不纳入；保留原始日志与 Notes，不删除用户历史。
- 本次授权涵盖建立 unit、实施、验证与 PR 交付；生产部署另行授权。

## 用户场景

Agent 执行长任务，直接在用户材料和工具结果旁看到短引用，不必先查询一页引用表。用户追加纠正后即使裁剪、换窗或进程重启，Agent 仍能恢复原要求和工具原文并继续交付。查询预算时不再收到大量内部计算字段。

## 验收标准

### Requirement: 内容旁提供简短稳定的引用

#### Scenario: 首次阅读任务与工具结果
- **WHEN** Agent 首次阅读新任务材料和工具结果
- **THEN** 可以直接取得同一窗口内按顺序递增的短引用，无需额外查询引用表
- **AND** 控制提示不伪装成新的任务材料

#### Scenario: 新窗口重新编号
- **WHEN** 成功切换到一个新窗口
- **THEN** 新窗口的新内容从短编号 1 开始；不同窗口可以有相同短编号
- **AND** 同一新规则下已发出的窗口引用仍按原 window_id 与 item_id 恢复，不被重新编号；不兼容旧版本会话级编号

### Requirement: 长任务按原始证据继续

#### Scenario: 裁剪、换窗与重启
- **GIVEN** Agent 已记录任务和结果的引用
- **WHEN** 经历工具结果裁剪、上下文换窗和节点重启后继续任务
- **THEN** 原引用保持有效，可恢复原文和长结果的后续部分
- **AND** 来源和既有访问范围保留，未完成任务不被误报为完成

### Requirement: 预算信息简洁且准确表达估算

#### Scenario: 查询剩余预算
- **WHEN** Agent 查询当前窗口剩余预算
- **THEN** 得到简洁的剩余量或未知状态，并知道该数值是估算
- **AND** 不附带默认引用表和内部预算中间参数

## 范围与非目标

- 在范围：dsh-agent-context 插件的短引用、History 与标记清理、提示词、预算返回；Nano 固定依赖接入与必要验证。
- 非目标：DSH fork/private import、跨会话读取、控制消息角色还原、Skill 恢复、历史 Notes 编号兼容、生产部署或清空历史。
