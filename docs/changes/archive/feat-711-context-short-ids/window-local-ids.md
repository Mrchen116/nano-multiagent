# feat-711: 窗口内短编号后续修正

## 已确认目标与边界

用户要求永续 session 中每个新窗口从 1 编号，并进一步明确“不需要！不用兼容旧版本”。Codex history 契约不能证明其服务端必然重置，本次按用户要求实施，不声称复制未公开算法。不改访问权限、宿主 source_history 的 seq、预算和裁剪阈值。

仅保证新规则内的窗口/短编号在裁剪、换窗、重启后稳定。保留原始日志和 Notes，不兼容旧版本会话级短编号，不加迁移标记、编号基数恢复或旧窗口回退。

## 设计

- 将原 history.ts 的成功窗口识别提到插件内部 windows.ts；history 保留原导出，checkpoint/消费者无需改接口。History 与编号都使用同一 start + summary + 无 error 的 end 定义，失败/不完整事务不重置。
- itemIds 从完整日志重建：每个成功窗口结束处把下一个编号重置为 1；在该窗按逻辑消息首次出现递增。message.id 全程去重，物理替换不占号，保留原消息所属窗及其原号；不从持久标记反推版本或编号基数。
- pending user 接在当前窗口已提交内容之后。同一步触发换窗时，事务完成后重新标记这些 pending inputs，先剥自己的旧标记再附新标记，避免正文出现两个编号。
- History 的寻址继续使用 window_id + item_id，允许不同窗口重号；原始 message.id 和 seq 仍负责物理去重、排序、分页、原文和窗口归属。prune 后旧消息仍归原窗口，fork/重启依据完整继承日志重建。
- guidance 明示编号只在窗口内有效，Notes 继续成对保存窗口和短号。新不可变插件版本按既有发布流程接入 Nano，生产部署仍另行授权。

## Context 与验证

Consumer 为用户/工具结果旁读取短标记并用 history 恢复的模型。Before: A/1、A/40 → B/41；After: A/1、A/40 → B/1；读 A/1 与 B/1 得不同原文，内容不能混窗。

沿用 M1-short-ids，仅追加受影响验证：同号不同窗的原文恢复、同规则原窗口不变、新窗口首次输入/工具 ID、同一步 pending 输入遇到换窗、失败事务、裁剪副本和 JSON 重放。测试捕获实际 adapter 输入；真实模型沿独立 RuntimeClient 的新会话，经历两次公开换窗和进程重启后直接恢复两个窗的 item1。旧版本兼容不在验收范围，不保留兼容测试。其他已有效门禁按影响保留。

## 门禁影响与用户裁决

R6/R7 的兼容设计保留为历史；用户明确取消旧版本兼容后不实施 R7 的 metadata/回退方案。代码审查 R8 的旧版本无 marker 窗口问题按需求变更 superseded，不声称兼容问题已被修复。最终 code review/verifier 以本版本需求为准。产品 R3 已验证新会话模型可见规则；最终删除兼容代码不改其记录中的任何新会话编号/文本，按实际影响保留并补包接线验证。
