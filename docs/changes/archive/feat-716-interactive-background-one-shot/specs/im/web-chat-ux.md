# IM web-chat-ux Specification (delta for feat-716)

## MODIFIED Requirements

### Requirement: 交互内容保持聊天阅读与操作连贯

Web IM SHALL 在对应 Agent 回复中呈现交互，用户可操作或自然打字继续，不管理后台保存和附带模式，也不提供用户可见的附带开关、选择附带横条或 Detach。私人背景至多随一条普通消息携带一次；私聊的普通发送 SHALL 先完成卡片保存或同步最新已保存草稿；此步骤失败时 SHALL 沿用普通发送失败反馈。

#### Scenario: 自动保存与自然提问
- **WHEN** 用户调整控件、刷新或继续打字
- **THEN** 本人状态在后台保存恢复；正常成功无保存提示、选择附带横条或 Detach。普通本人消息只显示原话；私聊后台将所有有效待发卡片的最新状态一起携带一次、一起消费，不再编辑则下一条不新带，后来只改一张就只带那张，群聊只有明确按钮提交才共享快照，明确请求仍显示实际发送结果。

#### Scenario: 发送前完成卡片保存
- **GIVEN** 私聊中有尚未保存的卡片改动
- **WHEN** 用户按普通发送按钮
- **THEN** 先尝试保存改动，保存成功后同一次点击继续发送；有效待发改动只随这条消息携带一次
- **AND** 保存因网络或临时故障失败时，使用普通发送失败反馈，保留正文和卡片改动。再次点击发送会重试保存，成功后继续发送。

#### Scenario: 自动同步同一账号的最新卡片草稿
- **GIVEN** 同一账号在另一端已保存较新的卡片草稿，当前端提交的旧版本被拒绝
- **THEN** 自动读取并显示服务端最新保存的卡片状态；用户已点击发送时，保留该次点击的正文并继续发送
- **AND** 读取失败时保留本机编辑和正文并沿用普通发送失败反馈，下一次发送重新读取最新版本。

#### Scenario: 多卡背景过大时恢复
- **WHEN** 普通发送的有效卡片背景整组超出总量边界
- **THEN** 沿用发送失败提示，明确说明尚未发送及缩减卡片内容后重试、或在做过改动的设备上离开此聊天清除该端已保存待发背景的方式
- **AND** 正文、附件和卡片编辑保留，整组不消费、不静默少带，下一次发送重新按全部有效待发卡片判定
- **AND** 不新增附带选择、Detach 或确认弹窗，提示在桌面与窄屏完整可读

#### Scenario: 手机与桌面
- **WHEN** 用户在桌面或手机阅读和操作交互回复
- **THEN** 字段、主要动作和聊天输入可读可用，不因卡片宽度或内层滚动妨碍主对话。
- **AND** 窄屏下输入区上方的提示与既有的发送结果提示不互相遮挡，输入框高度不被挤到不可编辑

#### Scenario: 生成与渲染失败
- **WHEN** 回复正在生成或交互无法渲染
- **THEN** 用户能识别运行状态，已可读内容不无故消失，失败时如实提示并可继续打字；有附加正文时保留，没有时不指向不存在的摘要。

#### Scenario: 私人状态与真实失败
- **WHEN** 用户重新打开会话、两台设备同时修改或发送失败
- **THEN** 恢复本人状态；冲突和未知结果明确反馈、保留当前编辑和原请求快照，不能静默覆盖或重复发送。
