- Q2: 是否保留 single_thread 可选？
  A: 保留。需求只改缺省值，未要求下架单 Thread；`single_thread` 仍是合法模式，创建后不可切换的规则不变。
- Q3: 原实施轮是否已有用户验收？
  A: 原实施由用户直接指令驱动，当时尚未完成用户亲测；原 PR 提交时仍待验收。

## 用户场景

人事行政的小林要给团队新增一个“质量巡检”助手。她打开 Agents → New agent，工作模式一栏已经停在“全局模式”上，说明文字是“跨聊天保持持续上下文，统一处理任务”。她没有动这一栏，填完名字和指令直接创建——这个助手从一开始就能跨聊天持续工作，不需要她先理解两种模式的差别再挑一个。

如果她确实只是想要一个“每个聊天各管各的”的轻量助手，她仍然可以把单 Thread 切回来，创建结果与她显式选择单 Thread 时完全一致。

由 PA 代主人创建助手、或在 iPhone 上创建助手时，用户不选模式也会得到同样的结果：不填就是全局模式。

已有的单 Thread 助手不受影响：它的模式仍显示为单 Thread，行为、聊天绑定和工具面板都和升级前一样，也不会因为这次升级被悄悄改成全局模式。

## 验收标准

### Requirement: 新建 Agent 不指定模式时按全局模式创建

#### Scenario: 创建页缺省选中全局模式
- **WHEN** 用户打开 Agents → New agent，未触碰工作模式一栏
- **THEN** 工作模式显示为已选中的“全局模式”，排在选项首位
- **AND** 创建出的 Agent 模式为全局模式

#### Scenario: 显式改回单 Thread 仍然生效
- **WHEN** 用户在创建页把工作模式切到“单 Thread”并创建
- **THEN** 创建出的 Agent 是单 Thread 模式，工具面板与聊天行为按单 Thread 呈现

#### Scenario: 不经创建页创建的 Agent 同样缺省全局
- **WHEN** 创建请求（含 PA 代创建、iPhone 客户端）未携带工作模式
- **THEN** 创建结果与显式选择全局模式一致

### Requirement: 既有 Agent 的模式与行为不因缺省值变化而改变

#### Scenario: 既有单 Thread 助手保持原样
- **GIVEN** 节点或服务端记录中存在创建时未写明模式的旧 Agent
- **WHEN** 升级后查看该 Agent 或与它聊天
- **THEN** 它仍按单 Thread 工作，模式在详情页显示为单 Thread，不会变成全局模式

#### Scenario: 模式仍不可切换
- **WHEN** 用户在已创建 Agent 的设置里尝试改变工作模式
- **THEN** 仍被拒绝，并保持原模式

## 范围与非目标

- 在范围：创建页缺省与选项顺序、iPhone 创建表单缺省、PA 代创建推荐的缺省配置、服务端新建请求在缺模式时的缺省值；产品契约规范化与库表列缺省保留旧记录兼容语义、iOS 上残留的“实验”标注。
- 非目标：下架 `single_thread`；为既有 Agent 做模式迁移；改变单 Thread 与全局模式各自的工作方式、工具集合、Inbox、投递或权限行为；改变“创建后不可切换”。
