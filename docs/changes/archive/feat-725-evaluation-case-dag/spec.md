# feat-725 统一评测入口与内部协作 DAG

## 原始需求

> 我觉得你整个agent_coordination的evals要统一基础设施，DAG，统一一些原语，发subagent、send_message给subagent，给用户、 用户给agent发问。然后统一一个可视化case的前端，可以看DAG，让我能容易看出来整个case是什么样的。后面新增caes也很容易

> 对，所有几个类型evals也统一下，在一个前端服务中展示，方便点

## 对齐依据

用户已要求保留历史原话与附件、从默认 Global 配置测试 Sol 6.1 high、根据真实前置推进、缺失前置停止相关分支，以及全案审阅。此前 GC-01/02 的手写时间线和分支函数已经多次发生因果脱节。Agent 采用现有 eval-ui 作为统一入口。Memory、Intelligent UI、Spec/design alignment、内部协作均出现在同一服务，各自已有执行与评判语义继续归本 suite 管理。

## 用户场景

用户打开一个本机页面，从四类评测中选 case。内部协作可以先看全图，再按任务筛选，点节点查看谁发给谁、完整原话、附件、前置、分支和这一类动作要查什么。添加 case 的作者填写消息和关系后即可预览同一份数据，并用共享回放器运行。缺前置时，被阻断的节点和独立继续的任务可以区分。其他 suite 的材料和既有实验入口仍可查看。

## 验收标准

### Requirement 统一入口

#### Scenario 四类评测可发现
- WHEN 用户打开 eval-ui
- THEN 可从同一目录选择四类评测，查看它们已有的案例、输入与判定材料。
- AND 已挂接的原生 Memory 轨迹与 Intelligent UI 现场入口仍然可用。

### Requirement 可读的协作图

#### Scenario 查看消息和因果
- WHEN 用户选择 GC-01 或 GC-02，按任务筛选并选中节点
- THEN 图上能辨认参与者与流向，详情显示完整正文、附件、来源、必须具备的前文和固定检查项。
- AND 在下一步缺少前文时，图中能看出受影响的分支。

### Requirement 共享回放

#### Scenario 新增案例
- WHEN 作者新增一份合法 case 和引用材料
- THEN 可在统一页面预览并经同一回放入口运行，无需新建专用 Python 回放器或改前端。

#### Scenario 前置失败
- WHEN 某节点必需的派工、收件或公开提问未出现
- THEN 对应依赖节点停止投递，独立任务能继续；结果记录失败证据与被阻断的节点。

### Requirement 保留真实通信与评测边界

#### Scenario 脚本与被测行为
- WHEN 回放使用模拟子 Agent
- THEN 派工由主 Agent 自己作出，子 Agent 回报走实际内部通道，用户输入和公开回复走 IM。
- AND 原话、图片可读性、发送与实际阅读的区别仍有可复查证据；控制资产不进入候选工作区。

### Requirement 既有 case 可审查

#### Scenario 迁移后的 GC-01/02
- WHEN 用户查看迁移后的案例
- THEN 仍能找到已修订的 iOS 决策前文、Computer use 澄清、Work 带图反馈、卡片与附件线及各自的触发条件。

## 本轮范围

统一四类评测的展示、材料入口和可选实验链接；统一内部协作案例的定义、执行、观察、分支与代码证据。真实模型运行继续由单独的评测命令触发。网页以审查和只读证据为目标。

## 实施中的用户范围确认

用户补充原话「你在跑评测吗，不用真的跑评测吧？」。本轮停止真实模型评测，交付统一基础设施与真实网页；通信与调度使用模拟和协议级证据核验。已开始的两条短链保留本地记录，结束状态照实标明，不以它们作 Prompt 效果比较。
