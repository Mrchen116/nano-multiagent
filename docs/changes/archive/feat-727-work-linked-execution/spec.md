# feat-727: Work 关联执行入口收进所属卡片

## 原始需求

> [https://github.com/Mrchen116/nano-multiagent/issues/475](https://github.com/Mrchen116/nano-multiagent/issues/475) 走快修模式，直接改前端，我要看看类似这里的[https://im.nanoim.win/settings/agents/nano-manager?view=work](https://im.nanoim.win/settings/agents/nano-manager?view=work)各种关联执行，你改之后要怎么设计

Issue #475 要求连续查看多条「子执行返回」时，各条关联入口位于所属消息卡片内，避免独立大框增加滚动距离和归属辨认成本；点击分别打开对应子执行。

## 用户场景

用户在 Agent Work 中连续阅读多条子执行返回或 Agent 消息，直接从当前消息内部进入对应执行。查看委派工具和后台结果时，也能在该卡片内找到关联入口，无需展开完整工具参数或结果。桌面继续使用主轨迹与子轨迹对照，窄屏仍可返回主轨迹。

## 验收标准

### Requirement: 关联入口在所属轨迹卡片内紧凑呈现

#### Scenario: 连续消息各自进入来源执行
- **GIVEN** 同一轮主轨迹有连续子执行返回及 Agent 消息，来自不同或重复的关联执行
- **WHEN** 用户阅读并点击各条消息内的关联入口
- **THEN** 入口位于所属消息卡片内部，打开该消息对应的执行
- **AND** 关联入口不作为另一条独立轨迹卡片展示

#### Scenario: 折叠的工具和后台结果
- **GIVEN** 委派工具或后台结果具有可查看的关联执行
- **WHEN** 用户在卡片尚未展开时查看并点击关联入口
- **THEN** 可从所属卡片内部进入对应执行，不需要先展开完整明细
- **AND** 工具调用状态和后台结果状态仍各按实际记录展示

#### Scenario: 桌面与窄屏查看和返回
- **WHEN** 用户从卡片进入子轨迹并返回
- **THEN** 桌面沿用子轨迹侧栏，窄屏沿用子轨迹与主轨迹之间的返回路径

## 范围与非目标

- 范围：Web 工作记录中已有消息、工具和后台结果关联入口的归属、紧凑布局与折叠可达性。
- 非目标：原生轨迹渲染、后台执行身份或关联推断规则、Work 权限、iOS、模型可见 Context、生产部署。
