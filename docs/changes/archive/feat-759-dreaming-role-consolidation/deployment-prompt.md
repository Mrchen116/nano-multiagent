# 一次性部署提示词：用户角色统一到 ROLE.md

这份提示词只在用户授权部署包含 feat-759 最终实现的版本时执行。本文件本身不授权生产写入。生产只做迁移必需修改和有限结果核对，不发送聊天、生成卡片、创建业务任务或运行产品验收。

## 目标与范围

旧版在 IM agent_profiles.custom_prompt、节点配置 agents[].custom_prompt 保存可编辑指令，PA 首次创建会填入系统默认文案。新版没有这些配置字段和Persona注入：PA默认文案由运行时系统提示词提供；每个Agent自己的职责、目标、分工与服务约定只读其工作区 `.nanoassistant/ROLE.md`。普通配置不写ROLE，创建的initial_role只是一次创建意图。

部署前先确认目标代码确实实现上述行为，确认本次获授权的IM服务、节点、用户与Agent范围；不能用历史机器路径猜测。依当前部署skill定位配置、DB和workspace，并检查工作区实际归属。迁移所有将由新版接管的节点，或明确保留未升级节点在旧版，不能在新旧协议之间临时补兼容代码。

## 准备与计划

1. 读取本unit最终review中的隔离验证结果及本次授权部署范围。盘点每个Agent实际 memoryMode；显式 legacy 模式不会读取 ROLE。对 legacy 且有需要保留的用户指令或角色约定的对象，必须在删除旧字段前停止该切换批次，先取得维护者切换到 document 模式的明确决定并按现有文档记忆迁移要求准备，或将其整套服务保留在旧部署。不能只写入 ROLE 就当作迁移生效，也不新增兼容读取。枚举旧字段的IM值、节点实际值和ROLE（包括空态占位符）；只在受保护的本地目录记录原文与清单，不写回仓库。
2. 在旧服务仍可正常处理配置时收口所有相关pending/gateway_applied配置操作、PA创建请求及Node pending receipts；无法确定结果则停在升级前，不能删除未决业务意图。已完成历史receipt/审计保留为历史，不再作为新配置来源。
3. 每个Agent规划目标ROLE：原样已知PA默认文案不搬入ROLE；用户自定义内容必须保留。若文本是已知默认文案加明确附加内容，只去掉完整匹配的默认段，保留附加原文。不要靠相似度或包含词猜测某段属于默认。已知默认文本取实际部署旧版本Git源码 `apps/im-server/src/personal-agent-defaults.ts`，保存版本/hash用于审计。
4. 已有非空ROLE原文优先保留；未重叠的旧用户说明可原样追加到合理章节。相同文字去重。不根据ROLE与custom_prompt冲突自行选择新职责；超出2,000 UTF-16上限时不截断，不把剩余内容塞进Memory。准备保留含义的具体草稿或指出冲突，取得维护者对该稿的确认后才继续该对象。IM与Node自定义值不一致时先核实最终已提交配置，不能任意取其中一份。
5. 保存迁移计划：Agent ID、真实节点/workspace、每份源内容SHA256、目标ROLE正文/hash、需要删除的旧字段、已完成配置操作的数量。计划尚有冲突就不要进入全量切换。

## 停机、备份与执行顺序

1. 按部署skill暂停本次范围内的旧服务/节点，防止配置和ROLE并发写入；保留正常会话与任务历史，不通过清空历史解决迁移。
2. 备份一致的IM SQLite DB（含WAL正确checkpoint/backup）、各节点配置和操作receipt库、各ROLE原始存在状态及内容。记录旧部署SHA、备份hash/路径与恢复命令。备份不得进入Git。
3. 重新核对源hash与计划一致。逐Agent以安全的临时文件+原子替换保存目标ROLE；缺失目录只在已确认真实workspace内创建。对符号链接、共享workspace或文件归属不明确的对象停止处理，不能写到其他Agent。
4. 核对ROLE回读、UTF-16长度和目标hash后，从节点YAML移除custom_prompt；IM在一个事务中移除agent_profiles.custom_prompt列（先检查列是否存在）。必要的配置版本/快照更新遵循最终实现与现有部署工具，不能改变身份、绑定、workspace、模型、工具、Skill、Feature或其他用户设置。不改变Memory文件。
5. 升级并启动目标版本。不要加入运行时旧字段读取、自动回填PA文案或双写ROLE的兼容路径。

## 完成判据（生产有限核对）

- 启动/健康检查符合部署skill；每个已迁移Agent的绑定、workspace和其他配置未改变。
- 所有目标ROLE实际回读hash与计划一致，长度合规；原本未设ROLE且没有用户自定义内容的PA仍处于未设置状态，而非把默认文案伪装成用户约定。
- 新配置schema/当前输出无custom_prompt，节点配置无旧字段。一次只读设置/提示词预览可确认PA系统默认仍存在，Global不获得PA专属段；ROLE只读接口返回预期内容。预览不包含运行时ROLE正文不能误判为迁移失败。
- 节点恢复配置不要求旧字段；没有遗留待恢复配置操作阻塞服务。旧完成历史审计中出现custom_prompt字符串不等于当前仍使用它。
- 只需计数、不变量和选定小样本，不发生产消息触发模型，不额外创建Agent测试。记录观察截止时间与真实结果，不声称生产完成了隔离功能回归。

## 中断、重复执行与恢复

本地迁移记录按Agent保存阶段、源hash/目标hash和备份。恢复先读现场：目标ROLE已为计划hash则跳过写入；若用户已改成其他文本，不覆盖，停止并重新核对。旧字段已移除、DB列不存在则跳过相应删除。未完成对象仅在源hash仍匹配时继续。备份不可因重跑被覆盖。

在服务启动前发现失败，可在保持服务停止的状态下恢复该切换批次的配置、DB和ROLE原始存在状态，再恢复旧版本；避免新DB配旧二进制或新二进制读旧配置。启动后出现真实新写入时不能直接用旧DB覆盖，应先保全增量并重新制定恢复步骤。

## 交付前隔离验证

在合成配置、SQLite和工作区副本验证：原样PA默认、空Global、自定义Global、PA默认加用户内容、已有ROLE不覆盖、冲突与超限不静默处理、legacy模式在计划阶段阻断、重复执行，以及在ROLE写入后/删除旧字段前中断后的恢复。新版本创建和保存ROLE的真实链路、请求上下文由本unit测试与隔离运行证明。具体版本、命令及结果回填review；这些验证在交付前完成，不能留给生产。


## Dreaming staging 退役

部署前停止旧版本维护任务并等待其退出，备份正式记忆仓及维护状态。保留正式库实际文件、Git 历史和未完成来源进度；不把旧 run 的 staging/plan 自动应用到正式库。旧未完成 run 按失败结束，新版本从正式库和未推进的来源重新处理；历史 run 只作审计材料，过期清理由既有策略负责。此步骤与前述 ROLE 迁移一并在隔离副本验证，生产只检查版本、状态与文件一致性，不启动额外生产 Dreaming 验收。


轨迹改为保留工具原文后，尚未完成的旧格式分页不能沿用旧的消息片段偏移。一次性切换时，在备份后清除受影响 stream 的 `continuation`，保留已完成的 `cursor` 和 `baseline`；该未完成 step 从头重新取材，可能再次读到已呈现的部分，不把整步跳过。无需重放已完成范围。消息去重集合 `seen` 已退役，可在同次状态迁移中删除；新版不依赖它。隔离验证通过：清除部分页偏移后能完整重读未完成 step，随后正确推进 cursor。
