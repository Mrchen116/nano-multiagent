# Work 读取性能

## 相同容量的中心对照

在 macOS Air 的 Node 24.22.1 上运行隔离 Fastify、真实用户授权和 SQLite，数据为 15,000 个主轮次、100,000 个关联执行、15,000 项最新轮工具记录，首项含 2 MiB 已保存正文。头页在同一进程和数据库交替测量 21 次热请求。结果取本轮最终中心实现的对照，原接口完整正文的单次耗时来自同容量初始基线。

| 路径 | 响应字节 | 热请求中位 / P95 |
| --- | ---: | ---: |
| 原 Work 摘要 | 5,831 | 0.88 / 1.71 ms |
| 合并时间线摘要 | 5,875 | 1.10 / 2.78 ms |
| 原工具首批完整正文 | 2,139,264 | 单次 9.12 ms |
| 工具首批有界预览 | 42,089 | 单次 1.52 ms |

冷合并头页 7.18 ms。首批预览少传约 98.0% 字节，显式展开可通过同权限的单项接口读取完整结果。中心测试覆盖第一批已有大行、后来追加的大行和原 seq 的大结果更新。旧回复精确定位走索引且不读取中间历史。

## 密集窗口和活跃集合

100,000 个已注册关联执行，其中 10,000 个有窗口内活动，2,500 个同时运行。每条路径测 21 次热请求。图首批和后页各 6,971 B，包含主节点、最多 24 个活动候选及所需祖先。

| 路径 | 热请求中位 / P95 |
| --- | ---: |
| 派工图首批 | 6.21 / 10.00 ms |
| 派工图后页 | 5.53 / 8.88 ms |
| 头像状态和首批名单（2,431 B） | 32.56 / 47.69 ms |

图祖先从候选集合按真实会话键检索。初次 SQL profiling 发现 SQLite 误选全量目录嵌套循环，固定以候选为外层后，相同样本单次祖先查询约由 1.18 s 降为 0.28 ms。头像按可信子 Agent 身份去重，开销随活跃集合增长。保留已报告时段用量和未知覆盖率。

这些是 loopback HTTP 和进程内查询时间，实际浏览器渲染、生产延迟、长任务和索引初始化代价没有包含在这些数字内。隔离浏览器以真实两层派工验证交互，使用少量新数据。

附加索引初始化对照在同 Node SQLite 内存库执行旧 schema 后装载候选 schema。样本含 100,000 个关联会话、15,000 个轮次、15,000 个工具项与 30,000 个起止事实。一次安装及播种 100 条活动状态约 143 ms，重新执行已有 schema 约 0.46 ms。内存库数字不含生产磁盘和进程启动。
