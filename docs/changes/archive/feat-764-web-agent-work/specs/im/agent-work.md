# IM Agent Work Specification (delta for feat-764)

## ADDED Requirements

### Requirement: Web Work 可以从派工关系进入同一工作记录

#### Scenario: 查看时间范围和多层执行
- **WHEN** 用户打开派工关系或切换时间范围
- **THEN** 显示对应范围内有真实派工关系的会话及必要祖先，能继续查看未展开的分支；同一个会话的多次唤醒归属同一节点。
- **AND** 主执行与子执行分别显示自身已报告的累计 token，不重复计入后代。缺失值与报告不完整的范围明确区分。
- **AND** 点节点进入对应会话的工作记录，返回图保留范围和来源节点。

### Requirement: Web 工具详情使用一致的阅读顺序

#### Scenario: 查看已有语义呈现与通用工具
- **WHEN** 用户展开一个工具记录
- **THEN** 按调用、结果、来源检查已有事实，专用终端、文件、差异或消息视图可用；通用结构可逐项查看，复杂值可展开。
- **AND** 原消息或子执行入口紧贴所属记录。已确认实发正文和请求正文一致时只显示一份；不一致时分别标明。调用、投递和被启动执行分别报告各自状态。
- **AND** 完整原生明细仍遵守既有 Work 访问规则。

## MODIFIED Requirements

### Requirement: 系统维护保留独立可回溯轨迹

系统维护不进入模型管理目录时，仍在既有轨迹发起位置保留用途、父会话、范围、状态和真实会话入口；访问遵守既有 Work 权限。

#### Scenario: 维护效果不佳后回溯
- **GIVEN** 维护执行已完成、取消或失败，运行资源已经释放
- **WHEN** 用户在重启后打开该次轨迹
- **THEN** 可按需查看实际输入、模型与工具记录、输出和结束事实。历史 fork 的继承上下文保留；独立 Dreaming 展示显式输入，不伪造继承历史。
- **AND** 查看不恢复执行，不需要先遍历全部维护历史或使用 list_agents 找到它。

#### Scenario: Dreaming 部分完成与普通成功
- **WHEN** 用户查看 Dreaming 结果
- **THEN** 宿主回执区分本批交流处理、任务复盘生成/更新与已整合、实际保存、入口同步、版本记录、剩余材料及失败原因；模型正常结束或复盘生成不被当作全部记忆更新完成；预算省略不冒充原始历史全部已读。
- **AND** 普通成功仅更新已有工作记录，不发送聊天通知或新增用户待办。

#### Scenario: 从 Work 辨认 Dreaming 阶段
- **WHEN** 用户在 Web IM 的工作记录或执行轨迹里查看 Dreaming
- **THEN** Work 中提取执行显示「Dreaming · 提取任务摘要」，整合执行显示「Dreaming · 整合长期记忆」。原生轨迹显示各自保存的阶段标题。两个执行均失败时也能区分，并打开各自的轨迹。
- **AND** Web 工作记录可从主时间线进入对应的独立维护轨迹，并在维护条目查看已报告的模型、工具数和 token。没有模型调用与没有指标来源时分别如实呈现。

### Requirement: 工作概览按需读取完整过程

#### Scenario: 大量工具记录
- **WHEN** 用户打开含大工具结果的工作页
- **THEN** 首先可见真实轮次摘要、状态和统计；进入视区后加载有限过程预览，更多过程和完整工具参数、结果及来源可按需打开。
- **AND** 刷新和切换视图保留阅读位置，失败时可重试，既有客户端完整读取契约不变。

#### Scenario: 在 Web 连续阅读主执行或子执行
- **WHEN** 用户打开工作记录或进入任意层级的子执行
- **THEN** 在同一个阅读区顺序查看该执行的多轮记录；接近阅读位置的首批过程可直接看到，长结果及更早内容仍按需可查。
- **AND** 从子执行回到发起位置保留父执行已读页、滚动和展开状态。

### Requirement: Web 回复的 View Work 定位实际发信唤醒

#### Scenario: 同一 Agent 的多次同名唤醒分别发信
- **GIVEN** 同一 Global Agent 的多个唤醒分别发出聊天回复，且实际发信关联已保存
- **WHEN** 用户从消息操作打开某条回复的执行记录
- **THEN** 进入该 Agent 的完整 Work，自动定位实际产生该回复的唤醒，直接可见其过程预览，完整工具记录按需可达；不会因唤醒同名而混淆。
- **AND** 消息锚点仅决定过程预览和滚动位置，不筛选、截去或替换其他轮次；列表保留正常最新优先顺序与更早记录的分页可达性。点击较早A仍保留较新B，点击B仍保留A；其他记录遵循普通视区读取。

#### Scenario: 再次查看较早回复
- **WHEN** 用户重复打开较早回复的执行记录，包括其唤醒已不在最新一页时
- **THEN** 直接定位真实目标轮次并加载其过程预览，保留已加载记录；中间尚未加载时明确标出，可使用正常分页继续查看或回到最新轮次。
- **AND** 回复属于已保留的历史主执行时，进入该历史执行的工作记录并定位原轮次，返回后仍可继续读当前主执行。

#### Scenario: 定位后继续阅读与切换视图
- **GIVEN** 回复对应轮次已自动定位，用户随后展开或收起工具详情，或阅读其他位置
- **WHEN** 用户在同一 Work 内切换到原生轨迹再返回工作记录
- **THEN** 保留工具详情的展开状态与原阅读位置，不把内部视图切换误作新的回复定位；从聊天再次进入或改点另一回复时仍应用相应定位。

#### Scenario: 关联尚未同步或不可用
- **WHEN** 用户打开回复的 Work，但尚无可证实的发信关联
- **THEN** 明确提示该回复的工作记录尚未同步或不可用，不以时间、同名标题或其他轮次猜测关联；已有 Work 仍可读取。
- **AND** 后续同步取得真实关联后可完成定位，仍遵守既有 Work 资格和来源聊天权限。

### Requirement: 大量执行可逐步检查

#### Scenario: 逐页浏览历史关联执行
- **WHEN** 用户在支持分页的客户端打开历史很多的 Work
- **THEN** 主执行和关联执行的轮次按最新在前显示。Web 可在当前执行的已读边界主动加载更早轮次，失败时可在该处重试；其他支持自动分页的客户端仍可在接近边界时加载。
- **AND** 从已知的委派或执行入口可以直接进入相应的旧执行。

#### Scenario: 正在回看时出现新事实
- **WHEN** 用户停在已加载的历史页，Agent 产生新的工作事实
- **THEN** 可以继续看到实时进展，旧页和选择位置保持可用。
