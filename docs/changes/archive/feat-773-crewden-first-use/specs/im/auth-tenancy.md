## ADDED Requirements

### Requirement: Web 官网首页提供可直接进入注册的产品介绍

#### Scenario: 访客与已有会话的入口
- **WHEN** 未登录用户打开 `/`
- **THEN** 展示 Crewden 官网首页，说明人与个人助手、专业数字员工的协作方式，并提供真实 `/register` 和 `/login` 入口。
- **AND** `/` 恢复有效会话后，个人空间可用或有效公司成员进入 `/chat`，其余账号进入 `/membership`；`/about` 始终允许查看官网介绍。

#### Scenario: 协作示例与真实工作明确区分
- **WHEN** 访客切换“接住变化、一起推进、带回成果”或打开发布计划
- **THEN** 页面展示明确标识的本地示例，切换阶段与查看成果不调用执行接口、不创建任务、不执行发布。
- **AND** 发布计划弹窗支持键盘关闭并返回触发位置；成果保留“等待负责人确认发布”的含义。
- **AND** 团队协作版面以持续在场的两位真人、各自的 PA 与专职 Agent 演示消息交接、并行准备和成果汇合；进入可见区域后播放一轮，在真人取舍处等待访客确认，再呈现共享成果。提供暂停和重播，离开可见区域或后台页签时停止推进；减少动态效果偏好下关闭自动推进与运动，保留逐步操作。全部动作仅改变本地示意，不发送真实消息、创建任务或宣称实测效率。

#### Scenario: 注册前理解条件并连续进入产品
- **WHEN** 用户通过首页选择创建账号
- **THEN** 进入真实注册页；首页告知运行助手需要连接电脑和模型服务，注册成功遵循现有首次设置与绑定深链契约。
- **AND** 首页和认证入口共享 Crewden 名称、线框 Logo、紧凑的中英文选择控件（完整语言名、统一菜单样式、支持键盘操作）及以紫色为主、淡黄与浅绿为辅的视觉，窄屏自然重排且所有内容与操作均可滚动访问。
- **AND** 首页通过可切换的 IM 协作示意介绍个人助手与专职 Agent：切换相关聊天时，同一 Agent 的长期职责和多个并行事项仍保持可见，以之前的约定、新变化和成果去向表达持续工作与主动跟进；场景明确标注为示意。设置步骤与常见问题补充使用条件，移动导航支持章节跳转与键盘关闭。
- **AND** 创建账号入口始终进入注册页；认证页仅通过品牌标志返回产品介绍，不额外展示“官网首页”文字入口；注册表单不提前展示电脑与模型设置说明，相关引导在注册成功后的首次设置中出现。

## MODIFIED Requirements

### Requirement: Web 认证入口在提交前说清规则并给出可行动反馈

注册与登录页在未登录状态下提供一致、可本地化的表单反馈；能在当前字段修正的问题不伪装成笼统服务失败，服务异常也不伪装成输入错误。

#### Scenario: 认证入口延续当前 Web IM 设计语言
- **WHEN** 用户在桌面或手机打开注册或登录页
- **THEN** 页面以 Crewden 品牌、共享线框 Logo、紫色入口配色和一致的字体、表面层级与交互状态呈现主要认证任务
- **AND** 注册后的首次设置、聊天和管理页面延续同一品牌、字体与紫色交互状态；工作区以白色与中性底色承载工作，黄绿等辅助色仅用于小面积身份与选中提示。桌面使用固定侧边导航，账号菜单集中承载账户、电脑、模型及组织设置；语言只在该菜单中提供一处入口，默认单行显示当前语言、点击后展开完整语言名选项，移动端保留“我”中的语言入口。未选中聊天时提供个人助手与发起聊天的真实入口；有助手聊天记录时展示真实的最近消息摘要，不能虚构已完成结果。小任务入口只填入助手聊天草稿，替换既有草稿或附件前须由用户确认，取消后保持原内容。角色头像遵循 [Agent 身份头像](agents-nodes.md#requirement-创建助手时可选择统一且可辨认的角色头像)；入场与悬停动效遵守系统减少动态效果偏好。
- **AND** 桌面认证入口以明确标识的协作插画衔接官网，手机窄屏收起详细插画、优先展示表单，不将桌面布局等比缩小或产生水平滚动
- **AND** 较矮视口下内容变高时可纵向滚动到主操作与页脚

#### Scenario: 注册规则在输入前可见
- **WHEN** 未登录用户打开注册页
- **THEN** 页面明确区分必填项和可选显示名，并在密码附近告知至少 8 位
- **AND** 用户可主动显示或隐藏密码，而不改变已输入内容

#### Scenario: 可本地判定的输入问题原位反馈
- **WHEN** 用户提交必填项为空的认证表单，或提交包含短密码的注册表单
- **THEN** 页面在对应字段原位告知修正方式，将焦点放到第一个问题，且不发出必然失败的认证请求
- **AND** 用户编辑有误字段后，与旧值相关的反馈消失

#### Scenario: Unicode 输入按服务端字符限制处理
- **WHEN** 用户在认证字段输入包含 Unicode 字符的内容
- **THEN** 页面按与服务端一致的字符语义判断长度，限制内的输入不会被浏览器提前截断
- **AND** 超过服务端字符上限时才在对应字段原位反馈，并阻止必然失败的认证请求

#### Scenario: 认证拒绝与服务异常可区分
- **WHEN** 注册用户名重复、登录凭据错误，或认证服务无法完成请求
- **THEN** 重名在用户名原位反馈，错误凭据不区分用户名与密码，服务异常则显示不同的可重试提示
- **AND** 失败不清空其他已输入内容

#### Scenario: 服务端拒绝可修正的输入
- **WHEN** 认证服务拒绝一项可由用户修正的输入
- **THEN** 页面使用当前语言在受影响字段告知修正方式
- **AND** 不向用户直接暴露服务端内部错误原文

#### Scenario: 未登录用户切换语言
- **WHEN** 用户在注册或登录页切换中文与英文
- **THEN** 规则、反馈和提交状态立即改用新语言，已输入内容保留
- **AND** 新语言在后续打开认证页时继续生效

#### Scenario: 辅助技术定位认证输入错误
- **WHEN** 键盘或辅助技术用户提交无效认证表单
- **THEN** 字段状态、可见文案和焦点变化使用户能定位第一个问题
- **AND** 密码显隐与提交状态有明确的可读名称

#### Scenario: 认证请求处理中
- **WHEN** 一份有效认证表单正在提交
- **THEN** 页面清晰告知处理状态，并阻止重复提交
- **AND** 用户仍可切换语言，处理状态立即使用新语言

#### Scenario: 注册成功进入个人首次设置
- **WHEN** 服务成功创建账号
- **THEN** 页面保存新会话并进入首次设置，无需再次输入凭据；因设备绑定而注册时保留绑定深链，确认后可继续设置；注册与登录入口互相切换时也保留该安全站内返回位置

#### Scenario: 登录成功返回原始深链
- **GIVEN** 用户因访问带查询条件或页内锚点的受保护位置而进入登录页
- **WHEN** 用户成功登录
- **THEN** 个人空间可用或有效公司成员返回完整的安全站内原始位置，路径、查询条件与页内锚点都保留；无个人空间的旧待批准或停用账号先显示本人状态，不提前显示公司缓存

#### Scenario: 暂时冷却可以恢复
- **WHEN** 认证请求被限流
- **THEN** 当前语言告知等待时间和重试方法，保留已填写的非敏感表单状态，不伪装成密码错误或永久禁用。
