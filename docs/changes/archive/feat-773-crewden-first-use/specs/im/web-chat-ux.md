## ADDED Requirements

### Requirement: 群聊头部与设置保持紧凑

- 群聊头部在桌面与移动端显示成员总数，不铺开完整成员姓名；可打开群设置时，点击成员数进入既有群详情查看名单。
- 群详情中的成员列表和可见范围、置顶、静音按连续内容排列并支持滚动，不因少量成员产生大块空白；开关与可见范围保留既有权限和保存行为，解散或退群操作单独分区。

## MODIFIED Requirements

### Requirement: 聊天身份与群聊选择信息清楚可辨

聊天和 Agents 页面 SHALL 使用统一浅色表面、辅助文字和头像配色；群聊使用区别于单 Agent 字母头像的群组图标。

#### Scenario: 新建群聊选择候选 Agent
- **WHEN** 用户打开新建群聊
- **THEN** 候选第一行显示名称及本地化在线状态，第二行显示 Agent ID 与所属机器名；机器名缺省时回退 node ID
- **AND** 描述不占用额外行，机器归属不依赖描述内容

#### Scenario: 私聊与群聊减少重复身份信息
- **WHEN** 用户查看 PA、普通 Agent、真人私聊或群聊
- **THEN** 标题栏不叠加会话类型标签，私聊不重复罗列参与者；正常电脑名称在 Agent 头像详情中查看，头像保留在线状态，需处理的电脑更新提示仍可见。
- **AND** 普通私聊消息省略重复署名和 PA 角色标签；群聊及旁观会话保留发送者姓名，代发和委托来源继续明确展示。

#### Scenario: 群聊标题栏保持轻量
- **WHEN** 用户查看群聊标题栏
- **THEN** 群头像与成员数表达群聊身份，不再重复显示群聊类型标签；设置和任务入口使用统一无描边图标按钮，保留可访问名称、悬停提示与键盘焦点反馈，移动端点击区域不小于 44px。

### Requirement: Web 聊天可从 Agent 头像查看工作状态

#### Scenario: 私聊和群聊查看同一个 Agent
- **GIVEN** 用户可以查看该 Agent 的 Work
- **WHEN** 在私聊或群聊点击 Agent 头像
- **THEN** 在头像旁查看主 Agent 状态、正在执行的主轮次最近工具及该工具状态，以及正在运行、待授权的子 Agent 数量；关闭后原聊天位置和草稿仍可继续使用。
- **AND** 可以展开一、二级等活跃子执行并打开相应 Work，配置入口仅在具备编辑资格时显示。
- **AND** 消息署名不重复显示电脑节点名；已知的所在电脑在头像详情中按需查看。

#### Scenario: 执行状态暂不能确认
- **WHEN** 工作记录正在补齐、节点离线或活跃状态不能确认
- **THEN** 显示对应同步或不确定状态，不把尚未确认的执行数显示为零。
