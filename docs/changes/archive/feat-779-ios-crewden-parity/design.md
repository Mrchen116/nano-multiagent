# feat-779 · Crewden iPhone 体验与能力对齐

对照 [已确认的需求](spec.md) 和 `b405a96a7` 的 Web。用户确认手机可以省去 DSH 原生轨迹查看器，并将交付规划交由作者决定。以下三个里程碑均可独立验收。

## Changelog

## 现状分析

**涉及范围。** [App 入口](../../../../src/IM/ios/NanoIM/App/NanoIMApp.swift)负责原生四栏、账号和深链。[聊天](../../../../src/IM/ios/NanoIM/Features/Chat)持有会话 UI 和实时事件，[本地库](../../../../src/IM/ios/NanoIM/Storage)按服务与用户隔离数据。[Agent](../../../../src/IM/ios/NanoIM/Features/Agents)、[任务](../../../../src/IM/ios/NanoIM/Features/Tasks)和[我的](../../../../src/IM/ios/NanoIM/Features/Me)已有原生业务页。功能入口的对照基准是 [Web 路由](../../../../src/IM/frontend/src/app/router.tsx)及其挂载页面。

**约束。** IM 负责授权、身份和持久结果；沿用 [iOS 业务、安装与前后台约定](../../../specs/im/ios-client.md)。保持同一 bundle ID、Keychain 范围与现有本地数据分区，以便旧版直接升级。设备端继续由电脑执行。除现有 Intelligent UI 回复内容，业务页面使用原生视图。Work 无需引入 DSH 包、轨迹 ticket 或查看器桥接。

**复用与历史。** [feat-773](../feat-773-crewden-first-use/design.md)已有跨端角色身份与首次交办规则；[bugfix-763](../bugfix-763-ios-chat-continuity)确定了滚动、可见卡片与重连的原生基础；[feat-764](../feat-764-web-agent-work/design.md)、[feat-771](../feat-771-delegation-lifetime-usage)和[bugfix-776](../bugfix-776-work-activity-stall)已有聚合、用量与就绪事件。使用现有 IM API、原生 Session、ChatStore 和 Work 翻页能力。新增的 Swift 表示只承接原先缺失的信息。

## 架构总览与关键决策

1. **把角色身份贯穿真实任务。** 浅色画布与深色适配、一个主强调色、统一 Crewden 标记和角色形象由原生主题与资产承载。登录／注册、Chats、任务、Agent、Work、我的都采用同一视觉层级；列表优先显示名称、实际摘要和必要状态，配置留在详情。保持系统输入、返回手势、Dynamic Type、语义色对比与 VoiceOver 操作。PA 在 Chats 有固定入口，复用实际会话标题、末条、时间与未读；去重普通列表中的同一会话。账号尚无 PA 时入口转为创建。头像在群成员、卡片、消息、Agent 行、提醒和选择器按同一身份解析；人和群沿用各自表现。
2. **入口读快照，操作看回执。** 登录后的 RootTabs 保持本地先行；首次设置是用户可跳过、可恢复的原生路径。已有聊天不等待 PA、模型或 Work 请求。通过现有创建、设备绑定、模型和 PA 读写判断当前步骤；活动提示与详细工作只在用户查看时读取。表单清楚区分未保存、已提交、设备已生效；沿用现有原生保存入口、离线只读与丢弃草稿确认。
3. **两种意图有两种入口。** 可查看 Work 的 Global Agent 头像用于当前活动。消息操作用于引用或定位当次发信的工作；同一组动作向 VoiceOver 提供具名操作。原生 push 打开 Work/关联执行，返回时恢复上一个视图的会话、焦点、历史位置和展开项。Work 顶层只有「工作记录」与「派工关系」。后者用可展开的父子列表，避免在手机画布上平移一张桌面大图。
4. **在原入口补上管理动作。** 本人 PA 的排除会话、联系人和风险处理归 PA；协作范围、角色约定、模型、插件与生命周期归 Agent；电脑端安装、更新与恢复归“我的 → 电脑”。设备安装指引允许复制到电脑，更新结果由节点报告。不改变账号资质或将公开可发现等同管理权限。

### 模型消费边界

消费者仍是当前会话的普通／Global Agent 或 PA。新开场建议停留在 UI 草稿；确认发送、引用和卡片背景经既有 IM 校验、授权和投递链路，只生成原有消息语义。读取旧记录、看头像、图形和聊天搜索均不唤醒模型。变更 PA 观察范围、审批与角色的消费者仍按现行 Gateway 契约生效。M1/M2 以相同输入对照 Web/iOS 的实际出站及服务接收：填建议前后无消息、同一幂等请求只产生一条消息。比对中心实际 relay 中的定向收件人、引用来源、正文及按收件 Agent 分配的一次性背景；显式卡片与普通引用分别验证。M3 用独立账号核实排除和解除后的后续观察及禁止访问来源；不另设 iOS 提示词或身份映射。

## 视觉基线与原生交互验收

**窄屏 Web 对照。** 设计时使用该版本的 Web 和合成账号、会话及工作状态。在 390×780 的浏览器中打开聊天列表，核对固定 PA 的末条消息、时间和未读数；进入群聊，核对发言人、正文和引用的阅读顺序。点阿拓的头像打开活动层，将窗口缩至 320×640，仍能读到当前状态并进入工作记录。原生改版前的对照来自 feat-716 的合成聊天旅程。

原型试画后，用户明确指出现有 Web 缩窄即可，重新设计只有在观感和使用上更好才值得。移除 HTML 原型及其截图，不作为实现或验收依据。微信参考图说明的是群聊阅读和长按就地操作；沿用 Crewden 的人物、颜色和可用动作。实际截屏中的私人消息不进入仓库或测试数据。

| 用户任务 | 沿用的 Web 体验 | 在真实 iPhone 客户端比较的结果 |
|---|---|---|
| 找到聊天、认出助手 | 紧凑标题、搜索、固定 PA、筛选及普通列表。PA 和专业 Agent 形象沿用已有图形；固定 PA 行取同一会话的末条、时间和未读。 | M1。相同账号和数据，在窄屏 Web 与 iOS 分别打开。空 PA 显示开始协作提示；旧 PA 显示实际末条与时间，有未读才出现计数。头像大小、行距与首屏能扫到的会话数不因额外品牌横幅受损。 |
| 首次交办 | 用 onboarding、角色选择和首次私聊当前窄屏页作参照。注册、任务、Agent、我的沿用相同层级，返回与表单使用系统控件。 | M1。真实 SwiftUI 页面完成命名、选形象、进入私聊并填草稿。已登录用户离线时仍能先看到本地聊天。 |
| 群里读消息、引用并返回 | 群头保留名称、人数和必要动作；沿用 Web 发送者行、不同长度的气泡、引用缩进和底部输入，不为复制/查看 Work 给每条回复常驻一行按钮。 | M2。在同一段有长短句、多人署名与引用的历史上长按目标；原生菜单关联到所选气泡，VoiceOver 提供同名动作，保留系统文本选择与复制。键盘出现后可见草稿/引用和发送，返回 Work 后能接着读原文。 |
| 从现在的活动看到过去的交付 | 头像只表达当前活动，消息操作进入对应记录。沿用 Web 工作记录的阅读次序、派工时间窗和各执行用量。 | M2。优先用系统弹层容纳头像详情并保留当前聊天；窄屏的派工子级沿一列展开，点击可读真实子执行，返回同一父位置。只有实际使用比 Web 等效形式更易操作时保留差异。 |
| 低频管理 | PA 政策、设置表单、任务详情均沿用相应 Web 移动页的分组、字段、保存语义与错误位置。 | M3。测试者在手机上能沿同一路径完成操作；整体观感以真实原生画面与 Web 对照判断。 |

验收方法：使用隔离的同一数据集分别截取窄屏 Web 和原生模拟器画面；涉及触控、软键盘、侧滑、动态字号、暗色或 VoiceOver 的判断在支持该能力的 iOS 客户端实测，记录设备条件。对齐优先级是信息主次、身份和操作位置，随后是字阶、内边距、颜色。原生平台差异以实际操作的收益作判断。首个真实 SwiftUI 切片作为后续视觉参照，必要时直接修改该页面。设计阶段还没有观察更新后的原生 App。

## 能力组合与契约增量

界面层级、可达性按 frontend-experience-review；跨端真实交付与从消息找 Work 按 product-journey-review；消息请求、配置、取消与恢复的语义用代码/契约审查。模型可见内容的对照采用上文实际发送、引用及观察范围的证据；详情阅读本身无模型输入。无需更改 DSH、PA 或 Gateway 的消费实现。

- [iOS delta](specs/im/ios-client.md) 替换原缩写头像保证，新增首用、PA 管理、引用定位、原生 Work 与管理能力的用户保证。
- [Work delta](specs/im/agent-work.md) 明确双视图中的 DSH 原生轨迹适用 Web，产品工作记录可在 iPhone 查阅。
- 任务、会话、账号、模型与节点等业务权限继续采用现行 IM 各域契约。设计未改变服务端业务行为。

## 风险、回退与迁移

头像缺老数据、本地草稿升级、焦点竞争与慢 Work 是主要风险。旧样本应涵盖无头像的 Agent、纯文本草稿和结果未知的冻结发送。SQLite 变更在现有本地迁移事务内做可加演进；分区被清理后不从旧数据恢复。导航以当前会话和用户意图处理，后台的旧请求不能移走读者。Work 首屏按摘要/可见轮次读取，长工具原文、历史和子树按需加载，保持稳定键和位置；每次变更授权重新核实。失败可退出详情回已有聊天；修复构建复用相同应用身份，不要求退出账号或清库。无人工一次性部署迁移。

## Runbook for Reviewer

生产无服务需要为本设计重启。实施验收使用独立 worktree 及专属运行目录，按[固定日常模板与资源回收](../../../development/worktree-runtime.md)操作。

| 资源 | 启动／进入 | 停止／核实 |
|---|---|---|
| 隔离 IM、Web、Gateway 与节点 | `./scripts/e2e-up.sh --profile daily --wt "$RUN_ROOT"`，RUN_ROOT 为本轮独占绝对路径。使用该次输出 IM_URL、UI_URL 及 .e2e-daily.json。 | `curl -fsS "$IM_URL/health"`，核实 daily owner、PA、节点在线；结束 `./scripts/e2e-down.sh --wt "$RUN_ROOT"`，确认端口释放。 |
| 首用空态 | 使用另一独占 RUN_ROOT 启动 `./scripts/e2e-up.sh --profile default --wt "$FIRST_USE_ROOT"`；默认绑定的合成主人有在线电脑，未被 daily 种下 PA。要验注册/无电脑，另用该 IM 新账号完成 Web 管理员准入；新账号使用下述第二个专属节点完成真实绑定。 | 核实 onboarding 返回的实际节点、模型与 PA，再进入相应状态。只对新建合成节点操作。相同 down 命令传本轮 FIRST_USE_ROOT。 |
| iPhone 和 Web | 取当前 checkout：`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`，导出本轮 NANO_IOS_BUILD_ROOT 和 NANO_IOS_SIMULATOR_ID；`./src/IM/ios/scripts/build.sh test`，安装该构建的 Debug App，登录页填写相同 IM_URL，在浏览器打开 UI_URL。接线见 [iOS 构建与独立旅程](../../../../src/IM/ios/README.md)。 | 设计时已核实本机 Xcode 和可用 iOS 26.4 模拟器，开发配置检查有 E2E config；实施时核实实际 SHA、origin 与账号。由本轮创建的模拟器用 simctl shutdown/delete 回收，借用者恢复原状态，清理独占产物。 |

空账号真实绑定的准备方法：在 FIRST_USE_ROOT 内取一个全新子目录 FIRST_NODE_ROOT（绝对路径），使用构建好的本仓 CLI。以刚获准的合成新用户登录 iPhone；另开终端运行以下启动命令，使用其显示的该实例绑定链接在手机确认。保留电脑端的设备证明和需要时的终端确认。不要复用 default 栈已绑定给 nano 的节点。命令会为新节点分配随机 node ID，将状态、workspace、owner 根放在该目录内；调试时关闭自动启动注册。进入模型设置时使用本机 dev_host 指定的 E2E 测试提供方资料，核对服务返回的连接结果，凭据不写入证据。停止节点后核实对应 PID 已退出，再回收该目录与专属栈。

```sh
NANO_INSTALL_AUTOSTART=0 NANO_INSTALL_ROOT="$FIRST_NODE_ROOT" node apps/node/lib/cli.js setup --config "$FIRST_NODE_ROOT/config.yaml" --im-service-url "$IM_URL"
node apps/node/lib/cli.js stop --config "$FIRST_NODE_ROOT/config.yaml"
```

取证分三组：

1. 首次设置从空账号／无 PA 进入；用绑定和模型验证真实结果，创建期间离开并重入，从另一端核实只有一个 PA、相同名称/头像、会话一致。用 daily 已有数据验老账号本地冷开。原生体验回归覆盖触控、软键盘、VoiceOver 的等价消息动作和深浅色；未实测真机的能力注明设备条件。
2. 用 daily 主人与 P/E/Q 的真实聊天构造目标：有两段不同工作的同一 Global，以及一个可识别的父子派工；在两端分别找到同一历史消息、回复来源和子执行。用原生 UI 查长按/返回并留读点前后对照，另用冻结请求与旧库测试验证结果未知时不重复。负例用同实例第二成员、被撤销会话与节点离线；offline 测试只控制独占的本轮资源。
3. 对照管理表逐项勾稽；管理员/普通成员用隔离 IM 加入同一公司并分配相应角色。PA 风险/解封使用专用合成参与者、测试消息和服务现有处置路径；失效来源保持不可见。电脑端更新及第三方通道仅需验证本次原生控制读写与状态映射，优先复用已有节点更新验收、服务集成测试及通道诊断测试；客户端用隔离候选/合成回执覆盖确认、取消、失败，不让工作站或生产设备更新。不以协议模拟宣称实际第三方收件成功。账号、token、设备凭据仅在本地测试环境使用。
