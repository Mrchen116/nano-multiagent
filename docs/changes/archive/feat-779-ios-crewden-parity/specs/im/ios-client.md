# IM · iPhone 客户端

## MODIFIED Requirements

### Requirement: iOS 独立客户端保持 IM 业务与权限契约
IM SHALL 提供原生 iPhone 客户端。聊天、任务、Agent 和我的及其管理页面 SHALL 保持现有 IM 业务契约，内部业务页面 SHALL NOT 委托网页容器完成。Intelligent UI 回复内容允许使用随包共享渲染组件，原生宿主 SHALL 保持业务权限与交付权威。公共可见性 SHALL NOT 推导出管理权限。

#### Scenario: 使用原生业务入口
- **WHEN** 用户从 iPhone 图标进入聊天、任务、Agent Work、配置、通道、节点、账号、公司和策略页面
- **THEN** 这些页面在原生客户端内可操作，并保持聊天、任务图、agents-nodes、external-channels、auth 与 settings 对应契约的权限、结果和失败语义。
- **AND** 外部网站链接可以打开系统浏览器，但不得附带 IM 凭据。

#### Scenario: 查看群聊与自己的空间
- **WHEN** 用户打开群聊详情
- **THEN** 先看到群名、成员与群任务，置顶与免打扰可以就地切换。邀请、改名、成员管理及解散遵循原会话权限；进入相应操作后才显示编辑或移除控件。
- **WHEN** 用户进入「我的」
- **THEN** 点个人身份可编辑资料，已有个人助手可直接打开私聊，未完成的创建可继续设置。电脑连接与绑定入口在一起，模型配置与退出登录从设置进入。

#### Scenario: 输入与辅助访问
- **WHEN** 用户使用中文组合输入、多行输入或 VoiceOver
- **THEN** 组合文字不会误发送，输入区和主操作保持可达，关键控件提供可读名称，长内容可选择和复制。
- **AND** 消息的复制正文和可用分支操作提供具名辅助操作，与长按菜单保持相同可用条件；创建分支仍需确认。

#### Scenario: 聊天输入和身份延续 Web 体验
- **WHEN** 用户在群聊输入 `@` 或在草稿开头输入 `/`
- **THEN** 输入框旁直接出现可筛选、可点击的成员或命令候选；选择保留其余正文和编辑焦点，仅预填不发送，附件菜单不承载提及和命令。
- **AND** 真人、群、PA 与专业 Agent 的身份在会话、消息、成员和 Agent 页面保持一致；已选择的 Agent 形象跨端相同，未选择时由稳定身份确定。私聊改名不改变对方头像，代发保留实际归属。

### Requirement: 原生聊天阅读连续性

客户端 SHALL 区分跟随最新与主动阅读历史，按用户最近的明确意图定位；尺寸变化和迟到的后台结果 SHALL NOT 覆盖更新的用户操作。

#### Scenario: 从 Chats 打开与重新打开
- **WHEN** 用户从 Chats 的普通会话行打开或重开已有消息的会话，未指定消息锚点
- **THEN** 显示已取得最新消息的尾部，包括缓存未变化的重入，不以额外网络请求或读取全部历史为跳转前提。

#### Scenario: 跟随最新与动态内容
- **GIVEN** 用户处于最新位置，或明确点击最新
- **WHEN** 流式正文、生成 UI、图片、键盘或输入区尺寸随后变化
- **THEN** 最新内容尾部保持在有效视口内，不要求反复点击最新，不等待全部远程内容齐备才可阅读正文。
- **AND** 旧分页或旧阅读恢复的迟到定位不能覆盖明确点击最新的结果。

#### Scenario: 连续滚过多个交互卡片
- **WHEN** 用户快速划过消息里的多张交互卡片、折返回刚读过的卡片，或停下查看
- **THEN** 消息正文可持续阅读，卡片保留已知尺寸与可恢复的编辑状态。停下来后可见卡片自动加载至可操作，等待期间在原位显示进度。离屏回收时，同一轮阅读继续复用仍有效的草稿和页面。
- **AND** 回收、缓存和后续渲染均服从当前会话权限、草稿冲突和受保护媒体规则。

#### Scenario: 主动读历史与返回
- **GIVEN** 用户主动上翻阅读历史
- **WHEN** 新消息、后台校正、异步增高、加载更早消息、聊天详情返回或前后台切换发生
- **THEN** 保持当前阅读上下文，不自动抢到最新；用户有明确的回到最新入口。
- **AND** 用户主动上翻可以终止尚未完成的自动跟随；退出到 Chats 后从普通会话行重入则定位到最新。

#### Scenario: 显式定位与详情返回
- **WHEN** 用户从历史搜索、来源链接或引用打开指定消息，或从 Work 返回原会话
- **THEN** 显式定位优先显示指定原文及相邻历史，详情返回恢复离开时的读点；稍后主动点击最新可终止旧定位。

## ADDED Requirements

### Requirement: iPhone 可完成首次交办与个人助手专属管理

#### Scenario: 首次设置与恢复
- **WHEN** 已获准用户在手机上开始设置或回到进行中的创建
- **THEN** 能分清需在电脑完成的步骤，在手机验证模型连接、为助手命名并选择形象，恢复同一次创建，确认就绪后进入对应私聊。开始提示可填入空草稿，正文由用户确认发送。

#### Scenario: 主人调整观察与联系人限制
- **WHEN** 主人打开 PA 的协作设置或风险事件
- **THEN** 可以核实来源与作用对象、修改排除会话、处理事件和解除联系人限制，结果与 Web 共享，未经确认的修改不会显示为已生效。

### Requirement: 原生消息引用与历史定位保持可读上下文

#### Scenario: 从搜索或引用回到原文
- **WHEN** 用户在手机搜索历史消息、打开命中或点开消息中的引用
- **THEN** 在有权限的原会话中定位消息并可阅读相邻历史，原文不可访问时如实反馈。可发送会话支持选取或取消引用，重试保持同一次发送的引用对象。

### Requirement: 原生 Work 可从当前活动、具体交付与派工关系进入

#### Scenario: 查看活动与追溯回复
- **WHEN** 有查看权限的用户点 Global Agent 身份或在一条回复上查看工作
- **THEN** 分别看到已知的当前活动或该回复对应的工作轮次。无法定位时说明情况；返回时能接续原来的阅读位置。

#### Scenario: 检查父子执行
- **WHEN** 用户在工作记录与派工关系中打开关联执行
- **THEN** 可阅读相应执行、时间窗内的派工关系及各执行累计用量和报告覆盖情况。在线状态与记录完整度分别表达，已授权的已保存记录可独立查阅。

### Requirement: 原生管理入口与服务端能力和权限一致

#### Scenario: 日常与低频管理
- **WHEN** 有权限的用户在 iPhone 管理电脑更新、Agent 审批策略和工作区插件，或使用已有任务、账号、模型、通道与公司管理入口
- **THEN** 可以完成对应管理动作并核对服务确认的结果；只读、离线、操作处理中或访问撤销时仍遵循对应业务的权限与恢复语义。
