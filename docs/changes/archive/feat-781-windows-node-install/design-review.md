### Issues

- **R1-W1　首次核对清单发生在安装包已经改动公共入口之后。** `design.md` 第 18、26 行规定，双击时安装当前用户共享的启动器、开始菜单及 URI 处理程序，返回 IM 并点击连接后，才取得发起方选中的清单并核对 EXE。一个完好但过期的正式安装包就能走到这一步。已绑定电脑上的用户即使随后得到“重新下载”，旧版本的安装器也已经有机会改动原来工作的公共入口。这与首文档“获取指定版本失败后重试”要求的原安装仍可使用有关。请明确由哪个可信入口在什么时间验证候选字节，以及验证前允许写入的范围。至少应保证清单不匹配时，已有手动启动、登录自启、URI 入口和各配置活动版本仍然可用。在已有绑定的 VM 上使用完整但非目标版本的候选验这个分支；截断文件无法双击的测试覆盖不到它。[安装时序](design.md#接口与数据流) · [IM 分发契约](specs/im/agents-nodes.md)
- **R1-W2　跨平台停止契约仍强制使用 POSIX 信号。** Gateway delta 第 43 行把“超时则升级 SIGKILL”用于所有受管平台，而设计第 28 行为 Windows 定义了本机管道和按所有权收拢 Job Object 子树。后者可以正确实现用户的停止需求，却不符合 delta 的字面判据；只结束单个 Gateway 进程也不能证明所属 DSH 子树已退出。请保留 Unix 信号约定，把 Windows 判据写为优雅停止超时后强制收拢已经核实归属的子树、确认结束后才报告停止。原有 PID 复用和单实例保护继续适用。[Gateway delta](specs/gateway/service-lifecycle.md) · [Windows 节点平台边界](design.md#接口与数据流)

### Recommendations

- **R1-R1** 在至少一次真实首聊中，请助手使用一个默认启用的本地工具读取带随机内容的工作文件，并在更新后继续读到原内容。这可用同一份证据覆盖“回复来自这台电脑”和“原工作文件可访问”，也能发现只能加载、不能执行的默认工具。

### 历史问题闭环

- **R1-W1 · closed。** 已有安装双击时仅暂存候选。原引导器先从用户确认的 IM 取清单，核对候选 EXE 与描述文件，校验并准备依赖后才提交启动入口。确无已有入口的首次安装可建立引导入口。M1 纳入已绑定机运行完好但过期的正式候选，随后分别验证开始菜单、URI 与登录启动。设计层已满足保护原安装的要求。[下载与首次上线](design.md#接口与数据流)
- **R1-W2 · closed。** 修改后的停止场景分别定义 Unix 强制信号与 Windows 有界收拢。Windows 只有确认已核实归属的子树全部退出后才报告停止；单实例、PID 所有权和正常停机条款保留。[Gateway delta](specs/gateway/service-lifecycle.md)
- **R1-R1 · 已采纳。** M1 让助手读取本机工作区的随机文本，更新后在原聊天复读。该证据同时关联真实执行节点、聊天和文件。[审查安排](design.md#本次审查安排)

### Coverage 与证据

- **需求与体积。** 普通用户仍可在原生 Windows 10/11 x64 上双击开始。首文档新增冷安装和纯业务更新的实际传输判据。设计分别记录引导 EXE、首次真实回复前的产品资产总字节、落盘占用、更新与重复安装传输。5 MiB 是引导器的设计预算；完整依赖体积由候选逐项列出。这样可以识别把同样的负担推迟到双击后才下载的情况。安装包尚待构建，目前没有 Windows 产品包的实测大小。[首文档](spec.md) · [大小基线与检查](design.md#接口与数据流)
- **组装、身份与更新。** 在冻结源码中，`scripts/build-node-release.mjs` 生成既有 Unix 载荷与候选清单，`packages/product-contracts/src/node-update.ts` 解析该格式，IM 安装路由和已认证的节点更新服务使用所选清单。`apps/node/src/release.ts` 和 `update-worker.ts` 读取在用发布身份、核验目标并驱动既有屏障。Windows 方案把版本描述文件作为注册及切换身份，描述文件固定引用两份归档；各归档校验、缓存和回滚引用有明确归属。按内容缓存 runtime 允许应用单独更新，动态 DSH 插件和实际原生依赖需在构建、真实装载两处验证。没有引入第二套执行运行时或通用依赖发布服务。
- **体验与契约。** 原网页的下载、已安装连接、等待、重试和上线状态仍适用；新增的网络准备进度和失败原因由实际观察下载的原生窗口展示。宽窄网页的选择和恢复路径继续参见 R1 的截图证据。IM delta 保留既有 Unix 固定版本、同源绑定与成功条件；Gateway 新增运行环境复用场景。用一份可复用运行环境和另一种同等有效的应用打包格式，也能满足该可观察判据。
- **验收与资源。** M1 由两台干净客体覆盖七个首文档场景，两个候选覆盖纯业务更新及回退；独立资产镜像可同时支持可控失败与传输记录。Bbot 的预检回执说明已受理两版客户机任务。客体实况、模型交付、重启恢复、安装大小与缓存命中均以实施时的实际证据为准。职责已指向有仓库访问权限和 Windows 虚拟机条件的 Grok Bot，用户无需代操作。无生产迁移。
