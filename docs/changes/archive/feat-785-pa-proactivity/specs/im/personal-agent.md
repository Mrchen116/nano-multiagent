# im/personal-agent Specification (delta for feat-785)

## MODIFIED Requirements

### Requirement: 来源限制与风险提醒明确

#### Scenario: 来源排除与恢复
- **GIVEN** PA 所属节点在线且设置页已刷新当前范围
- **WHEN** 主人调整 PA 的聊天访问范围
- **THEN** 对新消息和历史查询实际生效，不承诺抹除已读内容，不展示全局暂停观察开关。

#### Scenario: 可疑套取
- **WHEN** 对方反复越界索取且有原消息证据
- **THEN** 阻止披露并通知主人，未触发自动屏蔽的事件在真实通知送达后才告知对方；自动屏蔽的主人专属通知及计数规则见 [Gateway PA 契约](../gateway/personal-agent.md#requirement-系统累计五次输入风险自动屏蔽联系人)，不增加常规人工审批。

#### Scenario: 默认职责由系统提供
- **WHEN** 首次创建或使用PA
- **THEN** 服务方式、持续推进和Skill默认指导由系统提供，不向custom_prompt或ROLE写入默认文案。用户长期个性约定通过ROLE维护。
- **AND** 旧用户配置只在获授权部署时按一次性提示词迁移，不自动覆盖现有ROLE或Skill选择。

#### Scenario: 简洁的隐私知情提醒
- **WHEN** 主人看到已拒绝的越界请求
- **THEN** 默认展示一条紧凑保护摘要，按联系人合并重复提醒，展开后查看原因和原消息；界面跟随应用语言，原始证据保持原文。
- **WHEN** 主人选择“知道了”
- **THEN** 仅收起本次已看到的提醒，不改变访问权限、联系屏蔽或披露策略，不把知情当成放行。
- **WHEN** 主人主动展开后续协作并拒收此人请求
- **THEN** 沿用现有联系屏蔽机制，同步收起该联系人已有的未处理提醒；明确拒收私聊请求，群聊保留消息并提示风险，不影响主人与对方聊天。失败保留未成功的提醒并允许重试。

#### Scenario: 按人屏蔽并可撤销
- **WHEN** 主人屏蔽某人的请求
- **THEN** 对 Web IM 的同一账号拒收私聊请求；共同群聊仍正常接收，并向 PA 提供服务端可信的联系人风险提示，不因群内有该人而禁止正常群务回复；对外披露继续检查真实受众。
- **WHEN** 主人打开 PA 的现有 Agent 配置页
- **THEN** 看见当前已屏蔽联系人、原因与可打开的证据链接，在节点在线且已刷新当前状态时可解除屏蔽；失败时保留原状态并允许重试。
- **WHEN** 主人解除屏蔽
- **THEN** 私聊请求恢复、新消息不再带当前屏蔽提示，并通知主 PA 当前限制已撤销；历史事件保留供回看，不自动形成永久信用标签，不承诺删除已进入上下文的信息。
- **WHEN** 主人查看自己的 PA 与他人的原私聊
- **THEN** 复用会话只读观察权限，不加入会话、不允许发送；私人群仍按原权限判断，无权查看时链接到已交付的主人风险通知。

#### Scenario: 独立启停 PA 主动筹划并与运行特性统一保存联动
- **GIVEN** PA 所属节点在线且设置已确认同步
- **WHEN** 主人在 Web 或原生 iOS 的 PA 运行特性配置中开启或关闭「主动筹划」并保存
- **THEN** 界面以单一可编辑开关清楚说明开启与关闭后果（关闭后停止对话安静后的自动静默复盘与待拍板提议立卡，主人明确交办的任务与自行设定的定时提醒照常运行），仅对本人 PA 展示该特性、不对普通团队数字员工展示
- **AND** 开启主动筹划时与「任务图」特性保持同一页面可见的依赖联动与轻提示，沿用现有配置乐观锁保存与生效确认，未经节点确认生效前不将状态伪装为已生效

#### Scenario: PA 设置页离线只读
- **GIVEN** PA 所属节点不可达
- **WHEN** 主人查看 PA 配置、主动筹划状态、来源范围或已屏蔽联系人
- **THEN** 已保存信息、原因和有权查看的证据仍可阅读，改名、主动筹划切换与保存、来源调整与解除限制统一禁用，服务端拒绝这些新设置写入
- **AND** 恢复连接后先刷新再开放，不自动提交未保存内容；聊天内既有隐私提醒和风险保护流程不受此设置页条件改变
