## 澄清记录

- Q1: 本次内核升级的目标版本、`dsh-agent-context` 组件及在途提案如何安排？
  A: 目标版本选定 DSH `0.2.2` 系列（当前候选 `0.2.2-rc.5`）；项目配套组件 `dsh-agent-context` 随本次内核升级一并适配发布并接入；在途未实施提案（如 `feat-770-ordinary-agent-ptc`）留待本次内核升级完成后再独立推进，本次保持现有 PTC/Workflow 执行边界不变。
- Q2: DSH 0.2.2 的底层新机制与本仓既有实现如何结合或替换？
  A: Agent 调研确认并对齐：直接吸收增量系统提示词更新、零模型调用超大工具结果修剪、超限图片自动卸载占位、切小窗口模型前预压缩、步骤级条件工具准入与 MCP 按需加载等增强机制；用原生步骤级模型选择与文件策略配置替代本仓原有的请求期路由改写及提示词字符串修补胶水代码；Global/PA 的一级外部 CLI 委派继续保留本仓支持多轮追问、反向沟通与 Agent Work 投影的 `delegate_worker`，不用单轮实验性 `subagent_oar` 替代。
- Q3: `working_directory` 服务与模型工具如何取舍，如何保证工作区审批安全？
  A: 经核实源码与上游架构演进，采用方案 A：保留底层工作目录服务（保持原始项目身份不可变、将当前目录置于用户上下文以保护系统提示词缓存前缀、支持目录缺失自愈），禁用面向模型的 `working_directory` 切目录工具，同时统一本仓文件审批器与运行时工具的路径解析基准，防止相对路径解析错位越权写入或吸入工作区外未受信任的指令文件。
- Q4: 原生 `AgentTeam`、网页搜索及新增工具 `apply_patch`、`cordis_inspect`（`0.2.2-rc.5` 实际工具名为 `cordis_inspect_list` 与 `cordis_inspect_query`）的暴露策略是什么？
  A: 原生 `AgentTeam`（共享任务板工具）先关闭，任务协同继续统一使用 Nano 的 `task_graph`，保留具名多层 `subagent` 与容量查询能力；网页搜索在未配置 SearXNG/Brave 且未显式指定其他搜索源时，允许复用节点已有的可用官方 DeepSeek 凭据提供更稳定的搜索体验，同时强制关闭附带用户原始对话片段（不外发聊天原文）；`apply_patch` 作为默认文件修改工具纳入（新建及未显式锁定白名单的助手与 Global 一级原生执行者默认拥有，既有显式白名单保持用户已存选择不变），调用时受与 `write`/`edit` 一致的工作区及自动审批约束；`dsh-tool-cordis` 提供的只读运行时检查工具（`cordis_inspect_list`、`cordis_inspect_query`）仅在 Agent 启用了 `plugin_manager` 时自动跟随开放，其余场景默认隐藏且不在普通工具目录单独暴露勾选项。
- Q5: 轨迹查看器分叉 `@nano/trajectory-ui` 如何升级？
  A: 整体同步上游 `0.2.2` 轨迹 UI 新能力（嵌套子调用独立与批量折叠、存活会话实时工具原始 JSON 结果与渲染结果双视图、流式计时/重试错误与工具原始报错保留），同时完整保留 Nano 既有的父子执行范围导航与历史补载体验。

## 用户场景

1. **日常对话、长任务与升级无感衔接**：运维者将节点更新到搭载 DSH 0.2.2 与新版 `dsh-agent-context` 的版本后，用户原有的普通助手、PA 与专业 Global 数字员工继续在既有会话中工作，历史消息、分支创建、中断恢复、备用模型切换和停用/删除隔离全部如常。面对多轮代码检索产生的大量工具输出、多张历史聊天图片，或在对话中途调整助手功能开关与切换较小上下文模型时，助手能平稳过渡并继续完成回复，需要核对早先细节时仍可按需回查历史原件。
2. **代码补丁修改、插件自省与严密的工作区边界**：用户让启用了文件补丁修改能力的助手重构多处文件时，助手可直接使用 `apply_patch` 一次完成多文件增删改移；工作区内的常规文件修改在自动审批下顺畅完成，一旦补丁涉及受保护目录或工作区外路径则按规则拦截或征询授权。当用户在工作区内让开启了插件管理能力的助手开发调试扩展时，助手可借助只读运行时检查工具（`cordis_inspect_list`、`cordis_inspect_query`）查询当前运行时的服务、事件与扩展配置结构；而在未开放插件管理的普通助手或群聊中，内部自省工具、任意切目录工具及重复的原生团队任务板均不出现，任务推进仍清晰归口在 Nano 任务图与派工体系中。
3. **开箱可用的网页检索与对话隐私保护**：用户在仅配置了官方 DeepSeek 模型凭据、尚未额外部署 SearXNG 或配置 Brave Key 的节点上让助手检索外部资料时，助手能稳定拿到网页搜索摘要而不再频繁撞上公共搜索引擎的人机验证；同时用户的私人聊天原文不会被截断附带到搜索请求中。若节点原本已配好 SearXNG 或 Brave，则继续沿用既有搜索源。
4. **在 Agent Work 中高效阅读复杂执行轨迹**：用户在 Web IM 的 Agent Work 中点开某位数字员工或子任务的执行轨迹时，面对包含大量嵌套子调用的步骤，可以按父调用逐条收起或从工具栏一键折叠所有子调用，保持主干清晰，搜索关键字或定位特定调用时又能自动展开对应项；查看正在活跃运行的会话时，能上下对照工具返回的原始 JSON 数据与模型实际看到的渲染文本，在遇到模型重试或工具报错时也能直接看到流式进度、上次尝试失败原因和工具真实的错误原文。

## 验收标准

### Requirement: 升级运行时后既有助手会话、模型切换、分支与生命周期管理保持连续可用

#### Scenario: 升级后继续既有对话、创建分支与管理助手生命周期
- **GIVEN** 节点已有包含历史对话、子任务记录或记忆的普通助手、PA 与 Global 数字员工
- **WHEN** 节点升级到新版运行时后用户继续在既有聊天发消息、从历史回复创建分支、恢复中断工作，或停用、永久删除某一助手
- **THEN** 既有助手保留原身份、工作区与历史上下文继续回复，新建分支可正常独立对话并保留分支点能力配置
- **AND** 停用或删除目标助手仅清理其所属执行与独占记录，同节点其他助手的在途执行与历史查看不受影响

#### Scenario: 模型切换、备用链容错与小窗口模型过渡
- **GIVEN** 会话已有若干轮对话历史，或助手配置了有序备用模型链
- **WHEN** 用户将会话切换到上下文窗口更小的模型后继续提问，或主模型因可用性故障触发备用模型接续本轮回复
- **THEN** 会话在不卡死的情况下完成必要的上下文压缩或模型切换并给出回复，备用模型切换提示与粘性行为保持既有体验

#### Scenario: 超大工具输出与多图长对话下的连续执行
- **GIVEN** 会话中累计了大体积工具输出，或历史图片数量达到当前模型单次请求上限
- **WHEN** 用户继续发起新请求，并在需要时让助手核对早先轮次的原始输出
- **THEN** 助手自动裁剪过长历史工具输出或将最早超限图片替换为带只读附件说明的占位后完成本轮回复，不因上下文或图片超限直接中断整轮对话
- **AND** 助手仍可通过上下文历史回查能力读取早先记录的完整内容

### Requirement: 文件补丁、运行时自省与工作区边界按助手权限协同工作

#### Scenario: 默认提供多文件补丁并执行一致的工作区审批
- **GIVEN** 新建或未显式固定工具白名单的助手、Global/PA 一级原生执行者，或已在工具白名单中启用 `apply_patch` 的助手
- **WHEN** 助手使用 `apply_patch` 在工作区内修改普通业务文件，或尝试通过补丁修改受保护配置及工作区外部文件
- **THEN** 工作区内普通文件的新增、修改、删除或移动可在单次调用中完成，并在自动审批模式下按与 `write`、`edit` 相同的规则放行；已有显式工具白名单的存量助手保留原保存选择，可在设置中随时勾选启用
- **AND** 涉及工作区外路径或受保护目录（如 `.git`、凭据与指令配置）的补丁不会被当作普通工作区文件静默免审放行，而是按当前审批策略拦截、送审或请求用户确认

#### Scenario: 运行时自省工具仅随插件管理权限开放
- **WHEN** 用户在已启用 `plugin_manager` 的助手上开发或排查工作区插件
- **THEN** 助手可使用只读运行时检查工具（`cordis_inspect_list`、`cordis_inspect_query`）查询当前可用的运行时提供方与配置结构
- **WHEN** 助手未启用 `plugin_manager`（包括默认关闭或取消该工具的助手、群聊数字员工及禁用该入口的子执行者）
- **THEN** 工具列表不暴露上述运行时自省工具，调用请求被拒绝

#### Scenario: 保持固定工作区边界且不暴露冲突的目录或团队任务工具
- **WHEN** 用户查看任意助手的可用工具或交办多步骤协作事项
- **THEN** 助手不暴露切换会话目录的 `working_directory` 工具、原生 `AgentTeam` 任务板工具或实验性单次 CLI 工具 `subagent_oar`
- **AND** Global 与 PA 继续通过既有 `task_graph` 与 `delegate_worker` 推进事项、支持对同一 worker 追加说明与停止，且不会因访问外部目录而自动加载工作区外的指令文件

### Requirement: 网页搜索在缺少独立搜索源时安全复用可用凭据并保护对话隐私

#### Scenario: 未配独立搜索源但具备 DeepSeek 凭据时完成脱敏搜索
- **GIVEN** 节点未配置 SearXNG 或 Brave 搜索凭据、未显式固定其他搜索提供方，但已配置可用的官方 DeepSeek 凭据
- **WHEN** 用户在私聊或群聊中让助手搜索外部网页信息
- **THEN** 助手可正常完成网页搜索并返回带来源链接的结果摘要
- **AND** 发往搜索服务的请求仅包含搜索查询词本身，不附带用户的原始聊天消息文本；第三方自定义代理密钥不被转发至官方搜索端点

#### Scenario: 保留显式搜索源优先级与无凭据回退提示
- **GIVEN** 节点已配置 SearXNG、Brave 或显式指定了搜索提供方，或节点没有任何专用搜索及官方 DeepSeek 凭据
- **WHEN** 助手执行网页搜索
- **THEN** 已配置的搜索源按既有优先级生效；无专用凭据时走既有公共搜索回退并在遇到网络或验证限制时给出可读的失败原因与建议

### Requirement: 原生执行轨迹查看器提供子调用折叠、实时原始结果对照与准确状态呈现

#### Scenario: 折叠与搜索定位嵌套子调用且保留父子范围导航
- **GIVEN** 用户在 Agent Work 中打开一段包含父工具调用及其多个嵌套子调用的执行轨迹
- **WHEN** 用户点击工具栏的子调用批量折叠开关或点击已折叠父调用摘要行展开单个父调用，随后通过搜索或定位跳转到某个被折叠的子调用，或在父子执行范围与更早历史之间切换
- **THEN** 嵌套子调用可通过工具栏批量折叠／展开或从已折叠摘要独立展开，搜索与定位命中时自动展开目标子调用；既有的执行范围筛选、子任务跳转与向上加载更早历史保持正常可用

#### Scenario: 对照查看存活会话的实时工具原始结果与冷态历史的降级说明
- **WHEN** 用户在存活会话的轨迹详情中查看刚执行的工具调用结果
- **THEN** 结果区域同时展示工具返回的原始结构化结果与提供给模型的渲染结果
- **WHEN** 用户打开已冷态归档的历史会话查看工具调用结果
- **THEN** 渲染结果完整显示，并明确提示原始结果仅对实时工具调用可用，不报错或白屏

#### Scenario: 如实呈现流式进度、重试上次错误与失败工具原文
- **WHEN** 会话处于等待响应、流式输出、请求重试失败或工具执行报错状态，用户打开或刷新轨迹查看器
- **THEN** 进行中与重试中的请求不会提前显示为已完成，流式阶段展示实时计时，重试详情可查看最近一次尝试的错误信息
- **AND** 失败的工具调用在列表、详情面板与复制内容中均保留工具实际返回的错误原文

## 范围与非目标

- 在范围：
  - 将本仓锁定的 DSH 运行时与客户端相关包统一升级至 `0.2.2` 系列（`0.2.2-rc.5`），同步升级配套组件 `dsh-agent-context` 并更新架构文档与安装产物裁剪清单；
  - 适配模型选择、条件工具、工具执行器插件拆分、工作区插件树、无父字段普通分支（fork）及增量系统提示词等运行时新契约，清理被原生机制替代的旧修补逻辑；
  - 按对齐边界配置内置服务与工具：默认开放 `apply_patch` 并对齐工作区路径审批基准，按 `plugin_manager` 授权联动开放只读运行时检查工具（`cordis_inspect_list`、`cordis_inspect_query`），保留底层工作目录服务但关闭 `working_directory` 工具、原生 `AgentTeam` 与 `subagent_oar`，升级脱敏的网页搜索回退策略；
  - 将 `@nano/trajectory-ui` 与 `@nano/dsh-trajectory-viewer` 同步升级至 `0.2.2-rc.5`，接入子调用折叠、存活会话实时原始结果查看及轨迹状态修复。
- 非目标：
  - 不在本次升级中实施 `feat-770-ordinary-agent-ptc`（普通执行 Agent 与 Dreaming 默认切换 PTC 留待升级合入后独立修订推进，本次保持现有 `per-call` Workflow PTC 与默认执行模式行为不变）；
  - 不切换或启用实验性 SQLite 会话存储后端，继续使用既有 JSONL 会话存储；
  - 不升级至强制要求更高 Node 运行时版本的 `0.2.3-alpha` 分支。
