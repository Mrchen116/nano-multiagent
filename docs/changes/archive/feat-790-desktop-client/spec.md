# feat-790: Crewden Desktop 桌面客户端（V1）

## Relations

- Related: feat-781, feat-779

## 原始需求

> 我想谋划一个desktop版本，motivation是，我们很多时候在本机工作，用web呢，干啥都转一道IM，但是desktop版本呢，很多东西能直接读本地，比如看本机agent的轨迹。虽然web 也能做，本地开个服务就行，但是会遇到跨域的问题。此外，desktop应该还有其他的好处，因为大多数IM都不是在网页上，虽然我不太清楚有哪些好处

> - 定位就是类似飞书，slack一样，高频使用的。
> - 「本机 Node 状态/配置图形化管理（合并掉终端运维）」这自然也要做的

> 用桌面端，肯定就是不需要去命令行干啥了，直接点开，并开机自启就行了

> V1，并要求支持windows

## 澄清记录

- Q1: Desktop 客户端的产品定位是什么？是否需要把本机 Node 的状态与配置管理一并做成图形界面以替代终端运维？
  A(原话): - 定位就是类似飞书，slack一样，高频使用的。 / - 「本机 Node 状态/配置图形化管理（合并掉终端运维）」这自然也要做的
  Agent 解读: 产品定位是对标飞书、Slack 的全天候高频主力桌面工作台（承载完整 IM 协作、原生系统通知、未读提醒与后台常驻），同时内置本机节点状态观察与配置图形化管理面板，替代原有的命令行运维与手改本地配置文件操作。

- Q2: 用户安装使用桌面端时，是否还需要依赖终端命令安装或管理后台节点？自启体验如何？
  A(原话): 用桌面端，肯定就是不需要去命令行干啥了，直接点开，并开机自启就行了
  Agent 解读: 桌面端必须做到全程零命令行开箱即用——自带或自动准备受管运行环境与本机后台节点，双击点开即可使用并默认开启系统登录自启（登录系统后静默常驻菜单栏/系统托盘并自动拉起本机节点上线，关闭主窗口不中断后台运行；若机器上已有命令行或后台安装器接入过的节点数据，支持平滑接管并保留原有身份、凭据和工作区）。

- Q3: 首版（V1）的范围边界与操作系统覆盖要求是什么？
  A(原话): V1，并要求支持windows
  Agent 解读: 按完整日常主力闭环立项 V1（包含零命令行点开即用与开机自启、高频桌面 IM 工作台、本机 Agent 原生轨迹与工作区文件本地直读直开、菜单栏/托盘及图形化本机节点配置控制面；全局快捷呼出浮窗、副屏拆多窗盯轨迹等进阶外设留作后续迭代），且 V1 要求同时支持 macOS 与 Windows。

- Q4: Crewden Desktop 与现有 Web「连接电脑」入口（含 feat-781 刚做的 Windows 纯后台启动器与 Mac 终端脚本）如何衔接，首次打开怎么连上 IM？
  A(原话): 与轻量后台安装器并存：网页同时提供「仅装后台节点」和「下载完整 Desktop 客户端」两套入口
  Agent 解读: Web IM 的首次引导与添加电脑页面同时提供「下载完整 Desktop 客户端」（面向在本机日常高频协作的主力桌面用户）与「仅装后台节点」（保留现有终端脚本及 Windows 轻量后台启动器，面向服务器或无需桌面界面的电脑）两套路径；Desktop 既支持从网页唤起带入 IM 服务地址，也支持直接点开填写/切换 IM 服务地址登录并在应用内一键完成本机绑定，且与本机已装过的后台节点共享或平滑接管同一套节点身份与工作区数据，不产生双实例冲突。

- Q5: V1 首版需要覆盖并真机验收哪些电脑系统与芯片架构？
  A(原话): (Recommended) macOS Apple Silicon (arm64) + Windows 10/11 x64（覆盖当前主力 M 系列 Mac 与主流 Intel/AMD PC，并与现有实机/虚拟机验收环境一致）
  Agent 解读: V1 首版支持并在真机/隔离桌面上完整验收 macOS Apple Silicon（`arm64`）与 Windows 10/11 `x64`；旧款 Intel Mac、Windows ARM64/32 位及 Linux 桌面端不在首版范围内。

## 现状与背景

当前用户在个人电脑上使用 Nano 时，日常聊天与管理依赖浏览器打开 [Web IM](../../specs/im/web-chat-ux.md)，而本机 Agent 执行依赖后台节点服务（见 [Gateway 操作说明](../../operations/gateway.md) 与 [服务生命周期契约](../../specs/gateway/service-lifecycle.md)）。这套分离模式在本机高频工作场景下存在三处明显割裂：

1. **本机工作数据被迫绕公网回环**：即使人与 Agent 都在同一台电脑上，查看 [Agent Work 与原生轨迹](../../specs/im/agent-work.md) 或预览本机工作区文件（[节点代理读取契约](../../specs/im/agents-nodes.md)）仍须经中心 IM 中转；遇到超大工具输出或长历史时受制于中心同步体积上限与网络往返，而在网页端自建本机端口又会遭遇现代浏览器的跨域、混合内容与局域网访问拦截。
2. **安装与日常节点运维仍未脱离命令行与手改配置**：Windows 虽在 [feat-781](../archive/feat-781-windows-node-install/spec.md) 提供了轻量后台节点安装器，用户仍需回浏览器完成绑定与日常聊天；macOS 首次接入仍需在终端运行安装脚本。此外，配置本机网络代理、切换一级委派 Worker 框架（内置运行时 / Codex / Claude Code）、设置环境变量、指定专用自动审批模型以及查看节点故障日志，在双平台均需手改本地配置文件并执行命令行重启。
3. **缺少桌面原生常驻触达体验**：Web IM 混在浏览器标签页中易被误关或被浏览器后台省电策略冻结连接，缺少独立应用未读角标、菜单栏/托盘常驻控制以及点击直达目标会话的系统级通知闭环。与此同时，[原生 iPhone 客户端](../../specs/im/ios-client.md) 已建立了独立客户端按「服务地址 + 账号」隔离会话与断网保态的产品基线，桌面端需要与之保持一致的权限与隔离契约。

## 用户场景

### 场景 1：双入口选择、零命令行点开即用与已有节点平滑接管

小林准备在自己的主力电脑（M 系列 Mac 或 Windows 10/11 x64 电脑，电脑上未安装 Node.js、npm、pnpm 或 WSL）上开始使用 Crewden：

- 她打开已部署的 Web IM 进入首次设置或「连接电脑」页面，页面清晰区分两类并存选择：**「下载 Crewden Desktop 客户端」**（推荐给在这台电脑上日常办公协作的用户，内置本机助手管理）和 **「仅安装轻量后台节点」**（适合远程服务器或不需要在当地打开聊天窗口的设备，继续提供命令行安装脚本与 Windows 轻量后台启动器）。
- 小林下载安装并点开 Crewden Desktop。如果她是从当前 Web IM 点击唤起打开，桌面端自动带入该 IM 服务地址；如果她是直接双击图标冷启动，桌面端允许她直接输入或确认要连接的 IM 服务地址并登录账号。
- 登录成功后，她无需打开任何终端、也不用再切回浏览器，直接在 Desktop 窗口内确认将「当前这台电脑」绑定到自己的账号。桌面端自动在后台准备好运行环境并拉起本机节点上线；随后她在同一窗口内完成模型服务配置、创建或打开个人助手（PA），发出第一条消息并收到真实回复。若下载运行组件或连接服务时网络中断，界面明确说明原因并提供一键重试，不会停留在无反馈的卡死状态。
- 另一位老用户阿哲的电脑上，此前已经通过命令行脚本或 Windows 轻量后台启动器安装并绑定过节点，积累了多个 Agent 和本地工作区文件。阿哲安装并打开 Crewden Desktop 登录同一服务与账号后，桌面端识别到本机已有节点数据，引导平滑接管：自动停用旧的独立后台启动入口并交由桌面端统一托管，原封不动保留原电脑身份、已配置模型凭据、已有助手与全部本地工作区文件，既不需要重新绑机，也不会在后台跑出两个相互抢占的节点进程。

### 场景 2：像飞书/Slack 一样开机自启、菜单栏/托盘常驻与高频协作

日常工作中，Crewden Desktop 是小林电脑上全天开着的主力协作软件：

- **开机静默自启**：第二天小林重启电脑并登录系统账号，Crewden Desktop 按默认开启的登录自启设置自动在后台启动，安静驻留在 macOS 菜单栏（或 Windows 系统托盘），并自动拉起本机后台节点恢复在线，她的 PA 和本机数字员工立刻进入可工作状态，全程无需手动点开应用或敲命令。后台服务偶发异常退出时也会自动恢复。
- **高频桌面工作台与系统触达**：小林在主窗口中完成单聊、群聊、任务推进、Agent Work 检查以及助手、通道、模型和空间管理，体验与权限规则同 Web IM 完全一致。当后台有新消息、`@提及` 或 Agent 发来待确认的工具权限审批卡时，Dock / 任务栏图标显示未读提醒并弹出系统原生通知；小林正在 IDE 写代码时点一下系统通知，Crewden 主窗口立即唤起置顶并精准跳到对应会话或待审批位置。
- **关窗不掉线与自主启停**：小林点主窗口关闭按钮时，只是收起聊天窗口，后台连接、消息通知和正在执行任务的本机 Agent 不受任何影响；点击 Dock / 任务栏图标或菜单栏/托盘图标即可秒开窗口。当她需要临时停用本机算力时，可从菜单栏/托盘或设置里一键暂停本机后台节点，或关闭「开机登录自启」——关闭自启后下次重启登录电脑保持离线，直到她主动打开并启动。
- **多服务与多账号切换隔离**：当阿哲需要在公司正式 IM 服务与另一套自建测试 IM 服务之间切换，或退出当前账号登录另一账号时，桌面端记住常用服务地址并在切换后严格隔离不同服务、不同账号的会话、草稿、受保护媒体和轨迹视图；遇到短暂网络波动时保留当前已加载内容并温和提示重连中，不会把正在阅读的页面踢回登录框。

### 场景 3：本机 Agent 原生轨迹秒开与本地工作区直达

阿哲在主力电脑上让跑在本机的 PA 派发了多个子 Agent 排查问题并生成测试报告：

- **本机原生轨迹与大输出直读**：阿哲在 Desktop 中点进该本机 Agent 的 Work 并切换到原生轨迹（或从发起位置钻入子 Agent / fork 执行范围）。因为当前电脑正是该 Agent 所属的已绑定节点且当前登录账号具备 Work 查看资格，Desktop 直接从本机读取轨迹数据——完整历史批次、多层子执行切换、超过中心同步单条上限的大体积工具输出原文，以及执行中读取过的本机工作区图片都能立即打开检查，既没有公网回环等待，也不会遇到浏览器跨域错误；原有的时间概览联动、搜索、折叠与返回父级原阅读位置能力完整保留。
- **远端节点无感切换与多端同步不丢**：紧接着阿哲点开另一位跑在团队共享服务器上的数字员工 Work，Desktop 自动通过 IM 服务读取其工作记录与原生轨迹，操作方式完全一致，无需手工切换通道。与此同时，阿哲本机 PA 的聊天回复与常规工作记录仍照常同步给中心 IM，他下班路上拿出 iPhone 打开 App 依然能接续查看刚才的对话和工作进展。
- **本机工作区文件直达**：PA 在本机工作区里产出了分析文档和代码改动，阿哲在 Desktop 的聊天或工作视图中看到对应的本机文件与目录入口时，直接点击即可在 macOS Finder / Windows 资源管理器中定位该文件，或调用本机默认应用打开查看编辑，省去从网页上传再下载一份副本的繁琐步骤。

### 场景 4：「这台电脑」图形化节点状态与配置管理（告别终端与手改文件）

阿哲想给本机节点配置本地代理、把一级委派 Worker 切成自己本机装好的 Claude Code 或 Codex，并查看刚才一次模型连接报错的原因：

- 他从菜单栏/托盘或应用设置进入 **「这台电脑」** 管理面板，一眼看到本机节点的在线状态、后台执行运行时健康状态、当前版本与检查更新入口，并直接展开本机运行日志面板搜索和复制最近的错误日志，无需再去翻找隐藏目录。
- 在同一页面中，他无需打开编辑器手改任何配置文件：
  - 填写或开关本机 HTTP/HTTPS 网络代理与直连排除地址；
  - 查看桌面端自动检测到的本机一级 Worker 运行时可用情况（内置运行时、Codex、Claude Code 是否已安装就绪），点选切换目标运行时；
  - 增删本机运行环境变量，或从已注册模型目录中选择专用自动审批模型。
- 点击保存时，对于需要重启本机后台节点才能生效的设置，界面明确告知影响范围（若当前有正在运行的本机任务则提示等待完成或确认重启时机），并提供一键保存并完成受管重启；待新进程恢复就绪后界面确认已生效。若填写格式有误、所选审批模型不在有效目录内或重启未能就绪，界面保留用户编辑内容与原可用运行状态，并给出清晰原因与恢复操作，绝不把未生效的配置显示为已应用。

## 验收标准

### Requirement: 连接电脑提供完整 Desktop 客户端与轻量后台节点并存入口，并支持零命令行接入与已有节点接管

#### Scenario: Web 引导与添加电脑页面并列提供两套接入方式
- **WHEN** 已登录用户在 Web IM 打开首次引导的电脑连接步骤或设置中的添加电脑入口
- **THEN** 页面同时提供「下载完整 Desktop 客户端」（覆盖 macOS Apple Silicon 与 Windows 10/11 x64）和「仅安装轻量后台节点」（保留终端安装命令与 Windows 轻量后台安装器）两套可选入口，并清晰说明两者适用场景
- **AND** 某平台尚未发布对应安装包时，该入口如实说明暂不可用，不暴露失效下载链接，也不影响其余可用入口

#### Scenario: 在干净的 macOS Apple Silicon 与 Windows 10/11 x64 电脑上零命令行完成首次接入与真实回复
- **GIVEN** 分别使用未安装 Node.js、npm、pnpm 或 WSL 的干净 macOS Apple Silicon 电脑与 Windows 10/11 x64 电脑，且用户拥有可用的模型服务
- **WHEN** 用户安装并打开 Crewden Desktop（无论从当前 Web IM 唤起带入服务地址，还是直接点开应用输入要连接的 IM 服务地址），登录账号并在应用内确认绑定当前电脑、配置模型与助手后发送消息
- **THEN** 当前电脑在所连接的 IM 服务中显示在线，用户直接在 Desktop 内收到该电脑上助手的真实回复
- **AND** 从打开安装包到收到首条真实回复，全程无需打开终端、复制执行脚本、安装开发工具或回浏览器完成二次确认

#### Scenario: 平滑接管本机已安装的后台节点身份与工作区
- **GIVEN** 当前电脑此前已通过命令行安装脚本或 Windows 轻量后台安装器绑定到某 IM 服务，存在已有助手、模型配置与本机工作区文件
- **WHEN** 用户在该电脑安装打开 Crewden Desktop，连接同一 IM 服务并登录原所属账号执行本机接入/接管
- **THEN** Desktop 复用原电脑节点身份、已配置模型凭据、已有助手和原工作区文件，用户可在原会话继续对话并访问原有工作区内容，无需重新绑定或重新配置模型
- **AND** 本机不会同时运行两个相互竞争同一节点配置的后台实例

#### Scenario: 首次准备、下载或连接失败时可理解并可重试
- **WHEN** 首次打开、准备本机运行环境、连接指定 IM 服务或绑定电脑过程中发生网络失败、地址不可达或包校验失败
- **THEN** Desktop 在当前界面展示具体失败原因与重试或修改服务地址入口，不无限停留在加载态，也不破坏本机已有的可用节点数据

### Requirement: Desktop 支持系统登录自启、菜单栏/托盘常驻、异常恢复与受管更新

#### Scenario: 默认系统登录自启与后台异常退出自动恢复
- **GIVEN** 用户已在 macOS Apple Silicon 或 Windows 10/11 x64 上通过 Crewden Desktop 完成电脑绑定，且保持默认的开机登录自启设置
- **WHEN** 用户重启电脑并重新登录同一系统账号，或运行期间本机后台节点进程意外退出且故障原因已消除
- **THEN** 在网络与 IM 服务可达时，Crewden Desktop 自动驻留菜单栏或系统托盘并使原电脑恢复在线，原助手可继续在聊天中正常回复，无需用户手动启动应用或打开终端

#### Scenario: 关闭主窗口保持后台在线并支持多入口即时唤起
- **GIVEN** Crewden Desktop 正在运行且本机节点在线
- **WHEN** 用户关闭主聊天窗口
- **THEN** 应用保持在菜单栏或系统托盘常驻，本机节点继续在线执行任务，新消息与待处理提醒仍正常接收
- **AND** 当用户点击 Dock / 任务栏图标、菜单栏/托盘打开入口或系统通知时，主窗口恢复显示

#### Scenario: 主动停止本机节点与关闭开机自启
- **WHEN** 用户从菜单栏/托盘或应用内本机管理页主动停止本机后台节点
- **THEN** 本机节点变为离线并保持停止，直到用户手动再次启动，或在仍开启登录自启时重新登录系统
- **WHEN** 用户关闭「开机登录自启」设置并重启电脑重新登录系统账号
- **THEN** 该电脑保持离线且不自动拉起后台运行；用户随后手动打开 Crewden Desktop 并启动后，原电脑身份与助手恢复可用；若自启设置因系统权限等原因未能应用，界面如实展示实际状态与恢复提示

#### Scenario: 受管更新延续电脑身份、登录会话与工作区数据
- **GIVEN** 已绑定并正常使用的 Crewden Desktop 存在新发布版本
- **WHEN** 用户通过更新入口完成升级（若有在途本机任务，界面提示等待完成或允许用户处理后再切换）
- **THEN** 升级后仍保持原服务登录会话、原电脑节点身份、已有助手及本地工作区文件，可在原聊天继续对话；更新下载或切换失败时回退保留原可用版本并说明原因

### Requirement: 主窗口承载完整 IM 高频协作体验、原生系统通知与多服务/多账号隔离

#### Scenario: 桌面主窗口保持既有 IM 业务能力并支持系统通知直达
- **WHEN** 用户在 Crewden Desktop 主窗口使用单聊、群聊、渐进式任务、Agent Work、Agent 与外部通道配置、模型服务、账号及公司空间功能
- **THEN** 各功能在桌面窗口内完整可用，其权限边界、乐观锁、离线只读提示与操作结果同既有 IM 契约保持一致；外部网页链接在系统默认浏览器打开且不附带 IM 凭据
- **AND** 存在未读消息或收到新消息、`@提及`、待决工具权限请求时，应用图标/托盘呈现未读提示并触发系统原生通知；点击该通知可唤醒主窗口并直接定位至对应聊天或待处理事项

#### Scenario: 切换 IM 服务地址或账号时严格隔离数据，短暂断网不误退登录
- **WHEN** 用户重新打开应用、退出当前账号登录另一账号，或切换到另一个 IM 服务地址
- **THEN** 重开时自动恢复上次有效会话；切换账号或切换服务地址后，界面不再展示上一账号或上一服务的会话、草稿、受保护媒体与轨迹内容，迟到的旧请求结果也不会写回当前界面
- **AND** 当遇到短暂断网或服务端暂时不可达时，保留当前已确认的界面内容并展示温和重连状态，不把用户送回登录页；仅当服务端明确拒绝凭据或停用账号时才清除对应内容并要求重新登录

### Requirement: 本机节点所属 Agent 支持原生轨迹与工作区文件本地直读，远端节点与多端同步透明兼容

#### Scenario: 本机已绑定节点的 Agent 原生轨迹与大体积输出本地直读
- **GIVEN** 当前登录账号对某 Agent 具备 Work 查看权限，且该 Agent 归属在当前 Desktop 所托管并已绑定的本机节点上
- **WHEN** 用户在 Desktop 中打开该 Agent 主执行或关联子执行/fork 的原生轨迹，翻阅历史批次、查看超过中心同步单条上限的大体积工具输出，或预览被该执行实际读取过的工作区图片
- **THEN** 界面直接从本机加载并完整呈现上述轨迹记录、完整工具原文及工作区图片，不出现浏览器跨域或混合内容错误，也不因中心同步体积限制而缺失正文
- **AND** 原有的时间概览选区联动、搜索、轮次折叠、子执行范围聚焦与返回父级恢复阅读位置能力全部正常可用；对无该 Agent Work 查看权限的登录账号仍拒绝读取

#### Scenario: 远端节点 Agent 查看与跨端同步保持一致
- **GIVEN** 同一账号下既有运行在本机节点的 Agent，也有运行在其他成员电脑或服务器节点上的 Agent
- **WHEN** 用户在 Desktop 中切换查看远端节点 Agent 的 Work 与原生轨迹，或在 iPhone / Web 端查看本机节点 Agent 的聊天与已同步工作记录
- **THEN** Desktop 查看远端节点 Agent 时自动通过 IM 通路正常展示，无需用户手动切换连接模式
- **AND** 本机节点 Agent 产生的聊天消息与常规工作记录仍持续同步至中心 IM，跨设备查看保持一致

#### Scenario: 一键在本地打开本机工作区文件与目录
- **GIVEN** 聊天消息、工具过程或工作记录中关联了本机已绑定节点所属 Agent 工作区内的真实文件或目录
- **WHEN** 用户在 Desktop 中触发「在文件管理器中显示」或「用本地应用打开」操作
- **THEN** 系统直接调用 macOS Finder / Windows 资源管理器定位该路径，或使用系统默认应用打开原文件，无需先经中心服务下载副本
- **AND** 若目标文件属于远端节点或在本机已不存在，界面仅提供常规远端预览/下载或明确提示本机路径不存在，不静默无响应

### Requirement: 应用内提供「这台电脑」节点状态、运行日志与本机专属配置的图形化管理

#### Scenario: 可视化查看本机节点健康状态与运行日志
- **WHEN** 用户打开菜单栏/托盘状态摘要或应用内「这台电脑」管理页
- **THEN** 可直接查看本机节点与 IM 的连接状态、后台执行运行时存活状态、开机自启状态及当前版本号
- **AND** 可在界面内直接查看、刷新和复制最近的本机运行日志与启动/连接错误摘要，无需打开终端或手工查找本地隐藏日志目录

#### Scenario: 图形化配置本机代理、一级委派 Worker 框架、环境变量与专用审批模型并重启生效
- **WHEN** 用户在「这台电脑」管理页查看或修改本机网络代理（代理地址与直连名单）、一级委派 Worker 框架（自动展示本机内置运行时、Codex、Claude Code 的可用检测状态供选择）、本机运行环境变量或专用自动审批模型并保存
- **THEN** 不需重启即可生效的变更立即应用；需要重启本机后台节点才能生效的变更在界面明确提示，并在用户确认后自动完成受管平滑重启，重启恢复在线后新配置在后续任务中实际生效，全程无需手改本地配置文件或执行命令行重启

#### Scenario: 本机配置校验失败或重启未就绪时保留原可用状态
- **WHEN** 用户提交格式非法的代理/环境变量、选择了未就绪或不在有效模型目录内的审批模型，或受管重启后新配置未能使节点正常就绪
- **THEN** 界面明确展示具体失败原因并保留用户正在编辑的输入内容，不把未生效的配置显示为当前生效值，并保持或回退至原先可用的节点运行状态

## 范围与非目标

- **在范围**：
  - 提供支持 macOS Apple Silicon（`arm64`）与 Windows 10/11 `x64` 的 Crewden Desktop 客户端安装包、发布清单与受管更新机制。
  - 在 Web IM 首次引导与添加电脑入口提供「下载完整 Desktop 客户端」与「仅装轻量后台节点」两套并存路径；支持从网页唤起或直接冷启动连接 IM、应用内完成电脑绑定，以及对本机已有后台节点的平滑接管。
  - 默认开启系统登录自启、菜单栏（macOS）/ 系统托盘（Windows）常驻、关闭主窗口保持后台在线与异常退出自动恢复，支持图形化启停与自启开关控制。
  - 桌面主窗口完整承载既有 IM 业务界面，具备应用未读提示、系统原生通知点击直达，以及按「IM 服务地址 + 账号」隔离会话与断网保态体验。
  - 本机已绑定节点所属 Agent 的原生轨迹、大体积工具输出与受引用工作区图片本地直读，远端节点透明回退，以及本机工作区文件/目录一键在系统文件管理器或本地默认应用打开。
  - 应用内「这台电脑」图形化管理面板：运行状态与运行日志查看，以及本机网络代理、一级委派 Worker 框架探测与选择、环境变量、专用自动审批模型的图形化配置与受管重启生效。
- **非目标**：
  - Intel 架构 Mac（`darwin-x64`）、Windows ARM64 / 32 位系统，以及 Linux 桌面客户端（Linux 与无桌面服务器继续使用现有命令行后台节点脚本）。
  - 下线或移除现有的轻量后台节点安装路径（终端安装脚本与 Windows 轻量后台启动器继续保留并存）。
  - 在桌面客户端内内置独立多租户 IM 中心服务端（客户端仍连接已部署或自建的 IM 服务）。
  - V2 后续迭代的桌面进阶效率外设：全局快捷键呼出迷你快捷输入/审批浮窗、副屏独立拆出多窗口盯轨迹、拖拽本地文件夹直传本机路径引用、全局截图热键，以及中心 IM 不可达时的离线本机直聊模式。
