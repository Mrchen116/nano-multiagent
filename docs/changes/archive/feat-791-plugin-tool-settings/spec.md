# feat-791: 插件开发管理特性收编与全量工具及插件缓存联动

## Relations

- Related: `feat-645`, `feat-787`

本单元沿用 `feat-645` 已确立的运行特性依赖联动、2 秒自动淡出轻提示与双端一致性规则，并收口 `feat-787` 引入 `cordis_inspect_list` / `cordis_inspect_query` 后暴露的能力/工具/插件分层割裂与缓存联动问题。

## 原始需求

用户在实测助手设置页与插件页时提出原话：

> 为啥，`cordis_inspect_list` / `cordis_inspect_query` 不显示在这。他们是一个完整的插件吗？应该放在plugins管理页面吗
>
> 其实我对我们现在的体系感觉有点点乱，我看plugins里有dsh-agent-context，我没看出来关了之后工具区有啥变化

> 你的迁移我觉得基本ok，可以先合入。然后你和我讨论下能力/工具/插件设置页心智与缓存联动问题。你先给我讲讲你觉得怎么样合理

## 澄清记录

- **Q1：系统内置插件（如 `dsh-agent-context`）是否保留在「插件」页供用户按需关闭？**
  - 用户答复原话：
    > 我有一些虽然是系统内置，但是效果不一定，或者不一定需要的插件我，我是希望用户可以关掉的。比如这个。
  - Agent 解读与现状核实：保留 `dsh-agent-context` 等系统预置可选插件在「插件」页中由用户按需开启或关闭（不可物理卸载）；而助手或用户后装的工作区插件同时支持启停与卸载。当前之所以在「插件」页关闭 `dsh-agent-context` 后切回「配置」页看不出变化，存在两处实证缺陷：① Web「插件」面板启停后未刷新「配置」页主能力查询；② 编辑保存时将固定工具名混入持久化工具白名单，导致插件关闭后其工具被误判为“已保存但目录缺失”的异常项继续塞在工具列表里，甚至报错锁死保存按钮（iOS 同样会残留“已保存，目录未报告”条目）。

- **Q2：「配置」页工具区域的收放方式、特性收编与“已关闭插件是否算全量工具”？**
  - 用户答复原话：
    > 更喜欢这个。但工具区展开，我希望是全量的工具可以被看到。当然了，如果一个插件被关闭了，还属不属于全量工具？这个我没思考好
    >
    > 以及现在我们就有工具和特性的联动吧？比如开了某个特性自动显示开了对应工具？我记得某个feat我重点对齐过这类的联动，这些我希望保持
  - Agent 解读与结论确认：
    1. Web「配置」页将原先默认平铺的底层工具胶囊区改为默认折叠（与原生 iOS 默认收起的工具折叠组对齐），首屏聚焦人话级运行特性；
    2. 展开工具区后展示**当前已启用运行时的 100% 真实全量工具**——不再隐藏 `cordis_inspect_list` / `cordis_inspect_query` 伴随工具，也不再隐藏当前已启用工作区插件注册的工具；而处于**已关闭状态**的插件因已从当前运行时停用卸载（且未加载插件代码时无法可靠预知动态注册工具名），其工具随插件关闭立即从全量工具列表中移除，从而给用户提供直观明确的停用反馈；
    3. 完整保持 `feat-645` 的特性与工具/技能联动规则（开启特性自动点亮依赖、开启期间保护依赖并弹 2 秒自动淡出轻提示、关闭特性默认收回非共享依赖、之后允许单独开启工具且不反开特性、工具旁不增加额外依赖归属标注）。

- **Q3：已启用插件提供的工具在全量工具区点击时的交互方式？**
  - 助手提议：已启用插件带来的工具（如 `dsh-agent-context` 的 4 个上下文工具、或自装插件贡献的工具）在全量工具区显示为开启态；用户点击尝试单独关闭时，沿用 `feat-645` 交互保持开启并弹出 2 秒自动淡出轻提示，引导前往「插件」页关闭对应插件，不在静态工具白名单之上叠加插件子工具黑名单。
  - 用户答复原话：
    > 可以

- **Q4：上方运行特性（Features）本次收编哪些能力？**
  - 助手询问：除新增「插件开发与管理」特性（联动 `plugin_manager`、`cordis_inspect_list`、`cordis_inspect_query` 与 `nano-plugin-development` 技能）外，Goal 系列或 Workflow 等是否保持原状不额外新增特性开关，本次只提「插件开发与管理」这一个新特性？
  - 用户答复原话：
    > 只提它

## 用户场景

1. **用人话特性管理“插件自扩展”，不再在英文函数名里盲找或黑盒隐藏**
   用户在 Web 或 iOS 打开助手「配置」页时，首屏看到清晰的运行特性开关，其中包括默认开启的「插件开发与管理」。用户无需理解 `cordis_inspect_list` 等底层名称，就能一键控制助手是否具备在工作区编写、安装、管理插件及只读查阅宿主契约的能力；需要查看已安装插件时可直接跳往「插件」页。若特性开启期间用户在工具列表误点关掉其中某个必需工具或技能，开关保持开启并弹出约 2 秒自动淡出的轻提示告知先关闭「插件开发与管理」；若高阶用户关掉该特性后只想单独开启 `cordis_inspect_list` 供模型只读查询，也可以单独开启生效且不会反开特性。升级前已存在的助手会自动承接原有 `plugin_manager` 启停选择：原本可用者平滑开启新特性并补齐只读自省能力，原本已显式禁用的受限助手继续保持关闭。

2. **默认收起保持清爽，展开即见当前运行时的真·全量工具**
   日常配置时底层工具列表默认折叠，标题栏显示当前启用工具计数摘要，不让几十个英文工具名淹没页面；当用户展开工具列表检查细节时，模型当前在运行时里实际拥有和可选的每一个工具——包括普通可选工具、`cordis_inspect_list` / `cordis_inspect_query`、运行模式固定工具（如 Global 沟通工具），以及当前已启用插件提供的工具（如 `dsh-agent-context` 的四个上下文工具或助手刚装好的 `demo-dice` 插件中的 `roll_dice`）——全部如实可见，零隐藏黑盒。若用户直接点击由已启用插件提供的工具或模式基础固定工具，按钮保持开启并弹出约 2 秒自动淡出的轻提示，清楚说明该工具由哪个插件提供（请去「插件」页关闭）或属于基础固定能力。

3. **在「插件」页关停内置可选插件或自装插件，切回「配置」页秒级同步且不卡保存**
   用户觉得某个助手不需要 `dsh-agent-context`（或某个自建插件），进入「插件」页将其开关切为关闭，随后切回「配置」页展开工具列表：无需手动刷新浏览器，`notes`、`history`、`new_context`、`get_context_remaining`（或该自建插件的工具）已经从全量工具列表与计数中干净消失，页面底部不会冒出“目录缺失/未报告”红字报错，也不会锁死保存按钮；重新回「插件」页打开开关后，这些工具又立即回到全量工具列表中。

## 验收标准

### Requirement: 「插件开发与管理」作为运行特性统一联动插件管理与只读自省能力

#### Scenario: 开启与关闭「插件开发与管理」联动依赖工具和技能
- **WHEN** 用户在 Web 或原生 iOS 新建助手，或在助手配置页切换「插件开发与管理」运行特性
- **THEN** 新建默认开启该特性，开启时同步启用 `plugin_manager`、`cordis_inspect_list`、`cordis_inspect_query` 工具与 `nano-plugin-development` 技能；关闭且无其他已开启特性共享依赖时，同步关闭上述工具与技能，保存后助手不再具备工作区插件管理与宿主只读自省能力
- **AND** 本次除「插件开发与管理」外不新增其他运行特性开关，Goal 系列与 Workflow 等工具保持原有独立选择方式

#### Scenario: 特性开启期间保护必需依赖，关闭后支持单独启用工具
- **GIVEN** 「插件开发与管理」运行特性处于开启状态
- **WHEN** 用户尝试单独关闭 `plugin_manager`、`cordis_inspect_list`、`cordis_inspect_query` 或 `nano-plugin-development`
- **THEN** 对应开关保持开启且不跳动，操作附近淡入轻提示说明需先关闭「插件开发与管理」再调整，约 2 秒后自动淡出，不遮挡操作、不叠加多条提示，且工具旁不增加依赖归属标注
- **WHEN** 用户关闭「插件开发与管理」后，在工具列表中单独开启其中某项工具并保存
- **THEN** 被单独开启的工具实际可用，「插件开发与管理」保持关闭而不被反向打开

#### Scenario: 存量助手平滑承接既有插件管理权限
- **GIVEN** 升级前已保存配置的存量助手
- **WHEN** 用户打开其配置页或继续对话
- **THEN** 原先允许使用 `plugin_manager` 的助手保持「插件开发与管理」开启并具备完整依赖，配置页不因新增伴随工具报错或锁死保存；原先已显式禁用 `plugin_manager` 的助手保持「插件开发与管理」关闭，不静默扩宽其可用工具范围

### Requirement: 工具列表默认折叠，展开后完整呈现当前已启用运行时的全量工具

#### Scenario: 默认折叠摘要与展开查看全量现役工具
- **WHEN** 用户打开 Web 或原生 iOS 的助手创建或配置页
- **THEN** 工具列表区域默认处于折叠状态并显示启用数量摘要
- **WHEN** 用户展开工具列表
- **THEN** 列表完整展示当前已启用运行时中的全部工具，包含普通可选工具、`cordis_inspect_list` 与 `cordis_inspect_query`、当前模式基础固定工具，以及所有当前已启用插件提供的工具（含系统内置可选插件与工作区自装插件注册的工具），不再隐藏上述现役工具

#### Scenario: 点击已启用插件工具或基础固定工具时轻提示说明关闭途径
- **GIVEN** 用户已展开全量工具列表，且列表中包含已启用插件提供的工具或运行模式基础固定工具
- **WHEN** 用户点击由已启用插件提供的工具尝试关闭
- **THEN** 该工具保持开启且不跳动，操作附近弹出约 2 秒自动淡出的轻提示，指明该工具由对应插件提供、请前往「插件」页关闭
- **WHEN** 用户点击运行模式基础固定工具尝试关闭
- **THEN** 该工具保持开启且不跳动，弹出同类轻提示说明其为基础固定能力

### Requirement: 插件启停和卸载与全量工具列表及配置保存实时一致

#### Scenario: 关闭与重开系统内置可选插件后工具列表和保存即时同步
- **GIVEN** 助手已保存过配置，且「插件」页包含系统内置可选插件 `dsh-agent-context`
- **WHEN** 用户在「插件」页关闭 `dsh-agent-context`，直接切回「配置」页展开工具列表并修改任意其他配置项后保存
- **THEN** 无需手动刷新页面，`notes`、`history`、`new_context`、`get_context_remaining` 立即从全量工具列表与启用计数中移除，页面不出现缺失工具或目录未报告警告，配置可正常保存；重新开启 `dsh-agent-context` 后，上述四个工具立即恢复显示在全量工具列表中

#### Scenario: 安装、停用或卸载自建工作区插件后工具列表同步增减
- **WHEN** 助手在工作区安装并启用一个注册了自定义工具的插件，随后用户在「插件」页将其停用或卸载
- **THEN** 插件启用期间切至「配置」页展开工具列表即可看到该自定义工具；插件停用或卸载结算后切至「配置」页，该自定义工具立即从全量工具列表中消失，不影响其余工具选择与配置保存

## 范围与非目标

- **在范围**：
  - 新增「插件开发与管理」运行特性并与 `plugin_manager`、`cordis_inspect_list`、`cordis_inspect_query`、`nano-plugin-development` 建立 `feat-645` 规范的依赖联动与存量配置承接；
  - Web 助手创建/编辑页工具列表改为默认折叠（带计数摘要），Web 与原生 iOS 展开后完整显示当前已启用运行时的全量工具（含伴随工具与已启用插件贡献的工具），并对插件工具及固定工具提供 2 秒轻提示；
  - 修复插件启停/卸载后的跨分区能力缓存实时刷新，清理固定工具与动态插件工具对静态工具白名单的污染，消除关闭插件后的缺失工具报错与保存阻塞。
- **非目标**：
  - 不为已处于关闭状态的插件预展示或缓存其未加载的工具名；
  - 不为单个已启用插件内部的多个工具另设子级工具黑名单（插件提供的工具统一由插件开关控制）；
  - 不把 Goal、Workflow 等其他工具提升为新的运行特性；
  - 不包含 DSH 原生 `delegate_worker` 子工作记录与原生轨迹钻取（已单独建单 [#552](https://github.com/Mrchen116/nano-multiagent/issues/552)）。
