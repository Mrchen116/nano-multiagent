## MODIFIED Requirements

### Requirement: 设置 detail 页工具勾选态按存储真值渲染

Agent 创建与设置 detail 页的工具区域默认处于折叠状态并显示当前启用工具计数摘要；展开后完整展示当前已启用运行时的全量工具（包含静态可选工具、`cordis_inspect_list` 与 `cordis_inspect_query`、当前模式基础固定工具，以及当前已启用工作区插件提供的工具）。静态可选工具按存储的 `tool_allowlist`（含升级前存量配置对 `plugin_management` 的平滑承接）渲染勾选态：合法空名单不按默认值回填，运行模式固定项与已启用插件工具按当前有效运行态渲染，不再按 capabilities `default_on` 显示为默认全开；用户勾选或取消静态可选工具只读写纯净的静态 `tool_allowlist`（不混入模式固定工具名或工作区插件工具名）。空名单在 single_thread 且无开启 Feature 依赖业务工具时合法；有固定项或开启 Feature 时不能借空集绕过依赖保护。

#### Scenario: 默认折叠摘要与展开查看全量现役工具
- **WHEN** 用户在 Web 或原生 iOS 打开 Agent 创建或配置页
- **THEN** 工具区域默认折叠并展示当前有效启用工具计数摘要
- **WHEN** 用户展开工具区域
- **THEN** 完整展示当前已启用运行时的全部工具，包括静态可选工具、`cordis_inspect_list`、`cordis_inspect_query`、运行模式基础固定工具与当前已启用插件（含系统内置可选插件及工作区自装插件）注册的工具；已关闭插件的工具不出现在列表与计数中

#### Scenario: 存储为空全不亮
- **GIVEN** single_thread agent 的存储 `tool_allowlist` 为空且依赖工具的 Feature 均关闭
- **WHEN** 打开该 agent 的设置 detail 页并展开工具区域
- **THEN** 可选业务工具均不亮，当前运行模式固定能力与仍处于启用态的 `dsh-agent-context` 内部工具保持选中

#### Scenario: 显式清空保存后保持
- **GIVEN** single_thread agent 当前启用若干工具且依赖工具的 Feature 均关闭
- **WHEN** 用户取消全部可选工具勾选、保存、刷新页面
- **THEN** 可选业务工具保持全部不亮，且提交与持久化的 `tool_allowlist` 不混入固定工具或工作区插件工具名

### Requirement: Agent 配置页展示 workspace 自动工具的实际可用状态

Agent 设置通过独立“插件”页签管理当前 workspace 的已安装 DSH 插件包（含系统内置可选插件如 `dsh-agent-context` 与工作区自装插件），包括没有工具、已停用和加载失败的插件。显示可读名称、描述、版本及真实运行状态，并提供开关、详情和（对可移除包的）卸载确认。配置页展开全量工具列表时如实呈现当前已启用插件提供的工具及其有效状态；工作区插件工具与运行模式固定工具均不因编辑保存无关配置而写入静态 `tool_allowlist`（历史配置曾混入的固定或上下文工具名在插件关闭时不触发缺失目录报错，并在下次保存时清除）。插件页开关或卸载完成结算后实时刷新同一 Agent（及同工作区缓存）的能力与配置视图，无需手工刷新页面。插件页明确作用于共享 workspace，关闭为整体停用且保留安装包，卸载为独立操作；均不重建聊天。

#### Scenario: 安装后查看与保存配置
- **GIVEN** Agent 已在 workspace 自助安装工具插件并启用生效
- **WHEN** 用户打开配置页展开全量工具列表，并修改保存无关配置
- **THEN** 插件页显示对应包已启用，配置页全量工具列表显示该插件提供的工具处于开启态，且持久化静态 `tool_allowlist` 不添加插件工具或固定工具名

#### Scenario: 启停或卸载插件后切回配置页即时同步且不阻塞保存
- **GIVEN** 助手已保存过配置，且「插件」页包含系统内置可选插件 `dsh-agent-context` 或已启用的工作区自装工具插件
- **WHEN** 用户在「插件」页将其关闭或卸载（待操作结算完成），直接切回「配置」页查看并保存其他配置修改
- **THEN** 无需手动刷新页面，被关闭或卸载插件的工具立即从全量工具列表与启用计数中移除，页面不出现缺失工具或“目录未报告”错误，保存正常成功；重新开启插件后，其工具立即恢复显示在全量工具列表中

#### Scenario: 关闭管理能力
- **GIVEN** workspace 自装插件仍安装启用，但 Agent 的「插件开发与管理」及 `plugin_manager` 工具已关闭
- **WHEN** 用户重新打开插件页与配置页全量工具列表
- **THEN** 用户仍能在插件页查看及管理安装包；配置页将自装插件工具如实展示为未激活态，不把包启用等同该受限 Agent 可调用

#### Scenario: 不提供工具的插件仍可管理
- **WHEN** 用户打开插件页
- **THEN** 已安装的非工具插件也出现在列表中；可以关闭、重新开启、展开详情或确认卸载

#### Scenario: 开关和卸载即时提交且反馈准确
- **WHEN** 用户点击开关或确认卸载
- **THEN** 无需另存 Agent 表单；忙碌时显示等待，终态按实际运行结果展示，操作失败保留诊断和重试入口
- **AND** 同 workspace 的其他 Agent 共享这一选择，其他 workspace 不受影响；卸载保留源码和用户文件

#### Scenario: 离线、空列表与中断可区分
- **WHEN** 无插件、读取失败或待执行操作期间节点重启
- **THEN** 页面分别显示空状态、无法确认或重新读取的实际状态，未完成操作可重试，不把离线或未知结果当成成功

### Requirement: Web 与 iOS SHALL 使用一致的 Feature 依赖联动与轻提示

#### Scenario: 开启、关闭和独立重开
- **WHEN** 用户创建或编辑 Agent 的 Feature、工具或 Skill
- **THEN** 开启 Feature（含默认开启的「插件开发与管理」`plugin_management`）完整展开依赖；合法关闭默认撤销直接工具和 Skill 但保留共享及固定能力；随后单开工具（如单独启用 `cordis_inspect_list`）或 Skill 尊重最后选择，不反开 Feature
- **AND** 默认 Task 带出 Cron；关闭 Task 不级联关闭 Cron；Goal 与 Workflow 等独立工具保持各自工具选择，不设额外 Feature 开关，工具旁不增加依赖归属标注

#### Scenario: 阻止关闭或点击插件工具时保留状态并轻提示
- **WHEN** 用户点击被开启 Feature、模式固定基础能力或真实业务责任需要的开关，或在全量工具列表中点击由已启用插件提供的工具
- **THEN** 开关保持原态且不闪动；操作附近轻提示说明先关闭哪个 Feature、前往「插件」页关闭哪个插件、或说明其为基础固定能力/需开启 `plugin_manager` 方可激活，约 2 秒后自动淡出，无关闭按钮、不遮挡目标或抢焦点；提示作为独立浮层，不挤开控件、不改变列表换行或留下空位
- **AND** 重复点击延长同一提示，不堆叠；批量取消保留需要项，页面仍可编辑其他配置

#### Scenario: 保存重新校验且保留草稿
- **GIVEN** 页面预检后新增了有效责任或出现相关在途工作
- **WHEN** 用户保存关闭候选
- **THEN** 服务端重新检查并拒绝冲突关闭，页面恢复被阻止能力及其依赖，保留其他编辑并轻提示，不自动再次提交
- **AND** API 返回明确依赖、占用、资源缺失或状态无法确认原因；未确认成功不显示已生效

#### Scenario: 查询状态不泄露业务内容
- **WHEN** 有权限用户请求 Agent 能力使用状态
- **THEN** 仅返回本 Agent 的责任计数、相关忙碌能力与检查时间，不返回任务内容或他人数据；配置保存仍以最新权威状态复核
