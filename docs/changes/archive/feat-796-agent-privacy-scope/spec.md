# feat-796: Agent 与个人助手可见性及双向通信权限管理

## Relations

- Related: `feat-795`

在 `feat-795` 组织级同事与关联助手发现名录基础上，为普通/全局 Agent 与个人助手（PA）补齐真正的对外可见性隐藏、双向通信隔离、收紧权限时的既有会话收口，以及主人与本人名下多 Agent 之间的内部私聊与专属群协同能力。

## 原始需求

> 还有一个问题，用户开的所有agent都会被展示出来吗，以及别人都能私聊吗，我其实希望agent也能有权限管理，我开的有的agent，包括pa，我可能不希望别人能看到，也不希望我的这个agent能跟其他人联系。只能我，或者我开的agent跟他联系或者拉群

## 现状核实

核查现行产品契约（[agents-nodes.md](../../specs/im/agents-nodes.md)、[personal-agent.md](../../specs/im/personal-agent.md)、[routing-delivery.md](../../specs/gateway/routing-delivery.md)）与当前实现，现状与用户期望存在五处明确差距：

1. **目录与名片未隐藏**：现行配置虽有「团队协作 / 仅限本人」选项，但只作用于入站消息过滤，不控制目录与资料可见性。即便设为「仅限本人」，团队成员名下的 Agent 与已激活的 PA 依然会展示在其他同事的「同事」名录、个人名片、侧边栏搜索、新建聊天弹窗与公开智能体资料/工作页中。
2. **他人仍能建私聊且体验断层**：其他同事仍能向「仅限本人」的 Agent 或 PA 发起私聊并发送消息，消息在界面显示发出但在后台被静默跳过，既未阻断入口也造成误解。
3. **未阻断助手主动对外联系**：现行「仅限本人」只拦截入站唤醒，不拦截出站投递；处于该档位的助手（含 PA 自身发言与代表主人发言）仍能向其他同事或含外部同事的会话发送消息。
4. **误伤主人名下其他 Agent 与主人专属群**：现行契约与实现将「仅限本人」限定为“只接收创建者亲自发给该 Agent 的一对一私聊，所有群消息均不进入收件内容”，导致主人名下的 PA 或其他 Agent 无法与该私有助手私聊，也无法在仅含「主人本人 + 主人名下 Agent」的专属群聊中协同工作；同时将 PA 设为「仅限本人」还会一刀切中断 PA 对主人自身聊天的静默旁观记事能力。
5. **开启个人空间的团队成员无法公开普通 Agent**：先注册个人空间后获批加入团队的账号（或因创建 PA 启用了个人空间的账号），其个人空间下的普通 Agent 即使选择公开协作档位，其他团队同事在目录、聊天与工作视图中依然不可见、不可联系。

## 澄清记录

- Q1: Agent（含 PA）的权限档位与新建默认值如何设定？
  A(用户原话): `我建议是两档，然后默认pa和普通agent都是公开。你觉得呢`
  Agent 解读: 采用「团队公开」与「私有（仅自己与名下助手）」两档权限模型，不引入按人白名单；新建普通/全局 Agent、首次创建 PA、弹窗创建 PA 以及通过 PA 代建助手时均默认「团队公开」，同时在各创建入口与设置页支持直接选择或切换为「私有」，避免不想公开的助手在创建瞬间先暴露给团队；并修复启用了个人空间的有效团队成员将普通 Agent 设为「团队公开」时仍对同事不可见、不可联系的问题。

- Q2: 当原本「团队公开」的 Agent（或 PA）切换为「私有」时，既有含其他同事的群聊、历史同事私聊以及私有 PA 的后台旁观边界如何处理？
  A(用户原话): `ok，按你说的来。`
  Agent 解读: 用户确认按推荐的三项边界收口：
  1. **含外部同事的既有群聊自动退群**：切换为「私有」时，该助手自动退出所有包含其他团队同事（或他人名下助手）的群聊，保留群内历史消息可读，但立即移出当前群成员与 `@` 候选；仅包含「主人本人 + 主人名下助手」的私密专属群保留不动；同时只要群内存在私有助手，就不允许将外部同事加入该群或将该群设为团队公开可加入。
  2. **历史同事一对一私聊保留记录但双向封禁收发**：曾与该助手建立过一对一私聊的其他同事仍可回看历史消息，但无法继续发送消息且输入框明确提示该助手当前未对外开放，该私有助手也不能向该会话发送消息；日后若主人将其切回「团队公开」，该一对一私聊自动恢复可收发。
  3. **私有 PA 作为「隐身秘书」**：设为「私有」的 PA 对其他同事彻底隐藏、不可新建私聊、不留在含外人的群、不向任何外部同事或含外人会话发送消息或代主人发言；但仍按主人在 PA 设置中允许的「聊天访问范围」静默旁观主人自己的聊天，为主人整理待办与背景并仅向主人（或主人内部会话）汇报。

## 用户场景

1. **创建即选定公开或私有，默认开放且零瞬间泄露**
   林夏在团队中工作。当她新建一个面向全组服务的「API 评审员」Agent 或首次初始化个人助手（PA）时，权限默认选中「团队公开」，无需额外配置即可让同事在「同事」目录与个人名片中看到并直接发起协作。随后她又准备创建一个处理个人财务与草稿的「私人记账助手」（或请 PA 帮她代建一个仅内部使用的实验助手），她在创建表单中直接将权限切换为「私有（仅自己与名下助手）」再提交——该助手从诞生第一刻起就不会出现在任何同事的通讯录、名片或搜索结果里。此前先注册个人空间、后来获批加入团队的老同事陈明，名下设为「团队公开」的普通数字员工也能正常出现在林夏的「同事」名录、陈明的个人名片与新建聊天列表中，点击即可查看公开资料/工作记录或发起私聊，但陈明在个人空间里的私人历史会话与私有任务依然不会暴露给团队。

2. **主人与本人名下多 Agent 的私聊与专属群闭环协同**
   林夏把「私人记账助手」和「私人研究员」都设为「私有」。在林夏自己的界面里，她依然能在聊天、智能体列表和建群候选中看到并管理它们：
   - 林夏可以直接一对一给「私人记账助手」发消息，也可以让自己的 PA 或另一个名下 Agent 直接一对一联系「私人记账助手」转交资料；
   - 林夏新建一个「个人周报工作台」私密群，把自己的 PA、「私人记账助手」和「私人研究员」一起拉进群里。在这个只包含林夏本人和她名下助手的专属群中，无论是林夏发言、`@` 某个私有助手、在群话题中回复，还是几个助手之间互相接力发消息，都能正常唤醒和回复；
   - 当「个人周报工作台」群里包含私有助手时，群可见性固定为私密，打开群设置「添加成员」也不会允许把外部同事王五拉进来（提示群内含私有助手，不可添加外部成员），防止私有助手意外暴露在有外人的群中；反之，在已有王五参与的「产品研发群」里添加成员时，林夏也只能勾选自己的「团队公开」助手，私有助手不可选入外人群。

3. **双向硬隔离：私有助手既不被外人打扰，也不主动对外发声**
   王五在「同事」目录、林夏的个人名片、侧边栏 `⌘K` 搜索、「新聊天」弹窗以及「智能体」公开列表中，完全看不到林夏设为「私有」的助手或私有 PA，哪怕猜测链接直接访问该私有助手的资料页或工作页也会收到不可访问提示。同时，即便林夏的私有助手在某次执行中尝试向王五或向「产品研发群」发送消息、加入公开群，系统也会直接拦截并明确告知该助手当前为私有模式、仅允许与主人及主人名下助手通信，促使其改为向林夏本人汇报。

4. **从「团队公开」切换为「私有」时的平滑收口与可逆恢复**
   林夏此前有一个「团队公开」的助手「架构顾问」，既被拉进了有王五在场的「产品研发群」，也和王五有过一段一对一私聊讨论。现在林夏将「架构顾问」切换为「私有」并保存：
   - 「架构顾问」立即自动退出「产品研发群」（群内此前它发过的历史消息和回执依然保留可读，但它不再出现在群成员列表和 `@` 提及候选中，尚未处理的外部群积压消息同步清退且不再补发），而林夏自己的「个人周报工作台」专属群不受影响；
   - 王五侧栏里原有的「架构顾问」一对一私聊保留历史对话供查阅，但顶部/底部清楚提示“该助手当前设为私有，暂不对外接收或发送消息”且隐藏可编辑输入框，王五无法继续向它发送消息，「架构顾问」也无法再向这段私聊发消息；
   - 一周后林夏将「架构顾问」重新切回「团队公开」，王五不仅能再次在目录和林夏名片中看到它，原有的那段一对一私聊也立即自动恢复正常输入与收发。

5. **私有 PA 的「隐身秘书」体验**
   陈明希望自己的 PA 只做幕后贴身秘书，不想让同事在名片上看到他的 PA 或直接找他 PA 聊天。他在创建 PA（或在 PA 设置页）时将其设为「私有」：
   - 对所有同事而言，陈明的名片与「同事」目录里不显示任何 PA，同事无法给该 PA 发私信，该 PA 也不会进入任何有同事在场的群，更不能在同事群或同事私聊中发言或使用「PA 代发」；
   - 但在陈明自己这一侧，只要他没有在 PA「聊天访问范围」中排除「产品研发群」或他与王五的真人私聊，PA 依然能静默旁观陈明参与的这些对话，帮陈明提炼待办、核对上下文或生成回复草稿，并只在陈明与 PA 的私人对话（或陈明本人的内部专属群）中向陈明汇报。

## 验收标准

### Requirement: 普通 Agent 与个人助手提供统一的「团队公开 / 私有」两档权限且默认团队公开

#### Scenario: 各创建入口默认团队公开且支持创建时直接设为私有
- **WHEN** 用户在 Web 新建普通/全局 Agent、首次引导页创建个人助手、聊天区弹窗创建个人助手、在原生 iOS 创建或编辑助手，或通过 PA 代建新 Agent
- **THEN** 权限选项统一提供「团队公开」与「私有（仅自己与名下助手）」两档且默认选中「团队公开」
- **AND** 用户在创建时直接选为「私有」并提交后，新建助手从创建完成起即处于私有状态，不会先对其他团队成员短暂可见

#### Scenario: 设置页随时切换公开与私有档位
- **GIVEN** 主人拥有一个已创建的普通 Agent 或个人助手且所属电脑在线
- **WHEN** 主人在助手设置页将其权限在「团队公开」与「私有（仅自己与名下助手）」之间切换并保存
- **THEN** 新档位保存成功后立即生效，刷新页面保持最新档位，且单纯切换该权限不会在既有聊天时间线插入运行配置缓存失效分界线

### Requirement: 私有档位对其他团队成员彻底隐藏，团队公开档位跨个人空间历史正常可见

#### Scenario: 私有助手与私有 PA 不出现在其他同事的任何发现与资料入口
- **GIVEN** 团队成员 A 将名下某个普通 Agent 或 PA 设为「私有」
- **WHEN** 同团队的另一有效成员 B 查看「同事」目录、A 的个人名片、聊天侧栏搜索、「新聊天」弹窗、「新建群聊」候选、「智能体」列表，或直接访问该助手的资料页与全局工作视图
- **THEN** B 看不到该私有助手或私有 PA，直接访问其资料页或工作视图时显示不可访问状态；A 本人在自有列表、搜索与聊天入口中仍可正常看到并管理该助手

#### Scenario: 启用了个人空间的团队成员公开普通 Agent 对同事正常可见可联系
- **GIVEN** 账号 C 先注册了个人空间（或因创建 PA 启用了个人空间），且当前已是有效团队成员，其名下有一个设为「团队公开」的普通/全局 Agent
- **WHEN** 同团队有效成员 B 查看「同事」目录、C 的个人名片、搜索联系人、查看该 Agent 的公开资料与工作视图或向其发起一对一私聊
- **THEN** B 可以正常发现该 Agent、查看其公开资料与工作记录并建立一对一私聊进行对话
- **AND** C 在个人空间内的私人会话与私有任务对 B 保持不可见；若 C 日后被停用团队成员资格，B 立即不再看到或联系该 Agent，而 C 本人在个人空间内仍可继续使用自己的该 Agent

### Requirement: 私有助手支持主人与本人名下多 Agent 私聊及专属群闭环协同，并阻断对外双向通信

#### Scenario: 主人本人及名下其他 Agent 与私有助手一对一及专属群协同
- **GIVEN** 主人 A 名下有设为「私有」的助手 X，以及同一主人名下的另一助手 Y（普通 Agent 或 PA）
- **WHEN** A 本人与 X 一对一私聊、让 Y 与 X 一对一私聊，或创建仅包含 A 本人与 A 名下助手（含 X、Y）的私密专属群并在群内发言、`@` 提及或话题回复
- **THEN** X 正常接收来自 A 本人及同主人助手 Y 的私聊消息、专属群消息与话题回复，并可在上述内部会话中正常回复或主动发送消息

#### Scenario: 含私有助手的群聊禁止混入外部同事或设为团队公开
- **GIVEN** 用户正在「新建群聊」勾选成员，或在群聊详情打开「添加成员」与群可见性设置
- **WHEN** 新建群聊已勾选任一私有助手，或当前群聊成员中已包含私有助手
- **THEN** 群聊可见性锁定为私密，不允许同时勾选或向群内添加其他团队同事，服务端同步拒绝将外部成员加入含私有助手的群或将私有助手加入含外部成员的群；反之，已含其他团队同事的群聊在「添加成员」时也不允许添加主人的私有助手

#### Scenario: 私有助手与外部成员双向通信被阻断
- **GIVEN** 主人 A 名下的助手 X（普通 Agent 或 PA）处于「私有」档位
- **WHEN** 其他团队成员 B 尝试与 X 新建私聊或拉群，或 X 在运行中尝试向 B、向他人名下助手、向含其他同事的群聊或非主人外部渠道会话发送消息（含 PA 自身发言与代表主人发言）或主动加入公开群
- **THEN** B 的新建会话请求被拒绝；X 的对外发送或加群操作被拦截且不会产生对外消息，同时向模型返回清晰的私有范围限制原因以便其改为向主人汇报

### Requirement: 从团队公开切换为私有时自动收口既有外部群聊与历史同事私聊，且支持切回恢复

#### Scenario: 切换为私有时自动退出含外部成员的群聊并保留专属群
- **GIVEN** 主人 A 的助手 X 原本处于「团队公开」，且同时加入了含同事 B 的群聊 G1 与仅含 A 及 A 名下助手的私密专属群 G2
- **WHEN** A 将 X 的权限切换为「私有」并保存成功
- **THEN** X 自动退出含外部成员的群聊 G1（G1 内的历史消息仍保留可读，但 X 立即不再出现在 G1 成员列表与 `@` 提及候选中，尚未交给模型的外部积压消息停止递送且切回后不补发），而 X 在专属群 G2 中的成员身份与协同能力保持不变

#### Scenario: 切换为私有时历史同事私聊只读封禁，切回团队公开后自动恢复
- **GIVEN** 同事 B 此前已与主人 A 的「团队公开」助手 X 建立过一对一私聊并留有历史消息
- **WHEN** A 将 X 切换为「私有」并保存成功
- **THEN** B 打开该历史私聊时仍可完整阅读既有消息记录，但界面隐藏可发送输入框并展示“该助手当前设为私有，暂不对外接收或发送消息”提示，B 直接提交发送消息或 X 尝试向该会话发消息均被拒绝
- **AND** 当 A 随后将 X 重新切换回「团队公开」后，B 在该一对一私聊中的输入框与双向收发自动恢复正常

### Requirement: 私有个人助手保持对主人允许会话的静默旁观与对内汇报能力

#### Scenario: 私有 PA 静默旁观主人参与的允许会话并仅向主人汇报
- **GIVEN** 主人 A 将自己的个人助手（PA）设为「私有」，且未在 PA 聊天访问范围中排除含同事 B 的会话 C（A 为会话 C 成员，PA 不在会话 C 中）
- **WHEN** A 与 B 在会话 C 中产生新消息
- **THEN** PA 仍能以旁观者身份接收并查询会话 C 的消息背景、为主人更新记忆或整理待办，并在与 A 的私人会话（或 A 的内部专属群）中向 A 汇报或提供回复草稿
- **AND** PA 绝不出现在会话 C 成员或同事可见名录中，也无法向会话 C 直接发送消息或代表主人发言

## 范围与非目标

- **在范围**：
  - 普通/全局 Agent 与个人助手（PA）统一的「团队公开 / 私有（仅自己与名下助手）」两档语义与中英文文案更新（Web IM、Desktop 及原生 iOS 配置/创建文案同步）；
  - Web 首次引导创建 PA、弹窗创建 PA、原生 iOS 创建 PA、新建普通 Agent 及 PA `agent_creation` 工具创建时支持直接选择权限档位（默认「团队公开」）；
  - 中心 IM 联系人目录、单联系人查询、公开智能体资料与全局工作视图对「私有」助手的非主人隐藏，以及已启用个人空间的有效团队成员名下「团队公开」普通 Agent 对团队同事的可见性与可联系性修复；
  - 主人本人与名下多 Agent 之间的一对一私聊、同主人专属私密群聊入站唤醒与出站投递放行，以及含私有助手群聊的成员与可见性约束（前后端双重校验）；
  - 私有助手（含 PA 自身发言与代主人发言）对外部同事及含外人会话的出站硬拦截与清晰工具错误反馈；
  - 从「团队公开」切为「私有」时自动退出含外部成员的既有群聊、冻结历史同事一对一私聊（保留历史可读、前端只读提示、切回「团队公开」自动恢复），以及保留私有 PA 对主人允许会话的静默旁观能力。
- **非目标**：
  - 不引入按指定同事、部门或项目分组的细粒度白名单权限档位（保持两档极简模型）；
  - 不删除或撤回切换为「私有」前已经在群聊或历史私聊中成功发出的历史消息；
  - 不改变多租户账号审批模型（未加入团队的纯个人账号与被停用成员仍与团队空间隔离）。
