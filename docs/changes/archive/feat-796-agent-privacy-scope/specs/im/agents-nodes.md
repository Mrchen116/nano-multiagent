## MODIFIED Requirements

### Requirement: 登录用户可发现人和 Agent，管理配置保持个人归属

#### Scenario: 从目录直接发起聊天
- **WHEN** 有效账号按名字、用户名或稳定 ID 搜索联系人
- **THEN** 可辨认自己名下全部可用 Agent（含「团队公开」与「私有」）；获批的有效团队成员还可辨认其他有效团队成员（含公开 `@username`）及其设为「团队公开」的普通/全局 Agent 与已激活 PA（无论该成员是否同时启用了个人空间）并直接私聊，不要求已有 Gateway、好友申请或管理者逐人授权；他人设为「私有」的 Agent 与 PA 不出现在目录或单联系人查询结果中；无匹配时显示空结果。

#### Scenario: 公开 Agent 资料与配置分开
- **GIVEN** 另一位有效团队成员管理的普通/全局 Agent 或已激活 PA 处于「团队公开」档位
- **WHEN** 有效团队成员浏览该 Agent 资料
- **THEN** 能看到名字、管理者、在线状态及工作模式（普通/全局 Agent 显示已知设备名，全局普通 Agent 可进入 Work；他人公开 PA 不暴露设备名与私人 Work），能向该 Agent 发消息；当管理者对应的用户为当前可见非本人团队成员时，还可从管理者字段直接向该真人同事发起私聊；不能读取完整配置、凭据或保存管理修改
- **AND** 若该他人 Agent 或 PA 处于「私有」档位，非管理者访问其资料或全局 Work 均返回不可访问。

#### Scenario: 一个人多 Gateway，单台离线
- **WHEN** 用户绑定多台 Gateway，其中一台离线
- **THEN** 可辨认各 Agent 所属设备与在线状态，其余设备和人际沟通正常；设备及其 Agent 仍只有原管理者管理。

### Requirement: Agent 协作范围决定哪些聊天新消息可以送达

#### Scenario: 创建、保存与查看
- **WHEN** 用户在 Web、Desktop、原生 iOS、首次设置引导或聊天弹窗创建或编辑普通 Agent 与个人助手（PA），或通过主 PA 代建 Agent
- **THEN** 权限档位统一提供「团队公开」与「私有（仅自己与名下助手）」两档，新建均默认「团队公开」，且支持在创建时直接选为「私有」；配置接口继续以 `collaboration_scope` 的 `team` / `owner_only` 读写同一选择，单纯切换该档位不在既有聊天时间线插入运行配置缓存分界线。

#### Scenario: 私有档位的内部协同与对外双向隔离
- **WHEN** 普通 Agent 或 PA 处于「私有」（`owner_only`）
- **THEN** 对其他团队成员隐藏目录、个人名片关联展示、公开资料与全局 Work；允许接收创建者本人、同一创建者名下其他 Agent 发来的一对一私聊（及已绑定创建者的飞书单聊），以及仅含同一创建者本人与其名下 Agent 的私密专属群消息与话题回复，并允许在上述内部会话中正常回复与主动发言
- **AND** 其他团队成员无法向其新建私聊或将其拉入含外部成员的群聊；该助手（含 PA 自身发言与代表主人发言）向任何外部成员或含外部成员的会话发送消息、创建外部会话或加入公开群均被拒绝；私有 PA 对主人已参与且未排除会话的静默旁观能力按 [personal-agent](personal-agent.md#requirement-双向主人消息可用于协助) 保持有效。

#### Scenario: 收紧与恢复范围
- **WHEN** 设置成功从「团队公开」切换为「私有」
- **THEN** 该助手自动退出所有包含其他团队成员（或公开可见）的既有群聊，仅保留主人与同主人名下 Agent 的私密专属群；越出私有范围且尚未交给模型的外部积压消息停止递送，恢复「团队公开」后也不补发；此前与其他团队成员建立的一对一私聊保留历史可读但双向禁止继续发消息，重新切回「团队公开」后该一对一私聊自动恢复可收发。
