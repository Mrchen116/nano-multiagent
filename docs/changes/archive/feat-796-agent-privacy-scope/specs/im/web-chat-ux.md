## MODIFIED Requirements

### Requirement: 聊天身份与群聊选择信息清楚可辨

用户进入对话时应能看懂自己正在和谁协作，回到列表时应能找到最近的工作进展。消息正文与真实摘要优先；常规运行详情按需查看，需要用户处理的状态在相关操作处可见。身份提示随读者视角变化：同一伙伴跨入口可辨，群聊、旁观和代发仍能辨认实际参与者及发言归属。角色形象的选择与一致性见 [Agent 身份头像](agents-nodes.md#requirement-创建助手时可选择统一且可辨认的角色头像)。

#### Scenario: 新建聊天分类筛选并区分真人同事与跨团队 Agent
- **WHEN** 用户打开新聊天
- **THEN** 提供「全部 / 同事 / 助手」分类筛选，默认列表将真人同事分组排在 Agent 之前；真人条目展示显示名、`@username` 及关联公开 PA 提示（若有），Agent 条目仅展示本人全部可用助手及他人「团队公开」助手的名称、在线状态、归属信息与已知设备名（同事公开 PA 不暴露节点 ID，他人「私有」助手与私有 PA 不展示）

#### Scenario: 新建群聊选择真人同事与本人候选 Agent
- **WHEN** 用户打开新建群聊或查看群详情成员及「添加成员」面板
- **THEN** 新建群聊分「同事」与「我的智能体」两组展示并将真人同事排在本人 Agent 之前，支持按姓名或 `@username` 搜索过滤且不混入他人名下普通 Agent；真人候选展示显示名与 `@username`（不暴露内部用户 ID），本人 Agent 候选第一行显示名称及本地化在线状态、第二行显示 Agent ID 与所属机器名（机器名缺省时回退 node ID）
- **AND** 新建群聊中一旦勾选本人任一「私有」助手，群可见性锁定为私密并禁止同时勾选其他真人同事（附清晰原因说明）；反之已勾选其他真人同事时禁止勾选本人「私有」助手；群详情中若群内已含「私有」助手则将可见范围锁定为私密（禁用公开可见性切换并显示原因说明）且在「添加成员」中不提供外部真人同事，若群内已含外部真人同事则在「添加成员」中过滤掉本人「私有」助手
- **AND** 描述不占用额外行，机器归属不依赖描述内容；群详情顶部头像簇按实际群成员展示（不因群内存在 Agent 而忽略真人成员），群内非本人真人成员与加人列表同样展示 `@username`，且加人列表支持按姓名或 `@username` 搜索过滤并保留已选成员

#### Scenario: 历史一对一私聊因对端助手设为私有而只读提示
- **GIVEN** 用户打开与他人名下助手的一对一历史私聊，且该助手当前已被其管理者设为「私有」（会话 `can_write === false` 且 `write_blocked_reason === "agent_private"`）
- **WHEN** 用户查看该聊天面板或直接打开不可访问的智能体公开资料路由
- **THEN** 历史消息保持正常可读，隐藏底部消息输入框与历史消息分支按钮，顶栏隐藏失效的智能体设置跳转并保留个人置顶/免打扰会话菜单，会话顶部提示区以当前语言明确说明“该助手当前设为私有，暂不对外接收或发送消息”（直接访问不可见助手资料路由时同样显示明确未开放提示而非网络故障重试）；当管理者将该助手重新切回「团队公开」并推送更新后，输入框与消息操作自动恢复可用

#### Scenario: 私聊与群聊减少重复身份信息
- **WHEN** 用户查看 PA、普通 Agent、真人私聊或群聊
- **THEN** 标题栏不叠加会话类型标签，私聊不重复罗列参与者；正常电脑名称在 Agent 头像详情中查看，头像保留在线状态，需处理的电脑更新提示仍可见。
- **AND** 普通私聊消息省略重复署名和 PA 角色标签；群聊及旁观会话保留发送者姓名，代发和委托来源继续明确展示。

#### Scenario: 群聊标题栏保持轻量
- **WHEN** 用户查看群聊标题栏
- **THEN** 群头像与成员数表达群聊身份，不再重复显示群聊类型标签；设置和任务入口使用统一无描边图标按钮，保留可访问名称、悬停提示与键盘焦点反馈，移动端点击区域不小于 44px。
