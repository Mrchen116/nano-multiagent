# im/conversations-messages.md (delta for feat-803)

## MODIFIED Requirements

### Requirement: 群会话按成员关系管理，解散限创建者

前端经 `/im/v1/conversations/{id}*` 对一个已存在的群会话管理其成员与元数据：向群添加参与者（Actor）、移除某个参与者、修改群名、解散整个群。操作要求当前用户是群成员（非成员 404）。真人成员可改名、添加真人或自己管理的 Agent、移除非创建者成员或自己退出；普通成员不能将他人管理的 Agent 拉入任何群聊；创建者不可被移除。含「私有」（`owner_only`）Agent 的群聊必须保持私密且仅限同一创建者本人及其名下 Agent 共处，不允许混入外部成员；含「项目级」（`project`）Agent 的群聊必须保持私密（禁止公开可见），允许包含该助手管理者本人邀请的有效团队成员（非该助手管理者不得向含他人「项目级」Agent 的私密群添加外部真人成员扩圈），完整角色权限对照见 [统一权限矩阵](auth-tenancy.md#requirement-agent-与个人助手按统一权限矩阵控制发现会话轨迹与披露审核)。解散仅仍在群内的创建者可执行，非创建者被拒。这些能力让用户在内置 Web IM 里完成基本群治理，无需重建群。

#### Scenario: 向已存在的群会话添加参与者
- **GIVEN** 终端用户参与一个群会话，且账号下存在尚未加入该群的可用 Agent（公开群仅可添加「团队公开」Agent；含其他真人成员的私密群可添加本人「团队公开」或「项目级」Agent；仅含本人及本人名下 Agent 的私密群还可添加本人「私有」Agent，包括同一主人名下跨公司空间与个人空间的可用 Agent）
- **WHEN** 前端 `POST /im/v1/conversations/{id}/participants` 带一组 Actor（`{type:"agent", id:"<agent_id>"}`）
- **THEN** 200 返回该会话快照，其 `participants` 含新加入的 Agent；此后该 Agent 能收发该会话后续消息，共同处于该私密群的有效团队成员自动取得与该「项目级」Agent 的目录可见、一对一私聊及 Work 查看资格，加入的真人成员可回看群已有历史

#### Scenario: 含私有或项目级助手的群聊边界与非主人拉群/扩圈拒绝
- **WHEN** 用户或调用方尝试向已包含任一「私有」Agent 的群会话添加其他真人成员、将「私有」Agent 添加到含外部成员或公开群、将「项目级」Agent 添加到公开群、非创建者尝试将可见的他人「项目级」/「团队公开」Agent 添加到另一个群会话，或非助手管理者尝试向已包含他人「项目级」Agent 的私密群添加新的外部真人成员
- **THEN** 服务端明确拒绝（公开群或私有助手成员互斥返回 409，非主人拉他人助手入群或向含他人项目级助手的私密群拉新外部成员返回 403 并说明仅助手管理者可邀请/扩圈）且群成员保持不变

#### Scenario: 项目级全局助手跨非重叠私密群加入时要求主人确认背景互通
- **GIVEN** 某全局模式（`work_mode = "global"`）的「项目级」Agent 已在一个含外部真人成员的未解散私密群中
- **WHEN** 主人本人在未附带跨群共享确认标志的情况下，尝试将该助手加入另一个外部真人成员集合不完全相同的私密群（或向当前私密群添加导致两群外部真人成员集合不完全相同的新成员、或新建此类私密群）
- **THEN** 服务端返回 409 `project_agent_cross_group_confirmation_required` 提示全局助手跨会话共享记忆与工作区；主人本人确认并附带 `confirm_project_context_share: true` 重试后成功完成入群

#### Scenario: 助手收紧为项目级或私有时自动退群与清理在途状态
- **GIVEN** 某 Agent 已加入公开群 G_pub、含外部成员的私密群 G_priv，以及仅含主人本人与同主人名下 Agent 的私密群 G_own
- **WHEN** 主人将该 Agent 从「团队公开」收紧为「项目级」，或进一步收紧为「私有」
- **THEN** 收紧为「项目级」时自动从 G_pub 移除而保留 G_priv 与 G_own；收紧为「私有」时自动从 G_pub 与 G_priv 移除而仅保留 G_own；在所有被移除群聊中同步清理该 Agent 的话题关注、未完成流式占位与待决权限请求，向原成员推送成员变更事件并撤销失权未消费任务上下文与发布系统通知（已完成历史消息保留可读）

#### Scenario: 重复添加已在群的参与者保持幂等
- **GIVEN** 某 agent 已是该群成员
- **WHEN** 前端再次 `POST /participants` 提交同一 agent
- **THEN** 成员不重复出现，会话快照参与者集合不变（不报 500）

#### Scenario: 添加请求为空或 agent 无法解析被拒
- **WHEN** 前端 `POST /participants` 提交空列表或无法解析为已知 agent 的 id
- **THEN** 400 拒绝，会话成员不变

#### Scenario: 非成员添加参与者返回 404
- **WHEN** 用户对自己未参与的会话 `POST /participants`
- **THEN** 404，不泄漏该会话存在

#### Scenario: 修改群名生效，空名被拒
- **WHEN** 前端 `PATCH /im/v1/conversations/{id}` 提交非空 `title`
- **THEN** 200 返回更新后的会话，会话列表与详情显示新群名
- **AND** 提交空 `title` 时不接受为新名（会话名保持原值）

#### Scenario: 会话参与者带 user_id 供成员管理
- **WHEN** 前端读取会话（`GET /conversations` 或写操作返回的快照）
- **THEN** 每个 participant 带 `user_id`（agent participant 的 `id` 是 agent_id，`user_id` 是其稳定 IM 用户标识），前端据 `user_id` 调移除端点

#### Scenario: 移除参与者后该成员从群消失并同步收敛项目级私聊资格
- **GIVEN** 群里有真人成员与「项目级」Agent
- **WHEN** 前端 `DELETE /im/v1/conversations/{id}/participants/{user_id}` 移除某成员或移除该「项目级」Agent
- **THEN** 204；该会话快照参与者集合不再含被移除者，被移除者不能再发言或接收成员消息流；若此次移除后某外部真人成员与该「项目级」Agent 不再共享任何未解散私密群，双方既有的一对一私聊同步转为只读（`write_blocked_reason: "agent_project_restricted"`）、撤销该私聊未消费任务上下文并关闭该成员对该助手的实时原生轨迹连接

#### Scenario: 仅创建者可解散群，非创建者被拒
- **WHEN** 会话创建者 `DELETE /im/v1/conversations/{id}`
- **THEN** 204，该会话移出日常列表，消息与任务保留为历史只读；未完成任务关闭，done/closed 保持；若解散的私密群使某外部成员失去与群内「项目级」Agent 的最后一个共同未解散私密群，双方历史一对一私聊同步转为项目级只读；历史按解散前冻结的成员与可见范围授权
- **AND** 非创建者发起同一请求时 403，会话不被解散

#### Scenario: 跨账号添加真人及自己的 Agent
- **GIVEN** 三个账号拥有不同的 Gateway 或没有 Gateway
- **WHEN** 群成员添加同事，各管理者添加自己管理的「团队公开」Agent（或在私密群添加本人管理的「项目级」Agent）
- **THEN** 成员跨账号、跨 Gateway 加入同一群；普通成员不能把他人管理的 Agent 加入群。

#### Scenario: 移除后在线与重连界面收敛
- **GIVEN** 用户被移出群或群已解散
- **WHEN** 用户在线收到更新或断线后重新连接
- **THEN** 该聊天从其已加入列表移除，客户端清理旧授权缓存并重读资格；私密群移出者不能继续读取，公开群访客可主动读取。解散后不产生新的群消息，具有历史资格者可从任务的历史入口回看。

### Requirement: 群类型具有明确默认值、加入方式与切换资格

新建群默认公开，可选私密；包含个人空间成员、「私有」（`owner_only`）Agent 或「项目级」（`project`）Agent 的新建群固定为私密；旧群升级时默认私密。公开群允许公司内有资格的人和「团队公开」Agent 自行加入，私密群需邀请。公开／私密双向切换仅限已加入该群的公司管理员，且群内存在「私有」或「项目级」Agent 时不可切换为公开。

#### Scenario: 创建和加入
- **WHEN** 人或 Agent 新建群，或希望参与已有公开群
- **THEN** 普通公司群新建时默认公开且能选择私密，含「私有」或「项目级」Agent 的群强制私密（显式请求创建为公开时返回 409 拒绝）；公开群可供有资格成员与「团队公开」Agent 自行加入（「私有」与「项目级」Agent 非成员读取、搜索公开群或调用加公开群均被拒绝），私密群不提供自行加入；人有界面入口，Agent 有工具入口。

#### Scenario: 从已有会话入口发现公开群
- **WHEN** 用户在聊天列表的“＋”菜单选择发现公开群
- **THEN** 搜索框与会话列表保持原有布局；弹窗沿用聊天界面的遮罩、标题栏、群头像及可点击列表行，按内容决定高度，长列表在弹窗内滚动，手机使用对应底部面板。
- **AND** 能关闭或按 Escape 返回原会话，选择群进入原有访客查看／加入流程，不因浏览而入群。

#### Scenario: 更改可见范围
- **WHEN** 已入群的公司管理员把不含「私有」及「项目级」Agent 的群改为公开或私密
- **THEN** 群消息和所属任务一起采用新范围，已有成员与内容保留。
- **AND** 若群内当前包含「私有」或「项目级」Agent，尝试改为公开时返回 409 拒绝；非管理员群创建者或普通成员不能仅凭创建／改名权限切换；未入群的公司管理员也不能直接切换。

#### Scenario: 外部影子会话保持原可见范围
- **WHEN** Gateway 同步外部 channel 并创建影子会话
- **THEN** 不因内置群默认公开而公开外部聊天；影子会话仍按成员范围访问。

#### Scenario: 公司内读取与成员写入分离
- **WHEN** 有效公司成员或「团队公开」Agent 发现并浏览公开群
- **THEN** 可读取详情、消息与会话附件；默认聊天列表仍显示已加入会话，查看不自动加入。发言、上传与任务维护需加入未解散会话；私密群、私聊及解散历史采用各自权限。
- **AND** 改范围后，详情、消息、附件、任务、Agent 查询和待投递消息重试使用当前资格；不宣称撤回已被接收者读取的内容。

### Requirement: 外部成员与私有助手的历史一对一私聊保持只读且可逆恢复

#### Scenario: 助手切换为私有或失去共同私密群后历史同事私聊双向封禁但保留历史与个人偏好控制
- **GIVEN** 同事 B 与主人 A 名下的助手 X 曾建立一对一私聊并存在历史消息，随后 A 将 X 切换为「私有」（`owner_only`），或 X 处于「项目级」（`project`）而 B 已不再与 X 共享任何未解散私密群
- **WHEN** B 读取会话列表、该会话详情或消息时间线，修改个人置顶/免打扰或删除该直聊，或 B / X 尝试向该会话发送新消息
- **THEN** B 仍可读取该会话与既有消息记录，会话快照标记 `can_write: false` 与对应的 `write_blocked_reason`（`"agent_private"` 或 `"agent_project_restricted"`），且 B 仍可通过 `PATCH /im/v1/conversations/{id}` 调整本人的 `is_pinned` 与 `is_muted` 偏好或移除该直聊；B 与 X 向该会话发送新消息或修改会话标题均返回 403 拒绝。

#### Scenario: 再次共享未解散私密群或切换回团队公开后历史私聊自动恢复
- **GIVEN** 上述一对一私聊因助手 X 处于「私有」或无共同私密群而只读封禁，且 A 与 B 仍为有效团队成员
- **WHEN** X 处于「项目级」且 A 将 X 与 B 置于同一未解散私密群，或 A 将 X 切换为「团队公开」（`team`）
- **THEN** 该会话自动恢复 `can_write: true`（清除 `write_blocked_reason`），B 与 X 可继续在原会话内双向收发消息而无需重建会话。
