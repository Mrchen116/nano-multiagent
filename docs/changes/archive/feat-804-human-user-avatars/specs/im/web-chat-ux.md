# IM web-chat-ux Specification (delta for feat-804)

## MODIFIED Requirements

### Requirement: 聊天身份与群聊选择信息清楚可辨

用户进入对话时应能看懂自己正在和谁协作，回到列表时应能找到最近的工作进展。消息正文与真实摘要优先；常规运行详情按需查看，需要用户处理的状态在相关操作处可见。身份提示随读者视角变化：同一伙伴跨入口可辨，群聊、旁观和代发仍能辨认实际参与者及发言归属。真人使用圆形自定义照片头像或首字母柔和色圆章，个人助手与专业数字员工使用各自的角色剪影，角色形象的选择与一致性见 [Agent 身份头像](../../../../specs/im/agents-nodes.md#requirement-创建助手时可选择统一且可辨认的角色头像)。

#### Scenario: 新建聊天分类筛选并区分真人同事与跨团队 Agent
- **WHEN** 用户打开新聊天
- **THEN** 提供「全部 / 同事 / 助手」分类筛选，默认列表将真人同事分组排在 Agent 之前；真人条目展示圆形头像（已上传照片或首字母圆章）、显示名、`@username` 及关联公开 PA 提示（若有），Agent 条目展示本人全部可用助手、他人「团队公开」助手以及与本人共享未解散私密群的他人「项目级」助手的角色剪影、名称、在线状态、归属信息与已知设备名（同事公开 PA 不暴露节点 ID，他人「私有」助手、私有 PA 及无共同私密群的他人「项目级」助手不展示）

#### Scenario: 新建群聊选择真人同事与本人候选 Agent
- **WHEN** 用户打开新建群聊或查看群详情成员及「添加成员」面板
- **THEN** 新建群聊分「同事」与「我的智能体」两组展示并将真人同事排在本人 Agent 之前，支持按姓名或 `@username` 搜索过滤且不混入他人名下普通 Agent；真人候选展示圆形头像、显示名与 `@username`（不暴露内部用户 ID），本人 Agent 候选第一行显示名称及本地化在线状态、第二行显示 Agent ID、所属机器名及项目级/私有标识
- **AND** 新建群聊中一旦勾选本人任一「私有」助手，群可见性锁定为私密并禁止同时勾选其他真人同事；一旦勾选本人任一「项目级」助手，群可见性同样自动锁定为私密但允许正常勾选其他真人同事；群详情中若群内已含「私有」或「项目级」助手则将可见范围锁定为私密（禁用公开可见性切换并显示原因说明），含「私有」助手时在「添加成员」中不提供外部真人同事，含本人「项目级」助手时允许主人继续添加外部真人同事，而含他人「项目级」助手时对非主人禁用添加外部成员并说明仅助手管理者可扩圈（公开群的「添加成员」过滤掉本人「私有」与「项目级」助手）
- **AND** 当主人将已在其他含外部成员私密群中的全局「项目级」助手新建或加入外部真人成员集合不完全相同的私密群时，弹窗明确展示跨会话共享记忆与工作区背景互通提示，取消不执行、确认后完成入群
- **AND** 描述不占用额外行，机器归属不依赖描述内容；群详情顶部头像簇按实际群成员展示（不因群内存在 Agent 而忽略真人成员），群内非本人真人成员与加人列表同样展示 `@username`，且加人列表支持按姓名或 `@username` 搜索过滤并保留已选成员

#### Scenario: 既有真人身份槽位统一展示受保护照片头像并在次级结构中保持克制
- **WHEN** 已登录用户在桌面或移动端查看导航栏个人菜单、「我的」身份卡、账号设置、会话列表、消息流与话题回复的发言人头像、话题参与者、已读回执明细弹窗、`@` 提及候选、聊天搜索联系人、一级「同事」目录、个人名片、任务创建者与负责人、公司成员列表，或个人助手关联的屏蔽联系人与风险事件真人条目
- **THEN** 已设置自定义头像的真人通过当前登录凭据按 `(user_id, avatar_version)` 单飞拉取并在同会话内存复用同一圆形照片头像（不在 URL 暴露访问令牌），未设置的真人及外部渠道未映射发送者显示首字母柔和色圆章，个人助手与专业数字员工保持角色剪影；消息气泡内的引用回复块、输入框待引用预览条与正文提及胶囊保持纯文本引用层级而不叠加头像
- **AND** 自定义头像加载中、离线或读取失败时原位保持首字母柔和色圆章而不出现破损图标或布局抖动；用户更换或移除头像后各入口按新版本即时刷新，退出登录、切换账号或切换服务地址时立即释放内存中的头像对象 URL

#### Scenario: 历史一对一私聊因对端助手设为私有或失去共同私密群而只读提示
- **GIVEN** 用户打开与他人名下助手的一对一历史私聊，且该助手当前已被设为「私有」（`write_blocked_reason === "agent_private"`）或处于「项目级」但双方已无共同未解散私密群（`write_blocked_reason === "agent_project_restricted"`）
- **WHEN** 用户查看该聊天面板或直接打开不可访问的智能体公开资料路由
- **THEN** 历史消息保持正常可读，隐藏底部消息输入框与历史消息分支按钮，顶栏隐藏失效的智能体设置跳转并保留个人置顶/免打扰会话菜单，会话顶部提示区以当前语言分别说明“该助手当前设为私有，暂不对外接收或发送消息”或“该助手仅面向同项目私密群成员开放，当前无法继续发送消息”（直接访问不可见助手资料路由时同样显示明确未开放提示而非网络故障重试）；当双方重新共处未解散私密群或管理者将该助手切回「团队公开」后，输入框与消息操作自动恢复可用

#### Scenario: 私聊与群聊减少重复身份信息
- **WHEN** 用户查看 PA、普通 Agent、真人私聊或群聊
- **THEN** 标题栏不叠加会话类型标签，私聊不重复罗列参与者；正常电脑名称在 Agent 头像详情中查看，头像保留在线状态，需处理的电脑更新提示仍可见。
- **AND** 普通私聊消息省略重复署名和 PA 角色标签；群聊及旁观会话保留发送者姓名，代发和委托来源继续明确展示。

#### Scenario: 群聊标题栏保持轻量
- **WHEN** 用户查看群聊标题栏
- **THEN** 群头像与成员数表达群聊身份，不再重复显示群聊类型标签；设置和任务入口使用统一无描边图标按钮，保留可访问名称、悬停提示与键盘焦点反馈，移动端点击区域不小于 44px。
