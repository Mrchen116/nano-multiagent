## 用户体验

独立体验审查者 ux_review 操作 Chromium、隔离 IM 与 headless 桌面宿主。1280×840 下展开的就绪卡片右缘为 335 px，输入区从 447.4 px 开始；打开个人菜单时浮层收起。1280×720 下热切换回到原会话，回复引用和草稿可继续编辑。420×680 下个人页支持检查与开关，聊天页在导航区提示等待。未绑定的电脑可以从当前服务取得更新；已绑定电脑可以等待任务并取消。审查者指出卡片重复说明自动更新机制，已把标题下文案缩短为发布来源。

四条旅程的交互、截图与运行限制见 [M1 验证记录](M1-desktop-seamless-updates/evidence/verification.md)。真实 Chromium 使用了构建后的产品 UI。Gateway 任务报告和操作系统打开安装器分别使用确定性替身与意图记录。实际替换安装、Windows 图形界面和已部署公网发行均未在本机验收。

## 代码与契约

独立 code_review 在 `5115522a4` 确认七项阻塞。closure 在 `ffd6328d9` 复核后确认其中五项关闭。final_two 在 `6f5846f4a` 定位剩余两条路径，owner 在 `083a94ac9` 完成对应修改。

| 问题 | 修复与复核依据 |
|---|---|
| Rust 记录中的空值导致 Node 拒绝预部署包 | 写入前省略缺席字段，真实 Node release loader 已读回 Rust 产物；分包更新的进程测试覆盖启动及回退。 |
| 下载或等待期间再次检查卡死 | 返回快照前释放状态锁，正在进行的检查也会合并。 |
| 重启时选中不同 IM 的缓存 | 按服务保存最后验证的发布清单，只考虑该清单明确授权的包。 |
| 切服后触发旧操作，取消请求过早报告完成 | 异步检查后重读上下文，按服务过滤 worker 回调，忽略未携带来源的旧版通知；由节点终态确认取消，禁止自动重试同一目标。 |
| 新界面未启动便报成功，在线节点长任务被放弃 | 在服务返回页面时保存上一个可用指针。页面挂载后确认版本，超时恢复旧 UI；在线成功回报也经过这条路径。节点操作跟踪至终态，迟到的成功回报保留已回退的失败状态与重试入口。 |
| 正式发布无法升级宿主，也不带更新亮点 | 发布器匹配描述文件与清单的协议代数，提升并验证正式清单和亮点，模拟发布测试覆盖两个桌面平台。 |
| 旧宿主被热装依赖新版 API 的界面 | 首次提供新 API 的外壳发布为协议 2，旧宿主从 IM 安装入口覆盖安装一次，以后使用应用内更新。 |

最终契约归并至 IM 的 Desktop Client 与 Agents and Nodes，并更新 IM 索引。保留原有登录自启、死进程锁恢复、托盘唤醒与远端 owner 更新约束。检查或下载失败时原版继续可用；回退适用于实际尝试切换后启动失败。

最终独立 reviewer resolved 定向核验 `6f5846f4a..083a94ac9`。无来源回调在 handler 终止；匹配回退目标的成功回报维持 failed/switch_rolled_back 并保留重试入口。两项均为 closed，其余五项沿用前轮结论。
