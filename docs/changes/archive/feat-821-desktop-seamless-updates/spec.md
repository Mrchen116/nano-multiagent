# feat-821: Crewden Desktop 无感自动更新与一键换新体验

## Relations

- Related: feat-790, feat-799

## 原始需求

> 用户提问：
> 「还有一个问题。现在windows和mac桌面端支持做自动更新吗，无论是自部署的IM服务还是我们的公网服务，其实都会提供最新版本，如果发现最新版本能不能支持用户手动，或者自动更新」
>
> 用户立项指令与产品体验定位：
> 「开个thread做吧」
> 「重点要从用户体验，前端交互上做好设计，我们是活泼，低摩擦，给年轻用户使用的商业产品。」

## 澄清记录

- Q1: 更新触发策略与用户控制边界怎么定？
  A: 默认开启「自动保持最新」——桌面端连接当前 IM 服务后在后台静默检查并预下载校验新版本，绝不打断正在输入的草稿或运行中的助手任务；准备就绪后，在本机无运行中任务且窗口退居后台空闲或下次启动时平滑完成换新，若用户正在前台使用则在左下角导航区呈现轻盈灵动的一键「点一下秒换新」胶囊（可按需展开精简更新亮点）。同时保留随时关闭「自动保持最新」的能力，并在个人菜单、系统托盘与「这台电脑」提供一致的手动「检查更新 / 立即换新」入口。
- Q2: 未绑定本机节点的纯聊天桌面客户端、自部署内网 IM 以及原生客户端壳升级怎么覆盖？
  A: 公网官方 HTTPS IM 与配置了受信发布源的内网自部署 IM 一体化支持；Windows（x64）与 macOS（Apple Silicon）桌面端即使尚未绑定本机节点、本机节点已停止或本机节点归属其他账号（仅作为纯聊天桌面客户端使用），也能直接从当前连接的 IM 服务独立发现并完成桌面端更新。日常更新走应用内数秒热切换；当新版本升级了外层桌面客户端宿主程序时，不展示冰冷的「不兼容」报错或命令行指令，而是无缝衔接为友好的「下载并升级客户端」一键安装引导。

**Agent 解读**：本次按 Full change unit 流程端到端交付 Windows 与 macOS 桌面客户端的无感自动更新与手动一键换新体验。核心设计方向是对齐现代年轻化商业桌面软件（如 Linear、Arc、Notion、Discord）的轻快、自明与零打扰质感：用自然亲和的用户语言取代运维面板式的技术术语，打通「公网官方服务 + 内网自部署服务」与「已绑定节点 + 纯聊天未绑定客户端」的全场景更新闭环，并将绝大多数日常迭代收敛为保留当前路由、输入框草稿、登录态与工作区的数秒热切换，同时把偶发的外层客户端安装包升级无缝融入同一套交互语言。

## 用户场景

1. **正在聊天工作时，新版后台静默就绪，「点一下秒换新」不丢半个字草稿**
   阿哲在 Mac 或 Windows 上打开 Crewden Desktop，正在项目群里敲一段长消息。此时他连接的 IM 服务发布了新版本。得益于默认开启的「自动保持最新」，客户端在后台静默完成了新版本的下载与完整性核验，全程没有任何弹窗抢焦点，也没有打断正在运行的数字员工任务。准备妥当后，主界面左下角导航栏上方轻轻浮现一枚温润灵动的胶囊提示——显示新版本号与「点一下秒换新 ✨」，旁边带有一个小巧的展开入口可瞄一眼本次更新亮点。阿哲没有急着先发掉写了一半的输入框草稿，直接点了一下「秒换新」：如果本机当前没有正在执行的助手任务，界面在短短几秒内完成平滑刷新，回来时依然停留在刚才的项目群话题、输入框里写了一半的文字与提及原封不动、账号保持已登录、本地工作区完好无损；如果本机恰好有助手正在跑任务，胶囊温柔提示「等当前任务跑完就自动换新」，期间他随时可以取消，绝不硬生生掐断工作。若阿哲合上窗口让应用静置在菜单栏/托盘且本机空闲无在途任务，或第二天重新打开客户端，更新也会在后台悄然切换就绪。

2. **仅把桌面端当聊天软件用（未绑定本机节点）或连接公司内网自部署 IM，照样丝滑更新**
   设计师小鹿在自己的轻薄本上装了 Crewden Desktop，平时只登录公司内网自部署的 IM 服务跟团队里的共享数字员工聊天，并没有把这台轻薄本绑定成运行节点（或者有时她把本机后台节点手动停掉了）。过去更新入口只藏在已绑定在线电脑的运维卡片里，她的客户端根本收不到更新。现在，无论连接的是官方公网服务还是配置了内部发布源的自部署 IM，也无论这台电脑是否绑定了本机节点，她的桌面端都能直接从当前连接的 IM 服务发现最新桌面版本，自动预下载或由她手动点一下完成换新；切换到另一个 IM 服务地址后，更新检查也会自动对齐新服务所提供的版本，绝不跨服串用。

3. **个人菜单、系统托盘与「这台电脑」三处一致的低摩擦手动检查与偏好开关**
   有些同事喜欢一切尽在掌控，或者刚听说团队发了新功能想立刻尝鲜。小鹿点开左下角头像个人菜单，一眼就能看到当前桌面版本号、清爽的「检查更新」入口（有新版时直接变为醒目的「点一下秒换新」或「立即更新」）以及「自动保持最新」开关；右键菜单栏/系统托盘图标也能直接点「检查更新…」，或在「电脑」设置页顶部的「这台电脑」卡片查看更新状态并管理自动更新偏好。如果当前已经是最新版，点击检查后原位轻快反馈「已是最新版本 ✓」，几秒后自然收起；如果因为断网或发布源暂时不可达导致准备未完成，界面用大白话清楚说明「暂时连不上更新源，当前版本可照常使用」并附带「重试」按钮，全程看不到任何校验哈希串、内部协议号或生硬的工程报错码。

4. **遇到客户端外壳大版本升级时，无缝衔接为一键下载安装引导**
   隔了一段时间，Crewden 发布了一次包含底层桌面窗口外壳升级的大版本，没法只靠应用内热切换完成。小鹿的桌面端不会弹出令人困惑的「版本不兼容，请通过安装命令升级」警告，而是在同一更新入口平滑展示「本次升级包含新版桌面客户端」与更新亮点，提供一键「下载并安装新版」按钮：客户端直接从当前受信发布源下载并核验完整安装包并显示清晰进度；在 Windows 上点击后直接拉起安装器平滑关闭旧实例并覆盖升级后重开，在 macOS 上校验完成后一键打开新版磁盘映像并给出清晰的「拖入应用程序文件夹替换即可」轻指引（对未公证内部版本保留熟悉的打开提示）。升级完成后重新打开，原有的登录会话、连接的 IM 服务、已绑定的电脑身份、模型凭据与本地工作区全部延续如初。

## 验收标准

### Requirement: 桌面客户端支持从公网官方与自部署 IM 服务独立发现更新并默认自动准备

#### Scenario: 默认开启「自动保持最新」并在后台静默准备新版本
- **GIVEN** 用户在 macOS（Apple Silicon）或 Windows 10/11（x64）上首次或日常使用 Crewden Desktop
- **WHEN** 当前连接的公网官方 IM 服务或配置了受信发布源的内网自部署 IM 服务发布了较新的桌面端版本
- **THEN** 「自动保持最新」默认处于开启状态，客户端在后台自动下载并核验该目标版本，期间不弹出模态遮罩、不打断用户正在编辑的输入内容，也不中断正在执行的本机助手任务
- **AND** 当用户正在前台使用主窗口时，准备完成后在左下角导航区呈现非阻塞的新版就绪胶囊（展示目标版本号、可按需查看的更新亮点与一键换新动作）；当主窗口隐藏在后台且本机无正在执行的助手任务、无待决切换阻塞，或用户下次重新启动客户端时，客户端自动平滑启用已准备就绪的热更新版本

#### Scenario: 未绑定本机节点或本机节点未运行时仍可独立检查与完成桌面端更新
- **GIVEN** 用户在 Crewden Desktop 已登录账号（或停留在桌面端界面），但当前电脑尚未绑定为本机节点、本机节点处于手动停止状态，或本机现有节点归属于其他账号而当前用户仅使用聊天功能
- **WHEN** 当前连接的 IM 服务发布了新的桌面端版本，自动更新触发或用户手动点击「检查更新 / 立即更新」
- **THEN** 桌面客户端无需先绑定或启动本机节点即可独立发现新版本、完成下载核验并切换至新版本界面与内置运行环境

#### Scenario: 关闭「自动保持最新」后仅按用户手动指令检查和下载
- **GIVEN** 用户在个人菜单或「这台电脑」卡片中关闭了「自动保持最新」开关
- **WHEN** 当前连接的 IM 服务发布了新版本，或客户端重新启动
- **THEN** 该偏好跨重启持久保留，客户端不会在后台自动下载或自动切换新版本；用户仍可随时手动点击「检查更新」，发现新版本后由用户点击确认才开始下载与换新

### Requirement: 热切换更新数秒内完成并完整保留当前路由、输入草稿、登录态与本机工作

#### Scenario: 前台一键换新保留当前聊天路由、未发送草稿与登录会话
- **GIVEN** 新版热更新包已在本地准备就绪，用户在桌面端已进入某个具体聊天会话（或话题、任务、助手设置页面），且聊天输入框内有尚未发送的文字草稿或提及内容
- **WHEN** 用户点击新版就绪胶囊、个人菜单、「这台电脑」或系统托盘中的换新操作（且本机无正在执行的助手任务）
- **THEN** 客户端在数秒内完成本机受管运行环境（若已绑定）与桌面界面的平滑切换，自动回到换新前所在的同一页面路由，聊天输入框内的未发送文字草稿与回复引用完整保留，登录会话、电脑身份、已配置模型与本地工作区全部延续

#### Scenario: 本机存在运行中助手任务时等待任务安全收尾并支持取消
- **GIVEN** 当前电脑已绑定本机节点且有正在执行的助手任务，新版热更新包已准备就绪
- **WHEN** 用户触发换新（或自动更新进入待切换阶段）
- **THEN** 界面以自然语言明确提示「将在当前任务完成后自动换新」并提供「取消本次换新」操作，绝不强行中断正在执行的任务；用户在切换开始前点击取消后，保留当前版本继续运行且不重复自动打断

### Requirement: 个人菜单、系统托盘与「这台电脑」提供一致、零黑话的手动更新交互与异常恢复

#### Scenario: 多入口一致查看版本、手动检查更新与获取明确状态反馈
- **WHEN** 用户打开桌面端左下角个人菜单、菜单栏/系统托盘菜单或「电脑」页的「这台电脑」卡片并触发「检查更新」
- **THEN** 各入口一致反映当前版本号与实时更新状态：已是最新时就地展示轻快的「已是最新版本」反馈，服务尚未发布桌面包时展示「当前服务暂未提供桌面更新包」，正在后台准备时展示清晰的阶段进度，新版本已就绪时直接提供一键换新按钮
- **AND** 全程所有用户可见界面文案均使用通俗友好的产品语言，不裸露校验哈希值、内部协议字段名或生硬的工程错误码

#### Scenario: 网络中断、核验未通过或启动回退时保态并可一键重试
- **WHEN** 检查或下载更新期间网络中断、发布源不可达、安装包完整性核验未通过，或新版本切换后未能正常就绪触发自动回退
- **THEN** 客户端完整保留原可用版本、登录态与全部本地数据，界面清晰说明更新未完成及原版本仍可正常使用，并提供直接可用的「重试」入口，不发生损坏或半成品切换

### Requirement: 需要升级桌面客户端外壳的大版本无缝转化为应用内一键下载与安装引导

#### Scenario: 外层桌面客户端程序变更时平滑下载完整安装包并引导升级
- **GIVEN** 当前连接的官方或受信自部署 IM 服务发布的新版本升级了外层桌面客户端宿主程序（无法仅靠内部热切换完成）
- **WHEN** 桌面客户端检测到该新版本并由用户点击升级客户端
- **THEN** 界面不显示「版本不兼容」报错或终端命令行说明，而是友好说明本次更新包含新版桌面客户端并展示更新说明，从当前受信发布源下载并完整核验对应平台的安装包并呈现下载进度
- **AND** 下载核验完成后，Windows 客户端支持一键拉起新版安装程序平滑关闭运行实例并覆盖安装重开；macOS 客户端支持一键打开已核验的新版磁盘映像并在界面给出清晰的拖拽替换步骤提示，升级完成后原登录会话、连接的服务地址、电脑节点身份与本地工作区完整保留

## 范围与非目标

- **在范围**：
  - Crewden Desktop（`macOS Apple Silicon` 与 `Windows 10/11 x64`）面向公网官方 HTTPS IM 与受控自部署内网 IM 的统一桌面端版本发现（含未绑定/已停止/非本人节点的纯聊天桌面客户端模式，以及已绑定本机节点的联动热更新模式）；
  - 默认开启且持久化的「自动保持最新」偏好开关、后台静默预下载与 SHA-256 完整性校验、本机空闲/下次启动自动平滑应用；
  - 主界面左下角灵动低打扰的「新版就绪 · 点一下秒换新」胶囊（含更新亮点展开与稍后收起）、个人菜单（`UserMenu`）、系统托盘菜单与「这台电脑」卡片的一致手动检查/更新入口及零黑话自然语言反馈；
  - 应用内热切换期间对当前页面路由、聊天输入框未发送文字草稿/引用、登录会话与本机工作区的完整保持；
  - 外层 Tauri 原生客户端宿主程序升级（`shell_protocol` 演进）时，从当前官方或受信自部署源下载核验 `.exe` / `.dmg` 安装包并拉起覆盖安装（Windows）/ 打开映像引导替换（macOS）的无缝衔接体验。
- **非目标**：
  - 不改变普通浏览器 Web IM（无需客户端安装更新）或 iPhone 原生客户端（沿用既有 IPA / 分发渠道）的更新方式；
  - 不在 Linux 平台新增桌面原生客户端（Linux 继续沿用后台 Node + Web IM 边界）；
  - 不绕过现有官方/公网严格 HTTPS 与自托管受信发布源校验红线，不经 IM 业务进程中转安装包字节流，也不跳过下载产物的完整性哈希校验。
