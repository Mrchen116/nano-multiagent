# gateway - Personal Agent Delta Specification

> Target: `docs/specs/gateway/personal-agent.md`

## MODIFIED Requirements

### Requirement: PA 主动筹划执行主会话平时轻量记账、夜间深度筹划、实质早报触达与唤醒前观察流同步

对角色为个人助手（PA）且开启 `proactive_planning` 的主体，宿主围绕主人全盘目标与获准观察流执行个人化主动思考与实质早报闭环（普通团队全局数字员工的岗位主动筹划与低噪挂板规则见 [Global Agent 规范](global-agent.md#requirement-全局数字员工围绕岗位职责执行两阶段静默运转原会话归属与低噪触达)）。PA 的两类主动唤醒均直接作用于自身主会话（不拆与主会话记忆脱节的孤立短期小会话），夜间睡眠时段顺接在自身标准凌晨 `Dreaming` 之后执行每日一次深度筹划。在日常对话与观察唤醒轮中，PA 依据常驻 `MEMORY.md` 的「主动性与介入偏好」四档简短触发校准识别需积极盯紧与提前备料的事项（触发后按需顺链接读取 `knowledge/proactivity-policy.md` 或相关背景页）并严守免打扰禁区，且全程不读取后台观察池 `knowledge/proactivity-signals.md`。

#### Scenario: 平时对话安静后主会话轻量记账，不抢发或反复重做早报
- **GIVEN** PA 开启了主动筹划且未处于停用状态
- **WHEN** 主人在 PA 私聊或已获准观察的会话中交流计划、进展或具体时间安排，随后会话进入安静空闲期
- **THEN** 实时对话轮次优先自然快速回复；当存在尚未记账的主人私聊消息或已准入主人相关观察事件且安静满静默窗口时，宿主向 PA 主会话自身提交轻量记账隐藏唤醒 `proactive_review`（到点若主会话正忙则保留未记账水位待空闲后重试；主动唤醒自身回合与被动任务系统通知不推进活动水位，无新增真人活动时零唤醒且不自激；尾部唤醒消息仅在当前上下文窗口尚未包含最新内容时按需附带更新后的 `MEMORY.md` 与合规 `knowledge/proactivity-policy.md` 正文，同窗未变时不重复追加，且不重写系统提示词前缀），由主会话原位更新已说定的明确任务状态与具体事项跨天 `schedule`，对常驻 `MEMORY.md` 免打扰禁区话题保持零记账，不做重度发散筹划也不折腾明早早报列表（睡前多次补充仅做原位更新）
- **AND** 非免打扰时段（若 `MEMORY.md` 或 `knowledge/proactivity-policy.md` 的「触达时机与汇总方式」记录了主人自定义安静时段则优先按该时段判定）仅在发现约一小时内紧急冲突时可简短提醒一句，其余情况及免打扰时段保持聊天静默，轨迹记入 PA 的 Work 记录

#### Scenario: 凌晨紧随标准夜间 Dreaming 之后执行主会话深度筹划并安排实质早报触达
- **GIVEN** PA 开启了主动筹划且未处于停用状态
- **WHEN** 进入本地凌晨睡眠窗口（默认 `03:00–06:00`），自上次夜间筹划以来存在新增主人私聊对话或已准入观察动态，且距最近一次真人活动已满夜间静默时长门禁（防止熬夜跨凌晨连续发言时抢占主会话；全天无新活动或白天开盖时零筹划唤醒）
- **THEN** 若 PA 启用了 `dreaming` 特性且同一有效时区当夜周期的标准 `Dreaming` 尚未完成检查（含实际完成整合，或因未满最小增量门槛而静默延后并标记当夜检查完成），在连续失败未达上限（如 3 次）且下次重试未超出凌晨窗口截止时间前，宿主非阻塞返回忙态等待标准凌晨 `Dreaming` 先完成当夜周期评估（用户关闭 `dreaming` 特性或当夜重试越界时直接降级放行，不整晚阻塞），随后向 PA 主会话提交每日最多一次的夜间深度筹划隐藏唤醒 `proactive_nightly`
- **AND** 在 `proactive_nightly` 轮中，宿主在尾部唤醒消息中仅当相对当前上下文窗口已有快照/内联版本发生变化时按需附带最新 `MEMORY.md` 正文与合规 `knowledge/proactivity-policy.md` 策略细则（不依赖可选文件工具、不在同窗重复追加无变化副本、不静默重写系统提示词前缀，且不加载后台观察池 `knowledge/proactivity-signals.md`），主会话严格遵守免打扰禁区、低打扰挂卡与触达汇总规则，统揽全天对话围绕长线大目标做必要的零副作用查证，准备次日有实质信息量的参考要点或工作区草稿文件，先收起已解决或过时的旧 `proposed` 提议（不标为人类未采纳负反馈），再对符合主动边界的重投入调研、跨 Agent 协作、长线目标前沿下一步或新构想在私人空间建立有界数量的 `proposed` 待拍板提议卡（若主人已有固定早间定时任务，同步将待早间顺递摘要与卡片引用记入跨上下文压缩持久保留的固定笔记工具供次日早间消费）；夜间全程不主动发聊天消息吵人；关闭特性、停用 Agent 或节点更新时立即拦截待触发并取消运行中的 `proactive_review` 与 `proactive_nightly` 唤醒

#### Scenario: 原生定时实质早报顺路触达、准备材料解耦与无干货零唤醒
- **GIVEN** PA 开启了主动筹划
- **WHEN** 夜间深度筹划完成并决定次日早间触达方式，或主人配置的早间、午后、晚间主会话原生定时任务触发
- **THEN** 若主人已配置早间固定定时任务，夜间筹划不另设闹钟，次日早间定时触发时在同一条消息中主动与主人对齐其自身今日计划并顺路附上夜间备好的实质要点、普通工作区文件附件或顶层 `task_cards` 活卡片供参考，尊重主人自身计划决定权而不越权代定日程（准备提纲或文档不耦合进任务图数据结构）
- **AND** 若主人未配置固定早间定时任务，仅当夜间筹划确实产出了有实质信息量的新准备干货或待拍板卡时，由主会话建立一个早间一次性原生 `schedule` 送达实质早报；无任何实质新价值时不建闹钟、保持零唤醒且绝不发送“暂无更新”类空洞早报

#### Scenario: 定时唤醒前同步观察流最新动态并保留私聊未读暂扣
- **GIVEN** PA 的原生定时任务或心跳即将唤醒主会话
- **WHEN** 主人此前已在获准观察的群聊或私聊中发出了尚未满十分钟合并周期的最新消息
- **THEN** 宿主在定时唤醒进入模型首步前等待完成中心待处理观察事件拉取并同步至本地收件箱，对存在未读观察来源的定时轮次向模型提示先读取最新收件箱记录，配合既有的私聊自身未读消息发送暂扣（`held_for_revalidation`），使 PA 在发提醒前能读取最新进展并静默结项已完成事项，避免发出马后炮催问
