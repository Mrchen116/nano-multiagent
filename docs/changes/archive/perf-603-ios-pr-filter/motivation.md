## 澄清记录

用户确认按以下规则快速实施：完整 PR 差异涉及 iOS 目录中的代码、测试、资源、工程、依赖锁文件、构建脚本或 CI workflow 时运行；仅文档、`.gitignore` 或其他模块变更跳过。主干 push 继续完整运行。

## 现状痛点与性能目标

2026-10-14 核对最近五次 PR 的 GitHub Actions：iOS job 分别耗时 610、480、386、403、560 秒（中位数 480 秒）；前端 81–109 秒，后端 122–175 秒。[最新样本](https://github.com/Mrchen116/nano-multiagent/actions/runs/38491538836/job/115617627527) 中模拟器编译、准备和测试共 439 秒，实际测试约 20 秒，Release 归档另占 145 秒。

目标：iOS 无关 PR 的 macOS job 执行次数降至零，前后端继续独立运行；涉及 iOS 的 PR 与主干 push 保留完整模拟器测试和 Release 归档。不在本次引入依赖或构建缓存。

## 用户侧验收标准

本次仅调整开发 CI 调度，不改变 App、Web、Node 或后端产品行为。

- 无关 PR 的 iOS check 显示跳过，前后端检查正常运行。
- iOS 实现、测试、资源、工程、锁文件、构建脚本或 CI workflow 变更继续运行完整 iOS job。
- 删除、重命名与混合修改按整个 PR 的差异判断，不只检查最后一次提交。
- 主干 push 完整运行；路径判断失败时仍运行 iOS gate。
