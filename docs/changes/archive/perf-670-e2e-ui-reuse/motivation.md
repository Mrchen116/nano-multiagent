# perf-670: 自动复用仍有效的 E2E UI 构建

## 原始诉求

围绕开放 PR #416 的启动耗时，用户依次提出：

> 那不重新构造可以吗，如果不涉及前端变化，可以复用吗

> 我的需求里有前端变化的大概3分1。我不想浪费时间的同时，保持每次测试都是正常的

> 好，按快修模式走，测好了再更新pr

Agent 对范围的解释：保留现有启动入口，自动判断能否复用，无需用户记住跳过构建的参数；受影响输入或产物变化时重建，失败时阻止启动。用户明确授权由 Agent 验证后更新原 PR；不记录不存在的用户亲自重跑，不合并或部署。

## 现状与目标

PR #416 的 `2d1dcd250` 为所有 profile 无条件执行主前端与轨迹查看器构建；即使只有后端源码变化也重复相同工作。该 PR 的同源 UI、可选 Vite 和生命周期修复保留。

本轮同一 checkout 实测：新策略首次真实构建（包含需要的共享包）16.370 秒，无变化校验/复用 0.196 秒；原策略无变化时也执行两条完整构建命令。此数字仅为本机一次 UI 准备阶段测量，不代表完整 E2E 时间或跨机器性能。目标为无变化时零构建命令，校验在该机器低于 1 秒；应重建时不能牺牲正确性。

## 验收标准

### Requirement: 无需人工选择是否构建

#### Scenario: 仅修改后端后启动隔离测试
- **WHEN** 浏览器构建输入及已有产物均未变化，调用既有 e2e-up 入口
- **THEN** 复用已有 UI，仍执行服务启动与健康检查，输出实际 build/reuse 决策。

#### Scenario: 新需求使用新的 worktree
- **WHEN** 同仓库的新 worktree 拥有相同的浏览器构建输入和环境
- **THEN** 可以复制校验通过的成功产物，不必因 worktree 路径不同重新构建；账号、数据库及服务运行目录仍独立。

#### Scenario: 构建输入变化或产物失效
- **WHEN** 主前端、轨迹查看器、共享包、相关配置/依赖变化，或文件缺失/被覆盖
- **THEN** 对应 UI 自动重建或恢复匹配且验证通过的缓存，启动不使用过期产物；新文件、删除文件和未提交修改同样生效。

#### Scenario: 构建失败
- **WHEN** 必需构建失败，或构建期间输入变化
- **THEN** 本次准备失败，不能留下可被误用的成功记录，也不能将旧产物当作本次通过。

### Requirement: 保持既有隔离测试入口

#### Scenario: 同源 UI 和可选 Vite
- **WHEN** 正常启动或复用后使用 IM 同源页面或 `--vite`
- **THEN** 主页面、登录与轨迹资源仍可访问，精确 Origin 校验和本实例进程清理保持有效。

## 范围与回退

仅调整开发/E2E 构建准备和对应测试/文档。不改变业务 UI、模型输入、生产部署或后端构建前置要求；不建立远端缓存或共享运行数据。同仓库各 worktree 可复制复用一致产物，共享缓存只保留每套最近一个成功版本，限制磁盘占用。无产品 spec delta。删除本地与共享成功记录会强制重新构建；回退实现恢复无条件构建，无数据库迁移。
