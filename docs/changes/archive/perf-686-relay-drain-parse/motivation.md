# perf-686 中继积压的 payload 解析开销

## 原始诉求

> 修复 apps/im-server/src/relay-delivery.ts 在选择每条 relay 时反复 JSON.parse 整批候选 payload 的问题。256 条积压、32 个发送名额，一次 drain 测到 7,760 次解析。用真实投递循环计数，对照发出的消息和次序。保留各 Agent 轮转公平性、节点窗口上限、重连/ACK/超时退避、发送前逐条资格复核与撤销。

用户选择快速开发，并授权在正常体验保持一致时直接验证和交付可审 PR。本记录事后整理；验证由开发者在隔离环境完成。

## 现状与目标

在基线 `7e79e9b79` 上，固定资格结果时复现了 7,760 次解析。改动目标是单次 drain 中每个参与选择的候选 payload 最多解析一次。测量方法和运行结果见 [design](design.md)。

### Requirement: 积压消息仍按既有轮转和投递资格交付

#### Scenario: 多个 Agent 的消息交错或部分被撤销

- **WHEN** 在线节点有空位，同时多个 Agent 有待投递消息
- **THEN** 节点收到与基线相同的消息及顺序，未确认消息占用的窗口仍以 32 为上限；已失去资格的收件方不再收到相应消息。

#### Scenario: 重连或等待回执

- **WHEN** 节点重连、收到 ACK 或等待回执超时
- **THEN** 节点可继续接收未确认消息，已确认消息不再重放，超时消息遵守原有退避间隔。
