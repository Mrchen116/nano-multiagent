# perf-688 · 减少空闲轮次核对历史 Task 消费凭证的开销

## 原始诉求

> 修复没有新 Task 时，每轮仍把累计消费凭证逐项对整张映射表重扫。300 张均已消费凭证实测一次 commit 读回 9 万行。

## 性能基线和目标

在 300 条原文均已消费、中心没有新增或撤回的隔离场景，PA 的一次 prepare 读回 90,600 行映射，一次 commit 读回 90,000 行。每次核对还针对同一 Inbox 做 300 次重复读取，尝试 300 次无效更新。目标是让一次凭证核对最多批量读取一次候选映射，已对账的凭证产生零条待处理记录和零次消费写入。计数口径见 [实现和测量](design.md)。

### Requirement · 维持已有会话的 Task 上下文

#### Scenario · 下一轮收到新原文

- **WHEN** 消费过 Task 消息的会话再次执行，并有新的、仍有权查看的 Task 原文。
- **THEN** 模型按原有顺序看到完整原文，已执行的消息仅保留在历史中。

#### Scenario · 中断后恢复或准入前撤权

- **WHEN** 原生会话已落盘而产品侧确认中断。
- **THEN** 重启后通过同一会话的原文凭证补交。仅排队的原文仍待消费，准入前撤权的原文被移除。

## 范围

调整 PA 的消费核对。原生证据采集、同步协议和流式输出另属各自职责。沿用现有数据和索引，可直接回退实现提交。
