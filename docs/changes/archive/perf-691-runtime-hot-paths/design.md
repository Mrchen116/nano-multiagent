# perf-691：As-built Design

本文在实现后整理。基线为 `5e0f0413a`。改动只覆盖 motivation 中已复现的七个问题。

## 最终结构

### Web 同步和会话成员

浏览器建连仍先核对登录状态、读取游标、触发订阅者恢复，再建立用户 WebSocket。`GET /im/v1/sync?view=cursor` 在同一认证和账号资格边界返回 `max_event_id`。默认请求仍返回完整会话快照。旧服务端会忽略新参数，浏览器仍能读取同名游标。新服务端按 Agent 主键连接会话成员档案。

### PA 观察

Gateway 心跳将重试委托给 PersonalAgents。观察读取和重试共用待办 ID 筛选，基于当前节点绑定、生命周期代次、来源权限、排除策略和直聊联系人限制选择记录。生命周期只读取一次。SQL 窄列迭代按 event_id 前进，来源资格只在本次同步扫描内复用，达到所需条数即停止；只为命中页加载正文。

不可读观察仍留在原状态。重新获权后可再次读取，公开群和 PA 自身可访问的来源仍按原授权判定。当前代次未处理索引由正常启动建库路径创建。心跳不再为“读出来必为空”的队列发送通知。

### 飞书入站

ExternalStore 分别提供按原始输入 ID 查找、按镜像及 Agent 查找、待准入 ID、待镜像正文、最近 50 条来源历史。对应索引限制查询范围。恢复和 flush 继续沿原准入及镜像逻辑处理，保持原 rowid 顺序，平台接收和 IM 镜像仍分别确认。空字符串镜像与历史 NULL 均按未镜像处理。

### 单线交付

NodeStore 依据已有 delivery 与逐输入 receipt 选择仍欠工作的输入，模型切换通知继续经过既有幂等检查。运行尝试先建立 turn 映射，logicalEvents 保留原先首个匹配运行的归属。正文及过程事件仅在确有未决交付时加载一次，上限固定为本次观察后的 durable seq；异步通知期间后续写入的事件留待下一轮观察。

同轮群聊判断和外部回复来源按现有会话/turn 索引读取。群聊草稿重验仍能看到后续输入。未确认、unknown、失败回执、同轮多输入和已发送的模型通知仍使用原状态机。

### 创建恢复

创建路由在现有按 Agent 串行队列内核对未决操作的类型、owner、node 和规范化候选。只有同一请求能复用恢复结果。新操作在原 candidate_json 内记录首次省略技能时选定的默认值，Gateway 请求仍使用原公开字段。缺失快照的旧记录保留恢复路径；若省略技能且目录已变化而无法重建原候选，则返回冲突。其他内容的请求不会代领原请求的成功。

## 资源增长与剩余范围

以 C 为候选来源数、P 为会话成员数、A 为全局 Agent 数、N 为待观察项、L 为页长、H 为历史输入数、E 为会话事件数、R 为模型尝试数。

| 路径 | 最终代价与边界 |
|---|---|
| Web 仅取游标 | 会话数不再影响装配和响应体；最大事件 ID 通过现有数据库键读取 |
| 会话成员 | 从每成员扫描全部 A 个档案，改为每成员主键查询 |
| 观察页 | 只物化 L 个完整事件；资格缓存 O(C)，未获权来源积压仍可能需要线性遍历其窄列候选 |
| 飞书输入 | 单条主键读取；flush 的正文物化随未镜像项数增长，最近历史至多 50 项 |
| 单线交付 | 已确认且回执齐全时不物化旧事件与输入正文；数据库仍核对已有输入和回执，模型运行快照仍随历史增长 |
| logicalEvents | 首次建立尝试映射 O(R)，事件归并 O(E)，替代原逐事件搜索模型尝试的乘积 |

未决单线交付仍读取当前 seq 范围的会话事件。这个范围承担模型、token usage 与过程顺序语义，本轮未增加第二套聚合或持久化进度来跳过它。上述改善来自减少重复操作，未以测得时延制定生产 SLA。

## 兼容、失败与回滚

- 无一次性数据重写。新增索引可随普通启动补齐；回退代码仍能读取现有数据，额外索引不影响原数据语义。
- 新创建操作额外元数据只留在原 JSON 中。旧记录没有该字段时使用原候选核验能力。
- 权限、生命周期和输入确认分别复用现有事实，不引入跨请求可失效的权限缓存。
- 出现行为差异时按对应提交回退，保留已有会话、观察、入站账本和操作回执。

## 验证定位

- 真实 Fastify + SQLite 路由测试覆盖完整快照、仅游标、撤销账号资格、创建 503/409/201 和旧待办恢复。
- PA/IM 回归覆盖撤权与再加入、被屏蔽前缀、消息顺序、旧代次、镜像重试、输入缺回执与已确认 fallback。
- 同样本探针比较次数、完整输出及顺序。所有探针使用隔离数据，网络和模型替身有明确边界。
- 隔离 IM 与 Node 运行后，真实浏览器登录、创建群聊、主动断开并恢复 WebSocket；两次游标读取均成功且原群聊保持打开。验证后浏览器和服务均关闭。
- 本轮采用后台优化的工程验收，用户明确无需亲测。产品设计和用户体验按既有契约验证，创建恢复纠错遵循既有冲突语义；验收与归档依据见 acceptance.md。

## Canonical 影响

仅为 Web 增加可选择的游标响应形式，最窄 delta 位于 specs/im/agents-nodes.md。其他变化恢复或保持已有行为约定，没有新的产品设计。
