## 已复现的问题与目标

使用已合入基线的真实路由及处理方法。以下规模是隔离样本，不能解读为生产时延。

| 触发场景 | 基线行为 | 目标 |
|---|---|---|
| Web 建连只需要事件游标，已有 300 个群 | 返回 215,918 字节，准备 3,605 条 SQL | 游标读取与会话数无关，保留原完整快照 |
| 8 个会话成员，系统有 10,000 个 Agent 档案 | 拼接 JOIN 导致每名成员扫描 Agent 表 | 按 Agent 主键取相同成员和字段 |
| PA 分页读 2,000 条可读观察，每页 50 | 排空共逐项查 41,000 次生命周期 | 合格项够一页即停止，保留撤权过滤与顺序 |
| 主人失去私群访问，消费完权限撤销通知 | 其余不可读观察引起 3 次心跳空唤醒 | 唤醒须对应可读取的当前工作 |
| 收到一条飞书消息，已有 10,000 条已镜像记录 | 旧消息正文被解码 20,000 次 | 按输入 ID 准入、按待办镜像，不重读已完成正文 |
| 单线会话 3,000 个已关闭轮，唤醒没有新事件 | 读 9,000 条旧事件，为每个事件线性查询运行记录 | 消除事件与运行数的乘积，保持每轮交付和确认 |
| 未确认的创建 Alpha 后，用同一 Agent ID 请求不同配置 Bravo | 第二次返回 201，实际响应和库中都是 Alpha | 只有相同意图可复用成功，冲突请求遵循已存在 ID 的契约 |

## 用户可观察的不变性

### Requirement: 保持聊天、重连和 Agent 投递行为

#### Scenario: 连回聊天并继续收消息

- **WHEN** Web IM 重连或请求重新同步，或原生客户端请求完整快照。
- **THEN** 浏览器恢复同一个事件游标并重新核对成员资格，原生客户端仍获得可访问的会话列表；聊天成员、预览和权限保持一致。

#### Scenario: 已确认与待确认工作混合

- **WHEN** PA 分页取观察、飞书重送消息或单线 Agent 在模型切换后恢复。
- **THEN** 合格输入维持原顺序，已确认交付不重复，尚欠的投递或回执按原有规则恢复；不可读内容不交给 Agent。

### Requirement: 创建响应准确代表请求结果

#### Scenario: 首次创建应用后回执丢失

- **WHEN** 使用相同 ID 重试原创建或提交不同的创建内容。
- **THEN** 原请求可按现有恢复契约获取真实结果；不同请求不能把先前的配置报告为本次创建成功。

## 范围与回滚
