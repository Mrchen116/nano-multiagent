# perf-692：指定聊天查询按需读取

## 原始诉求

> 我希望通过多轮的这种检查以及修复。在确保不变用户体验、不变产品设计。的情况下，把整个性能跟代码架构，调整合理，变得使用上稳定高效，代码可长期维护，不引入额外的复杂度。

本项来自 perf-691 完成后的独立复查，沿用用户选择的快修模式。基线 `a40d56ff4` 已包含 PR #445。

## 问题与目标

Work.query 在检查具体 action 前装配全部可访问聊天。inbox.read 的 info 查询、inbox.check 的 describe 以及目标 read 都用不到该完整列表。30 个聊天时，目标 info 的 Global / PA 分别准备 698 / 1,555 条 SQL；300 个聊天时 PA 为 15,055 条。

目标是使固定聊天 info/describe/read 的装配规模与其他聊天数无关。实际需要发现聊天的 list、跨聊天搜索与 PA 目标解析保留原列表。

## 体验不变性

### Requirement: Agent 读取指定聊天保留范围和展示

#### Scenario: 查询聊天信息、批量描述或阅读一段历史

- **WHEN** 当前 Agent/PA 在有效会话中访问指定聊天。
- **THEN** 返回的标题、成员、来源、消息、顺序、游标与原实现相同。
- **WHEN** 目标被撤权或排除，scope 无效，或 Global session 不符合入口资格。
- **THEN** 保持原拒绝语义。

## 迁移与回滚

无持久数据变化，无 API/schema 变化。回退本实现提交即可恢复旧装配时机。
