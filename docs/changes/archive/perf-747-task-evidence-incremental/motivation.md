# 模型前置 Task 证据增量处理

## 用户要求

用户对五项审查发现逐项要求修复，并授权安排节奏：“都得解。怎么节奏做，你自己规划”。本单元对应“模型前置 Task 证据增量处理”。

## 现状与动机

每个模型 step 都 flush 并发送全部历史 Task 消费正文。1,000 条已消费证据导致单次内部请求约 2.14 MB。同 Agent 的并行会话逐个重复跑同一空同步。

保留原生 Task 消息、审计、模型可见内容和授权判断。

## Requirement: 模型前置 Task 证据增量处理

### Scenario: 长历史下完成原有操作

- **WHEN** 已有长期 Task 历史的 Agent 继续处理新输入，或者多个会话同时进入模型
- **THEN** 新模型请求只携带尚未确认的 Task 消费证据；重复或断线重试不漏消费、不重复注入，权限撤销仍在新模型请求前生效。同一时刻的等价授权同步可合并，持续产生的新变化仍可被察觉。
