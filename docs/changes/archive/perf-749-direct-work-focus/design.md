# 直接展开真实 Work 轮次

## 方案

- 中心保留已授权的 Work 消息映射，支持 opt-in 返回确切目标轮次的轻量摘要。按根 Agent、消息 ID、revision 使用 message_sent 部分索引；目标摘要复用正常轮次摘要序列化并携带其原生展示顺序位置。资格撤销及已删除映射仍使用现有路由检查。
- Web 的普通无限查询按 Agent/执行标识持有已载页和连续游标，独立于按来源消息请求的锚点。目标不在已加载列表时，将其摘要与当前列表按持久位置合并并展开，复用现有明细。缓存已访问的锚点，普通列表加载同一轮时以最新普通摘要去重。锚点走现有账号缓存清理；鉴权失败、删除或明确不可用时去除失效摘要，迟到关联仍可经刷新显示。历史主执行在自己的关联执行面板使用同一规则。
- 目标摘要附当前执行中紧邻的较新轮 ID。较旧锚点的该 ID 与屏上前一轮不同时，在两卡间标记“中间轮次尚未加载”，即使只缺一轮或另一端不在视窗。既有“更早轮次”按钮放在连续已载区间末尾、首个缺口前，从原游标继续；后续缺口只标记。正常分页逐步补过锚点后提示消失，紧邻不出现缺口。保留最新优先、折叠、轨迹往返和历史关联执行位置。用户可见变化见 [Work 契约增量](specs/im/agent-work.md)。

## 验证安排

独立代码审查核对锚点、旧主执行、鉴权和未完成同步。性能使用至少 1,000 轮的隔离 Work fixture，比对 HTTP 次数和返回摘要数量。Web 从 A 先手动翻页再跳 B 和 A，验证较新邻居、连续游标、折叠及轨迹往返；分别验证紧邻、只缺一轮、多个缺口、补过锚点提示消失、迟到/撤权、窄屏关联执行的分页位置。体验自检看连续块末尾按钮和缺口提示是否容易区分。
