# perf-751 · Global 子执行增量同步

## 原始诉求与边界

> 一个gateway大概最多有50个agent。不考虑单thread模式的agent。用户大概1000人，轨迹就非常大了，一个agent可能持续运行一年。这个过程中自然也会开无数的subagent。我觉得你要以这个基准去考虑问题，去考虑优先级。
>
> 那就按这个优先级开始修，三个 P0 都要解，怎么拆 PR、怎么排节奏你自己定

本单元处理第一个 P0。Global 新增执行或事实时，旧子执行的数量不应决定日常同步工作量。接单和重启接管、中心和 Web 的展示与 Work 传输另有交付。

## 现状和目标

DSH 每个目录页从树根查找上一页 ID。Gateway 在实时通知后请求整棵树并逐个对比 checkpoint。隔离探针使用实际 DescendantReader，1 万个子执行返回 40 页并访问 209,719 个目录位置。目标是在同一基线下，只有一个子执行变化时访问受该执行及必要祖先约束，旧树的一次恢复遍历则至多线性随目录项增长。

### Requirement: 活跃 Global 保留完整执行记录

#### Scenario: 查看正在推进的子执行
- **WHEN** 已有长历史的 Global 启动子执行，随后它产生工具、输出或最终状态
- **THEN** Work 能看到新执行、真实父子关系和完整记录，已结束的旧执行仍能打开。

#### Scenario: 重启或断线后继续检查执行
- **WHEN** 节点断线、重启，或停止启用中的 Agent
- **THEN** Work 以已保存事实为准，补齐需要恢复的记录，保留子执行真实归属和终态，不凭缺失数据宣告完成。
