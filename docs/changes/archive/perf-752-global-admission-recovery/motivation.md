# perf-752 · Global 接单和恢复随实际待办推进

## 原始诉求

> 一个gateway大概最多有50个agent。不考虑单thread模式的agent。用户大概1000人，轨迹就非常大了，一个agent可能持续运行一年。这个过程中自然也会开无数的subagent。我觉得你要以这个基准去考虑问题，去考虑优先级。
>
> 那就按这个优先级开始修，三个 P0 都要解，怎么拆 PR、怎么排节奏你自己定

## 现状和目标

已接单检查和持久回执在 `session.submit` 对相同根会话反复折叠整段原生日志。隔离样本 4 万和 40 万个事件，两次扫描分别约 7.5 和 56.6 ms。DSH 初始化另外在对外接单前逐个检查每个 Global 根的历史子执行。目标是热接单只处理新的日志后缀，空闲旧 Agent 无需回放历史即可让其他 Agent 接单。首次实际恢复某一原生 Session 的成本单独测量。

### Requirement: Global 连续工作与故障恢复

#### Scenario: 收到新消息或重复投递
- **WHEN** 使用已有长轨迹的 Global 收到输入，或客户端重试相同输入
- **THEN** 真实输入只进入一次，确认、取消、模型切换和完成结果可区分。

#### Scenario: 节点异常退出后恢复
- **WHEN** 节点重启且某个 Global 的子执行中断
- **THEN** 其他无关 Agent 可以先接单；该 Global 实际开始处理下一步时仍看到已验证且未消费的中断通知，未完工作不会凭空完成。
