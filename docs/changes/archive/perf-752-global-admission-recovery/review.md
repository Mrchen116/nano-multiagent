# perf-752 · 审查与验证

代码基线为 perf-751 的 `6461b5f9b`。独立代码与 Agent Context 审查覆盖目标注册、原生收口、同根接单证据和模型可见通知。首轮审查发现了整代恢复等待、目标 revision 替换与失败间隔、后台任务继承旧 Agent 权威、Schedule 恢复串行、更新暂停、关闭顺序和回执重试。对应修复保留目标 lifecycle 门槛，后台操作按 Agent 进度推进，Schedule 的通知或修复未达成时在该 Agent 的恢复队列重试。

- 50 个配置的隔离真实 DSH + WebSocket Relay 夹具。强杀前确认 A 根已正常结束、后台 child 仍在模型中；冷 initialize 未读取原生正文。受控暂停 A 的 child 观察时，B 经同一 socket 接到新输入并返回投递回执，模型入口执行，A child 正文尚未读。放行后 A 在真实 provider hook 中出现 `subagent-recovery` 来源。这个夹具直接装配 GlobalAgent。
- 独立的真实 Gateway 进程用例验证产品的 Node 装配。环回 Relay 保留 A 的启用冻结查询不回，B 已接收并回执。测试没有借用生产服务，也没有请求公网模型。
- 原生强杀测试验证持久 pending、下一次正常触发的首个模型请求、异常来源/文案、跨重启去重，以及部分读取失败时阻止相关 child 覆盖既有事实。未额外对禁用根抓取模型请求，生命周期、禁用根和停止围栏由专门用例覆盖。
- 固定合成样本里，40,000 / 400,000 事件的两个旧证据查证中位为 18.0 / 147.7 ms。索引已建立时各加一条事件后为 0.033 / 0.016 ms。首次内存索引分别约 20 / 317 ms。数值仅对证据查证，未当作首字延迟或 RSS 结论。

一次访问旧冷根仍受该根原生历史和实际活跃子执行的查证成本影响。未测全年轨迹、50 个 Agent 同时繁忙时的 RSS 或真实模型服务延迟。
