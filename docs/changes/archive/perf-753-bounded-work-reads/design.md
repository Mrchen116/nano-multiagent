# perf-753 · 实施设计

## 接口与兼容

现有 Work 路径提供显式 `catalog=separate` 模式给新版 Web 和 iOS。主 summary 只提供主 Session、状态、最近统计和有界轮次。关联执行使用同一授权边界下的新分页查询，稳定排序以 session_id 为 keyset，limit 受控，选中项可独立按 ID 读取。已有客户端的未选择模式维持原格式，现有轨迹、旧消息定位和源聊天授权路径不改变。主 Session、最新 usage、目录使用合适的 root/scope、session/usage 索引，分页版本无需为找最近已报告 usage 扫全部轮次正文。SQLite 索引随已支持 schema 安装，旧行不重写。

新客户端首个 response 带显式分页模式标记，以此为能力协商。未标记响应走旧内嵌目录，客户端不调用新路由；中心先升级，旧客户端继续工作，回滚中心时新版 iOS/Web 仍能使用旧读取。所有新版 Work routes 统一 current Agent 访问资格与删除检查。

## 主历史与详情

主 summary 带当前 main session ID；新版轮次缓存按实际执行 ID 分区，cursor 从该 ID 的专属路径翻页。每个已读区段保留服务返回的首尾和 next_turn_id 作为相邻证明。最新页更新后保留旧区段并按 ID 去重；若没有重叠或相邻证明，中间保留缺口提示，滚动接近时按上方区段的真实游标补到旧缓存。滚动接近轮次末尾时按同样方式自动续页，加载失败可在原处重试。主 Session 变化开启新缓存区，旧执行继续出现在目录，不用旧游标查新 Session。焦点 anchor 保持独立。

协商后的全部 summary 入口（主 head/older、关联 Session turns、旧消息 focus）都不调用控制详情或逐轮 COUNT/JSON 扫描，只读有界字段、真实状态和已报告 usage。已存在的工具条数与后台返回标记可作为展开后的详情；未读取摘要不显示为零或已完成。控制记录有独立详情读取，保留已有操作入口。Web 和 iOS 都按活跃主/子最新页更新；前后台恢复、轮询、WebSocket、权限后刷新与显示状态共用同一头部入口，停止对旧页自动请求。选中详情按稳定 ID 获取。活动详情初次读取确立该轮的 revision 水位。已打开的活动轮次以实际变化 revision 为游标，按有界分页只查新增或被替换的 item，并按稳定 ID 替换旧值，即使序号没变。每次自动刷新只消费一页变化；积压按游标继续。首次进入时待同步的旧消息 focus 是独立的精确查找，仅在待同步时随头部重试，不扫描历史。未打开历史不自动读，iOS 展开时首批加载并显示加载/失败状态。折叠预览保持当前状态和是否等待授权，不把未读 item 当空。

## 关联入口

显式 child session ID 优先，从消息来源、原生详情和委派事实直接打开，并按 ID 查元数据。旧工具项先按当前父 execution 与 exact tool call ID 查找；没有精确关联才按父 execution 与 child agent ID 查询弱候选。旧后台返回无 child session ID 时按根及已有 agent ID 查弱候选；若多次运行或跨父级重名，保留多个候选、提供有界续页并让用户选择，不能因目录分页/排序改变而打开另一个执行。关联记录暂未同步时显示不可用并可以重试。按 parent/call、root/agent 建索引，无需拉全目录做匹配。

## 验证和回退

单一 milestone 验证实际 HTTP 鉴权、旧和新版读取、Web/iOS 深链与直接选择、浏览器翻过多页后活跃更新，旧页请求数不随已加载页数增加。1 千/1 万/10 万子执行测同样的 20 条首屏返回和索引读计划，测试根 scope、旧记录、未知统计、已退休根以及旧关联。需要真实前端体验与旅程验收，独立代码审查和性能对照。现有视觉结构内增加已有加载更多样式，无需改变页面结构或选择替代产品方案。旧二进制回退继续读取原表和索引之外的数据，无一次性部署迁移。
