# perf-754 · 大 Work 记录不能卡住后续同步

## 原始诉求

> 一个gateway大概最多有50个agent。不考虑单thread模式的agent。用户大概1000人，轨迹就非常大了，一个agent可能持续运行一年。这个过程中自然也会开无数的subagent。我觉得你要以这个基准去考虑问题，去考虑优先级。
>
> 那就按这个优先级开始修，三个 P0 都要解，怎么拆 PR、怎么排节奏你自己定

## 现状和目标

每节点上传单条 Work journal，收到中心持久 ACK 才能继续。超过 16 MiB 的一条事实会暂停全节点上传，当前仓库测试确认该行为。目标是大事实按固定工作量传输、保留完整原文，并让之后正常事实最终同步。新版客户端依然能看到记录状态并访问完整明细。该能力与 Work 读取分页独立交付。

### Requirement: 大过程记录保留完整并可恢复同步

#### Scenario: 单个工具输出或过程事实较大
- **WHEN** Work 正在同步一条超过普通内联上限的记录
- **THEN** 该记录的身份、时间、类型、状态和原文保留，获授权用户可按需打开原文；已完成该记录同步后，后续记录正常继续。

#### Scenario: 大记录传输时断线或被撤权
- **WHEN** 在传输大记录时节点断线、中心重启，或其绑定与 Work 访问权被撤销
- **THEN** 授权仍有效时可续传且不会重复推进；被撤销的绑定不可继续写入，被撤销的用户不可继续发起原文读取。
