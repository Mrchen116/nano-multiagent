# perf-765: 减少 Dreaming 批次材料读取开销

## Relations

- Related: [feat-759](../feat-759-dreaming-role-consolidation/design.md)

## 原始诉求

> 抄codex的设计，改掉。按快修模式改

> 那提取任务摘要也一起改，按 Codex 的做法先裁剪单条工具结果。

> 现在用之前那次 57 次模型请求、148 次工具调用的 Dreaming 批次做一次隔离重放（在干净的memory仓起步否则无法成功，并回滚到没收集过这段轨迹的记忆之前，因为之前就是因为已经有记忆了所以后面没写任何记忆），跑真实模型验收。对比改前改后的模型请求数、工具调用数、token 和耗时，也看看记忆整理结果有没有退化。

## 澄清记录

- 单条工具结果裁剪和整批预算同时生效。整合直接消费首轮提供的入选正文。超出整批预算的来源仍可进入后续批次。
- 回滚到起始提交会丢弃批次开始时已有的未提交 tracked 修改。用户明确确认这是预期行为。
- 对照重放中，两版都保留主要事实。两份旧页上的后续状态链接位置不同。当前只有各一组样本，保留这一观察。

## 现状痛点

生产样本在已有记忆的基础上得到 0 页变更，仍有 57 次主请求、2 次压缩和 148 次工具调用。隔离环境从同一历史记忆快照起步的旧版样本有 111 次模型请求、242 次工具调用，其中 107 次工具调用的参数提到批次来源文件。

## 目标状态

两阶段在选材前限制单条普通工具结果的大小，整合首轮直接收到入选材料。保留必要回查入口，减少分段读取及反复查找。用同一批次、相同起始记忆和真实模型对照，记录请求、调用、token、耗时和整理结果。

## 用户侧验收标准

### Requirement: 维持真实依据和整理结果

#### Scenario: 从干净历史记忆整理已冻结的来源
- **WHEN** 同一主体重新整理同一批获准材料
- **THEN** 两版均可提交有效记忆，保留本批主要事实、纠正和依据，成功后才推进进度。
- **AND** 记录两版实际成本、内容差异与实验限制。

#### Scenario: 仓库检查反馈后仍无法完成
- **WHEN** 同一会话三次修复后仍无法满足仓库要求
- **THEN** 宿主尝试恢复本批开始时的 Git 提交并报告结果，本批来源进度保留。

## 影响范围

Dreaming 的任务摘要提取、长期记忆整合、正式记忆仓检查与恢复，以及内置 nano-memory Skill 的相关说明。

## 迁移与回滚策略

使用现有记忆仓和增量进度。恢复代码版本即可恢复原有选材与整合路径。
