# 证据驱动的研究与写作

## 目标

把研究问题变成一份证据边界清楚、推导有逻辑、目标读者能独立理解的结论或文章。

把本 skill 作为判断边界，不要当成固定流程。根据题目和用户意图自主选择搜索路径、工具、记录方式、文章结构、验证方法和视觉形式。只创建对恢复上下文、核验来源或形成结论有帮助的中间产物。

追求以下结果：

- 研究对象和用户真正关心的问题一致；
- 现象、分类、转变或设计背后的原因得到解释；
- 来源事实、直接观察、综合推论和作者判断没有混淆；
- 文章由核心论证推进，而不是由材料和术语堆成目录；
- 文字、案例、表格和图都带来信息增量。

## 研究原则

### 对齐真正的问题

开始深入研究前，弄清楚要解释什么、研究结果用来做什么、写给谁，以及哪些相邻问题不在本次范围。只有歧义会实质改变研究对象或结论时才停下来询问；其余情况采用最小、可说明的假设继续。

可以从具体问题提炼通用课题，但始终保留它与原始问题的联系。用户已经给出的范围、主结构和用途是约束，不要在搜索过程中静默换题。

### 用第一性原理重建“为什么”

不要把流行术语、社区分类、时间线或现成框架直接当成研究结论。从对象的基础能力与环境、参与者的目标和实际约束出发，解释困难如何催生机制，机制带来什么能力或结果，又暴露什么新限制。

下面是一条思考线索，不是必须逐项填写的模板：

```text
基础能力与环境
→ 目标、约束或矛盾
→ 产生的机制、做法或设计
→ 获得的能力、结果与代价
→ 新限制、分化或后续演进
```

研究现状版图时，用共同目标、约束和机制解释类别为何分化；研究历史时，解释阶段之间为什么发生转变；研究设计时，说明选择回应了什么问题并产生什么价值。允许非线性、多因素和仍未解释的部分。

把因果关系当作待验证的解释。时间先后、维护者叙事和技术上的可能性都不能单独证明因果；检查关键反例、替代解释和证据缺口，避免事后编出一条过于顺滑的故事。

### 让证据只承担它支持的命题

对关键结论保持三个判断：

- 来源实际支持哪一句话，不能支持什么；
- 当前拿到的是来源陈述、直接观察、跨来源综合还是作者判断；
- 结论是否需要进一步检查源码、原始数据、运行产物或实际案例。

不要求机械标注每句话，也不规定固定的来源组合或台账格式。来源的选择服从问题：产品机制可查官方材料和源码，实际行为可查运行时、数据和测试，领域演进可结合各阶段的一手材料与同期实践。

研究工具或系统时，必要时追到真实触发方式、作用范围、输入输出和证据上限。静态配置或代码具备某项能力，不等于一次运行真的使用了它；没有观察到某行为通常表示未知。

在证据已经足以回答当前问题、关键张力已经检查、剩余缺口已经明确后停止扩搜。不要用来源数量代替证据充分性。

### 从案例得到可迁移理解

用具体案例看清机制，再判断结论能否推广。单个仓库、项目或实验可以提供实例、反例或机制线索，不能自动代表整个领域。

当文章提出因果解释、效果判断或工程方法时，按主张风险选择足够的检验方式，例如对照案例、历史事件、真实运行或反例。是否需要正式回测、做到什么程度，由问题的重要性和可用证据决定。

## 从研究形成文章

### 让结构服从论证

先形成核心主张和主要推导，再决定目录。服从用户已经确定的文章结构；没有既定结构时，选择最适合当前问题的组织方式，不套固定题型。

每一节都应推进一个独有的读者问题，并说明它与前后论点的关系。框架、分类和原则如果来自跨来源综合，应让读者看得出其推导依据，不要伪装成外部共识。

长段落或章节逻辑不清时，先用三句话以内说出它真正的核心命题和因果关系。现文无法让读者得到同一结论时，围绕主张重写，而不是局部替换措辞。

### 保持信息增量和读者独立性

- 只保留能增加机制、边界、取舍或理解的内容；
- 面向外部读者时，介绍清楚案例和必要背景，不依赖会话或当前仓库的隐含上下文；
- 使用自然、具体的词，必要的抽象概念在首次出现时给出明确指代；
- 删除常识性总结、重复结构、无独有信息的表格、虚构的读者误解和低价值元话语；
- 克制使用“不是……而是……”；只有真实存在的误解值得对照；
- 连续正文只按语义结构换行，不按固定列宽机械折行；
- 让引用紧邻它支持的命题，不用窄证据支撑更宏观的结论。

研究笔记可以保存来源、推导、冲突和未知；读者文章只保留服务主论点的材料。两者是否拆成不同文件，由任务规模决定。

### 让视觉承担推理

只在视觉能让复杂关系更容易理解和检查时使用图表。有效的图应明确表达实体、关系、层级、映射或阶段变化，并在正文中得到解释；装饰性图片和正文复刻没有必要。

根据关系选择表格、Mermaid、SVG 或生成式插图。需要精确结构和文字时优先使用可控媒介。制作后实际检查标签、关系、纵横比和阅读尺寸。

### 正确吸收反馈

把用户纠正视为对研究问题、证据、逻辑、读者假设或表达的反馈。检查它是否影响上游判断和其他段落，不要只修被点名的一句话。一次性的项目纠偏只约束当前任务；反复出现或用户明确要求长期保留的偏好，才进入通用规则。

## 长任务

短任务直接在上下文中完成。只有在研究跨会话、可能发生上下文压缩、需要交接或用户要求保留过程时，才建立持久工作区。

保存足以恢复工作的内容即可：

- 当前研究问题、范围和用户已经确认的关键决定；
- 关键来源及其实际支持与限制；
- 当前综合、主要张力、未知和下一步；
- 中间产物与最终产物的位置。

文件名、数量和格式由任务决定。需要一个轻量起点时，读取 `references/working-set-templates.md`；它是可删改的参考，不是交付清单。

## 交付前

用少量问题做最终判断：

- 产物是否回答了用户真正的问题；
- 核心结论是否解释了“为什么”，而不只是罗列“有什么”；
- 关键事实、因果推导和作者判断是否各自在证据边界内；
- 每一节和每个视觉是否有独立信息价值；
- 目标读者能否在没有会话背景的情况下理解文章。

交付时只说明有用的研究边界、仍未解决的问题和产物位置，不复述整套工作过程。
