证据性质可以在笔记中用简短前缀表示：

- `[SC]` 来源正文、表格或图中直接报告；
- `[O]` Agent 直接检查源码、原始数据、日志、运行产物，或独立复算/复现实验；
- `[I]` 受限推论；
- `[S]` 跨来源综合；
- `[J]` 作者判断。

标签用于作者自检，不要求机械写进正文。

## 论证骨架

题型只决定文章如何组织，不替代上面的第一性原理推导。

选择：现状版图型 / 历史演进型 / 决策型 / 机制比较型

### 现状版图型

1. 共同对象与目标：
2. 决定性的环境与约束：

4. 由机制推出的类别与分支：
5. 各类获得的能力、代价与适用条件：
6. 尚未覆盖的空白与可能变化：

### 历史演进型

1. 阶段起点的能力与环境：

4. 出现的新机制：
5. 新获得的能力：
6. 新限制：

### 决策型

1. 待完成的任务或风险：

## Feedback ledger

```md
# Feedback ledger

| 时间 | 用户原话 | 类型 | 暴露的上游问题 | 受影响产物 | 形成的可复用规则 | 状态 |
|---|---|---|---|---|---|---|
|  |  | 事实/范围/逻辑/读者/语言/版式/视觉 |  | brief/sources/map/draft/visual |  | open/done |
```

一次反馈可能影响全文。例如“这只是常识”通常不只是删一句话，还要检查：

- 该段有没有说明新机制；
- 相邻段落是否也只复述表面现象；
- 标题是否承诺了比正文更多的解释；
- 引用是否被用来装饰常识；
- 是否应该删除整段而不是换个说法。
