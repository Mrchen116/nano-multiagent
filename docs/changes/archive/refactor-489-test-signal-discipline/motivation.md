无。

> 好，新建一个unit。不单要做清理，还要从impl worker写测试用的规范入手，改规范

## 澄清记录

- Q1: 这一个 unit 是否应直接清理全部“有充分证据无回归价值”的存量测试，并同步改造 worker 测试规范；对于价值不明确但可能有风险的测试，只产出逐项处置清单、不在本 unit 擅自删除？
  A(原话): 清理 + 重构吧。有的适合直接删了，有的测试可能要改掉，合并，之类的。目的就是去除无用的，但要做到真实保护。
  Agent 解读: 本 unit 同时处理高确定性删除、可证明等价的改写或合并，并以真实回归保护为完成标准；不以删测数量为目标。
- Q2: 你是否希望把这条变成 `change-impl-worker` 的长期硬要求——当实现路径或测试边界变化时，worker 必须先审视现有测试，并对每个受影响测试明确作出“保留、改写/合并、删除”的决定及依据？
  A(原话): 对
  Agent 解读: 这不是一次性清债；worker 的测试规范必须在未来变更中要求显式的存量测试处置决定。
- Q3: 本 unit 是否覆盖 Python、前端 Vitest、测试辅助脚本和 CI 中的质量检查，统一按“真实保护”标准清理？
  A(原话): 对。
  Agent 解读: 审视范围是所有已提交的自动化测试与测试质量门禁；一次性手工验收记录不视作永久测试资产。

## 现状痛点

当前测试体系已经同时出现两类相反的问题：一部分测试把提示词措辞、文档句子、历史文件名、被删除的
内部符号或一次重构过程当作永久 CI 契约；另一部分真正覆盖进程、会话、用户界面和产品入口的测试又存在
跨层重复、过大文件或时序不稳定的风险。

前者会在没有产品回归时制造红灯，阻碍正常重构；后者则让真正的行为保护难以识别和维护。实施 worker 虽然
已有“不要测实现细节、不要留下临时验收测试”的原则，但没有要求其在路径变化时系统地审视和处置存量测试，
导致坏样本会被持续复制。

## 目标状态

测试套件只为真实且可回归的产品、公开接口、运维或架构边界服务。每项永久自动化测试都能说明它保护的行为、
选择的最低验证层和长期保留理由；没有这种理由的测试被删除，或被合并、改写为更直接的行为保护。

`change-impl-worker` 将测试视为持续维护的回归资产：当实现路径或测试边界变化时，先识别已有覆盖，再明确
保留、改写/合并或删除的决定及依据；交付证据同时说明真实入口保护仍然存在。

## 用户侧验收标准（不变性）

本次是开发质量改造，不新增终端产品功能。用户继续使用既有 CLI、个人助手和 IM 行为时，结果与变更前一致；
维护者获得的是更可信的 CI 信号和更可维护的回归保护。

### Requirement: 无产品回归的维护改动不被历史测试噪声阻塞

#### Scenario: 维护者等价重构提示、文档或内部组织
- **WHEN** 维护者没有改变产品、公开接口、运维或架构边界的真实契约
- **THEN** CI 不会仅因历史措辞、文件名、已退役实现或一次性迁移基线而失败

### Requirement: 真实用户与系统行为继续受到最低层的有效保护

#### Scenario: 维护者改变既有产品路径或公开边界
- **WHEN** 变更会影响用户可见行为、公开接口、运维结果或架构依赖边界
- **THEN** 套件保留或建立直接覆盖该风险的自动化保护，并避免由更高层重复断言同一行为

#### Scenario: 维护者运行已清理的全套门禁
- **WHEN** Python、前端、测试辅助脚本和 CI 质量检查运行
- **THEN** 每个失败都能指向仍存在的真实风险或可执行质量规则，而不是历史实现细节

### Requirement: 实施 worker 持续维护测试资产

#### Scenario: worker 改变实现路径或测试边界
- **WHEN** worker 规划或完成一个 milestone
- **THEN** worker 明确审视受影响的存量测试并记录保留、改写/合并或删除的依据
- **AND** worker 为保留的用户、接口、运维或架构风险提供最低层的真实回归保护

## 影响范围

- Python 测试、前端 Vitest、测试辅助脚本和 CI 测试质量门禁。
- `docs/development/testing.md` 与 `change-impl-worker` 的长期测试规范和交付要求。
- 已提交测试的组织、重叠覆盖和稳定性；不改变产品功能目标。

## 迁移与回滚策略

- 按可证明的风险簇逐步删除、合并或改写测试；每一簇先确认留下的真实保护，再移除冗余或历史断言。
- 对有真实风险但当前不稳定或层级不当的测试，先稳定、降层或调整运行门禁，不以删除掩盖风险。
- 每一步运行对应最低层验证与完整 CI；任一保护缺口可单独回退该簇的提交，不影响产品数据或运行时状态。
