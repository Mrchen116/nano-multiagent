## 按 Skill 归并的调整建议

1. **change-orchestrator-simple**：主 Agent 默认承担实施与集成，不机械按模块开 worker；需要时派发一个具体独立子任务。合并一批相关修复，在固定版本上审查。复用已有测试结果时记录版本和命令，避免每个角色全部重跑。
2. **change-design-reviewer**：只对实质设计变化复审。涉及 SDK/内核时，在现有审查内明确比较“复用既有消息入口”与“新增内核机制”，检查责任归属，不只检查 import 合法性。
3. **change-code-review / change-verifier**：保留独立性，但允许同一个独立 Agent 完成代码、契约、delta 的统一审查；候选核验针对确有不确定性的具体发现，不默认把所有修复再交一轮第三方。此建议需要调整现有门禁规则，不能假装当前规则已经允许全部合并。
4. **change-reviewer**：保留真实产品验收；集中环境准备，失败只复测受影响路径，避免每次小修重走全部旅程。
5. **所有复审角色**：纯格式、记录归档、无行为变化的收尾由主 Agent 校验。原审查结论按未受影响的范围保留；不要因为提交号变化就机械全量复审。

对这类跨包改动，建议默认组织为：主 Agent 设计与实施 → 一位独立静态审查者 → 一位真实产品验收者。是否增加实施 worker 或第二审查者由独立工作量、风险与具体争议决定，不规定固定人数。
