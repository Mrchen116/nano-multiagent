# gateway routing-delivery delta — refactor-564

保留 feat-563 的「Agent 获得执行环境与用户界面的背景」「当前会话的 Agent 图片回复具有统一交付语义」全部要求和Scenario。其 relay-protocol 与 im/web-chat-ux delta 原样继续适用；本文件仅替换失败反馈要求。

## MODIFIED Requirements

### Requirement: 图片发送结果能指导 Agent 恢复

#### Scenario: 普通回复被拦截
- **WHEN** 普通回复因图片问题而未发送
- **THEN** Agent 得到真实系统来源的内部反馈，明确该草稿未送达而此前成功消息仍可见，并在原会话修正或如实说明未完成；反馈不冒充真人消息、不显示为用户正文，不要求保持原run id。

#### Scenario: 显式发送被拦截
- **WHEN** send_message 因图片问题而未发送
- **THEN** 工具返回简短的未发送事实、原因和修正方向，不返回成功，不向用户发布内部错误正文；已有新输入拦截反馈保持，不再额外产生一份普通回复反馈。

#### Scenario: 重试与部分完成
- **WHEN** 已准备图文的投递回执丢失或仅部分渠道成功
- **THEN** 继续恢复时复用原交付身份与已知回执，不重复投递已成功渠道，不向 Agent 谎称所有收件人都未收到；无法确认时保留未确认状态。

#### Scenario: 有限修正与停止
- **WHEN** 图片持续不能交付或用户停止/重置
- **THEN** 同一请求不会无限自启动模型修正；持续失败时转为文字说明或如实未完成终态，不能强行发布失败草稿；停止/重置撤销未准入的自动反馈，后续真人消息可以开启新的请求。
