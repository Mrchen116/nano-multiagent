## 现状痛点

## 目标状态

逐项审计上述用例及对应低层保护；能够确定性验证的全部改为受控 provider 或合并进已有低层测试，重复失败原因只留最低有效层。默认关键路径回归无需付费模型或本地代理。真实 IM、Node/DSH、公开协议、持久化和进程恢复的接线风险仍由合适层保护。模型理解能力不再冒充系统机制验收。

## 用户侧验收标准（不变性）

无产品用户面变更：只修改测试、测试夹具、测试入口及开发文档，不修改 apps/packages 产品行为、生产模型配置或部署。Full 零用户面，采用独立 code review + verification；不另做产品 reviewer。

## 影响范围

所有 tests/e2e 用例（32 项的逐项处置），scripts/e2e-critical.sh、相关 recording fixtures、测试清单和开发指南；若同一风险已在 TS 测试覆盖则复用并验证。不运行付费模型测试，不扩大到无关产品改造。

## 迁移与回滚策略

先建立或确认替代保护，再删除旧测试；处置表记录旧测试到新保护及实际命令。保持真进程与公开 API seam，不用伪造产品状态完成断言。回滚为 revert 本 unit 的测试变更，无生产数据迁移。
