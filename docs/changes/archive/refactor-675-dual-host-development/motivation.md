# refactor-675: Air 与 Mini 同时开发

## 原始诉求

> 我想在mac mini那边也用agent进行本项目的开发，有什么不合适的地方吗，是不是当前的skill不太适配

> 回到一开始的问题，如果后面我长期两台机子都会在开发，甚至在一些agent云端电脑也进行开发。我们当前的体系有什么要调整。我可以固定部署在这台air进行

## 澄清记录

- 关于「把首文档、设计直接提交到 main」：用户说「这个我是希望可以不带来编号的混乱，而且我一般spec，design & 开发 会在一台机子，所以不会不同机子抢吧」。
- 关于「先让 Mini 的生产目录独立出来」：用户说「同意」。
- 关于「共用一套 skill，机器差异放在本机配置里」：用户说「同意」。
- 关于「让测试环境和证据能跨机器使用」：用户说「这个感觉有点复杂，你能协助一次搞好？先让air和mini能同时开发。飞书这个更麻烦，只能air用这个号。mini后面如果有需要，再开一个bot，这样是不是简单了。」
- 关于「Air 部署只接收明确版本，不接收开发现场」：用户说「这个好说，现在我也是手工认为main应该部署更新，才在air启动部署」。

Agent 解读：本次完成 Air/Mini 开发隔离和本机配置；保留 spec/design 推送 main、同一 unit 通常在同机完成、用户在 Air 手动发起部署。飞书测试号仅 Air 使用，Mini 不复制其凭据。云端适配、跨机任务调度与证据平台不在本次范围。

## 现状痛点

- 2026-10-28 只读核验：Mini 生产 SHA 为 `4cea0166d70a604da6a7dcea9246d81e37b1e1bb`，IM/Gateway cwd 与 CLI 位于开发主仓，IM 数据库和上传目录也在该仓 `data/`；Tunnel plist 使用主仓 `.venv/bin/python`。开发切换、构建或清理可能影响生产。来源：现场 plist、launcher、Git；当前操作契约见 [prod-fleet](../../../operations/prod-fleet.md)。
- `scripts/e2e-up.sh` 会重建目标目录的测试数据库，尚无生产目录拒绝检查。默认 Gateway 配置指向 `127.0.0.1:4000`；Mini 已验证的模型地址为 `100.88.34.122:4000`。
- [LLM 联调](../../../development/llm-integration.md) 和 AGENTS.md 的日志定位绑定 Air。共享 skill 本身可复用，但缺少本机资源入口。
- 编号脚本锁定 Git common dir，只保证同一个 clone 的并发唯一。不同需求在两机同时取号仍可能撞号；同一 unit 的各阶段同机不构成此冲突。

## 目标状态

- 两台机器都能运行相同开发流程；开发与生产 checkout、持久数据和运行依赖隔离。
- 本机设置提供可发现的测试入口、日志位置与能力；仓库维护一套 skill 和无密钥示例。
- 保留整数编号与首文档/设计直推 main；新建前同步，推送冲突时核对编号，先成功推送的占用编号，不覆盖远端。
- 现有飞书验收固定在 Air；Mini 可完成开发与普通隔离 E2E，涉及飞书时在 Air 对同一代码版本验收。
- Mini 迁移保持当前生产版本、身份、密钥和历史数据；后续升级仍由用户明确发起。

## 用户侧验收标准（不变性）

本次没有产品 UI、Agent 工具或业务行为变更，开发工具的真实运行与生产迁移核对作为实施标准交给 design/verifier；不新增产品旅程。

### Requirement: 开发不会替换生产现场

#### Scenario: 两台机器分别进行开发
- **WHEN** 用户在 Air 和 Mini 的开发 checkout 安装依赖、构建、切换任务分支或启动隔离测试
- **THEN** 生产仍使用其固定版本与持久数据，现有账号和节点身份保持不变。

### Requirement: 飞书测试身份不被两机争用

#### Scenario: Mini 需要飞书验收
- **WHEN** Mini 开发的任务需要使用现有测试 Bot
- **THEN** 验收移交 Air 对明确代码版本执行；Mini 不启动该 Bot 的监听器，也不复制其凭据。

### Requirement: 手动部署与既有业务行为保持

#### Scenario: 完成开发或合并代码
- **WHEN** 任一机器完成开发或代码合入 main
- **THEN** 不自动部署；用户仍在 Air 明确发起更新，既有消息、附件、设备绑定与生产版本不因开发完成而改变。

## 影响范围

开发文档、共享工作流 skill 的环境入口与编号约定、E2E 启停入口、本机开发配置；Mini 生产 checkout、IM 数据路径与服务启动引用。无业务运行时代码、协议、云端平台或安装包发布变化。

## 迁移与回滚策略

Mini 采用同 SHA 路径迁移，先准备独立 checkout 与依赖，再在有限停写窗口复制数据库/附件并切换服务。原路径及受保护备份保留至核验通过，失败恢复原启动引用与迁移前数据；不能丢弃新路径已接受的写入。具体执行、恢复和有限验证在设计的部署提示词维护。
