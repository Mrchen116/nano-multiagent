# Gateway Task Graphs Specification (delta for refactor-679)

## MODIFIED Requirements

### Requirement: 停止后的上下文同步 SHALL 不自行启动执行

#### Scenario: 停止通知延迟消费
- WHEN 真人 /stop 已中断并持久暂停作用范围内的 Task
- THEN 将可信停止事实持久投递到下一模型步骤，但解除停止保护、通知本身和停止前积压输入不触发新的模型请求。
- AND 后续有效新输入或调度触发时一并读取；旧答复不能恢复 paused，明确的新恢复或新责任不会被待处理通知阻挡。
- AND 停止引发的同一 Agent 任务消息只同步上下文，不自行唤醒；重启后最新未消费的可信停止事实仍在下一次有效唤醒中可见，已消费事实不重复注入。

#### Scenario: 外部变更与离线恢复
- WHEN 人或 Agent 修改正文、责任、状态或关系，删除任务，或系统因群解散／成员资格变化收缩任务处理资格
- THEN 受影响 Agent 通过对应所属聊天系统消息在最近下一模型步骤获知业务变化，不为同一事实另生成一份私下责任快照。
- AND 消息明确任务及可用详情入口，要求变化时提示读取最新正文；失去访问资格的主体只获得必要撤销事实，不获取失权内容。
- AND 离线期间任务已撤回，恢复后首个有效输入也能消费尚未消费的撤回消息；空闲且无可执行任务时不为同步单独启动。
- AND 连接就绪或当前责任查询成功不代替业务消息追平；尚未完成必要同步时不沿旧责任推进，已注入但尚未消费的失权内容不会随新输入进入模型。

#### Scenario: 内部对象重建而事实未变
- WHEN 内部对象释放重建或宿主丢失上次展示记录，但任务事实未变且模型已有信息仍有效
- THEN 不据此生成新的 Task 提醒或重复消息；执行确因中断而需继续时仍按正常续跑规则处理。

### Requirement: waiting SHALL 关联有效原生安排并允许主动恢复

#### Scenario: 首次等待及校验失败
- WHEN Agent 已完成必要提问或交办并核实实际送达，为无可执行下一步的任务建立安排后提交 waiting
- THEN 系统核实真实安排的负责人、根会话、启用及未来执行有效性，成功后原子保存等待原因及关联。
- AND 无效或无法核实则明确拒绝并保留原状态；未获送达确认不能声称正在等用户答复；不设最少交互轮数或独立阻塞审核模型。

#### Scenario: 安静等待与安排失效
- WHEN 没有 doing 且所有 waiting 均有有效安排
- THEN Task 允许暂时空闲，其他 doing 存在时仍继续工作；关联后来失效须触发处理或明确显示运行限制，不静默失联或重复刷屏。

#### Scenario: 关联 Schedule 被删除
- WHEN 用户或 Agent 删除 Schedule 后，具体 Task 仍为 waiting 且没有有效的关联安排
- THEN Agent 获得指出该 Task 标题、唯一标识、所属聊天与入口的 reminder，说明无法按原计划唤醒，要求检查是否已结束、能继续则推进、仍需等待则建立新的有效检查。
- AND 此 Task reminder 不因删除者是 Agent 而省略，不能由删除工具回执或 Schedule 自身变化通知代替；删除不会仅因 waiting 引用被拒绝，提醒不自动改变 Task 状态。
- AND 多项受影响任务逐项可定位，已经换用有效安排或离开 waiting 的任务不再要求修复；未知检查结果不冒充确认删除。

#### Scenario: 提前答复与定时复查
- WHEN 相关答复、协作结果或定时提醒实际到达
- THEN Agent 读取当前状态与外部事实判断是否恢复 doing，重新考虑阻塞必要性和授权内替代路径；定时到期不是授权或默认同意，仍需等待时先安排有效的下一次检查，间隔按任务判断且不超过一小时。
- AND 离开 waiting 清除关联，旧定时输入不能重新打开 paused、closed、done 或 in_review；同一正常到期已安排复查处理时不另加一轮相同原因的修复催促。

## ADDED Requirements

### Requirement: 自动续跑 SHALL 包含必要行动规则及当前本人任务概要

#### Scenario: 一轮结束仍有可执行责任
- WHEN 主会话按现有任务续跑条件继续执行
- THEN 获得全部本人 doing／waiting 概要、任务详情与讨论入口，以及核对当前事实、取得并验证进展、完成前检查整个目标的必要指导。
- AND 等待前核实阻塞及实际送达、尝试授权内替代办法并建立有效检查；其他 doing 继续，暂停和被拒绝动作的限制保留，提醒不构成新授权。
- AND 普通新消息与无变化内部重建不因此追加整份续跑 prompt，任务正文和历史讨论按需读取。

### Requirement: Task 操作成功后 SHALL 提醒具体任务的实际交付

#### Scenario: 保存等待说明或提交结果
- WHEN Agent 成功登记 waiting 或提交 in_review／done 的任务结果
- THEN 提醒明确本次任务和固定所属聊天；waiting 说明实际进展、阻塞、已尝试路径、需要谁提供什么及下次检查，in_review／done 交付核验后的成果。
- AND Global 根 Agent 实际发送到该聊天，内部 child 向父 Agent 汇报并附固定聊天，由根 Agent 公开交付；不因最近处理其他聊天而改变目标，不用任务系统消息或私有结束语冒充成果交付。

#### Scenario: 续期、回执重放与发送未确认
- WHEN 相同反馈已确认送达、无新内容续期、回执重放或发送失败／未知
- THEN 先核对较新状态及消息，已确认内容不重复发送，失败／未知如实处理；不撤销已保存 waiting 或删除有效 Schedule，其他可执行责任继续。


## ADDED Requirements — 用户验收修复

### Requirement: 后台 Task 故障只在影响当前工作时进入上下文

#### Scenario: 普通输入不受后台故障影响
- **WHEN** 普通输入没有已知受影响任务或待消费 Task 原文，后台同步/查询不可用
- **THEN** 不追加 Task 故障提示；实际工具调用失败在结果中说明。

#### Scenario: 具体受影响对象及去重
- **WHEN** 当前任务或待消费原文确实受影响
- **THEN** 限制只列具体对象，同一可见限制不逐步重复，也不因内部对象重建重发；未核实的原文不投递、旧状态不驱动自动续跑，独立已授权工作可继续。
