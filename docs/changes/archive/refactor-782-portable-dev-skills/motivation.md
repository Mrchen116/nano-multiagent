# refactor-782 可编辑的跨仓开发 skills

## 原始诉求

“能快速在新的仓库用上，包括现有的仓库，不是要搞一堆前置操作”
“包括本仓也要用你做出来的通用的这个版本，而不是原来的”
“我开发过程发现问题，直接改skill提commit，push就迭代完成了”

## 对齐结果

在每个开发环境安装一次，从一份可编辑的 Git checkout 加载。迁移 20 个开发 skill 和一个显式调用的研究工具，三个 Nano 专用 skill 与产品运行时资产归项目。用户要求最终实测选简单任务并用 Sol。

### Requirement: 开发者能沿用现有技能
#### Scenario: 新老仓库使用
已安装环境中直接点名 skill 或使用统一入口，仓库不必初始化。Nano 沿用既有分支、验收与交付约定。
#### Scenario: 现场改进
在业务仓库对话中定位并修改独立库源码，正常 commit 和 push。新会话能使用修订后的版本。
