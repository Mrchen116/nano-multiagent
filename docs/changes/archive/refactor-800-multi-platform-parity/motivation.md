## 原始诉求

> 我们现在有很多个不同的平台、不同的端：
> - Windows
> - Mac
> - Linux
> - Web
> - iOS
>
> 不同的端除了一些端特有的功能，我们其实整体上是希望它功能完全一致的，体验上是完全一致的。
>
> 但是我们现在端又很多，所以开发代码时候很容易agent就会遗漏掉。我们怎么能够加一些测试，或者说什么形式验证之类的，能够去确保我们最后做出来的每一个合入之后，每多端的体验都是一致的呢？
>
> 当然不一定是测试或者形式化验证，也有可能是说是代码架构，或者其他方式。

> 第一层这个会不会导致性能问题？比如im服务带宽压力？比如原本桌面端看本地轨迹是直连本地的。我不知道是否会受影响

## 现状痛点

核对基线：`origin/develop`（`3b4c0f022`）及近期 GitHub Actions 实际运行记录。

1. **五端横跨两条正交轴，存在三处高频跨语言与跨系统分叉裂缝**
   - **Web / Desktop WebView（TypeScript）vs 原生 iOS（Swift）**：Web 与 Desktop 主窗口共享 [`src/IM/frontend`](../../../src/IM/frontend/README.md)，但原生 iPhone 客户端 [`src/IM/ios`](../../../src/IM/ios/README.md) 独立维护 SwiftUI 模型、会话列表、未读汇总、权限按钮与消息呈现，极易出现双端规则漂移（如 `1a7edfcbd` 修复的 Web 与 iOS 默认身份头像不一致）。
   - **Web 前端（TypeScript）vs Desktop 常驻宿主（Rust）**：Desktop 为支持关窗常驻与开机静默自启通知，在 Rust 宿主独立解析用户事件流计算未读角标与系统弹窗，刚交付即发生群话题通知、卡片回复与外链处理同 Web IM 不一致（`2cc0e9dec`）。
   - **macOS vs Windows vs Linux 本机节点（Node / Host）**：[`apps/node`](../../../SPEC.md) 在三类系统上分别对接不同进程生命周期、本地通信管道与文件系统语义，常规单测仅在 Linux 运行时易漏掉平台差异（如 `7497544b5` 修复的 Windows 目录 `fsync` 报错）。

2. **共享协议跨语言手写镜像，漏字段或漏新状态不会在编译期暴露**
   - [`packages/product-contracts`](../../../SPEC.md) 仅约束 TypeScript 调用方；iOS 的 Swift 模型与 Desktop 宿主的 Rust 结构均靠人工同步镜像，且客户端存在可选字段缺省与默认通配分支。后端新增状态、消息块或操作约束时，漏改端照常编译通过，直到用户实际触发才暴露空白内容或异常状态。

3. **现有流程与 CI 存在“彻底忘改某端反而绿灯放行”的门禁盲区**
   - 现行 [`.github/workflows/ci.yml`](../../../.github/workflows/ci.yml) 的 `ios_changes` 仅在 diff 命中 `src/IM/ios/`（及极少数固定文件）时才执行 `ios` 检查。当 Agent 修改共享协议、`im-server` 或 Web 功能却彻底遗忘 `src/IM/ios/` 时，CI 跳过 iOS 并绿灯放行。
   - [前端体验与验收规范](../../development/frontend-experience.md) 允许共享业务优先在 Web 实测以控制模拟器成本，但缺少设计期与代码期的逐端对齐核对门禁，容易被开发 Agent 误作“无需核对其他端代码”。

4. **远端 CI 历史耗时已达 11~17 分钟，存在重复编译浪费，不能粗暴叠加重型多端任务**
   - 抽样近期 PR 运行记录（Run `45936537506`、`45934680777`、`45936537584`、`45936537490`、`45934320101`）：
     - **`CI` 未触发 iOS 时总墙钟 11.2~11.3 分钟**：`TypeScript backend and tooling` 耗时 **672~689s**（其中串行 `pnpm test` 占 **573~587s**），`Frontend checks` 仅 **131~213s**。
     - **`CI` 触发 iOS 时总墙钟 14.8~17.3 分钟**：`iOS build and tests` 耗时 **871s（14.5 分钟）**——无编译缓存；[`src/IM/ios/scripts/build.sh`](../../../src/IM/ios/scripts/build.sh) 先冷编译并启动模拟器跑 UI 测试耗时 **482s（8.0 分钟）**，紧接着 `archive` 又从零二次编译前端交互包与 Release 真机归档耗时 **288s（4.8 分钟）**。
     - **并行候选工作流耗时较短**：`Windows installer candidate` 约 **200s（3.3 分钟）**，`Desktop client candidates` 缓存命中时 Mac **226s（3.8 分钟）**、Windows **372s（6.2 分钟）**。

## 目标状态

把“多端体验与行为一致”从依赖开发 Agent 记忆，转变为**架构少分叉 + 编译器防漏状态 + 共享考卷锁细节 + 并行快检防忘改**的四重确定性保障：

1. **设计点名与 PR 漏端对称拦截（防“整端彻底忘改”）**
   - 正式变更在本仓设计阶段显式逐行确认五端（Web、Desktop macOS、Desktop Windows、iOS，以及 macOS / Windows / Linux 后台节点）属于“复用共享实现自动生效”、“需同步端侧实现”还是“既定产品边界豁免”。
   - 本仓自动化检查扫描变更范围：当修改共享协议、公共 IM 契约或共享前端业务功能而未同步受影响端（且无显式合规豁免说明）时，在合入前直接阻断并提示遗漏端；纯单端样式修复或既定端特有能力凭明确说明正常放行。
   - 节点与宿主涉及操作系统差异的底层能力（文件原子替换/同步、单实例锁、进程收拢、本地通信管道与环境变量传递）收拢至明确的平台适配边界，并在 Linux、macOS、Windows 三套系统上运行轻量契约测试。

2. **单一契约跨语言生成与穷尽检查底座（防“改了但漏字段/漏新状态”）**
   - 以 `packages/product-contracts` 为唯一权威源，建立向 iOS（Swift）与 Desktop 宿主（Rust）自动派生共享协议类型的生成与零差异校验机制。
   - 对核心共享状态与类型枚举消除客户端业务分发处的默认通配兜底，使新增协议变体在任一端未处理时直接触发编译或静态检查报错。

3. **控制面单一权威与跨端黄金测试向量底座（防“两边都写了但细节打架”，且零性能回退）**
   - **控制面收拢**：将易漂移的低频控制面判定（先行打通通知触发与摘要语义样板，并确立操作可用性下发模式）收归 `im-server` 单一计算，复用现有查询内存上下文、不引入额外数据库往返，高频流式增量帧不附带冗余信息。
   - **数据面与高频交互留本地**：Desktop 本机原生轨迹与本地工作区文件直读、各端零延迟输入与离线缓存继续 100% 本地运行；对必须在各端本地执行的纯逻辑建立 `src/IM/shared/` 跨语言黄金测试向量运行底座，先行在会话未读汇总与消息时间线分隔规则上实现 Web/Desktop 与 iOS 共用同一套用例断言。

4. **分层快检与 iOS 重复编译治理（多端门禁零增时，常规 iOS PR 更快）**
   - 静态对称检查、契约生成校验与三系统底层窄测试全部控制在数秒至数分钟内并行完成，不拉长常规 PR 的总墙钟等待时间。
   - 将 iOS CI 拆分为「快速编译与纯内存契约/向量单测门禁」和「重型模拟器 UI 测试 / Release 真机归档门禁」：共享契约或跨端向量变更触发快速门禁即可在并行窗口内验证 iOS 一致性；耗时近 5 分钟的二次 Release 真机归档仅在涉及 iOS 工程打包配置、发布脚本或主干/发版路径时运行，不再拖慢普通开发 PR。

## 用户侧验收标准（不变性）

本次重构既面向在各设备日常协作的终端用户（确保跨端体验对齐且不破坏任何本地直连与响应速度），也面向在仓库内推进需求的开发者与 Agent（确保漏端在合入前被快速、准确拦截）。

### Requirement: 同一账号在 Web、Desktop 与 iOS 上的通知、未读与核心状态体验保持一致

#### Scenario: 群聊、话题与待处理事项的通知和未读汇总跨端一致
- **GIVEN** 同一账号同时使用 Web、Desktop（macOS 或 Windows）与 iOS 客户端
- **WHEN** 会话内产生新消息、群话题回复、卡片动作回复、`@提及` 或待决权限请求，且部分会话或话题处于静音或未关注状态
- **THEN** 各端展示的未读计数变化、是否触发提醒及点击提醒到达的目标位置保持一致，静音会话与未关注话题不会在桌面常驻后台误触发提醒。[Web 聊天体验](../../specs/im/web-chat-ux.md) · [iOS 客户端契约](../../specs/im/ios-client.md) · [Desktop 客户端契约](../../specs/im/desktop-client.md)

#### Scenario: 核心状态展示与消息时间线阅读规则跨端一致
- **WHEN** 用户在 Web、Desktop 与 iOS 查看同一批会话列表、消息时间分隔、默认身份形象及助手运行/停用状态
- **THEN** 会话排序、时间分隔合并、身份视觉与可执行状态反馈与既有契约一致，新增共享状态不会在某一端呈现为空白或无响应控件。[会话与消息契约](../../specs/im/conversations-messages.md) · [助手与节点契约](../../specs/im/agents-nodes.md)

#### Scenario: 断网保态与切换账号或服务的数据隔离保持不变
- **WHEN** 用户在独立客户端断网打开聊天、切换登录账号或切换连接的 IM 服务地址
- **THEN** 本地已有内容呈现、短暂断网不误退登录以及跨账号/跨服务的数据隔离行为与变更前完全一致。[iOS 客户端契约](../../specs/im/ios-client.md) · [Desktop 客户端契约](../../specs/im/desktop-client.md)

### Requirement: 桌面本机直读优势与中心服务流式响应性能不受影响

#### Scenario: Desktop 查看本机助手原生轨迹与打开本地工作区文件继续直连本机
- **GIVEN** 当前电脑已绑定到当前登录账号，且目标助手运行在本机节点
- **WHEN** 用户在 Desktop 查看该助手的原生轨迹、超过中心同步上限的大体积工具输出，或在本地文件管理器中定位与打开工作区文件
- **THEN** 数据读取与文件打开仍直接在本机完成，不回退为中心服务中转，也不出现体积截断；查看远端节点助手时仍透明走中心通道。[Desktop 客户端契约](../../specs/im/desktop-client.md)

#### Scenario: 多会话读取与流式消息呈现保持原有流畅度
- **WHEN** 用户加载多会话列表或在会话中接收助手的流式回复
- **THEN** 列表展示与流式逐字更新体验与变更前一致，不会因通知或权限状态统一计算产生卡顿、丢字或重复提醒。

### Requirement: macOS、Windows 与 Linux 后台节点保持稳定运行与恢复语义

#### Scenario: 三类系统上的节点启停、单实例保护与断线恢复保持一致
- **WHEN** 用户或运维者在 macOS、Windows 或 Linux 上执行节点安装、启动、停止、重启、本地配置更新或经历网络中断后重连
- **THEN** 单实例互斥、文件与状态安全落盘、IM 自动重连恢复及 macOS / Windows 已启用的登录自启行为均与变更前一致；Linux 节点继续配合 Web IM 完成全部助手协作与管理。[Gateway 服务生命周期](../../specs/gateway/service-lifecycle.md)

### Requirement: 开发变更遗漏受影响端时在合入前被拦截，且不拖慢常规 CI 反馈

#### Scenario: 修改共享能力或共享协议但遗漏受影响端时检查失败
- **WHEN** 一次变更修改了跨端共享协议、核心状态枚举或公共客户端功能，但遗漏了受影响的原生端处理且未提供合规豁免说明
- **THEN** 仓库自动化检查在合入前明确失败，并指出未同步的平台或未处理的协议分支，不会因未触碰该端目录而跳过检查绿灯放行。

#### Scenario: 单端局部修复或既定端特有能力可凭明确说明正常通过
- **WHEN** 一次变更仅涉及单端局部样式/平台专属能力（如 Desktop 本机文件操作、iOS 个人签名维护，或 Linux 不设桌面安装包），并按约定声明平台影响范围
- **THEN** 自动化检查正常通过，不强制在无关端添加冗余改动。

#### Scenario: 常规 PR 检查总等待时间不增加且消除无关的重复真机归档编译
- **WHEN** 提交仅涉及后端、共享契约或常规 iOS 界面逻辑的 PR
- **THEN** 新增多端快检在并行时间窗内完成，不拉长常规 PR 总墙钟耗时；未触及打包发布配置的检查不再重复执行全量 Release 真机归档编译。

## 影响范围

- **在范围**：
  - **流程与对称门禁**：更新 [`docs/development/change-workflow.md`](../../development/change-workflow.md)、[`docs/development/frontend-experience.md`](../../development/frontend-experience.md) 及仓库检查脚本（`scripts/` 与 `tests/contract/`），落地五端对齐声明检查、平台适配层边界约束与 PR 漏端对称拦截。
  - **CI 快慢分层**：调整 [`.github/workflows/ci.yml`](../../../.github/workflows/ci.yml) 与相关候选工作流、[`src/IM/ios/scripts/build.sh`](../../../src/IM/ios/scripts/build.sh)，拆出 iOS 快速契约/单测门禁与重型 UI 模拟器 / Release 真机归档门禁，并在 Linux / macOS / Windows 并行任务中挂载节点底层系统适配窄测试。
  - **跨语言契约生成与穷尽检查底座**：基于 `packages/product-contracts` 建立面向 iOS Swift 与 Desktop Rust 的共享类型/枚举生成与无默认兜底校验，先行覆盖核心会话、消息、权限与助手生命周期状态枚举。
  - **控制面收拢与共享黄金测试向量先行样板**：在 `apps/im-server`、`apps/desktop`、`src/IM/frontend` 与 `src/IM/ios` 落地通知触发与摘要控制面收拢样板，并扩展 `src/IM/shared/` 跨端测试向量覆盖会话未读汇总与消息时间线分隔规则。
- **非目标（不在本次范围）**：
  - 修改外部通用独立库 `dev-workflow-skills`（所有五端范围约定、设计声明规则与自动化门禁均仅落在本仓文档、脚本与工作流中）。
  - 新建 Linux 桌面 GUI 客户端安装包或新增 Linux 系统级登录自启功能。
  - 在本 unit 内一次性推倒重写全仓所有历史存量页面的接口模型与本地逻辑（未在先行样板内的历史模块随后续需求触及时按新门禁渐进迁移）。
  - 对存量约 11.5 分钟的 Linux `backend` 全量测试套件做分片并行化改造（可独立立项推进）。
  - 修改 DSH 运行时边界或任何 Agent 模型可见的 Prompt、工具 Schema 与记忆上下文。

## 迁移与回滚策略

- **平滑演进与线上兼容**：跨语言生成模型与服务端新增控制面提示字段均保持现有线上 JSON 字段名、报文类型及缺省兼容语义；新服务端与已安装的旧版 iOS 客户端、Desktop 客户端及各平台后台节点分开升级时仍可正常互通，不涉及数据库破坏性变更或本地工作区数据迁移。
- **存量过渡规则**：门禁脚本对增量 diff 与先行已接入模块强制执行对称与穷尽检查，避免将未触及的历史存量一次性标红阻塞正常开发；后续任何触及共享能力的新需求均按五端对齐表渐进纳入共享契约与测试向量。
- **回滚策略**：门禁脚本、CI 工作流拆分、代码生成与先行样板分层清晰；若任一环节出现误拦截或兼容问题，可按批次独立回退对应提交，既有用户会话、节点身份与运行数据不受影响。
