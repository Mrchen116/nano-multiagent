## MODIFIED Requirements

### Requirement: Desktop 主窗口保持既有 IM 业务权限、原生通知直达与按服务及账号隔离

#### Scenario: 主窗口完整承载既有 IM 业务并支持原生通知直达
- **WHEN** 用户在 Crewden Desktop 主窗口操作聊天、渐进式任务、Agent Work、助手与外部通道设置、模型服务、电脑管理、账号及公司空间
- **THEN** 各项业务能力、访问权限、乐观锁与离线只读语义同既有 IM 契约一致；外部网站链接通过系统默认浏览器打开且不携带 IM 凭据
- **AND** 收到符合提醒资格的新消息（含外部渠道对端入站消息与已关注群话题回复，排除账号拥有者本人在外部渠道发出的镜像消息）、已静音会话中的明确 `@提及`、会话内待决工具权限审批或本人管理助手处于等待权限确认（`waiting_permission`）的 Work 更新时，应用图标/托盘按未静音会话汇总更新未读状态（随已读与静音变更实时同步），并在窗口未聚焦目标视图时弹出桌面通知（或发送系统原生通知）；点击通知唤醒主窗口并定位到目标聊天、对应群话题或助手 Work 入口；静音会话的非提及消息、权限结案回写与重连历史回放不弹出重复通知

#### Scenario: 官方与公网严格保持 HTTPS，受控支持私有化预设地址、内网 HTTP 与外部唤起切服确认
- **WHEN** 用户在服务切换栏输入，或通过外部唤起链接（含客户端冷启动、Windows 二次进程转发与 macOS 协议打开事件）传入官方域名或公网非私网地址的明文 `http://` 形式
- **THEN** 客户端拒绝切换至该不安全地址、保持当前已生效服务不变，并唤醒主窗口向用户明确提示官方及公网服务必须使用加密 `https://`（本机回环开发地址除外）
- **AND** 企业内部独立部署打包预设了默认内部 IM 地址与受信自托管发布源时，首次打开客户端默认连接该预设 IM 地址并支持从该受信源完成应用内受管更新；内网私网 `http://` 地址仅在严格满足 RFC1918/RFC4193 私网 IP 字面量或 `.local` 主机范围校验时允许接入
- **AND** 无论客户端处于未运行冷启动还是后台常驻状态，凡由外部唤起链接请求切换到与客户端当前已保存服务不同的新 IM 服务地址时，客户端唤醒主窗口并弹出服务切换确认提示（展示当前服务与目标服务地址；目标为明文内网 `http://` 时显著标示未加密风险），用户取消时保留原服务与会话不变，仅在确认后才执行切换

#### Scenario: 切换 IM 服务地址或账号时隔离数据，短暂断网不误退登录
- **WHEN** 用户重新打开客户端、切换账号或切换到另一 IM 服务地址
- **THEN** 重开时恢复上次有效会话与当前服务的待恢复发送记录；切换服务地址后，界面按服务隔离会话、草稿、受保护媒体与轨迹视图并保留原服务待恢复的未确认消息发送记录；退出或切换账号时清除上一账号在该服务下的本地数据，迟到的旧响应不会写回新语境
- **AND** 遇到短暂断网或服务暂时不可达时，保留已确认界面内容并展示重连状态，不退回登录页；仅当服务端明确拒绝凭据或账号停用时才清除内容并要求重新登录
