## MODIFIED Requirements

### Requirement: 前台提醒与后台限制明确
客户端 SHALL 在活跃时提供可关闭的前台轻提示，并与 Web 及 Desktop 遵循一致的提醒资格、目标跳转与未静音全局未读汇总语义；SHALL NOT 将免费个人签名描述成后台远程推送或持续运行保证。

#### Scenario: 实时消息、待决权限与历史重放
- **WHEN** 活跃 App 收到其他未静音聊天的新消息（含真人消息、Agent 回复及外部渠道对端入站消息）、已静音聊天中的明确 `@提及`、会话内待决工具权限请求，或本人管理助手处于等待权限确认的 Work 更新
- **THEN** 开启的轻提示默认不暴露消息正文，点击可分别定位对应聊天、所属群话题或该助手的 Work 视图；账号拥有者本人在外部渠道发出的镜像消息、已静音聊天的非提及消息以及历史补齐均不触发提醒。
- **AND** 底部聊天入口的总未读角标仅汇总未静音会话的未读数并随已读或静音变更同步更新，已静音会话在会话列表行内仍保留自身的未读计数与静音图标。

#### Scenario: 后台及安装帮助
- **WHEN** 用户查看帮助，或从后台、锁屏或被终止状态回到 App
- **THEN** 可理解后台新消息不保证系统推送，返回后能补齐历史；不要求通知权限才能聊天。
