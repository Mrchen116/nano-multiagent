## MODIFIED Requirements

### Requirement: Web 应用内新消息提醒按会话类型标识来源

Web IM SHALL 在会话外的提醒中按来源类型标识会话、群聊发送者或待确认的助手事项，并提供直达对应聊天、群话题或助手 Work 视图的操作。静音会话 SHALL NOT 弹出普通消息或常规完成提醒（包括页面处于后台时的浏览器系统通知），明确 `@提及` 当前用户的消息除外；外部渠道镜像会话中仅对端入站消息按普通新消息计入未读与提醒，账号拥有者本人在外部渠道发出的镜像消息 SHALL NOT 触发提醒或增加未读；会话内待决工具权限审批与本人管理助手处于等待权限确认（`waiting_permission`）的 Work 更新 SHALL 按同一受众资格触发提醒。桌面侧边导航与移动端底部聊天入口 SHALL 一致展示仅汇总未静音会话的未读总数，静音会话在其列表行内仍保留自身的未读数与静音标识。

#### Scenario: 私聊提醒沿用会话名并区分外部渠道发送方
- **WHEN** 用户在其他页面收到未静音真人、外部渠道对端入站或 Agent 私聊的新消息提醒
- **THEN** 弹窗显示该私聊的会话名，包括已保存的自定义名称，并展示消息摘要；账号拥有者本人在外部渠道发出的镜像消息不触发提醒且不计未读。

#### Scenario: 群聊、话题与待决权限提醒标识来源并直达目标视图
- **WHEN** 用户在其他页面收到未静音群聊（含已关注群话题）的新消息提醒、已静音会话中的明确 `@提及`、会话内待决工具权限请求，或本人管理助手处于等待权限确认的 Work 更新
- **THEN** 群聊提醒同时显示群名、发送者的可读名称和摘要（只有两个成员的群仍按群聊展示），权限提醒标识待确认工具或助手；点击提醒分别直达对应聊天、所属群话题或该助手的 Work 视图。
- **AND** 静音会话中的非提及消息在页面前台与后台均不弹出提醒，重连历史回放与权限结案回写不重复弹出提醒。

#### Scenario: 桌面与移动端聊天导航入口未读汇总排除静音会话并实时同步
- **WHEN** 用户同时拥有未静音会话和已静音会话的未读消息，或在任一端阅读消息、切换会话静音状态
- **THEN** 桌面与移动端的聊天主导航入口一致显示仅汇总未静音会话的未读总数并随已读或静音变更更新，不在其他主导航项重复叠加同一聊天未读数；会话列表中的已静音会话行继续显示其静音标识与未读计数。

#### Scenario: 纯 UI 新消息
- **WHEN** 用户在其他页面收到一条已交付的纯 UI 消息
- **THEN** 提醒使用本地化的「互动卡片」标签，并遵守既有来源显示、单次去重和静音过滤规则。

#### Scenario: 尚未加载聊天列表或名称暂不可得
- **WHEN** 用户停留在设置等页面时收到新消息或待决权限提醒
- **THEN** 不要求先打开聊天列表才能显示来源名称；名称暂不可得时显示可读通用称谓，不将内部 ID 作为名称兜底。
