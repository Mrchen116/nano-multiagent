# bugfix-356 spec-author 澄清记录 Q/A 必须原话

## 原始报告

> '/Users/czj/Repos/nano-multiagent/.claude/skills/change-spec-author/SKILL.md'用的时候经常出现spec skill，记录问答不老实的情况，他不原文记录我对他问题的答案，有时候他当时可能是误会了我意思，或者说我里面的回答有一些暗信息他没有 get 到，后面去做，进一步做 design 的时候。去读spec的时候，就会读不到我那些信息，从而导致了错误的设计。

## 澄清记录

- Q1: 这次修改本身的力度?
  A(原话): 你写的太多了，就这么小一个需求，要讲这么多东西吗？模型遵循能力其实是很好的，你要 言简意赅的把核心的东西表达出来就行了。不要写这么多。关键是你的表达是否精准。
  Agent 解读: SKILL.md 修订要极简——一条规则一句话,理由一句话,不堆例子不长篇说理。已据此压缩 §0 规则 2、§3.2、§6、§8。同时记入 feedback memory。

- Q2: 这次改动也立成 unit 吗?
  A(原话): 这次改动也算一个需求，做个极简的spec文档补充
  Agent 解读: 走 bugfix lite (fix.md),不升 full。

## 现象 / 复现

`change-spec-author` 跑澄清时,A 段把用户原话压成"实质内容"(例:用户答"只群聊吧。不过单聊以后要不要支持 @ 引用历史消息我还没想好,先不做" → 落盘成"A: 只群聊"),丢掉跑题/弱表达/边缘场景这类暗信号。design 阶段读 spec 时拿不到这些信号,做出错误设计。

## 根因

SKILL.md §3.2 原文明写"用户答的实质内容,不一定原文",等于授权 agent 改写。模型遵循了这条指令。

## 修复

`.claude/skills/change-spec-author/SKILL.md`:

- §0 加规则 2:"A 段粘原话,不准改写、概括、提炼;不确定理解先复述确认;agent 解读另起 `Agent 解读:` 分开"
- §3.2 把"答复实质,不一定原文"改成"粘原话",示例 A 段改为 `A(原话): ...`
- §6 反 anti-pattern 加一条"不要提炼实质"
- §5 完成判据加一条"A 段是原话不是概括"
- §8 示范片段同步

## 验证

下次走 spec 流程时,澄清记录 A 段应是 `A(原话): <用户怎么说就怎么粘>`,不再出现"实质内容"概括。
