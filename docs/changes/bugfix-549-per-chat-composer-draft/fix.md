# bugfix-549: 切换聊天后输入框草稿互相串

## Relations

- Related: refactor-482
- Closes: 无

## 原始报告

> 我发现在IM的一个chat写了一些东西还没发，切换到另一个chat，写的东西还在，这不合理。切回去了应该就是那边的输入框了，该是空就是空，切回来才应该还在

## 澄清记录

- Q1: 待发附件要不要也按会话隔离？比如在 A 贴了一张图还没发，切到 B，B 里应不应该还挂着这张图？
  A(原话): 对
  Agent 解读: 未发送文字和待发附件是同一份 composer 内容，都按会话隔离；切到没写过的会话应是空输入框、无待发附件，切回去才恢复该会话自己的文字和附件。

- 用户补充:
  A(原话): 不要为了问问题而问问题，显然的不用问
  Agent 解读: 其余按现有产品语义收口，不再追问。桌面/移动、单聊/群聊同一规则；`@mention` / slash 开着属于同一份未发送内容，跟着会话走。刷新或关掉页面不要求把草稿存下来。蒸馏预填仍写入目标会话的输入框。某个会话发送失败时，仍保留该会话自己的文字和附件以便重试，不得把这份内容带到别的会话。

## 现象 / 复现

Web IM 里，未发送的输入框内容和待发附件会跟着整页输入框走，而不是跟着当前会话。

**复现**

1. 打开会话 A，在输入框写一段还没发的文字（或贴一张待发图片）。
2. 切到另一个没写过的会话 B。
3. B 的输入框里仍是 A 刚写的内容（待发附件也还挂着）。
4. 若在 B 把这段改掉或清掉，再切回 A，A 也不是刚才那份了。

**期望**

- 切到 B：B 用自己的输入框。没写过就是空的，也没有 A 的待发附件。
- 切回 A：A 仍是刚才没发出去的文字和附件。
- 在 B 另写一份：两份互不影响。
- 发送成功只清掉当前会话这份；发送失败仍留在当前会话，方便就地重试。
- 蒸馏成功预填目标会话输入框的行为不变；预填进的是那个会话自己的内容，不会塞进别的会话。

## 根因

聊天页右侧 `MessagePane` 在切换 `/chat/:id` 时不卸载。未发送文字、`@mention` 元数据、待发附件、slash 收起态和发送中锁都活在这个组件自己的生命周期里，不跟会话走。

切会话时，`conversation.id` 变化只会清掉复制菜单这类消息操作态（feat-484），输入框这份状态故意没动。current spec 也没写「每个会话各自一份未发送内容」，所以没有切会话隔离测试。发送失败保留草稿（M154）测的是同一会话里重试，不是跨会话共用。未实施的 refactor-482 还把「切路由保留当前未提交 draft」写成了要保住的现状，等于把这次串会话当成正确行为往下传。

**原始意图与修复不变量**

- M154：发送/上传失败后，用户不用重新拼装这份草稿和附件，可以就地重试。修复后这条仍成立，但是「当前这个会话」的草稿，不是整页共用一份。
- 蒸馏：成功后新建执行会话并预填 prompt，用户按普通聊天继续发。修复后预填仍进入目标会话输入框。
- feat-484：切会话时进行中的复制操作作废。这条继续独立成立，不能为了修草稿把复制隔离拆掉。
- feat-469：切走之后才回来的上传失败，不得写进新打开的会话。这条继续成立。
