# bugfix-591: 安装包仅显式发布并使用版本号

## 原始报告

> 只有我要求的时候才发包，不是每次合并部署都更新，而且发包应该定版本号，现在雷霆长的随机数名字。

## 现象 / 复现

2026-10-13 合并并部署 PR #342 时，部署者依据 current `docs/operations/local-stack.md` 中“更新 IM 时同步发布对应的 Node 包”执行发布，产生 `Nano Node 8b023da56a5b45579b8a0a68463d953cf24d580c`。用户仅要求合并部署，没有单独要求发包。

本次修正的边界：普通合并、构建、部署不发布安装包、不切换线上已验证的安装清单；只有用户明确要求发包时才发布，使用明确填写的 `X.Y.Z` 版本号，Release/tag 为 `Nano Node vX.Y.Z` / `vX.Y.Z`。源码 SHA 仅用于固定构建和追溯。缺少版本号时不猜测、不自动递增。当前已发布的 SHA 版本继续可安装，不重命名或删除旧 Release。本次不执行发布、部署或修改线上清单。

## 根因

feat-588 的安装分发设计将完整 commit SHA 同时用作固定源码和用户可见版本，并要求 IM 部署携带同次发布的清单；该耦合进入操作规范，导致部署请求被解释为发包授权。工作流虽只有 `workflow_dispatch`，但没有显式版本输入；发布器、IM 清单校验和安装脚本都固定接受 40 位 SHA。

原功能意图是让 IM 指定经过验证的固定安装版本、包体从 GitHub 直下，并校验实际上传字节，避免 latest 漂移、覆盖既有版本或失败时破坏原安装。这些不变量必须保留。修复为单个 M1-fix，发布命名和已有安装入口同步调整；保留现有 SHA 清单仅为当前线上两份已发布包的实际兼容需要。
