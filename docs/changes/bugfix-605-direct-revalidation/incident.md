# bugfix-605: 全局 Agent 私聊发送前复核

## 原始报告与确认

> https://im.nanoim.win/chat/c_8wedfh29 去看下时间线，“之前的太不稳定了”发送的时候，agent的回答还没生成好吧，按我原本设计，不应该拦截他最新的发言，给他最新的消息，再重新发言吗

> 所以对应的修复是
>
> 1. 私聊也发送前复核
> 2. 不中英文混用
>
> 分别用快速修复的方式完成。

第二项独立记录为 bugfix-606；本项采用用户明确选择的快速开发方式。

## 现象与根因

2026-10-14 的飞书私聊 Web 镜像中，11:10:00 收到补充并在 14 毫秒后得到 Gateway 接收回执，11:10:40 才调用发送旧答；11:11:01 才读取补充，11:11:32 再补答。以上均为北京时间，来自生产持久消息、会话事件和 Agent 工作事件。

全局模式忙时保存消息至 Inbox，不硬中断工具；旧发送前复核仅覆盖内置 Web 群聊，明确排除了私聊及外部渠道。单纯取消群聊判断还不足以处理飞书与 Web 镜像不同的目标身份。

## 目标与边界

- 全局 Agent 向已有 Web 或飞书私聊投递前，发现目标尚未读取且需要处理的新输入，旧稿保持未发送。
- Agent 得到真实未发送反馈及待阅读 Inbox 来源，读取新输入后用新发送调用重新判断交付。
- 既有内置群复核、发送幂等、已发送消息、其他会话及背景输入规则保持；不硬中断当前工具。
- 本次修复当前故障的全局 Agent 显式发送路径，不改变 single_thread 的流式回复机制，也不扩展外部群聊复核。

## 验证与状态

保护最窄公开 seam 为 GlobalAgent.call(send_message)。扩展既有 global-agent.test.ts 群复核测试，参数化覆盖 Web 私聊、飞书直接目标、双向镜像别名；保留旧调用不可重发、读后新调用可发送、其他目标与背景输入不阻塞、身份隔离断言。修复前四个新增私聊场景均失败。

自动化检查和独立代码审查记录见 design.md 与 code-review.md。用户已确认修复意图，尚未亲自体验候选版本；unit 保留 active，未归档、未合并、未部署。自动化通过不冒充用户验收。
