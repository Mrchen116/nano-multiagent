# bugfix-611: 全局 Agent 空响应恢复原生重试

## 状态

快速开发；实现、适用本地测试和独立代码审查已完成。用户已确认方案，尚未亲自验收修改后的产品；unit 保持 active。

## 原始报告与澄清

用户在排查全局 Agent 读文件后无回复的执行后提出：

> 那我主张，直接按照DSH原本的设计，不接受这种情况，然后重试，可以不，然后再在全局模式的系统提示词要要求他结束输出一些东西？raft跟我们一样是inbox + send message模式，/Users/czj/Repos/opensource-hub/raft-source 他怎么设计的呢，先看看他的再决定

核对本地 Raft 后，用户确认：

> 可以，就按这个方案改，恢复 DSH 原生重试，全局提示词要求非空的内部收尾说明，走快修模式。

后续用户将过程沟通要求纳入同一快修：

> 那我们也加上这个要求：接到任务先通过 send_message 简短回应，长任务中间发必要的进度，别让用户一直等到最后。一起走这次快修。

## 现象与复现

全局 Agent 执行读取工具后，模型返回空内容，未调用 send_message。执行却以 completed 结束，用户未收到请求结果。原生 profile 回归用例可在最终请求返回 EMPTY_RESPONSE 时稳定重现：旧实现没有 llm/retry，直接完成。

## 影响范围

全局主 Agent 的普通模型请求。已通过 send_message 交付及无需公开更新的后台轮次也曾允许空内容结束；这些轮次现在需要非空内部收尾，不增加公开消息。单 Thread 和 child 的通信路径保持。

## 根因

DSH 已将空返回识别为 EMPTY_RESPONSE。Nano 的全局 llm/stream 中间件将这个错误无条件改写为 stop，没有检查是否实际交付，阻断了原生请求重试。旧提示词同时明确允许无正文结束。模型为何在本次请求生成空内容尚未确证；不将消息历史过滤假说当作根因。

## 修复方向与验收标准

- 移除全局空响应豁免，按 provider 的 DSH 原生策略重试，耗尽后报告失败。
- 全局提示词要求非空、简短的内部收尾，描述已投递结果、已说明阻塞或无需公开回复的原因。
- 内部收尾不代替 send_message；有请求待交付时继续工作，已经发送的结果不重复发送。
- 接到真人任务后，先向原会话显式发送简短确认和下一步，再深入调查或执行；长任务按必要进展更新，不等到最终结果才回应。用户明确要求不回复时遵循该要求。
- 确认与进度不等于最终交付；更新简短，不刷重复状态、工具日志或空闲消息。
- 后台无可行动更新时不向聊天发送额外消息。
- 不新增重试循环、公开消息兜底、交付判定状态机，不修改上游运行时。
