# bugfix-621: PA 飞书主人私聊与提醒恢复

## Relations

- Related: feat-616
- Related: bugfix-594

## 原始报告

> 为啥我飞书给PA发消息，没回应
>
> 而且原本定好的每天早上的定时任务，也没触发？没给我发消息
>
> 这个没问题，继续用这个逻辑，第一个收到消息的就是主人
>
> 就按这个设计修，在测试部署中，把飞书私聊收发和定时提醒都实际验通，别只看服务在线。

## 已确认范围

复用首次来信持久化的飞书主人绑定。主人和 PA 的飞书私聊与 Web 主人私聊同权；群聊不升级为主人私聊。回复和定时提醒发给已绑定主人时不走对外披露审查。保留其他收件人的既有审查、普通工具权限、同一个 PA 主会话和原渠道回复。修复旧输出阻塞新输入及重复接入。只部署隔离测试栈；生产更新和合并不包含在本次授权中。

## 现象与复现

2026-10-20 生产 a4c4b1b3：09:10 定时任务进入 PA 主会话，两次 send_message 均被隐私审查拒绝，理由是无法证明飞书收件人为主人。09:22 主人飞书来信已持久化并经 observation 进入主会话，但被标记 external，Agent 将其当背景事实且未回复。发送内容是普通文本，与 Intelligent UI 无关。

## 根因分析

feat-616 本来要让 PA 以主人身份边界处理个人数据与交办，同时审查对外披露。源角色判定在 6498814966 将所有带 sender_source_id 的消息排除出主人角色；原始授权查询仅支持 Web 主人私聊。外发实现对所有飞书目标统一审查，没有复用已存在的 app + owner_open_id + direct 判定。external 的 PA 入站先 await 混合输入镜像和输出投影的 flush；历史输出报错可以阻止后续直接接入。与此同时 observation 独立接入，形成双入口和不同消息 ID。生产 unsupported_message_type 的具体抛出路径尚不能仅凭旧日志确认；本次通过可控回归验证输出失败不再阻塞输入。

不变量：主人绑定不由模型或消息正文声明；非主人与群聊不能获得主人私聊权限；未知发送结果不自动重发。

## 验收

### Requirement: 主人私聊可交办

#### Scenario: 飞书主人来信
- GIVEN 已绑定主人的测试飞书 Bot 与正式 PA
- WHEN 主人在飞书私聊要求回复唯一测试标记并安排稍后的提醒
- THEN PA 在该飞书单聊回复，且可依据该原始消息执行交办
- AND Web 主人私聊仍可用，同一来信只处理一次

### Requirement: 主人提醒实际送达

#### Scenario: 到时主动提醒
- WHEN 上述一次性提醒到时
- THEN 同一 PA 主会话执行提醒，飞书原单聊收到唯一标记
- AND 有真实平台消息回执和平台消息读取证据

### Requirement: 失败隔离与权限不扩大

#### Scenario: 旧输出失败后的新来信
- GIVEN 旧输出投影失败
- WHEN 主人发送新消息
- THEN 新消息仍被 PA 接收并回复，恢复后不重复处理

#### Scenario: 非主人或群聊
- WHEN 非主人私聊或群聊成员自称主人，或 PA 向这些目标发送私人信息
- THEN 不获得主人私聊授权，保留既有输入与披露审查边界
