# bugfix-643: 后代历史投影导致 DSH 堆溢出

## 原始报告与范围

用户确认：

> 好，走快修模式，在worktree中修复

采用快速开发，在独立 worktree 修复已定位的历史加载峰值。当前状态为 active：代码已实现，尚未取得用户实际验收；未部署生产。

## 现象与复现

2026-10-23 Air 生产 DSH 多次在约 4 GiB 堆上限处退出，自动重启后再次失败。Gateway 保持连接不代表 runtime 可用。三个根执行已有 645 个后代，子会话日志包含继承历史，解压总量约 6.21 GB。

生产分配采样定位到 `session.descendants` 下的历史解压与解析；原始诊断与脱敏统计定位在本机 `/tmp/nano-air-oom-20261023/report.md`。调查未证明永久对象泄漏，也未证明全部历史 Agent 仍在执行。

## 根因

处理函数对全部后代使用 `Promise.all`，每个完整 observation 租约一直持有到异步工具展示数据读取结束。大量完整继承历史同时被 pin，缓存容量不能限制在途租约数量。完成的历史越多，跨 I/O 等待时堆峰值越大。此前单子会话功能回归未覆盖该压力组合。

## 修复目标与边界

逐个读取并释放完整 observation，只保留响应必需的自有事件。保持子执行身份、顺序、完整自有事件、cursor、workflow 关联及现有模型/工具展示语义。既有历史不删除、不重新执行。

本次不改变游标协议、不增加内存上限、不修改或 fork DSH，不扩展为全局 Agent 生命周期回收机制。单个巨大日志及全量响应仍有自身内存成本；本次消除的是同一请求中全量并行保留继承历史的放大。
