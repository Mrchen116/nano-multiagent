# Gateway Personal Agent — bugfix-678 Delta

Target: `docs/specs/gateway/personal-agent.md`

## ADDED Requirements

### Requirement: PA 输入审核以消息为独立准入单位

#### Scenario: 单条拒绝和技术失败
- **WHEN** 非主人 participant 消息被拒，或同一次审核经统一底层恢复仍失败
- **THEN** 只结算该条拒绝或故障；不撤销整个来源，不阻塞其他已准入消息，不把故障描述为安全拒绝。
- **AND** 主 PA 获得准确原因及消息引用；已报告失败不因启动、Inbox check/read 自动再次审核。

#### Scenario: 显式重审与恢复
- **WHEN** 主 PA 对故障消息显式请求重审，或节点恢复
- **THEN** 重审重新检查当前来源并执行同一审核，不允许直接设置 allow；重复终态不重审，未完成审核中断明确报错，消息状态和其他已准入输入保持。

### Requirement: 输入审核获得有界原始对话背景

#### Scenario: 连续对话与直接回复
- **WHEN** 审核一条外部消息
- **THEN** 提供完整当前消息、该消息之前最近 20 条原聊天消息，以及窗口外可访问的直接回复目标一次；保留真实发送者、顺序与来源，历史仅为证据。

#### Scenario: 超限和恢复
- **WHEN** 历史超预算、回复缺失或审核恢复
- **THEN** 从最旧历史整条省略并标明缺失；当前消息无法完整提供则明确失败；不加入待审消息之后的新消息或越权读取背景。

### Requirement: 外发审核凭证只随实际条件变化而失效

#### Scenario: 无关披露与时间经过
- **GIVEN** 精确动作已通过独立审核且尚未提交
- **WHEN** 另一动作先提交或经过超过 60 秒
- **THEN** 不因全局披露计数或时间经过强制重审；完整内容、受众、权限、来源、生命周期和一次性提交条件仍检查。

#### Scenario: 真实条件改变
- **WHEN** 新消息需要重新考虑动作，或内容、附件、受众、权限、主人授权及其他实际提交条件变化
- **THEN** 不直接发送，向 PA 返回未发送及具体变化原因；由 PA 决定后续，不自动重新审核后代发。
- **AND** 已提交或结果未知仍按原操作查询回执，不借旧凭证更换内容或重复执行。

### Requirement: 披露审核实际消费待发图片

#### Scenario: 授权图片与隐含私人信息
- **WHEN** PA 向他人发送支持范围内的图片
- **THEN** 审核模型实际收到冻结图片和正文、受众、原授权上下文，按完整内容判断；文字无敏感信息不代表图片可免审。
- **AND** 仅允许审核的同一字节内容发送，变化必须返回未发送并重新决策。

#### Scenario: 能力或材料不足
- **WHEN** 图片不可访问、格式/尺寸/数量超限、模型不支持或实际请求不能装入完整图片
- **THEN** 明确报告能力或处理故障，不以 URL、文件名、助手描述或占位文本代替看图，不声称主人未授权，不静默漏图放行。


### Requirement: 系统累计五次输入风险自动屏蔽联系人

#### Scenario: 阈值与去重
- **WHEN** 同一PA的同一可信联系人累计五条独立注入或恶意套话判定
- **THEN** 系统立即沿用现有黑名单屏蔽；前四条、重复投递、普通授权不足和技术故障不会触发该阈值，Agent不获得黑名单修改工具。

#### Scenario: 自动屏蔽通知
- **WHEN** 系统触发自动屏蔽
- **THEN** 主PA在主人专属私聊说明累计五次及已执行的屏蔽，真实回执确认送达；失败不回退屏蔽，暂停与恢复保留未完成事实，不重复发送，不要求向被屏蔽对象额外发信。
- **AND** 主人已解除时，迟到通知准确说明历史动作和当前已解除状态；来源失权不阻断系统动作告知，但不携带已不可访问的原文。

#### Scenario: 计数重置与升级
- **WHEN** 主人解除屏蔽或将事件标为误判
- **THEN** 解除后从零累计，误判事件退出当前计数；历史证据与回执保留，旧消息重投不重新计数，已生效屏蔽仍通过主人解除入口处理。
- **WHEN** 新规则启用或运行恢复
- **THEN** 新规则从启用后确认的风险开始累计，不追溯旧事件；新计数与自动触发事实跨重启保留。

## MODIFIED Requirements

### Requirement: 主 PA 执行安全事件的提醒与拒绝

#### Scenario: 风险处置
- **WHEN** 输入被判 deny 或带需处置 incident，且该事件未触发系统自动拉黑
- **THEN** 不把其准入为普通任务；系统持久提供事件事实给主 PA，PA 先向主人提醒，再通过正常发送工具向原聊天拒绝，后端不替 PA 写模板消息。
- **AND** 有限安全处置不授权转发私人资料、攻击原文或代表主人承诺；对外文案独立审核，只有真实回执才算送达。
- **AND** 同一联系人每条新拒绝消息均独立交付与处置；重复投递同一消息不重复处置，联系人摘要聚合不复用其他消息的提醒或拒绝回执。

#### Scenario: 自动拉黑通知例外
- **WHEN** 第五条风险输入触发系统自动拉黑
- **THEN** 主 PA 仅在主人专属私聊告知已执行的屏蔽及当前状态，不再向原聊天发送该事件的拒绝；该事件以真实主人通知回执为完成条件，不等待对方回执。
- **AND** 黑名单的私聊拒收与群聊风险提示立即生效，不依赖通知送达。

#### Scenario: 暂停与发送结果未知
- **WHEN** PA 暂停、处置中断或发送结果未知
- **THEN** 保留未完成事实，不启动用户停止的 PA；恢复先核已有回执，不重复确认送达的消息，不把未知结果当可安全重发。
