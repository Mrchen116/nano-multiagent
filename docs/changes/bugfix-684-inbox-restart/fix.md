# bugfix-684：重启后接续仍未读的首条私聊

## 原始报告

> 什么意思呀？不行就帮我解决呀！就如果有bug的话要解决呀！

官网 v1.0.2 新用户已绑定节点、创建 PA，只发送一条私聊，没有收到回复。用户不应靠再发一条来唤醒原消息。

## 现象 / 复现

在 a6769441e，新装节点曾遭遇公网心跳超时。重连后，第一条私聊的 Inbox 通知已进入原生会话。验收为调整网络而停止临时节点时，模型正在调用 inbox.check：调用被宿主拒绝，原生 turn/end 为 error，原消息仍未读。重启后节点和助手均在线，此通知没有再唤醒。此时间线不能归因为模型没有启动，或仅凭事后的 enabled 时间推定启用顺序错误。

## 根因

原通知已经获得持久接受序号，重复投递相同 ID 不会再次执行。67ee7b5474 引入的恢复逻辑只处理原生 interrupted（异常退出后补记的中断）。受管节点停机时，宿主先拒绝旧实例的回调，可能把正进行的读取记作普通 error；正常进入关机取消时又使用了与用户 /stop 相同的原因。两者都遗漏在未读通知恢复之外。

保留 Global Agent 的既有契约：只接续仍待处理的交办，保留原消息，按持久输入去重；显式停止、普通模型错误、已经完成或已经消费的消息不能因节点恢复而重跑。节点禁用和旧实例的执行隔离维持原义。
