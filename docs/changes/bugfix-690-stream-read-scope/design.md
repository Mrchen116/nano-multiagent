# bugfix-690 流式读取设计

本文在实现后整理。基线为 main `7e79e9b79`，代码和回归测试为 `b79f0d882`。

## 通知与存储

- Global 保留 product.cancel 的独立入口，仅对自己消费的事件、模型变更和状态通知查询绑定，仍优先使用 rootSessionId。单聊按 sessionId 主键读取一条绑定，再按当前 Agent 模式判定归属。
- 单聊仍对每帧检查会话是否曾接收群输入。NodeStore 用 SQLite 部分索引保存符合原群聊谓词的行，只取存在性。系统唤醒和同会话更早的群消息仍参与判断。
- 合并发送时按会话和逻辑轮次读取输入，保留原有的准入顺序与本轮自动任务判定。群聊发送前对新输入的复核、发送确认、补发与恢复使用原有持久事实。查询不引入进程内缓存。

## 存量库与回滚

首次打开已有节点库时 SQLite 为历史行建立两个索引，需要一次建索引的时间和空间。后续写入由 SQLite 维护。输入、绑定、投递表的记录和协议均未改写。回退代码后旧版本可继续打开同一数据库。无需单独部署迁移。
