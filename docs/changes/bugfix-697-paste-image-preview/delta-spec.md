# bugfix-697: Proposed specification delta

## `docs/specs/im/web-chat-ux.md`

将剪贴板图片待发场景补充为：粘贴后立即在输入容器内展示本地缩略图或固定尺寸占位；网络请求完成前已有对应可移除卡片，上传状态覆盖在缩略图上。输入和追加粘贴可继续，多图按粘贴顺序展示和发送。

将“图片被拒绝或上传失败”的旧表述（失败项不进入待发区）替换为：失败保留原卡片及本地预览，在卡片旁显示原因、适用重试/倒计时和移除动作；不再重复发全局上传错误通知。重试/成功原位更新，移除项不会被晚到结果重新加入。上传未完成时不发送，失败不得隐式丢弃；仅发送文字仍是明确操作，保留未发送附件。

## `docs/specs/im/conversations-messages.md`

普通图片上传场景补充：声明为现有支持图片类型的请求，其内容具有现有支持图片签名时，以探测到的实际类型存储；与声明不一致时同步校正附件 MIME 与文件名后缀，无需用户手动改名或转换。未知图片内容和不支持的 MIME 仍拒绝，保留既有访问、大小、容量和限流边界。

失败反馈场景补充：将不支持格式与无法识别的图片内容分别说明，不把所有 415 统一解释为格式不支持。
