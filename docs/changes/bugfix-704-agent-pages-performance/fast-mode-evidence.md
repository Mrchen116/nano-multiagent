# 快修阶段实现与验证记录

状态：未完成性能验收，未部署生产。此前 [design.md](design.md) 是提案，以下记录当前实际实现及未完成项；未经用户实际验收，不归档。

## 继续快修：首次可见与可操作

用户追加要求：配置页和工作页从打开到真实内容可用均不超过 1 秒；轨迹必须使用禅（nano-manager）的真实记录，并给出相同测试环境下的页面实测对照。以下为本轮实际实现，历史样本保留在后文，不作为本轮成绩。

- Agent 页面 HTML 使用已有 HttpOnly Cookie 验证当前会话，不消费或轮换 refresh token。HTML 带短期 access token 与通过原 API 鉴权取得的 contacts、saved settings、Work summary；只嵌入成功响应，JSON 转义 `<`，HTML `private, no-store` 且 `Vary: Cookie`。没有有效 Cookie 时仍走原登录恢复。客户端仅一次复用当前文档、同一 access token 的数据，五秒后不再消费；身份切换仍通过原 BroadcastChannel 清除旧状态。
- 配置的 `settings?view=saved` 只读已提交数据，永不启动能力检查，也不授予保存资格。新打开且身份/节点状态、配置版本仍匹配时，先编辑草稿，后台独立确认能力；确认失败保留可编辑草稿并提示重试。保存三处入口仍要求当前确认成功、无查询错误、无在途读取且满足既有版本/权限/operation 检查。断线、恢复及状态事件撤销初次草稿准入。
- Owner Work 与配置读取独立，预取与正式列表复用同一分页查询；从配置切换 Work 保留未提交草稿，隐藏的配置组件不再挂载 Work 或第二个轨迹查看器。保留原页签跳转、owner 生命周期按钮及聊天入口。
- 与 Agent 页面无关的 Chat、Task Graph、Models、Onboarding 按需加载；带内容 hash 的前端资源长期缓存，HTML 始终重新验证身份。
- 发现轨迹专用 `ws` 没有显式传入全局 HTTP/HTTPS agent，会绕过 `NODE_USE_ENV_PROXY` 所配置的代理；普通控制 relay 已显式传入该 agent。专用轨迹连接现采用相同通路。真实网络对照采用与生产相同的 Air 代理设置，但使用隔离 Mini IM、账户、端口和 Quick Tunnel。
- 配置检查清理失败新增 `cleanup_stage` 和 `error_code`，不放宽清理/保存保护。曾见目录已构建但清理失败使确认失败；不能把此现象与后续启动超时混为一个已解决根因。

真实数据副本保留禅会话 `3143edc8-1ead-48ce-b7ca-1da50a7233bb` 的压缩事件帧，只修改隔离身份头部；事件帧 727,064 B，SHA-256 `da493efb477b80e912086bbd6086e75eec230c8e021198018787b3fca53ddfe8`，解压约 2.82 MB。另复制两个真实子执行用于完整读取。中心复制该 Agent 的三个 session、六个 turn、343 项 Work。构造副本时一度错误合并压缩分帧，相关轨迹失败样本作废；未补齐真实子执行、未采用生产代理配置或与构建/测试重叠的样本也不作为最终性能验收。

### 最终页面实测（本轮有效对照）

**剩余耗时定位：**修后配置 navigation 首字节等待 1.587 / 1.184 / 1.043 秒，Work 为 1.389 / 0.637 / 1.296 秒；响应到字段/记录可见另约 59–151 毫秒。同版本同账户在 Mini 本机请求完整认证 HTML 的生成/响应为 1–4 毫秒。浏览器一次细分观察连接已复用，无新增 DNS/TLS，时间主要停在 requestStart 至 responseStart。由此能确认当前页面主要剩在公网首字节等待，尚未把它进一步归因到具体代理、Cloudflare 接入或跨境链路；不能声称数据库或渲染仍占数秒，也不能声称已解决具体网络根因。双 Quick Tunnel 均接入 LAX；改用 IPv4 连接器未带来稳定改善，未修改生产代理或 DNS。

轨迹最后两次节点日志：prepare 至 socket_open 分别 1.408 / 1.439 秒，runtime_ready 另 14 / 2 毫秒；ready 后 4.967 / 4.910 秒才收到第一条 session/list；约第 7.35 / 7.52 秒收到 session/follow，第 8.61 / 8.60 秒收到取首批的 next，首批 96,276 B 在 1–2 毫秒生成并交给 socket。下一次拉取分别约第 14.24 / 15.10 秒才抵达。证明运行时读取这份真实历史不是十几秒瓶颈，连接准备、协议串行往返和首批跨公网交付仍耗时；socket send 回调不等于浏览器已收到，不能将差值精确归因到某一网络段。

本轮最终回归：前端 54 项、服务端/Node 轨迹 32 项通过；受支持 Node 24 下原生配置检查 6 项通过，前端构建和后端类型检查通过。Node 25 下的配置检查失败不作为受支持运行时结论。初次 stream 同步复用在途配置确认，去除 contacts 重复读取和刚确认后的重复时区写入，均已包含在上述最终构建及回归。

身份边界补充：初始化原 BroadcastChannel 后才接纳 HTML 会话；登录/退出写入不含身份或凭据的变更时间。若当前文档下载期间另一页完成身份切换，拒绝旧 bootstrap，回到现有 Cookie 恢复，不复活旧账号。

## 实际实现

- 配置：已有确认值在普通后台读取时保持可编辑；读取期间单独阻止保存，断线、未确认和版本冲突保护仍生效。
- Work：Web 显式请求轮次摘要，展开轮次才请求该轮完整 items；旧接口缺省仍返回完整内容。保留工具计数及后台任务标题分类。向真实 fetch 传取消信号、合并事件刷新，兜底刷新由 3 秒改为 15 秒。**目前按轮次而非逐工具请求明细**，展开一个含大结果的轮次仍可能慢。
- 原生轨迹：follow 和历史 page 默认限制在最多 5 条消息窗口；合法 turnWindow 的下限同步调整，使用 DSH 的 hasMore/beforeSeq 继续翻页。已确认会话可先渲染最新窗口，再异步恢复原阅读位置，用户交互取消旧位置恢复；查看器按清单并行预加载必要组件。单帧分片等待仍有 DSH 上游缓冲的既有限制；跨帧积压满队列仍明确中断。旧 5 秒批次期限延长至 60 秒，握手及配对分别设置 12 秒和 15 秒超时。普通慢读与真正连续性中断不混为一谈。
- 可选 `NANO_TRAJECTORY_DIAGNOSTICS=1` 记录关联 ID、方法、耗时及字节数，不记录正文和票据。原生发布模块的版本 URL 与部署 manifest 一致时才可长期缓存；不匹配返回 404。

## 验证

使用 Air 上隔离 Gateway 和浏览器，Mini 独立端口 IM、独立测试账户和独立 Cloudflare Quick Tunnel 的 HTTPS/WSS，非生产隧道或生产数据库。用户指定的 nano-manager 真实轨迹通过隔离副本测试；原始事件压缩帧保留，副本头部改为隔离身份，测试节点可能向副本追加自身事件，副本约 504 行、解压约 2.82 MB。该链路形态接近生产，但 Quick Tunnel、测试身份和网络条件不等于生产命名隧道。

- 本机对同一真实轨迹，固定首屏窗口从约 3 MB 降至约 96 KB；模拟停顿 6 秒后可读取首批，原版本同类 5.5 秒实验报 slow_consumer。
- 网络测试中历史旧实现一次 `session/page` 返回约 2.59 MB；小页后其中一次约 0.90 MB，单个消息仍可很大。节点首批生成约 1–3 ms；一次 96 KB 批次节点发送回调约 2 ms。一次采样节点准备约 1.14 s 完成 socket 握手；其 ready 之后到收到浏览器第一个读取请求约 6.7 s，之后多次跨机往返。不能据此推断每段网络延时。
- 真实网页上曾观测 13 行轨迹首次可见约 15–17 s，后续一次从 13 行增至 22 行约 18–27 s；另一轮在 13.8 s 时仍未显示、24.1 s 时显示 13 行。加上并行组件预加载后连续两次分别 13.65 s、14.06 s 可见 13 行、无错误，样本过少且网络变化不能归因出预加载净收益。未达到提议的 5 s 目标；未完成足够样本的 p95，也不能声明“快速稳定”。一次节点侧轨迹 WebSocket 无法完成握手，加入超时以便中断重试，但握手故障的网络根因未证实。
- 工作页使用 20 轮、100 条工具、约 4 MB 的合成数据（隔离服务随后还含恢复的测试数据），同一次环境直接公网读取 3 次：summary 8,725 B，0.447–0.489 s；原完整接口 6,135,959 B，6.247–8.640 s。此为接口样本，不代表浏览器冷启动 p95 或生产测量。
- 追加页面显示对照：2026-11-03，同一台 Mini、同一临时 Cloudflare HTTPS 入口、同一隔离数据库和 Chrome 登录会话，分别运行生产原版 `70ee96ab7` 与候选 `9d87edbd8`。测试 Work 的 4 轮、146 项按 nano-manager 当时各项 payload 字节数构造约 3.78 MB 合成数据，节点离线。每次从浏览器重载计时到首批工作记录 `.im-work-turn` 出现：原版 11.967、7.516、6.665 s；候选 5.424、4.629、4.474 s，中位数分别 7.516、4.629 s。候选响应核实四轮均为 deferred。均为暖浏览器的少量样本，不代表在线节点场景或 p95。另对生产 nano-manager 原版直接重载两次为 5.603、4.513 s；不可与隔离候选作为严格成对对照。
- 配置页单次浏览器重新加载到字段可见可编辑约 7.1 s，未达到提议的 3 s 目标；后台刷新保留编辑及阻止保存由前端回归验证，网络下配置慢的节点启动/传输细分仍未查明。
- 配置页追加同环境对照：2026-11-03，Air 在线隔离节点、Mini 独立 IM、同一测试账户和数据库、同一临时 Cloudflare HTTPS 入口及暖 Chrome；重载开始计时，DOM 采样到显示名字段可见且可编辑。原版 `70ee96ab7` 三次 3.681、4.435、3.964 s，候选 `58f1b5c21` 三次 3.798、3.618、3.659 s，中位数分别 3.964、3.659 s。该测试使用隔离测试 agent，不是生产 nano-manager；重载调用返回后才开始采样，结果是采样上界。样本少，不能证明稳定提速。生产 nano-manager 实际重载测量在 60 s 内未确认可编辑，随后页面显示“刷新失败”，显示名字段禁用；不能推断始终禁用或将此次结果与隔离候选直接对比。
- 服务端、轨迹、静态资源相关回归 24 项，前端配置/Work 42 项通过；同一次独立审查的明确问题（跨帧无界积压、摘要标题、后台恢复覆盖用户位置和旧版本缓存污染）已修复并复审闭合。实际全历史完整性、大规模 burst、双机断网恢复、10 次冷暖样本、生产体验和用户验收仍未完成。

## 保留的风险

空闲超时是兜底，并非根治所有慢消费者；特别是大型单帧的分片等待期间，上游 DSH 订阅缓冲没有本项目可证明的严格字节上限。诊断数据表明剩余时间包括初始化与跨公网多次往返，但尚不能分别归因到具体代理、链路或浏览器阶段。不能只根据上述改动宣布三个页面已快速稳定加载。
