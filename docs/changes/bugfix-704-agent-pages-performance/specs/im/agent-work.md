# Work 与原生轨迹加载增量

### Requirement: 已保存工作记录独立于配置确认加载

#### Scenario: 直接打开 Work
- **WHEN** 用户打开工作页，包括配置能力暂不可确认时
- **THEN** 目标是在 1 秒内看到真实已保存的工作摘要；工作读取不等待配置或节点检查。
- **AND** 从配置切换工作后再返回，未提交草稿保留；隐藏的配置组件不重复读取轨迹。

#### Scenario: 配置了普通公网代理的节点读取轨迹
- **WHEN** 控制连接与轨迹专用 WebSocket 访问同一 IM
- **THEN** 两者采用相同的节点网络代理与直连规则，不因专用连接绕过代理而无限等待。

### Requirement: 工作概览按需读取完整过程

#### Scenario: 大量工具记录
- **WHEN** 用户打开含大工具结果的工作页
- **THEN** 首先可见真实的轮次摘要、状态和统计；展开时可以按需查看完整过程与工具参数、结果及来源，不因摘要省略而丢失。
- **AND** 刷新和切换视图保留阅读位置，失败时可重试，既有客户端完整读取契约不变。

### Requirement: 普通慢速传输不丢弃原生轨迹

#### Scenario: 大型历史及短暂缓慢读取
- **WHEN** 用户读取跨多个批次的主或子执行，并在正常网络延迟或短暂停顿后继续
- **THEN** 可按真实顺序继续检查完整历史及新增事实，不因固定短期限误报慢消费者。
- **AND** 源真实溢出或断线时状态和恢复边界明确；身份失效、离开或取消后释放资源且不改变执行。
