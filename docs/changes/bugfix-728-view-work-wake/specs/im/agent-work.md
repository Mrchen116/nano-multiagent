# IM agent-work Specification (delta for bugfix-728)

## ADDED Requirements

### Requirement: Web 回复的 View Work 定位实际发信唤醒

#### Scenario: 同一 Agent 的多次同名唤醒分别发信
- **GIVEN** 同一 Global Agent 的多个唤醒分别发出聊天回复，且实际发信关联已保存
- **WHEN** 用户点击某条回复的 View Work
- **THEN** 进入该 Agent 的完整 Work，自动定位并展开实际产生该回复的唤醒，按需显示其完整执行与工具记录；不会因唤醒同名而混淆。
- **AND** 消息锚点仅决定自动展开和滚动位置，不筛选、截去或替换其他轮次；列表保留正常最新优先顺序与更早记录的分页可达性。点击较早A仍保留较新B，点击B仍保留A；未命中的记录不要求自动展开。

#### Scenario: 再次查看较早回复
- **WHEN** 用户重复点击较早回复的 View Work，包括其唤醒已不在最新一页时
- **THEN** 沿正常完整列表自动加载摘要页至目标并展开，不需要用户逐页寻找；已加载的较新记录不丢弃，可以继续查看更早记录或回到最新轮次。
- **AND** 回复属于已保留的历史主执行时，在其关联执行面板定位，不替换当前主执行列表。

#### Scenario: 定位后继续阅读与切换视图
- **GIVEN** 回复对应轮次已自动定位，用户随后折叠该轮或阅读其他位置
- **WHEN** 用户在同一Work内切换到原生轨迹再返回工作记录
- **THEN** 保留用户折叠状态与原阅读位置，不把内部视图切换误作新的回复定位；从聊天再次进入或改点另一回复时仍应用相应定位。

#### Scenario: 关联尚未同步或不可用
- **WHEN** 用户打开回复的 Work，但尚无可证实的发信关联
- **THEN** 明确提示该回复的工作记录尚未同步或不可用，不以时间、同名标题或其他轮次猜测关联；已有 Work 仍可读取。
- **AND** 后续同步取得真实关联后可完成定位，仍遵守既有 Work 资格和来源聊天权限。
