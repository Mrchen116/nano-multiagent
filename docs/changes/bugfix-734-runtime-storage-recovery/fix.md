## 现象 / 复现

Air 上的「禅」在 2026-11-09 10:23 和 10:24 收到两条交办。IM 已确认投递，Inbox 仍未消费。原生会话第 266、267 轮均在模型调用前因同一个模型运行记录临时文件的 `ENOSPC` 结束。检查时已有约 21 GiB 可用，工具记录观察也仍抛出原先的写盘错误。

验收时在隔离运行时让模型和工具记录写入暂时返回 `ENOSPC`，再恢复可写。后续执行和 Work 读取应继续，已接收且因写入失败在模型调用前中止的交办应自动重新唤醒，用户无需重发。保持现有会话和投递去重语义。

## 根因

Nano 的模型运行记录写入保存第一次异常，随后所有写入都在访问存储前抛出该异常。工具记录则继续把操作接在一个已经拒绝的 Promise 上。两条链路都没有机会重新写入。模型的 pre-step 需要持久化成功才继续，Work 观察同样依赖工具记录。已投递的 Inbox 唤醒在本次故障中以错误结束，现有恢复只重试已中断的唤醒。

[备用模型契约](../../specs/gateway/agent-capabilities.md)依赖已持久化的轮次证据，[Global 输入恢复契约](../../specs/gateway/global-agent.md)要求保留未读输入及稳定身份。恢复需要保住落盘检查，并以原生证据区分尚未进入模型的失败唤醒和可能已经执行的工作。
