# bugfix-736: Web 聊天打开后保持在最新消息

## Relations

- Related: feat-617

## 原始报告

> 为啥我点进去不是在最底下，而是在中间。很不舒服

原报告附普通 Web 会话链接，此处省略私有会话标识。

## 现象 / 复现

在生产 Chrome 新标签直接打开报告的普通会话，最新消息已加载，视口仍距底部约 700 CSS 像素，最新消息不在视口内。隔离 Chromium 使用真实 Web 消息列表和合成交互卡片，卡片加载完成后消息列表增高 1,274 像素，滚动位置保持不动。

预期：普通打开会话时定位到最新消息；卡片等内容稍后展开时，已经在看最新消息的视口继续贴底。用户向上翻看、加载更早记录或显式定位指定消息时，保留原有的历史定位语义。范围仅限 Web。

## 根因

消息列表只在消息数据更新时执行贴底。feat-617 的 Web 交互卡片按需加载渲染器，再异步读取交互状态并展示完整内容；这个过程只改变布局高度，不更新消息列表数据，原有贴底逻辑没有收到信号。不能通过取消按需加载或强制覆盖历史阅读位置来修复。

## 本次审查安排

用合成卡片控制异步展开时序，在真实 Chromium 检查桌面和窄屏贴底、主动上翻保持位置；复用现有历史分页及消息定位测试。独立代码审查核对滚动条件与 Web 契约。
