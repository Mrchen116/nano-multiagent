# bugfix-744：进程重启后让主 Agent 在下一轮看到子 Agent 中断

## 原始报告

> 我觉得不需要真的恢复子agent，只需要保证子agent挂了这个信息能传到主agent，他就能决策恢复

> 我觉得不是唤醒主agent，而是有新的触发的时候唤醒，这这是一条排队消息放着。理解不

## 现象 / 复现

共享 DSH 进程异常退出并重启后，Global 主 Agent 能继续使用原会话，Work 能读回中断的子执行，主 Agent 下一次因正常输入运行时却看不到这些子执行的中断通知。11 月 9 日生产现场的 714、716、720 均有未封口的子轮次，恢复后的 Work 已补齐显示，原父会话空闲。

重启时，把有持久证据的直接委派中断作为系统消息放进 Global 主会话的待处理队列。只有正常触发才能启动下一轮，届时主 Agent 一并读取通知并自行决定如何处理原委派。重复重启只保留同一中断的一份通知。正常结束、显式停止和缺少中断证据的会话不能被报告为进程中断。

## 根因

DSH 在在线子 Agent 结算时向在线直接父级发送 `subagent-settled`。进程级退出跳过该路径。SessionQuery 冷读会为未封口的轮次合成中断事件，Work 恢复只将事实同步到记录；Global Inbox 恢复以已存在的 Inbox 输入为依据，子执行中断没有进入主会话。应保留原生正常结算、Work 冷读和 Global 已有触发语义。
