# bugfix-755 合盖断网后保留在途 Agent 轮次

## 现象 / 复现

运行中的 Nano Agent 在短暂断线后可能自行完成。隔离 DSH 的模型连接持续失败时，默认五次重试耗尽后，原轮次以 `TRANSPORT` 错误结束。此后即使进程 PID 不变、模型连接恢复，原轮次也没有新的请求。716 的历史现场在合盖前已因部署停服中断，验证的是 #744 的进程退出通知路径。

只要原进程还存活，模型服务暂时无法建立连接时，主 Agent 和各级子 Agent 保留各自原轮次，连接恢复后自动继续。用户仍可停止等待中的轮次。已完成工具结果保留。进程退出后沿用 #744 的中断通知。已连上后发生的流错误以及供应商返回的鉴权、限流、配置等错误沿用原策略。

## 根因

DSH 的普通 provider 重试默认有次数上限。传输适配器把建连失败和部分响应流中断都汇总为 `TRANSPORT`，该错误参与普通重试预算，预算耗尽会结束该轮次。IM 重连和冷启动恢复分别管理消息传输和已退出进程的持久状态。Codex 源码 `8fdf647295` 对有证据的 `ConnectionFailed` 单独等待，普通流重试仍有界。Nano 集成使用锁定 DSH 的公开扩展点。

## 本次审查安排

| 必须回答的问题 | 能力 | 验证方法 |
|---|---|---|
| 主 Agent 与嵌套子 Agent 无需新输入即可继续原轮次，已完成工具结果保留 | 代码审查、真实 DSH 进程验证 | 用本地模型端口制造建连失败并恢复，核对 PID、session、turn 和模型请求 |
| 取消、流中断、正常供应商错误和进程退出各自保持原语义 | 代码审查、回归 | 核对普通预算和既有 #744 强杀重启测试 |

## 修复

Nano 在既有模型 HTTP 接入点保留请求级建连失败信号，由绑定主 Agent 和各级工作子 Agent 的公开 `agent/request-error` 钩子在原模型步骤等待并重试。Air 本机模型代理会为上游建连失败返回带 `upstream_connection_error` 和 `ConnectError` 或 `ConnectTimeout` 的 502，三种模型协议均只将这类明确报告的代理错误纳入等待。等待从 5 秒按倍数退避，单次最长 60 秒，独立于普通流重试额度，随原轮次取消。DSH 仍执行原步骤、结算工具结果和管理重启恢复。
