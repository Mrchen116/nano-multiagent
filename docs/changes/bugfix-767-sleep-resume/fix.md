# bugfix-767 合盖联网后自动继续原任务

## 原始需求

> 那就把这个缺口修掉，主 Agent 和各级子 Agent 都要保证合盖后开盖联网能自动继续原任务，补上对应验证，提交 PR。

## 现象 / 复现

#755 的恢复目标仍适用：Gateway/DSH 进程存活时，主 Agent 与各级子 Agent 保留原任务和已完成工具结果，合盖断网后开盖联网无需新消息自动继续，用户可取消。进程退出沿用既有恢复路径。

生产 Air 会话 `3143edc8-1ead-48ce-b7ca-1da50a7233bb` 第 412 轮在 2026-11-14 00:04 至 02:33（北京时间）经历模型流空闲超时与代理 `502 ConnectError` 交替。系统电源日志显示此前 11 月 13 日 22:06 合盖休眠，随后多次短暂唤醒与超时同秒出现。该轮普通超时重试耗尽后失败，网络恢复也不能继续。后台子会话 `347e4415-02a9-4cfe-b6c9-3ac2b7c5abec` 同样失败。

## 根因

现有持续等待只识别 HTTP 建连错误与代理明确报告的上游连接错误。合盖可能让已发出的请求停滞，适配器输出 TIMEOUT，进入 DSH 有限重试预算。休眠的持续时间与短暂唤醒使错误交替出现，最终结束原轮次。#755 的确定性回归仅覆盖建连失败，未覆盖挂起流与进程暂停恢复。

## 本次审查安排

独立代码审查检查主/各级子 Agent 接线、退避和取消、完成工具结果保留及最终契约。扩展真实 DSH 的现有连接恢复测试，覆盖挂起流超时超过普通额度、连接错误交替、暂停/恢复后原轮完成，并保留普通服务错误和退出恢复回归。确定性进程暂停与实体合盖分别记录验证边界。
