# 工作状态恢复与隔离

本文为快修后的实现记录。

- Node 与 DSH 的双向 JSON-RPC 以行为边界。序列化一帧后转义 U+2028 和 U+2029，读端解析回原字符。工具输出、事件分页、检查点与历史内容继续使用原有格式。
- 后台目录补齐最多同时处理两个不同根，同根请求仍合并。一个根等待完整历史时，另一个可继续；原有逐页读取及 stdio 背压继续限制每页生成和传输。
- GlobalAgent 分别追踪主轨迹和子执行的恢复。InboxStore 保留原有持久化 pending 标记，进程内记住已确认只剩子执行的根。进程重启后必须重新核实。尚待定位的根会话或尚待写入的事实均保持保守。
- WorkSync 仅在有待处理或待上传记录时附带按 Agent 的进度。每个可确认的范围带上该 Agent 的最高已生成日志序号；只有子执行仍在恢复时，仅声明主执行已就绪。最高序号通过原有 journal_root_agent 索引读取。
- IM 将进度绑定在当前已鉴权的 Gateway 连接和日志上。中心已确认对应序号后才显示相应状态。没有范围声明时继续使用整机进度，断线继续使用离线语义。超出报头预算时仍可继续传输历史。
- 头像弹窗仍立即显示，每行在原位置转圈，获得可信主状态和子执行计数后分别显示。派工图使用所属 Agent 的完整性。
- 无需数据库迁移。回退会恢复之前的进度判断和 RPC 编码；已补齐的检查点和投影可继续读取。

验证定位见 [incident](incident.md) 及 [review](review.md)。
