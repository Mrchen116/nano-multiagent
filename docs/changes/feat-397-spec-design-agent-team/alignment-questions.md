## A. 需要你拍板的（spec 级，决定用户可观察行为）

### D1 — 轻 brief 入口长什么样？
**推荐**：自由文本，不强制模板；可夹带链接、截图路径、"参考某产品"。系统的活儿就是把你没说的部分靠"自主澄清 + 自主研究 + 价值岔路升级"补齐，而不是逼你填表。
**理由**：你原话就是"简单沟通一下需求"。强制模板等于把对齐负担又推回给你，与目标相悖。
**牵动**：spec.DRAFT R1。

### D2 — 系统回来找你，走哪个通道？
**推荐**：走你已有的 **IM / personal-assistant 通道**——让 spec/design team 的协调者以 agent 身份在 IM 里给你发"决策包"，你像回消息一样异步处理。文件（docs/changes 下）作为落盘备份。
**理由**：你已经有 IM + Gateway + agent 身份这套基础设施，天然适合异步推送+回复；不必新造交互面。这也呼应你"群聊/单聊"的最初设想——但用途是**人机异步对话**，不是 agent 互相辩论（后者被研究证明是陷阱）。
**牵动**：spec.DRAFT R4；这是个真选择，你也可能更想要"纯文件、我自己去看"，所以单列出来。

### D3 — "价值岔路"（该升级问你）怎么界定？
**推荐**：满足任一即升级，否则自动决并记录理由——
  1. 有多个合理选项，且对**产品/用户体验**影响显著；
  2. 与既定原则（constitution / AGENTS.md）冲突；
  3. 不可逆或高成本（改了难回头）；
  4. 系统自评低置信。
**理由**：研究的落点就是"编译能编译的，escalate 不能编译的"。这 4 条把"通用最佳实践"留给自动、把"你的品味/产品判断"留给你。
**牵动**：spec.DRAFT R3。**请补充**：有没有"无论如何都必须问我"的红线类别（比如任何涉及付费/数据删除/对外接口的决策）？

### D4 — 打扰频率要不要设上限？
**推荐**：设 escalation rate 目标（例：一个变更单元里升级 ≤ 某个数；研究给的经验区间是 15–20%），超了系统要合并/降噪，而不是逐条弹。
**理由**：你要的是"少被打扰"。没有这个上限，系统会退化成"什么都问"，等于没解放你。
**牵动**：spec.DRAFT R3 的频率 Scenario。**请定**：你能接受的打扰频率直觉值（每个需求愿意被问几次？）。

### D5 — 评测先行，产出带"自评分"？
**推荐**：**是**，而且把"质量自评 rubric"作为本 unit 的第一块拼图。每个门禁的产出（spec / design）附一份自评分（完整性 / 一致性 / 可演进性 等维度），并**高亮薄弱处**，把你的审查注意力引到该看的地方。
**理由**：研究点名的最大风险是"没有可优化的目标函数"+ 用户头号抱怨"淹死在 markdown 海里"。自评分既给系统反馈闭环，又直接降低你 review 的工作量——正好服务"我回来尽可能少干活"。
**牵动**：spec.DRAFT R5。**注意**："可演进性"的全自动度量是研究空白，初期需你人工校准 LLM-as-judge，这点要接受。

### D6 — 品味怎么沉淀？仅你一人？
**推荐**：你在岔路上的每次裁决/纠正都**落库并复用**，下次同类岔路自动按你偏好决（或直接推荐你上次的选择）；你可随时查看/编辑这个"品味库"。**仅单人品味**，不做团队对齐。
**理由**：研究说个人开发者在这件事上有"不对称优势"（品味来源单一、闭环短）。这也是让你"越用越少被问"的核心机制。
**牵动**：spec.DRAFT R6。

### D7 — 陌生领域，系统自己查还是问你？
**推荐**：**自己查**——给 spec/design team 配自主研究能力（web search + 翻参考项目），把调研依据和来源附在产出里，不为"这是什么"来问你。（就像我这两天替你做的 deep research 那样，只是内化进流水线。）
**理由**：你原话"遇到陌生的我也上网找资料、参考同类项目"。这部分是纯劳动、无需你的品味，最该自动化。
**牵动**：spec.DRAFT R2。

### D8 — "美观/前端设计"这个维度算进来吗？
**推荐**：把"设计品味"作为品味库的一个**维度**纳入（你对 UI/交互的偏好会被记录、影响 spec/design 判断）；但**自动生成视觉方案/UI 设计本身先不做**（研究：AI 视觉 agent 原型生成尚可 ★★★★☆、跨页一致性差 ★★☆☆☆），列为 related、后续单独立项。
**理由**：你原始需求提了"前端设计角度看美观性"，不能丢；但视觉自动化是另一个深坑，混进来会撑爆本 unit。
**牵动**：spec.DRAFT 范围与非目标。**请确认**：这样切是否符合你对"美观"的期待，还是你希望本期就要它产出视觉草案？
