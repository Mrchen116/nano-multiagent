# feat-414: 消息气泡显示本轮墙钟耗时

## Relations

- Closes: #96

## 原始需求

> https://github.com/Mrchen116/nano-multiagent/issues/96 分析这个问题，我觉得可能更合理是去掉这个工具列表的求和，而改成在消息气泡上显示累计这个气泡花了多久

issue #96 原文(@Mrchen116):工具调用聚合徽标显示 `36 tool calls · 8.1s`,但 `8.1s` 是每个工具
`duration_ms`(纯执行耗时)的累加,不含工具之间 LLM 思考 / 等待的时间;实际墙钟远大于此,用户据此
误判 agent 实际耗时。issue 建议方向 (a) 后端补每工具 `started_at`/`ended_at` 取首尾墙钟,或 (b) 把
文案语义改成「累计执行时间」。用户在本对话里给出了第三个、更贴近「用户真正想看这一轮花多久」的方向。

- Q2: 这个时长显示在哪些气泡上?(推荐:所有 agent 回复气泡都显示,含零工具的纯文本回复;用户气泡不显示)

  Agent 解读: 从工具徽标里挪到气泡 status 行(挨着 TokenChip),覆盖纯文本慢回复。

- Q3: 这一轮还在跑的时候,气泡上显示什么?(推荐:进行中显示实时走动的计时,答完定格成最终墙钟)

## 用户场景

用户在 IM 里让某个 agent 跑一个稍重的任务——比如一轮里调了几十次工具、中间夹着多轮 LLM 思考。任务跑完后,用户想知道的第一件事是「这一轮到底花了我多久」。

现状下,气泡上挂的工具徽标写着 `36 tool calls · 8.1s`,用户自然把 `8.1s` 当成「这轮花了 8.1 秒」。但这个数只是每个工具纯执行耗时的累加,不含工具之间 agent 思考、等待上游的时间。实际从「用户按下发送」到「agent 答完」可能是几十秒。用户据此严重低估了 agent 的真实耗时,体感和数字对不上。

变更后:每个 agent 回复气泡的 status 行(就是现在放 TokenChip / 时间戳那行)显示**本轮墙钟耗时**——从用户这条消息发出、agent 开始处理这一轮,到 agent 答完为止。

- 这一轮还在跑时,这里是一个**实时走动的计时**,用户盯着它增长,就知道 agent 还活着、已经等了多久;
- agent 答完,计时**定格**成最终墙钟(如 `42s`),这才是用户真正想看的「这轮多久」;
- 哪怕这一轮 agent 只回了一段纯文字、一个工具都没调,气泡照样显示它花了多久——这是原来挂在工具徽标上的耗时做不到的(没工具就没徽标);
- 与此同时,原来工具徽标里那个会误导的 `· 8.1s` 累加被拿掉,折叠态只剩 `36 tool calls`;展开工具列表后,每个工具行自己的执行耗时(`Read 120ms`)照旧保留——那个数是准的,只是不再求和冒充总耗时。

净效果:用户看气泡就知道这轮真实墙钟,不再被工具执行时间的累加误导。

## 验收标准

### Requirement: agent 回复气泡显示本轮墙钟耗时

#### Scenario: 含多轮工具与思考的慢任务(正常路径)
- **GIVEN** agent 跑一轮里调了多次工具、中间夹着 LLM 思考的任务,整轮实际花了数十秒
- **WHEN** agent 答完、这条回复气泡呈现完成态
- **THEN** 气泡 status 行显示本轮墙钟耗时(从用户发出到 agent 答完),数量级与用户体感的等待时长一致,而非工具执行耗时的累加小数

#### Scenario: 纯文本回复、零工具调用
- **GIVEN** agent 这一轮只回了一段文字,没有调用任何工具
- **WHEN** agent 答完
- **THEN** 气泡 status 行同样显示这一轮花了多久

#### Scenario: 这一轮仍在进行中
- **WHEN** 这一轮 agent 还在跑、尚未答完
- **THEN** 气泡上显示一个随时间实时增长的计时
- **AND** agent 答完后,该计时定格为本轮最终墙钟,不再变化

#### Scenario: 用户自己发的消息气泡
- **WHEN** 用户查看自己发出的消息气泡
- **THEN** 该气泡不显示任何耗时(耗时只属于 agent 的回复轮次)

### Requirement: 工具徽标不再用累加耗时冒充总耗时

#### Scenario: 折叠态工具徽标
- **GIVEN** 一条有 N 次工具调用的 agent 气泡
- **WHEN** 用户看折叠态的工具徽标
- **THEN** 徽标只显示工具调用次数(如 `36 tool calls`),不再带 `· Xs` 的累加时长

#### Scenario: 展开后的单工具耗时
- **WHEN** 用户展开工具列表
- **THEN** 每个工具行仍各自显示自己那次的执行耗时

## 范围与非目标

- 在范围：
  - 每个 agent 回复气泡显示本轮(用户发出 → agent 答完)墙钟耗时,落在气泡 status 行
  - 进行中实时计时,完成时定格为最终墙钟
  - 零工具的纯文本回复也显示耗时
  - 工具徽标折叠态去掉累加时长,只留调用次数;展开态单工具耗时保留
- 非目标：
  - 不做后向兼容 / 旧消息耗时回填(开发态,见 Q5)
  - 不改单个工具 `duration_ms` 的计量口径(仍是纯执行耗时,只是不再求和)
  - 用户自己的消息气泡不显示耗时
  - 不做耗时的跨消息统计 / 聚合面板 / 历史趋势 / 排行
