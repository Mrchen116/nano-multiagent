一个气泡装下全部技术动作：工具调用面板 + 待决审批卡。已决审批不再是独立卡片——它就是工具列表里行尾标「已授权 / 已拒绝」的一行。点「▶ 开始」，你在深色待决卡上点允许/拒绝来驱动 agent。

行内分区对照：闸门（谁批准） vs 结果（执行如何）

同一行两个区互不打架：闸门区紧贴名称右侧，结果区在行尾。

●readAGENTS.md0.2s
●bash已授权npm run build1.2s
✕bash已授权npm testexit 13.1s
✕bash已拒绝rm -rf node_modules/.cache未执行*
✕bashcurl https://flaky.api/x执行超时

真实文案：失败带退出码=exit 1，无退出码=failed，超时=执行超时，中断=已中断，拒绝 reason=已拒绝。
行 3 关键边界：授权了但执行失败 → 名称旁「已授权」(闸门) 与行尾「exit 1」(结果) 各占一侧。行 4 拒绝 → 闸门「已拒绝」、行尾「未执行*」(*新提的标签，现状没有)、且抑制行尾原有的「已拒绝」reason 徽标避免双印。行 5 自动工具超时 → 仅结果区「执行超时」，无闸门标。

一个气泡内：▸ N 次工具调用 · K 次授权 · X 允许 · Y 拒绝（收起态分项计数，小圆点区分）；展开后，授权过的行尾标 已授权（绿）/ 拒绝的标 已拒绝（红），文字标注，和普通工具行同列。
待决审批是唯一独立的深色卡，永远贴在气泡最下方等你操作；你一旦决定，它折叠消失，结果并成工具面板里的一行。没有单独的已决摘要胶囊了。
