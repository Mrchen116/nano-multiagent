## 原始需求

> http://127.0.0.1:8011/chat/4549b2bd294744129dfea6bdb5f64703 群聊点配置，怎么也跳到了某个agent的配置页啊。还有没法改群名，等等，作为IM缺失的能力。你先去审视一遍代码，从产品经理角度分析，从IM来看，还缺哪些能力

随后（审视报告给出能力盘点后）：

即对应盘点中的 P0 范围里：
1. 修群聊配置入口（群聊不再跳到某个 agent 的配置页）+ 群聊专属「群设置」入口 + 改群名。
2. 群设置面板里铺开成员列表 + 移除成员 / 退群 / 解散群（后端 DELETE 系列已具备）。

## 澄清记录

- Q1: direct chat 与 group chat 的「配置」入口分成两套吗？（direct 保持跳 agent 配置页；group 改为打开群设置面板，不再跳任何 agent 配置页）
  A(原话): 对
  Agent 解读: 群聊配置入口语义 = 配这个群；不再复用「抓第一个 agent 跳其配置页」的 direct 假设。

- Q2: 谁能在群设置里执行管理操作（改名 / 移除成员 / 解散）？随后用户反问「现在有这个群聊属于谁的属性吗」。核实后确认：会话有 `creator_id`（解散权限锚点）+ `owner_id`（租户归属）；「移除成员」后端无创建者校验，仅「解散」是创建者专属。基于「单人 + agent 群、agent 不操作 UI」的现实，收窄为 Q2'：群设置要不要「退群」动作？
  A(原话): 不做退群。
  Agent 解读: 群设置只给三件事——改群名 / 移除某个 agent 成员 / 解散群，均对创建者（即操作者本人）可见可用，不做权限分层 UI。

- Q3: 破坏性操作的确认与解散后的去向？（解散：二次确认 + 成功后回会话列表空态；移除成员：轻确认 + 停留在群里）
  A(原话): 好

- Q4: 两个边界——群里 agent 能不能被移到「一个不剩」？群名能不能改成空？
  A(原话): 1. 0 agent可以，但是"发消息没有 agent 会回"不需要提醒用户。正常IM都不会。2. 群名，也OK
  Agent 解读: 允许移除到 0 个 agent，群仍存在、成员只剩用户本人，**不加任何「没人回」提示**（与普通 IM 一致）；群名为空则拒绝提交、保持原名。

- Q5: 群成员列表里的 agent，点一下能进它的配置页吗？
  A(原话): 好
  Agent 解读: 成员列表中每个 agent 行可点击 → 跳 `/settings/agents/{id}`，承接原本错放在群「配置」按钮上的 agent-跳转语义。

- Q6: 移动端要不要一并支持？
  A(原话): 要
  Agent 解读: 群设置在 375px 移动端同样可打开并完成改名 / 移除 / 解散，布局形态留给 design。

- Q7: 用户指出「只能删人不能加人有点怪」。核实后端：无独立添加成员端点，但底层 membership 写入（repositories.py:478）已存在、relay task 按 participant 创建的逻辑（web_im_service.py:222）也有，补「添加成员」是抽出已有写入 + 新增一个端点 + 前端选择器。问：把「添加成员」并入本 unit 吗？
  A(原话): 并入
  Agent 解读: 范围扩为完整群成员管理（看 / 加 / 移除）。后端新增 `POST /conversations/{id}/participants`，前端群设置加「添加成员」入口（agent 选择器，可复用建群多选）。

## 用户场景

用户在 IM 里建了一个群聊，把几个 agent 拉进去协作。用一阵子后他想做两件最普通不过的群管理：给群改个名、把某个不再需要的 agent 移出去。

今天他在群聊里点「配置」，期待看到「这个群」的设置，结果被甩到了群里**第一个** agent 的配置页——配置入口把「配群」错当成了「配某个成员」。而群名一旦在创建时定下就再也改不了：标题栏只读显示，没有任何编辑入口。成员列表也只是一行用 `·` 分隔的只读文字，想踢人无从下手。

变更后：
- 群聊的「配置」打开的是**群设置**面板，承载「群名 / 成员列表 / 移除成员 / 解散群」。direct chat（用户 + 单个 agent）的配置按钮维持原样——点了进那个 agent 的配置页，因为那本来就对。
- 在群设置里，他能把群名改成想要的名字；空着不让保存。
- 成员列表把群里每个成员摆出来；点某个 agent 成员能直接进它的配置页（想配 agent 就在这儿点，不用绕回左侧 agents 列表）。
- 他能把某个 agent 移出群（先一句确认）；想清空就一直移到一个 agent 不剩也行，群照样在，界面不弹任何「没人回你」之类的提醒。
- 反过来，他也能往群里**加 agent**：群设置里点「添加成员」，弹出还没在这个群里的 agent 让他挑，选完加入，成员列表立刻多出来；已经在群里的 agent 不会重复出现在可选项里。删和加成对，成员管理是闭环的。
- 他不想要这个群了，就「解散群」——弹一道「删除不可恢复」的确认，确认后群和聊天记录一起删掉，界面回到会话列表，不再停在已经没了的会话上。
- 以上在手机（移动端）上一样能做。

## 验收标准

### Requirement: 群聊配置入口指向群设置，不再错跳 agent 配置页

#### Scenario: 群聊点配置打开群设置
- **GIVEN** 用户打开一个含多个 agent 的群聊
- **WHEN** 用户点击聊天窗口的「配置」入口
- **THEN** 打开「群设置」面板（含群名 / 成员列表等）
- **AND** 不跳转到任何 agent 的配置页

#### Scenario: direct chat 点配置仍进该 agent 配置页（保持不变）
- **GIVEN** 用户打开一个 direct chat（自己 + 单个 agent）
- **WHEN** 用户点击「配置」入口
- **THEN** 进入该 agent 的配置页，与变更前一致

### Requirement: 在群设置里修改群名

#### Scenario: 改群名成功
- **GIVEN** 用户在某群的群设置面板
- **WHEN** 用户把群名改成一个非空名字并保存
- **THEN** 保存成功，聊天窗口标题栏与会话列表显示新群名

#### Scenario: 群名不能为空
- **WHEN** 用户把群名清空后尝试保存
- **THEN** 无法提交（保存不可用或提示群名不能为空），群名保持原值

### Requirement: 查看群成员并可进入某成员 agent 的配置页

#### Scenario: 成员列表展示全部成员
- **WHEN** 用户打开群设置面板
- **THEN** 看到群里所有成员（用户本人 + 各 agent）的列表

#### Scenario: 点 agent 成员进其配置页
- **WHEN** 用户点击成员列表里某个 agent 成员
- **THEN** 进入该 agent 的配置页

### Requirement: 移除群里的 agent 成员

#### Scenario: 移除一个 agent 成员
- **GIVEN** 群里有多个 agent
- **WHEN** 用户对某个 agent 成员发起移除并在确认提示中确认
- **THEN** 该成员从成员列表消失，用户停留在该群

#### Scenario: 移除到一个 agent 不剩（边界）
- **GIVEN** 群里只剩最后一个 agent
- **WHEN** 用户移除该 agent 并确认
- **THEN** 群依然存在，成员列表只剩用户本人
- **AND** 不出现任何「没有 agent 会回复」之类的提示

### Requirement: 向群里添加 agent 成员

#### Scenario: 添加一个 agent 进群
- **GIVEN** 当前账号下有 agent 还没在这个群里
- **WHEN** 用户在群设置点「添加成员」，从候选里选中一个 agent 并确认
- **THEN** 该 agent 出现在成员列表里，成为群成员（之后可在群里收发消息）

#### Scenario: 已在群里的 agent 不重复出现在候选
- **GIVEN** 某些 agent 已经是该群成员
- **WHEN** 用户打开「添加成员」候选列表
- **THEN** 候选里只列出当前账号下尚未在该群的 agent，已在群的不出现

#### Scenario: 没有可添加的 agent（空态）
- **GIVEN** 当前账号下所有 agent 都已在该群里
- **WHEN** 用户打开「添加成员」候选列表
- **THEN** 候选为空，给出「没有可添加的 agent」之类的空态提示

### Requirement: 解散群

#### Scenario: 解散群成功
- **GIVEN** 用户在自己建的群的群设置面板
- **WHEN** 用户点「解散群」并在「删除不可恢复」确认提示中确认
- **THEN** 该群及其聊天记录被删除，当前聊天窗口关闭，界面回到会话列表（不再显示已删除的会话）

#### Scenario: 取消解散
- **WHEN** 用户点「解散群」后在确认提示中取消
- **THEN** 群、成员、聊天记录均无变化

### Requirement: 移动端可用

#### Scenario: 移动端完成群管理
- **GIVEN** 用户在 375px 宽的移动端打开某群
- **WHEN** 用户进入群设置并执行改群名 / 移除成员 / 解散群
- **THEN** 各操作均可正常打开与完成，布局不破版

## 范围与非目标

- 在范围：
  - 群聊「配置」入口改为打开群设置面板，修掉错跳第一个 agent 配置页的行为；direct chat 配置入口保持现状。
  - 群设置面板：改群名（空名拒绝）、成员列表（可点 agent 成员进其配置页）、添加 agent 成员（候选排除已在群的）、移除 agent 成员（带确认）、解散群（带不可恢复确认 + 解散后回会话列表）。
  - 桌面端与移动端（375px）均支持。
  - 复用已有后端端点：`PATCH /conversations/{id}`（title）、`DELETE /conversations/{id}/participants/{uid}`（移除）、`DELETE /conversations/{id}`（解散，创建者）。
  - 新增后端端点：`POST /conversations/{id}/participants`（添加成员；复用已有 membership 写入 + 为新增 agent 创建 relay task）。

- 非目标：
  - 群头像、群描述（数据模型无相应字段）。
  - 「退群」（移除自己保留群）动作——本产品「单人 + agent 群」场景下与解散重叠，不做。
  - 非创建者的权限分层 UI——当前无「多个真人同群」场景，不为其提前造权限层。
  - 消息撤回 / 回复 / 已读回执、@ 人、搜索等其它 IM 能力（属更大盘点的后续单元）。
