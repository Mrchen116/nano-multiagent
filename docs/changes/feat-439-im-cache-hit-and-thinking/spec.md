## 澄清记录

**Q1（缓存命中率口径）**：一条助手回复常由多次模型请求组成（一次回复里穿插十几次工具调用 = 十几次请求）。命中率该按哪个口径算？
**A**：按**整轮累计**（B）—— 命中率 = 这一轮所有请求命中的输入量之和 ÷ 所有请求总输入量之和，不是只看最后一次请求。

**Q2（思考的真实形态，design 阶段调研后回填）**：调研发现一条助手回复里其实有**多段思考**——回复过程中每次模型请求都可能各自思考一次，思考和工具操作是交替发生的（先想一下→查两个文件→再想一下→改文件→给答案）。原始设想的「正文上方一个思考块、逐字滚动」与此不符。怎么展示？
**A**：把**整轮的多段思考和工具操作按发生的先后顺序**一起展示在一个可折叠区域里，让用户能看到「什么时候想了什么、接着做了什么」。思考整段呈现（不逐字滚动）、可逐段展开收起。

## 用户场景

两个独立、但都挂在同一个意图上的展示增强：**owner 在自己用的 Web IM 里盯着 agent 干活时，想多看到两类被当前 UI 吞掉的信息。**

### 场景 A：看一轮回复实际命中了多少缓存

nano 在 IM 里和 agent 长对话，上下文涨到 190k。他点开消息底部的 token 气泡想了解这轮开销——现在只能看到「输出 / 总计 / 已用上下文 / 百分比」。他还想知道：这么大的 context 里，有多少是命中了 provider 的前缀缓存、并没有真的重新计算？这直接关系到这一轮实际烧了多少钱和时间。

而且一次回复常常触发十几次工具调用，也就是十几次 LLM 请求。他要看的是**这一整轮所有请求累计**的缓存命中情况，而不是只有最后一次。

展开气泡详情后，他在「已用上下文」那行下面看到新增一行：`缓存命中 168,402 (87%)`。这轮如果一次都没命中，则显示 `缓存命中 0 (0%)`，他一眼知道功能在、只是这轮没命中。

### 场景 B：看 agent 在什么时候思考了什么

nano 用的是带 thinking 的模型(如 K2.6)。agent 在回复前/中会思考，但现在 IM 只显示最终正文，思考过程整段被吞掉。排查「agent 为什么做了这个决定」时，他特别想回看那段思考。

而且一条回复里 agent 常常**想一下→做几步→再想一下→再做几步**，思考是分多段、和工具操作交替发生的（Q2）。他想看到的正是这条「什么时候想了什么、接着做了什么」的过程。

在他自己用的这套 Web IM 里：助手回复里有一个可折叠的「过程」区域，把这一轮的多段思考和工具操作**按发生的先后顺序**排在一起；每段思考整段呈现、默认收起为一行 `💭`，他想看时点开能读到完整思考，历史消息回看也一样能展开。模型这轮没思考时，过程里就不出现思考行。

将来这套个人助手经 channel 接到第三方 IM 给别人用时，那些**外部触点只看到干净的正文**，不暴露思考过程。

## 验收标准

### Requirement: token 气泡展示本轮缓存命中率

#### Scenario: 本轮有缓存命中
- **GIVEN** 一次助手回复已完成、token 气泡可见
- **WHEN** 用户点开 token 气泡的详情面板
- **THEN** 在「已用上下文」行下方看到一行缓存命中，显示命中的 token 数与百分比(如 `缓存命中 168,402 (87%)`)
- **AND** 百分比是这一轮所有 LLM 请求累计的命中比例(口径见澄清记录 Q1)，取值在 0%–100% 之间

#### Scenario: 本轮无缓存命中(空态)
- **GIVEN** 一次助手回复本轮没有任何缓存命中
- **WHEN** 用户点开 token 气泡的详情面板
- **THEN** 缓存命中行仍然显示，值为 `0 (0%)`，不隐藏该行

### Requirement: 内部 Web IM 把思考与工具操作展示为一条过程

#### Scenario: 一条回复含多段思考与多次工具操作
- **GIVEN** 用户在自建 Web IM 与一个带 thinking 的模型的 agent 对话
- **WHEN** 一条助手回复里发生了多段思考、多次工具操作
- **THEN** 该回复里有一个可折叠「过程」区域，把这一轮的多段思考与工具操作**按发生的先后顺序**排在一起，用户能看出「先想了什么、接着做了什么、又想了什么」(口径见澄清记录 Q2)

#### Scenario: 思考整段可展开回看
- **GIVEN** 过程区域里有思考段
- **WHEN** 用户点开某一段思考
- **THEN** 能读到该段完整思考内容、可再次收起；历史消息回看时同样能展开

#### Scenario: 模型本轮无思考(空态)
- **GIVEN** 模型本轮没有产出任何思考内容
- **WHEN** 助手回复显示
- **THEN** 过程区域里不出现思考行(不留空壳)

### Requirement: 外部 IM 不暴露 thinking

#### Scenario: 外部 channel 只收到正文
- **GIVEN** 个人助手经 channel 接入的第三方外部 IM
- **WHEN** 同一条助手回复送达该外部 IM
- **THEN** 外部 IM 只显示回复正文，不包含任何思考内容

## 范围与非目标

- 在范围：
  - token 气泡详情面板新增「缓存命中(整轮累计)」一行(含 0% 空态)。
  - 内部 Web IM 助手消息展示 thinking：流式实时显示 + 结束收起 + 可展开回看 + 持久化历史可回看。
  - thinking 数据贯穿后端链路并持久化(渲染端按内/外决定显不显)。
  - 前后端真栈联调验证两项都能在 IM 里真实看到。
- 非目标：
  - 不在主气泡按钮上加缓存命中率(只进详情面板)。
  - 不为「内部/外部」新造用户/权限模型——只沿用 channel 这一既有边界。
  - 不做缓存命中率的历史趋势图/跨会话统计/成本换算。
  - 不改动 thinking 在 agent 内核侧的接收与持久化(已具备)，也不改模型是否开启 thinking 的配置。
  - 外部第三方 channel 的实际接入不在本 unit(本 unit 只保证外部触点不带 thinking 这一契约)。
