# feat-445: 从某条消息位置 fork 出分支单聊

## Relations

无外部 unit 依赖。（与现状「direct-agent 单聊 + fresh session 另开新会话」能力同族，复用其命名与单聊机制，但不阻塞于任何在途 unit。）

## 原始需求

> 我想在我们的IM上做这个功能，加个按钮，在某个消息位置fork。新增一个和那个用户的单聊，把全部的从0到fork点聊天记录带过去
>
> 附截图：ChatGPT 在某条助手消息的「…」菜单里有「新聊天中的分支」入口（见对话内截图，路径 chatgpt.com/c/...，菜单项「新聊天中的分支」）。

## 澄清记录

- Q1: fork 按钮在什么会话里能用、fork 出来的单聊是「和谁」的？
  A(原话): 群聊暂时不支持。
  Agent 解读: fork 只在「你 ↔ 单个 agent」的单聊里支持；群聊本期非目标。fork 出来的新单聊就是和当前这个 agent 的另一个分支单聊。

- Q2: fork 出来的新单聊里，agent 是真的「记得」之前那段对话（上下文连续），还是只把历史当只读记录展示？
  A(原话): a
  Agent 解读: 选 A——上下文连续。新单聊里 agent 带着 0→fork 点的完整记忆继续对话，与 ChatGPT「分支」效果一致；这是 fork 相对「重开空单聊」的核心价值。

- Q3: fork 按钮挂在哪条消息上？「0 到 fork 点」是否包含被点的那条消息？
  A(原话): 只有agent的消息可以按fork。
  Agent 解读: 入口只出现在 agent 的回复消息上（用户自己的消息没有 fork 入口）。带过去的范围到「被点的那条 agent 回复」为止（含该条，闭区间）。

- Q4: 搬到新单聊里的那段历史，以什么形态呈现？
  A(原话): 对
  Agent 解读: 原样保留完整气泡——用户消息、agent 回复正文，以及当时的工具调用 / 思考过程折叠区都和原会话一致；让用户看到的历史与 agent「记得」的一致。

- Q5: fork 完成后是否立刻进入新单聊？原会话是否受影响？
  A(原话): 好
  Agent 解读: 点 fork 后自动跳进新单聊、可直接发消息；原会话完全不受影响，两条线从 fork 点起各自独立演化、互不回流。

- Q6: 分支单聊在会话列表里叫什么名、怎么区分？
  A(原话): 不用，现在所有title = <agent 名>啊
  Agent 解读: 不引入分支专属命名 / 后缀。fork 出来的单聊 title 就是 `<agent 名>`，与现状所有 direct-agent 单聊一致（现状即如此）；不做当场命名步骤。

## 用户场景

小李在和某个 agent 的单聊里一路聊下来，agent 刚给了一条「分三点」的回复。小李对其中「第二点」很感兴趣，想顺着它深挖一大段，但又不想把当前这条主线对话搅乱（后面他还要回来接着聊别的）。

他把鼠标移到那条 agent 回复上，点出现的 **fork** 按钮。页面立刻把他带进一个**新的、和同一个 agent 的单聊**：里面已经躺着从对话最开头到这条回复为止的全部消息——他自己的提问、agent 的每一条回复，连当时的工具调用和思考过程折叠区都和原来一模一样。他直接在底部接着发「第二点再展开讲讲」，agent 心领神会地知道「第二点」指的是哪一点——因为它带着到 fork 点为止的完整记忆在跟他聊。

与此同时，原来那条单聊**原封不动**：消息没少、agent 在那条线里的记忆也没被新分支影响。小李随时可以切回去，两条线从 fork 点起各走各的。

几个他会自然碰到的边界：
- agent 还在「转圈」生成回复时，那条没回完的消息上**没有** fork 按钮——不能带着半截回答岔出去。
- 他自己发的消息上**没有** fork 按钮（只有 agent 的回复能 fork）。
- 如果这个 agent 此刻**离线**，fork 用不了——会提示 agent 当前不可用，因为分支单聊要让 agent「记得」历史，这需要 agent 在线。
- 群聊里的消息暂时**没有** fork 入口。

## 验收标准

### Requirement: 已完成的 agent 回复上提供 fork 入口

fork 入口只出现在单聊中已经回复完成的 agent 消息上；用户自己的消息、尚在生成中的 agent 消息、以及群聊里的消息都不提供 fork。

#### Scenario: 单聊里已完成的 agent 回复可 fork
- **GIVEN** 用户在与某 agent 的单聊里，有一条已回复完成的 agent 消息
- **WHEN** 用户把焦点移到该 agent 消息上
- **THEN** 该消息上出现一个 fork（分支）按钮，可点击

#### Scenario: 用户自己的消息没有 fork 入口
- **WHEN** 用户查看自己发出的消息
- **THEN** 该消息上不出现 fork 按钮

#### Scenario: 生成中的 agent 回复没有 fork 入口
- **GIVEN** 一条 agent 回复仍在生成中（未收尾、显示运行中）
- **WHEN** 用户查看该消息
- **THEN** 该消息上不出现 fork 按钮；待其回复完成后才出现

#### Scenario: 群聊消息不提供 fork
- **WHEN** 用户在群聊里查看任意消息（含 agent 消息）
- **THEN** 不出现 fork 按钮

### Requirement: fork 创建分支单聊并带入起点到 fork 点的完整历史

在某条 agent 回复上 fork，会新建一个与同一 agent 的单聊，把从会话最开头到被点击的那条 agent 回复（含该条）之间的全部消息原样带入；该 agent 回复之后的消息不带入。历史以与原会话一致的完整气泡呈现。

#### Scenario: 新单聊含起点到 fork 点的全部消息
- **GIVEN** 一条单聊里依次有若干消息，用户在其中某条 agent 回复 M 上 fork
- **WHEN** 进入新建的分支单聊
- **THEN** 其中含从会话起点到 M（含 M）的全部消息，顺序与原会话一致

#### Scenario: fork 点之后的消息不带入
- **GIVEN** 被 fork 的 agent 回复 M 之后原会话还有更晚的消息
- **WHEN** 用户查看分支单聊
- **THEN** M 之后的那些消息不出现在分支单聊里

#### Scenario: 带入的历史保留完整气泡形态
- **GIVEN** 原会话里 fork 点之前包含带工具调用 / 思考过程的 agent 回复
- **WHEN** 用户在分支单聊里回看这些历史消息
- **THEN** 它们与原会话呈现一致——正文、工具调用、思考过程折叠区都在，而非只剩纯文本

### Requirement: 分支单聊里 agent 带着到 fork 点为止的完整记忆继续对话

进入分支单聊后，agent 对带入历史的内容是「记得」的，用户可基于历史用省略 / 指代继续追问，agent 据历史正确理解。

#### Scenario: 在分支单聊里基于历史追问
- **GIVEN** 带入的历史里 agent 给过一条「分多点」的回复
- **WHEN** 用户在分支单聊里发「第二点再展开讲讲」（不重述第二点内容）
- **THEN** agent 的回复针对历史里那条回复的「第二点」展开，表明它带着历史上下文，而非把用户当作新对话从零开始

### Requirement: fork 后自动进入新单聊且原会话不受影响

点击 fork 后用户被自动带入新建的分支单聊、可直接发消息；原会话的消息与对话状态完全不变，两条线从 fork 点起各自独立演化、互不回流。

#### Scenario: fork 后自动进入分支单聊
- **WHEN** 用户点击某条 agent 回复上的 fork 按钮
- **THEN** 页面自动切换到新建的分支单聊，用户可立即在其中发送新消息

#### Scenario: 原会话保持不变
- **GIVEN** 用户已从某会话 fork 出一个分支单聊
- **WHEN** 用户切回原会话
- **THEN** 原会话的消息与之前完全一致（未因 fork 增减或改动）

#### Scenario: 两条线独立演化
- **GIVEN** 用户在分支单聊里发了新消息、agent 也回复了
- **WHEN** 用户切回原会话
- **THEN** 原会话不出现分支单聊里的新消息；反之在原会话里继续聊也不影响分支单聊

### Requirement: 分支单聊在会话列表里与现有单聊一致地呈现

分支单聊作为一个普通的 direct-agent 单聊出现在会话列表里，命名与现状所有该 agent 的单聊一致（title 为 agent 名），不引入分支专属命名或当场命名步骤。

#### Scenario: 分支单聊出现在会话列表且名称为 agent 名
- **WHEN** fork 完成后用户查看会话列表
- **THEN** 列表里出现这个新单聊，其名称为该 agent 的名字（与现有该 agent 单聊的命名一致）

### Requirement: agent 离线时 fork 不可用

被 fork 的 agent 当前离线 / 不可用时，fork 操作无法进行，用户得到明确提示，而非静默失败或建出一个 agent 不记得历史的空壳单聊。

#### Scenario: agent 离线时 fork 给出明确反馈
- **GIVEN** 某 agent 当前离线
- **WHEN** 用户尝试在其历史回复上 fork
- **THEN** fork 不执行，用户看到「该 agent 当前不可用，暂时无法 fork」一类明确提示；不会建出一个 agent 不记得历史的单聊

## 范围与非目标

- 在范围：
  - 单聊（你 ↔ 单个 agent）中，在已完成的 agent 回复上 fork
  - 新建分支单聊并带入起点→fork 点（含该 agent 回复）的完整历史（完整气泡形态）
  - 分支单聊里 agent 上下文连续（带着到 fork 点为止的记忆继续）
  - fork 后自动进入新单聊；原会话独立不受影响
  - agent 离线时禁用 fork 并明确提示
- 非目标：
  - 群聊里的 fork（本期不做）
  - 在用户自己的消息上 fork
  - 在生成中的 agent 回复上 fork
  - agent 离线时「先建会话、上线后再补上下文」的 lazy seeding 机制
  - 分支单聊的专属命名 / 当场命名 / 分支关系可视化（沿用现状单聊命名）
  - 选择历史区间（只支持「起点→fork 点」，不支持任意起止段）
