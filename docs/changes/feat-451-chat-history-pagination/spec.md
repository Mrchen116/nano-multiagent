  A(原话): 只用滚动到顶部自动触发
- Q2: 参考你说的飞书体验，滚动到“还没到顶”就提前触发加载。触发点设在距顶部多远比较合适？
  A(原话): 你来设计
  Agent 解读: 采用“距顶部一定偏移量提前触发”的策略，具体阈值由 design 阶段确定并在实现中可微调。
- Q3: 每次滚动触发时加载多少条更早消息？
  A(原话): 每次 50 条
- Q4: 当用户正在翻看更早消息时，收到新消息（或 agent 回复）应该怎么表现？
  A(原话): 你来设计，成熟的产品经理
  Agent 解读: 用户翻看历史时不应被打断；新消息仅在用户已位于底部附近，或用户自己刚发出消息时，才自动滚到底部。
- Q5: 除了分页，本次还要一起修哪些前端微体验问题？
  A(原话): 本需求要顺便修：1，2，4，5，8（移动端可以改成长按消息出来的菜单中fork）。
  Agent 解读: 本次范围在分页基础上，额外包含：1 移动端回车发送；2 自动滚底策略；4 composer 自动增高；5 消息气泡复制/长按菜单；8 移动端 fork 入口改到长按菜单里。
- Q6: 之前 sweep 找到的其他问题是否也要写进本 spec？
  A(原话): 你找到的那堆问题，要写到spec中呀
  Agent 解读: 把 high / medium 严重程度的体验问题一并纳入 feat-451：加载骨架屏、消息分组与时间戳、图片附件预览、@/slash 候选列表滚动不穿透、权限卡片自动聚焦、agent thinking 提示。Low  severity 的问题（未读 badge 封顶、返回按钮 touch target、sheet 下滑关闭、工具按钮 active 反馈等）本期暂不纳入，可后续单独打磨。

## 用户场景

小队在群里和 Planner、Reviewer、Writer 几个 agent 已经聊了很久。用户回到聊天窗口，只能看到最近 50 条消息。他想起前面 Reviewer 给过一个重要结论，于是向上滚动消息列表。当他接近顶部时，更早的消息自动加载出来，无缝接到现有内容上面；他继续向上滚，又能看到更早的内容，直到翻完整个会话。加载过程中列表顶部有轻微的加载提示，加载完成后他刚才正在看的那条消息仍停在原来的位置，没有被推到底部。与此同时，如果他正停在底部等 agent 回复，新消息一到会自动滚到底部；但如果他正埋头翻看历史，agent 的新回复不会突然把他拉走。

在手机上，他输入完问题后习惯性地按输入法回车，消息立刻发送出去，不用去够右上角的 ↑ 按钮。如果输入内容很长，输入框会自动增高，方便他查看多行文字。他问完问题后，列表底部会出现轻微的“agent 正在思考…”提示，让他知道请求已被接收。他看到 agent 之前给出的一段结论想复制，长按消息气泡就能调出「复制文本」菜单；在单聊里，长按 agent 的已完成回复，还能看到「fork」选项，一键分支出新会话继续聊。他发了一张截图，点击缩略图就能全屏查看。

消息列表不再每条都带一个时间戳：同一个发送者连续说的几句话会聚成一组，只在最后一条显示时间；跨天时会出现“昨天”“周一”这样的日期分隔。当 agent 向他请求某个工具权限时，输入拒绝理由的框会自动获得焦点，在手机上键盘弹起时确认/取消按钮也不会被顶出屏幕。他在群里想 @ 某个人，手指在候选列表里上下滑动时，只有候选列表在动，背后的聊天内容不会跟着滚动。

## 验收标准

### Requirement: 消息历史可通过向上滚动分页加载更早内容

#### Scenario: 会话有多页历史，用户向上滚动触发加载
- **GIVEN** 一个会话的历史消息超过一页
- **WHEN** 用户在消息列表中向上滚动到接近顶部
- **THEN** 更早的消息自动加载并插入到列表顶部
- **AND** 用户原来的阅读位置保持稳定，不自动跳到底部

#### Scenario: 已经翻到最老的消息
- **GIVEN** 用户已经加载到会话的第一条消息
- **WHEN** 用户继续滚动到顶部
- **THEN** 不再发起新的加载请求
- **AND** 顶部显示“没有更多消息”或类似的空状态提示

#### Scenario: 正在加载更早消息
- **WHEN** 用户触发更早消息加载且请求尚未返回
- **THEN** 消息列表顶部出现加载状态提示（如 spinner 或文案）

### Requirement: 新消息到达不打扰正在翻看历史的用户

#### Scenario: 用户正在看历史时收到新消息
- **GIVEN** 用户已经向上滚动离开底部，正在查看较早内容
- **WHEN** 有新消息或 agent 回复到达
- **THEN** 消息列表不自动滚动到底部
- **AND** 用户仍停留在当前阅读位置

#### Scenario: 用户在底部时收到新消息
- **GIVEN** 用户位于消息列表底部附近
- **WHEN** 有新消息或 agent 回复到达
- **THEN** 消息列表自动滚动到底部，让用户看到最新内容

### Requirement: 移动端输入法回车发送消息

#### Scenario: 移动端按回车发送
- **GIVEN** 用户在移动端的聊天输入框中输入了文字
- **WHEN** 用户按下输入法回车键
- **THEN** 消息被发送，输入框清空
- **AND** 不回车换行

#### Scenario: 桌面端保持 Enter 发送 / Shift+Enter 换行
- **GIVEN** 用户在桌面端的聊天输入框中
- **WHEN** 按 Enter（无 Shift）且不在输入法组合态
- **THEN** 消息被发送
- **WHEN** 按 Shift+Enter
- **THEN** 输入框内插入换行

### Requirement: composer 输入框随内容自动增高

#### Scenario: 输入多行文字时 composer 增高
- **GIVEN** 用户在 composer 中输入文字
- **WHEN** 文字超过一行
- **THEN** composer 自动增高以展示更多内容
- **AND** 增高到最大行数后不再继续变高，内部可滚动

### Requirement: 消息气泡支持复制与长按菜单

#### Scenario: 长按/右键消息气泡调出菜单
- **GIVEN** 聊天列表中有任意消息气泡
- **WHEN** 用户在移动端长按气泡，或在桌面端右键气泡
- **THEN** 弹出操作菜单，至少包含「复制文本」

#### Scenario: 复制消息文本
- **GIVEN** 操作菜单已打开
- **WHEN** 用户选择「复制文本」
- **THEN** 该消息的文本内容被复制到剪贴板

#### Scenario: 移动端单聊里长按 agent 回复进行 fork
- **GIVEN** 当前是直接用户↔agent 的会话，且某条 agent 回复已完成并可 fork
- **WHEN** 用户在移动端长按该 agent 回复，并在菜单中选择 fork
- **THEN** 触发 fork 流程，并给用户明确反馈（如 toast）

### Requirement: 进入会话加载历史时显示加载占位，避免“空状态闪烁”

#### Scenario: 打开有历史的会话
- **GIVEN** 会话中已有消息
- **WHEN** 用户打开该会话且历史尚未返回
- **THEN** 先看到骨架屏/加载占位
- **AND** 加载完成后平滑切换到真实消息列表

#### Scenario: 打开无消息的会话
- **GIVEN** 会话中没有任何消息
- **WHEN** 加载完成后
- **THEN** 显示空状态提示

### Requirement: 消息按发送者/时间分组，减少冗余时间戳

#### Scenario: 同一发送者连续发言
- **GIVEN** 同一发送者在短时间内连续发多条消息
- **WHEN** 消息渲染在列表中
- **THEN** 它们聚合成一组，只在最后一条显示时间戳

#### Scenario: 跨天对话显示日期分隔
- **GIVEN** 消息列表跨越不同日期
- **WHEN** 列表渲染时
- **THEN** 在日期变化处显示日期分隔线或标签

### Requirement: @ 成员与 / 技能候选列表在移动端滚动不带动底层页面

#### Scenario: 在手机上滚动候选列表
- **GIVEN** @ 成员列表或 / 技能列表较长
- **WHEN** 用户在列表内上下滑动
- **THEN** 只有列表本身滚动
- **AND** 背后的消息列表/页面不跟随滚动

### Requirement: 权限请求卡片出现时输入框自动聚焦，且按钮不被键盘遮挡

#### Scenario: 权限卡片出现并需要填写理由
- **GIVEN** 聊天中出现一个权限请求卡片
- **WHEN** 卡片第一次显示且包含可输入的拒绝理由输入框
- **THEN** 输入框自动获得焦点
- **AND** 在移动端软键盘弹出时，确认/取消按钮仍可见

### Requirement: agent 处理中显示 thinking/typing 提示

#### Scenario: 用户发消息后 agent 尚未生成回复气泡
- **GIVEN** 用户刚发送一条消息
- **WHEN** agent 正在处理但还没有创建回复气泡
- **THEN** 在消息列表底部显示 thinking/typing 提示
- **AND** 新回复气泡出现后提示消失

### Requirement: 图片附件可点击放大查看

#### Scenario: 点击聊天中的图片
- **GIVEN** 消息中包含图片附件
- **WHEN** 用户点击图片
- **THEN** 弹出全屏/大图预览
- **AND** 用户可关闭预览返回聊天

### Requirement: 桌面与移动端体验一致

#### Scenario: 在手机端向上滚动加载历史
- **WHEN** 用户在移动设备上打开同一聊天并向上滚动
- **THEN** 同样触发加载更早消息，且阅读位置保持稳定

#### Scenario: 在手机端长按 agent 消息 fork
- **WHEN** 用户在手机端长按可 fork 的 agent 回复
- **THEN** 出现包含 fork 选项的菜单

## 范围与非目标

- 在范围：
  - 聊天页（`/chat/:id`）消息列表的滚动加载更早消息。
  - 加载状态提示、无更多消息提示。
  - 加载更早消息时保持用户阅读位置。
  - 新消息到达时的自动滚底策略（不打扰看历史）。
  - 移动端输入法回车发送消息。
  - composer 输入框随内容自动增高。
  - 消息气泡的「复制文本」菜单（长按/右键）。
  - 移动端单聊里把 fork 入口放进消息长按菜单。
  - 进入会话时的历史加载占位（骨架屏）。
  - 消息按发送者/时间分组与日期分隔。
  - @/slash 候选列表在移动端的滚动不穿透。
  - 权限请求卡片的理由输入框自动聚焦及键盘适配。
  - agent 处理中的 thinking/typing 提示。
  - 图片附件点击放大预览。
  - 桌面端与移动端共用同一组件，行为一致。

- 非目标（本期不做，可后续单独打磨）：
  - 修改后端 API 或仓库（后端已支持分页）。
  - 消息列表虚拟化。
  - 搜索/跳转历史消息。
  - 每页加载条数的用户设置。
  - 非聊天页面的分页加载。
  - 除上述菜单外的消息操作（删除、编辑、引用、转发）。
  - 未读 badge 封顶显示。
  - 移动端返回按钮 touch target 放大。
  - 新建群聊底部 sheet 下滑关闭手势。
  - 工具调用展开按钮的 active 反馈。
  - 群设置移动端导航栏字号调整。
  - token chip 详情在窄屏的溢出处理。
  - 会话列表下拉刷新。
  - 空状态动效/引导提示。
