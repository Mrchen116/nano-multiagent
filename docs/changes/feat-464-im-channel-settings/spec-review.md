## Issues

- [CRITICAL] [澄清记录 Q5]: Q 字面问“是否同时删除历史”，A 写“对”，而 Agent 解读与验收标准要求“不删除历史”。不改会让 design 在数据删除边界上得到相反前提。应把 Q 改为“是否认可删除只移除连接、不删除历史的推荐方案”，保留 A 原话不动。
- [CRITICAL] [澄清记录 Q7]: Q 字面问“是否允许多个飞书 Bot”，A 写“对”，而 Agent 解读与验收标准要求“每种类型最多一个”。不改会让 design 选错单实例/多实例模型。应把 Q 改为带推荐结论的确认问法，保留 A 原话不动。
- [WARNING] [Requirement「离线配置与重连收敛」]: 离线 Scenario 只覆盖新增或修改，未覆盖停用、启用、删除。下游可能只实现字段编辑排队，却让生命周期操作在离线时走另一套语义。
- [WARNING] [Requirement「通用的外部 channel 管理页」]: 缺少列表加载失败态。下游可能把请求失败渲染成“尚未配置”空态，诱导用户重复添加或误判配置丢失。
- [WARNING] [Requirement「连接状态与可操作诊断」]: 缺少“权限检查本身失败/无法确认”的状态。下游可能把平台检查故障误报成某项权限缺失，给用户错误修复方向。

## Recommendations

- 将 Q3 改成带推荐前提的确认问法，使 A 的“对”无需依赖对话外上下文即可理解。
