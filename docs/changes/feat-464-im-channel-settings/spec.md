# feat-464: IM 通道配置页

## Relations

- Related: feat-447

## 原始需求

> 现在IM配置页中的通道页，还没东西。现在已经支持飞书channel了。但是要用户去配置文件改，很不方便，帮我设计怎么纳入到IM的通道页

## 澄清记录

- Q1: 通道页是否要承担完整连接生命周期，包括配置、保存即连接、状态展示、停用和重连？
  A(原话): ok
  Agent 解读: 通道页承担完整生命周期；保存正确配置后立即连接，不要求手工重启 Gateway，并展示未配置、连接中、已连接、异常、已停用等状态，支持停用和重连。

- Q2: 当 Agent 所属 Gateway 节点离线时，通道页应该怎样处理配置？
  A(原话): 和配置页对齐吧，离线的时候配置页怎么样？
  Agent 解读: 对齐当前配置页的离线语义：节点离线时仍可编辑并把期望配置保存到 IM，节点重连后自动应用；通道页同时区分“配置已保存”和“运行连接已生效”，避免把离线保存误报成已连接。

- Q3: 是否认可推荐方案：飞书接入采用分步向导，而不是只提供 `App ID / App Secret` 表单？
  A(原话): |-
    对。飞书开放平台准备指引不用太细，就简单给个https://open.feishu.cn/page/launcher?from=backend_oneclick 链接，简单引导下。

    还要考虑我们是多channel的，只是还没做到其他的，所以前端要基于多channel考虑
  Agent 解读: 使用轻量分步向导：提供飞书开放平台入口和最少必要指引，不在 IM 内复刻完整开放平台教程；通道页从一开始按多 channel 的通用目录、实例和状态模型设计，飞书只是首个可配置的 channel 类型。

- Q4: 通道页是否把内置 Web IM 也作为一个通道展示？
  A(原话): 不展示web IM
  Agent 解读: 通道页只展示用户可配置的外部 channel；Web IM 不进入通道清单。多 channel 通过通用的添加入口、channel 类型选择和实例状态卡片表达。

- Q5: 是否认可推荐方案：用户删除飞书通道时只移除连接配置和凭据，不删除由它产生的影子会话和聊天历史？
  A(原话): 对
  Agent 解读: 认可推荐方案：删除只移除飞书连接配置和凭据并停止后续消息收发，不删除已有的飞书私聊或群聊影子会话及聊天历史。

- Q6: 飞书凭据有效、基础消息能收发，但某些权限尚未开全时，通道应当完全不可用，还是允许降级使用？
  A(原话): 允许降级使用，但是权限受限的话，要呈现出来，到底缺啥，用户要知道
  Agent 解读: 权限不完整但基础链路可用时进入“连接受限”而非整体失败；页面必须逐项展示缺失权限、受影响能力和可执行的修复方向，不能只显示模糊的受限状态。

- Q7: 是否认可推荐方案：本期一个 Agent 对每种 channel 类型最多配置一个实例，“多 channel”不包含同时添加多个飞书 Bot？
  A(原话): 对
  Agent 解读: 认可推荐方案：本期一个 Agent 对每种 channel 类型最多配置一个实例；多 channel 指同一 Agent 可以同时拥有飞书及未来其他类型的 channel，不包含同时绑定多个飞书 Bot。

## 用户场景

用户在 IM 的 Agent 详情页进入“通道”，看到的是该 Agent 的外部 channel 管理页，而不是飞书专属表单。页面用统一的 channel 卡片展示已经配置的外部 channel，并提供统一的“添加通道”入口。内置 Web IM 不在这里展示。当前可添加的类型只有飞书；未来支持其他 channel 时，它们沿用相同的入口、卡片和状态语言。

第一次接入飞书时，用户点击“添加通道”，在类型选择器中选择飞书，进入轻量配置向导。向导提供[飞书开放平台](https://open.feishu.cn/page/launcher?from=backend_oneclick)入口和简短准备说明，提示用户创建应用、启用 Bot 与长连接并准备所需权限；页面不复刻完整开放平台教程。用户填写 App ID 和 App Secret 后保存。节点在线时，系统立即检查并连接，不要求用户编辑配置文件、查看终端日志或重启 Gateway。

连接结果必须直接在卡片和详情中可见。正常时显示“已连接”；基础能力可用但权限不完整时显示“连接受限”，并逐项告诉用户缺少什么权限、会影响什么能力以及去哪里修复；凭据无效、Bot 未启用或连接无法建立时显示“连接失败”和可执行的下一步。连接中、重连中、已停用等阶段也有明确状态，用户可手动重试。

如果 Agent 所属节点离线，用户仍能像现有配置页一样编辑并保存期望配置。页面明确显示“配置已保存，等待节点上线应用”，不把“已保存”误报成“已连接”。节点重连后，配置自动应用并刷新为真实运行状态。

用户可以编辑凭据、停用、重新启用、重连或删除飞书 channel。已保存的 App Secret 不以明文重新展示；用户可以保留现有密钥，或显式替换。删除 channel 只删除连接配置和凭据并停止后续收发，不删除此前生成的飞书私聊、群聊影子会话及聊天历史。

本期保持当前的一对一规则：同一个 Agent 最多配置一个飞书 Bot。多 channel 指同一个 Agent 可同时配置不同类型的外部 channel，而不是同类型多账号。

## 验收标准

### Requirement: 通用的外部 channel 管理页

#### Scenario: 尚未配置任何外部 channel
- **GIVEN** 当前 Agent 尚未配置任何外部 channel
- **WHEN** 用户打开 Agent 详情页的“通道”页签
- **THEN** 页面显示外部 channel 空态和统一的“添加通道”入口
- **AND** 页面不把 Web IM 展示为一个 channel

#### Scenario: 从统一入口选择 channel 类型
- **WHEN** 用户点击“添加通道”
- **THEN** 页面展示 channel 类型选择器，当前可选类型包含飞书
- **AND** 入口、标题和列表采用通用 channel 语言，不表现为飞书专属页面

#### Scenario: 当前类型已经存在
- **GIVEN** 当前 Agent 已配置一个飞书 channel
- **WHEN** 用户再次打开“添加通道”类型选择器
- **THEN** 页面明确表示该 Agent 已有飞书 channel，不能再添加第二个

#### Scenario: channel 列表加载失败
- **WHEN** 用户打开“通道”页签，但系统暂时无法读取已保存的 channel 列表
- **THEN** 页面显示加载失败和重试入口
- **AND** 页面不把读取失败误报成“尚未配置”的空态

### Requirement: 飞书轻量接入向导

#### Scenario: 用户查看飞书准备指引
- **WHEN** 用户选择添加飞书 channel
- **THEN** 页面显示简短的开放平台准备说明
- **AND** 提供可访问的 `https://open.feishu.cn/page/launcher?from=backend_oneclick` 链接

#### Scenario: 在线节点保存有效配置后立即连接
- **GIVEN** Agent 所属节点在线，且用户已在飞书开放平台完成必要准备
- **WHEN** 用户填写有效的 App ID 和 App Secret 并保存
- **THEN** 页面先显示保存和连接进度，随后显示“已连接”
- **AND** 用户不需要编辑配置文件或重启 Gateway

#### Scenario: 必填凭据缺失
- **WHEN** 用户没有填写 App ID 或 App Secret 就尝试保存
- **THEN** 页面在对应字段给出明确提示，且不声称配置已连接

#### Scenario: 已保存密钥不会重新明文展示
- **GIVEN** 飞书 channel 已保存 App Secret
- **WHEN** 用户再次进入编辑页
- **THEN** 页面只表明密钥已配置，不展示原始明文
- **AND** 用户可以选择保留现有密钥或显式替换

### Requirement: 连接状态与可操作诊断

#### Scenario: 权限完整且连接正常
- **GIVEN** 飞书凭据、Bot、长连接和所需权限均可用
- **WHEN** 用户查看飞书 channel 卡片或详情
- **THEN** 页面显示“已连接”及最近一次状态更新时间

#### Scenario: 权限不足但基础能力仍可用
- **GIVEN** 飞书凭据有效且基础消息可以收发，但部分权限未开通
- **WHEN** 系统完成检查
- **THEN** 页面显示“连接受限”而非“已连接”或“连接失败”
- **AND** 页面逐项显示缺失的权限、每项受影响的能力和可执行的修复方向

#### Scenario: 缺少普通群消息权限
- **GIVEN** 飞书 channel 能处理私聊和 @Bot 消息，但无法接收未 @Bot 的普通群消息
- **WHEN** 用户查看权限诊断
- **THEN** 页面明确指出缺少相关权限
- **AND** 页面说明群聊背景上下文会不完整，而不是只显示笼统错误

#### Scenario: 暂时无法完成权限检查
- **GIVEN** 飞书基础连接可用，但系统暂时无法从开放平台确认权限清单
- **WHEN** 用户查看权限诊断
- **THEN** 页面明确显示“权限状态暂时无法确认”及重试建议
- **AND** 页面不把检查失败误报成某项权限确定缺失

#### Scenario: 凭据或连接无效
- **WHEN** App ID 或 App Secret 无效、Bot 未启用，或连接无法建立
- **THEN** 页面显示“连接失败”
- **AND** 页面给出具体原因或下一步检查建议，不要求用户查看终端日志才能理解问题

#### Scenario: 连接暂时中断
- **GIVEN** 飞书 channel 此前已连接
- **WHEN** 连接暂时中断并正在恢复
- **THEN** 页面显示“重连中”或对应异常状态
- **AND** 用户可以看到自动恢复结果，或手动发起重连

### Requirement: 离线配置与重连收敛

#### Scenario: 节点离线时保存飞书配置变更
- **GIVEN** Agent 所属节点当前离线
- **WHEN** 用户新增、修改、启用、停用或删除飞书 channel 并确认保存
- **THEN** 页面接受并保留本次期望状态
- **AND** 页面显示“配置已保存，等待节点上线应用”，不显示“已连接”

#### Scenario: 节点重连后自动应用
- **GIVEN** 用户在节点离线期间保存了飞书 channel 配置
- **WHEN** Agent 所属节点重新上线
- **THEN** 页面无需用户再次保存或重启服务即可看到配置开始应用
- **AND** 最终显示真实的“已连接”“连接受限”或“连接失败”状态

### Requirement: 飞书 channel 生命周期管理

#### Scenario: 停用已连接的 channel
- **GIVEN** 飞书 channel 当前已连接
- **WHEN** 用户执行停用并确认
- **THEN** 页面显示“已停用”，后续飞书消息不再触发该 Agent
- **AND** 已保存的配置仍可供用户重新启用

#### Scenario: 重新启用 channel
- **GIVEN** 飞书 channel 当前已停用
- **WHEN** 用户重新启用
- **THEN** 页面重新执行连接并展示真实连接结果，不要求重填未变更的密钥

#### Scenario: 删除 channel 保留历史
- **GIVEN** 飞书 channel 已产生私聊或群聊影子会话
- **WHEN** 用户删除该 channel 并确认
- **THEN** IM 立即删除期望配置和凭据，并在节点尚未应用时持续显示“删除已保存，等待节点应用”
- **AND** Gateway 确认实际停止该 channel 后，删除中的条目才从当前 Agent 的通道列表中移除，后续不再收发消息
- **AND** 停止失败时页面显示原因和重试入口，不把它伪装成已删除
- **AND** 既有影子会话和聊天历史仍可在 IM 中查看

### Requirement: 节点绑定不得隐式迁移跨 owner channel

#### Scenario: 已绑定节点被另一个 owner 确认
- **GIVEN** 节点已经绑定 owner A，并保存或运行其外部 channel
- **WHEN** owner B 尝试确认同一 node 的绑定
- **THEN** IM 拒绝跨 owner 改绑，不修改节点、Agent、channel、manifest 或凭据归属
- **AND** owner B 不能读取或控制 owner A 的 channel
- **AND** 同 owner 的重复确认仍保持幂等

## 范围与非目标

- 在范围：
  - Agent 详情页中的通用外部 channel 管理页、空态和“添加通道”类型选择器
  - 飞书作为首个可配置 channel 的轻量接入向导
  - 飞书 App ID / App Secret 的新增、保留与替换体验
  - 配置保存与运行连接状态分离展示
  - 在线热生效，离线保存后在节点重连时自动应用
  - 已连接、连接受限、连接失败、连接中、重连中、已停用等用户可见状态
  - 缺失权限、受影响能力和修复方向的逐项诊断
  - channel 列表读取失败与权限状态无法确认时的明确失败反馈
  - 飞书 channel 的编辑、停用、重新启用、重连和删除
  - 每个 Agent、每种 channel 类型最多一个实例
  - 删除连接后保留既有影子会话和聊天历史
- 非目标：
  - 在通道页展示或配置内置 Web IM
  - 本期实现飞书以外的其他 channel
  - 同一个 Agent 同时绑定多个飞书 Bot 或同类型多账号
  - 在 IM 中复刻完整的飞书开放平台创建应用教程
  - 改变飞书现有私聊、群聊、影子会话、权限审批或文档操作行为
  - 删除 channel 时清除影子会话、聊天历史或 Agent 会话历史
  - 新增飞书群级白名单、黑名单等精细策略配置
