## 用户场景

Web IM 的核心用户会在同一条 Agent 回复中阅读长文本、打开资料链接、摘取局部内容、复制整条回复，或从某个回复继续 fork。消息正文首先是可阅读、可取用的内容，消息级操作是辅助能力；两者不能互相争夺右键、长按和链接点击。

桌面用户选中回复中的一句话后，可以继续使用熟悉的快捷键或系统右键菜单，只复制自己选中的文字。在没有选区时，用户仍能通过气泡旁按需出现的轻量操作入口复制整条消息或从可 fork 的回复处分支。普通阅读状态保持安静，不让按钮和菜单长期占据正文。

用户点击外部资料链接时，新内容在新标签页打开，当前聊天、阅读位置和未发送输入不被替换；IM 内部链接仍在当前产品内自然导航。用户在链接上右键时，仍能使用浏览器提供的复制地址和打开方式。

移动用户长按正文时进入系统文本选择，长按链接时使用系统链接操作；需要复制整条消息或 fork 时，通过消息元信息旁清晰但克制的更多入口打开短菜单。移动端不再用自定义长按菜单压制文本选择。

面对代码回复，用户可以直接复制单个代码块而不必复制整条消息。无论复制整条消息还是代码，用户都能看到简短、明确的成功或失败反馈。

键盘用户能够找到并操作消息级入口、链接和代码复制入口，看到清晰焦点状态；界面语言与当前语言设置一致，不出现突兀的中英文混排。

## 验收标准

### Requirement: 消息正文支持原生文本选择与局部复制

#### Scenario: 桌面端复制选中的局部文字
- **GIVEN** 一条消息中有多段可见文字
- **WHEN** 用户只选中其中一部分并使用复制快捷键或系统右键菜单复制
- **THEN** 剪贴板中只有用户选中的可见文字
- **AND** 不会被替换为整条消息正文

#### Scenario: 桌面端选中文字后打开右键菜单
- **GIVEN** 用户已经在消息正文中建立非空选区
- **WHEN** 用户在选区内右键
- **THEN** 显示浏览器原生文本菜单
- **AND** 不显示 IM 的整条消息操作菜单

#### Scenario: 移动端长按选择消息文字
- **WHEN** 用户在移动浏览器中长按消息正文
- **THEN** 可以使用系统文本选择并调整选择范围
- **AND** 不会被 IM 的消息操作菜单替代

### Requirement: 消息级操作可发现且不干扰阅读

#### Scenario: 桌面端按需显示消息操作
- **WHEN** 用户将指针移入一条消息，或使用键盘聚焦其消息操作
- **THEN** 消息旁出现轻量操作入口
- **AND** 提供“复制整条消息”，并仅在该回复确实可 fork 时提供“从此处分支”

#### Scenario: 桌面端普通气泡右键
- **GIVEN** 当前消息内没有文本选区，且用户没有在链接或代码内容上操作
- **WHEN** 用户在消息气泡普通区域右键
- **THEN** 显示短小的消息操作菜单
- **AND** 菜单只包含当前消息可用的复制整条消息和 fork 操作

#### Scenario: 链接与正文选区保留原生右键能力
- **WHEN** 用户在消息链接上右键，或在已有文本选区内右键
- **THEN** 保留浏览器原生的链接或文本操作
- **AND** 不显示 IM 的消息操作菜单

#### Scenario: 移动端打开消息操作
- **WHEN** 用户点击消息元信息旁的更多入口
- **THEN** 显示适合触控的短菜单
- **AND** 提供“复制整条消息”，并仅在该回复确实可 fork 时提供“从此处分支”

#### Scenario: 消息处于普通阅读状态
- **WHEN** 用户没有悬停、聚焦或主动打开消息操作
- **THEN** 消息正文周围不长期展示成排操作按钮或菜单
- **AND** 既有消息信息层级和阅读密度保持克制

### Requirement: 复制整条消息得到可复用正文并获得反馈

#### Scenario: 复制整条富文本消息
- **GIVEN** 消息包含段落、列表、引用、表格、代码或链接
- **WHEN** 用户选择“复制整条消息”
- **THEN** 粘贴结果中的段落、列表项和代码内容仍各自分隔，不挤成一段
- **AND** 具名链接仍能让用户得到链接文字和真实地址

#### Scenario: 有选区时仍可明确复制整条消息
- **GIVEN** 页面中存在非空文本选区
- **WHEN** 用户点击另一条或当前消息的“复制整条消息”
- **THEN** 复制的是用户所操作的完整消息正文
- **AND** 不会误复制页面中原有的局部选区

#### Scenario: 整条复制不混入消息外围信息
- **WHEN** 用户复制整条消息并粘贴到其他输入位置
- **THEN** 结果不包含头像、发送者、时间、耗时、token、过程盘、思考、授权卡或投递状态

#### Scenario: 复制成功
- **WHEN** 用户通过 IM 的消息或代码复制入口完成复制
- **THEN** 页面显示短暂且不打断阅读的“已复制”反馈

#### Scenario: 复制失败
- **WHEN** 浏览器无法完成用户发起的消息或代码复制
- **THEN** 页面明确提示“复制失败，请重试”
- **AND** 用户仍停留在当前聊天和阅读位置

### Requirement: 聊天链接按目标自然导航

#### Scenario: 打开外部网页链接
- **GIVEN** 消息中包含指向 IM 之外网页的链接
- **WHEN** 用户普通点击该链接
- **THEN** 链接在新标签页打开
- **AND** 当前聊天、阅读位置和未发送输入保持不变

#### Scenario: 打开 IM 内部链接
- **GIVEN** 消息中包含指向 IM 内部页面的链接
- **WHEN** 用户普通点击该链接
- **THEN** 在当前产品页内导航

#### Scenario: 操作外部链接
- **WHEN** 用户悬停、键盘聚焦或右键一个外部链接
- **THEN** 具名外链显示轻量的外部跳转提示，直接显示完整网址的链接不重复添加提示
- **AND** 用户能使用浏览器原生链接操作

#### Scenario: 移动端长按外部链接
- **WHEN** 用户在移动浏览器中长按消息里的外部链接
- **THEN** 显示系统提供的链接预览或操作
- **AND** 不显示 IM 的消息操作菜单

#### Scenario: 不支持的链接目标
- **WHEN** 消息内容包含浏览器或产品不支持的链接目标
- **THEN** 页面不把它表现为可正常打开的链接
- **AND** 当前聊天不发生意外跳转

### Requirement: 代码块支持独立精确复制

#### Scenario: 复制单个代码块
- **GIVEN** 一条消息包含一个或多个代码块
- **WHEN** 用户使用某个代码块自己的复制入口
- **THEN** 只复制该代码块中的代码内容
- **AND** 不包含代码围栏、同消息其他正文或其他代码块

#### Scenario: 键盘操作代码复制
- **WHEN** 键盘用户聚焦某个代码块的复制入口并执行复制
- **THEN** 获得与指针用户相同的代码内容和复制反馈

### Requirement: 消息交互跨设备与输入方式保持一致

#### Scenario: 键盘访问消息操作
- **WHEN** 键盘用户依次访问消息级操作、链接和代码复制入口
- **THEN** 每个可操作入口都有清晰焦点状态和可理解名称
- **AND** 菜单关闭后焦点回到发起操作的入口

#### Scenario: 界面语言保持一致
- **GIVEN** 用户当前选择中文或英文界面
- **WHEN** 消息操作入口、菜单、提示或错误出现
- **THEN** 所有新增文案使用当前界面语言
- **AND** 中文界面不出现孤立的英文 `fork`

#### Scenario: 触控入口易于点击
- **WHEN** 用户在移动设备上点击消息更多入口或菜单项
- **THEN** 点击图标周围的可见按钮区域即可稳定完成操作
- **AND** 不需要精确点中图标线条

## 范围与非目标

- 在范围：
  - Web IM 中用户消息与 Agent 消息的正文选择、局部复制、整条复制和复制反馈。
  - 桌面端按需消息操作、上下文感知右键行为和键盘可达性。
  - 移动端原生文本/链接长按与独立消息更多菜单。
  - Agent Markdown 正文中的外部/内部链接导航和链接可达性。
  - 单个代码块复制。
  - 既有 fork 能力在新消息操作入口中的呈现与反馈，不改变 fork 的产品语义。
  - 中文和英文界面的对应文案。
- 非目标：
  - 表情反应、回复、转发、收藏、置顶、删除、编辑、分享等新消息能力。
  - 链接预览卡、外链安全确认页或自定义浏览器菜单。
  - 自制文本选择器、选区悬浮工具条或可见的多种复制格式选项。
  - 附件复制、附件分享或附件菜单。
  - 改变消息发送、历史分页、实时同步、过程盘、授权卡、token 指标或 fork 后端语义。
  - 重做消息气泡、会话布局或整体视觉主题。
