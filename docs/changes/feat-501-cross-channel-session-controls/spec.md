# feat-501: 跨入口会话控制

## Relations

无。

## 原始需求

> 现在连到飞书上，飞书中没法/new，也没法用户主动压缩上下文。你看竞品是不是都有

> 调研好之后，帮我新建unit，和我进行spec对齐。我觉得内部IM和飞书channel都要考虑这个问题

## 澄清记录

- Q1: `/new` 后，是否保留当前聊天界面的可读历史，只让 Agent 从下一条消息起使用全新的上下文？
  A(原话): 当然。这种没有第二选择的问题不用问我
  Agent 解读: `/new` 在原 IM conversation 或飞书 chat 内确认并切换到新的 Agent 上下文；原有可见消息保留，后续消息不再使用旧上下文。

- Q2: 除了裸 `/compact`，本期是否还要支持 `/compact <关注点>` 来指导摘要保留什么？
  A(原话): 按照你在代码仓的理解和分析，独立按照skill进行spec和design完成。我在你做完design后做统一review
  Agent 解读: 用户授权依据当前产品与竞品完成其余取舍；本期纳入 `/compact <关注点>`，飞书与内部 IM 保持一致。

## 用户场景

用户在内部 IM 与 Agent 长时间讨论一个任务后，能直接发送 `/new`。聊天记录仍留在当前对话中供人回看，系统在同一处确认已开始新会话；下一条普通消息开始，Agent 不再把之前任务当作当前上下文。若 Agent 正在执行，`/new` 是明确的放弃边界：用户看到旧操作停止，再看到新会话已就绪，而不是收到一段来自旧任务的迟到回复。

同一用户也能在内部 IM 或飞书中发送 `/compact`，继续当前任务但把较早对话压缩为摘要。用户在任务进入新阶段、却希望保留认证决策等特定事实时，可发送 `/compact 保留认证方案与未完成项`；后续追问仍以这段工作为基础。命令始终给出可见结果：已压缩、当前历史不足以压缩、正在处理因而暂不可压缩，或失败但上下文未改变。

飞书不是例外入口。用户把 `/new` 或 `/compact` 当作普通文本发送给 Bot，得到同一语义的确认；飞书触发的命令及结果会出现在对应内部 IM 影子会话中，方便用户从两个入口连续地理解会话状态。群聊的上下文属于该群与该 Agent 的共同工作线，因此用户需以 `@Bot /new` 或 `@Bot /compact` 明确指向 Bot；确认也回到同一群。

## 验收标准

### Requirement: 用户可在任一聊天入口开始新的 Agent 会话

#### Scenario: 内部 IM 中开始新会话
- **GIVEN** 用户与 Agent 已有多轮内部 IM 对话
- **WHEN** 用户发送 `/new`
- **THEN** 当前对话中出现“已开始新会话”的确认，既有可见消息仍可阅读
- **AND** 用户随后追问时，Agent 不再把先前对话当作当前工作上下文

#### Scenario: 飞书私聊中开始新会话并同步状态
- **GIVEN** 用户在飞书与 Bot 的私聊已有对应内部 IM 影子会话
- **WHEN** 用户在飞书发送 `/new`
- **THEN** 飞书原对话收到已开始新会话的确认
- **AND** 内部 IM 影子会话可看到该命令与同一确认

#### Scenario: 运行中的会话被用户明确换新
- **GIVEN** Agent 正在当前聊天中执行并持续产生回复
- **WHEN** 用户发送 `/new`
- **THEN** 用户看到旧操作已停止且新会话已开始
- **AND** 此后不再收到旧操作继续产生的回复

#### Scenario: 群聊中明确指向 Bot 后开始新会话
- **GIVEN** 飞书或内部 IM 群聊中存在该 Agent 的共同上下文
- **WHEN** 用户发送 `@Bot /new`
- **THEN** Bot 在同一群确认已开始该群的新会话
- **AND** 后续该群对 Bot 的提问不再使用先前共同上下文

### Requirement: 用户可主动压缩当前会话并选择保留重点

#### Scenario: 用户压缩当前会话
- **GIVEN** 当前内部 IM 或飞书聊天已有可压缩的较早对话
- **WHEN** 用户发送 `/compact`
- **THEN** 当前聊天中出现压缩完成的确认
- **AND** 用户随后继续提问时，Agent 仍能延续这段工作的关键信息

#### Scenario: 用户为压缩指定关注点
- **GIVEN** 当前聊天已有可压缩的较早对话，其中包含认证方案和未完成事项
- **WHEN** 用户发送 `/compact 保留认证方案与未完成项`
- **THEN** 当前聊天中出现已按该关注点压缩的确认
- **AND** 用户随后询问认证方案或未完成事项时，Agent 能延续相应信息

#### Scenario: 飞书主动压缩同步到内部 IM
- **GIVEN** 用户在飞书私聊或群聊中与 Bot 继续一段已有上下文的工作
- **WHEN** 用户向 Bot 发送 `/compact` 或 `@Bot /compact <关注点>`
- **THEN** 飞书原聊天收到本次压缩结果
- **AND** 对应内部 IM 影子会话可看到命令与相同结果

#### Scenario: 没有足够历史可压缩时给出明确结果
- **GIVEN** 当前聊天尚未积累可压缩的历史
- **WHEN** 用户发送 `/compact`
- **THEN** 用户看到无需压缩的说明
- **AND** 当前 Agent 上下文保持不变

#### Scenario: 压缩无法完成时不丢失上下文
- **GIVEN** 当前聊天有可压缩的历史
- **WHEN** 用户发送 `/compact`，但压缩未能完成
- **THEN** 用户在原聊天看到失败说明
- **AND** 用户可以继续使用压缩前的上下文对话

#### Scenario: 正在运行时不会静默改变上下文
- **GIVEN** Agent 正在当前聊天执行
- **WHEN** 用户发送 `/compact`
- **THEN** 用户看到需等待当前操作完成或先停止的说明
- **AND** 当前操作与上下文不因该命令被静默改写

## 范围与非目标

- 在范围：内部 IM 与飞书以文本命令提供 `/new`、`/compact` 和 `/compact <关注点>`；命令结果在触发聊天可见，飞书结果同步到内部 IM 影子会话；群聊的控制命令以明确 @Bot 触发。
- 非目标：不创建新的 IM/飞书聊天窗口，不删除可见历史，不改变自动压缩阈值或策略，不增加 `/reset` 等别名，不提供恢复、选择历史会话、按用户拆分群上下文或新的群聊权限模型，也不新增飞书原生 slash-command 菜单。
