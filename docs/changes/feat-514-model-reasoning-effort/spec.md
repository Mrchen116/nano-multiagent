# feat-514: Model reasoning effort

## 原始需求

> 但是现在IM上还没法选。现在只能选模型，没法选推理强度，我觉得应该加上。具体有哪些强度，你应该上网去搜，每个模型对应的支持哪些强度。然后用户先选模型，然后推理强度的那个选项框会按照模型来给选项。

## 澄清记录

- Q1: 对不支持调节强度的模型，配置页应该怎样呈现？
  A(原话): 你从一个商业产品的优差设计的角度去考虑。我没有什么推荐。
  Agent 解读: 采用稳定的“推理”信息位：可调模型显示选择器；固定思考模型显示“始终开启，由模型决定”的只读状态和简短说明，而不显示空白或禁用的伪下拉框。
- Q2: 用户在已有会话中保存新的模型或推理强度后，应该怎样生效？
  A(原话): 跟切换模型是一个设计啊。
  Agent 解读: 推理强度与模型同属一次 Agent 运行配置更新：不打断正在生成的回复，在既有会话的下一轮新回复整体生效并保留历史。

## 用户场景

用户在 Web IM 创建或编辑 Agent 时，会先选择模型。此时他不该记住每个模型的上游参数，更不该面对一个所有模型都长得一样、但提交后才发现不被支持的“推理强度”控件。

当他选择 K3，模型字段下方随即出现“推理强度”，可在低、高、最大之间选择；“高”作为推荐的初始选择。保存后，用户能确定这个 Agent 在之后的每一轮会话中以同一模型和同一强度工作。若他改选 K2.7 Code 或其高速版，原来的可选控件自然变为清晰的只读说明：“始终开启思考，由模型决定”。他不会误解为能力被关闭，也不会以为产品遗漏了可操作项。

模型和推理强度是一组设置。用户在已有对话中更新任一项时，正在生成的回复不被打断；下一轮回复采用保存后的整组设置并继续引用原有历史。用户在模型仍使用平台默认值时，产品不让他孤立设置推理强度，而是说明需要先为 Agent 明确选择模型。

这一体验适用于节点当场声明的每一个模型：产品只给出该模型当前真正支持的选择。模型目录或其可选强度在用户保存前发生变化时，产品不悄悄替换用户的选择；用户会看到需要刷新后重新选择的明确反馈。

## 验收标准

### Requirement: 选择模型后呈现与该模型匹配的推理设置

#### Scenario: 选择可调推理强度的 K3
- **GIVEN** 用户正在 Web IM 的 Agent 创建或编辑页，节点在线且提供 K3
- **WHEN** 用户选择 K3
- **THEN** 页面显示“推理强度”选择器，且只提供低、高、最大三个选项
- **AND** “高”以推荐初始选择呈现

#### Scenario: 未明确选择模型
- **GIVEN** Agent 使用平台默认模型
- **WHEN** 用户查看推理设置
- **THEN** 页面说明需先选择模型才能配置推理强度
- **AND** 用户不能保存一项脱离模型的推理强度

#### Scenario: 模型目录更新使草稿选项失效
- **GIVEN** 用户打开配置页后，节点的模型能力目录已发生变化
- **WHEN** 用户尝试保存当前不再被所选模型支持的推理强度
- **THEN** 页面不显示保存成功
- **AND** 页面明确提示刷新配置后重新选择

### Requirement: 固定思考模型清楚说明限制而不伪造控件

#### Scenario: 选择 K2.7 Code 或高速版
- **GIVEN** 用户正在创建或编辑 Agent
- **WHEN** 用户选择 K2.7 Code 或其高速版
- **THEN** “推理”位置显示“始终开启思考，由模型决定”的只读状态与简短说明
- **AND** 页面不显示空白、禁用或可提交的推理强度下拉框

#### Scenario: 从可调模型切换到固定思考模型
- **GIVEN** 用户已为 K3 选择一项推理强度
- **WHEN** 用户改选固定思考模型
- **THEN** 页面立即移除不适用的推理强度选择
- **AND** 保存后的 Agent 不会携带该固定模型不支持的选择

### Requirement: 模型与推理设置作为同一份 Agent 配置生效

#### Scenario: 新建 Agent 保存模型和推理强度
- **WHEN** 用户创建 Agent，并保存一个支持调节的模型及其推理强度
- **THEN** 创建完成后的配置页显示保存的模型和推理强度
- **AND** 用户与该 Agent 开始对话时，首轮即使用这组设置

#### Scenario: 既有对话中更新模型或推理强度
- **GIVEN** Agent 正在用当前设置生成回复，或已有历史会话
- **WHEN** 用户保存新的模型、推理强度，或两者同时保存
- **THEN** 当前已开始的回复不在中途切换
- **AND** 同一会话的下一轮新回复使用保存后的整组设置并保留历史

#### Scenario: 保存失败时保留可理解的编辑状态
- **WHEN** 用户保存模型与推理设置失败
- **THEN** 页面保留用户尚未成功保存的选择
- **AND** 显示可理解的失败原因，而不把未生效的值展示为已保存

## 范围与非目标

- 在范围：Web IM 的 Agent 创建和编辑体验；每个在线节点已注册模型的可选推理能力；模型与推理设置的持久化、下一轮整体生效和明确失败反馈。
- 非目标：在单条聊天消息上临时覆盖模型或推理强度；向用户展示上游协议参数；为没有上游可调强度的模型虚构档位；修改自动工具审批分类的固定无思考行为。
