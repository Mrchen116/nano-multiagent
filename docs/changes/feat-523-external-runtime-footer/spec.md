# feat-523: External runtime presentation

## 原始需求

> 我觉得没必要，你帮我仿照他的机制，让我的外部channel也能show 模型和context_pct。设计上要所有外部channel都支持，虽然现在只有飞书channel

## 澄清记录

- Q1: 外部 channel 的模型 / context 页脚应默认开启，还是默认关闭、配置开启？
  A(原话): 「我觉得没必要，你帮我仿照他的机制，让我的外部channel也能show 模型和context_pct。设计上要所有外部channel都支持，虽然现在只有飞书channel」「我问你，Hermes是这样的吗」
  Agent 解读: 以已核实的 Hermes 语义为准：默认关闭；可全局开启，并允许单一外部 channel 覆盖；开启后只显示该轮最终回复的运行信息。用户要求 Nano 只显示 `model` 与 `context_pct`，不包含 Hermes 支持的 `cwd`。

- Q2: 运行信息不完整时应如何显示？
  A(原话): 「仿照他的机制」
  Agent 解读: 沿用 Hermes 的可见语义：缺少某一项时静默省略该项；若两项均不可用，则不增加空白页脚或占位符。

- Q3: 飞书中的运行信息应作为普通文本页脚，还是卡片？
  A(原话): 「NO啊，Hermes不是这个效果的，他是有卡片的啊」
  Agent 解读: 飞书的普通最终回复必须以一张原生卡片呈现：正文在上，底部有紧凑的运行信息区；不能把运行信息另发成普通消息，也不能只在普通文本正文后追加一行。其他当前或未来外部 channel 仍由同一 Gateway 语义得到运行信息，但按各平台能力呈现。

## 用户场景

用户在飞书等外部 IM 与自己的 Agent 对话时，希望在一轮回答真正结束后，一眼确认这轮实际使用的模型和上下文占用，而不是从中间进度、工具过程或内部 Web IM 中猜测运行状态。当前只有飞书接入；飞书必须把正文和这两项信息放进一张原生卡片，底部以紧凑信息区呈现。这个能力仍属于 Gateway 的外部 channel 体验：未来新增的外部 channel 在启用后也获得同样的最终回复运行信息，而不需要各自重写其语义。

用户或运维者可以选择是否暴露该运行信息。默认对外保持简洁；全局启用后，各外部 channel 的最终回复显示简洁的模型与 context 百分比，例如 `gpt-5.4 · ctx 42%`。若某个 channel 不适合显示，单独关闭它即可。用户看到多条过程性消息时，只有这一轮的普通最终回答携带运行信息；不把工具进度、审批卡、控制确认或空回复误标成最终运行结果。

## 验收标准

### Requirement: 外部 channel 的最终回复可显示运行信息

#### Scenario: 已启用的飞书最终回复是一张带运行信息的原生卡片
- **GIVEN** 外部 channel 的运行信息页脚已启用，且本轮 Agent 最终回复具有模型名与上下文占用数据
- **WHEN** 用户从飞书发起一轮普通对话并收到最终回复
- **THEN** 用户收到一张原生飞书卡片，卡片上部是原最终回复正文
- **AND** 同一张卡片底部有紧凑运行信息区，显示模型名与上下文占用百分比，例如 `gpt-5.4 · ctx 42%`
- **AND** 不额外发送独立的运行信息消息，也不把该信息作为普通文本追加到正文后

#### Scenario: 已启用的其他外部 channel 显示运行信息
- **GIVEN** 某个已接入的非飞书外部 channel 的运行信息已启用，且本轮 Agent 最终回复具有模型名与上下文占用数据
- **WHEN** 用户从该 channel 发起一轮普通对话并收到最终回复
- **THEN** 最终回复以该 channel 支持的呈现方式显示模型名与上下文占用百分比，例如 `gpt-5.4 · ctx 42%`

#### Scenario: 中间消息不显示运行信息
- **GIVEN** 已启用外部 channel 的运行信息页脚
- **WHEN** 同一轮处理先产生过程性文字、工具进度、审批卡或控制确认，再产生普通最终回复
- **THEN** 只有普通最终回复显示运行信息
- **AND** 过程性文字、工具进度、审批卡和控制确认不显示该运行信息

#### Scenario: 运行信息不完整时不显示虚假占位
- **GIVEN** 外部 channel 的运行信息页脚已启用
- **WHEN** 最终回复只能取得模型名或上下文占用中的一项
- **THEN** 运行信息区只显示可取得的一项，不显示空字段或未知占位符
- **WHEN** 两项均不可取得
- **THEN** 最终回复不增加空白运行信息区

#### Scenario: 飞书卡片正文超出单卡可发送大小时保持一张可读卡片
- **GIVEN** 飞书运行信息已启用，且普通最终回复的正文在连同运行信息区编码后超出单张飞书卡片的可发送大小
- **WHEN** 用户收到该最终回复
- **THEN** 用户仍只收到一张原生飞书卡片
- **AND** 卡片正文保留开头的可读内容并以明确的截断标记结束
- **AND** 卡片底部仍显示本轮可取得的运行信息，不额外发送普通文本或第二张卡片

### Requirement: 运行信息按外部 channel 配置控制

#### Scenario: 默认不暴露运行信息
- **GIVEN** Gateway 未显式启用外部 channel 的运行信息
- **WHEN** 用户从任一外部 channel 收到普通最终回复
- **THEN** 回复不显示模型名或上下文占用运行信息

#### Scenario: 全局开启覆盖所有外部 channel
- **GIVEN** Gateway 已全局启用运行信息
- **WHEN** 用户从飞书或未来接入的任一外部 channel 收到普通最终回复
- **THEN** 该外部 channel 的最终回复都显示运行信息

#### Scenario: 单一外部 channel 可以覆盖全局设置
- **GIVEN** Gateway 已全局启用运行信息
- **WHEN** 某一外部 channel 被单独关闭该功能
- **THEN** 该 channel 的最终回复不显示运行信息
- **AND** 未单独关闭的外部 channel 继续显示运行信息

#### Scenario: 单一外部 channel 可以独立开启
- **GIVEN** Gateway 未全局启用运行信息
- **WHEN** 某一外部 channel 被单独开启该功能
- **THEN** 该 channel 的普通最终回复显示运行信息
- **AND** 未单独开启的外部 channel 保持不显示

### Requirement: 内部 Web IM 保持原有消息体验

#### Scenario: 内部 Web IM 不显示外部页脚
- **GIVEN** Gateway 已为外部 channel 启用运行信息
- **WHEN** 用户在内部 Web IM 发起一轮对话并收到回复
- **THEN** 内部 Web IM 回复不显示该外部 channel 运行信息

## 范围与非目标

- 在范围：所有外部 channel 的可配置最终回复运行信息；飞书以原生卡片呈现并在单卡大小超限时明确截断正文；本期字段仅为模型名与上下文占用百分比；默认关闭、全局开启和单一 channel 覆盖；飞书作为首个真实外部 channel 验证入口。
- 非目标：在内部 Web IM 显示运行信息；显示工作目录、精确 token 数、费用、耗时、session ID、工具调用次数或其他运行指标；把运行信息加到中间进度、审批卡、控制确认或调试消息；把飞书卡片复制为独立的第二条消息；为未来 channel 单独复制一套运行信息语义；在卡片大小超限时拆分为多条飞书消息。
