# feat-542: Gateway 可配置的 macOS 登录自启

## 原始需求

> 设计下，我们要弄成真正的常驻，用户可以选择是否开机自启，在配置文件中设置。

## 澄清记录

- Q1: 配置文件里的开机自启只管理 Gateway 本身，还是还要连带管理 IM 与本机 LLM 代理？
  A(原话): 只管理 Gateway 本身。IM是远端的
  Agent 解读: 本 unit 只负责 Gateway 的系统常驻；IM 与 LLM 代理不受该配置项控制。

- Q2: 现有配置没有开机自启字段时，升级后默认开启还是默认关闭？
  A(原话): 默认开
  Agent 解读: 缺省字段与显式开启具有相同语义；既有用户升级后进入默认开机自启策略。

- Q3: 修改或升级配置后，开机自启设置在什么时候真正生效？
  A(原话): 好
  Agent 解读: 下一次正常执行 Gateway `start` 或 `restart` 时自动对齐系统服务；开启则创建或更新服务并由其启动，关闭则移除服务后沿用当前后台启动方式。

- Q4: 开启开机自启后，Gateway 运行中意外退出时是否也要由系统自动拉起？
  A(原话): 好
  Agent 解读: 开启后同时具备登录或开机拉起与异常退出恢复；人工 `stop` 必须被识别为有意停止，不能立即自动拉起。

- Q5: 配置仍为开启时，用户手工执行 `stop` 后，下次开机是否重新自动启动？
  A(原话): 好
  Agent 解读: `stop` 只停止当前运行期；配置仍开启时下次登录或开机重新启动，长期关闭以配置文件为准。

- Q6: 本期把开机自启支持做到哪些操作系统？
  A(原话): 好
  Agent 解读: 本期只支持 macOS；Linux systemd 与 Windows 服务不在范围内。

- Q7: macOS 上的“开机自启”要求系统尚未登录用户时就运行，还是用户登录后自动运行即可？
  A(原话): 好
  Agent 解读: 使用用户级系统服务，在用户登录后自动启动；不要求登录前运行，也不要求管理员权限。

- Q8: 配置要求开机自启，但系统服务注册或启动失败时，Gateway 应拒绝启动，还是降级为现有后台模式并明确告警？
  A(原话): |-
    你意思是在我改完配置，start 或者restart的时候？
    **降级为现有后台模式，同时让启动命令明确显示“Gateway 已运行，但开机自启配置失败”**。我觉得合理
  Agent 解读: 该失败语义发生在用户修改配置后执行 `start` 或 `restart` 时；Gateway 保持本次可用，但必须明确说明没有获得跨登录重启与异常退出恢复能力。

## 用户场景

macOS 用户把个人助手 Gateway 作为自己账户下的长期节点使用。用户只需在 Gateway 的本地配置文件里选择是否登录后自动启动；没有写该选项时默认开启。修改配置后，用户照常执行一次启动命令（无子命令）或 `restart`，产品便让长期意图生效，不再要求另记一套系统服务安装命令。

开启后，用户登录 macOS，Gateway 会在不需要手工敲命令的情况下恢复运行并重新上线；进程意外退出时也会自动恢复。用户显式执行 `stop`，表示本次登录期间有意停机，Gateway 不会立刻反复拉起；只要配置仍为开启，下次登录仍会自动运行。用户若要长期关闭自启，则修改配置后再次执行 `start` 或 `restart`。

如果用户要求开启自启、但应用该设置失败，当前 Gateway 仍以普通后台方式运行，避免助手当场不可用；启动命令同时明确告诉用户“当前可用，但没有开机自启和异常恢复”，不能把降级状态显示为成功。

该选择只管理 Gateway。远端 IM、本机或远端 LLM 代理及其他基础设施保持各自独立的生命周期。

## 验收标准

### Requirement: 用户通过本地配置选择 Gateway 是否登录自启

#### Scenario: 缺省配置默认开启自启
- **GIVEN** macOS 用户的既有 Gateway 配置没有写自启选项
- **WHEN** 用户升级后首次执行启动命令（无子命令）或 `restart`
- **THEN** 启动结果明确显示 Gateway 已启用登录自启并正在运行

#### Scenario: 显式开启自启
- **GIVEN** macOS 用户在 Gateway 配置中开启自启
- **WHEN** 用户执行启动命令（无子命令）或 `restart`
- **THEN** 启动结果明确显示 Gateway 已启用登录自启并正在运行

#### Scenario: 显式关闭自启
- **GIVEN** macOS 用户在 Gateway 配置中关闭自启
- **WHEN** 用户执行启动命令（无子命令）或 `restart`
- **THEN** Gateway 本次仍按普通后台方式运行，启动结果明确显示登录自启已关闭
- **AND** 用户下一次登录后，Gateway 不会自行启动

#### Scenario: 编辑配置后尚未重新启停
- **WHEN** 用户只修改自启选项，尚未再次执行启动命令（无子命令）或 `restart`
- **THEN** 当前运行方式保持不变，不把尚未应用的配置显示为已经生效

### Requirement: 开启后 Gateway 由系统持续保持在线

#### Scenario: 用户登录后自动上线
- **GIVEN** Gateway 自启已成功启用
- **WHEN** 用户重新登录 macOS
- **THEN** 无需手工执行 Gateway 命令，Gateway 会自动运行并恢复其节点与消息入口

#### Scenario: 意外退出后自动恢复
- **GIVEN** Gateway 自启已成功启用且正在运行
- **WHEN** Gateway 进程意外退出
- **THEN** 无需用户手工干预，Gateway 会自动重新运行并恢复其节点与消息入口

### Requirement: 人工停止与长期自启意图互不混淆

#### Scenario: 人工停止不被立即拉起
- **GIVEN** Gateway 自启已成功启用且正在运行
- **WHEN** 用户执行 `stop`
- **THEN** Gateway 在本次登录期间保持停止，不会被立即自动拉起

#### Scenario: 临时停止后下次登录恢复
- **GIVEN** 用户执行过 `stop`，但配置中的自启仍为开启
- **WHEN** 用户下一次登录 macOS
- **THEN** Gateway 自动运行并恢复其节点与消息入口

### Requirement: 自启应用失败时保持当前可用并如实反馈

#### Scenario: 开启自启失败后降级运行
- **GIVEN** macOS 用户的配置要求开启自启
- **WHEN** 用户执行启动命令（无子命令）或 `restart`，但自启设置未能成功应用
- **THEN** Gateway 仍以普通后台方式运行
- **AND** 命令结果明确区分“Gateway 当前已运行”和“登录自启及意外退出恢复未生效”，并给出可继续排查的错误

## 范围与非目标

- 在范围：macOS 上 Gateway 的配置选择、默认开启、下一次启动（无子命令）/ `restart` 应用、登录后启动、异常退出恢复、人工临时停止，以及自启失败时的可见降级反馈。
- 在范围：现有配置缺少新选项时按开启处理，并让生产部署流程在重启 Gateway 时自动迁移到系统常驻。
- 非目标：登录 macOS 用户之前启动 Gateway，或要求管理员权限的系统级服务。
- 非目标：管理远端 IM、LLM 代理、SearXNG 或其他外部依赖的生命周期。
- 非目标：Linux systemd、Windows Service 或跨平台服务管理抽象。
- 非目标：在 Web IM 中增加自启设置页面；本期只以本地配置文件为入口。
