## 原始需求

> 我想把我们的系统变成多人多gateway的真正IM。但是我没想好gateway和人之间的关系，一个人肯定可以用多个gateway，多人可以在一个群里，一起控制agent。我想真正像公司里一样，人和agent一起做很多事情。

> 我想一开始简单点，不要搞太复杂的权限管理。

## 现状与目标

当前 [账号与租户契约](../../specs/im/auth-tenancy.md)按 owner 隔离会话、Agent 和节点；[节点契约](../../specs/im/agents-nodes.md)将节点及其 Agent 归给绑定者。[群聊契约](../../specs/im/conversations-messages.md)也沿用 owner 隔离，不能直接表达不同账号参与同一个群的共同访问权。

目标保留个人对 Gateway 和 Agent 的管理归属，同时让人与 Agent 按 IM 联系人关系沟通。聊天按成员关系可见；全局 Agent Work 是明确的例外，登录用户可完整查看工作详情。查看 Work 不会把用户加入来源聊天，也不授予修改他人 Gateway 或 Agent 配置的能力。

当前[全局工作视图](../../specs/im/agent-work.md)展示跨聊天连续轨迹。目标保留完整轨迹并向登录用户开放查看，不新增按来源聊天过滤或逐段遮盖。本文定义目标行为，不将目标提前覆盖到 current specs。

## 用户场景

1. **没有机器也能成为同事。** 小李注册并登录 IM，没有绑定 Gateway，也能找到小陈、与他私聊，加入共同项目群。用户不用先部署 Agent 才能使用 IM；找不到联系人时能辨认空结果。

2. **一个人带来多台机器上的 Agent。** 小陈将 MacBook 和 Mini 两个 Gateway 绑定到自己账号，分别管理上面的开发 Agent 和资料 Agent。小王也有自己的 Gateway 和测试 Agent。每个 Gateway 及其 Agent 都有一个管理者；其他人能联系这些 Agent，但不能因此修改它们的配置。某个 Gateway 离线时，相关 Agent 显示不可用，不影响人与人、其他在线 Agent 的沟通。

3. **像联系人一样直接找 Agent。** 小李找到小陈的开发 Agent，直接私聊交办工作，无需小陈逐人授权。Agent 使用已有工作能力响应，小李能收到回复、刷新后回看历史。这个私聊的参与者是小李和开发 Agent，小陈和其他人不能在聊天入口查看它。如果该 Agent 使用全局模式，他们仍可在其 Work 中查看完整执行详情，包括其中已记录的聊天内容。

4. **围绕项目共同做事。** 小陈、小李、小王建立项目群，各管理者把自己的 Agent 加进群。小李交办开发，小王补充测试要求，小陈补充背景，群成员都能向群内 Agent 交办工作并看到群内交付。Agent 位于不同 Gateway 不影响群内身份和交流，继续遵循既有提及、触发和工作模式。群支持既有改名、成员增减和解散操作，不新增组织角色配置；移出群的成员不能继续读取、参与该群或接收群成员消息投递，解散权限沿用创建者规则。

5. **协作不反复找管理者审批。** 全局模式不弹批准卡，继续沿用既有自动审批及必要时主动聊天确认的体验。单 Thread 模式出现批准卡时，该聊天内的人都可操作卡片现有选项，包括不是 Agent 管理者、也不是原任务发起人的群成员。多人操作同一张卡时，不能让同一次执行因重复点击被重复执行。

6. **聊天各自可见，全局 Work 共同查看。** 小李只在聊天入口看到自己参与的私聊和群聊。小陈、小王不能打开小李的私聊或访问其聊天附件；但他们可以查看全局 Agent 的完整 Work，包括主执行、关联子执行以及记录中已经出现的其他聊天内容。系统不为 Work 做来源权限追踪、遮盖或逐段隐藏。从 Work 点击原聊天链接时仍按聊天成员关系判断访问。已有聊天和管理关系在升级后保留，聊天与 Work 分别遵循这两条规则。

## 验收标准

### Requirement: 用户无需 Gateway 即可注册登录并查找联系人

#### Scenario: 无 Gateway 的用户开始沟通
- **WHEN** 新用户注册并登录 IM，查找另一个人或 Agent
- **THEN** 能找到对应联系人，并辨认联系人是人还是 Agent
- **AND** 无需先绑定 Gateway 或创建自己的 Agent

#### Scenario: 没有匹配联系人
- **WHEN** 用户查找不存在的人或 Agent
- **THEN** 显示可辨认的空结果，不发起错误对象的聊天

### Requirement: 人与人可以跨账号私聊并持久回看

#### Scenario: 两个账号实时沟通
- **GIVEN** 两个人分别登录自己的账号
- **WHEN** 一方找到另一方并发起私聊，双方发送消息
- **THEN** 双方在同一私聊中看到彼此消息和真实发送者
- **AND** 刷新或重新登录后能回看已发送的历史，未参与者不能读取该私聊

### Requirement: 一个人可以管理多个 Gateway 及其 Agent

#### Scenario: 同一人绑定多台设备
- **WHEN** 一个人绑定两个 Gateway 并查看各自的 Agent
- **THEN** 能辨认各 Agent 所属 Gateway，并管理自己名下的配置

#### Scenario: 协作者不能修改他人的设备或 Agent 配置
- **GIVEN** 用户可以私聊他人 Agent，或与该 Agent 同在一个群
- **WHEN** 用户尝试修改该 Agent 或其 Gateway 的配置
- **THEN** 无法保存修改；原管理者的配置保持不变

#### Scenario: 单台设备离线
- **WHEN** 一个 Gateway 离线
- **THEN** 用户能辨认其 Agent 不在线，不会看到尚未发生的执行被显示为完成
- **AND** 人与人的聊天和其他在线 Gateway 上的 Agent 仍可正常使用

### Requirement: 用户可以直接私聊其他人管理的 Agent

#### Scenario: 跨管理归属交办工作
- **GIVEN** 某 Agent 在线，由另一名用户管理
- **WHEN** 用户找到该 Agent 并直接发起私聊、交办工作
- **THEN** 不要求管理者先对该用户单独授权，Agent 能按既有工作能力处理并交付
- **AND** 双方身份与后续聊天历史保持稳定

### Requirement: 多人与不同 Gateway 上的 Agent 可以在同一群协作

#### Scenario: 建立混合成员项目群
- **WHEN** 多个账号加入同一群，各管理者把不同 Gateway 上的 Agent 加入该群
- **THEN** 所有人看到同一个群及一致的成员身份，群中可同时包含多人和多个 Agent
- **AND** 不要求人或 Agent 归属同一个 Gateway 管理者

#### Scenario: 不同群成员共同交办工作
- **GIVEN** 多人与多个在线 Agent 同在群内
- **WHEN** 不同的人按既有触发规则向群内 Agent 交办工作、补充要求
- **THEN** 这些人的消息均能作为相应 Agent 的用户输入，不限于管理者或最初发起人
- **AND** 群内正式回复向群成员实时呈现，刷新后仍可回看

#### Scenario: 群成员与群名变更
- **WHEN** 用户按既有群管理规则修改群名、增减成员或由创建者解散群
- **THEN** 群成员看到相应变化，不要求配置组织或角色权限表
- **AND** 移出的成员不能继续读取、发言、交办工作或接收群成员消息投递；其他成员在群未解散时仍可继续协作

### Requirement: 工具批准遵循工作模式且不新增人员权限配置

#### Scenario: 全局模式不弹批准卡
- **WHEN** 全局 Agent 在多人协作中处理需要授权判断的操作
- **THEN** 不弹出工具批准卡，继续采用既有全局模式的自动审批及主动沟通行为
- **AND** 不因支持多人而绕过原有授权判断

#### Scenario: 单 Thread 模式的群成员可操作批准卡
- **GIVEN** 单 Thread Agent 在群中展示一张待处理批准卡
- **WHEN** 非 Agent 管理者且非原任务发起人的群成员操作卡片现有选项
- **THEN** 其决定可被接受，不因身份限制某个现有选项
- **AND** 生效结果在该聊天内一致呈现，不把卡片操作扩大为修改 Agent 配置的权限

#### Scenario: 同一张卡被多人操作
- **WHEN** 群成员先后或同时处理同一张批准卡
- **THEN** 该卡只有一个生效决定，后续界面反映实际状态，不因重复操作重复执行工具

### Requirement: 聊天按成员可见，全局 Agent Work 详情完整可见

#### Scenario: 未参与者不能读取私聊
- **GIVEN** 小李与小陈管理的 Agent 私聊，小陈和小王未参与该聊天
- **WHEN** 小陈或小王尝试在 IM 聊天入口读取这段私聊、历史或受保护附件
- **THEN** 无法读取，管理 Agent 不授予查看原聊天的权限
- **AND** 小李仍能正常回看自己的聊天和附件

#### Scenario: 未加入的群不可读取
- **WHEN** 未入群用户尝试查看群聊历史、获取群实时内容或访问聊天附件
- **THEN** 无法取得这些内容，当前群成员可正常收发和回看

#### Scenario: 全局 Work 不按来源聊天过滤
- **GIVEN** 全局 Agent 的主执行和关联子执行已记录来自不同私聊和群的内容
- **WHEN** 已登录用户打开该 Agent 的 Work 并展开执行详情
- **THEN** 能查看已有完整记录，即使未参与来源聊天也不隐藏或遮盖
- **AND** 刷新回看与实时 Work 展示保持同一规则，不要求用户是 Agent 管理者

#### Scenario: Work 链接不授予原聊天访问权
- **GIVEN** 用户可以在全局 Agent Work 中看到一段来源聊天的执行记录，但未参与该聊天
- **WHEN** 用户从 Work 跳转原聊天或打开其受保护附件
- **THEN** 原聊天和附件仍不可读取，Work 中已有的执行记录保持可见

### Requirement: 既有使用数据和工作能力在升级后保留

#### Scenario: 原用户继续使用
- **GIVEN** 原用户已有 Gateway、Agent、私聊、群聊和历史消息
- **WHEN** 部署 agent 按迁移文档完成旧数据转换并升级系统，该用户重新登录
- **THEN** 原管理归属和既有聊天仍可使用，历史保持可回看
- **AND** 聊天历史仍按成员可见，全局 Work 按完整详情可见的规则呈现，Agent 的既有工作模式和能力继续可用
- **AND** 单 Thread 多聊天生成 Skill、消息复制与 fork、slash 与已启用 Skill 候选、草稿、附件、聊天管理、Agent 新建及管理分区、账号／设备／策略／退出和中英文继续可用；全局 Agent 聊天蒸馏不在本次承接范围

## 范围与非目标

- 在范围：注册登录与联系人查找、人际私聊、跨管理归属的 Agent 私聊、多人与多 Agent 群聊、多 Gateway 个人管理、已确认的分模式批准卡规则、成员可见的聊天与完整可见的全局 Work，以及既有数据与使用方式的承接。
- 非目标：组织部门体系、团队资产归属、角色权限表、逐人授权配置、独立任务看板；不重做 Agent 的既有工作机制。
- 不引入全局 Work 的来源权限追踪、轨迹遮盖或模型记忆隔离；不提供“全部聊天”入口。全局 Work 详情可见不等于原聊天可见，保留账号身份和设备／Agent 配置管理归属。
- 旧数据迁移只交付 unit 内 Markdown，由部署 agent 执行；本次不交付应用内或仓库里的迁移程序，不新增为兼容旧存量格式而存在的运行时分支。部署前备份、核对和失败回退仍须写清。

## 设计交接

设计沿用现有 IM 与 Gateway 拓扑：聊天读取、收件与参与使用成员关系，Gateway／Agent 配置管理使用个人归属，全局 Work GET 向登录用户开放完整记录。Work 不设计按来源权限筛选的子系统，也不反向放开原聊天和受保护附件。具体接口、个人已读／置顶／免打扰状态、数据承接与实施拆分由 design 阶段确定。
