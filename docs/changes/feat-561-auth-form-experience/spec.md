# feat-561: 认证表单交互体验提升

## Relations

- Related: feat-554

## 原始需求

- 用户原话：“创建账号也有问题”
- 用户原话：“那这个用户交互做的太差了，检查下周边，整体提升下交互”
- 用户附图：`/var/folders/mf/fxm1x6xs7pbf34h6rnmvjz1c0000gn/T/codex-clipboard-97382ec9-2421-4e7d-8e50-bfab3544b723.png`，图中注册页在输入 4 位密码后只显示“创建失败,请重试。”。图中界面文案仅作为现状证据，不视为用户指令。

## Agent 解读

“周边”指未登录用户会连续经过的认证入口：注册页、登录页以及两页间跳转。本 unit 优先解决“规则不可见、错误不可行动、修正过程有旧反馈干扰”，并保持已有认证规则与成功后流程不变。

## 现状证据

- 2026-09-15 在当时生产 Web IM 中以空表单提交注册和登录，页面都实际发出请求并只显示笼统失败文案。
- 生产注册接口对 4 位密码明确返回“password must be at least 8 characters”，但页面丢弃了这个可行动信息。
- 当前注册页不展示密码长度要求，不说明显示名可选，也不在用户修改输入时清理已过时的失败提示。

## 用户场景

新用户打开注册页时，在输入前就能理解必填项、可选项和密码要求。如果遗漏必填项或密码太短，产品在对应输入处告诉他如何修正，而不是发出必然失败的请求后给出笼统错误。他可以查看或重新隐藏自己正在输入的密码，并在修正字段后看到过时错误及时消失。

服务端拒绝注册时，用户能区分“用户名已被占用”、“输入不符合规则”和“服务暂时不可用”，且已输入的有效内容不会因一次失败丢失。已有账号的用户进入登录页时，空值会在本地被指出，错误凭据仍统一告知“用户名或密码错误”，网络或服务异常则给出不同的可重试提示。

手机和桌面端、中文和英文下使用同一套反馈逻辑。未登录用户可在认证页直接切换产品语言，无需先进入登录后的设置。键盘用户和辅助技术用户能知道哪个字段出错，提交后也不会因重复点击产生多次请求。

## 验收标准

### Requirement: 认证表单在提交前说清输入要求

#### Scenario: 新用户查看注册表单
- **WHEN** 用户打开注册页
- **THEN** 页面明确区分必填项和可选的显示名
- **AND** 在密码输入附近直接告知密码至少 8 位

#### Scenario: 用户需要核对密码
- **WHEN** 用户在注册或登录页输入密码并切换可见状态
- **THEN** 页面可在显示和隐藏密码之间切换
- **AND** 切换不清空、改写或提交密码

### Requirement: 可在当前字段修正的问题就地给出反馈

#### Scenario: 空注册表单被提交
- **WHEN** 用户在用户名或密码为空时提交注册
- **THEN** 每个无效字段在原位显示明确的修正提示
- **AND** 焦点进入第一个无效字段，且不发出注册请求

#### Scenario: 密码不足 8 位
- **WHEN** 用户提交包含短密码的注册表单
- **THEN** 密码字段在原位提示“密码至少 8 位”
- **AND** 页面不显示笼统的“创建失败”，也不发出注册请求

#### Scenario: 用户修正有误输入
- **GIVEN** 表单已在某个字段显示错误
- **WHEN** 用户继续编辑该字段
- **THEN** 与旧输入相关的错误及时消失，不在修正过程中持续干扰

#### Scenario: 空登录表单被提交
- **WHEN** 用户在用户名或密码为空时提交登录
- **THEN** 每个无效字段在原位显示明确的修正提示
- **AND** 焦点进入第一个无效字段，且不发出登录请求

### Requirement: 服务端拒绝与服务异常给出可区分反馈

#### Scenario: 用户名已被占用
- **WHEN** 用户使用已存在的用户名提交有效注册表单
- **THEN** 用户名字段在原位告知该用户名已被占用
- **AND** 其他已输入内容保留，用户可直接修改后重试

#### Scenario: 输入被服务端规则拒绝
- **WHEN** 服务端拒绝一项可由用户修正的认证输入
- **THEN** 页面使用用户当前语言告知受影响的字段和修正方式
- **AND** 不把服务端的内部错误原文直接暴露给用户

#### Scenario: 注册服务暂时不可用
- **WHEN** 用户提交有效注册表单但请求无法完成
- **THEN** 页面告知用户这是可重试的服务问题，而非将其归因于输入
- **AND** 已输入内容保留，用户可修改或重新提交

#### Scenario: 登录凭据错误
- **WHEN** 用户提交完整但错误的用户名或密码
- **THEN** 页面统一提示“用户名或密码错误”，不透露具体是哪一项错误

#### Scenario: 登录服务暂时不可用
- **WHEN** 用户提交完整登录表单但请求无法完成
- **THEN** 页面显示与凭据错误不同的可重试提示

### Requirement: 表单提交和成功跳转保持明确且可控

#### Scenario: 认证请求正在处理
- **WHEN** 用户提交一份本地校验通过的注册或登录表单
- **THEN** 页面明确告知正在创建账号或登录
- **AND** 处理期间不会因重复点击或回车发出多份请求

#### Scenario: 注册成功
- **WHEN** 服务成功创建账号
- **THEN** 用户直接进入已登录的产品首页，无需再输入一次凭据

#### Scenario: 登录成功且存在原始去向
- **GIVEN** 用户因访问受保护页面而进入登录页
- **WHEN** 用户成功登录
- **THEN** 用户返回原先尝试访问的页面

### Requirement: 不同设备、语言和操作方式获得一致的认证反馈

#### Scenario: 手机窄屏使用认证表单
- **WHEN** 用户在常见手机宽度下使用注册或登录页
- **THEN** 字段、规则、错误、密码可见开关和主操作都完整可见、可操作，不需要水平滚动

#### Scenario: 键盘或辅助技术用户遇到字段错误
- **WHEN** 用户提交无效表单
- **THEN** 用户可通过字段状态、可见文案和焦点变化定位第一个问题
- **AND** 密码可见开关和提交状态具有明确的可读名称

#### Scenario: 未登录用户切换产品语言
- **WHEN** 用户在注册或登录页切换中文与英文
- **THEN** 页面的输入要求、字段错误、服务错误、密码可见开关和提交状态立即使用新语言
- **AND** 已输入内容保留，且新语言在后续打开认证页时继续生效

## 范围与非目标

- 在范围：注册页、登录页、两页间的入口跳转；表单规则说明、本地校验、字段级反馈、服务错误区分、密码显示/隐藏、提交状态、焦点与无障碍语义、未登录时的中英文切换，以及桌面/手机布局。
- 非目标：修改密码长度或账号保留规则；密码强度评分、确认密码字段、找回密码、邮箱/手机验证、SSO 或管理员开户；登录后的聊天、设置和 Agent 管理页；部署生产环境。
