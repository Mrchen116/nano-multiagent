# kernel runs Specification (delta for feat-563)

## ADDED Requirements

### Requirement: SDK 消费者可在普通回复公开前处理完整候选与恢复失败

消费者可选择接入产品输出处理；未选择的消费者保持原正文、工具和运行行为。输出处理获得真实运行身份、完整模型轮正文与受运行绑定的权限/提交能力；不授予模型新的工具，不绕过既有权限策略。

#### Scenario: 交付失败且没有新输入时继续
- **WHEN** 消费者将尚未公开的候选报告为交付失败
- **THEN** 内核保留候选及未发送状态，向模型提供系统反馈，在既有预算内继续同一运行，即使没有新的用户输入
- **AND** 反馈说明参与者未收到该草稿、更早成功发布消息仍可见，后续回复应补全收件人仍需的信息；失败不冒充新用户输入。

#### Scenario: 消费者检查候选操作权限
- **WHEN** 消费者在输出处理回调中检查一次读取并发送图片的操作
- **THEN** 检查沿用该运行的工具权限策略、来源上下文、交互和取消语义，不执行对应工具，不生成伪造的模型工具调用或重复审批。

#### Scenario: 准备期间收到新输入
- **GIVEN** 消费者启用了输入复核
- **WHEN** 输出准备期间接受了本轮尚未采纳的新输入
- **THEN** 原候选不能提交，既有未发送草稿与新输入恢复语义保持，准备过程不持有同步提交锁。

#### Scenario: 已交付与不确定结果保持真实语义
- **WHEN** 消费者报告已交付、部分交付或结果未确认
- **THEN** 内核记录真实状态，不将已交付候选重复公开，不将部分/未知结果描述为整条消息从未发送。

#### Scenario: 限制与默认消费者
- **WHEN** 运行被取消、达到预算限制，或消费者未启用该能力
- **THEN** 前两者按既有规则结束且不强制发布失败草稿；未启用者保持原有行为。
