## 用户场景

用户在 iPhone 15 Pro Max / iOS 26.4 打开独立 Nano IM App，使用已有账号进入与 Web 相同的聊天、任务、Agent 和“我的”。全部产品界面为原生界面，首版不以打开 Web 页面代替管理功能。既有服务地址为 `https://im.nanoim.win/`；本期独立于 Web 的键盘与导航修复。

用户在手机读历史、发文字和附件、群聊提及 Agent、查看实时回复、工具明细和权限审批；从任务节点回到真实聊天继续讨论，查看全局 Agent 主/子工作轨迹。切换 App 后回来能继续当前工作，掉线不误显示成功，账号切换不残留他人数据。

用户在手机完成现有 Web 的所有管理工作：创建设备上的 Agent、编辑模型与备用模型/推理强度/指令/能力、看提示词预览及 Skill 使用情况、管理心跳与现有定时任务、添加和维护外部通道、确认设备绑定、修改节点和账号；管理员还可管理公司准入与系统策略。可见不等于可管理，不能扩大既有账号权限。

用户不为 Apple 开发者计划或分发维护付费。当前 Mac 负责构建，Mac mini 运行 AltServer；用户自行完成 Apple 账号登录、协议、设备信任与开发者模式，同网维护免费签名。续签失败和过期均有明确恢复步骤。此过程保留 Mini 既有生产 IM/Gateway。

## 范围与非目标

- 全量基线：`e6a5c0ea5` 的现有 Web 用户功能及 current IM specs；设计用功能对照表防漏项，实施前同步 main 后对实际新增行为另做影响核对。不是逐像素复制桌面排版。
- 在范围：完整原生客户端、四个入口与所有下级管理页、中文/英文、原生照片/文件选择与预览分享、前台新消息反馈、前后台恢复、免费安装与同网续签实证。
- 原生能力边界：可显示 App 活跃期间的新消息提示；后台/锁屏/被终止时不承诺收到未知新消息，回到前台后补齐。系统通知权限不能成为聊天准入条件。
- 非目标：付费分发、App Store/TestFlight 发布、APNs 远程推送、后台常驻网络、额外分享扩展/Widgets/快捷指令、离线发送队列、iPad/macOS 专属界面、新增 Web 当前没有的管理操作、在 iPhone 执行 Agent 或 LLM。
- 外部网页（例如飞书开放平台准备应用、消息中的外部链接）可按现有含义用系统浏览器打开；Nano 自己的聊天、任务、管理页面不能借此改成 Web 壳。

## 验收标准

### Requirement: R1 独立原生入口保持完整功能与自然导航

#### Scenario: S1 四个入口与原生返回
- **WHEN** 用户从主屏幕图标打开 App，并依次进入聊天、任务、Agent 和我的及其下级页面
- **THEN** 全部 Nano 产品页面在 App 原生界面内操作，返回自然，当前层级清楚，不弹出 Safari 完成管理；会话详情不被底部全局导航挤占。

#### Scenario: S2 键盘、长内容与辅助操作
- **WHEN** 用户使用中文输入法、多行输入、长配置表单、大字体与 VoiceOver 操作关键入口
- **THEN** 组合输入不会误发送，输入区与主要按钮不被键盘或安全区遮挡；可滚动到主操作，控件有可读名称，长正文与代码可选择/复制。

### Requirement: R2 账号会话与公司资格延续既有边界

#### Scenario: S3 登录、注册与恢复
- **WHEN** 用户注册、登录已有账号，或关闭再打开已登录 App
- **THEN** 看到明确字段反馈及与 Web 相同的公司资格；有效会话可恢复，待批准/停用账号只显示本人状态和下一步，不显示公司缓存。

#### Scenario: S4 暂时失败与退出切换
- **WHEN** 登录被限流、网络暂不可用，或用户退出 A 后登录 B
- **THEN** 等待/重试与密码错误可区分；退出立即移除 A 的页面、附件与待发内容，迟到回复不能重新展示 A 的数据，B 只见自己有权的数据。

### Requirement: R3 聊天、联系人和群管理完整可用

#### Scenario: S5 找人、建聊与群设置
- **WHEN** 用户搜索联系人/聊天、新建真人或 Agent 私聊及群聊，修改群名、增删成员或解散自己创建的群
- **THEN** 身份、设备与在线状态清楚，创建和权限结果与 Web 一致；删除需明确确认，不因人数变化把群改为私聊。

#### Scenario: S6 会话偏好与已读
- **WHEN** 用户改聊天名、置顶、静音或阅读消息
- **THEN** 对应偏好按现有范围保存，未读只推进到实际看见的内容；未静音新消息在前台可感知，不把正在看的历史强拉到底部。

#### Scenario: S7 发送、提及、命令与历史
- **WHEN** 用户发送文字、群提及或选择 slash 命令，并滚动查看更早消息
- **THEN** 发送者和目标正确，命令先填入待发内容；历史顺序、分页位置、配置分界线和实时回复一致，未发草稿按聊天隔离，不切聊天自动发送。
- **AND** 群聊在输入框键入 `@` 直接显示当前成员候选，继续输入可筛选，点选只替换当前提及并继续编辑；开头键入 `/` 直接显示命令候选。换行和中文组合输入不自动选择或发送；`+` 只提供附件操作。
- **AND** 聊天列表、消息、群成员与 Agent 目录/详情延续 Web 的名称缩写和固定配色，同一身份保持一致；聊天改名不改变对方头像。

#### Scenario: S8 发送结果不确定与重连
- **WHEN** 发送后断网、服务端已收但响应未到，或 App 回到前台恢复连接
- **THEN** 显示可理解的待确认/重试反馈，恢复后同一消息不出现两份；未确认的发送不假称失败后偷偷重发，断线期间消息最终可见。

#### Scenario: S9 消息操作、fork 与 Skill 蒸馏
- **WHEN** 用户复制正文/代码、从可 fork 的已完成回复建立分支，或选择历史会话生成 Skill 蒸馏草稿
- **THEN** 复制内容正确，fork 保留截至该回复的历史；蒸馏保留来源/执行 Agent/作用域选择及现有跨 Gateway 限制，生成草稿后由用户决定发送；离线/不可操作时有明确原因。

### Requirement: R4 图片附件使用系统选择、预览与分享

#### Scenario: S10 上传、接收与导出
- **WHEN** 用户从照片/文件选择或主动粘贴图片，发送并再次打开聊天中的图片/文件
- **THEN** 可辨认待发项和上传状态，图文顺序与比例保留；授权附件可原生预览、保存或分享，取消选择不发送，复制/分享只由用户操作触发。

#### Scenario: S11 附件失败与权限改变
- **WHEN** 附件超出限制、上传/下载失败、冷却，或用户失去聊天访问资格
- **THEN** 失败项可移除/重试，也能按现有规则仅发送文字；拒绝访问后不再显示其缓存或继续分享，外部网站不会收到 IM 登录凭据。

### Requirement: R5 真实 Agent 过程、指标和审批可检查

#### Scenario: S12 过程与结果
- **WHEN** 用户展开回复的工具、思考、后台返回或运行统计
- **THEN** 看见已报告的顺序、状态、参数、结果与指标；未报告项显示未知，工具返回、子任务完成和对聊天发出最终回复不混淆；回看仍能辨认过程。

#### Scenario: S13 审批提交与确认
- **WHEN** 用户在聊天或 Agent Work 中选择实际权限选项，且确认及时或延迟到达
- **THEN** 选择含义、执行归属与 Web 一致；“已提交，等待确认”与已完成可区分，不能重复批准或把迟到当成请求已结束。

### Requirement: R6 任务和 Agent Work 原生保留完整浏览语义

#### Scenario: S14 任务层级、关系与回聊
- **WHEN** 用户搜索公司任务，进入计划/探索图、子层级与节点详情，从本群任务或节点回到最后有权访问的聊天
- **THEN** 依赖与衍生、前置/后续、选项/结果/变更说明清楚；面包屑可返回，引用追加到聊天草稿而不自动发送，无权或失效关联不跳转，记录完成不自动执行。

#### Scenario: S15 全局 Agent 主子工作轨迹
- **WHEN** 有效成员打开全局 Agent 的 Work 并进入关联子执行、历史轮次和分页明细
- **THEN** 看见原有完整工作内容、归属、统计与状态，能返回主轨迹；非 owner 也能按既有 Work 权限阅读，但不能因此进入原聊天、附件或配置管理。

### Requirement: R7 Agent 创建与完整配置管理均可原生完成

#### Scenario: S16 在线节点创建与路径确认
- **WHEN** 用户从 Agent 或设备入口新建，选择工作模式、节点、模型和能力，采用默认或自定义 workspace
- **THEN** 使用真实节点目录，已有目录需明确确认，模式随节点切换保留；无设备/离线/重复 ID/路径失败时说明原因；中途返回保护未保存草稿，成功只创建一份 Agent。

#### Scenario: S17 所有配置字段与预览
- **WHEN** owner 编辑名称/描述、主模型/有序备用/推理强度、Custom Instructions、工具/Skills/运行特性、群回复策略及提示词预览
- **THEN** 保存与重开保持真实选择，空显式 Skills 与默认发现可区分；不可用能力保留现状并解释，不伪造目录；预览覆盖当前稳定配置并说明运行时上下文不在内，已有工作模式和 workspace 不可改。

#### Scenario: S18 保存冲突、确认中和权限
- **WHEN** 配置发生并发冲突、节点未确认或非 owner 打开其他人的 Agent
- **THEN** 不覆盖更新、不把确认中当成保存成功；保留可恢复草稿并提供重读路径，非 owner 仅能用现有公开/Work 能力；配置保存与聊天下一轮实际采用分开显示。

#### Scenario: S19 Skills、心跳与定时任务
- **WHEN** owner 查看 Skills 来源/状态/使用统计，调整心跳开关、间隔和活跃时段，预览 HEARTBEAT.md，查看或明确删除既有 cron 任务
- **THEN** 与 Web 相同的操作均可完成，在线/离线/空数据可区分；删除需明确确认且只影响所选任务，现有会话/统计关联可继续查看，不添加 Web 没有的 cron 创建表单。

### Requirement: R8 外部通道完整管理保持凭据与运行状态语义

#### Scenario: S20 新增、编辑与凭据替换
- **WHEN** owner 添加当前支持的飞书通道、编辑 App ID 或选择保留/替换密钥
- **THEN** 必填提示、单 provider 限制和节点安全存储前置与 Web 一致；已保存密钥不可读取，修改 App ID 必须替换密钥，不把本地输入写进日志或普通草稿。

#### Scenario: S21 连接、停用与删除恢复
- **WHEN** 用户启停/重连通道，或确认删除后节点离线或实际停止失败
- **THEN** 保存期望与实际连接分开；已知受限/未知权限/失败原因和修复方向清楚，离线状态标为最后已知；删除回执和重试保持到真实停止，聊天历史保留。

### Requirement: R9 设备绑定与节点管理保持双端确认

#### Scenario: S22 接受、拒绝与过期绑定
- **WHEN** 用户在 App 输入或粘贴 Gateway 提供的绑定链接，检查目标设备后接受/拒绝，或链接已过期
- **THEN** 显示当前账号、设备和 Agent 清单，接受后仍等待设备端确认，真正绑定后才成功；拒绝/过期无错误归属，不要求把链接中的秘密发到聊天。

#### Scenario: S23 节点配置与状态
- **WHEN** owner 查看自己的节点、修改别名及现有中继/上报开关，从节点创建 Agent，或节点离线恢复
- **THEN** 对应配置与在线状态及时一致，不能改他人节点；App 不直接连接 Gateway 私有接口或要求用户 SSH 才能操作已提供的功能。

### Requirement: R10 账号、公司成员与策略管理完整覆盖

#### Scenario: S24 账号与语言
- **WHEN** 用户修改 Web 已提供的个人资料、默认入口设备与语言
- **THEN** 原生页面可保存并回显，中文/英文覆盖规则、错误和主要操作，返回后保持选择。

#### Scenario: S25 公司准入与停用
- **WHEN** 管理员分页查看并批准待加入者或确认停用成员，普通成员进入公司管理，或尝试停用最后管理员
- **THEN** 管理员可完成原有操作并看到后果，非法操作被拒；停用覆盖客户端及名下机器资格，不被原生缓存绕过。

#### Scenario: S26 策略与附件容量
- **WHEN** 用户查看系统策略，管理员编辑当前全部策略项并查看服务/owner 的附件容量
- **THEN** 普通成员只能读；管理员可保存默认模型、审计、轮次/限流/附件大小/保留天数，失败保留草稿；容量真实显示，不把权限失败伪装空数据。

### Requirement: R11 前台消息反馈与系统后台限制清楚

#### Scenario: S27 前台提醒与返回 App
- **WHEN** App 前台收到其他未静音聊天的新消息，或用户从后台/锁屏返回
- **THEN** 前台可选择开启不暴露正文的轻提示并跳到对应聊天；历史重放不重复提醒；返回后补齐历史与当前状态，未读和消息一致。

#### Scenario: S28 不承诺免费后台推送
- **WHEN** 用户查看通知设置/帮助，或 App 已在后台、锁屏、被终止
- **THEN** 清楚知道首版不保证后台新消息系统推送，关闭提醒仍可聊天；不会用虚假的“已开启推送”或未取得签名能力误导用户。

### Requirement: R12 免费安装、续签与过期恢复可实际完成

#### Scenario: S29 首次安装
- **GIVEN** 用户已在本机完成 Apple 协议/账号登录和手机授权
- **WHEN** 用户安装本期构建并从 iPhone 主屏幕打开
- **THEN** 不支付开发者费用即可使用已验收功能；清楚知道免费签名会到期，凭据不进仓库和聊天。
