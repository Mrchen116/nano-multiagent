## ADDED Requirements

### Requirement: 托管 IM 提供连续首次设置

新个人用户可从连接电脑、连接模型、定义首个助手一路进入真实聊天。安装页提供可复制给本地 Agent 的 prompt 和可直接运行的手动命令，都针对当前 IM，不包含用户密码或模型凭据。进度由真实节点、模型和助手状态恢复；已有用户不被强制重新引导。

#### Scenario: 安装并恢复
- WHEN 用户运行页面提供的安装方式并确认设备绑定
- THEN 页面显示本人电脑并继续模型步骤；重复安装/刷新不重建身份或丢失数据。

#### Scenario: 有指导的助手创建
- WHEN 用户选择用途、名称与目标并完成创建
- THEN 获得独立助手及工作目录，进入真实聊天并可发送符合用途的起步任务；建议不冒充真实回复。

### Requirement: 页面完成模型连接

节点 owner 可查看发现的连接、配置 API、自定义兼容服务或启动原生 Codex 授权；状态区分发现、授权、验证和失败。验证失败不完成设置，凭据不回显或进入安装材料。

#### Scenario: 验证与失败恢复
- WHEN 用户测试连接
- THEN 以节点实际模型请求结果显示可用或修复动作；等待、失败、重试不丢失电脑绑定。

## MODIFIED Requirements

### Requirement: 设备绑定把节点归属到当前用户

Gateway 和其全部 Agent 由同一个有效账号管理；绑定与整体换绑要求本机持有设备身份的操作者明确确认及目标账号有效，不额外要求公司管理员批准。

#### Scenario: 首次绑定与同账号重试
- **WHEN** 本机发起绑定，有效账号在网页确认目标账号（全新空设备无需再在终端重复确认）
- **THEN** 节点及全部 Agent 归属该用户；响应可辨认操作、设备、接收人和当前状态，缺少必填信息明确失败。
- **AND** 同一操作重试幂等，不重建身份、配置或重复初始化渠道。

#### Scenario: 已绑定设备整体交接
- **WHEN** 有权操作本机的人将 Gateway 确认交给另一有效账号
- **THEN** node、全部 Agent 及相关配置/渠道管理权一起转移，身份、工作记录和本机 workspace 保留；私人 Agent 与其 Work/轨迹转入接收人的私人空间，原公司 Agent 仅可转给有效公司成员并保持公司空间。双端确认明确说明助手工作历史随设备转交；旧管理者及旧机器连接失去相应控制权。
- **AND** 原私人会话和任务图保持原空间；接收人不取得旧私人聊天/附件/任务图权限，转移的 Agent 不再向旧私人空间发送或读取。新管理者不自动成为旧真人私聊的成员；其他成员只使用 Agent，不因此取得配置管理权。

#### Scenario: 旧管理者停用后仍可合法交接
- **WHEN** 旧 owner 已停用，但操作者可完成本机设备证明和新成员确认
- **THEN** 可以整体换绑，不要求先恢复旧 owner 或管理员额外批准；停用不会永久封禁物理设备。

#### Scenario: 抢绑、取消与中断
- **WHEN** 远端用户只知道 node_id，或重放旧操作/伪造本机确认
- **THEN** 不能绑定、换绑或替换该设备的登记身份。
- **WHEN** 确认前取消，或提交期间连接中断
- **THEN** 取消不改变归属；中断能核实并恢复同一提交结果，不出现部分 Agent 转移或旧账号继续控制的状态。

### Requirement: 登录用户可发现人和 Agent，管理配置保持个人归属

#### Scenario: 从目录直接发起聊天
- **WHEN** 有效账号按名字或稳定 ID 搜索联系人
- **THEN** 可辨认自己及私人 Agent，获批团队成员还可辨认公司成员和公司 Agent 并直接私聊，不要求已有 Gateway、好友申请或管理者逐人授权；无匹配时显示空结果。

#### Scenario: 公开 Agent 资料与配置分开
- **GIVEN** 公司 Agent 由另一人管理
- **WHEN** 用户浏览该 Agent 资料
- **THEN** 能看到名字、管理者、设备名、在线状态及工作模式，能发消息，全局 Agent 可进入 Work；不能读取完整配置、凭据或保存管理修改。

#### Scenario: 一个人多 Gateway，单台离线
- **WHEN** 用户绑定多台 Gateway，其中一台离线
- **THEN** 可辨认各 Agent 所属设备与在线状态，其余设备和人际沟通正常；设备及其 Agent 仍只有原管理者管理。
