## 用户场景

普通用户在首次设置中从内置目录选服务商、填写 API Key、选择模型并测试，然后创建助手。中转或自部署服务用户切换到自定义 API，填写地址/协议和模型。已经使用助手的人从常驻设置进入模型服务页，选择自己的电脑，添加新服务、给现有服务增加模型或调整地址和密钥，再在助手设置中选择使用的模型。修改失败时原有可用连接继续可用，密钥不回显。尝试移除在用模型时能知道哪些助手依赖它，先完成迁移后再移除。

## 验收标准

### Requirement: 首次接入优先呈现普通 API 用户的路径

#### Scenario: S1 没有本机代理的新用户
- **WHEN** 新用户在首次设置进入模型步骤
- **THEN** 首先看到服务商/API 接入，不需要先寻找折叠入口或准备本机代理；填写密钥并选择模型、实际测试成功后继续创建助手和获得真实回复。
- **AND** 原有订阅登录保留为可选路径，本机代理仅为可选的自定义服务，不展示开发者专用发现结果作为主入口。

### Requirement: 常驻入口支持管理电脑上的模型服务

#### Scenario: S2 已完成首次设置后再次管理
- **WHEN** 用户从设置打开模型服务
- **THEN** 可以选择自己的电脑，查看已有服务及模型并打开编辑；不需要重新走安装或创建助手。
- **AND** 没有电脑或电脑离线时显示明确的连接/恢复入口，不误报为空配置；其他用户的电脑和凭据不可管理。

#### Scenario: S3 使用内置服务商目录
- **WHEN** 用户添加内置 API 服务商
- **THEN** 可从当前支持目录选择提供商，使用默认连接方式和模型目录，填写密钥后测试保存；不局限于首次页面手工列出的少数提供商。

#### Scenario: S4 添加自定义服务及模型
- **WHEN** 用户填写自定义 API 的显示名称、地址、协议、凭据和模型
- **THEN** 可测试并保存服务，添加多个模型，之后在助手设置选择；不同服务的同名上游模型可分别选择，不相互覆盖。

### Requirement: 编辑可恢复且不意外破坏现有助手

#### Scenario: S5 编辑已有服务
- **WHEN** 用户重新打开服务编辑，更换密钥、地址或增改模型列表
- **THEN** 页面保留现有非敏感值；密钥不回显，留空保留原凭据；保存成功后新设置在运行节点实际可用，已有助手仍引用同一连接，无需重新创建。

#### Scenario: S6 保存失败与并发修改
- **WHEN** 测试失败、取消、电脑掉线或另一页面先修改同一配置
- **THEN** 当前页面明确说明未完成及可采取的操作，保留可重试草稿；不把失败配置替代原来可用的连接，也不悄悄覆盖另一页面的新修改。

#### Scenario: S7 移除服务或模型
- **WHEN** 用户移除被助手或其备用选择使用的服务/模型
- **THEN** 明确告知依赖和先更换的要求，原助手保持可用；切换依赖后可确认移除，其他服务不受影响。

#### Scenario: S8 持久与界面一致性
- **WHEN** 用户刷新设置或重启电脑节点
- **THEN** 已保存的服务、模型及助手选择保持一致；首次向导和常驻编辑器呈现同一连接状态，桌面与手机均能操作。

## 范围与非目标

在范围：Web API 优先入口、常驻模型管理、内置目录与自定义 API、多模型、凭据替换/保留、连接真实测试、在用依赖保护、隔离/失败恢复和必要安装包同步。

非目标：修改上游 DSH、建立第二套模型调用内核、自动迁移生产凭据、强制同步不同电脑的密钥、对所有云厂商认证完成真人实测、原生 iOS 模型管理页、自动合并或部署。DSH 参考中的账号、插件和 Agent 预设页面不在范围；高级 header/重试策略等未展示字段保持现有值，不扩成全部底层配置编辑器。
