## 澄清记录

本轮没有新增问答。#333 已明确交互方向、八类验收场景与范围边界，可直接据此收口首文档。Issue 中“不在本次启动开发”是创建 issue 时的历史背景；本轮用户要求将其建立为解决该问题的 unit。

沿用的产品决定：

1. 主要路径是“父轨迹真实发起点 → 对应子 Agent 本次执行区间 → 返回原发起点”。顶部执行选择器保留为辅助入口。
2. 主动调用与后台自动拉起都可从父轨迹发现；用途、是否 fork、执行状态和父子来源应可理解。
3. 默认检查本次执行的完整过程，fork 继承历史仍可查看；同一子会话被多次唤起时必须区分各次执行。
4. 关系、起止和状态以真实记录为依据；工具启动调用返回不等于子执行结束，信息不足时明确未知。
5. 进入与返回保留阅读上下文，桌面与窄屏均可完成；沿用既有 Work 只读权限与原生检查能力。

## 用户场景

### U1：沿着一次委派检查结果

用户正在 Work 原生轨迹中阅读主 Agent 的工作。在委派发生的位置，直接看到它为何调用子 Agent、是否 fork、当前进行到什么状态。点击该记录便进入对应执行，时间概览已经选中本次开始到结束的范围，下面的输入、模型请求、工具调用和输出可逐项检查，不必在顶部列表猜名称或手动寻找起止。

### U2：理解后台维护与 fork 的范围

用户发现主 Agent 自动开展了记忆整理或技能复盘。即使这次启动没有模型工具调用，也能在真实发起位置发现用途明确的入口。进入 fork 子轨迹后，默认看到的是子 Agent 本次新执行；继承的父级历史仍可回看，但不会误以为它也是子 Agent 本次完成的工作。

### U3：追踪并行、重复唤起和嵌套工作

同一主轨迹可能同时发起多个子执行，也可能再次唤起同一子会话。用户从哪个发起点进入，就看到哪一次执行。子 Agent 进一步委派时，可以继续深入，再逐级返回，每一级都明确来源并恢复之前的阅读状态。

### U4：检查运行中或非正常结束的工作

用户在子执行还在运行时进入查看，范围随真实新增记录延伸，运行状态清楚；已知完成、失败或取消时以实际结束为准。即使启动工具已经返回，也不会把它误报为结束。遇到缺失历史或连接中断，用户能分辨哪些事实已知、哪些边界未知，而不会看到猜测的范围或结果。

### U5：跨屏幕回看且保持只读

用户在桌面或窄屏查看共享 Work，完成进入、检查与返回；刷新后仍能从已有记录找到同一发起关系和对应执行范围。返回父轨迹恢复原发起位置、缩放和选择，保留 Work 原有检查能力。整个浏览过程不会启动、重跑或控制执行，也不会扩大聊天及附件权限。

## 验收标准

### Requirement: R1 在真实发起位置发现并进入子执行

#### Scenario: R1.1 主 Agent 主动调用普通子 Agent（U1）
- **GIVEN** 主轨迹中存在一次真实的普通子 Agent 委派
- **WHEN** 用户阅读该发起位置并点击对应记录
- **THEN** 可以辨认用途、非 fork 方式及实际执行状态，并直接进入该次子执行。
- **AND** 不需要先在顶部执行列表中寻找或猜测对应对象。

#### Scenario: R1.2 后台自动拉起记忆整理或技能复盘（U2）
- **GIVEN** 后台机制已经真实发起记忆整理或技能复盘，即使没有模型工具调用
- **WHEN** 用户查看父轨迹的发起位置
- **THEN** 两类用途均可通过对应记录辨认并进入正确子执行；内部 UUID 可在详情中检查，不以 UUID 标签代替用途说明。

### Requirement: R2 自动聚焦本次完整执行区间

#### Scenario: R2.1 打开已结束的子执行（U1）
- **WHEN** 用户从发起记录进入一次已有真实起止记录的子执行
- **THEN** 时间概览自动选中本次开始到本次结束的区间，沿用原生区间聚焦视觉，并与下面的过程记录关联。
- **AND** 用户可直接定位起点及终点，检查本次输入、模型请求、工具调用、输出及结束状态，无需先手动拖选或翻找。

#### Scenario: R2.2 fork 继承历史与本次新执行分开（U2）
- **GIVEN** 子 Agent 通过 fork 继承了父级历史
- **WHEN** 用户从该 fork 的发起点进入子轨迹
- **THEN** 可以辨认 fork 方式，默认聚焦本次新执行，清楚看到起点；继承历史不计入该范围。
- **AND** 用户仍可查看继承历史，并能区分它与本次子 Agent 新产生的记录。

#### Scenario: R2.3 同一子会话多次被唤起（U3）
- **GIVEN** 同一个子会话先后被唤起两次，具有不同发起点
- **WHEN** 用户分别从两个发起点进入
- **THEN** 各自聚焦对应那一次执行区间，不将两次活动或整个会话历史混作一次执行。

### Requirement: R3 起止与状态忠于真实执行

#### Scenario: R3.1 启动已返回而子执行仍运行（U4）
- **GIVEN** 发起子执行的工具调用已经返回，但子执行仍在运行
- **WHEN** 用户进入子轨迹并持续查看
- **THEN** 明确显示运行中，区间延伸到真实最新记录，不在启动工具返回时提前结束。
- **AND** 检查旧记录时，新内容不会强行改变阅读位置。

#### Scenario: R3.2 正常完成、失败或取消（U4）
- **GIVEN** 分别存在正常完成、失败和取消的子执行
- **WHEN** 用户查看这些执行，或当前运行的子执行进入上述结束状态
- **THEN** 每次均显示其真实结束状态，以真实结束边界收束范围，并保留可检查的已有过程，不把失败或取消显示为成功。

#### Scenario: R3.3 关系或边界信息不足（U4）
- **GIVEN** 可读取历史不足以确认某个发起关系或执行起止
- **WHEN** 用户检查相关轨迹
- **THEN** 明确说明对应关系或边界未知，仍允许检查已有记录，不以猜测的关联或结束点呈现为确定事实。

#### Scenario: R3.4 查看过程中连接中断（U4）
- **WHEN** 用户查看子执行期间节点不可读取或连接中断
- **THEN** 显示不可读取或更新中断，已加载范围不被误认为正在更新，也不自动判定执行已经结束。
- **AND** 恢复读取继续查看原执行，不重新执行任务。

### Requirement: R4 父子对应准确且能恢复阅读上下文

#### Scenario: R4.1 多个并行子执行（U3）
- **GIVEN** 同一父轨迹发起多个并行子执行
- **WHEN** 用户分别点击各发起记录
- **THEN** 每个入口都进入其对应子执行，并显示来自哪个父执行、哪次发起，不混入其他子执行的范围或结果。

#### Scenario: R4.2 返回父轨迹原发起点（U1、U5）
- **GIVEN** 用户在父轨迹已有滚动位置、缩放及选择状态，并从发起点进入子轨迹
- **WHEN** 用户执行一次返回操作
- **THEN** 回到对应父轨迹发起点，恢复进入前的滚动、缩放和选择状态，可以接着原来的上下文继续阅读。

#### Scenario: R4.3 嵌套进入并逐级返回（U3）
- **GIVEN** 主 Agent 的子 Agent 又发起了下一层子执行
- **WHEN** 用户沿发起点逐级深入，再逐级返回
- **THEN** 每级显示准确父级来源和本次执行范围，返回对应的上一层发起位置并恢复该层阅读状态。

### Requirement: R5 刷新后仍可回看同一次执行关系

#### Scenario: R5.1 刷新后从原发起记录重新进入（U5）
- **GIVEN** 发起关系及执行过程已有保存记录，包括同一子会话多次唤起的情况
- **WHEN** 用户刷新 Work 后找到原发起记录并进入
- **THEN** 仍能辨认父子关系，并聚焦该次真实执行范围，不依赖刷新前的临时浏览状态才能定位。

### Requirement: R6 桌面与窄屏保留完整检查旅程

#### Scenario: R6.1 在两类屏幕完成进入、检查和返回（U5）
- **WHEN** 用户分别在桌面和窄屏操作原生轨迹
- **THEN** 发起记录、区间与来源均清楚可辨，能完成进入、定位起止、检查记录和返回父级的连续旅程。
- **AND** 顶部执行选择器仍可作为辅助入口，既有搜索、折叠、时间概览和记录检查器继续可用。

### Requirement: R7 浏览遵守现有 Work 只读权限

#### Scenario: R7.1 非管理者查看与访问资格变化（U5）
- **GIVEN** 查看者是有权查看 Work 的公司成员，但不是 Agent 管理者
- **WHEN** 查看者进入、检查或返回各级子执行
- **THEN** 可以完成相同的只读旅程，浏览不会启动、重跑、取消、审批或修改任务，也不会取得原聊天及受保护附件的额外权限。
- **AND** 退出登录、切换账号或被停用后，原账号轨迹停止更新并清除，后续读取按既有资格规则处理。

## 范围与非目标

在范围：Work 原生轨迹中的主动与后台发起入口、用途与 fork 表达、单次执行区间、真实状态、并行／重复／嵌套关联、逐级返回与阅读状态恢复、持久回看，以及桌面与窄屏只读体验。

非目标：新增 subagent 调用能力，改变调度、fork 上下文继承语义或后台复盘触发频率，清理或删除执行历史，增加任务控制权限，重设计工作记录视图。本项“原生轨迹”指 Work 中既有 DSH 轨迹查看方式；不因该名称自动扩大为另建 iOS 专属轨迹渲染器。
