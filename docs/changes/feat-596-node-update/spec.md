# feat-596: 用户主动更新电脑端

## Relations

- Related: feat-587, feat-588

## 原始需求

> 现在还有一个问题，用户本地按着我们的新手教程安装了，后面有新版本，怎么给更新

> 好好想想具体用户体验，给个最流畅的方式

> 自动更新还是激进了，可以按个按钮之后再更新

> 好，开始按这个设计，并实现

## 澄清记录

用户否决默认自动更新。已确认的方案：自动检查，用户点击“更新”后才下载、安装和重启；点击即授权，不重复确认。下载时助手继续工作，有在途任务则等待结束后切换，可在切换前取消。更新中显示真实状态，允许消息等待，恢复后继续处理。成功明确反馈；失败保留可用旧版并可重试。离线节点不能发起更新，多电脑分别操作。现有用户用一次安装命令补上能力，新用户首次安装即带更新能力。

## 用户场景

用户在日常聊天或电脑设置中发现轻量的新版本提示，查看简短说明并主动更新自己的某台电脑。用户不需要复制终端命令、不需要重复确认，也不用守着页面等任务结束。下载时继续聊天，切换期间新消息持久等待；刷新页面或关闭浏览器不会取消已授权的更新或遗失消息。其他电脑不受影响。

首次使用者按现有教程安装即可获得按钮更新能力；旧版使用者看到明确的一次性升级指引，执行后保留原身份、助手、模型与文件。更新异常时不冒充成功，不重新走新手教程。

## 验收标准

### Requirement: 用户主动发起单台电脑更新

#### Scenario: 发现并点击新版本
- **GIVEN** 在线电脑存在可安装的新版本
- **WHEN** 用户查看电脑设置或聊天中的电脑入口
- **THEN** 可发现轻量提示，查看版本与更新说明，并点击一次“更新”开始下载
- **AND** 点击前不下载、安装或重启，点击后不重复确认，其他电脑不受影响。

#### Scenario: 离线与无新版
- **WHEN** 电脑离线或已经是当前推荐版本
- **THEN** 分别显示“电脑上线后可更新”或“已是最新版本”，不提供可执行的更新动作。

### Requirement: 下载与等待不打断工作

#### Scenario: 下载后等待任务
- **GIVEN** 用户已发起更新，电脑上有正在执行的任务
- **WHEN** 新版准备完毕
- **THEN** 显示任务结束后更新，当前任务继续执行；安全切换前可取消本次更新。

#### Scenario: 取消或重复点击
- **WHEN** 用户在切换前取消，或重复提交同一次更新
- **THEN** 取消保留原版继续工作；重复操作不产生并发更新或重复重启。

### Requirement: 切换期间聊天连续且状态可恢复

#### Scenario: 更新期间发消息并刷新
- **GIVEN** 电脑正在切换版本
- **WHEN** 用户发送消息并刷新页面
- **THEN** 电脑显示正在更新而非普通离线，消息显示等待更新完成；恢复后继续处理且不要求重发、不重复回复。

#### Scenario: 关闭网页仍完成
- **WHEN** 用户发起更新后关闭网页，再重新打开
- **THEN** 更新独立推进，页面呈现实际进度或结果；成功后原身份、助手、模型连接、聊天与文件继续可用。

### Requirement: 失败可恢复且结果真实

#### Scenario: 下载失败
- **WHEN** 下载或校验失败
- **THEN** 原版继续可用，页面显示失败和重试，不显示更新成功。

#### Scenario: 新版启动失败
- **WHEN** 新版无法正常连接服务
- **THEN** 尝试恢复旧版，只有确认恢复后才显示“已恢复原版本”；恢复仍失败时明确提示需要恢复电脑，并保留恢复入口与数据。

### Requirement: 新旧安装用户都能进入按钮更新

#### Scenario: 首次安装与旧版过渡
- **WHEN** 新用户首次安装或旧用户完成一次性升级指引
- **THEN** 后续版本可用按钮更新；旧用户的身份、助手、模型和文件保留，不被要求重新创建。

## 范围与非目标

在范围：Web 电脑设置与聊天入口、真实版本与更新状态、发布配套元数据、用户授权后的本地更新及失败恢复、更新期间消息等待、安装器过渡、相关测试与操作文档。

非目标：默认自动安装更新、跨电脑批量更新、iOS 原生新增更新管理页面、强制升级、任意历史版本选择、跨不兼容数据格式的自动回退。当前版本选择仍由 IM 已验证发布清单决定；未发布清单不冒充可更新版本。
