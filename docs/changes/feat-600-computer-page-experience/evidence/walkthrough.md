# 原型实际浏览器走查

2026-10-14，Chromium 实际渲染；本地静态原型，无真实后端。作者先看画面和完成操作，再对照 spec。所有截图为浏览器原始输出；没有图像拼接或修饰。

## 观察与判断

| 过程 | 证据 | 实际观察 → 用户代价/收益 |
|---|---|---|
| 桌面列表 1440×960 | [desktop](desktop.png)、[旧页](before.png) | 两台电脑的名称、状态与新版本动作在首屏连续可见；旧页四张统计卡和永久表单被撤下，读者不必跨多块找“更新” |
| 820×900 列表 | [tablet](tablet.png) | 名称与动作仍各有空间，保持同排而非突然出现另一套导航 |
| 手机列表 390×844 | [mobile](mobile.png) | 电脑主信息在上、更新说明和主动作在下，按钮 44px；离线提示自然换行，首屏可以比较两台电脑 |
| 手机等待更新 | [waiting](mobile-waiting.png) | “等待当前任务完成”说明自动继续的条件；取消在该状态可见；没有虚假百分比。首轮截图同时残留前次取消 toast，已修正开始新更新时立即撤下旧反馈并重新截图 |
| 360px 长名称 | [long](mobile-long.png) | 列表单行截断不挤出详情入口；点击后详情完整换行。没有页面级横向滚动 |
| 改名成功与编辑 | [桌面详情](desktop-details.png)、[手机改名](mobile-rename.png) | 保存后列表/详情同名；再次编辑时文字选中、取消和保存同高；手机独立返回而非挤在窄抽屉 |
| 保存失败 | [rename-error](mobile-rename-error.png) | 失败紧靠输入，下方仍可重试；输入“保留的新名称”未丢失。空值也显示就地原因 |
| 离线诊断 | [offline-details](mobile-offline-details.png) | 普通页面先解释需要打开 Nano；原始错误仅用户展开诊断后出现；离线改名/创建不可执行 |
| 需恢复 | [recovery](mobile-recovery.png)、[恢复指引](mobile-recovery-guide.png) | 卡片说明新旧版均未启动，提供恢复方法；修正恢复态的绿色状态点和版本含义，改为琥珀色和“上次版本”，避免暗示旧版仍可用 |
| 连接电脑 | [connect](mobile-connect.png) | 手机完整展示目标电脑、操作顺序和复制入口；原型明确没有可执行命令；安装包缺失时无复制按钮 |

连续操作已走通：更新→准备→取消→重新更新→等待→切换→成功；切换期间无取消按钮。演示区逐个打开失败、回退、恢复、legacy、source、unavailable、incompatible、空、加载、首次错误与 stale 状态；无页面溢出。原型异常由演示状态模拟，不能当作真实恢复证据。

## 验证边界

- 原型默认中文；英文、真实请求 pending/错误、WS 刷新/跨页恢复和物理键盘软键盘由 M1 在产品实现时验收。本轮仅确认桌面 Enter/Escape 与原生 dialog 的关闭路径，未声称物理手机或 VoiceOver 通过。
- 相邻聊天页使用前序真实截图核对设计语言；没有重跑聊天旅程。手机“我”入口只核实代码，原型导航为明确标注的背景。
- 安装命令内容来自已有 API 的设计契约；本轮不安装、不发消息、不升级任何电脑，不改共享全局 toast。
- 默认界面、360px 长名、手机编辑/等待/恢复、桌面详情均已实际看图，不以 DOM 宽度检查单独推导视觉结论。
