# 设计基线与原型走查

- 日期：2026-10-14；基线：main `ee03471d6`，线上 Web IM 的实际页面观察。
- 方法：Cua 驱动真实 Chrome 读取电脑、账号和策略页面；原型由本机静态 HTTP 服务与 Codex in-app browser 实际渲染。未修改线上数据。
- 基线结果：电脑页以返回、标题和电脑管理任务组织；账号展示两次 ID、完整设备行和无条件首次设置；策略字段缺乏分组和解释，容量在保存下面。两页与电脑的有效画面在本会话上一轮工具截图中，未保存原件；后来截图误抓到用户已切换的其他页面，已移除，不能作为基线。
- 原型桌面：说明在左、表单在右，个人身份与资料编辑清楚；团队与设备管理不属于资料提交。[账号桌面](prototype-account-desktop.png)。
- 原型窄屏：320px 内容容器实际渲染，分组改为说明在上/字段在下，策略预设与真实用量分开；发现刷新按钮换行后增加不收缩约束，原型演示按钮/选择器的文字颜色也已修正。[策略窄屏](prototype-policies-narrow.png)、[只读窄屏](prototype-readonly-narrow.png)、[待批准账号窄屏](prototype-account-mobile.png)。手机截图是明确标注的容器预览，不是物理设备截图。
- 原型操作：显示名改为 Alex Ops → 模拟保存失败 → 草稿仍在 → 取消失败模拟 → 重试成功；切换普通成员后容量和保存动作消失，预设显示为文本值。各团队资格的解释与去向由独立演示控制切换。
- 体验判断：用户无需从设备行里猜账号职责；策略不再把尚未执行的记录伪装成已生效控制；只读值比灰色禁用表单更容易阅读。手机保留完整说明与触达区域，不把桌面两栏压缩。
- 边界：此处只证明设计与演示操作；真实 API 持久化、权限、失败、后台 refetch 和产品实际响应式布局留给实施后的独立产品验收。原型外部入口仅说明去向，loading/服务故障与零电脑由设计契约及真实产品验证。
- R1 后复查：320px 限高滚动容器、既有底栏背景内实际修改长策略表单并触发失败，保存条内 alert、重试按钮与底栏同时可见；代表截图 [手机失败反馈](prototype-mobile-save-failure.png)。原型只是正确呈现导航背景，不重建其他页面。独立原始构建基线 [账号](baseline-account-isolated.png)、[策略](baseline-policies-isolated.png) 来自本次隔离账号。
