# feat-604: 账号与策略的完整设置体验 — 技术方案

> 对齐: spec.md

## Changelog

## 现状分析

### 涉及范围

`src/IM/frontend/src/features/settings/account/` 与 `policies/` 当前以 620px 居中卡片容纳表单。账号重复用户 ID 和电脑清单，无条件突出首次设置；策略没有分组标题和字段解释，容量区域位于保存动作之后。两页读取失败都可能一直显示加载，后台查询更新会重置草稿。相关入口是 `features/me/me-page.tsx` 与 `app/shell/user-menu.tsx`，路由保持不变。

### 既有约束

只改 Web 呈现和本地编辑状态；保留 `/im/v1/me` 与 `/im/v1/policies` 的字段及写权限。有效公司成员可读取策略，只有管理员可修改和查看容量；私人账号仍跳转资格页。不得扩大执行运行时或跨包依赖。原生 iOS 不变。

### 可复用能力

- 用：全局 `--im-*` token、现有 `im-btn`/`im-input`、AuthStore 身份快照、React Query、`/me` 和电脑/团队路由。
- 改：两页本地草稿与反馈，成功更新 query cache；草稿独立于后台 refetch，提交时锁住对应表单；仅持有未保存内容时显示改动状态。
- 不用：新设置框架、全局草稿 store、全站导航重构。只建立两页共用的 scoped CSS，不抽象表单引擎。
- `apps/im-server/src/control.ts` 仅保存六项 policies；全仓消费搜索显示它们未被运行时或上传链路读取。`media.ts` 的实际容量由服务端附件限制决定。明确提示“仅保存预设，尚未接入执行”，不暗示应用成功。保留所有字段可编辑，不扩展后端执行机制。

### 相关历史

既有账号卡片、策略 restyle、个人空间注册与电脑页重设计提供当前行为基线。近期加入的附件容量是独立的管理员查询，不属于策略 PATCH；本次保留这一边界。2026-10-14 线上实际观察（本会话）证实两页与电脑页的层级、配色和导航存在差异，参见 [基线与走查](M1-settings/evidence/design-walkthrough.md)。

## 架构总览

路由与后端保持。账号从“资料 + 完整设备列表”改为“个人身份与显示名 + 空间与团队 + 关联管理”；策略从“六个字段 + 保存 + 用量文字”改为“实际附件存储 + 明确标注未生效的分组预设 + 局部保存”。两页共享标题、行、分组、状态、表单与按钮节奏，跟随现有白色内容区、浅色背景和青绿色动作。

## 关键决策

1. **账号只直接编辑显示名。** 头像和 @用户名用于身份辨认；账号 ID 与加入时间放在“账号详情”折叠区。电脑只显示拥有数量与管理入口，不再请求电脑详情列表；数量为零时出现助手设置引导。语言和退出仍在现有个人菜单或 Me，不复制入口。
2. **空间资格是独立阅读区，不与资料一起保存。** AuthStore 的 personal/company 状态映射为个人空间可用性和 none/pending/active/suspended 团队状态。none 可查看加入入口、pending 可查看申请、suspended 可查看资格；进入已有 membership 页面并携带返回 `/settings/account`。active 管理员进入成员管理，active 普通成员展示已加入事实，不进入现有 active 不适用的申请页面。
3. **实际容量优先，历史预设保持明确未生效。** 管理员容量先显示服务占用条、已用/上传中/剩余/上限；按需展开可见账号用量，并说明权限范围内明细不一定等于全服务总量。满额显示文字警示，数值始终保留，未知显示失败而非零。预设按“运行预设”（模型、轮次）、“安全预设”（审计、限流）、“附件与留存预设”分组，每项解释记录含义，顶部统一声明尚未执行。真实模型管理链接到模型服务；不说容量卡可清理或改配额。
4. **编辑状态只属于本页。** 未开始编辑时随 query 更新；开始编辑后用独立草稿，refetch 不覆盖。显示名 trim 后与已存值比较；模型 trim，数字用原始字符串以允许清空，再由表单 required/min=1/step=1 与提交校验阻止空值、非正整数。成功使用响应更新 cache、重置草稿和显示可访问 status；失败保留内容，并在当前可见的保存条内显示 alert，成功 status 也在该处，不依赖回到页首。提交期间禁用字段和重复提交；放弃仅重置本表单。不会引入离页拦截器；页面内跳转仍按现有导航，离页不承诺保存草稿。
5. **只读成员看到值，而非整页灰色输入框。** 显示同样分组和说明，以文字值呈现，无保存条，无容量请求。资料/策略/容量使用独立错误和重试；成功读取的区域不被其他查询故障挡住。
6. **手机按阅读任务切单栏。** 桌面最大宽度与电脑页接近（960–1016px），分组为左侧说明、右侧字段；手机小于 680px 改成说明在上、字段在下，按钮最小 44px，保存条位于表单末尾并在滚动容器内 sticky bottom，预留安全区且不覆盖底部导航。手机原型使用限高内容滚动区，隐藏桌面顶栏，并保留现有四项底栏背景；滚动到长表单末尾保存时，失败/重试反馈与操作必须同时可见，且底栏及最后字段不被覆盖。桌面和手机都有返回“我的账号”。中英文全部放入现有 i18n。

## 接口与数据流

账号 GET/PATCH 沿用 `getAccount/updateAccount`。账号保存保留当前 `default_entry_node_id/locale`，响应同步 display_name 到 AuthStore，更新账号 query；membership 状态从已认证 AuthStore 读取，不借 account 表单写入。策略 GET/PATCH 沿用 `getPolicies/updatePolicies`，写入仍发送完整六项；普通成员不执行 PATCH。容量沿用管理员 `/im/v1/attachments/capacity`（service + owners），只读且不绑定策略保存。使用服务端返回 limit_bytes，不从预设推导真实限制。

`specs/im/auth-tenancy.md` 增加账号设置职责、策略预设与实际容量区分、可恢复编辑状态；归并到 `docs/specs/im/auth-tenancy.md`。不修改后端字段/权限或扩大运行时承诺。

## 风险与回退

历史策略实际上未生效是已有能力缺口，必须如实披露；本次不接通执行。中英文长内容、窄屏占用条与底部保存区域实际走查。独立状态避免 refetch 覆盖草稿；离页仍沿用现有不持久化语义。回退本 unit 前端提交即恢复旧呈现，无迁移。

## Runbook for Reviewer

仅需隔离 IM 与 Vite；不启动 Gateway/DSH/LLM。测试用户、团队批准、少量上传文件全部在本次临时 DB 创建，线上凭据和生产数据不复用。资源可用：本机 Node 24+、项目 pnpm/npm 依赖、Cua 浏览器。由实施者在 evidence/runtime.md 记录实际路径、端口和停止命令，reviewer 先核实树和进程。未配置 LLM 不影响这两页。

| 服务 | 停止 | 启动 | 健康 |
|---|---|---|---|
| 隔离 IM | 对 evidence/runtime.md 中本次 PID 发 SIGTERM | `IM_JWT_SECRET=<本次随机值> IM_PUBLIC_URL=http://127.0.0.1:<vite-port> node apps/im-server/lib/main.js serve --db <本次临时DB> --port <im-port>` | GET `/health` 或 `/openapi.json` |
| Vite | 对本次终端 Ctrl-C | `VITE_IM_PROXY_TARGET=http://127.0.0.1:<im-port> npm run dev -- --host 127.0.0.1 --port <vite-port> --strictPort`（frontend cwd） | GET 首页及真实两页 |

**Review 驱动方式**：真实浏览器操作两页，资料/策略保存后刷新确认、只读成员登录、空间资格状态、容量按需展开；故障由临时测试环境停启服务触发，不改变生产。独立 reviewer 可在该隔离 DB 调整测试角色、用量和临时 Vite 窄屏预览容器（不修改产品文件），必须注明边界。

**验收前置**：隔离管理员、普通 active 成员、私人 none/pending/suspended 用户；fixture 来自本次注册与管理员批准，仅临时数据库。320/390px 通过浏览器窄视口或等宽 iframe 实际渲染；中英文通过已有语言入口。失败恢复由停启本次 IM 验证。
