# IM Auth and Tenancy Specification (delta for feat-604)

## ADDED Requirements

### Requirement: Web 账号设置分清个人资料、空间资格与关联管理

Web 账号页以个人身份与显示名编辑为主，账号 ID 和加入时间按需查看；个人空间与团队资格分别显示，电脑由摘要和入口导向既有电脑管理。

#### Scenario: 修改资料和查看资格
- **WHEN** 用户进入账号页
- **THEN** 可修改显示名，辨认当前登录用户名与个人/团队资格，并按资格找到加入申请、申请状态或管理员成员管理入口。
- **AND** 尚未连接电脑时可继续助手设置；已有电脑时通过摘要进入电脑管理，不重复设备详情。

### Requirement: Web 策略设置区别实际容量与未接入执行的预设

有效公司成员可按分组阅读策略预设及其说明；仅管理员可编辑，预设明确标注尚未接入执行。管理员可独立查看实际附件容量与成员用量，不从预设值推断实际容量限制。

#### Scenario: 管理员与只读成员
- **WHEN** 管理员查看策略页
- **THEN** 实际服务占用、上传中、剩余与上限先于预设显示，成员用量按需查看，容量未知有重试而不显示为零。
- **WHEN** 普通有效成员查看策略页
- **THEN** 看到只读预设，无保存操作或管理员容量明细。

### Requirement: Web 账号与策略编辑反馈清楚且保留未提交内容

两页未修改或输入不合法时不可保存，提交期间防止重复操作，保存成功有明确反馈。保存失败与后台重新读取不覆盖当前草稿；离页不承诺保留草稿。

#### Scenario: 失败、刷新与放弃
- **WHEN** 用户编辑后保存失败或页面后台重新读取
- **THEN** 草稿保持可见，可以修改后重试；放弃恢复已存值，成功保存退出未保存状态。
- **WHEN** 页面读取失败
- **THEN** 对应区域显示失败与重试入口，不阻断其他已加载区域。
