# feat-610: Agent 自助安装 workspace 工具

## 原始需求

> 没迁移到DSH之前，我可以让agent自己写python脚本到workspace固定目录下变成工具，现在呢，现在可以让agent怎么给自己加工具

> 那现在 Agent 能自己写插件并启用吗？还是得我手动加白名单、重启节点？我希望它能像以前一样自己给自己加工具。

> DSH本身不应该支持这个能力吗，我记得这是DSH宣传的卖点

> 那就复用 DSH 原生能力把这段接完整，让 Agent 能自己写工具、安装并启用，不用我手动加白名单和重启。保留 workspace 隔离，重启后也要能继续用。

## 澄清记录

用户已明确采用 DSH 原生能力、workspace 隔离、安装自动启用、无需人工修改白名单或重启，以及跨重启持续可用。本次仅补齐 workspace 自建工具路径，不扩展到跨 workspace 的全局插件管理；保留既有工具选择和正常执行审批。

## 用户场景

用户在与助手的既有聊天中要求增加一个可复用能力。助手创作工具、安装并验证，然后在同一聊天使用。用户无需进入配置页选工具或重启服务。相同 workspace 的其他聊天也能使用这个工具；另一个 workspace 无法发现或调用该私有工具。节点正常重启后，用户继续原聊天仍可使用它。

用户此前关闭的工具保持关闭。安装失败时助手收到真实失败原因，可以修正后重试，已经可用的工具不受无关失败影响。用户也能要求停用或移除自己安装的能力。

## 验收标准

### Requirement: Agent 可自助创作并安装工具

#### Scenario: 在既有聊天创建并使用新工具
- **GIVEN** Agent 已获准使用自建工具管理能力与必要的文件写入能力
- **WHEN** 用户要求增加一个可复用工具
- **THEN** Agent 能创作、安装并调用该工具，向用户交付实际执行结果
- **AND** 用户无需手动修改工具白名单或重启节点，既有聊天历史保持

### Requirement: 新装工具按 workspace 隔离且持续可用

#### Scenario: 同 workspace 的多个聊天共享新装工具
- **WHEN** Agent 在一个聊天成功安装工具后，在相同 workspace 的另一个聊天使用它
- **THEN** 工具可调用并返回真实结果

#### Scenario: 其他 workspace 不获得私有工具
- **GIVEN** workspace A 已安装私有工具，workspace B 尚未安装
- **WHEN** B 的 Agent 查找或尝试使用该工具
- **THEN** B 不能发现或执行 A 的私有工具

#### Scenario: 重启后继续使用
- **GIVEN** 工具安装成功且节点随后正常重启
- **WHEN** 用户在既有聊天再次要求使用该工具
- **THEN** Agent 能继续调用它，无需重新安装、选择工具或创建新聊天

### Requirement: 自建工具不改变其他已有工具选择

#### Scenario: 安装不重新启用既有禁用工具
- **GIVEN** 用户已经关闭一个既有工具
- **WHEN** Agent 安装并启用另一个新工具
- **THEN** 新工具可用，已关闭工具仍不可执行

### Requirement: 安装与停用结果准确可恢复

#### Scenario: 安装失败后修正重试
- **WHEN** Agent 安装的工具无法加载
- **THEN** Agent 得到失败原因，不声称已经可用
- **AND** 修正后可重试，其他已安装工具仍能使用

#### Scenario: 停用或移除自建工具
- **WHEN** 用户要求 Agent 停用或移除已安装工具
- **THEN** 后续调用不可执行该工具，无需重启，重启后保持该选择

### Requirement: 配置页如实显示自动启用的 workspace 工具

#### Scenario: 自建工具显示实际状态且不要求手工加白名单
- **GIVEN** Agent 已安装启用 workspace 工具
- **WHEN** 用户打开 Agent 配置页
- **THEN** 工具以 workspace 来源及实际启用状态展示，不显示为等待人工勾选的静态工具
- **AND** 保存其他配置不会将这些工具名自动写入静态白名单；停用由聊天里的管理工具处理

## 范围与非目标

- 在范围：workspace 工具创作、安装、启停和移除；既有聊天热生效；跨重启保存；同 workspace 共享及跨 workspace 隔离；安装结果与工具选择协调；现有执行审批。
- 非目标：全局任意插件管理 UI、迁移所有旧 Python SDK 工具、修改 DSH 上游或增加新的 Agent Loop；生产部署和安装器发布。
