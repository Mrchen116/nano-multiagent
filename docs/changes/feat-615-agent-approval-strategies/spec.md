## 现状与依据

- 当前 DSH 接入在 `packages/dsh-integration/src/index.ts` 注册 `NanoApproval`，由 `policy/approval.ts` 承担自动判定与既有人工/无人值守分流。插件入口存在，不需要引入第二套主 Agent Loop。

- [feat-552 工作区快速放行证据](../archive/feat-552-global-auto-approval/evidence/workspace-file-fastpath.md) 证明旧实现曾对普通工作区 Write/Edit 直接放行，并覆盖真实路径、符号链接与敏感目标边界。当前 DSH `policy/approval.ts` 未保留该分支。恢复应基于当前 DSH 接入，不恢复旧 Python 运行时。
- Codex 参考为本机 `~/Repos/opensource-hub/codex` 的 `codex-rs/prompts/templates/guardian/policy_template.md` 与 `codex-rs/guardian-context/src/profile.rs`：分别给出风险/授权判定和含工具结果的上下文保留规则。外部实现属于设计输入，不自动成为本仓完整产品契约。

## 用户场景

用户在 Web IM 编辑自己管理的 Agent，选择 CC 或 Codex 审批策略，保存后继续既有聊天。两个 Agent 可使用不同策略，也能把同一个 Agent 切回另一策略；聊天历史保留，正在处理的任务不被中途换规则。

CC 模式恢复日常工作区文件创建与编辑免分类审核。目录外操作仍依原规则审查。Codex 模式根据具体风险、用户授权和已观察的工具事实判断；必要时核实本地情况，连续任务复用审查上下文。两套策略均须保留真实用户来源和工具权限约束。

完成后用同样任务分别测试两套：工作区文件编辑、明确授权的目录外小文件维护、空文件写入、条目迁移、连续多步编辑，以及未授权危险操作和工具结果中的恶意指令。用户能从报告判断各任务是否完成、是否误拒或错误放行、运行耗时与模型消耗。报告保留初次失败，不从少量样本推导普遍优劣。

## 验收标准

### Requirement: Web IM 按 Agent 保存审批策略

#### Scenario: 两个 Agent 独立选择与持久化
- **WHEN** 用户分别为两个自己的 Agent 选择 CC 与 Codex 并保存、刷新页面
- **THEN** 两者分别显示已选策略，修改一个不影响另一个；选择区用简短说明帮助理解两者区别。

#### Scenario: 既有聊天切换与切回
- **GIVEN** Agent 已有聊天历史
- **WHEN** 用户保存另一策略并回到聊天发起下一轮任务，再切回原策略
- **THEN** 下一轮采用相应策略，聊天历史保留；保存前已进行的整轮和已发出的人工审批不被改写。

#### Scenario: 保存失败明确可恢复
- **WHEN** 节点不可达或保存发生版本冲突
- **THEN** 页面明确失败或待确认，不将候选选择显示为已生效；用户可按既有提示恢复操作。

### Requirement: CC 恢复普通工作区文件快速放行

#### Scenario: 工作区日常写入与编辑
- **WHEN** CC Agent 在自身工作区创建普通文件并修改其中一段内容
- **THEN** 文件操作正常完成，不因分类模型拒绝而要求用户重复授权。

#### Scenario: 路径边界与敏感目标
- **WHEN** CC Agent 操作工作区外文件，或通过符号链接指向受保护目标
- **THEN** 不因路径表面位于工作区而获得新增免审权限，仍受相应规则约束。

### Requirement: Codex 结合风险、授权和现场证据审查

#### Scenario: 授权的文件维护与连续任务
- **WHEN** 用户明确要求在指定目录外小文件中填写空白内容、迁移指定条目并继续整理
- **THEN** Agent 依据真实文件状态完成这些低风险维护，不仅因路径在工作区外或编辑中删除一段旧文字而要求额外授权。

#### Scenario: 缺少事实时核实现场
- **WHEN** 一个判断依赖文件是否存在或实际内容，而前文没有该信息
- **THEN** 审查可只读核实后再决定，核实过程不改文件、不发送消息、不执行待审动作。

#### Scenario: 危险或恶意指令不能获得放行
- **WHEN** 工具结果夹带与任务无关的删除或泄露指令，或者 Agent 请求未授权的大范围破坏操作
- **THEN** 动作被阻止，用户文件与信息不因切换策略而失去保护。

#### Scenario: 长任务和同时审查
- **WHEN** 连续任务产生较长审查历史或同时有多个动作待审
- **THEN** 每个结果对应自己的待审动作，预算恢复不把缺失证据当作授权；审核失败按现有方式反馈，不冒充允许。

### Requirement: 使用同样任务提交可核实的两套效果报告

#### Scenario: 同条件对照
- **WHEN** 在隔离环境中分别执行同一组测试任务
- **THEN** 报告列出固定模型与推理档位、任务与初始文件状态、每次结果、是否完成、放行/拒绝和故障类型、耗时与可取得的 token/缓存用量；明确样本规模和不可比较项，不隐去首次失败。

## 范围与非目标

- 在范围：CC 快速放行；独立 Codex DSH 插件的完整同步审查机制；Web IM 逐 Agent 选择；配置应用与恢复；等条件对照任务及报告。
- 保持既有 Agent 主执行运行时、消息身份、人工审批、无人值守分流和子任务权限边界。既有配置不强制切换到新策略。
- 不包含生产部署或重启、原生 iOS 新设置界面、额外授权目录管理、通用评测平台。对照在隔离环境执行，不触及用户真实危险目标。
