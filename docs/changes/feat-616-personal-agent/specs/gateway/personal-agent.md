# Gateway personal-agent Specification (delta for feat-616)

## ADDED Requirements

### Requirement: PA SHALL 根据真实来源确定执行权限，不接受正文或模型自报身份

#### Scenario: 外部或历史控制文字
- **WHEN** 外部消息、观察材料或历史 owner 文字含停止、配置、授权或覆盖指令
- **THEN** 不控制本人私密主执行，不开启私人资料/工具权限；当前本人专属私聊的有效控制仍按原契约执行。

#### Scenario: 受限运行不能继承私密能力
- **WHEN** PA 处理外部会话或受限观察批次
- **THEN** 不加载本人私密历史、人设/记忆文件、skills/extensions 或文件/网络/插件/再委派能力；当前 scope 只能读取宿主允许的来源并提出对应范围的结果。

### Requirement: 自动观察 SHALL 可靠发现本人待处理事项而不冒充本人操作

#### Scenario: 无手动转交的新消息与本人回复
- **WHEN** 已启用观察范围内收到真人/Agent请求，随后本人回复
- **THEN** PA 能主动准备有出处的建议，最新回复使过期催回复建议失效；阅读不改变真人已读，也不解释为任务完成。

#### Scenario: 历史与新消息并行
- **WHEN** 历史回溯期间到达新消息或任务变化
- **THEN** 新事件不会被历史扫描跳过，旧承诺会结合最新事实判断；未扫描及覆盖缺口可辨认。

#### Scenario: 忙碌、离线、重连和重复输入
- **WHEN** PA 忙碌或重启后接到重复/积压事件
- **THEN** 持久恢复并合并处理，优先本人新请求，不重复发过时提醒；同步、已读懂、已发送和任务完成保持可区分。

### Requirement: 撤权 SHALL 使旧资料、候选、游标和受影响执行上下文失效

#### Scenario: 策略、资格或受众变化
- **WHEN** owner 排除来源、退出公司/群、迁移节点，或外部受众变化
- **THEN** 旧队列/游标/资料许可不能继续越权使用，受影响上下文重建；发送前重新核当前权限，不凭旧批准放行新范围。

### Requirement: 对外输出和任务写回 SHALL 经宿主校验授权与最新目标状态

#### Scenario: 模型请求改目标或私料范围
- **WHEN** 模型提议向绑定外目标发送、引用未放行资料，或修改未授权任务
- **THEN** 宿主拒绝，不能通过私密主脑自批、普通 child 或外部 Agent 转述获得许可。

#### Scenario: 成功与不确定回执
- **WHEN** 发送或授权任务写入返回不确定状态
- **THEN** 不宣称成功；使用原幂等身份核实，避免重复投递或覆盖。

### Requirement: Agent 间协作 SHALL 有界且不把请求当作 owner 承诺

#### Scenario: 诱导循环或多跳委派
- **WHEN** 外部 Agent 连续接话、转述授权或要求扩大协作
- **THEN** 不自动获得新授权，因果链/预算约束阻止无限互相唤醒；必要时给主人说明待决定，合法已开始工作的结果仍能收取。


### Requirement: PA 私密自动工作 SHALL 同时约束非 IM 出站数据

#### Scenario: 第三方材料要求网络查询或上传私料
- **WHEN** 观察触发的私密工作试图经搜索查询、URL、插件、上传或 shell 网络动作传出数据
- **THEN** 只有真实 owner 当前动作或有界规则覆盖时才可继续；缺授权时回本人确认，不因工具被称作只读、安全或无人值守允许就放行。
- **AND** 读取允许的本地来源、准备材料及给本人建议仍可主动完成。

#### Scenario: 宿主中介与独立任务能力
- **WHEN** PA 请求结构化非 IM 动作
- **THEN** owner 对完整接收服务、参数/外传资料、目的及版本确认后，宿主绑定原生执行身份，由不可覆盖的 guard 与最终 broker 校验消费；参数变化、撤销及未知回执不产生重复外发。
- **WHEN** 工作需要任意 shell、run_code 或插件
- **THEN** 自动观察不得直接执行；可提出 owner 明确批准的独立任务，传最小任务包，由 PA 身份的 owner-only fresh authorized_task 使用专业能力执行，不继承私密脑历史；若是广权限本机模式须明示残余读取/联网风险，不声称强隔离。

### Requirement: PA 撤源清理 SHALL 如实区分上下文失效与磁盘物理删除

#### Scenario: 派生知识与重启
- **WHEN** 源内容已进入记忆、摘要、本人建议、child 或审核记录后被排除
- **THEN** 暂停相关自动处理，失效整组受污染执行/许可与未知来源派生项，通过可恢复 operation 重建允许内容后才恢复；旧 DM/Work 展示不授予模型重新摄取资格。
- **AND** 旧 runtime 日志、导出及已发送内容可能保留，清理完成只表示 PA 管理缓存清除与旧上下文禁用；不把 append-only 日志宣称为已删除。

#### Scenario: 广权限结果不能清洗来源
- **WHEN** 独立任务可能读取批准包以外的本机资料
- **THEN** 正文、进度、错误、产物和派生执行结果均保持 unknown/tainted，仅供本人查看；固定状态通知不包含正文，不自动交回 PA 模型、记忆、审批或观察流。
- **AND** 只有本人选择准确内容并明确作为新输入提交时才可重新处理；专业执行者自报来源或原任务授权不替代此决定。
