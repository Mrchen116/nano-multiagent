# IM agents-nodes Specification (delta for feat-616)

## ADDED Requirements

### Requirement: 新手首个助手 SHALL 创建为本人的 PA，后续专业助手保持独立

#### Scenario: 命名并完成创建
- **WHEN** 新用户完成节点/模型设置并为首个助手起名
- **THEN** 该助手具有稳定的本人 PA 身份与专属私聊；在模型或节点尚不可用时明确显示待完成状态，不假装能工作。

#### Scenario: 并发、取消和重试
- **WHEN** 首次创建被重复提交、中断后重试或取消
- **THEN** 不生成多个 PA，不静默清除既有 Agent；取消不触发对外消息或开启尚未确认的观察。

## MODIFIED Requirements

### Requirement: 新建时选择工作模式，已有 Agent 保持原行为

模式选择适用于普通专业 Agent。首次 PA 固定采用本人私密全局主执行，外部交流按受限会话执行；PA 角色不能由普通模式切换获得或取消。已有普通 Agent 保持原行为。

#### Scenario: 新建全局 Agent
- **WHEN** 用户创建 Agent 并选择全局模式
- **THEN** 创建结果保留该选择，后续跨聊天工作按全局方式进行

#### Scenario: 保留单 Thread 方式
- **WHEN** 用户使用已有 Agent，或新建时选择单 Thread 模式
- **THEN** 继续使用当前各聊天独立工作的行为

#### Scenario: 不提供模式切换
- **WHEN** 用户查看或编辑一个已创建 Agent 的配置
- **THEN** 可以辨认其模式，但不能将其改成另一种模式

### Requirement: 登录用户可发现人和 Agent，管理配置保持个人归属

个人助手增加受本人联系策略约束的同公司原生联络资格；其公开投影只含身份和联系必要信息，不公开私人配置/设备细节/Work。下述普通公司 Agent 可见性保持，不把其 Work 共享规则套用于 PA。

#### Scenario: 从目录直接发起聊天
- **WHEN** 有效账号按名字或稳定 ID 搜索联系人
- **THEN** 可辨认自己及私人 Agent，获批团队成员还可辨认公司成员、公司 Agent 及联系策略允许的同公司 PA 并直接私聊，不要求已有 Gateway、好友申请或管理者逐人授权；无匹配时显示空结果。

#### Scenario: 公开 Agent 资料与配置分开
- **GIVEN** 公司 Agent 由另一人管理
- **WHEN** 用户浏览该 Agent 资料
- **THEN** 能看到名字、管理者、设备名、在线状态及工作模式，能发消息，全局 Agent 可进入 Work；不能读取完整配置、凭据或保存管理修改。

#### Scenario: 一个人多 Gateway，单台离线
- **WHEN** 用户绑定多台 Gateway，其中一台离线
- **THEN** 可辨认各 Agent 所属设备与在线状态，其余设备和人际沟通正常；设备及其 Agent 仍只有原管理者管理。

### Requirement: 托管 IM 提供连续首次设置

新个人用户可从连接电脑、连接模型、命名首个个人助手一路进入真实聊天。安装页提供可复制给本地 Agent 的 prompt 和可直接运行的手动命令，都针对当前 IM，不包含用户密码或模型凭据。进度由真实节点、模型和助手状态恢复；已有用户不被强制重新引导。

#### Scenario: 短窗口完整完成设置

- **GIVEN** 首次设置步骤的表单内容超过当前窗口高度
- **WHEN** 用户在桌面或手机上继续填写设置
- **THEN** 可纵向滚动到完整表单、保存与继续操作，不因屏幕高度被截断。

#### Scenario: 安装并恢复
- WHEN 用户运行页面提供的安装方式并确认设备绑定
- THEN 页面显示本人电脑并继续模型步骤；重复安装/刷新不重建身份或丢失数据。

#### Scenario: 有指导的助手创建
- WHEN 用户为个人助手填写名称、确认清楚说明的观察范围并完成创建
- THEN 获得唯一 PA 及工作目录，进入本人专属私聊；可直接交办自己的目标，其他专业 Agent 之后仍可创建，建议不冒充真实回复。

### Requirement: 设备绑定把节点归属到当前用户

以下整体交接只适用于没有当前或历史 PA 私密资产驻留标记的普通节点。首次创建 PA 私密数据前，服务端和本机先持久登记不可由普通解绑清除的 residency；有任一标记或状态不明时，跨 owner 换绑在准备、commit/recover 与本机启动均失败关闭。同 owner 重连恢复正常。本期不提供 PA 节点跨 owner 清理/迁移交接；旧 owner 停用也不豁免。

Gateway 和其全部 Agent 由同一个有效账号管理；绑定与整体换绑要求本机持有设备身份的操作者明确确认及目标账号有效，不额外要求公司管理员批准。

#### Scenario: 首次绑定与同账号重试
- **WHEN** 本机发起绑定，有效账号在网页确认目标账号（全新空设备无需再在终端重复确认）
- **THEN** 节点及全部 Agent 归属该用户；响应可辨认操作、设备、接收人和当前状态，缺少必填信息明确失败。
- **AND** 同一操作重试幂等，不重建身份、配置或重复初始化渠道。

#### Scenario: 已绑定设备整体交接
- **WHEN** 有权操作本机的人将 Gateway 确认交给另一有效账号
- **THEN** node、全部 Agent 及相关配置/渠道管理权一起转移，身份、工作记录和本机 workspace 保留；私人 Agent 与其 Work/轨迹转入接收人的私人空间，原公司 Agent 仅可转给有效公司成员并保持公司空间。双端确认明确说明助手工作历史随设备转交；旧管理者及旧机器连接失去相应控制权。
- **AND** 原私人会话和任务图保持原空间；接收人不取得旧私人聊天/附件/任务图权限，转移的 Agent 不再向旧私人空间发送或读取。新管理者不自动成为旧真人私聊的成员；其他成员只使用 Agent，不因此取得配置管理权。

#### Scenario: 旧管理者停用后仍可合法交接
- **WHEN** 旧 owner 已停用，但操作者可完成本机设备证明和新成员确认
- **THEN** 可以整体换绑，不要求先恢复旧 owner 或管理员额外批准；停用不会永久封禁物理设备。

#### Scenario: 抢绑、取消与中断
- **WHEN** 远端用户只知道 node_id，或重放旧操作/伪造本机确认
- **THEN** 不能绑定、换绑或替换该设备的登记身份。
- **WHEN** 确认前取消，或提交期间连接中断
- **THEN** 取消不改变归属；中断能核实并恢复同一提交结果，不出现部分 Agent 转移或旧账号继续控制的状态。

#### Scenario: PA 私密资产节点拒绝跨 owner 交接
- **WHEN** 已驻留 PA 的节点尝试转给另一账号，包含旧操作重放、离线恢复或仅重命名运行目录
- **THEN** 服务端不提交任何 owner/Agent/Work 转移，本机不写入新 owner/token 或启动新 owner Agent；提示该电脑保存个人助手私密资料，暂不支持整体转交。
- **AND** PA 身份仍属原 owner；仅原 owner 可重新连接或在新在线节点重新绑定同一 PA，binding epoch 递增后旧节点请求被拒绝，私人历史不会自动迁到新节点。
