# IM personal-agent Specification (delta for feat-616)

## ADDED Requirements

### Requirement: 每位真人有唯一可命名且固定入口的个人助手

#### Scenario: 首次创建与改名
- **WHEN** 用户创建、重复提交、重试、改名或再次进入 PA
- **THEN** 保持同一个本人专属私聊和工作；首个助手为 PA，普通专业 Agent 继续可建，既有 Agent 不被静默转换。
- **AND** 名称显示在固定 Web 入口，手机也可找到；首次目标在明确开始合作时只提交一次。

### Requirement: PA 在现有 IM 框架内提供增量体验

#### Scenario: 桌面主导航与消息列表
- **WHEN** 本人进入 PA 或切换聊天、任务、智能体
- **THEN** 原顶部三个导航保持位置和顺序，具名 PA 快捷入口打开本人专属私聊；左侧保留消息搜索/筛选/会话列表，不将全局导航迁至左侧。

#### Scenario: 手机列表与会话
- **WHEN** 本人在手机打开 PA 或返回聊天列表
- **THEN** 列表页保留既有底部四项，固定 PA 会话可辨认；会话页隐藏全局导航、返回原列表，目标索引在 PA 聊天内。

#### Scenario: 日常聊天辅助回复
- **WHEN** 本人在普通聊天要求 PA 辅助回复
- **THEN** 保留原来源与受众，草稿可回原输入框编辑，本人发送与 PA 对外协调身份不混淆；不要求复制聊天到新门户。

### Requirement: PA 私聊围绕同一目标呈现进展与下一步

#### Scenario: 交办与再次回来
- **WHEN** 本人交办一个目标，或稍后回到 PA
- **THEN** 看到与同一原任务关联的进展、成果、等待对象和下次检查，知道哪些工作正在继续以及需要自己决定什么；不要求操作工具清单。

#### Scenario: 多目标与来源
- **WHEN** 多个目标并行或同一目标有多聊天更新
- **THEN** 来源可展开、同目标决定不重复；一个目标的更正/暂缓不影响其他目标，摘要不建立第二份任务状态。

### Requirement: 普通能力与成果自动衔接，只展示有意义的决定

#### Scenario: 自动准备与内部成果
- **WHEN** PA 在有效权限内搜索、整理或内部委派
- **THEN** 不出现 PA 专属搜索审批/内部任务批准/结果重新提供的必经步骤；成果回到原目标，可查看和继续修改。

#### Scenario: 业务判断与新披露
- **WHEN** 需要本人偏好或新的资料/受众授权
- **THEN** 展示推荐、理由、具体后果和明确操作，一次决定后继续；取消/关闭不误发，稍后决定说明再提醒时间。

### Requirement: 提醒、观察与跟进控制保持不同语义

#### Scenario: 控制打扰
- **WHEN** 本人稍后决定或要求仅重要变化提醒
- **THEN** 调整通知而不停止其他准备；必要决定、实质阻塞、约定期限风险和完成仍按本人设置处理。

#### Scenario: 观察启用、暂停和恢复
- **WHEN** 本人确认观察当前参与聊天及本人任务的范围
- **THEN** 自动观察无需逐条分享，首次整理和后续查询均按需读取历史，不设固定时间窗口，显示真实覆盖；可排除、暂停和清理，未加入公开群不全量监控。
- **WHEN** 本人暂停或恢复观察
- **THEN** 说明新信息覆盖变化与已有目标仍在跟进；仅从现在开始也不放弃旧目标，暂缓目标另有具名操作。

#### Scenario: 来源清理
- **WHEN** 本人清理一个来源
- **THEN** 显示 PA 自动缓存/旧上下文的真实清理状态及受影响工作；说明原聊天、任务、历史日志和外发资料的保留边界，不伪报完全遗忘。

### Requirement: 外部沿原生 IM 联络，私人工作只对本人开放

#### Scenario: 真人、Agent 与群
- **WHEN** 有效公司身份私聊 PA 或在本人允许其加入的群提及
- **THEN** 保持普通聊天，身份和当前受众明确；外部不获得本人私聊、Work、配置、其他来源或附件权限。

#### Scenario: 本人已授权的协调与新增请求
- **WHEN** PA 持续在本人明确的目标/对象/资料范围内协调
- **THEN** 不重复索要相同批准；先在已有范围安全协调，仅目标必需的新私料或受众请求准确决定，外部伪造同意不能扩权。
- **AND** 不披露的请求仍可在允许范围内礼貌回应或给替代方案，不将内部拒绝过程发给对方。

### Requirement: 本人可控制外部联系与工作完成

#### Scenario: 联系屏蔽
- **WHEN** 本人屏蔽具体身份或群
- **THEN** 当前策略生效后阻断其新请求/投递并取消对应待办许可；原聊天保留，解除后不重放屏蔽期请求，群屏蔽不全局屏蔽成员。

#### Scenario: 交付与完成
- **WHEN** 工作达到约定条件或仍需验证
- **THEN** 展示真实成果和原任务状态；等待本人时说明具体问题，已有有效确认不再强制二次验收，发送成功不自动等于目标完成。

### Requirement: 可疑套取双向告知且不增加本人审批

#### Scenario: 有依据的可疑索取
- **WHEN** 外部在明确拒绝后继续索取，或伪造本人授权等行为触发可疑事件
- **THEN** 阻止越界披露，向本人专属私聊报告对象、来源、具体依据和已采取措施，区分观察事实与“疑似”判断；对方仅在原会话得到边界说明及可核实的记录/告知状态。
- **AND** 对外“已通知本人”必须有本人通知实际送达的证据，不表示已读；pending/unknown 不冒称成功，恢复核实原操作不重复发送。

#### Scenario: 重复、误会与正常协作
- **WHEN** 同一事件反复发生，或本人不处理/标记误会/屏蔽
- **THEN** 重复更新同一事件而不逐条提醒、争辩或新增审批任务；正常授权工作继续。本人可查看记录、标记误会或按现有策略屏蔽，误会标记不扩权；新风险或实际泄露证据可升级提醒。

### Requirement: 隐私检查不成为用户管理的另一套工作流

#### Scenario: 安全改写与统一体验
- **WHEN** PA 理解外部请求需要私人背景，或待发草稿需减少披露
- **THEN** 用户仍通过同一个 PA 查看目标进展；可自动处理的检查与改写不要求用户切换 session、搬运资料或逐条批准。

#### Scenario: 审核或能力暂不能完成动作
- **WHEN** 外发检查不可用、证据不足或所需执行能力无法受控
- **THEN** 只在对应目标显示具体阻塞与可继续部分，实质阻塞按提醒设置报告；不冒称已发送，不把服务故障包装成用户审批，也不停止其他目标。

### Requirement: 新消息协助与历史查询融入原聊天

#### Scenario: 三种处理与真实代发身份
- **WHEN** PA 处理别人发给本人的新消息
- **THEN** 可不回复、准备私密草稿或在已授权范围代发；本人发送草稿为本人消息，自动代发在原会话向双方显示固定PA身份标记，历史回看/实时同步保持，不改变人际私聊成员关系或要求逐条审批。
- **AND** 普通浏览器不可伪造代理身份，投递仍核对当前owner写权限和授权；本人已回复使过期自动动作重新判断。

#### Scenario: 历史查询及来源定位
- **WHEN** 本人在PA私聊问起过去某群或私聊的约定
- **THEN** PA可查询本人参与过且当前仍可读、未排除的记录，给出作者、时间及原消息定位；本人能打开仍有权的出处。暂停观察不禁查询，查询不改变本人未读，不把未覆盖说成不存在。

### Requirement: 日常协助不暴露安全配置复杂度

#### Scenario: 自然语言开始与必要控制
- **WHEN** 本人交办、查历史或处理消息
- **THEN** 直接在现有聊天完成；不要求设置时间窗口、逐消息处理模式或审核参数，仅必要业务决定或新授权询问。保留可理解的来源查看、纠正和暂停入口，默认仅重要变化提醒。
