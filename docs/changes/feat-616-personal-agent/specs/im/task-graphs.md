# IM task-graphs Specification (delta for feat-616)

## ADDED Requirements

### Requirement: 个人助手协助 SHALL 保持源任务及负责人为唯一事实

#### Scenario: 为本人任务准备材料
- **WHEN** PA 读取本人有权且在观察范围内的任务并准备下一步
- **THEN** 任务负责人不自动改为 PA，不隐式 claim，不另建平行任务状态。

#### Scenario: 授权写回与并发
- **WHEN** owner 明确授权 PA 把结果或状态写回一个具体任务
- **THEN** 使用源任务的当前权限和 revision，记录真实 PA 主体及 owner 授权；发生冲突或失权时拒绝覆盖新状态。
- **AND** 该授权不自动包含改派、删除或新建公共任务，消息送达不算任务完成。

## MODIFIED Requirements

### Requirement: 有效成员和具备能力的有效 Agent 共享公司任务

以下普通任务路径与场景保持不变。个人助手另有窄化委托路径：可信 owner_private 或 observation 批次可按 owner 当前 read ACL（含空间资格）∩已启用观察范围∩本次目标/批次读取任务，无需逐任务批准；external 与普通 child 不取得这一投影。仅可信 owner_private 的写入路径可依据 owner 当前 write ACL、已启用任务能力和精确一次性 grant 补充结果或状态；不要求 PA 自己入群或改变其固定空间。PA 成员资格不能替代 owner 当前资格。所有写入仍记录 actor=PA、authorized_by=owner，并在同事务复核任务、来源、受众和策略版本；不授予 claim、改派、删除或创建公共任务权限。

资源空间资格是访问前提，具体范围跟随固定所属会话；公司会话仍要求公司资格，私人会话要求本人的私人空间资格。原公司无差别共享规则由以下规则替代。

公开群及其任务对公司内有资格的人和 Agent 可读；私密群及其任务仅成员可读；私聊任务仅参与者可读。公开不等于互联网匿名公开。领取、修改等写操作仍要求所属会话写入资格。

#### Scenario: 公开可读、加入后操作

- **WHEN** 公司内有资格的人或 Agent 尚未加入公开 A 群
- **THEN** 可读取公开群及其任务，自行加入后才能领取、修改；仅查看不会自动加入。
- **AND** 任务读取按需发生，不把全量任务自动注入上下文；不由此取得其他 Agent 配置及本机资源权限。

#### Scenario: 私密群和私聊

- **WHEN** 非成员尝试读取私密群或非参与者尝试读取私聊任务
- **THEN** 不因同公司、知道任务链接、管理某 Agent 或拥有公司管理员身份就取得读取资格；私密群参与需邀请。

#### Scenario: 在另一群讨论公开任务

- **WHEN** A 群任务在 B 群被引用、讨论或由具备 A 群写入资格的主体更新
- **THEN** 两处打开同一任务，任务归属和可见范围仍由 A 群决定；不复制任务、不按最后讨论群改变归属，也不产生局部子树共享权限。

#### Scenario: 资格失效或借用身份
- **WHEN** 调用者无目标资源的空间权限，或调用公司 Agent 的管理者未获准公司资格、Agent 未注册、机器失效、工具未启用
- **THEN** 拒绝相应访问，不能通过模型自报身份、旧连接、已知链接或飞书 ownerOpenId 绕过调用主体检查；外部发言人不另行关联 IM 账号。

#### Scenario: 个人助手代表本人有界协助
- **WHEN** 私人 PA 为本人公司或私人源任务申请写回
- **THEN** 仅批准的结果/状态 patch 可按 owner 当前资格写入，任务归属与负责人不变；owner 已退群或失去资格时，即使 PA 仍为成员也拒绝。
- **AND** 现有任务系统通知仍按原所属会话产生，确认前明确其受众；普通 Agent 不获得此委托能力。

### Requirement: 公司任务可共同维护且删除须明确授权

以下普通任务路径与场景保持不变。个人助手另有窄化委托路径：可信 owner_private 或 observation 批次可按 owner 当前 read ACL（含空间资格）∩已启用观察范围∩本次目标/批次读取任务，无需逐任务批准；external 与普通 child 不取得这一投影。仅可信 owner_private 的写入路径可依据 owner 当前 write ACL、已启用任务能力和精确一次性 grant 补充结果或状态；不要求 PA 自己入群或改变其固定空间。PA 成员资格不能替代 owner 当前资格。所有写入仍记录 actor=PA、authorized_by=owner，并在同事务复核任务、来源、受众和策略版本；不授予 claim、改派、删除或创建公共任务权限。

#### Scenario: 所属会话成员共同维护
- **WHEN** 所属会话有写入资格的人或真实 Agent 创建、修改或明确删除任务
- **THEN** 可共同维护相同任务；真人可通过 Web 和原生 iOS 直接操作，Agent 使用工具。每节点保留真实创建者及独立负责人；不增加交办人角色、不伪造主体。删除仅允许目标创建者或已入群真人公司管理员，负责人身份不单独授予删除权。
- **AND** 来源聊天及受保护附件继续按对象权限投影，不能借变更信息泄漏其原文。

#### Scenario: 明确删除与冲突重试
- **WHEN** 用户明确指定删除范围或确认 Agent 说明的删除范围
- **THEN** 经 [Gateway 统一工具权限流程](../gateway/task-graphs.md) 获准后，仅删除相应图或子树，其他任务不变；旧链接明确不可用。
- **AND** IM 继续核实调用主体与资源访问资格，不通过用户消息的措辞或本轮消息是否存在再次裁决删除授权。
- **AND** 写操作保持原子 revision 检查，过时请求不覆盖更新，同一写入重试不重复执行或改写原来源，删除回执也可核实。

#### Scenario: 个人助手代表本人有界协助
- **WHEN** 私人 PA 为本人公司或私人源任务申请写回
- **THEN** 仅批准的结果/状态 patch 可按 owner 当前资格写入，任务归属与负责人不变；owner 已退群或失去资格时，即使 PA 仍为成员也拒绝。
- **AND** 现有任务系统通知仍按原所属会话产生，确认前明确其受众；普通 Agent 不获得此委托能力。

Web、原生 iOS 提供创建大任务／当前层子任务、领取、调整负责人、编辑标题／描述／结果／状态和有权限删除等基础操作。Agent 工具提供对应能力，按实际调用主体鉴权。有所属会话写入资格的成员可共同维护，负责人不独占编辑。

#### Scenario: 人直接操作及成员共同维护

- **WHEN** 小王直接创建任务，或群内有写入资格的成员修改他人负责的任务
- **THEN** 操作按对应主体记账并反映到同一份任务；人直接创建记小王为创建者，修改者可辨认；不要求通过 Agent 才能完成基础操作。

#### Scenario: 先入群再分配

- **WHEN** 为任务选择负责人
- **THEN** 只能选择任务所属会话中的人或 Agent；非成员需先按群规则加入，分配操作不会自动拉人入群。

#### Scenario: 分配与领取分离

- **WHEN** 任务被分配或改派给某负责人
- **THEN** 分配本身不代表该负责人已经开工，也不把通知投递当作进行中；领取才表示接手开始推进。
- **AND** 其他主体不能通过领取直接抢占已有负责人任务，转交通过明确改派完成。

### Requirement: 会话任务继承固定资源空间边界

以下普通任务路径与场景保持不变。个人助手另有窄化委托路径：可信 owner_private 或 observation 批次可按 owner 当前 read ACL（含空间资格）∩已启用观察范围∩本次目标/批次读取任务，无需逐任务批准；external 与普通 child 不取得这一投影。仅可信 owner_private 的写入路径可依据 owner 当前 write ACL、已启用任务能力和精确一次性 grant 补充结果或状态；不要求 PA 自己入群或改变其固定空间。PA 成员资格不能替代 owner 当前资格。所有写入仍记录 actor=PA、authorized_by=owner，并在同事务复核任务、来源、受众和策略版本；不授予 claim、改派、删除或创建公共任务权限。

任务的固定所属会话同时决定其私人/公司资源空间；个人账号无需公司审批即可在自己的私人会话中保存、查看和维护任务。加入公司不发布原私人任务，停用公司资格不阻断仍有效的私人空间。公司公开群的读取与入群后写入仅在公司资格有效时可用。Agent 仍受自己的固定资源空间约束，不能借 owner 加入公司而跨空间操作。

#### Scenario: 私人任务与公司协作共存
- WHEN 用户保存私人会话任务后加入公司、再退出或停用公司资格
- THEN 原私人会话和任务的成员范围不变，公司成员与管理员不能因此读取；公司任务仍按公司资格和所属会话权限判定。
