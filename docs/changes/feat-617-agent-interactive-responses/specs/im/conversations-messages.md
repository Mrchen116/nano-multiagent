# IM conversations-messages Specification (delta for feat-617)

## ADDED Requirements

### Requirement: Agent 交互回复与普通消息共同持久化和授权

交互内容 SHALL 属于已公开的 Agent 消息，按同一会话权限读取；文字摘要在不支持交互的客户端仍可独立阅读。重复交付不新增同一消息，私有草稿不自动公开。

#### Scenario: 刷新与节点离线
- **WHEN** 用户刷新、换设备或 Agent 节点离线后读取交互回复
- **THEN** 已交付内容及已确认结果仍可读，未授权用户不能读取。

#### Scenario: 分支与原会话删除
- **WHEN** 用户 fork 含交互内容的历史，再删除原会话
- **THEN** 复制范围内公开内容与确认结果仍可读；旧交互作为只读历史，不复制私人未提交草稿。

### Requirement: 交互确认保留真实用户、原回复与选择语义

提交 SHALL 形成当前登录用户的会话消息，携带原回复与实际选择；附带选择的手写要求原样保留，选择摘要不能替代用户正文；私人未提交草稿仅对本人可见。重复提交不得创建重复输入或重复调度。

#### Scenario: 群中不同成员调整
- **WHEN** 两位成员分别调整同一卡片，随后其中一位提交
- **THEN** 草稿互不覆盖；公开结果明确属于提交人，原卡片作者 Agent 获得其选择上下文。

#### Scenario: 已提交或被替代的卡片
- **WHEN** 用户再次提交已确认卡片，或提交已被新版本替代的卡片
- **THEN** 分别返回原提交结果或明确提示已有更新，不产生新的业务执行。

#### Scenario: 带选择的手写要求与不同意图重试
- **WHEN** 用户修改草稿后发送“先别发送，把语气改得随意一点”并附带选择
- **THEN** 公开本人消息与 Agent 收到的输入均保留这句原文及修改后的草稿。
- **AND** 同样选择但正文或动作不同的再次提交明确提示冲突并保留新输入，不把它当作原提交成功。
