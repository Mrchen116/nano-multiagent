# IM conversations-messages Specification (delta for feat-617)

## MODIFIED Requirements

### Requirement: 交互确认保留真实用户、原回复与选择语义

提交 SHALL 形成当前登录用户的会话消息，携带原回复与实际选择；附带选择的手写要求原样保留，选择摘要不能替代用户正文；私人未提交草稿仅对本人可见。重复提交不得创建重复输入或重复调度。

#### Scenario: 群中不同成员调整
- **WHEN** 两位成员分别调整同一卡片，随后其中一位提交
- **THEN** 草稿互不覆盖；公开结果明确属于提交人，原卡片作者 Agent 获得其选择上下文。

#### Scenario: 多次探索与请求幂等
- **WHEN** 用户继续探索同一回复并发送另一个明确请求，或因网络重试同一次请求
- **THEN** 新请求可独立保存；同一幂等键和语义返回原结果，不重复调度；同键不同语义明确冲突。
- **AND** 被替代或 fork 的旧版本不接受新的业务请求。

#### Scenario: 增量更新保持完整历史
- **WHEN** Agent 对自己的同会话交互回复发送增量修改
- **THEN** 新消息保存校验后的完整版本，旧消息仍可读；失败或重试不会产生半条或重复版本。

#### Scenario: 带选择的手写要求与不同意图重试
- **WHEN** 用户修改草稿后发送“先别发送，把语气改得随意一点”并附带选择
- **THEN** 公开本人消息与 Agent 收到的输入均保留这句原文及修改后的草稿。
- **AND** 同一幂等键下正文、状态或动作不同的再次提交明确提示冲突并保留新输入，不把它当作原提交成功。
