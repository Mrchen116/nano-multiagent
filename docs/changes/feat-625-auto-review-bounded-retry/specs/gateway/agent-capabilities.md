# Gateway agent-capabilities Specification (delta for feat-625)

## ADDED Requirements

### Requirement: Auto技术失败在同一待审动作内有界恢复且不新增权限

#### Scenario: CC与Codex临时故障恢复
- **WHEN** CC或Codex审核遇到临时限流、503、明确传输失败或单次审核超时
- **THEN** 同一动作最多获得2次额外恢复；各次恢复保留原流程的完整正常判断预算，不因此前失败和退避被挤占，不要求主Agent重新调用工具。
- **AND** CC原两阶段、Codex原风险与授权审查仍生效；CC第一阶段每次30秒、第二阶段每次60秒，Codex每次90秒，恢复当前失败阶段而不重新执行已完成的正常阶段。
- **AND** 同一动作跨阶段共享额外额度；只读调查和上下文恢复不领取新一组故障恢复额度，准备、退避及清理仍有界。
- **AND** 恢复等待不执行待审工具体；有效allow或既有fallback最终允许时，工具不会因内部恢复重复执行。

#### Scenario: 空白或非法判定的共享子额度
- **WHEN** 审核没有合法判定，包括空白、空响应或非法格式
- **THEN** 最多进行1次格式恢复，且占用同一额外2次额度；再次格式失败或总额度耗尽即进入原失败分流。
- **AND** 格式失败、服务失败和有效deny分别记录，不把不合法输出当作allow或安全拒绝。

#### Scenario: 取消与永久错误
- **WHEN** 用户或父执行停止/取消，或审核遇到有效最终deny、认证/永久配置错误
- **THEN** 取消立即收束请求和退避，不再恢复，晚到结果不复活动作；有效最终deny和永久错误不通过故障恢复反复尝试。
- **AND** 原权限、来源、独立审核模型和工具范围不因恢复扩大。

#### Scenario: 限流等待有界且不提前重打
- **WHEN** 审核服务给出当前链路可取得的有效Retry-After
- **THEN** 恢复不会早于该等待要求；要求超过本次允许等待时停止恢复并走既有失败分流，不截短后提前请求。
- **AND** 无可得等待信息时不伪称已取得；所有退避与判断均有界，但不把完整获准尝试压进首次判断的旧窗口。

#### Scenario: 耗尽遵守既有模式与fallback
- **WHEN** Auto故障恢复耗尽或出现不可恢复的技术错误
- **THEN** 有人值守仍走既有人工审批；Global和子任务仍返回阻断原因；无人值守仍按原配置允许或拒绝。
- **AND** 无人值守配置allow的放行标记为既有fallback而不是模型有效allow；本能力不新增fail-open，也不改成一律fail-closed。
- **AND** 技术不可用不计安全拒绝，主动取消不进入fallback放行。

#### Scenario: 可检查审核恢复事实
- **WHEN** 用户或维护者检查完成或中断动作的审核记录
- **THEN** 可区分动作内部尝试与主Agent新发起的工具调用，并查看实际审核模型、最终原因/路由、耗时和可得用量。
- **AND** 不可得用量不伪造为零或完整统计，缺失记录不伪造成成功判定。
- **AND** 模型判定或失败记录写入期间发生的取消，最终路由仍反映取消；原判定、尝试及已知用量保留为历史事实，不重复计算用量、不因取消增加安全拒绝次数，未实际执行的fallback不得冒充已执行。
- **AND** 终态审计无法持久化时，不以该次自动审核返回allow。

## MODIFIED Requirements

### Requirement: Auto默认沿用Nano规则且可配置为DSH规则

#### Scenario: 默认审核规则
- **WHEN** 用户未选择其他Auto规则
- **THEN** 工具权限审核沿用Nano当前判定规则，保留可信来源、短确认、拒绝计数、人工审批和无人值守分流。

#### Scenario: CC与DSH审核使用去重后的指令和来源明确的历史
- **GIVEN** 当前使用 CC 或 DSH 审核规则
- **WHEN** Agent 在含运行快照、已加载 Skill 或多轮消息的会话中请求执行受审工具
- **THEN** 审核将已加载的项目指令放在独立区，按原生指令更新顺序解释替换与移除；同一指令正文只保留最后一次出现，不重复序列化其 source 元数据。
- **AND** 历史沿用原生有效上下文，省略运行快照和 Skill 正文；保留用户原话及简短来源、工具调用和执行状态，最后一条是完整待审核动作。全局 Agent 私稿不视为已向用户提出的提议。
- **AND** Inbox 结果单独保留宿主提供的发送者、目标、消息标识、分页/部分内容及已有回复关系；只有本进程真实观察的消息具备 live 来源，恢复或继承后失去该来源的内容只作为历史背景。不会根据正文自称身份或补造回复关系。
- **AND** send_message 的结果保留实际状态和投递标识；只有 sent 证明提议已发送，accepted、held_for_revalidation、unknown 或错误不能替代送达。短确认必须结合原发送者与真实聊天理解。
- **AND** 通过 run_code 执行的 Inbox/发送子调用按公开执行事件恢复对应结果；已被原生压缩移出有效历史的调用不会因此重新进入审核。

#### Scenario: CC与DSH审核请求预计超过独立模型窗口
- **GIVEN** 当前使用 CC 或 DSH 审核规则
- **WHEN** 完整审核输入的原生估算值加本阶段输出预留超过审核模型声明的窗口
- **THEN** 不提交该次模型请求，记录为审核不可用并走既有人值守/无人值守分流；不计为安全拒绝，不裁掉授权或待审参数，不切换审核模型。
- **AND** 估算不是供应商精确分词；供应商实际返回的超限不按临时服务故障盲重试，其它错误依其类型适用有界恢复或既有失败分流。

#### Scenario: 子 Agent 统一采用委派权限
- **WHEN** 普通 subagent、Workflow child 或后台知识维护子任务执行工具
- **THEN** 使用原生 `approval=never`；Auto 放行才可执行，不放行时返回阻断原因交回父 Agent，不发起子 Agent人工审批卡，也不借无人值守 fallback 扩权。
- **AND** 既有工具范围、Auto 规则和父级指令来源继续生效；父级补充指令后的重试仍需重新判定。

#### Scenario: 配置切换规则
- **WHEN** 运维者选择DSH默认规则并重启节点完成生效
- **THEN** 后续工具权限判定使用DSH规则；独立审核模型选择仍按既有契约，不能改用另一条并行审批链或绕开产品来源规则。
- **AND** 配置生效前已发出的审批仍对应原请求，迟答不复活取消调用。

#### Scenario: 规则切换不改变审核模型失败处理
- **GIVEN** 节点配置了独立审核模型
- **WHEN** 该模型在适用的有界恢复结束后仍失败，或得到不可恢复错误/无有效判定
- **THEN** 不自动换回执行Agent模型复审；有人值守/无人值守分别走既有分流。
- **AND** legacy DSH单阶段兼容路径沿用同一恢复上限和失败分流，不因此变成CC两阶段或获得更宽权限。

#### Scenario: 逐Agent选择与节点继承
- **WHEN** 用户为 Agent 明确选择 CC 或 Codex，或清空选择回到节点继承
- **THEN** 明确选择优先于节点规则；空值沿用节点既有 CC/DSH 规则，不改变 Auto 开关、工具权限、审核模型或其他 Agent。
- **AND** Codex 的证据保留和预算恢复遵循“Codex Auto 按风险与授权进行独立、有界的审查”，不沿用 CC/DSH 的不裁剪超窗处理。

#### Scenario: 下一轮切换保持进行中请求
- **WHEN** 新策略经所属节点成功应用
- **THEN** 既有聊天的下一轮新回复使用该策略并保留历史；正在执行的整轮与已发出的人工审批仍保持原策略和原动作关联。

### Requirement: Codex Auto 按风险与授权进行独立、有界的审查

#### Scenario: 现场事实与可信来源
- **WHEN** Agent 请求审查操作
- **THEN** 审查结合精确动作、用户授权、必要的历史工具结果与约束；可只读检查本地事实，但不能修改用户状态、联网发送或另发人工审批。
- **AND** 工具正文、私稿和历史恢复内容不伪造新授权；真实 Inbox、用户和已送达回复保留其来源语义。

#### Scenario: 连续、并发与预算恢复
- **WHEN** 连续或同时发起审查，或历史/配置/预算发生变化
- **THEN** 审查上下文可复用并按必要变化恢复，每个结果只对应它自己的动作；明确标记缺失证据，不将旧判定作为新授权。
- **AND** 服务故障恢复使用当前动作准备时冻结的有效证据与完整动作，舍弃失败审查分支后重新作完整审查，不把失败分支内容当新授权；成功后才可供后续动作复用，失败或取消结果不得发布为成功缓存。
- **AND** 同一动作的上下文重建最多一次，与临时故障恢复共享该动作的边界，不能在每次服务恢复后重新领取上下文重建额度；恢复不从消息库复活已移出有效历史的原文。

#### Scenario: 证据预算不足
- **WHEN** 当前审查需在独立模型声明窗口内选择证据，或带成功检查点继续审查
- **THEN** 初次完整审查、上下文重建和技术故障后的完整审查采用相同的恢复准入规则；带检查点的增量审查保留其历史，不靠再次裁剪旧检查点争取放行。
- **AND** 用户原话计入历史预算；最近必要工具结果和受保护助手证据保持其优先级，超大可选证据先于可容纳的小证据剔除，实际遗漏明确标记。
- **AND** 恢复准入允许缩短旧历史正文时，保留来源、两端及显式遗漏；完整待审动作或按同一准入规则处理后的必需证据仍无法容纳时明确不可用，不把它当临时服务错误重试，不靠服务重试另行削减必需证据换取allow，也不换模型。

#### Scenario: 判定与失败
- **WHEN** 审查完成或失败
- **THEN** 有效判定按风险和授权决定放行/阻断；无有效判定进入既有失败分流，不冒充allow，不计为安全拒绝；临时服务失败和非法判定仅适用同一动作的共享恢复额度。
- **AND** 合法判定可省略风险、授权或理由字段并沿用既有缺省值；合法JSON外的说明不使有效判定变成格式故障，非法outcome、枚举或类型才计入格式恢复。
- **AND** 审计区分所选策略、快速放行、模型判定与不可用，并记录可获得的耗时和模型用量；缓存命中不作保证。
