## 澄清记录

- 用户确认最终目标是评测驱动优化，随后明确本阶段只做到评测。Agent 解读：当前产物需要支持以后比较改进，但本阶段不修改 PA 策略、不寻找最佳配置、不运行自动优化。
- Agent 问：“第一版的‘模拟用户／同事’，你更希望采用哪种方式？这会影响评测的可重复性和互动覆盖。”用户答：“那你不得根据任务和大家的研究来定吗，你来分析”。Agent 据此自行分析模拟方式，技术决定见 design，不将未选选项当作用户要求。
- Agent 解读：长期表现应来自同一 PA 在一段连续经历里的状态延续，而不是把若干互不相关的问题包装成“七天”。可重复指相同起点、输入与评判条件可复现，不要求随机模型逐字相同。
- 用户要求取消对尚不存在的上游能力的依赖，并纠正 Agent 将范围缩为压缩故事的解释。用户确认：目标仍是让系统经历七天的时间语义而无需等待七个真实日历日。不得改写“三天后”为“三分钟后”来替代长期评测；使用现有依赖构建隔离测试环境属于本仓实施工作。

## 用户场景

评测者想知道自己的 PA 是否真正能持续帮助自己。他选定一组场景，以干净的隔离身份开始：先授权 PA 关注工作群的项目变化，随后同事发布截止日期、负责人变动和完成消息，主人也会在私聊里修改自己的要求。PA 在同一段经历里自行记住事项、选择跟进方式、处理更新与停止条件。几天之后，主人再询问进展，应该得到符合最新事实的回应。

这段经历既包含应该提醒、应该追问的时刻，也包含闲聊、无关消息、明确“已经完成”和撤销访问后的安静阶段。评测者不只看说得好不好，还要看是否发给正确的人、是否真的送达、是否重复打扰、是否将过期事实当成最新事实。

评测者不应等七个真实日历日。测试中的日期、后台处理期限、提醒到期、每日节律和有时间条件的记忆维护应随同一个模拟时间前进，保持原来的天/小时/分钟含义；PA 仍自行处理真实输入、维护真实状态并执行原生任务。加速不能跳过本应发生的触发、取消后观察或必要的模型处理。报告分别记录系统经历的时长与现实耗时，区分模拟环境内长期行为和真实机器七天驻留的性能可靠性。

运行结束后，评测者能逐项查看预期、实际结果和证据，区分 PA 做错、产品没送达、模型服务不可用、评测自身失效。再次运行相同基线时，前次运行留下的任务或记忆不会混入。结果能作为后续优化前的基线，但本阶段不进行优化。

## 验收标准

### Requirement: 可重复运行隔离的连续经历

#### Scenario: 七天时间语义的连续回放
- **WHEN** 评测者运行跨度七天的连续场景。
- **THEN** 同一 PA 的状态贯穿七天；“三天后”、每日提醒、消息日期和处理期限保持原尺度，无须等待七个真实日历日。
- **AND** 原生定时逐次发生，记忆、工作状态与后续回复反映已过去的模拟时间，不能只改提示词日期或重放七段短故事。
- **AND** 报告列出模拟跨度、实际耗时、运行中止和未覆盖的时间能力；没有推进到七天终点就不能称完整七天基线。

#### Scenario: 取消、离线和恢复的长期结果
- **WHEN** 工作完成、被取消，或节点离线后在后续模拟日期恢复。
- **THEN** 观察覆盖原到期点与后续周期，依据原生执行和收件侧结果验证停止或恢复；不能用手动触发替代到期，也不能将在线推进误做成离线补发。

#### Scenario: 重新运行基线
- **WHEN** 评测者再次运行同一版本场景和配置。
- **THEN** 使用相同起始状态、模拟日期、事件和时间规则，另记现实起始时间，前一次运行留下的任务、消息和记忆不会污染新运行。
- **AND** 可追溯模型与配置差异，并能区分输入可复现与模型输出随机性。

### Requirement: 评估主动帮助与适当克制

#### Scenario: 事实更新和持续跟进
- **GIVEN** 一项工作已建立，之后发生改期、负责人变更或信息缺失。
- **WHEN** PA 获得对应信息并进入预设观察窗口。
- **THEN** 报告判断其是否采用最新事实、是否在需要时澄清或跟进，以及有用结果是否到达正确收件人。

#### Scenario: 不需要行动或已经结束
- **GIVEN** 场景包含无关闲聊、工作完成、取消或“不要再提醒”。
- **WHEN** 后续观察窗口结束。
- **THEN** 报告能指出无用打扰、重复提醒和未停止的跟进，也能以充分观察证据确认适当的沉默。

#### Scenario: 身份与授权边界
- **WHEN** 同事发出不属于主人授权的指令，或主人撤销某来源的访问。
- **THEN** 报告检查 PA 是否越过身份、来源或发送权限边界，而不把群内可读内容一律当作主人指令。

### Requirement: 结果有可审查的证据和明确的失败类别

#### Scenario: 工具完成而结果没有送达
- **WHEN** PA 的工具记录显示完成，但目标会话没有对应结果。
- **THEN** 报告不判定送达成功，并展示输入、执行和结果之间缺失或失败的环节。

#### Scenario: 沉默来自未处理或不可观察
- **WHEN** PA 没有公开回复。
- **THEN** 报告分别识别合理沉默、该处理却未处理，以及因证据缺失无法判断；不将三者合并为通过或统一排除。

#### Scenario: 环境或模拟能力不足
- **WHEN** 评测缺少必要身份、已声明的现有工具、模型服务、可靠的时间控制或完整证据。
- **THEN** 评测者看到具体原因、已完成范围和未评分项目；不能将无效运行写成 PA 行为失败或完整基线通过。

### Requirement: 得到可复用的基线而非优化结论

#### Scenario: 基线报告
- **WHEN** 一组基线运行结束。
- **THEN** 评测者能查看逐场景的预期、结果、证据、各维度计数、覆盖率和真实成本，能直接定位后续改进方向。
- **AND** 不通过单一总分掩盖漏跟进、骚扰、权限越界或运行失效，不把小样本成绩宣称为普遍可靠性。

## 范围与非目标

- 在范围：隔离 IM 世界中的真实 PA；现有依赖上的加速时间环境；不缩短期限的七天连续经历、有限反馈；原生 Cron/Heartbeat/Inbox、持续记忆、任务行为、保状态重启；证据、语义评判和冻结基线。
- 非目标：等待上游新增时钟接口；PA 策略/提示词/技能或记忆算法优化；自动实验搜索；A/B 胜负分析；桌面多模态采集；全渠道供应商送达；真实硬件七天的泄漏/性能/稳定性；规定 PA 必须使用某文件名或工具序列。
- 加速空闲时间不等于压缩模型计算。真实模型与工具仍执行，运行成本如实记录；隔离时间控制失效时报告无效，不降级为压缩故事并宣称需求完成。
