# 原型实际渲染与走查

日期：2026-10-22。范围是设计原型，不是已实现产品验收。所有任务、人名和内容为虚构示例。

## 依据与方法

现有生产 Tasks 页面已在登录 Chrome 中只读观察：五列、灰底白卡、根任务/负责人过滤、独立子任务入口、遮罩详情不压缩背景看板。没有保存生产私人内容。iOS 以当前原生 TaskModels 和 Task 视图代码为基线，不声称已在原生 App 验证新功能。

原型通过 `python3 -m http.server 46350 --bind 127.0.0.1 --directory docs/changes/feat-635-task-driven-execution` 提供，Playwright CLI 驱动真实 Chromium。已走查 Web 1280×850、Web 390×844、iOS 交互示意 390×844 和配置 430×932。文件协议初次打开被浏览器策略阻止，切到本机静态服务；favicon 404 在增加内联 favicon 后消除。原型不调用产品 API。

- [窄屏 Web 离线](feat635-web-narrow.png)：详情撑满宽度，文字换行、动作可见；保存的安排时间与节点离线分开，未声称定时已执行。
- [iOS 详情示意](feat635-ios-detail.png)：独立的 sheet 边界、纵向信息、顶部关闭、内容下方动作；390 宽时原因和动作未被挤断。已操作暂缓→恢复推进→关闭；暂缓移至待办、进行中计数减一，恢复回进行中并清除等待摘要，反馈文案正确。
- [iOS Goal 默认关闭](feat635-ios-goal.png)：开关、独立能力说明和默认关闭同行可读；已实际点击开→关并核对 aria 状态和保存反馈。430 宽配置及桌面 Web 配置也已渲染，沿用相同内容层级。

走查时修正了推进中示例卡打开后误用等待任务正文的问题，并将该背景示例的状态编辑移出原型可操作范围；waiting 的暂停/恢复完整可操作。原型未实现新建、搜索、后台保存、真实 Schedule、真正 iOS sheet 动画；这些不能据本文件宣称已验收。下游还需在真实 Web/iOS 验证长原因、动态字号、安全区、分页和保存失败。

## R2 修订走查

- [Web 安排失效](feat635-web-invalid-r2.png)：1280×850 实际渲染。保留“等待负责人确认预算”和“预算确认后继续选择供应方案”；其下独立诊断关联安排已删除，时间栏显示暂无有效安排。用户可在同一详情同时判断业务是否仍阻塞、技术安排是否需修复。

- [iOS 安排失效](feat635-ios-invalid-r2.png)：390×844 实际渲染，原因、恢复条件、诊断、时间和动作均可读，没有因新增诊断遮掉按钮；随后切回有效等待，原因保持、诊断消失、恢复原检查时间。离线分支保持既有独立表达，未改动业务原因。

R2 修改限于诊断与业务等待信息分离，并增加 unknown 演示项；普通、失效与 unknown 切换均已实际驱动。仍不声称原生客户端或真实后端已验收。
