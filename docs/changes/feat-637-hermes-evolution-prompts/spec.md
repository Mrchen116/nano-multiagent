## 用户场景

1. 用户长期使用 Agent，明确告知自己的沟通偏好以及项目环境事实。后续会话能准确使用这些信息，而不是把环境事实混入画像，或在多个地方反复保存同一内容。
2. 用户修正旧偏好或过时事实。Agent 后续遵循有明确依据的新信息，不同时引用相互冲突的新旧结论；普通闲聊和临时任务进度不会不断增加长期记忆。
3. Agent 完成一个可重复的复杂任务，积累经验证的方法。后续相似任务能复用精炼的步骤和适用条件，已有技能得到必要修正，而不是积累越来越多事件记录。
4. Agent 为解除当前阻碍临时绕路，例如新建隔离环境。后台学习不会把该行为升级成每轮都必须执行的惯例，也不会将 Agent 自己的选择描述成用户要求。
5. 用户纠正某类工作的处理方式。对应 Skill 承载该类工作的规则，跨任务的人物偏好进入用户记忆；后台单项或联合复盘不会重复保存完整规则或相互改写成矛盾要求。
6. 主 Agent 在执行任务时直接维护技能。它使用与后台维护一致的内容质量要求。若多步维护只完成一部分，它核对实际结果，并准确说明剩余问题，不误报全部完成或全部撤销。
7. 非 Global 模式下，自动创建的 Skill 在多次使用后接受 F4 复盘。系统依据至少两个不同的已结束会话中反复出现的问题修补该技能。证据不足时不改写；手工技能和其他技能不受本次复盘影响。同一技能的复盘不重叠执行，不重复消费已经处理的证据。Global 模式不触发 F4，但保留正常的技能使用、使用记录及其他已启用的自进化能力。

## 验收标准

### Requirement: Memory 准确区分用户信息与环境事实

#### Scenario: 画像和项目事实各归其位
- **WHEN** 用户明确提供长期沟通偏好以及一个已确认的项目环境事实，并完成后台知识维护后开始后续会话
- **THEN** Agent 能按偏好交流，并正确使用该环境事实
- **AND** 用户查看持久知识时，个人信息和环境信息归属清楚，同一事实没有在两个记忆类别中重复保存。

#### Scenario: 没有长期价值的信息不沉淀
- **WHEN** 对话仅包含普通问答、临时进度或未经确认的推测
- **THEN** 后台维护允许没有知识更新
- **AND** 后续会话不会把这些内容当作长期事实或用户偏好。

### Requirement: 维护现有 Memory，而非持续追加重复或冲突条目

#### Scenario: 重复表达不产生重复记忆
- **GIVEN** 一项偏好或事实已被保存
- **WHEN** 用户在后续对话中再次表达同一信息
- **THEN** 用户看到的持久知识没有新增同义副本，后续回答保持一致。

#### Scenario: 明确纠正替代旧事实
- **GIVEN** 已有一项旧偏好或已过时的环境事实
- **WHEN** 用户明确纠正它
- **THEN** 后续会话使用新信息，不继续把被纠正的旧信息作为当前依据
- **AND** 更新仍能追溯到实际依据，不编造用户声明或来源。

### Requirement: Skill 学习产生精炼、经验证且有适用条件的方法

#### Scenario: 有效经验改善已有技能
- **GIVEN** 已有技能覆盖当前任务类别
- **WHEN** 一次任务验证出新的可复用方法或用户明确纠正该类任务的步骤
- **THEN** 后续相似任务能够遵循改进后的方法
- **AND** 用户查看技能时，新增内容表达步骤、条件和必要原因，没有重复旧规则或堆积本次事件叙述。

#### Scenario: 未成功尝试不成为可靠流程
- **WHEN** 一次任务结束时仍未找到验证成功的方法
- **THEN** 后续会话不会将这些失败尝试称为已经验证的推荐做法
- **AND** 后台维护不会仅为产生更新而虚构结论。

### Requirement: 临时恢复经验不覆盖原流程与用户约束

#### Scenario: 新建现场不被泛化为每轮惯例
- **GIVEN** 当前流程要求优先复用适合的现场，并对临时资源承担清理责任
- **WHEN** 某次任务通过新建隔离现场解除局部阻碍，随后触发后台学习
- **THEN** 后续同类任务不会仅因这一经历机械地为每轮新建并永久保留现场
- **AND** 如保存恢复方法，其适用条件、退出和清理责任与原流程相容。

#### Scenario: Agent 的选择不冒充用户要求
- **WHEN** Agent 自行采用一种方法，但用户没有要求把它作为长期规则
- **THEN** 后台知识不会将它记为用户已确认的偏好、授权或必须遵守的流程
- **AND** 新经验不以补充说明的形式悄悄推翻用户明确的约束。

### Requirement: Memory 和 Skill 分工一致，保留已有自进化体验

#### Scenario: 同一纠正不被双份固化
- **WHEN** 用户纠正某类任务的做法，并分别触发 Memory 与 Skill 后台维护
- **THEN** 用户在后续相似任务中看到修正生效
- **AND** 持久知识对完整规则有明确归属，不在 Memory 和 Skill 中重复堆积相同流程或形成冲突要求。

#### Scenario: 关闭自进化仍有效
- **WHEN** 用户关闭某项自进化能力，再进行包含可学习信息的对话
- **THEN** 被关闭的能力不会继续自动修改对应持久知识
- **AND** 其他已启用能力与正常对话保持可用。

### Requirement: 恢复 Memory 与 Skill 的联合后台复盘

两项能力同时满足本次维护条件时，系统 SHALL 使用一次 combined review 处理两类知识。仅一项满足条件时保留单项复盘。各项开关及触发计数保持独立。此规则同时适用于普通和 Global 模式；F4 保持独立。

#### Scenario: 两项同时满足条件
- **GIVEN** Memory 和 Skill 自进化均已启用，且同时达到维护条件
- **WHEN** 当前前台轮次正常结束并启动后台维护
- **THEN** 同一次联合复盘能够保存 Memory 并维护 Skill，知识按正确归属保存
- **AND** 不为同一批到期条件再启动两次单项复盘，更新通知只反映实际写入。
- **AND** 用户从轨迹入口能识别联合用途，并进入同一次真实执行，刷新后仍可辨认。

#### Scenario: 仅一项满足条件
- **WHEN** 只有一项能力达到维护条件，或另一项已关闭或缺少所需工具
- **THEN** 可用且到期的能力仍运行单项复盘，不等待另一项
- **AND** 未参与的能力不被写入，其维护计数不因该次复盘完成而重置。

#### Scenario: 联合复盘失败或中途关闭能力
- **GIVEN** 联合复盘已经启动，可能已有部分知识写入成功
- **WHEN** 复盘失败、取消，或用户关闭其中一项能力
- **THEN** 已成功的修改保留，通知只报告实际结果，不声称全部回滚或全部完成
- **AND** 已关闭能力不再接受后续写入，其他仍启用能力可在后续满足条件时继续维护；未完成复盘不消耗维护周期。

### Requirement: 主 Agent 直接维护 Skill 时遵守相同的质量要求

#### Scenario: 主 Agent 修正已有技能
- **GIVEN** 用户指出某个已存在技能中的错误步骤
- **WHEN** 主 Agent 在当前任务中修正该技能
- **THEN** 用户查看技能时，错误步骤已被修正，其他有效内容得到保留
- **AND** 同一纠正没有被重复写成额外的事件记录或冲突规则。

#### Scenario: 部分修改成功时报告实际状态
- **GIVEN** 一次技能维护需要多步修改，前一步已成功，后一步失败
- **WHEN** 主 Agent 处理该失败并向用户报告结果
- **THEN** 报告与实际保留的修改一致，不声称所有修改已自动撤销
- **AND** 若问题尚未修复，明确说明未完成部分，不将部分结果报为全部完成。

### Requirement: F4 仅适用于非 Global 模式，并恢复原有证据与修改范围约束

本条中的跨会话复盘场景适用于非 Global 运行模式。运行模式与 Skill 的 `agent/global` 存储范围是不同概念；共享存储范围本身不是禁用 F4 的理由。其他写入权限和来源限制仍适用。

#### Scenario: Global 模式不触发 F4
- **GIVEN** Agent 使用 Global 运行模式，其他自进化能力已启用
- **WHEN** Agent 多次使用一个自动创建的 Skill，并达到 F4 的使用次数条件
- **THEN** 系统不为该 Global Agent 排队或执行 F4 复盘
- **AND** 正常的技能使用和使用记录保留，普通后台 Skill 学习与 Memory 自进化不因本限制被关闭。

#### Scenario: 有充分证据时修补目标技能
- **GIVEN** 一个自动创建的 Skill 已达到复盘条件，至少两个不同的已结束会话提供了同一问题的有效证据
- **WHEN** F4 完成复盘并确认具体改进
- **THEN** 目标 Skill 中相应的问题得到修补，原有有效内容保留
- **AND** 不新建、重命名、归档或删除 Skill，不修改其他 Skill。

#### Scenario: 单个会话中的重复使用不等于跨会话证据
- **WHEN** 某个 Skill 已达到使用次数条件，但只有一个不同会话提供有效证据
- **THEN** F4 不修改该 Skill
- **AND** 不把同一会话中的多次使用计为多个会话的证据。

#### Scenario: 无效或已处理的证据不再次支持修改
- **WHEN** 排除未结束会话、缺失记录和已被复盘处理的证据后，剩余有效证据不足两个不同会话
- **THEN** F4 不修改技能，也不报告已经完成技能优化。

#### Scenario: 手工技能不被 F4 自动修改
- **GIVEN** 一个技能由用户手工创建、手工蒸馏，或来源不明
- **WHEN** 该技能被反复使用并达到复盘次数条件
- **THEN** F4 不自动修改该技能。

#### Scenario: 同一技能的复盘不重叠执行
- **GIVEN** 某个 Skill 已有一个排队或运行中的 F4 复盘
- **WHEN** 用户在其他会话中继续使用该技能
- **THEN** 该技能不会同时接受第二个 F4 复盘
- **AND** 后续使用记录仍得到保留。

## 范围与非目标

在范围：

- 更新后台 Memory 与 Skill 自进化提示词，以及主 Agent 的 Skill 管理工具说明、相关参数说明和维护指引；统一 Memory／Skill 分工，避免对同一能力给出矛盾要求。
- 以上游最新固定版本为参考，优先直接复用适合 Nano 的原文；为工具名称、支持动作、维护边界和已有契约做必要修改。
- 补足重复信息、明确纠正、知识归属、无有效学习信号、未验证方法及临时 workaround 泛化的行为覆盖。
- 恢复 combined review：两项同时满足维护条件时执行一次联合复盘；保留单项复盘、独立开关和计数，覆盖部分成功及取消。
- 将 F4 限定于非 Global 运行模式，并恢复原有证据门槛、目标限制、来源保护、已处理证据去重和同一技能复盘不并发的约束；允许为此补齐专用提示词、必要执行检查及对应回归验证，不以纯文案更新代替行为恢复。
- 保持已有按 Agent 的隔离、开关、来源可追溯要求和知识更新反馈；不以提示词更新暗中改变这些行为。

非目标：

- 本需求不清理现有 worktree，不批量重写用户已有 Memory／Skill，也不自动修复此前产生的全部错误规则。
- 不引入第二套运行时、额外常驻评审 Agent、审批系统、自动上游同步或独立知识治理平台。
- 不为与提示词适配无关的 Hermes 能力扩大范围，例如整套 curator、存储后端或调度机制重做。
- 不移植 Hermes 的批量操作协议、跨调用回滚或整个 Skill 的删除能力；本次保留 Nano 现有工具协议。
- 不设计 Global 模式的 F4 证据单位，不以轮次、Task 或换窗替代原跨会话门槛。Global 模式的 F4 后续另行对齐。

## 交给设计阶段的参考约束

用户的“能复用的直接复用，不能复用做必要的修改”是实现保真要求，由设计逐项落实，不能仅声称“参考 Hermes”。设计应给出原文来源、复用／修改／不适用判断及具体理由，覆盖 Memory、Skill 和 combined 三种复盘。

需要明确的适配点：

- 恢复旧版 combined 分支，并复用上游联合复盘的知识归属规则。按 Nano 工具名称和动作适配，不把当前分离实现当作必须保留的约束。
- `skill_manage` 保留 Nano 的单操作输入、`edit` 整文件重写、`patch` 局部修改和 `scope` 写入范围。工具说明不得承诺支持 `operations[]`、`replace_all`、支持文件局部 patch、整个 Skill 的 `delete` 或跨调用回滚。局部修改优先、修改前读取、规则提炼和去重等内容要求可以复用，并按现有能力表述。
- Hermes prompt 中关于强制先读后写、后台 curator 会完成后续工作的声明，必须与 Nano 实际能力核对。可保留读取和核对要求，但不能声称尚不存在的工具保证；如确需最小配套实现，在设计中说明必要性和范围。
- 优先复用知识分类、提炼、去重与失败方法排除规则；针对积极更新压力和局部 workaround 泛化做必要适配，允许有依据地保持不变，同时保留有效学习能力。
- Memory 与 Skill 分别维护时，应能落实统一归属，不能让仅有 Memory 工具的 review 被要求修改 Skill，或反之。保留 Nano 已有的来源追溯及“记忆不代表新授权”边界。
- 对本文件场景使用有真实输入和维护产物的验证，区分文案覆盖与实际模型行为；不能只靠字符串包含测试宣称行为问题解决，也不承诺 prompt 对所有未来会话给出绝对保证。

## 已确认的 F4 回归修复

历史调查发现，[feat-446 原需求](../archive/feat-446-skill-view-tool/spec.md) 对 F4 要求至少两个会话的证据，只修改目标 Skill，不创建或修改其他 Skill。旧实现包含对应的专用提示词和证据数量检查。

当前 DSH 的 F4 入口复用通用 `skills.txt`，再追加目标 Skill 和历史记录。该入口没有保留旧版专用提示词中的完整限制，也未看到至少两个会话的前置检查。这是当前代码与历史约束的差异，不表示已验证生产环境发生了越界写入。

用户已确认：“那应该就是搞错了，恢复 F4 原有约束”。上述约束恢复已纳入本 unit，不再作为待选范围。

恢复以原行为为准，不要求恢复旧 Python 模块。设计和验证须区分后台对话学习与 F4；覆盖证据不足、越界修改和同一技能并发复盘，不能只用预设模型返回一次合法 patch 来证明原约束已恢复。此调整不要求引入 Hermes 批量工具协议或全库整理流程。

### 已确认：本次 F4 仅适用于非 Global 模式

设计核对时发现，[Global 主会话绑定](../../../packages/personal-assistant/src/global-agent.ts) 按 `global:<agentId>` 复用持久 session。多个任务、多个聊天来源和多轮使用可以发生在同一个 session 中。因此，“至少两个不同的已结束会话”不能直接作为 Global 模式中独立使用经历的等价条件。

Agent 曾建议采用两个不同会话中已正常完成的使用记录。用户未接受该建议，原话：“妈的，这个很棘手，现在global模式好像跟F4有点冲突，我没想好”。

用户随后决定：“F4或者现在只限制成非global的吧”。本次按此限定适用范围：非 Global 模式恢复原 F4 约束；Global 模式不触发 F4。Global 模式如何划分独立经历不在本 unit 内设计，也不阻塞本次提示词修复。不得把两轮调用、两条消息、两次换窗或两个子会话自行视为两份独立经历。

Memory、普通后台 Skill 学习和主 Agent 工具提示词的既定范围不变。需求范围按本次决定收口，可继续设计。旧版设计已有 Round 1 审查；本次范围修订尚未复审、实现或产品验收。
