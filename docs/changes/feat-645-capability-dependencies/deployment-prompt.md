# feat-645 部署时补齐已有 Feature 依赖

这是交给部署 Agent 的执行提示词。本文件当前只保存操作要求，不代表已执行迁移，也不单独授权现在操作生产。应在本 unit 完成实现、用户要求部署该版本时使用。具体依赖以届时本 unit 定稿设计及目标版本实现为准，不把当前旧版 `requires_tool` 当作完整依赖表。

## 可交给部署 Agent 的 Prompt

请在本次用户已授权的 nano-multiagent 部署中，执行 feat-645 的一次性配置整理：**保留已有开启的 Feature，自动补齐其必需工具和 Skill，不因升级关闭 Feature。**

先阅读本仓 AGENTS.md、`prod-fleet-deploy` skill、当前生产运行手册，以及本 unit 的 spec、定稿 design 和依赖声明。若 unit 已归档，沿同一 unit ID 查找归档目录。遵循本次部署的节点范围和版本，不把历史路径、进程、Agent 配置或生产事件快照当作当前真相。

### 确定本次要补齐什么

1. 核实目标版本已经实现本 unit 的配置契约：工具开启即实际可用，Feature 不再是工具可用性的额外门槛。设计或实现尚未完成时，不用修改生产配置来模拟新行为，报告尚缺的部署前提。
2. 根据最终设计及实现列出各 Feature 必需的全部工具与 Skill，以及加载这些能力所需的依赖。核对基础固定能力的最终范围。不能把所有默认勾选项当作必需依赖，不能仅凭旧单个 `requires_tool` 推断完整清单，也不能自行发明设计尚未确定的关系。
3. 读取本次部署范围内 Agent 的真实持久配置，按升级前的有效语义判定哪些 Feature 已开启。区分缺省值和显式关闭，不把缺省字段一律解释为开或关。
4. 对每个 Agent 形成最小配置差异：保持已开启 Feature 开启；补齐其必需工具；使必需 Skill 可发现、可加载，包括按配置格式移除相关禁用项或补入相关允许项。多个已开启 Feature 取依赖并集。
5. 保留其余工具、Skill、模型、审批、身份、提示词及其他配置。Feature 已关闭但用户单独打开的工具或 Skill 保持可用，不反向开启该 Feature。Task 必需等待复查能力按最终依赖补齐，不擅自开启无关 Feature 或扩大通用调度能力。

### 应用与保存

按部署手册确定权威配置源、写回进程和服务顺序。在修改前保存可恢复的配置备份及必要状态，核对修改范围；通过项目支持的配置入口或手册规定的安全维护方式应用，避免运行中的配置写回覆盖修改。配置差异与执行证据保存在受保护的本地部署记录，凭据、原始个人配置及数据库不提交仓库。

这是部署 Agent 在升级窗口执行的一次性整理。**不向产品代码加入历史配置自动迁移、每次启动补齐旧配置或长期兼容逻辑。** 正常产品配置操作如何保证依赖完整，仍由本 unit 实现负责，不用部署提示词替代。

记录本次已处理的部署环境、版本、Agent 范围、备份位置及结果。发生中断时根据记录恢复本次未完成部分；已完成后不在后续普通重启或重复部署中重放旧配置整理，以免覆盖用户后来合法关闭 Feature 或单独调整工具、Skill 的选择。

### 验证与交付

- 对照迁移前后配置，确认原先开启的 Feature 均保留、必需依赖齐全、无关选择保持；界面重新读取后与保存结果一致。
- 验证目标版本实际加载的能力与配置一致：模型可见并可调用相应工具，必需 Skill 可发现和加载；不能只看勾选状态或服务在线。
- 对 Task 核实等待复查所需能力实际可用；结合本次部署已授权的验收场景验证有效安排与等待关联。不要随意改动已有业务任务来制造验证结果；没有实际走完的场景明确标为未验证。
- 确认原有审批与权限仍适用，工具可用不代表任意操作已经授权；不修改 Task/Goal 归属或做双写，不顺带修复其他运行语义问题。
- 汇报具体补齐范围、配置及运行验证结果、备份恢复位置、未完成项。依赖资源缺失或无法兑现时，报告具体缺口，不通过关闭 Feature、伪造可用状态或绕过审批宣称成功；按部署手册处理恢复。
