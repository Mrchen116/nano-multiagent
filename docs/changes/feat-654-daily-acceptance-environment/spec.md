# feat-654: 固定日常协作验收环境

## 原始需求

> 你可以看一下我们的skill，我们正常的开发流程里面，后面会有一个真实测试。那真实测试，它会构建一个真实的环境，对吧？它会开几个agent之类的。我想问他开多少个Agent，然后每个Agent叫什么名字啊？有什么职责？这些是现在已经定好的吗？还是他后面每做一个需求之后，他临时弄的？

> 我想把这个真实测试环境固定得更像日常使用，有明确名字和职责的几个 Agent，再加一个 PA。每次需求都复用这套环境。你可以看一下我实际的真实环境。

## 澄清记录

- Q1：“每次复用这套环境”，建议固定 Agent 阵容、职责、群聊和初始资料，每个需求启动独立副本，聊天与任务从基线开始；还是长期共用同一个环境、保留聊天和任务历史？
  - 用户选择：**固定模板，每个需求独立启动（推荐）**。
- 当前现场依据：2026-10-25 只读核对 Air/Mini 的实际 Gateway 配置、对应存活进程、P/E/Q 的 TEAM/ROLE 文件，以及 Mini IM 中的日常群成员与 PA 绑定。现有“ Nano 研发日常”群由主人和 `P · 产品与体验`、`E · 工程交付`、`Q · 独立质量` 组成；Mini 的 `Personal Agent` 有 active 主人绑定。这里只引用角色组织，不复制私聊、历史任务、凭据或生产身份。
- Agent 对需求的具体化：固定基础阵容为上述 P/E/Q 三个团队 Agent 加一个 PA；沿用可辨认的显示名，PA 显示名为 `PA · 个人助手`。P 整理目标和验收标准，E 落实交办并提供可检验结果，Q 独立核实结果，PA 为测试主人整理上下文、跟进明确交办。预置日常群、PA 私聊和小型示例项目资料。测试环境的 Q 是产品内的协作成员，不能替代开发流程中独立的产品 reviewer。

## 用户场景

开发者或独立产品 reviewer 验收新需求时，直接启动固定的日常协作模板。进入产品即可辨认 P/E/Q 的分工、与三人沟通的“研发日常”群，以及属于测试主人的 PA 私聊，不再每次临时发明测试成员。

模板提供同一份虚构的小型项目资料。测试者可向 P 澄清目标，交 E 完成一个有具体产物的任务，再让 Q 核实，并在 PA 私聊中询问团队进展。各角色根据自己的实际职责处理消息；PA 的主人关系、来源访问和私人聊天采用真实产品能力。

不同需求使用互相独立的环境副本，固定名字、分工和初始资料保持一致，运行中新增的聊天、任务和文件不进入下一次基线。当前需求可在副本里增加必要场景、用户或 Agent；启动、验收交接和报告能看清基线与本次补充。

## 验收标准

### Requirement: 固定可辨认的日常协作阵容

#### Scenario: 打开新环境
- **WHEN** 测试者按开发流程启动日常验收环境并登录
- **THEN** 能看到 `P · 产品与体验`、`E · 工程交付`、`Q · 独立质量` 和 `PA · 个人助手` 四个基础角色，以及“研发日常”群和 PA 私聊。
- **AND** 各角色的设置中有明确职责，日常群包含测试主人和 P/E/Q。

#### Scenario: 按职责完成一次工作
- **WHEN** 测试者依据预置示例资料，将一个小目标分别交给 P 整理、E 落实和 Q 核实
- **THEN** 能在真实聊天中收到与各自职责相符的结果，E 的工作具有可检查产物，Q 根据实际产物给出结论。

### Requirement: PA 具有真实个人助手关系

#### Scenario: 主人私聊与团队上下文
- **WHEN** 测试主人打开 PA 私聊并询问日常群中已发生的工作
- **THEN** PA 能基于允许访问的真实团队上下文回答，且以主人的个人助手身份提供帮助。
- **AND** PA 不需要作为团队群成员才能供主人查看该来源。

### Requirement: 每个需求复用同一基线并保持隔离

#### Scenario: 新需求独立启动
- **WHEN** 一个环境已有测试消息、任务或示例文件修改，另一个需求启动自己的环境
- **THEN** 后者仍有相同名字、职责、群聊组织和原始示例资料，不能看到前者新增的消息、任务或文件修改。

#### Scenario: 在基线上补充需求场景
- **WHEN** 当前需求需要额外成员、聊天或配置
- **THEN** 可以在当前副本中补充并在验收交接中说明，其他需求的基线不受影响。

### Requirement: 开发流程默认复用模板

#### Scenario: 准备与交接真实产品验收
- **WHEN** 主 Agent 准备正常开发流程的真实产品验收并交给 reviewer
- **THEN** 使用固定日常模板并交接本次入口、身份、角色、群聊、PA 和场景补充；reviewer 按需求观察真实结果。
- **AND** 环境准备失败时给出具体失败信息，不能把只有进程启动成功报告成日常模板已就绪。

## 范围与非目标

- 在范围：仓库维护的固定模板、初始示例资料、真实 PA/群聊建立、每需求隔离实例、相关开发 skill 与运行说明、自动回归与真实产品验收。
- 非目标：修改生产环境、搬迁生产 Agent、复制私人聊天/任务/记忆、建立长期共享测试服务器、要求测试团队替代开发侧 reviewer、复制完整生产双节点拓扑、改动产品的任务调度或 PA 权限机制。
- 保留既有低层自动化和专用 Feishu 验证场景；只有需要这些场景的需求才补充，固定日常基线不要求每次连接外部渠道。
