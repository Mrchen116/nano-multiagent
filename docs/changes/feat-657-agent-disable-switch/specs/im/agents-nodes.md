# im agents-nodes Specification (delta for feat-657)

## ADDED Requirements

### Requirement: 真人管理者可以独立启用和停用 Agent

#### Scenario: 从 Agent 入口停用
- **WHEN** 有权管理该 Agent 的真人在列表、详情或工作视图停用它
- **THEN** 立即提交停用，不需模型回答、二次确认或先保存其他设置；空闲 Agent 同样进入停用
- **AND** 不连带停止其他 Agent，不保存未提交的配置草稿

#### Scenario: 非管理者和 Agent 自身
- **WHEN** 非管理者或 Agent 工具尝试改变开关
- **THEN** 操作被拒，不能通过普通消息、任务或节点配置上报解除停用；原有可见性仍适用

### Requirement: 停用意图与停止确认分别展示

#### Scenario: 在线清理
- **WHEN** 停用已受理但尚在清理执行
- **THEN** 显示正在停用，只有全部受管执行确认停止后显示已停用

#### Scenario: 离线或清理失败
- **WHEN** 节点离线或无法确认全部受管活动停止
- **THEN** 显示等待节点确认或停止未确认，保留禁止新工作的状态并允许重试停止，不允许直接重新启用旧执行

#### Scenario: 设备在线但 Agent 停用
- **WHEN** 查看停用 Agent
- **THEN** 独立展示 Agent 开关和设备连通性，不用设备在线暗示它可以工作

### Requirement: 重新启用保留资料且不自动恢复旧工作

#### Scenario: 明确启用
- **GIVEN** Agent 已确认停用
- **WHEN** 有权管理的真人重新启用
- **THEN** 可以处理新工作，历史、会话、文件和任务仍可访问
- **AND** 旧任务、子 Agent、Bash、审批、积压输出不自动恢复，错过的定时触发不补跑
- **AND** 旧任务只在新的真人明确恢复后继续，独立周期计划仅从未来触发点运行

## MODIFIED Requirements

### Requirement: Agent 设置与外部渠道离线时保持可读并统一只读，恢复后刷新再解锁

#### Scenario: 离线首次打开或跨浏览器查看
- **GIVEN** 当前用户有权查看该 Agent，但节点不可达
- **WHEN** 用户打开整个 Agent 配置页及相关分区
- **THEN** 页面显示已保存配置和最后成功同步的展示信息、来源与时间，没有取得的信息明确暂时无法获取
- **AND** 模型与推理强度成对保留；插件、统计、任务和渠道的未知状态不伪装为空、关闭或失败，已同步工作历史仍可阅读
- **AND** 所有配置写入和节点操作禁用，阅读、展开、取消、放弃草稿及检查连接仍可用
- **AND** 独立的 Agent 停用控制例外：有权管理的真人仍可向 IM 提交持久停用意图并重试；页面显示等待节点确认，不声称已停止，尚未确认时不能重新启用

#### Scenario: 编辑中掉线并恢复
- **GIVEN** 用户已有未保存草稿或已打开的渠道编辑弹窗
- **WHEN** 节点失联并随后重新连接
- **THEN** 页面保留本页草稿并立即禁用修改和提交；重连先刷新当前配置、能力、相关资源版本和未确认结果，完成后才恢复相应操作；独立停用控制仍按生命周期权限和确认状态可用
- **AND** 刷新或历史数据均不自动提交草稿、不清空选择、不替用户补默认值；迟到的旧请求不能解锁页面
- **AND** 若版本或真实能力变化造成冲突，用户核对、调整或放弃后再主动保存，不能自动用新版本覆盖服务端内容

#### Scenario: 在线某一区域读取失败
- **GIVEN** 节点在线但某一设置分区的当前信息未取得
- **WHEN** 用户查看该分区
- **THEN** 页面保留最近确认内容、说明读取失败并允许重试；该分区未刷新成功前不可操作
- **AND** 独立分区不因统计等无关读取失败被禁用，历史信息不充当当前能力
