# feat-658 一次性部署提示词

适用条件：本 unit 已合入且用户另行授权部署。本文件不是本轮生产操作授权。部署 Agent 使用 prod-fleet-deploy，按当时 runbook 记录 IM、全部接收节点、Web 和在用 iOS 的实际版本。

## 前提与迁移

1. 实施提供对现有 `pa_delegated_messages` 增加 nullable `representation_operation_id` 的迁移；在隔离数据库副本 dry-run/apply/verify，包含旧 PA 消息、旧 prepared/allowed/confirmed 操作与已有 relay/event。新库 schema 同步。重复执行不改旧值，不从 label/body 推断授权。
2. 暂停入口流量及相关节点执行，备份数据库、部署版本和客户端可恢复产物。未消费的旧 PA 操作始终 self；过期 permit 仍按现有规则重新审核。
3. 更新 IM、节点/DSH integration、Web 和在用原生 iOS。只有所有接收节点与在用客户端具备新来源契约后恢复入口；不在混合版本期间开放 owner 模式。离线节点须先更新再接入新 relay。若在用 iOS 尚不能更新，则保持新 owner 发送未开放，不以旧客户端无标记展示冒充验收通过。
4. 核对新增列全部旧行 NULL、旧消息仍为 Agent、无历史补发/补授权。用部署许可允许的测试身份完成一条真实新代发，检查用户消息、来源、operation 关联、持久事件和 relay 一致；两端身份正确，审核/路由不回声。生产验收消息不得替用户做真实合并/部署/发布承诺。

## 故障恢复

- 启用前故障：保持入口停用，恢复备份与旧部署；此时尚无新消息，不能重放迁移样例。
- 已产生新消息后：停止入口及 owner 发送，保全新消息、来源与 operation 关联，优先前向修复。不得直接让不识别来源的旧节点消费新消息，不删除来源列或把新用户消息重写成旧 Agent 消息。
- 若必须回旧版本：由部署负责人先形成保全新数据的恢复方案及明确的服务停止窗口，再取得用户对具体恢复方案的授权；不能自动回滚数据库而丢失部署后消息。

实施在 M1 留下副本前后计数、旧操作模式验证、重复执行、失败中止及版本协调演练证据。所有生产停止/启动、备份、验证细节复用部署 runbook，本 unit 不加入永久兼容开关或第二套路由。
