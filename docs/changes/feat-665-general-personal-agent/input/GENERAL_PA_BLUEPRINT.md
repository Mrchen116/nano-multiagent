# 把 Nano 做成真正通用的长期个人助手

## 核心方向
PA 的主线不是开发，也不是分派任务，而是持续了解并帮助一个人：知道他关心什么、当前有哪些现实约束、哪些事情已经处理、哪里可以提前省心。长任务的持续执行者只是这一能力的一部分。

整体回路：**获准上下文 → 相关记忆与当前事项 → 判断有什么值得做 → 私人准备或授权内行动 → 真实交付 → 用户反馈与记忆修正。** 每个环节都有可查状态，而不是用一段提示让模型“自行保证”。

## 应当看得见的变化
| 场景 | PA 应做什么 | 不应做什么 |
|---|---|---|
| 用户在群里答应交材料 | 核对之后有没有交；找齐资料、准备草稿、适时私下提醒 | 把用户承诺当作代发授权 |
| 用户说以后优先下午开会 | 保存带场景的偏好，下次排时间实际使用 | 只会复述“记住了”，或自动改既有会议 |
| 群消息里活动改期 | 与当前安排交叉核对，形成调整建议 | 不查后续消息便提醒冲突 |
| 某个长期目标有新机会 | 在允许的观察/准备范围核实并准备可用成果 | 等用户再次逐件交办，或只问“要不要帮忙” |
| 同时交办研究、出行和文档 | 独立持续执行，主 PA 仍可响应，变更交回原负责人 | 三个领域都套开发流程，或每阶段换人 |
| 用户已经自己完成 | 更新原事项或关注项，不再催办 | 因旧笔记没关闭反复问 |
| 用户说“忘记这个” | 处理受控记录、投影、索引、活跃上下文及防复活，并报告范围 | 只删一个 Markdown 条目便宣称全系统抹除 |
| 没有日历或预订账号 | 先给核验过的方案，再指出最小接入缺口 | Skill 名里有“出行”便谎称订好了 |

## 现有基础不重造
保留现有 Global 主上下文、IM 来源模型、Task、原生子执行、Heartbeat/schedule、KnowledgeRuntime、技能选择、独立披露审核及 Work 可观测性。核对证据见 [现状与缺口](design/01-current-state-and-gaps.md) 和 [来源](SOURCES.md)。

具体补齐：

**记忆闭环。** 现有小型 USER/MEMORY 适合作为常驻概览，新增受控事实记录和检索；明确纠正走快路径，后台整合走原维护机制。域内个人偏好留在个人记忆，而不是共享 Skill。相关任务状态从原 Task/原系统查询，记忆不复制第二套状态。

**新价值发现。** 观察者只研究并回传，不直接联系外人或执行交易。主 PA 区分已委托工作、用户自己的承诺和未采纳机会。私人关注项记录发现、提议与反馈，接受之后关联原 Task/工作对象，不建平行任务引擎。

**主动而不烦。** “无新消息”不是强行通知的理由；“没收到新用户指令”也不是已授权工作停止的理由。先私人准备，再决定执行、建议、提醒或静默；少量有价值结果取代高频状态播报。

**可靠执行。** 复用原负责人、原生执行 ID、实际回传和回执。暂停/取消要真的停止；已有子执行进行中，主 PA 不重复实施，也不能永久失联。Task waiting 的现有校验继续有效。

**通用领域能力。** 12 个 Skill 覆盖主动关注、记忆、持续工作，以及研究决策、沟通、日程、出行、购物服务、行政表单、文档分析、学习、软件开发。连接器说明与领域方法分开；不要全文常驻，也不要硬编码竞品工具名。

**用户控制与产物。** 仍以 IM 为中心，展示正在代办、需要决定、为你留意；有来源、可修改、可稍后、可停止。生成文档或文件必须走可访问的真实产物交付，不把执行机器上的路径当下载链接。

## 最小新增接口
扩展已有 `memory`；新增 `personal_context` 只读组合查询和 `personal_attention` 私人关注/反馈。其余优先扩展已有 Work、Task、配置、事件与文件交付能力。若完整核对后没有生成产物的发布工具，再加最窄受控发布动作，不先造大而全连接平台。

模型可见授权、owner、受众、来源标签必须由宿主验证。结构化字段不是许可凭证，安全边界不能只写在提示里。

## 如何吸收参考，而不是照搬
Dots 官方资料支持长期负责、主动读取获准来源、研究与动作权限分离；社区 Skill 快照提供各领域办事细节。Instinct 的分层记忆材料是黑盒作者研究，启发摘要加按需明细，不当作其源码事实。Muse 社区提示补充统筹、分工与服务方式。所有新提示/Skills 为 Nano 重新组织，不复制产品专属工具或未经验证的内部参数。

## 交付顺序
M1：记得且用对——记忆和当前上下文。
M2：看见且帮得上——IM 增量、关注、准备与反馈。
M3：做得完且可控制——多事项执行、领域能力、真实产物与体验。

不是让用户多审批三轮。沿用仓库现有 change 流程，已确认的范围不重复问，真实设计冲突才对齐。全部目标通过 58 个合成场景和真实链路验证，不以文档、截图或模型自称完成代替证据。
