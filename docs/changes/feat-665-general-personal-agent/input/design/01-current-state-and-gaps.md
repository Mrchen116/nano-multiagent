## 产品目标
通用 PA 应能：理解用户、记得且用好信息、看见新需求、在授权内主动准备与行动、持续跟进、少打扰但不失联。开发是一个领域，不是总任务模型。IM 中用户的所有获准收发、人物与群、Task、执行结果，构成独特上下文；用户不需要手动转发，PA 也不需要监控屏幕才能主动服务。

## 代码已确认的缺口

### G1：受控长期记忆目前是两份有很小上限的文件
`MemoryChange` 仅 add/replace/remove，目标是 USER.md 与 MEMORY.md。字符上限分别 1375 和 2200，来源注释也进入长度计算。适合紧凑前缀，不足以作为长期个人事实的唯一受控知识层。普通工作区可存在别的文件，但不等于已有可管理、可溯源、可纠错的分层个人记忆。

改：增加记录层与查询；保留两份文件为短投影。不能只改大上限或把所有聊天塞进 prompt。

### G2：模型可见记忆快照延迟刷新
`features/memory-curation.ts` 使用 `compactedAt` 缓存，直到压缩边界变化才重建摘要。文件更新并不等于下次模型调用已获得最新事实；具体回答是否出错取决于其当前上下文，需实测。

改：关键纠正/遗忘立即触发失效或小型版本增量；一般事实按需检索；保留静态前缀的缓存收益。验收最终模型输入，而不只检查文件。

### G3：领域个人偏好可能被误放进 Skill
现有工具描述把 task-specific preferences 指向相关 Skill。对编码规约可能合适，但通用 PA 的餐饮、酒店、写作对象等个人偏好应在个人记忆中按场景检索，不能依赖特定 Skill 才出现，更不能进入全局共享方法。

改：清楚区分“这个人偏好什么”和“这类事怎样做好”。更新工具描述、PA 路径维护 prompt、combined prompt 和检索消费方式，保持非 PA 环境知识兼容。

### G4：默认提示倾向已交办工作，缺少明确的新价值发现路径
原默认提示已正确防止把偶然提及变任务，但没有完整规定如何理解用户自己的承诺、发现可提前准备的机会、保存待采纳建议、抑制重复提醒并吸收反馈。

改：不改授权边界，新增“观察 → 核对 → 私人准备 → 执行/提议 → 反馈”服务路径。记录关注不等于授权执行。

### G5：生成产物的可访问交付必须补查
已读的 personal-security.ts 明确支持转发已上传的原生 IM 附件，并说明本地路径不是上传、该路径没有 upload 工具。不能据此断言全仓所有插件都不具备上传能力，但通用 PA 的文档/表格/图片等成果必须有从执行环境到用户可打开资源的真实链路。

改：完整核对当前文件/附件/产物接口，已有则接通与验证；没有则新增最窄受控发布/import 动作，携带真实内容、受众、来源、版本和回执。先私人发布，外发另走原披露检查。不能以“文件生成成功”替代交付。

## 必须验证，不能冒充已确认 Bug
| 风险/缺口 | 为什么要测 | 不允许的推断 |
|---|---|---|
| 任务 doing + 活跃子 Agent 导致主 PA 重复续跑 | 两种已有机制需要显式绑定 | 不能仅读规范就声称已经复现空转 |
| 事件与记忆维护之间错过纠正 | 背景批次、实时消息、压缩同时存在 | 不能假定所有输入都已摄取 |
| 原生 child 可跨重启追加、取消并回传 | 有恢复与观测代码不等于完整产品闭环 | 不宣布“已支持永久线程” |
| 领域工具实接与权限 | 有 Skill 文件不等于有账号连接 | 不宣布所有日历/购物/电话已可用 |
| 私人信息从通用脚本或插件外传 | 聊天披露审核不是通用网络隔离 | 不称现有 reviewer 是完整沙箱 |
| UI 编辑/稍后/忽略等动作回传 | 卡片存在不等于点击业务闭环 | 不以截图代替状态及权限验收 |

## 本次范围，按用户价值排序
P0：记忆写入—检索—实际消费—纠错/遗忘；IM 变更关联与最新状态核对；用户承诺/机会与委托分离；主动准备与通知闭环；可靠多事项执行与真实交付；暂停、拒绝和来源边界。
P1：通用领域 Skill 集、动态能力说明、关注/记忆可管理 UI、长期权限的方便校准、领域外部连接器适配。
P2：在测出瓶颈后再加向量检索、重排序、预测性个性化、更多外部渠道、自动 Skill 提升评估。它们不是通用 PA 可用的前提。

## 明确不做
不把 PA 改成开发经理；不默认添加十个长期独立角色；不新建平行 Goal/Task 引擎；不每条 IM 消息启动多模型；不从观察消息制造授权；不靠更长 prompt 代替机制；不把所有 Skill 全文常驻；不强制用户先填完整人生问卷；不无条件接入外部账号或扫描历史全库。
