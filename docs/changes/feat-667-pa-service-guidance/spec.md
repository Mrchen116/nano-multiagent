本轮决定（Agent 对上述澄清的整理）：

- A+B 合并为本 unit 的单个交付：A 是服务指导、持续工作与轻量准备方法；B 是增加一层委派，以及所有 Global Agent（含 PA）的主/子产品工具边界。

- 保留现有持久化与恢复机制，不新增全自动跨重启执行恢复、重复副作用防护管理器或取消后的永久执行封禁。

- 暂不引入独立观察者；主 PA 继续使用已有获准来源做轻量观察、核对和私人准备。子 Agent 不获得 conversations 的观察者例外。
- 不增加按事项的文件、Memory 或历史隔离系统；既有权限与上下文继承规则保持，委派交接仍应只提供相关材料。

## 用户场景

1. 主人问一道简单问题或要一份简短晚餐建议，PA 直接给出有用答案，不要求管理任务或执行团队。主人交办需要较长时间的文档、研究、计划时，PA 在已有能力内安排执行，保留当前事项与结果归属。
2. 两项不相关工作同时进行，主人更正 A 的条件，随后问一个短问题；PA 能接住新问题，将更正带回原有工作，避免从头重复实施或串用 B 的条件。取消 A 只影响 A，B 仍交付。执行能力不足时明确说明已完成、未完成与原因，不能用确认收到代替结果。
3. 主人在获准观察的聊天里答应提交一份说明。PA 核对原话、责任及后续变化，在私人范围准备可直接使用的材料或草稿；不把这个承诺认成对外发送授权，也不凭没有材料而编造事实。
4. 主人后来已经提交，或相关情况没有变化、没有新的帮助价值时，PA 核实后停止重复催办。看到信息不全或无法访问的来源时明确覆盖限制，不假装已经检查完。
5. 主人可以沿用已有自定义、清空默认指导或禁用相关 Skill；升级不会偷偷恢复选择。已安装旧 PA 不被自动切换到新服务方式，不增加需要主人管理的配置流程。

## 验收标准

### Requirement: PA 按工作规模提供帮助

#### Scenario: 小事直接完成
- **WHEN** 主人提出当轮能完成的简短解释或生活建议
- **THEN** PA 直接给出可用答复，不要求主人额外管理任务或分工。

#### Scenario: 长事项持续交付并说明能力边界
- **WHEN** 主人交办需要较长处理的事项并给出明确结果要求
- **THEN** PA 在实际已有能力内持续推进并交付可核对结果；能力不足时清楚说明已完成部分、具体缺口和未完成结果，不把接单或内部确认称作完成。

### Requirement: 多事项的更正和停止不相互混淆

#### Scenario: 更正与短问题
- **GIVEN** 两项独立工作实际进行中
- **WHEN** 主人更正其中一项并提出一个独立短问题
- **THEN** PA 回复短问题，并使被更正事项按新要求继续，另一项的目标与成果保持独立；不让主人重新交办同一件事。

#### Scenario: 单项停止
- **GIVEN** 两项独立工作实际进行中
- **WHEN** 主人明确停止其中一项
- **THEN** PA 如实说明该项的停止结果，不把其晚到成果当成重新开始的理由；另一项仍能继续并交付。

### Requirement: 获准观察可促成有用的私人准备

#### Scenario: 承诺后的实际准备
- **GIVEN** 主人在获准观察的聊天里对他人作出明确承诺，资料足以准备一份有用草稿
- **WHEN** PA 获得该变化并核对原话和后续状态
- **THEN** 在私人范围提供或保存有具体内容的准备成果；不擅自对外发送、不冒充外部工作已完成、不增加主人未作出的承诺。

#### Scenario: 已处理、无新价值和覆盖不足
- **WHEN** 后续消息表明主人已经处理，或核对后没有新的帮助价值
- **THEN** 不再针对同一旧状态重复催办或制造无意义通知。
- **WHEN** 当前可读取信息不足以核实处理状态
- **THEN** 保留不确定性，不声称已经完整检查或事情仍未处理。

### Requirement: 服务指导尊重原有个人选择

#### Scenario: 自定义、清空和禁用保持
- **WHEN** 已有 PA 升级、重试创建或主人修改/清空服务指导、禁用相关 Skill
- **THEN** 原有选择保持有效，不自动补回默认指导、不绕过禁用项；主人仍使用原聊天和配置入口。

### Requirement: 主 Agent 负责协调内部多级执行和对外交付

#### Scenario: 任务执行者可再委派一层
- **WHEN** 主 Agent 的执行者需要将独立子工作交给下级
- **THEN** 可以完成主 Agent → 执行者 → 下级执行者的协作并逐级回传成果；最终仍由主 Agent 对用户负责，不要求用户管理内部人员。

#### Scenario: 子 Agent 只进行内部通信
- **GIVEN** 普通 Global Agent 或 PA 正在使用内部子 Agent
- **WHEN** 子 Agent 需要聊天资料、汇报进度或交付结果
- **THEN** 它向父级提出请求或回传结果，由主 Agent 查询并判断对外交付；子 Agent 不自行消费主 Inbox、读取产品聊天或向用户、群聊和外部 IM Agent 发送产品消息。

#### Scenario: 主人要求接续已停止事项
- **GIVEN** 主 PA 已记录事项执行者并根据主人要求停止该项
- **WHEN** 主人明确要求接续
- **THEN** 主 PA 根据当前 Task 状态、记录和实际执行者状态，沿既有机制联系原执行者；无法接续时说明具体情况，不静默从头复制工作，也不将晚到结果当作恢复授权。

## 范围与非目标

- 在范围：通用 PA 默认指导、持续工作方法、轻量主动准备方法；真实模型输入/工具回执/用户结果验证；必要的既有发现与配置保真检查；同配置现状与候选的有限对照，不能推导未经支持的提升百分比。
- 在范围的 B：原生委派深度 1→2；所有 Global 子 Agent 的上述产品工具注册边界与相应提示指导一致；父子内部通信保持。相关现有能力与真实旅程统一验收，失败时保留未通过，不用拆到后续 B 掩盖。
- 非目标：独立观察者、Task-child 硬绑定、整棵执行树自动取消/永久封禁、全自动跨重启接续、按事项文件/Memory 隔离、新记忆存储与迁移、全局遗忘机制、统一聚合检索、完整关注项数据库/预算/回执协议、新文件发布服务、新调度器、批量开启既有用户主动性、完整领域 Skill 包、界面重做。
- 不承诺依赖未接入外部账号的下单、预约、真实日历动作；不增加任何生产部署或数据迁移授权。不要求重新运行 #414 全部 58 项无关场景。
- 后续分片仅保留 C 不依赖新记忆/检索的领域方法、D 独立真实文件交付；不属于本次实施范围。
