# Global 模式的 Dreaming：输入与触发实现契约

这是 Nano 的设计建议，不是说竞品或现有代码已实现这些新接口。参考材料见 02-evidence.md 的 S7/S9/S11/S12/S13。

## 1. 名词必须分开

- 长期主体：Nano business agentId，拥有已有 workspace。
- IM 会话：交互的群或私聊，同一主体可参与多个。
- 原生 session：持久事件流的身份，可包括根和它的子执行。
- 模型 window：当前模型看得见的内容；换窗不表示一件工作完成，也不表示长期主体改变。
- 任务：业务责任与结果，由原 Task/工作系统持有，不用窗口号替代。

当前锁定 rc.5 README 说明：原生成功 compaction brackets 定义 window；item ID 为持久事件序号；history 仅查离开当前 surface 的记录并拒绝 active/cross-session 引用。notes 是 session 私有工作便笺。后台新会话不能直接拿父 history ID 绕过该约束。

## 2. 最小调度

自动运行条件：已启用；主体未暂停/停用；有合格增量；无同主体在途维护；距离上次成功自动运行至少默认 24h。初次启用时明确初始化源位置：默认从启用点开始，旧历史导入另给可核对范围；不能暗中扫描全部往事。

检查复用宿主生命周期/已有后台调度，不让 Agent 靠自建聊天提醒维持自身记忆。优先在主会话安静约10分钟且达到已落盘配对安全点时开始；不是要求连续闲置24小时。上述数字是可配置初值，不是竞品共同最优值。

长期业务尚未结束不阻止整理已完成的事件范围。持续运行主体可在配对边界冻结已有持久事件快照，让维护作业后台低优先级执行；不硬中断正在进行的模型请求/工具，不等待 session 结束。资源不允许就延期并保留积压。手动整理可以绕过24h，不绕过权限、排他、预算或文件冲突保护。

失败采用有界退避，last_attempt 与 last_success 分开。用户停用自动维护后不因定时器重新启动；人工整理是另一个明确请求。没有合格增量不用LLM。

## 3. 输入范围：既有历史必须包含，但不是整份 prompt

| 材料 | 是否摄入 | 解释 |
|---|---|---|
| 主人/同事给本主体的原始消息、纠正、反馈 | 是 | 必须保留真实作者、会话、对象和来源修订 |
| PA 已获准并已进入其处理链的观察批次 | 是 | observer 与 participant 不混同，观察不是委托；不消费主 Inbox |
| 已发布的 Agent 消息和交付 | 是 | 可分析行为与效果，不等于用户认可 |
| 工具实际结果、错误、验证、操作回执 | 选择性 | 保留判断所需结果；接受/排队不等于完成/交付 |
| 子执行报告与关键结果 | 是，去重 | 默认由根已收到的报告进入；需要细节再按真实后代绑定回查 |
| 原生 notes/compaction 恢复材料 | 作为导航 | 不能把摘要、模型便笺当独立事实证据 |
| 旧窗口的原始事件 | 是，按增量与必要回查 | 不因离开当前模型视野就丢弃 |
| 当前窗口的持久事件 | 是，在已完成配对边界内 | 不能只靠原生 history，因为它拒绝 active 项 |
| 系统提示、工具schema、注入的MEMORY全文、内部reasoning、token/心跳噪声 | 否 | 不作为新的经验；排除循环摄入 |
| 未读取的全公司IM/未连接外部应用 | 否 | 本轮是记忆维护，不是 Dots 式广泛研究 |

助理自述“成功”不得独立证明动作成功；原始工具错误依然是可用经验。重复汇报和 fork 继承历史保留原始 provenance，只计一份；不能因为继承到新session就视为新行为。

## 4. 每条源流独立游标，window 只是定位标签

逻辑键是 `(持久agentId, 原生sessionId, eventSeq)`。如真实后端事件有其他稳定ID，适配成等价标识；这不是要求伪造 seq。IM消息还保留原始 messageId、修订及所在会话，去重多次Inbox返回。消息编辑/撤回应有修订事件；不能只用 created_at 或数据库 max-rowid 把它漏掉。

示意：

```text
根 S1：已处理到 seq 1200
  W7: 1201..1320
  W8: 1321..1480   ← 本次安全上界
  W8: 1481..      ← 运行期间新到，留给后续
子 C1：已处理到 seq 60，本次至 seq 90
```

本轮可覆盖 S1 的 1201..1480，虽然跨两个 window 且业务任务未结束。根若换成另一持久session，旧流封存、新流继续挂到同一 business agentId；不要按 window 重置消费位置。child的 seq 不能与 root直接比较。

预算内按完整语义单元（消息组、调用结果配对、可恢复线程段）分页读取。大工具结果可给有限正文和明确原始引用，但缺失的关键证据不能被假定已核实。非合格系统事件可由确定性过滤排除并保留计数；合格但预算外的源项不可直接前移游标跳过。

初版优先处理连续可覆盖前缀；如果按重要性跳读后面的材料，必须保留未处理缺口，不能把 scalar watermark推过它们。新纠正的即时生效由前台路径保证，不靠把整个维护队列标完成。

## 5. 宿主只读适配，不新增个人聚合查询工具

实现一个内部 source adapter，用已支持的原生持久化/会话查询 API 获取本主体合法范围；验证它能读活跃与归档两部分。若没有公开API就报告缺口，不能猜私有字段/直接扮演root调用跨session工具。

将输入放入本Agent workspace内的维护区域，例如：

```text
.nanoassistant/maintenance/dreaming/<run-id>/
  manifest.json       # 真正导出的源流/边界/过滤/缺口/基线，不是事实库
  input.md            # 保留来源标签的有限材料；大输入按页
  staging/            # 基于当前记忆生成的临时副本/文档修改
```

这不是 memory/history 正式笔记，也不进记忆Git，不常驻注入。内容属于私有运行证据，权限和保留周期沿现有策略；不要无期限复制原始聊天。根代理不必看整个输入包，维护运行没有主Inbox消费能力。

初版不自动添加联网研究、邮箱扫描和全公司观察者。主 PA 现有获准观察可以提供背景；需要更多实际业务资料时由主Agent在原授权范围内决定，不让memory job扩大权限。

## 6. 维护、冲突与完成

只允许记忆目录的暂存修改、受限源读取，不开放外发、业务写入、Task调度或权限修改。独立提示和显式输入运行，不 fork 根全部prompt；具体如何使用原生提供的隔离会话/调用接口由本地Agent验证，不新增永久IM员工。

读取 MEMORY.md 和相关主题 → 补漏 → 检查跨事件关联 → 修订详细知识和必要历史 → 去重/修复链接 → 最后更新角色化入口。

提交按文件基线哈希与源资格复核。冲突时重读受影响内容并有界重试，不能覆盖用户刚修正的内容。对主Agent/人工写入以持久文件版本协调；不在整段LLM运行期间占写锁。

每个run记录源范围、实际变更、冲突/延期和版本回执。先保存真实文档结果和可重入运行记录，再确认消费位置；崩溃恢复核对已应用操作ID/提交元数据，避免同一增量再次追加。若采用多文件非事务工具，必须保存已应用部分、重试只补未完成项，不能声称整体原子。

没有变化但已真实检查过的范围可以被标处理；未读、失败、来源丢失或预算不足需分别标明。不能把“读过索引”当“读过内容”。完成不需发用户消息，无重要变化保持安静；运行证据应可在已有工作视图查看。

## 7. 换窗与遗忘边界

换窗不是Dream完成，也不自动清掉未处理历史。换窗前优先保证原始事件和正常恢复notes已落盘；整理稍后追上即可。当前提示刷新既定入口/相关页版本，不依赖下一次换窗。

正式知识仍以当前文档为准，历史旧断言只解释过去。已撤回来源、明确遗忘和停用主题不能被维护重新导入；单靠从当前文件删除并不能保证这点。对强遗忘需要宿主可验证的输入排除/派生清除策略；缺失时必须说明，不假装普通删除已完成彻底清除。
