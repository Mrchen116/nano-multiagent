# 实施顺序与必须验收的行为

## 原则

本包首先是设计澄清。基于当前main和公开DSH API逐项核对，不一次性打包成新的全平台。保持既有workspace、两级委派、Task责任、插件/Skill配置和自定义提示。

## 三片

1. **角色模板与记忆指导**：落地PA/专家入口、标准目录和按用途正文；读取/写入触发在启用条件下进系统指导，详细方法在Skill。不得向空库填用户事实或把模板注释当记忆。
2. **文档读写与刷新**：普通工具读取、受控写入/版本保护、真实Git回执、人工编辑、下一次相关判断刷新；替换旧条目式维护时仅退出该Agent的旧memory fork，不误停Skill维护。旧内容备份并保留原义，不批量模型重写。
3. **Global Dreaming**：先完成源适配与跨窗输入测试，再接24h初值的有界维护。先单PA、单专家试用；已有实例不因升级静默启用。

## 技术落点（先核对现有能力再实现）

- memory-curation：入口与读取指导；不要再以compaction作为唯一刷新条件。
- KnowledgeFiles/相关写入：文档正文，不再用§拆统一事实；原文件工具路径范围与真实写入保护。
- agent-config：绑定既有长期workspace和角色；无任意agentId切库参数。
- Knowledge运行与源读取：独立源适配/运行记录，复用宿主持久化和调度，不直接赋予普通子Agent根的conversations权限。
- 原生context engine：消费其公开历史/序列契约，不修改其换窗算法，不替代notes为新的长期Memory。

## 验收

- PA与专家没有互相注入模板或对方事实；专家先和甲再和乙工作不会套用甲的偏好。
- 出现明确纠正后当轮修改主题和相关入口；不等Dream、不等换窗。
- 普通文件保存、人工修改能被读到；Git失败不伪装版本成功；后台不覆盖人工改动。
- 输入检索读到结论与例外，未读部分不被宣称已核实。
- 重要工作结果出现后专家能记录适用条件；例行操作没有强制复盘文件。
- PA当日重要关系/计划变化可形成日期记录，普通闲聊不生成流水。
- 一个根session不结束、跨两个window也能取到正确增量；活跃与归档材料都覆盖。
- 同一IM消息多次出现在Inbox或fork前缀中仅算一次；消息修订不会丢失。
- 不摄入自身新生成记忆或系统提示触发递归维护；子报告不自证执行成功。
- 输入超预算/中途失败只推进已处理前缀；新到事件留在下轮。
- 保存后游标前崩溃可重入，不重复加日期记录；冲突不会改回旧偏好。
- 24h无新材料不调用模型；24h有材料不需闲置24h；主体停用后不被自动重启。
- 整理没有外发/业务操作/共享Skill发布；内存读取限制不被错误宣称为OS沙箱。
- 默认只整理启用后的合格范围；旧历史回溯需要明确范围和覆盖证据。

所有测试为待执行要求。未运行不得标passed；源码或提示存在不等于真实模型已正确消费。
