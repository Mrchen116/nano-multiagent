## 基线与范围

在已打开的 nano IM 创建 Agent 页面展开“指令与行为”，滚动观察自定义补充指令、特性列表、群聊回复策略与提交区。只读查看，未提交配置。当前页面两列展示记忆整理和技能创建，技能创建说明仍含持续维护；基线裁剪仅保留通用表单，去掉侧栏身份与主体列表。

- [现有表单](evidence/current-settings.png)
- 源码：`src/IM/frontend/src/features/settings/agents/agent-create-page.tsx`、`agent-detail-page.tsx`、`agent-settings.css`。原型沿用 13px 名称、12px 辅助说明、两列 feature / 窄屏单列、section 标签与内容分列。

局部原型保留相邻自定义指令、其他特性、群回复策略和保存区作为背景；只有 Dreaming 开关及模拟保存流程属于本次可交互增量。底部展开文本演示现有 Work 回执需要表达的信息，不提出新卡片或设置页内 Work 入口。外层明确标记模拟控制；产品区域不展示 legacy 或自动 Skill 复盘的说明、状态卡、恢复按钮。

## 实际渲染与操作

用 Chrome 实际打开 `prototype.html`，不是只做 DOM 检查。

| 观察/操作 | 结果与体验判断 |
| --- | --- |
| 1280 × 900 默认状态 | [桌面](evidence/prototype-desktop.png)：Dreaming 位于原记忆开关位置，与技能创建并列。名称与说明在同一视线内，能够区分定期整理与任务中创建技能；不引入新页面或大型说明区。 |
| 390 × 844 默认状态 | [窄屏](evidence/prototype-mobile.png)：实际 viewport 为 390，内容宽度 390，无横向溢出；特性改为单列，说明完整换行。首次尺寸切换截图曾保留旧布局，已在新布局实际生效后重新观察并覆盖证据。 |
| 取消勾选 Dreaming、模拟应用失败、点击保存 | [失败](evidence/prototype-failure.png)：关闭选择保留，错误紧邻保存区，保存仍可重试。用户不必记住已消失的 toast，也不会误以为已生效。 |
| 以同一草稿重试，模拟等待节点应用 | 显示“配置已保存，等待节点应用”；点击演示区的节点确认后才显示“配置已生效”。观察到两个状态明确不同。 |
| 外层模拟文件切换 legacy | [隐藏与结果示例](evidence/prototype-legacy-work.png)：Dreaming 行隐藏，无“旧记忆模式”替代提示；前台技能创建仍可见。Work 示例展开后能区分已核对、已保存、入口未同步、剩余范围和版本记录失败。 |

没有看到需要改变当前信息组织的视觉问题。相邻背景控件不承担完整表单编辑；真实创建/保存、配置传输及 Work 路由由 M1 真栈验证。iOS 无新布局，未运行模拟器，不宣称 iOS 视觉通过。临时 viewport 在走查后恢复。
