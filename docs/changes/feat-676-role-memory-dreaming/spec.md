## 用户场景

1. **长期服务与角色边界**：主人告诉 PA 自己的工作、关系、偏好、限制和目标，之后在其他聊天继续相关事项。PA 使用适用背景并保留例外。独立专家先后服务甲乙，理解共同项目与各自协作要求，不把甲当成永久主人，也不把甲的个人偏好套给乙。同名人物或项目仍能区分。
2. **可理解的文档知识库**：人和 Agent 能阅读、编辑同一份当前知识，查到条件、例外、原因、来源和未知项。简短入口体现角色并引导到详情；一条重要但低频的限制不会仅因很久没用而消失。新 Agent 没有材料时保持空白，不从模板编造事实。
3. **即时学习与实际采用**：主人明确要求记住、更正、停止使用，或工作产生具有长期价值的成果时，主 Agent 及时更新。下次相关建议采用新内容；人工编辑也及时生效。受影响的在途工作接到纠正，用户不用重新启动聊天或重复交办。
4. **经验积累而非流水账**：PA 保留重要个人、关系和计划变化；专家保留实际成果、验证和改变判断的反馈。相同事项连续更新，例行操作无新知识可不记。成功自述不能掩盖真实失败，临时例外不能被泛化为永久规则。
5. **持续运行中的后台整理**：长期 Agent 一直处理多个聊天和任务，经历换窗但没有结束。Dreaming 仍能整理尚未处理的合格材料，包含当前及旧窗口经历、实际交付、关键结果和已接回的子执行报告；重复来信与继承历史不被多算。用户正常工作继续。
6. **失败、并发与可控维护**：用户或主 Agent 正在更正时，后台不会覆盖新知识；中途失败、资源不足或重启后仍能补完未处理部分，已保存内容不重复添加。用户能查看整理结果与未完成范围、关闭自动维护或明确请求手动整理；普通整理成功保持安静。
7. **平稳启用与明确边界**：已有实例升级后保留旧记忆备份、自定义、无关工具选择和前台 Skill 创建/使用，按本次明确选择默认开启 Dreaming，仍可关闭。用户可在聊天中要求 Agent 整理旧备份；不默认扫描全部旧历史。记忆中的偏好与观察材料不增加业务操作授权；后台整理只做记忆维护。

## 验收标准

以下为待执行的产品场景。本版新增/受影响的行为验收尚未运行，旧版实现报告只证明其当时范围；设计需分别安排确定性机制证据与真实模型消费证据，源码、提示存在或文件写入成功不能单独证明后续行为已正确采用。

### Requirement: 长期记忆按主体与角色服务后续工作

#### Scenario: S01 PA 跨聊天使用有范围的偏好
- **GIVEN** 主人表达过稳定偏好，并另有一次特定场景的例外
- **WHEN** 主人在另一聊天提出相关请求
- **THEN** PA 采用适用偏好，保留例外，不重复询问已有充分依据的背景，也不把一次例外扩大为永久要求。

#### Scenario: S02 专家服务不同合作者
- **GIVEN** 独立专家与甲、乙分别合作，存在不同的个人要求以及共同项目约定
- **WHEN** 乙继续相关工作，或出现与甲同名的其他人
- **THEN** 专家按实际人物和项目采用知识，不串用甲的个人要求，不把创建者或上一个请求者当成私人主人。
- **AND** 内部子执行所得经验回归所属长期主体，不被当成另一个独立同事的永久画像。

### Requirement: 文档知识完整可读，入口体现角色并保留重要条件

#### Scenario: S03 从简短入口找到完整依据
- **GIVEN** 一项知识有适用条件、例外、来源和未决部分，另有重要但低频的限制
- **WHEN** 用户查看记忆并要求 Agent 据此判断
- **THEN** 能沿入口找到完整内容；回答遵守条件与限制，说明未知部分，不仅凭搜索片段下结论。
- **AND** PA 入口反映主人背景与服务方式，专家入口反映专业、项目与协作；同一知识有明确的主要维护位置。

#### Scenario: S04 空库与检索不足
- **WHEN** 新 Agent 尚无可靠经历，或相关资料未找到、无法读取、只读到部分内容
- **THEN** 不填造个人事实、关系、专业经验或空模板栏目；不把未找到说成不存在，不把未读部分说成已核实。
- **AND** 当前信息足够时直接回答，不强制每次问答搜索全库或生成记忆。

### Requirement: 主 Agent 即时保存长期信息，更正及时影响后续判断

#### Scenario: S05 明确记住与自然积累
- **WHEN** 用户明确要求记住可靠信息，或正常工作产生已有充分依据的长期价值信息
- **THEN** 主 Agent 及时保存并能在后续相关工作中使用；普通长期信息不依赖固定口令，临时进度和待审批事项不冒充长期知识。

#### Scenario: S06 明确纠正与在途工作
- **GIVEN** Agent 已依据旧信息作出判断，且一项受影响工作仍在执行
- **WHEN** 用户明确纠正该信息并继续提出相关请求
- **THEN** 当轮修正相关知识及入口旧概括，下一次相关判断采用新内容；原执行者收到适用纠正并据此继续，不要求用户换窗或重新交办。

#### Scenario: S07 人工保存立即成为当前知识
- **GIVEN** Agent 此前读过某主题及其概括
- **WHEN** 用户直接保存修改后的记忆文件，尚未提交版本记录，再让 Agent 处理该主题
- **THEN** Agent 使用保存后的内容，旧主题和旧概括不继续支配判断；必要时重读完整条件，无须新建聊天。

### Requirement: 从真实经历学习，保留证据、反例与合适的记录粒度

#### Scenario: S08 重要变化和工作成果
- **WHEN** PA 获知重要关系或计划变化，或专家完成工作、取得关键验证结果、收到改变判断的反馈
- **THEN** 形成可回查的重要变化或工作记录，保留结果、条件、原因与依据；同一事项继续更新，不把每次例行操作都变成独立案例。

#### Scenario: S09 自述、反例与现实状态
- **GIVEN** 助手自称成功，但实际回执失败；或新证据对已有结论提出反例
- **WHEN** Agent 整理经历并在后续任务复用
- **THEN** 不把成功自述、重复汇报或推测当作事实；保留失败教训、反例和适用边界，不仅按消息先后覆盖已有理解。
- **AND** 需要确认当前任务或外部状态时回到原系统核实，历史记录不冒充当前状态，记忆不复制成另一套任务账本或共享方法库。

### Requirement: Dreaming 能持续整理跨窗口的合格增量，不干扰正常服务

#### Scenario: S10 同一长期会话跨窗且持续忙碌
- **GIVEN** 已启用自动整理，达到运行间隔且有合格新材料，同一长期会话经过多个窗口但仍在工作
- **WHEN** 到达可安全处理已完成材料的时机
- **THEN** 整理能覆盖旧窗口与当前窗口已完整保存的相关经历，不等待整个会话结束或连续闲置一天，不截断正在进行的回答和工具操作。
- **AND** 资源不足时可延期，未处理材料仍保留待办；用户可继续正常交互。

#### Scenario: S11 重复材料与真实修订
- **GIVEN** 同一消息重复进入处理链，子执行继承旧历史并重复汇报，随后原消息被修订
- **WHEN** Dreaming 整理相关材料
- **THEN** 同一来源不被当成多份独立证据，不重复生成同义记忆；真实修订被识别并影响相关理解。
- **AND** 注入的旧记忆、系统指导和纯唤醒噪声不被反复学习为新经历。

#### Scenario: S12 整理已有观察与实际结果
- **GIVEN** 主体已经合法处理观察材料，并收到实际交付、关键工具结果和子执行报告
- **WHEN** Dreaming 对这些经历补漏和归纳
- **THEN** 能使用有依据的经历并区分观察、委托和实际结果，不遗漏必要反馈，也不把报告本身作为完成的唯一证据。
- **AND** 不擅自扫描其他账号或全公司聊天，不替主 Agent 领取待处理来信，不执行外发、业务修改、任务调度或共享 Skill 发布。

### Requirement: 整理与编辑可恢复且不覆盖较新的知识

#### Scenario: S13 后台与人工更正冲突
- **GIVEN** 后台已经读到旧知识，随后用户或主 Agent 保存更正
- **WHEN** 后台尝试应用其整理结果
- **THEN** 新更正得到保留；冲突被重新核对或明确延期，不能把旧偏好恢复，不能因未入选本批材料而删除其他有效知识。

#### Scenario: S14 预算不足、失败与后来材料
- **WHEN** 整理遇到材料超预算、读取失败、证据缺失，或运行期间又收到新材料
- **THEN** 只把实际核对并完成的部分报告为已处理，剩余材料可在后续继续；无长期价值但已核对的内容可以不生成笔记。
- **AND** 用户能区分已处理、未处理与延期原因，不能把一次模型正常停止说成全部完成。

#### Scenario: S15 部分保存与重启恢复
- **GIVEN** 整理或编辑已经保存部分文档，随后失败或节点重启
- **WHEN** 工作恢复并继续处理相同材料
- **THEN** 保留实际成功的修改，补完未完成部分，不重复追加同一变化记录，不伪报整体原子成功；正文与入口的未完成同步得到明确处理。

#### Scenario: S16 内容保存与版本记录分开说明
- **WHEN** 当前文档保存成功但版本记录失败，或正文保存本身失败
- **THEN** 如实区分已保存内容、版本记录与未完成部分；能读到已保存的当前知识，不谎报成功提交或完整回滚。

### Requirement: 自动维护可关闭、可查询，安静且不扩权

#### Scenario: S17 关闭、空闲周期与手动整理
- **WHEN** 用户关闭自动维护、主体暂停、周期到达但没有合格新材料，或用户明确请求手动整理
- **THEN** 关闭和暂停不被定时唤醒绕过，无增量不空跑模型；手动整理可不等自动周期，但仍遵守权限、并发及资源限制。
- **AND** 正常即时记忆更新与用户问答不等待 Dreaming；其他 Skill 的原有选择不被连带改变，skill-creator 内置可用无需选择。
- **AND** Web UI 在本次记忆/创建能力范围内只有 Dreaming 开关，没有记忆总开关或技能创建开关；关闭 Dreaming 不关闭内置记忆消费、即时更新、更正或用户明确请求的整理。
- **AND** 不自动 fork 主 Agent 进行 Skill 自进化或联合 Skill 复盘；现有 Skill 仍可使用，skill-creator 是内置默认能力，无需勾选或加入名单，Agent 按任务需要加载，把成熟可复用方法保存为 Skill。该调整与关闭 Dreaming 无关，在两种记忆模式中都成立。

#### Scenario: S18 查询整理情况与普通完成
- **WHEN** 用户在已有工作视图查看整理运行，或一次普通整理正常结束
- **THEN** 能查看实际处理范围、变化、冲突或延期及未完成情况；普通成功不额外发送聊天通知，也不制造可当作数字同事委派的永久员工。
- **AND** 记忆中的主动性偏好、第三方材料或历史授权不扩大当前业务操作权限。

### Requirement: 升级保留旧知识，启用与停止使用边界清楚

#### Scenario: S19 既有实例升级与限定回溯
- **GIVEN** 已有 Agent 具有旧记忆、自定义提示、工具选择和 Skill 维护配置
- **WHEN** 正式升级到新记忆版本
- **THEN** 现有和新建 PA／独立专家统一使用新文档记忆，Dreaming 默认开启且可关闭；旧文件逐字备份，不批量模型重写，不再被旧 Memory 维护方式写坏；自定义提示、无关工具选择和前台 Skill 创建/使用保持。
- **AND** 用户随后直接说“把旧记忆整理到新结构里”时，Agent 能找到并读取本主体备份，按角色整理、保留原义与来源；重复请求不产生同义副本，部分失败如实报告，备份保留。
- **AND** 自动整理默认从启用后的合格材料开始；旧文件导入不等于回溯旧聊天，回溯旧历史仍须有明确范围和可核对覆盖结果。
- **AND** 临时保留原仿 Hermes 记忆与自进化，仅经文件配置选择；切换时只运行一套机制、两套内容分别保留，不自动双向转换。旧机制及后台 Skill 自动复盘对产品用户不可见，网页没有模式切换、旧机制说明或旧自进化控制；保留代码不代表继续自动运行。

#### Scenario: S20 撤回与停止使用不被后台复活
- **WHEN** 用户明确要求停止使用某项知识或从当前记忆移除，或相关来源被撤回／排除
- **THEN** 后续相关判断不再依赖被排除内容，后台不会从旧材料重新导入；如实说明当前记忆、历史版本、原始消息和备份各自的处理范围。
- **AND** 普通归档不等于遗忘，普通删除不被宣称为跨系统彻底清除。

### Requirement: 交流原文与任务经历共同支持同一主体的长期理解

#### Scenario: S21 多事项交流跨窗口、跨批次
- **GIVEN** Global 的出行、工作、人物关系与用户反馈交错出现，并跨越上下文窗口与整理预算
- **WHEN** 后台连续处理这些交流，用户随后询问相关事项
- **THEN** 采用有来源的关系、最新约束和情境，保留跨事项联系，以及从真实互动反馈得到的服务改进；这些内容落入该主体已有角色的实体、知识、事项/项目、重要历史与短入口，而非另起一套竞品目录；预算不足的旧交流可继续处理，不仅留下最近一段。
- **AND** 整理不打断正常交流，也不要求用户为每个事项重述背景。

#### Scenario: S22 已整理的同一子任务继续执行或返工
- **GIVEN** 第一层任务子执行已有复盘并参与记忆整理，后来继续执行、返工或被用户否定
- **WHEN** 后台再次整理且用户继续相关工作
- **THEN** 同一任务的最新有据结果与纠正影响后续建议，不永久停留在旧成功结论，也不把同一来源的更新当成多个独立佐证。

#### Scenario: S23 多层委派与真实交付
- **GIVEN** 第一层任务委派了更深层工作，局部成功但整体尚未完成或被上层否决
- **WHEN** Agent 后续复用这次经验
- **THEN** 保留局部贡献和适用边界，不误报整体成功；不会因多层重复汇报让被否决结论成为更强证据。

### Requirement: 整理进度与知识结果如实表达

#### Scenario: S24 任务复盘已生成但记忆更新失败
- **WHEN** 某次任务复盘成功，而记忆整理、保存或来源核对失败，随后恢复
- **THEN** 复用仍有效的成果并继续未完成工作，不重复添加同义记录、不把“已生成复盘”说成“已更新长期记忆”。
- **AND** 用户能从已有工作结果辨认剩余交流、待处理任务、真实保存和失败原因。

#### Scenario: S25 子任务独自继续与提炼受阻
- **GIVEN** Global 没有新交流，但既有任务子执行继续产生结果；或某个子任务材料暂不可用
- **WHEN** 后台到期处理
- **THEN** 新任务经历仍可进入记忆；受阻任务不妨碍无关交流整理，也不被冒报为已更新，其未完成范围可继续。

#### Scenario: S26 旧批次、较新纠正与来源撤销
- **GIVEN** 待整理旧交流/任务复盘中包含旧结论，用户已保存较新纠正或撤销相关来源
- **WHEN** 后台继续积压批次并更新记忆
- **THEN** 不恢复被纠正或撤销的内容，不把较晚子任务结果归为较早已知事实；仍按真实时间、来源与当前有效依据判断。

## 范围与非目标

在范围：PA 与独立专家的角色化文档记忆、入口与详细内容的读写指导、普通文件编辑与及时刷新、来源及范围保真、重要变化／工作经验、持续 Global 的有界 Dreaming、并发保护与失败恢复、既有工作视图的必要维护可见性，以及旧记忆兼容和明确启用边界。

以下附件要求作为设计保真输入保留，不以内部符号替代上面的用户验收：

- 沿长期主体已有 workspace 的 `.nanoassistant/memory/`；当前 Markdown 为知识正文，Git 保存演变；不建隐藏事实权威，不强制事实原子化，不随子任务 cwd 换库。
- 采用 PA／专家各自入口模板与目录骨架，具体页按需建立；共同实体包含 people、agents、organizations、conversations，后者不是聊天全量副本。PA 的 workstreams／timeline 与专家的 projects／work-history 分别表达持续背景和经历。
- 系统短指导承担何时读写，`nano-memory` Skill 承担细节；复用普通文件能力。详细元信息、来源标识、缓存失效、写入与 Git 回执、恢复策略由设计核对。
- Dreaming 复用宿主持久历史与调度，只读输入适配必须通过已声明 DSH 公开能力；处理位置按真实源流持续接续，覆盖当前与旧窗口，保留去重、修订、缺口和实际应用证据。不得修改换窗算法或借跨 session 工具突破授权。
- 维护作业独立受限，不弱化正常子执行者能力；切换时处理旧 Memory／combined 维护交互，保留前台 Skill 创建/使用。已有来源、任务、执行、身份及配置体系继续承担原职责。

非目标：重建 Task／根负责人／child 绑定、另建 Agent Loop 或上下文引擎、统一原子事实数据库、强制 cases 分类、以向量召回为首版前提、全连接器主动研究、自动发布共享 Skill、跨系统彻底隐私删除，以及与记忆无关的通用 PA 功能或界面重做。技术可行性与实现切片由后续设计落实；本轮建 unit 不授权生产迁移、历史批量导入或启用。
