## 原始需求与范围收口

> 现在本仓已经有关于评测的设计，之前弄了memory的，这次我想弄intelligent UI的。搞这两个demo，作为评测集的两个case，再加你这个演示会议安排的场景。每个case都应该在从零开始的上下文开始测。我想测的时候直接去开评测测效果。你先把这个搞了。后面我还会做其他的不用能力的评测，比如agent并行工作的评测等等，形成多个不同能力的评测。

> 你测你看 memory，这是怎么做呀？我们先不纠结这个细节，先把case搭起来。

> 我记得做Memory的评测的时候做了一个可视化的页面，我们可以把这个基础设施抽取出来变成公共的评测的基础设施。

Agent 解读：本轮先建立四个可复用 case，并将此前本机 Memory 单题页面的公共展示层整理入仓库；不继续扩张自动运行、评分或调度细节。各能力保留自己的执行与判定规则。后续并行能力可继续登记 case，不以当前需求推导出多能力统一评分或调度器。

用户后续同意新增不点名工具的“团队活动方案与预算试算”，总数四个，并询问会议是否仍需保留。Agent 建议保留会议作为真实确认消息→Agent 回复的独立检查，当前未收到删除指令；活动试算仅检查本地操作，不擅自加入消息确认步骤。

用户随后指出试算任务仍明确要求交互，改选只给本地文件的自然广告分析任务；最新明确要求只评“是否用了UI”（客观）与“呈现得好不好”（主观），分析正确性不重要。v3因此替换第四题而非增加第五题，会议保持原样。

用户进一步纠正：为单独测试UI主动性，应直接将CSV放进Agent workspace，不应混入聊天附件读取。v4保持四题，将第四题改为工作区文件预置与自然任务。

## 验收

### Requirement: 可查看独立能力的 case

#### Scenario: Intelligent UI 四个 case
- **WHEN** 打开公共评测页面并选择 Intelligent UI
- **THEN** 分别看到酒店、看板、会议确认、广告分析的固定输入、适用的原图素材、操作步骤与判定标准，不将过程截图充当参考原图。

#### Scenario: 每个 case 从零开始
- **WHEN** 按 case 开展一次评测
- **THEN** 要求每 case/每 run 使用新身份、聊天、workspace、DSH home 和活动上下文；不混入旧 Memory/Inbox/修正提示。会议确认只包含规定旅程所必需的后续确认及回复。
- **AND** 页面建档或挂接已有现场不冒充本页面新执行，未运行/未判定不标通过。

#### Scenario: 无呈现提示的主动使用与视觉质量
- **WHEN** 将固定广告CSV预置于全新Agent工作区根目录，只给自然分析请求，不提UI、图表、交互或组件，不提供参考界面
- **THEN** 本case实际send_message/send_user_message调用携带非空字符串interactive.source记主动使用是，完整记录无此调用记否；只加载Skill、写代码或普通消息不算；调用失败仍记使用是，轨迹缺失或未执行记未判定。
- **AND** 人工单独评价实际UI呈现，调用但未交付界面或渲染错误记呈现失败；不因呈现失败改写使用事实，不评分析或计算正确性，不额外消耗模型裁判token。
- **AND** 页面可下载已登记的输入CSV，不允许读取任意未登记附件；候选只接收自然任务，文件按workspaceFiles预置，不经聊天附件链路；不接收判据或操作材料。

### Requirement: 复用已有评测页面

#### Scenario: 查看 Memory 证据
- **WHEN** 为公共页面挂接此前 Memory 实验归档
- **THEN** 可按实验、case、阶段/批次查看原生轨迹与报告，继续使用 Agent Work 的原生组件；不重写执行记录，不改变评分协议，不启动候选模型或业务动作。

#### Scenario: 新增其他能力
- **WHEN** 以后添加 Agent 并行工作等评测 case
- **THEN** 可复用能力目录、case 材料和阶段证据的展示层，不要求复制 Memory 或 Intelligent UI 的页面。

## 非目标

本轮不新增自动评测运行器、浏览器自动判定、模型裁判、并行调度或自动优化；不修改 Memory 协议/历史分数；不改生产服务。之前用户要求保留的三个产品预览服务继续保留。
