# feat-708: 内置携程问道 Skill

## 原始需求与澄清

- 用户：“是不是GitHub上的不重要，我想把这个能力接到我的Nano这个系统里面，默认给每一个PA都能用上。”
- 用户：“不需要这么复杂，走快修模式。”
- 凭证归属选择：“每位 PA 主人分别配置自己的凭证”。
- 核对原版缺失凭证处理后，用户最终决定：“那不用，直接这个skill内置就行了，不需要改了。”
- 用户进一步明确：“我明确一下，是给PA默认开启，对不对，其他Global Agent不是默认开启。”本次以正式 PA 身份限定默认装配，不按 Global 模式泛化。
- 参考：`trips-ai/tripai-skill` 的根目录 `SKILL.md`，版本及来源见随包 `PROVENANCE.md`。对话截图包含凭证，不复制到仓库，也不作为共享凭证使用。

## 用户场景

PA 主人向助手查询航班、酒店、火车票或旅行安排时，可使用随 Nano 安装的携程问道 Skill，无需自己安装。凭证配置、存储位置和缺失提示沿用原版；每位主人提供自己的凭证。本次不新增授权对话或配置界面。

## 验收标准

### Requirement: 携程问道随 Nano 提供且默认可用

#### Scenario: 默认配置的 PA 使用旅行能力
- **WHEN** 主人使用默认 Skill 配置的 PA 查询旅行信息
- **THEN** 助手可发现和加载携程问道，无需额外安装
- **AND** 显式限制 Skill 的已有选择继续生效

#### Scenario: 其他 Agent 不自动获得携程 Skill
- **WHEN** 使用没有 PA 身份的 Global Agent 或普通 Agent
- **THEN** 不默认启用或装配本次随包携程 Skill，原有自建 Skill 配置保持

### Requirement: 保留原版凭证使用方式

#### Scenario: 未提供凭证
- **WHEN** 主人尚未配置携程凭证，助手按 Skill 说明准备查询
- **THEN** 沿用原版缺少 API Key 的提示及配置指引，不使用其他主人的凭证

#### Scenario: 已配置自己的凭证
- **WHEN** 主人已按原版方式配置有效凭证并请求旅行查询
- **THEN** 可沿用原版携程查询方式

## 范围与非目标

只内置原版 Skill 并标记默认开启。不修改正文、API、凭证路径或失败处理，不新增工具、Feature、配置界面、共享 Token、自动索要 Token 或跨节点凭证同步。不强制覆盖显式 Skill 选择，不部署生产。

快速开发实现完成；自动验证与独立审查见 `design.md`、`code-review.md`。尚无主人实际试用确认，unit 保持 active，不记为已验收或已部署。
