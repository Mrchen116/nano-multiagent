# feat-714: iOS 本地聊天库与冷启动首绘

## Relations

- Related: bugfix-713, #468

本 unit 是 issue #468 路线图的 U1（`ios-local-chat-store`）：先立起「库为真、网络只做校正」的数据底座。`bugfix-713` 已瘦身为丢弃投影修复，其原先的本地快照首绘、发送乐观气泡、已读单调三项分别由本 unit 与 U2/U3 承接，故不再在 713 内实现。库选型、schema、仓储接口与并发边界属 design，不在本文定义。

## 原始需求

用户在 iPhone 上日常使用原生客户端，来源是 iOS 体验审计（32 条问题，P0 8 / P1 16 / P2 8）及其修复路线第①步。用户原话（保留）：

> 1. 启动后首屏长时间只有一个加载/“正在连接”，列表要等网络往返完成才出现。
> 2. 未读数点进会话后不清零 / 会“复活”。
> 3. 网络慢时发出的消息卡在输入框一段时间才进列表（输入区锁死、没有气泡）。

用户对目标态的定义（原话）：

> 我建议一步到位，目标态，一个商业的 IM 应该怎么样就怎么样，我先告诉你，这是我的目标。至于你要拆分多少个 unit，这是你去分析。

Agent 解读：本 unit 只承担上述第 1 条症状与「打开就有上次内容、断网也能读」这一目标态要求；第 2、3 条分别属于已读（U3）与发送（U2），不在本 unit 验收。

## 澄清记录

- Q1: 目标态要拆多少 unit、先做哪一个？
  A: 用户已确认 issue #468 的拆分方向（U1–U9）与执行顺序，U1 为第一个 unit。本 unit 的验收就是该路线图 4.2 节 U1 的用户可观察部分。
- Q2: `bugfix-713` 的 5 项范围如何处理？
  A: 用户已确认瘦身为只保留「`message_discarded` 恢复会话投影」；其中「会话列表本地快照 + 首绘」由本 unit 以库替换，不在 713 里先做一版快照。
- Q3: 已定的工程默认有哪些？
  A: 由 issue #468 记录：本地库用 GRDB、最低系统版本保持 iOS 26、库不存媒体字节、`/sync` 默认行为保持全量。这些是已定前提，不是本文的验收口径；选型与 schema 由 design 落实。
- Q4: 「结果未知的发送可以在网络恢复后自动补发」是否改变本 unit 的迁移要求？
  A: 该契约变更属 U2（发送内核）。本 unit 迁移未确认发送记录时必须保持现状语义不变：升级前后都「不重复发送、不自动重发」，只有用户显式重试才推进。

## 用户场景

早高峰地铁里，用户掏出手机点开 App。上一次看到的是三个会话：一个同事私聊、一个 Agent 会话、一个项目群。这次打开，列表立刻就在——顺序、预览、未读徽标都和昨晚睡前一样，没有「恢复登录…」，也没有「正在加载聊天…」的白屏。用户点进 Agent 会话，往上翻两屏，昨天的对话都在；顶部有一条不刺眼的提示说现在没连上，正在重试。他没被送回登录页，也不需要重新输密码。

列车出站，网络回来了。提示自己消失，列表里多了一条同事的新消息，预览和时间跟着变；刚才那个项目群已经把他移出，于是它从列表里消失，也没有在下一帧闪回来。整个过程里用户没有看到整屏的加载态替换掉已有内容。

换一个场景：用户换了新手机，第一次装上 App 登录。这时本地什么都没有，列表区明确显示在加载，而不是一句「暂无聊天」——他还不知道有没有会话，App 也不该替他下结论。等第一次结果回来，该有的会话出现，或者确实为空时才显示空态。

再换一个：用户退出登录、换成同事的账号，或者把服务地址改到另一台节点。之前账号的会话、消息、草稿和没发出去的内容都不能出现在新会话里；被撤销访问的那个群也不能靠本地残留闪回，哪怕此刻正好断网。图片和文件只在能访问时看得到，本地不留下它们的字节。

## 验收标准

### Requirement: 冷启动先看到上次的内容

#### Scenario: 有本地数据时打开即见列表
- **GIVEN** 用户上次正常使用过，本机留有该账号在该服务的会话与消息
- **WHEN** 用户在可上网环境下重新打开 App
- **THEN** 打开后先看到上次的会话列表，会话、预览、时间与未读与上次一致，不再出现只有「恢复登录…」或「正在加载聊天…」的空屏
- **AND** 从打开到列表出现之间不出现整屏加载态替换已有内容

#### Scenario: 后台校正后按服务端更新
- **GIVEN** 用户已看到本地内容，后台校正正在进行
- **WHEN** 校正结果返回
- **THEN** 内容、顺序与未读按服务端更新，期间不整屏闪回加载态
- **AND** 已失去访问的会话从列表消失，且不会在下一帧重新出现

#### Scenario: 首次安装或没有本地数据
- **GIVEN** 本机没有该账号的任何本地聊天数据
- **WHEN** 用户首次打开聊天页
- **THEN** 显示加载状态直到首次结果返回，不把空列表当作「没有会话」展示
- **AND** 只有确认结果为空时才显示「暂无聊天」一类的空态

### Requirement: 弱网或断网时仍能读到上次内容并知道未连接

#### Scenario: 断网冷启动
- **GIVEN** 本机有该账号的会话与消息
- **WHEN** 用户在断网或飞行模式打开 App
- **THEN** 先显示上次的会话列表，并明确标示当前未连接或正在重试
- **AND** 不把用户送回登录页，也不把此时的状态显示成已同步或已发送

#### Scenario: 网络恢复后自动校正
- **GIVEN** 用户正在离线查看本地内容
- **WHEN** 网络恢复
- **THEN** 内容自动校正为服务端结果，未连接提示消失
- **AND** 用户不需要重新登录，也不需要手动刷新才能看到新消息

#### Scenario: 离线打开进过的会话
- **GIVEN** 用户此前打开过某个会话，本机留有它的消息
- **WHEN** 用户在离线状态再次进入
- **THEN** 已有消息可正常阅读和往上翻，界面仍标示未连接
- **AND** 无法补齐的部分明确说明尚未完成，不静默显示为最新

#### Scenario: 离线打开没有本地内容的会话
- **GIVEN** 本机没有该会话的消息
- **WHEN** 用户在离线状态打开它
- **THEN** 明确说明需要连接后才能读取内容，不把它显示成「没有消息」的空会话

### Requirement: 撤销访问与切换账号后旧内容不进入新会话

#### Scenario: 退出登录后换账号
- **WHEN** 用户退出登录并登录另一个账号
- **THEN** 新账号看不到上一账号的会话、消息、草稿与未发出的内容
- **AND** 上一个账号的迟到网络结果不会把内容重新写回界面

#### Scenario: 切换服务地址
- **WHEN** 用户把服务地址改到另一台服务并登录
- **THEN** 新服务下只显示该服务的内容，旧服务的内容不出现

#### Scenario: 会话访问被撤销
- **GIVEN** 用户此前能访问某个群
- **WHEN** 用户被移出该群、群被解散或该会话的访问被撤销
- **THEN** 该会话从列表中消失，本地已存的消息与预览不再展示，也不会在界面闪回
- **AND** 处于离线状态时同样不展示被撤销的内容

#### Scenario: 受保护媒体不随本地内容留存
- **GIVEN** 用户此前在会话里看过受保护图片或文件
- **WHEN** 用户退出登录、切换账号，或该会话的访问被撤销后离线打开
- **THEN** 看不到这些图片与文件的内容，列表与消息只保留不含媒体的占位或说明
- **AND** 本地持久层只保留这些附件的元数据，不保留媒体字节

### Requirement: 本地数据按服务与账号隔离

#### Scenario: 两个账号在同一台设备上互不可见
- **GIVEN** 两个账号先后在同一台设备、同一服务上使用过
- **WHEN** 其中任一账号登录并离线打开 App
- **THEN** 只看到自己账号的会话与消息，另一个账号的内容既不可见也不会被当作自己的未读统计

#### Scenario: 同一账号在两个服务上互不混用
- **GIVEN** 同一账号在两台不同服务地址上都登录过
- **WHEN** 用户在其中一个服务下打开 App
- **THEN** 只显示该服务的内容，另一个服务的会话与预览不出现

### Requirement: 未确认发送记录迁移一条不丢

#### Scenario: 升级后未确认消息仍在
- **GIVEN** 升级前本机存有若干条结果未知的发送记录（弱网、断网或服务超时造成）
- **WHEN** 用户升级后第一次打开 App 并回到对应会话
- **THEN** 这些消息仍在原会话里，内容与附件与升级前一致，数量不减少
- **AND** 用户能看出它们仍处于未确认状态，可以继续核对或重试

#### Scenario: 迁移不改变既有发送语义
- **GIVEN** 本机存在未确认的发送记录
- **WHEN** 用户重新打开 App、回到会话或网络恢复
- **THEN** 这些记录不会被自动发出，也不会因为迁移而多发一条
- **AND** 只有用户显式重试才会推进，重试仍然只对应一条消息

### Requirement: 网络失败不再等同于未登录

#### Scenario: 有本地内容但网络失败
- **GIVEN** 本机有该账号的会话与消息
- **WHEN** 打开 App 时网络请求失败（断网、超时或服务暂时不可用）
- **THEN** 显示本地内容并提示未连接或稍后重试，不显示登录表单
- **AND** 不把这次失败描述成账号失效或需要重新登录

#### Scenario: 没有本地内容且网络失败
- **GIVEN** 本机没有可显示的本地内容
- **WHEN** 首次加载失败
- **THEN** 显示加载失败与重试入口，不谎称「没有会话」
- **AND** 用户重试成功后内容正常出现

#### Scenario: 凭据确实失效
- **WHEN** 服务端明确拒绝当前凭据、或账号已失效
- **THEN** 才显示需要重新登录或相应的账号状态，与网络失败区分开
- **AND** 失效后不再展示该账号的本地聊天内容

## 范围与非目标

在范围：

- 本地持久化会话、消息、未读与预览等聊天状态，并让界面从本地内容首绘、由网络结果校正。
- 冷启动首绘不依赖网络往返；后台校正期间不整屏闪回。
- 离线可读、未连接标示与网络恢复后的自动校正；网络失败与凭据失效的分类。
- 按服务与账号隔离的持久化范围，以及退出、切服务、账号失效、访问撤销时的清理与不闪回。
- 未确认发送记录从现有存储迁入本地库，一条不丢，既有「不重复、不自动重发」语义不变。
- 受保护媒体只保留元数据；库与文件保护沿用既有安全边界。
- 最低系统版本保持 iOS 26，Web 端行为不变。

非目标：

- 增量同步协议、游标与投影性能改造（U4）；本 unit 的校正仍走现有全量结果。
- 读事件、已读单调与多端已读传播（U3）；本 unit 只保证未读随会话状态持久化与显示，不改变清零与推进规则。
- 乐观气泡、发送状态机、输入区解锁与失败就地重试（U2）；结果未知发送的自动补发契约变更也属 U2。
- 后台刷新、本地通知、角标与深链（U5）。
- 媒体缓存、下载与清理策略（U6）；本 unit 只决定媒体字节不进入持久层。
- 完整连接韧性（退避节奏、重连编排、前后台恢复策略，U7）；本 unit 只做「网络失败不等于未登录」这一错误分类切面。
- 消息搜索（U8）。
- 聊天页阅读细节（未读分隔线、分页锚定、时间戳与触感反馈）与 UI 信息架构、视觉重设计（U9）。
- 不做 Web 端行为变更，不改服务端 `/sync` 默认返回。
