# im agent-work delta

## ADDED Requirements

### Requirement: Work 直接呈现当前正在工作的一级子执行数量与条目

对某个全局 Agent 的 Work「工作记录」视图，主 Agent 的直属一级执行（挂在当前主会话下的普通 subagent）若正在工作，其数量与条目在不展开折叠区时即可读到。workflow 子执行、cron 会话、已结束的执行与已退休主会话下的历史执行不进入这一数量。主 Agent 自身的状态仍按主执行显示，不被这一数量顶替或合并。

#### Scenario: 主 Agent 派发了多个直属子执行
- **GIVEN** 主 Agent 当前有三个直属子执行正在工作
- **WHEN** 有该 Agent 空间访问权的用户打开 Work 的工作记录视图
- **THEN** 不展开任何折叠区就能读到「当前有三个子执行在工作」这类结论
- **AND** 可展开或平铺看到这三次执行各自的条目，并与主 Agent 的轮次清楚区分

#### Scenario: 每个计入的子执行可辨认
- **GIVEN** 两个直属子执行正在工作
- **WHEN** 用户查看条目
- **THEN** 每条有可辨认的标识：有名称时用名称，没有名称时有可区分的执行标识
- **AND** 能看到开始工作的时间或据此得出的已工作时长，不出现倒计时、剩余时间或伪造的进度

#### Scenario: 没有子执行在工作
- **GIVEN** 没有正在工作的直属子执行，且页面没有节点离线、记录补齐或最新进度未确认的提示
- **WHEN** 用户查看这一位置
- **THEN** 明确显示当前没有子执行在工作，不是留白，也不是一个孤立的数字 0
- **AND** 主 Agent 自身的运行状态照常显示

#### Scenario: 只有非直属执行在活动
- **GIVEN** 主 Agent 正在跑一个 workflow 且其子执行在活动，或有一个 cron 会话在运行，或有已退休主会话下的历史执行
- **WHEN** 用户查看这一数量
- **THEN** 这些执行不计入「正在工作的一级子执行」
- **AND** 它们仍可通过既有的关联执行入口查看，workflow 与 cron 的既有呈现不变

#### Scenario: 已结束的唤起与驻留会话
- **GIVEN** 同一个子会话先后被唤起两次且都已结束，或子会话已结束但驻留、可再次续接
- **WHEN** 用户查看「正在工作的一级子执行」
- **THEN** 它们不进入在工作的数量；若仍出现在列表中，明确标为已结束
- **AND** 驻留但空闲的会话不被算作在干活

#### Scenario: 后台维护与用户委派可分辨
- **GIVEN** 主 Agent 除用户交办的一级子执行外，还有正在运行的系统维护（例如记忆整理或技能复盘）
- **WHEN** 用户查看这一数量与条目
- **THEN** 维护执行计入总数，但与用户的委派分组呈现，并写明这是自动进行、不需要用户处理
- **AND** 无法判断某条执行是否属于维护时，按普通委派呈现，不猜测用途

### Requirement: 子执行状态按已确认记录呈现，不可确认时如实降级

子执行的「运行中 / 等待授权 / 状态未知」由中心依据已保存的执行事实与当前节点连接判定，客户端不自行推断。无法确认时显示状态未知并说明原因，既不算作运行中，也不算作空闲或 0；主 Agent 与子执行使用同一判定，两个入口不得给出互相矛盾的结论。等待授权不受「长时间没有新记录」的影响——等人本身不产生记录。

#### Scenario: 运行中与等待授权分开
- **GIVEN** 两个直属子执行在运行，一个停在等待用户授权
- **WHEN** 用户查看数量与条目
- **THEN** 能看到在工作的总数，并能分辨其中运行中与等待授权各是几个
- **AND** 等待授权的那条可被明确指认，用户知道现在卡在等自己

#### Scenario: 节点离线
- **GIVEN** 节点在某个子执行进行中离线
- **WHEN** 用户查看这一数量与条目
- **THEN** 状态整体显示为状态未知并说明节点离线，不把离线前的数字当作现状
- **AND** 已保存的历史轮次与轨迹仍可回看

#### Scenario: 记录正在补齐或最新进度尚未确认
- **GIVEN** 工作记录仍在补传，或中心未确认最新记录位置
- **WHEN** 用户查看这一数量与条目
- **THEN** 状态显示为未知并分别说明正在补齐或最新进度尚未确认
- **AND** 已保存内容仍可读，补齐完成后回到真实状态

#### Scenario: 连接重建或长期没有新的事实
- **GIVEN** 节点连接重建后该执行没有产生新的事实，或一个运行中的执行长时间没有任何新记录
- **WHEN** 用户查看这一数量与条目
- **THEN** 该项不显示为运行中，而是状态未知，并说明是连接重建后没有新的执行记录或长时间没有新记录
- **AND** 主 Agent 的同类未确认状态使用同一判定，页面不出现「主 Agent 运行中而子执行未知」这类无法解释的组合
- **AND** 只要随后收到真实的新记录，状态立即回到真实值

#### Scenario: 子执行失败、取消或被中断
- **GIVEN** 一个直属子执行正在工作
- **WHEN** 它正常完成、失败、取消或被中断
- **THEN** 该条不再计入在工作的数量，也不显示为运行中；失败与中断不被显示为已完成
- **AND** 主 Agent 的轮次、结果与既有统计不因此被改写

#### Scenario: 单个子执行明细不可读
- **GIVEN** 用户在条目里能看到某个子执行，但它的明细当前不可读取
- **WHEN** 用户查看这一项
- **THEN** 该项仍按已确认的记录显示状态并计入数量，同时标明明细暂不可读
- **AND** 不因为读不到明细就把它算作不存在或已结束

#### Scenario: 工作视图读取失败
- **GIVEN** 页面读取工作记录失败或超时
- **WHEN** 用户查看这一数量与条目
- **THEN** 显示读取失败与重试入口，不显示 0 或空列表
- **AND** 重试成功后按真实记录显示
