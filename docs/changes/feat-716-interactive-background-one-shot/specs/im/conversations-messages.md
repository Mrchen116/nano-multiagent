# IM conversations-messages Specification (delta for feat-716)

## MODIFIED Requirements

### Requirement: 交互确认保留真实用户、原回复与选择语义

明确提交 SHALL 形成当前登录用户的会话消息，携带原回复与实际选择；私聊自然文字 MAY 一起携带本人所有有效待发卡片各自最新状态，且这些改动一起至多随一条消息携带一次，作为接收 Agent 判断用的后台状态，保留原文；群聊私人未提交状态仅对本人可见，普通文字不得共享。明确提交同样是一条本人发出的消息，它消费此前尚未发出的卡片改动，被消费的卡片不再挂到之后的消息上。重复提交不得创建重复输入或重复调度。

#### Scenario: 群中不同成员调整
- **WHEN** 两位成员分别调整同一卡片，随后其中一位提交
- **THEN** 草稿互不覆盖；公开结果明确属于提交人，原卡片作者 Agent 获得其选择上下文。

#### Scenario: 多次探索与请求幂等
- **WHEN** 用户继续探索同一回复并发送另一个明确请求，或因网络重试同一次请求
- **THEN** 新请求可独立保存；同一幂等键和语义返回原结果，不重复调度；同键不同语义明确冲突。
- **AND** 被替代或 fork 的旧版本不接受新的业务请求。

#### Scenario: 增量更新保持完整历史
- **WHEN** Agent 对自己的同会话交互回复发送增量修改
- **THEN** 新消息保存校验后的完整版本，旧消息仍可读；失败或重试不会产生半条或重复版本。

#### Scenario: 私聊自然追问与群聊明确提交
- **WHEN** 用户修改卡片后发送普通文字
- **THEN** 私聊 Agent 可按原话判断是否使用这条消息实际携带的卡片状态；该消息之后发出的普通文字不再重复携带已消费改动，只有再次真实编辑的卡片才重新待发。
- **AND** 群聊所有 Agent 和其他成员均不获得未提交状态；群聊只有明确提交动作才公开本人快照，不将普通发言自动定向卡片作者。

### Requirement: 自然消息的交互背景保持准确且不改变路由

私聊自然文字 SHALL 一起携带本人所有尚未被消费、清除或逐卡失效的真实卡片改动，每张只取最新状态。整组随本条消息一次性消费；每张背景保留独立来源，只交付各自卡片作者，不进入公开内容或其他成员的读取范围。整组超出总量边界时 SHALL 明确可恢复失败，不发送、不消费、不静默截取部分卡片。

#### Scenario: 改动一次只携带一次
- **GIVEN** 私聊里已有一张可交互卡片，用户此前没有改动过它
- **WHEN** 用户改变这张卡的一个字段或选择，随后发出普通文字
- **THEN** 这条消息只携带这一张卡的背景，带卡片来源、实际选择与这次改动的捕获时间
- **AND** 用户原话完整保留，不被改写或摘要
- **AND** 之后发出的消息不再携带它，连续多条同样不携带；用户再改动一次才重新携带

#### Scenario: 连续改动两张卡
- **WHEN** 用户先改动卡片 A、不发送，再改动卡片 B，然后发出普通文字
- **THEN** 该消息一起携带 A、B 各自最新状态，每张一份且来源不混合
- **AND** 下一条之前都没再改时，一张都不新带；后来只改 A，下一条只带 A

#### Scenario: 多卡中的一张失效
- **GIVEN** 用户改过 A、B 但尚未发送
- **WHEN** B 只读、被取代或已无法作为有效背景，然后发出普通文字
- **THEN** 不携带 B，仍携带有效的 A，失效不扩散到其他卡片

#### Scenario: 整组背景过大
- **WHEN** 用户发送普通消息，但有效待发卡片的整组背景超出系统总量边界
- **THEN** 明确说明消息尚未发送及缩减内容后重试、或按既有离开会话规则清除的恢复方式；不创建消息、不消费，不静默截取部分卡片
- **AND** 正文、附件和卡片编辑保留，缩减后下一次发送携带全部仍有效的待发背景；已确定消息的幂等重试不因后来新增的大草稿而失败

#### Scenario: 同一张卡再改一次
- **WHEN** 用户改动卡片 A 的一个字段、不发送，又改动 A 的另一个字段，然后发出普通文字
- **THEN** 该消息只携带 A，且内容是最后一次改动后的完整状态，不是两次各一条
- **AND** 之后发出的消息不携带它

#### Scenario: 只渲染不改动
- **WHEN** 用户打开或刷新会话、滚动经过若干卡片、切换会话后再回来，期间没有改变任何卡片内容，随后发出消息
- **THEN** 该消息不携带任何卡片背景
- **AND** 接收 Agent 的这条输入只有用户原话以及既有的时间等上下文，没有私人交互背景块

#### Scenario: 失效条件只清除这次携带
- **GIVEN** 用户改动卡片后没有发送
- **WHEN** 该卡被后续版本取代、变为只读、用户离开该会话，或改动发生在群聊或另一个私聊
- **THEN** 之后的消息不携带它
- **AND** 清除由做过这次改动的那一端执行：另一台设备在同一会话打开又切走，不清除这台设备上尚未发送的改动
- **AND** 该卡仍按原消息权限可读，失效只影响这次携带，不改变卡片本身的可交互性

#### Scenario: 刷新、重载与换设备后仍只携带一次
- **GIVEN** 用户改动卡片后没有发送
- **WHEN** 用户刷新页面、重启客户端，或同一账号在另一台设备上于同一会话发出消息
- **THEN** 该消息携带这次改动，带同一份选择与同一捕获时间
- **AND** 这条消息之后再发的消息不携带

#### Scenario: 发问后继续操作与网络重试
- **WHEN** 用户在私聊参考交互内容自然发问，随后继续修改卡片，或因网络重试同一次发送
- **THEN** 接收 Agent 可取得发问时携带的那份背景快照，之后的状态不改旧输入
- **AND** 同一次发送不重复入队，重试沿用已确定的那份背景，不会变成没有背景的另一条消息

#### Scenario: 私聊背景与群聊隔离
- **WHEN** 私聊消息带有后台交互背景，或用户在群内正常发言
- **THEN** 私聊背景只交付卡片作者，不进入公开消息或确认结果；群聊不携带后台背景，接收规则沿原消息，只有明确提交后才共享

### Requirement: 同一次普通 Web 发送在结果未知时幂等恢复

#### Scenario: 消息保存后返回中断
- **WHEN** 用户通过原有输入框发送文字或附件，中心保存后返回中断，随后刷新或重试
- **THEN** 恢复同一次发送的已有消息，不因重试创建第二条交办；确认成功前保留待发内容，不增加内部阶段展示。

#### Scenario: 恢复期间编辑新内容或切换聊天
- **WHEN** 原发送尚在核对，用户编辑后续内容或切换聊天
- **THEN** 原消息的迟到成功不清除后续草稿或其他聊天的内容，重试不把新正文替换进原发送；账号和聊天访问隔离保持。

#### Scenario: 明确再次发送相同正文
- **WHEN** 用户已完成一次发送，又明确发送相同正文
- **THEN** 作为两次真实交办保留，不因内容相同被错误合并。

#### Scenario: 核对本人的发送结果
- **WHEN** 当前真人通过 `GET /im/v1/conversations/:conversation_id/message-attempts/:key` 核对同次发送
- **THEN** 仅在仍有聊天资格且原发送者为本人时返回原消息；未找到返回 404，调用方只能以原身份和原快照重试
- **AND** 其他人的消息、机器凭据或已失去资格的聊天不可通过此入口读取。

#### Scenario: 同一发送身份携带不同快照
- **WHEN** 原发送身份再次用于不同发送者、正文、附件或引用回复目标
- **THEN** 返回 409，不静默替换旧内容或返回其他人的消息。
- **AND** 私人交互背景不属于这次快照身份：它随原消息一并确定，重试沿用原消息，不因背景变化产生冲突。
