# IM web-chat-ux Specification (delta for feat-716)

## MODIFIED Requirements

### Requirement: 交互内容保持聊天阅读与操作连贯

Web IM SHALL 在对应 Agent 回复中呈现交互，用户可操作或自然打字继续，不管理后台保存和附带模式，也不提供用户可见的附带开关、选择附带横条或 Detach。私人背景至多随一条普通消息携带一次；卡片改动尚未保存时 SHALL 明确告知，且 SHALL NOT 发出缺少这次改动的消息。

#### Scenario: 自动保存与自然提问
- **WHEN** 用户调整控件、刷新或继续打字
- **THEN** 本人状态在后台保存恢复；正常成功无保存提示、选择附带横条或 Detach。普通本人消息只显示原话；私聊后台将所有有效待发卡片的最新状态一起携带一次、一起消费，不再编辑则下一条不新带，后来只改一张就只带那张，群聊只有明确按钮提交才共享快照，明确请求仍显示实际发送结果。

#### Scenario: 发送前改动尚未保存（网络或临时失败）
- **GIVEN** 用户调整了卡片，这次改动因为网络或临时失败没有保存到中心
- **WHEN** 用户按下发送
- **THEN** 消息不发出，输入框上方出现明确提示：卡片改动尚未保存、这个会话暂时不能发送、这次不会带上，并提供「重试保存」
- **AND** 提示说明同一会话的其他消息也要等这次改动保存好（拦截范围是会话级，不是只拦这一条）
- **AND** 网络不可用时提示写明“当前网络不可用，恢复后会自动放行”，重试失败如实反馈，不静默发出缺背景的消息
- **AND** 已输入的正文与卡片当前状态保留，保存成功后提示消失、发送恢复；这条消息随后携带这次改动，且只携带一次
- **AND** 提示位于输入框与发送按钮的视线路径上，不依赖用户看到可能已在视口外的卡片内错误

#### Scenario: 发送前草稿在多端冲突
- **GIVEN** 同一张卡片的草稿已在另一台设备上被更新，本机这次改动被判定为冲突
- **WHEN** 用户按下发送
- **THEN** 消息不发出，输入框上方提示这是另一台设备更新了这张卡片、本机这次改动尚未保存，所以这条不会带上它
- **AND** 拦截范围与未保存失败一致，也是会话级：同一会话的其他消息同样要等这次冲突处理完，不只是这一条不发出
- **AND** 提示给出「查看最新改动」：只读展示字段级差异（另一台设备的值与本机的值），不应用也不丢弃任何内容
- **AND** 查看之后才给出「改用最新草稿（会放弃本机这次改动）」；选用后提示消失、发送恢复，需要本机那版时由用户在卡片上重新修改
- **AND** 在本机改动被明确放弃之前，正文、卡片状态与提示都保留，不做自动合并，也不静默丢弃冲突草稿

#### Scenario: 多卡背景过大时恢复
- **WHEN** 普通发送的有效卡片背景整组超出总量边界
- **THEN** 沿用发送失败提示，明确说明尚未发送及缩减卡片内容后重试、或在做过改动的设备上离开此聊天清除该端已保存待发背景的方式
- **AND** 正文、附件和卡片编辑保留，整组不消费、不静默少带，下一次发送重新按全部有效待发卡片判定
- **AND** 不新增附带选择、Detach 或确认弹窗，提示在桌面与窄屏完整可读

#### Scenario: 手机与桌面
- **WHEN** 用户在桌面或手机阅读和操作交互回复
- **THEN** 字段、主要动作和聊天输入可读可用，不因卡片宽度或内层滚动妨碍主对话。
- **AND** 窄屏下输入区上方的提示与既有的发送结果提示不互相遮挡，输入框高度不被挤到不可编辑

#### Scenario: 生成与渲染失败
- **WHEN** 回复正在生成或交互无法渲染
- **THEN** 用户能识别运行状态，已可读内容不无故消失，失败时仍能阅读摘要并继续打字。

#### Scenario: 私人状态与真实失败
- **WHEN** 用户重新打开会话、两台设备同时修改或发送失败
- **THEN** 恢复本人状态；冲突和未知结果明确反馈、保留当前编辑和原请求快照，不能静默覆盖或重复发送。
