# feat-720: 在用户的浏览器里操作页面（macOS 页面内动作）

## 原始需求

> 本节保留委派说明中的需求原文。本 unit 由主 Agent 转达的用户需求启动，未直接取得用户原始消息，因此不代写用户口吻；下列文字即本次收到的需求与已确认边界。

> 让节点（macOS）上的 Agent 能"在用户的浏览器里操作页面"，底层用已装好的 `cua-driver 0.38.0`（MIT，Apple 公证，macOS 唯一后端），跑在 DSH 节点进程内、**不引入第二套 agent loop**；动作审批复用现有 NanoApproval 层。首版范围是**页面内动作**（导航、点击、输入、滚动、读取），默认用驱动自有的独立 profile（`isolated_new`），要接用户已有 profile 必须显式前台授权。

已确认的边界（原文）：

> - 首版**不接**用户已有 profile 的静默路径；要接就必须显式 `existing_profile` + 前台授权，且文案写"需要你点一次授权、连接在 30 分钟空闲/8 小时总计内复用"。
> - 不做自建 Chrome 扩展桥（MV3 + native messaging）；这是将来单独 unit 的选项，只在本 unit 的非目标里一行提及，别展开设计。
> - 不登录账号、不提交表单、不下载；危险动作走审批；只写约定目录。
> - 未验证项必须如实标注：`delivery_mode:"foreground"` 未实测、iOS/Windows 未涉及、多显示器未验、真实登录态站点未验。

已确认的前台承诺（原文）：

> 产品承诺只能写成：**"不抢焦点地操作页面；新窗口或首次接入可能短暂占前台"**——design 与 spec 里都不许出现"绝不打扰用户"这类绝对表述。

## 澄清记录

- Q1: 首版是否接入用户已有 Chrome 的登录态与已开标签？
  A: 不接静默路径。要接必须由用户显式授权，并在授权说明中写明"需要你点一次授权、连接在 30 分钟空闲/8 小时总计内复用"；本 unit 不实施该通道（来源：委派说明"这个 unit 是什么"与"还要写清楚的边界"）。
- Q2: 是否自建浏览器扩展桥（MV3 + native messaging）？
  A: 不做。它是将来单独 unit 的选项，本 unit 只把它列进非目标（来源：委派说明"还要写清楚的边界"）。
- Q3: 前台行为可以承诺到什么程度？
  A: 只能承诺收窄后的那一句；不得出现"绝不打扰用户"一类绝对表述（来源：委派说明第 2 条硬约束）。
- Q4: 首版动作范围？
  A: 页面内动作：导航、点击、输入、滚动、读取。地址栏/浏览器自带界面操作、标签管理命令、下载、上传、登录、表单提交不在首版（来源：委派说明"这个 unit 是什么"与"还要写清楚的边界"）。
- Q5: 哪些结论必须先按未验证处理？
  A: `delivery_mode:"foreground"` 全部分支、iOS/Windows、多显示器/其它 Space、真实登录态站点；此外本机验证也未覆盖页面内文字输入（来源：委派说明末条与证据报告第 7 节）。

## 用户场景

**场景一：让 Agent 在浏览器里查一件事。**
用户在自己的 Mac 上开着 Chrome，登录着邮箱和公司后台，正在前台写文档。用户对 Agent 说"帮我打开这个文档页，找到设置里的导出按钮并点一下"。Agent 打开一个**自己的**浏览器窗口（不是用户那几个窗口），导航、读取页面、点击按钮，把结果回来。整个过程里用户的前台应用一直是他写文档的那个应用；他偶尔抬头能看到多了一个 Chrome 窗口在动，但没有被打断输入。

**场景二：页面自己弹出了新窗口。**
Agent 点击的按钮是页面脚本 `window.open` 打开的弹窗。这次浏览器自己把新窗口带到前面，用户正在敲的字被打断了。Agent 在结果里说明"页面打开了一个新窗口"，并在完成这次回读后结束自己的浏览器实例，前台回到用户的应用；要继续操作页面需要用户再发起一轮。用户知道这属于"新窗口可能短暂占前台"的范围，而不是 Agent 在乱动他的桌面。

**场景三：浏览器自带的小弹层。**
Agent 在页面上输入文字时，浏览器弹出了地址栏建议下拉或"翻译此页？"气泡。这些是浏览器自己的界面，不是页面内容。Agent 没有把这当成"出现了意外窗口"而停掉任务，也没有把它报告成失败；它继续读页面、继续下一步。

**场景四：页面把 Agent 带到了另一个标签。**
Agent 点击了一个会在新标签打开的链接，新标签成了当前标签，而旧标签还在。Agent 下一步要输入文字时，输入落到了它正在处理的那个页面，而不是"第二个标签"这种按位置猜出来的页面；如果它没法唯一确定目标，它会停下来重新读取或直接告诉用户"我不确定当前在哪个页面"，而不是赌一把。

**场景五：用户拒绝了审批。**
Agent 要点击一个"提交"按钮，审批卡片出现，用户点了拒绝。Agent 的结果明确说这次动作被拒绝、页面没有变化；它没有换一个元素再点一次，也没有改用别的工具绕过。

**场景六：本机能力不齐。**
用户在一台没装驱动、没给辅助功能权限、驱动版本不对、或驱动服务没起来的 Mac 上让 Agent 操作浏览器。Agent 直接说清楚缺的是哪一项、要怎么处理；它没有打开任何浏览器窗口，也没有把"什么都没发生"说成"已经做好了"。

**场景七：无人值守时不会自己开浏览器。**
半夜由定时任务、心跳或后台委派触发的轮次里，Agent 需要看一个页面，但本次还没有浏览器实例。它没有为了完成这条后台任务而在用户桌前弹出一个窗口，而是说明"需要一个用户发起的对话轮次才能启动浏览器"，并把这个限制留在结果里。

## 验收标准

### Requirement: 浏览器操作能力默认关闭，只在用户显式选择后提供

Agent 的浏览器读取与浏览器操作是两项可独立选择的能力，默认不选中；未选中时 Agent 既不会打开浏览器窗口，也不会读取任何页面。

#### Scenario: 新建和既有 Agent 默认都没有这项能力
- **GIVEN** 用户打开一个 Agent 的工具设置，该 Agent 从未配置过工具白名单
- **WHEN** 用户查看工具列表
- **THEN** 浏览器读取与浏览器操作两项都处于未选中状态
- **AND** 用户不选择它们时，Agent 接下来的回复不会打开浏览器窗口或读取网页

#### Scenario: 用户显式启用后开始生效
- **WHEN** 用户勾选浏览器读取与浏览器操作并保存
- **THEN** 该 Agent 下一轮新回复可以调用这两项能力
- **AND** 用户取消勾选后，后续回复不再提供这两项能力

### Requirement: Agent 只在自持的独立浏览器实例里操作，不触碰用户已有的窗口和登录态

Agent 打开的浏览器使用独立 profile；它看不到用户已经打开的标签、窗口和登录状态。实例随会话结束或空闲回收，不在用户机器上留下持久登录态。

#### Scenario: 用户已有 Chrome 窗口与登录态不受影响
- **GIVEN** 用户自己的 Chrome 开着多个窗口，并在其中登录了邮箱和后台
- **WHEN** Agent 首次执行一次浏览器任务
- **THEN** 出现的是一个独立的浏览器窗口，用户原有窗口、标签和登录状态保持不变
- **AND** Agent 读取到的页面内容只来自它自己打开的那个实例，不包含用户已登录的页面

#### Scenario: 实例随会话回收
- **WHEN** Agent 的浏览器任务结束，或该实例空闲一段时间
- **THEN** 该浏览器窗口消失，它使用的临时 profile 不被保留
- **AND** 用户下次再用时是一个干净的、未登录的新实例

### Requirement: 页面内动作在后台完成，前台影响按收窄后的承诺表达

产品对用户的前台承诺原句是：**"不抢焦点地操作页面；新窗口或首次接入可能短暂占前台"**。这句话是上限而不是时长保证，产品任何位置都不得改写成"绝不打扰用户"或等价绝对表述。

#### Scenario: 导航、点击、输入、滚动、读取期间前台不切换
- **GIVEN** 用户正在前台应用里打字，Agent 的实例已经启动
- **WHEN** Agent 在它自己的浏览器实例里导航、点击、输入、滚动并读取页面
- **THEN** 这段时间前台应用始终是用户原来那个应用
- **AND** 用户不需要切回自己的应用

#### Scenario: 页面脚本打开新窗口时可能短暂占前台
- **GIVEN** Agent 点击的页面元素会由页面脚本打开一个新窗口
- **WHEN** 新窗口出现
- **THEN** 浏览器可能短暂成为前台应用，用户当前输入可能被打断
- **AND** Agent 在结果里说明"页面打开了新窗口"，用户可以切回自己的应用继续工作

#### Scenario: 首次接入可能短暂占前台，且只发生在用户发起的轮次
- **WHEN** Agent 在用户发起的对话轮次里第一次启动独立浏览器实例
- **THEN** 启动过程可能把该窗口短暂带到前台
- **AND** 用户不需要做任何授权确认或点击
- **AND** 无人值守（定时/心跳）或后台委派轮次不会为此新开实例：它只复用已有实例，没有实例时说明需要用户先在对话里发起

### Requirement: 浏览器自带界面的噪声不打断任务，真正的窗口事件不被当成失败

浏览器自身的弹层（地址栏建议、翻译提示等）不是页面事件，也不等于失败；只有能确认为独立浏览窗口的事件才需要报告，无法判断时结束本次动作并说明。

#### Scenario: 浏览器弹层出现时任务继续
- **WHEN** 浏览器弹出一个无标题、固定小尺寸、没有自己页面地址的弹层
- **THEN** Agent 继续当前任务，不把它报告成失败或异常
- **AND** 它不会为了"处理这个窗口"而重复执行上一个动作

#### Scenario: 真正的页面新窗口被报告，前台随之归还
- **WHEN** 页面打开了一个有独立地址的真实浏览窗口
- **THEN** Agent 把它作为事件写进结果，说明发生了什么
- **AND** 它在完成这次回读后结束该浏览器实例，让前台回到用户原来的应用；继续操作页面需要用户再发起一轮
- **AND** 如果它无法判断这是页面窗口还是浏览器界面，它结束本次动作并说明，不自动重试

### Requirement: 页面或标签身份变化时，Agent 不按位置猜目标

页面可能自己打开新标签、切换当前标签。Agent 的后续动作必须落在它确认的那个页面上；无法唯一确定时拒绝执行并说明。

#### Scenario: 新标签成为当前标签后不点错页面
- **GIVEN** Agent 正在处理一个页面
- **WHEN** 它点击的链接在新标签打开该页面，新标签成为当前标签
- **THEN** 下一次点击或输入落在它正在处理的这个页面
- **AND** 不会因为"标签顺序变了"而操作到另一个页面

#### Scenario: 目标无法唯一确定时拒绝执行
- **GIVEN** 同一个窗口里有两个地址和标题都相同的标签
- **WHEN** Agent 要在这个窗口里执行一次点击或输入
- **THEN** 它报告无法唯一确定目标，并说明需要重新读取或请用户澄清
- **AND** 它不会任选其中一个标签执行

### Requirement: 动作经既有审批，危险动作有明确边界

所有会改变页面或发出请求的动作都经过现有审批；只有只读页面读取可以自动放行。无人值守轮次不会把"没人在场"当作自动放行的理由；没有人工审批出口的会话里，需要人工确认的动作被拒绝，Agent 说明并停下。登录、提交表单、下载不在能力范围。

#### Scenario: 用户拒绝后动作没有发生
- **WHEN** 用户拒绝一次浏览器操作的审批
- **THEN** 页面没有任何变化，Agent 的结果明确说明这次动作被拒绝
- **AND** Agent 不重试同一动作，也不换一个元素或换一个工具达到同样效果

#### Scenario: 没有人工审批出口时不自动放行
- **GIVEN** 一次由定时任务、心跳或后台委派触发的轮次
- **WHEN** Agent 的页面动作需要人工确认
- **THEN** 该动作不执行，也不会因为无人值守的自动放行配置而执行
- **AND** Agent 说明这一步需要在用户发起的对话里确认

#### Scenario: 超出边界的请求被拒绝并说明
- **WHEN** 用户要求 Agent 登录账号、提交表单或下载文件
- **THEN** Agent 说明这些不在浏览器能力范围内，不执行
- **AND** 它不会先用别的动作绕到同一个结果

### Requirement: 能力不可用或执行失败时如实说明，不把空响应当成功

驱动缺失、未运行、未授权、版本不符，或执行返回空/无法解析的结果时，用户得到可理解的失败说明，而不是一个看起来成功的空结果。

#### Scenario: 本机能力不齐时不假装可用
- **GIVEN** 本机没有安装驱动、驱动服务没有运行、缺少系统权限，或驱动版本与预期不符
- **WHEN** Agent 尝试执行浏览器任务
- **THEN** 用户看到具体缺少哪一项以及处理方向
- **AND** 期间没有打开任何浏览器窗口，也没有任何动作被描述成已执行

#### Scenario: 空响应不是成功
- **WHEN** 驱动返回空结果或无法解析的响应
- **THEN** Agent 报告这次动作失败，并说明可以怎样继续
- **AND** 它不把空结果描述成页面已更新或动作已完成

### Requirement: 关于页面画面与位置的结论必须有画面证据

Agent 说"某元素可见"或"已滚动到某处"时，结论要能对上它拿到的画面；读数与画面不一致时以画面为准并说明。画面截图只是本次任务的临时证据，只保留有限时间，不向用户承诺长期保存，也不作为记忆内容。

#### Scenario: 滚动结论与截图一致
- **WHEN** Agent 声称页面已经滚动到某个位置或某个元素在视口内
- **THEN** 它同时给出的画面证据与该结论一致
- **AND** 若只有读数、没有画面证据，它明确说明这一点，不把读数当成已验证

## 范围与非目标

- 在范围：
  - macOS 节点上的页面内动作：打开/导航到 http(s) 页面、读取页面内容与画面、点击元素（按最近一次读取返回的 ref）、在页面输入框输入文字、滚动页面；
  - 使用驱动自有的独立 profile（`isolated_new`），实例随会话与空闲回收；
  - 复用现有审批层与工具选择机制，两项能力默认关闭；
  - 浏览器自带弹层与真实窗口事件的区分、标签身份变化的处理、失败与不可用的如实报告；
  - 供实施与验收使用的本机验证证据（见 [evidence/desktop-verification.md](evidence/desktop-verification.md)）。
- 非目标：
  - 坐标点击：v1 不接受"按画面坐标点某处"，只接受最近一次读取返回的元素 ref（截图是设备像素、没有可用的 CSS px 坐标来源）。
  - 接入用户已有 profile 的静默路径。任何将来的接入通道都必须由用户显式授权，并使用固定文案"需要你点一次授权、连接在 30 分钟空闲/8 小时总计内复用"；该通道不在本 unit 实施（本机验证未覆盖，且当前驱动安装不满足其前置授权条件）。
  - 自建 Chrome 扩展桥（MV3 + native messaging）：将来单独 unit 的选项，本 unit 不设计。
  - 地址栏与浏览器自带界面的操作（地址栏输入并提交、标签管理命令、扩展管理、窗口/菜单操作）。
  - 下载、上传、文件选择、JavaScript 对话框处理、登录、表单提交、支付或发布类动作。
  - 任何形式的自主脚本化执行（一次调用内循环、条件判断、批量动作编排）；本 unit 只提供逐次工具调用，不引入第二套 agent loop。
  - 多显示器、其它 Space、Windows、Linux、iOS 与远程节点；本 unit 只覆盖当前 macOS 节点本机会话。
  - 真实登录态站点的页面行为；验证只使用本地夹具与公开页面。
