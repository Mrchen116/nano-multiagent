# feat-737 本地截图随 Agent 消息交付的技术方案

> 对齐 [首文档](spec.md)

## Changelog

- 2026-11-09 (M1) 使用专用 `AttachmentImage` 组件引用同消息附件。旧客户端按普通附件降级，避免把无法识别的图片引用送进公开照片搜索。

- 2026-11-09 (M1) 明确本地图片发送与卡片内展示是通用能力。移除本 unit 新增的截图对比例，用全新 Agent 和没有卡片成品示例的 Skill 复测。

## 现状分析

- [工具声明](../../../packages/dsh-integration/src/message-arguments.ts)的 `attachments` 接收已托管 URL。PA 将其送进审核和发布，普通 Agent 的 [显式发送](../../../packages/personal-assistant/src/global-agent.ts)尚未转发本地图片。`AgentPublication` 已支持附件与卡片同发，但 [IM 发布](../../../apps/im-server/src/messaging.ts)需要补齐附件归属校验和重放一致性。
- [媒体路由](../../../apps/im-server/src/media.ts)已有网关身份、目标会话写权限、生命周期、图片探测、10 MiB、配额和幂等上传。下载以所属会话鉴权。节点已有认证 HTTP 客户端，执行运行时继续只经既有 stdio product bridge 连接宿主。
- PA 现有 [准备与提交](../../../apps/im-server/src/personal-actions.ts)会冻结来源图片、给审核者实际图片、授权后复制到目标会话。把待审图片准备在 PA 主人与 PA 的私聊，可直接复用该流程。
- [OpenUI 图片组件](../../../src/IM/frontend/src/features/chat/interactive/open-intelligent-ui/components/media.tsx)使用普通 HTTP(S) 图片和公开搜索回退。Web 聊天已有受保护图片加载与放大；原生 iOS 已有原生附件预览和受限的卡片宿主桥接。卡片内的附件引用需要宿主支持。
- feat-551/563 的图片交付沿用同一会话受保护资源语义。DSH 迁移后的显式发送接线缺失由本 unit 补齐。Raft 参考版本为 `db5e399f017d584e49597e3a28757645d6807893`，复用其先传字节再绑定消息的语义，Nano 在一次发送调用中完成。

## 关键决策

**保留一次工具调用。** `send_message` 新增 `local_images: string[]`，按顺序列出最多五个绝对路径，第一版支持 PNG/JPEG/WebP，沿用现有图片上限。路径是工具审核可见的发送参数，由已获准执行的公聊工具走宿主上传。节点读取前检查本地实际文件和大小，拒绝非普通文件。现有幂等图片路由增加 Gateway 截图模式，复用 PA 的完整静态图片解码校验。普通 Agent 每图最多 10 MiB、边长最多 4096，PA 另受既有审核总量 20 MiB 限制。普通用户上传沿用现有格式探测。工具错误指出失败序号与原因，私有回执可带路径。公开消息、SingleThread 工具过程和权限卡片仅投影截图数量及失败类别，审核保留实际路径和权限事实。现有 URL 附件参数继续承载已有托管资源，同次调用有两类附件时，已有附件排前，本地图片排后，合计不超过五个位置。同一来源只准备一次，重复位置引用同一份资源。该参数限定显式自身份发送，PA 主人代发和原生父子消息接口不扩展。

**人工授权需要完整的待发证据。** 若本地图片发送的现有权限判定要求转人工，工具在读取或上传前拒绝，并给 Agent 返回私有的可操作反馈。群权限卡无法只向授权者显示本机路径与待发证据，因此不发布这类审批卡，也不把拒绝降格成数量确认。已经明确允许执行的自动权限判断仍适用，PA 对外披露审核照常覆盖实际截图和受众。提示 Agent 说明本次未发送，交由人从现有附件入口上传，或由 owner 在支持的权限模式下重新发起。手动请求分支要验工具被拒、没有上传及发图消息、群内无路径。

**卡片按同条消息的附件顺序取图。** `AttachmentImage(1, "改动前")` 指第一份消息附件，只能取图片。序号随有序附件持久化，无需维护额外的 URL 或映射。卡片源既可用这些图片，也可组合 `Grid`、`Table`、`Svg`。只要视觉结构有助于理解，即可使用无控件的卡片。布局由 Agent 按内容选择，群友可以点开原图。

**由聊天宿主取图和打开原图。** Web 通过消息自身的附件列表解析并复用受保护图片加载、放大。iOS 共享卡片渲染器按序号向原生宿主请求，宿主验证仍是当前卡片，从当前消息附件解析并沿用原生认证读取与图片预览。客户端不从卡片源码接受任意附件 URL，不把认证凭据交给卡片，不把失败的截图替换成搜索结果。成功呈现的附件从同一消息的附件区去重，未使用或加载失败的附件保留可操作入口。沿用已存在的缩略图和预览交互，卡片布局由 Agent 按内容生成。

## 接口与数据流

1. DSH 将路径保留在实际待执行的工具入参及权限检查中。PA 独立对外审核在产品侧执行。目标和会话权限先确认，过时草稿照常返回 `held_for_revalidation`。只处理原生 Nano IM 目标。
2. 节点的认证上传适配读取已授权工具列出的路径，将图片按顺序传到 `POST /im/v1/conversations/:id/images`。普通 Agent 上传到最终会话。PA 上传到自身主人会话，然后通过现有 PA action prepare / commit 审核并复制实际图片。已有上传凭据和读图授权保留在原来的所有方。
3. 每个不同本地来源的上传键以 Agent、工具操作标识和来源首次出现的序号构成。截图模式支持认证的 `GET /im/v1/conversations/:id/images` 按原键取回已提交上传，检查 Agent、会话写权限及生命周期。上传结果不明时先查这个回执，已落盘则沿用托管结果，原路径移走也可恢复。缺少已上传记录才读取并重试原键，字节变更按原有幂等冲突处理。普通群在上传后、提交前再次检查已知新输入。失败或过时的上传未绑定公开消息，其存储继续按媒体层处理。
4. 普通发布及 PA 主人私聊沿用 `agent.message.status`。PA 对外发布新增只读 `pa.action.status`，由绑定身份按原 request key 查询 `pa_operations`，确认会话与读取权限后返回已确认消息。截图发送遇到提交结果不明时返回原操作引用，Agent 用 `send_message({target, receipt_of})` 查询。查询只读，需匹配原 Agent、原操作及目标。原操作恢复时先查回执，已确认无需重新上传；状态仍不明确则继续返回 unknown。
5. 将已托管附件连同正文和 OpenUI 交给现有消息发布。普通发布只接受目标会话中的托管附件，按服务端元数据绑定并比较重试的附件顺序。PA 复用既有的来源权限和复制逻辑。IM 历史与实时事件传递同一份附件列表。卡片的普通 URL 图片沿用既有行为，截图引用只有消息内解析这一条路径。

## 模型可见信息

- Agent 从 `send_message` 的工具声明得知本地图片参数和失败后的操作。基础发图无需 UI Skill。启用 UI 时，Skill 给出 `AttachmentImage` 的签名、同消息索引规则和原图查看方式。内部执行者交接图片路径和顺序给发送消息的 Agent。
- 目标、文件路径及实际发送结果由宿主工具调用和回执承载。单张上传失败说明路径、失败原因及修正方向。已确认回执与暂缓、未知分别保留原语义，未知提示带可复制的回执查询参数。PA 审核模型使用现有冻结的图片内容及受众证据。
- 用隔离运行捕获实际工具声明、Skill 加载结果及发图工具回执。使用全新 Agent 复测截图比较与单张现场照片说明，移除隔离环境 Skill 的卡片成品示例，观察 Agent 如何选择布局、引用图片和发送。

## 契约层增量

- IM [卡片内附件预览](specs/im/conversations-messages.md)。

## 风险与回退

- 文件内容或目标在发送期间变化时，使用同一操作冻结的上传结果及最新权限，避免重发或提交旧草稿。已发送消息按历史资源回看。
- UI 载入失败时原生附件可点开。回退节点或客户端时，已交付资源仍保存在普通消息附件中，未识别的卡片引用由附件区承接。

## 一次性部署迁移

无。沿用现有消息附件存储。
