## 原始需求

> agent现在可以通过发UI来发本地的图片吗，比如一个场景，agent本地开发完代码，截图给效果发给IM的群里，大家看

> 那 Nano 也可以参考 Raft 做吧，先看看怎么复用现有的附件上传，让 Agent 开发完截图后能用 send_message 直接发到群里，大家点开看。另外，我觉得主要还是通过UI来放图会比较好，UI的作用不仅仅是交互，是便于理解，比如对比图，可以搞个表格，前面还可以加流程图之类的其他UI

## 澄清记录

讨论方案包含一次发送本地截图、普通消息和卡片复用同一份附件、前后对比优先用 UI 组织，以及 Web 和 iPhone 的查看、放大与回看。用户回复「好，开始搞」。

> 而且我们也不是只针对「开发完就发一张对比卡」这个场景。我们这是增加一种通用能力

本 unit 给 Agent 增加通用的本地图片交付能力。支持的本地图片可随消息发送，也可嵌入同一条消息的 UI，与说明、表格或流程图一起呈现。Agent 按内容选择表达方式。UI Skill 只新增附件引用规则，移除本 unit 之前加入的完整截图对比例；用全新 Agent 和没有卡片成品示例的 Skill 复测。

## 用户场景

Agent 改完页面后在本机截取改动前后的画面，在原 Nano IM 群里交付一条结果消息。群友能先看流程和改动说明，再比较两张截图，点开检查细节。单张截图也可以随普通消息交付。看过结果的人刷新、重开聊天或换设备后仍能回看，且读取范围遵循原群权限。

当前 Gateway 契约曾记录本地图片交付，现行 DSH 节点的显式发送链路缺少本地文件准备环节。IM 已有会话级图片上传及读图权限。Raft 的已发布源码和手册显示本地文件上传后与消息绑定，群友可直接预览。参照的是这一交付语义。 [现有图片契约](../../specs/gateway/routing-delivery.md) · [Raft 附件手册](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/manual/agent-knowledge/attachment.md#L28-L57)

## 验收标准

### Requirement: Agent 一次发出本地图片及说明

#### Scenario: 群友直接查看普通消息里的截图
- **WHEN** Agent 将本机准备的截图和说明发到已有发言资格的 Nano IM 群
- **THEN** 群友收到一条消息，能在聊天内预览并点开原图，Agent 原文件移走或节点离线后仍能回看
- **AND** 无群读取资格者即使持有图片地址也无法读取

#### Scenario: 图片准备失败与发送恢复
- **WHEN** Agent 要发送的截图无法读取、格式不支持、超限或上传失败
- **THEN** Agent 收到可据以修正的反馈，群里没有缺图的结果消息
- **WHEN** 同一次发送在响应丢失后重试
- **THEN** 群里只有一条交付消息，Agent 可查到实际结果

#### Scenario: 群聊中缺少足以确认图片的人工审批入口
- **WHEN** 发图动作需要人工确认且确认人无法私下核对实际待发对象
- **THEN** Agent 得到未发送原因，群里没有待审批的匿名截图请求或本地路径

#### Scenario: PA 对外发送截图
- **WHEN** PA 向其有资格发言的 Nano IM 群发送截图
- **THEN** 现有外发审核覆盖实际图片与受众，通过后才向群交付

### Requirement: 卡片可用本地图片解释内容

#### Scenario: 群友阅读改动前后对比
- **WHEN** Agent 在一条群消息里用卡片组合流程、改动前后截图和差异说明
- **THEN** Web 和原生 iPhone 群友能辨认每张图对应的版本，直接点开原图，并从历史回看
- **AND** 成功在卡片里显示的截图在同一消息里不重复铺开

#### Scenario: 群友结合本地图片和说明理解内容
- **WHEN** Agent 把本地图片作为图文消息的组成部分
- **THEN** 卡片可在适合阅读的位置引用同消息的图片，群友可以预览并点开原图

#### Scenario: 卡片无法显示
- **WHEN** 收件端无法渲染图片卡片
- **THEN** 群友仍可从这条消息的附件区打开原图

## 范围与非目标

- 范围包含 Nano IM 的显式 Agent 图片消息、Web 和原生 iOS 的受保护卡片图片与普通预览，以及解释类 UI 的 Agent 指导。
- 本地图片可由 Agent 用现有工具生成，也可来自其有权限读取的文件。飞书等外部通道、本地任意文件交付和自动转换普通最终回复中的 Markdown 路径不在本 unit 范围内。
