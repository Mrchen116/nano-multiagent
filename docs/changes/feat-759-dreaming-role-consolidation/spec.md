## 澄清记录

### 已确认的范围

下列三点为 Agent 上轮建议，经用户上述原话整体纳入本次；尚不代表各点的具体方案已确定。

1. **补齐角色视角。** Dreaming 获得所服务 Agent 的具体职责、长期目标和服务对象，用来判断应从经历中学习什么；角色背景不替代事实证据。
2. **区分材料保真与长期整合。** 任务摘要可保留较完整的经历与接续线索，正式记忆进一步筛选、关联和提炼；历史页保留理解结论所需的关键经历，不机械复制摘要全部细节。
3. **让整理包含重组。** 更新当前理解、合并重复内容、压缩已被取代的中间过程、维护可用首页，避免主要靠追加过程和限定语维持准确。

### 设计初心与历史依据

依据 feat-676 的[用户原话与最终决定](../archive/feat-676-role-memory-dreaming/spec.md)、[内容决策](../archive/feat-676-role-memory-dreaming/input/nano-memory-research-v2/01-decisions.md)、[文档规范](../archive/feat-676-role-memory-dreaming/input/nano-memory-research-v2/design/layout-and-documents.md)及[上游来源说明](../../../packages/dsh-integration/assets/dreaming-provenance.md)：

- 长期 Agent 从持续经历形成可修正、有依据、能改善后续判断与行动的理解；不以减少文件或字符数本身作为目标。
- Codex 提供任务经历提炼、整合与证据/范围保真方法；Instinct 黑盒材料启发文档分层与单一后台写入者；Muse 社区材料补充关系、目标变化和互动反思。不同来源的证据等级保持，不声称掌握后两者完整生产实现。
- Global 合格交流原文直接参与整理；第一层任务 child 提炼任务经历，更深层通过所属任务贡献结果。两路材料结合已有记忆，形成同一主体的长期理解。
- PA 围绕主人、关系、目标和服务校准；专家围绕专业职责、项目认识、工作经验与协作；保留关键经历、适用条件、反例及重要但不高频的约束。
- 一页入口直接提供关键理解与导航，详情按需读取；当前主题理解与历史经历分开，一个知识内容有一个主要维护位置。
- 正式记忆由 Dreaming 统一写入，当前对话立即采用新纠正；任务执行状态、原始历史与成熟 Skill 保持各自职责。

### 本轮调查依据与限制

2026-11-10 只读检查了禅与 PA 的正式记忆：首页和目录、角色/协作/项目/生活职业相关页面，以及部分长任务历史。禅当时有 21 份 Markdown、约 44.4 万字符，其中约 80% 位于 work-history；PA 有 16 份、约 6.46 万字符。观察到重复状态摘要、中间测试与审批过程占据较多篇幅，也保留了有价值的协作纠正、角色背景和个人目标。

禅首页当时为 9,461 字符；部署基线 `383bc7904` 的首页装配在超过 8,000 UTF-16 code units 时只提供读取提示。文件统计与装配代码支持首页超限判断，本轮未捕获新 provider 请求，未验证其是否实际漏读。未逐条核验全部记忆的原始来源；不把这些统计本身作为质量失败阈值。

当前契约见 [Agent capabilities](../../specs/gateway/agent-capabilities.md) 的角色化文档记忆、关键记忆与 Dreaming 条目。当前 Dreaming 明确提供 PA/专家类别，尚未专门提供具体 Persona/长期职责背景，相关缺口见 #465。记忆内容问题与该缺口的因果关系尚无对照实验证明，不能将全部问题归因于 Persona 缺失。

### 角色约定的维护与使用

用户提出将角色约定从 `MEMORY.md` 独立出来：

> 独立一个文件，这个文件dreaming不需要更新，主agent来更新，在识别到用户要求改的时候，跟用户确认过之后改。放在workspace的.nanoassistant里。

用户明确写入约束和初始为空时的行为：

> prompt约束就行。

> 不是被动的，一开始空的时候要不停找用户要。里面是一段提示占位符，要求agent不停的问用户。里面的内容只有用户明确沟通才能写入和更新。

按讨论归纳，工作区的 `.nanoassistant/ROLE.md` 简要保存用户明确的长期职责、目标及适用的协作分工。PA 的服务对象沿用系统绑定。

- 初始为空时，角色文件保留一段提示占位符，要求主 Agent 主动向用户询问角色信息。用户尚未明确时，主 Agent 持续主动追问。
- 首次填入和后续修改都由主 Agent 完成。主 Agent 先说明拟写入的约定，得到用户明确确认后再写入。用户的日常对话可以明确约定，临时交办不视为长期职责。确认行为通过 prompt 约束，无需额外的系统写入审批。
- 主 Agent 使用当前角色约定开展工作，Dreaming 在整合开始时读取同一份约定，作为判断记忆价值的背景。Dreaming 对角色约定只读。角色背景独立于 `MEMORY.md` 提供，来源事实与业务授权仍由各自的依据决定。
