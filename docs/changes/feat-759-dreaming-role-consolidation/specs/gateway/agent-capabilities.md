# Gateway Agent capabilities Specification (delta for feat-759)

## ADDED Requirements

### Requirement: 用户确认的角色约定独立于正式记忆

#### Scenario: 尚无约定
- **WHEN** 使用文档记忆的 PA 或独立 Agent 尚无用户确认的约定
- **THEN** 主 Agent 在正常用户交互中主动向 PA 主人或独立 Agent 所在节点的绑定主人询问长期职责、目标及适用分工，尚未澄清时在后续适当的交互继续询问。PA 的服务对象沿用主人绑定。
- **AND** 临时任务和未获同意的建议不写入角色约定。

#### Scenario: 首次确认或修改约定
- **WHEN** PA 主人或独立 Agent 所在节点的绑定主人在实际提议所在交流中明确同意拟写入的长期约定，且普通文件工具保存成功
- **THEN** 主 Agent 保存到所属工作区的 `.nanoassistant/ROLE.md`，后续主 Agent 请求及新开始的 Dreaming 整合消费同一份已保存约定。
- **AND** Dreaming 只将其作为组织记忆的角色背景，权限与事实来源保持各自依据。角色约定可由管理者直接维护，也可由主 Agent 在对话确认后更新。

#### Scenario: 未确认或未保存
- **WHEN** 适用的用户尚未确认该提议，或确认后文件工具不可用、拒绝或保存失败
- **THEN** 主 Agent 与 Dreaming 继续使用原约定或占位状态。确认后保存失败时，主 Agent 如实告知用户未保存。

#### Scenario: 管理者直接保存角色约定
- **WHEN** 管理者通过配置页成功保存新的角色约定或清空约定
- **THEN** 后续主 Agent 请求和新开始的 Dreaming 整合使用工作区同一份最新角色文件，清空后采用未设置状态。
- **AND** 当前整合批次继续使用其已有快照，权限与事实来源各自维持原有依据。

## MODIFIED Requirements

### Requirement: Dreaming 按交流与任务经历组织记忆

#### Scenario: Global 原文与第一层任务复盘
- **WHEN** 同一主体的 Global 跨聊天、跨窗口持续交流，第一层子执行开展具体任务
- **THEN** Global 合格交流保留原文、按连续范围分批进入后台整理；第一层子执行形成会话级任务复盘，与已有记忆一起由一个整理者更新同一文档库。
- **AND** 整理时按可信角色选择反思关注：PA 保留用户目标、处境、关系和帮助效果；专家关注领域与项目变化、已确认决定、环境条件、真实成败与多人协作，区分合作者偏好、任务要求与项目决定。共同的证据、适用范围与主动沟通偏好规则保持，按 PA/专家现有实体、知识、事项/项目、历史和短入口维护，不新增互相隔离的知识库；更深层结果经所属任务归纳，不独立逐层摘要。

#### Scenario: 从任务材料形成可复用的理解
- **WHEN** 一份任务复盘包含可复用结论、当时的任务要求和已被替代的尝试
- **THEN** 整合按当前角色判断长期价值，主题页保存有来源的现行认识和适用条件，历史页保留有助于理解或回查的关键经过。
- **AND** 保留任务要求的原适用范围，详细经历仍可通过合格来源回查。

#### Scenario: 按主题重组已有知识
- **WHEN** 一次整合有足够依据更新与本批相关的已有主题
- **THEN** 合并重复、修订过时结论、保留仍适用的例外和关键历史，并维护通往现行内容的链接。
- **AND** 日常请求中直接装入的首页保留跨任务所需的少量内容及按需阅读链接。只更新详情时，仍适用的首页可以保持原样。跨页迁移的有效内容在接收页保存前仍可从原页读取。

#### Scenario: 旧子会话续做
- **WHEN** 已提炼的子会话继续产生合格历史
- **THEN** 重新从该会话截至本批边界的合格历史按预算选择材料，生成新摘要替换同一会话旧摘要；无更新复用，不生成增量阶段复盘链。
- **AND** 来源与省略清楚，不声称完整重读全部历史；其后无新增 Global 消息也能处理更新。

#### Scenario: fork 继承背景用于理解
- **WHEN** 子任务自身指令或结果依赖继承的父会话条件
- **THEN** 合格继承历史与自身经历一起按现有过滤和输入容量选材，标明背景及原作者、时间、来源；背景曾被整理不代表必须删除，子续做后仍重新提炼并替换摘要。
- **AND** 继承内容不计为 child 新经历，同源引用不算多份独立证据；缺失或未提供的条件保留未知，不新增背景摘要阶段或平行 fork 存储，不突破当前来源资格与允许历史范围。

#### Scenario: 提炼输出与整合批次 Git 提交
- **WHEN** 任务提炼或记忆整理执行结束
- **THEN** 两阶段均不提供私有 `finish` 工具。提炼从最终 JSON 读取并校验 `rollout_summary`、`rollout_slug`，两者为空表示无信号。整合变更由 Dreaming Agent 发起正式库 Git 提交，宿主校验并保存正文与首页。没有改动时可以直接结束。
- **AND** 每次整合正常结束后，宿主检查正式仓。仍有未提交变更时，同一整合 Agent 收到检查结果并继续，仓库干净且文件和来源核对通过后才记录成功并推进对应来源。
- **AND** 模型失败、取消、输出结构错误、文件核对失败或仓库状态无法确认时不推进对应进度。最终状态依据宿主回执。

#### Scenario: 按模型容量联合安排材料
- **WHEN** Dreaming 对积压交流和任务经历选材
- **THEN** 两阶段各自以实际模型声明上下文的 70% 为首轮完整输入估算上限，并保留输出容量；系统提示、工具、记忆入口、来源说明与材料合并计算。默认不再固定 24K；显式材料上限仍可缩小批次，模型容量未知时如实不可用。
- **AND** Global 连续原文和对应截止时间内的任务摘要共享预算，装不下的完整摘要在继续推进下一段 Global 前补批处理；正文成功保存后才推进实际已纳入的来源/摘要版本，未来材料、失败与取消不被误标完成。

#### Scenario: 连续批次和独立进度
- **WHEN** Global 积压超出一批预算，或任务提炼成功而整理失败
- **THEN** 成功保存后推进对应 Global 范围及已整合摘要版本，正常情况下继续本次冻结目标，无 Dreaming 专属累计时长/步数限制；真实失败终止本次并保留已保存进度，后续运行核对应用回执后按当时最新上界重新冻结，旧轮次清单不成为准入条件；已提炼但未整合且版本匹配的有效摘要可复用。
- **AND** Global 未读交流因预算延后而不丢弃；不把窗口、LLM step 或每次 child 唤起当作独立记忆事项，不向模型要求逐 step 覆盖清单。
- **AND** 业务任务未完成或执行失败仍可总结经历，无信号正常结束；真实提炼故障停止本次并重试，不承诺永久故障时仍绕过推进。旧批次不提前纳入未来 child 结果，当前对话采用较新纠正，后续批次再持久化；来源撤销立即限制消费。
