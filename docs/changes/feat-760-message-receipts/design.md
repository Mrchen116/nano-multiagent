# feat-760 实际设计

本文在实现后整理。实现基线为 `bfc908101`，初审实现版本为 `b416109a4`。

IM 发送时保存收件人集合与三态。真人客户端在解码消息后确认送达，以现有聊天阅读上报推进已读。Gateway 使用各 Agent 的投递与读取事实推进对应收件行。发送者通过消息接口取得详情，Web 与 iOS 使用同一份收件人数据汇总状态。历史消息没有生成过回执数据时按原样展示。

Global Agent 的 Inbox 读取事务保留原路径。后台在读取提交后根据持久摄取记录派生回执，按内部 IM 和飞书分别发送并重试。失败的飞书项留到下轮，当前批次继续处理其余回执。原生单会话 Agent 以本地接收及运行时消费证据更新回执。飞书应响应的普通 Global Agent 消息使用 `OK` 与 `CheckMark`，按 Bot 更新原消息反应。Web 点勾打开可滚动浮层，回执刷新保留已加载的旧页和分页位置。iOS 将勾放在发送气泡右下角，点击打开原生浮层。两端打开详情时读取当前消息的逐人状态，也适用于已分页加载的历史消息。

服务启动时通过现有 schema 初始化机制增补回执数据结构。发布时需要同时提供支持回执的 IM、Gateway 和客户端版本。启动后的旧消息可以缺少回执数据。客户端送达确认在当前 Web 页面或 iOS 进程内以后台队列重试。重新启动客户端后，加载消息历史可再次确认。适用的失败和恢复路径由 relay recovery、Inbox、Global Agent 与飞书 adapter 测试覆盖。

本地对照曾用内存 SQLite、8,000 条历史记录和四条消息的读取页进行测量。60 个样本的读取提交中位耗时分别为功能前 0.089 ms、同步投影 1.492 ms、后台投影 0.089 ms。该测量范围为本地读取提交。Web 用真实页面与隔离 IM 观察过汇总、详情和状态更新。iPhone 17 模拟器连接隔离 IM 验证最终的气泡布局、三态和无标题详情。飞书反应通过 adapter 模拟验证。

最终版本的用户验收留在活动单元中跟踪。拟归并的对外契约见 [delta-spec](specs/im/conversations-messages.md) 和 [飞书 delta-spec](specs/gateway/external-channels.md)。
