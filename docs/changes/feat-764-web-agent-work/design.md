# feat-764: Web Agent 工作记录与头像状态卡

## Changelog

## 现状分析

- Web 聊天用 `message-pane.tsx` 的会话头和消息头像。现有 `View Work` 通过 Agent ID 和实际发信消息 ID 跳转。Work 由 `agent-work-panel.tsx` 组装，已有主、子执行分页和原生轨迹路由。工具详情已有 `WorkTool`、`ToolDetailBody`、`NativeToolDetail` 和 `ConversationToolCard`。
- 中心 `work.ts` 统一校验登录、空间、个人归属和删除状态；`work-records.ts` 有主执行查询、精确回复锚点、关联执行元数据、轮次状态和 usage。节点在线与 Work 同步可信度是不同信号。Work 现有 API 不能从一页目录推断全树活跃子执行数。
- Dreaming 的宿主回执从 DSH `knowledge.facts` 经 PA `KnowledgeUpdates` 投影至独立维护会话，原生轨迹已有真实身份。当前该投影没有报告工具次数、模型和用量。原生查看器、权限、导出、轨迹数据格式沿用现有实现。
- [perf-749](../archive/perf-749-direct-work-focus/design.md) 用持久发信关系直达旧轮次，不遍历中间历史。[perf-751](../archive/perf-751-incremental-global-descendants/design.md) 将 Gateway 子树发现和恢复改为增量。[perf-753](../archive/perf-753-bounded-work-reads/M1-work-reads/evidence/implementation.md) 将目录和正文从首屏摘要中拆出。在 15,000 轮、最新一轮约 15,000 个工具项、10 万关联执行的隔离样本里，中心头页从约 21.16 MB 降到 5,492 B，HTTP 中位数从约 2.11 s 降到 13.87 ms。该数字是历史实验，候选和本次基线另行重测。[perf-754](../perf-754-bounded-work-transfer/design.md) 正在设计独立大明细传输，本 unit 保留其兼容边界，既有投影和原文读入口继续负责大小限制与授权。

## 关键决策

1. **共用一个记录阅读区。** 主、历史主、子执行共用既有 Turn/WorkTool 与按需查询。选中执行替换阅读区，父级导航保存执行、实际来源行、滚动及展开状态。聊天锚点、派工节点和关联入口复用现有精确身份；普通页与锚点的缓存保持独立。派工图范围与选中节点不随返回丢失。原生轨迹继续走现有 `work_view=trajectory&execution=...` 入口。
2. **连续阅读使用有界正文。** 头页继续走 `view=summary&catalog=separate`。记录按日期和轮次连续排版，首屏及读到视区的轮次自动展示首批过程，最多两个并发，使用现有每页 20 项的正文入口；页面以下未到达的轮次只保留轻摘要。自动首批及活跃增量使用显式 opt-in 的过程预览，每项序列化预览最多 4 KiB、每页 20 项，预览只包含工具头部、正文片段、关联与状态。没有视区自动读正文、自动预取长参数或后台遍历历史。长结果和后续过程显式按需加载，保留旧回复直达、缺口、控制/授权和独立的原文入口。实时刷新复用头部和 `after_revision` 增量，不重读已加载历史；离开页面停止新读取。以稳定 key 和锚点补偿到达正文后的高度变化。
3. **中心聚合派工与头像状态。** 复用持久的 session 父链和轮次投影。用已确认的身份边，不凭标题、时间或聊天室归属拼派工。图按会话展示，同会话重复唤醒归在一个节点；保留所选窗口内的活动会话和其必要祖先。主节点含该 Agent 的主执行用量，各子节点只合计自身。图的时间范围用明确的截至时间和最近 3 天／2 小时；轮次开始或结束在窗口内即可作为活动，token 取窗口内结束的轮次已报告的 `total_tokens`，标明报告覆盖率。祖先只为路径完整时不被视作窗口内执行。运行中缺失数值继续显示未报告。普通子 Agent 计数从真实 descendant 注册事实（带 child identity）取证；派工边从确切 runtime 父链和委派回执取证，Workflow 以显式 workflow ID 分类。Dreaming 新链接带结构化 maintenance kind，旧的从维护轮次 origin 确认；仅有未分类 link 不因 scope=subagent 或标题就进入普通派工／活跃集合，等精确事实补齐后再纳入。待补齐时不能声称计数完整。
4. **头像只查询一份小状态。** 私聊头和消息头像、群聊 Agent 消息头像共用锚定浮窗。点击时才请求，权限沿用 Work；可编辑配置由现有服务端权限决定。只读返回主 Agent 状态、执行中本轮最后一次工具及其实际开始/结束状态、全量已确认活跃子 Agent 的去重计数、前一页简要名单。等待授权单列；同一个真实子 Agent 多轮只算一个，缺少 Agent 标识时使用确切会话身份。名单展开分页；正在补齐显示同步指示，离线或仍有未确认的活动态时不报实时数。复用 `agent.work.updated` 合并刷新；仅浮窗打开且页面可见时沿用 Work 的 15 s 轻量轮询与连接恢复、回前台刷新。连接／进度是单独的输入，响应不能仅因 revision 未变被丢弃。浮窗关闭取消定时器和读取。完整 Work 和配置复用现有路由，聊天不换页直至用户明确导航。
5. **工具详情复用已有语义视图。** 折叠行用真实名称、现有描述、状态及耗时，展开按调用、结果、来源组织。保留终端、文件、差异、inbox 等专用渲染；结构化通用字段按键值呈现，嵌套值折叠，原始文本保持原样。按确切 call ID 关联相邻回执和原消息，时间及回执状态可见。相同的请求／实发正文只展示一次；不同值分别标记。委派启动与结束保持不同事实。原始参数和结果沿用原生轨迹，未授权或未镜像的原文不因新组件扩大可见范围。
6. **Dreaming 指向独立维护会话。** 主时间线用同一时间排序插入轻量维护条目，显示真实阶段、状态、工具次数、模型与 token。DSH 集成在维护结束时从已打开会话的自有事件投影统计并持久化到 run；复用既有 token 口径，仅在完整边界确认时报告零次／未发起模型请求。通过 `knowledge.facts` 附统计，在 PA 追加版本化的结束投影事件，保留同 session/run ID、原宿主回执与旧投递事实。既有历史 Work 没有该统计时显示「未报告」，从原生轨迹仍可查当时的真实模型与用量；本 unit 不回扫历史原生会话，不添加新的中心至运行时读中转。结束投影只消费当前维护会话自身事件或已持久化的轻量 run 指标，不触发后代重新发现。禁止在日常 Work 首屏、节点启动或每次知识通知遍历历史原生会话补算。现有原生查看器内部不改。
7. **消息级入口合入既有消息操作。** Web 气泡正文和底部移除常驻 Work 链接。桌面悬停／键盘工具条增加一个有 tooltip 和可访问名称的图标，右键菜单及触屏长按／更多操作面板用「查看这条回复的执行记录」。入口沿用已有消息发送者、Global/删除和委派访问谓词，既有真实 `agentId + message_id` 路由不变；操作资格计算覆盖仅附件／交互卡的消息，头像卡是 Agent 整体状态的另一入口。

## 接口与数据流

- Work 主/子摘要、详细过程、控制记录和 exact focus 继续用现有路由。新增主 Work 合并页使用中心全局持久轮次 seq 作为稳定位置。中心独立取当前主执行与其已确认维护的前 N 条（各自按同一个 seq 排序和同一个排他 before_seq 约束），二路合并只返回整体前 N；未返回的余项由相同 cursor 续接。主查询复用 session/seq 索引；维护使用按 root 和 revision 的部分索引读 origin=Dreaming 的启动事实，并关联已持久轮次，不扫描其原生事件。稳定顺序取持久位置，显示真实发生时间。相同时间戳以 seq 排序；晚同步事件按持久位置插入，已读锚点不移动。头部更新与历史游标分离。精确消息锚点为独立补充，保留旧回复按真实发信身份直达；锚点与连续页不相邻时沿用缺口提示，普通游标逐步补齐。其他关联目录和旧客户端仍走既有分页。
- 自动过程预览走 `items?view=preview`，`after_revision` 使用同一预览口径。大项写入中心投影时在同事务生成 ≤4 KiB 的预览侧表，使用 item ID + revision 关联，级联删除；既有短项在 SQL 用 `octet_length(payload)` 限制后才读取 JSON。旧长项只有轻量身份、类型及「加载原文」，查询不把原 payload 送进主循环；单个用户显式展开才经同权限的 item 身份读原内容。原文显示由既有大小和传输契约约束；后页和同 seq 的修改按已有增量规则去重，已加载原文仅在当前可见且 revision 有变化时刷新。
- 中心新增 `GET .../work/activity`（头像状态和分页名单）与 `GET .../work/delegation`（窗口、分页图节点与必要祖先、独立用量）。两者只读现有中心投影，复用 `readable()` / Agent 删除拒绝，按当前 viewer 资格检查 Work。返回 scope/revision/同步信号，响应只含需要的身份、展示名、时间、状态、轻量工具标题和聚合数。按已授权根过滤后再取边与聚合，排除被删除或无资格的记录；缓存沿用账号和 Agent 的隔离范围。头像配置资格不从 Work 可读或可发消息推导。
- 头像聚合使用最新轮次中的活动投影及只覆盖运行中、等待授权、未知态的索引，按已授权根和真实身份归并；可用同一 SQLite 快照分别算计数与名单。派工范围通过按根、事件类型及时间的覆盖索引取得轮次开始/结束候选，再使用有界列的 turn 摘要和精确会话/父边索引；不读原始工具事件 payload，历史之外仅查活动集合及祖先。新图读取按节点分页，前端只画首批 24 个活动会话及已选路径，展开才读后续节点，完整聚合由中心按窗口查询，不用页面节点凑总量。最新工具走当前主轮次的工具序号索引，不跨轮或遍历历史。
- 相关投影新字段向后兼容，既有 iOS 及旧节点仍使用原 Work 路径。删除/撤权用原检查，新增索引在正常 schema 初始化注册；验收记录大历史启动/索引安装代价。无一次性历史重写或生产数据迁移。对模型可见信息无变化，读取或修正投影不进入 prompt。

### 隔离验收前置

按 [固定日常模板](../../development/worktree-runtime.md#固定日常验收模板) 使用 `scripts/e2e-up.sh --profile daily --wt <unit worktree>`。在本轮副本以 owner nano 打开 P 的私聊和研发日常群，用产品入口生成有精确投递关系的回复和两层派工。只在隔离 IM 另建普通公司成员及待定／外部身份，按真实登录与空间资格验证 Work 可读但配置不可写、私有 PA 不可读、来源权限独立。Dreaming 用隔离 Gateway 实际触发两个阶段并检查宿主回执和指标；额外注入只有进度声明的同步恢复、离线重连和旧缺失指标，用真实中心 API 观察，标注合成与模型生成来源。交接 `.e2e-daily.json`、角色、入口、受验提交和范围，结束走隔离回收。

基线夹具（15,000 轮、10 万关联执行、15,000 个工具项含 2 MiB 原文）已用 Node 24.22.1 在 Air 的隔离真实 Fastify / SQLite 上复测。冷首请求 5.82 ms，21 个热请求中位 0.64 ms、P95 0.86 ms，首屏摘要 5,831 B；直接读取当前首批正文 2,139,264 B、单次 9.12 ms。只有 loopback HTTP，不是浏览器渲染或生产延迟。验收在同夹具再测候选，同时增加窗口内密集活动和高活跃并发样本，记录索引候选、图节点数、字节和事件循环；复核 Gateway perf-751 旧目录随单次维护通知不扫描。覆盖预览初页和原 seq 大结果更新、两种源密度反转、同时间戳、无新事件同步转完成、非 owner 离线/恢复与关闭停止刷新。
