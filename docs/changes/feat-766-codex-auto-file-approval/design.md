# feat-766 设计

## 文件审批

Nano 的工具执行前审批拥有直接放行决策。沿用现有普通文件判定中的路径归属、受保护位置和自定义规则条件，保留原 CC 入口的行为。Codex 仅在 Auto 已启用且原生 pre-execute 已允许时，对 `edit` / `write` 检查实际 cwd、系统 `tmpdir()` 和平台提供的 `/tmp`。候选路径和真实目标须落在允许的根内且通过普通文件检查。临时根包含 /tmp、macOS 的 /private/tmp 和 tmpdir 的原始与真实拼写。Codex 将含父目录段的请求保留给模型，以免词法归一化改变 DSH 的目标。使用 native realpath 解析实际大小写及新文件最近存在的祖先，拒绝悬空链接及非普通文件。自定义 environment 与自定义审批规则一样保留模型判定。Codex 分流在收集审核证据及发起模型请求前完成，沿用已有 `workspace_file` 审计来源。原生工具保留观察与写入约束。当前 Nano 执行权限可以是 full access，shell 审批继续执行原逻辑。

## 子会话恢复

`NativeHistory.configuration` 由 DSH 创建或恢复 Agent 的公开生命周期回调调用。普通 continuable 子会话由 DSH 恢复后，先按原逻辑选定执行配置，再用所属 Agent 当前模板的完整 approval 替换执行副本的审批配置，覆盖存在、缺失和版本失配。首次委派及单次 Workflow、后台维护和聊天 fork 沿用原配置选择。已加载 Agent 的配置变更继续走现有 idle 后更新路径。审查请求消费当前审批规则和模型，原委派证据、会话身份与已有快照继续由各自所有者维护。独立审核上下文的配置指纹已纳入审批字段，会按实际新配置重建。无需迁移历史状态。
