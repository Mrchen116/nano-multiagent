## 用户场景

S1：用户让一个普通执行 Agent 查询多份材料、筛选记录并生成结果。Agent 能组合查询和处理数据，最终保留任务需要的答案、原始出处和未完成项。用户不需要把任务改写成程序，也不需要重复接收中间大结果。

S2：用户继续通过 Global/PA 派出执行者。执行者能完成原任务并将结果交回主 Agent；切换不会使它代替主 Agent 收取聊天或对外发送。Global/PA 主会话和审核流程继续工作。Dreaming 整合默认用 PTC 读写记忆、回查来源，提炼仍阅读宿主给定的材料并输出摘要。

S3：任务中既有读取，也有写文件、运行命令或对外操作。用户原来的权限与审批策略继续约束这些实际效果。拒绝不会因换一种调用形式而失效；执行过一部分的任务不能在重试时被描述成全部没执行。

S4：执行者压缩中间输出后，用户随后要求解释做过什么，或后台整理长期经验。仍可追到实际执行的操作和结果，区分原始依据、助手整理、失败和未执行部分；不会把不完整材料说成完整经历。

S5：执行出现错误、任务取消、进程重启，或者用户从配置文件改回 native。任务保留已有真实成果与记录，后续执行能恢复原调用方式；不得通过自动重跑含副作用程序制造重复操作。用户可用同等任务结果比较 native 与 PTC 的实际消耗与时间。

## 验收标准

### Requirement: 普通任务默认使用程序化工具编排

#### Scenario: 多来源查询与结果筛选（S1）
- **WHEN** 用户在具备通用执行能力的普通执行 Agent 上提交多来源查询、筛选和汇总任务
- **THEN** 得到符合任务要求的结果、必要出处和缺失说明，不要求用户手写调用程序。
- **AND** 不以省略必要依据或降低完整性换取更小的输出。

#### Scenario: 默认范围与例外（S2）
- **WHEN** 节点未显式配置 native 回退
- **THEN** 普通执行 Agent 和 Dreaming 整合阶段默认采用 PTC，不要求逐 Agent 开启；Global/PA 主会话、Dreaming 提炼和审核器保持既有模式。
- **AND** 未获得通用代码执行能力的受限 Agent 不因此获得该能力；不增加 IM 网页设置项。

#### Scenario: Dreaming 仅整合阶段改变工具调用方式（S2、S4）
- **WHEN** Dreaming 提炼任务经历并整合正式记忆
- **THEN** 提炼仍直接阅读宿主提供的选定轨迹、输出原有摘要结构；整合使用 PTC 编排现有来源回查、文件和 Bash 能力。
- **AND** 原有来源范围、正式仓写入约束、单写者、前台执行、宿主 Git 核验和失败恢复保持；不新增轨迹分析系统或持久 REPL。

### Requirement: 委派结果继续由原有负责人交付

#### Scenario: Global/PA 委派普通执行者（S2）
- **WHEN** 主 Agent 派出默认使用 PTC 的普通执行者完成任务
- **THEN** 执行者将结果和未完成项交回主 Agent，由原负责人处理对外回复。
- **AND** 执行者不能因为调用方式变化而获得主 Agent 专属操作权限。

### Requirement: 程序化执行保留实际动作的权限约束

#### Scenario: 审批与拒绝（S3）
- **WHEN** 程序请求有副作用、需审核或已经被拒绝的操作
- **THEN** 适用的自动审核、人工批准或无人值守拒绝继续生效；拒绝的操作不产生对应副作用。
- **AND** 不因使用代码直接操作或包装工具而绕过原有授权边界；后台执行者不新增向用户索取批准的通道。

#### Scenario: 权限设置和审核异常（S3）
- **WHEN** Auto 被关闭、用户明确选择跳过权限，或审核模型不可用
- **THEN** 分别遵循现有人工审批、显式跳过和审核故障处理规则，不把 PTC 当作新的免审授权。

### Requirement: 原始操作依据可恢复且不改变其来源身份

#### Scenario: 中间结果未全部交给执行模型（S4）
- **WHEN** 执行者筛选输出后，后台提炼经验或根据来源引用回查
- **THEN** 可在该次任务已获准的历史范围内取得原始操作、参数、结果和错误状态，助手汇总不会变成用户授权或原始工具证据。
- **AND** 超出范围或不能取得的原文明确不可用；不扩展实时聊天读取权限。

### Requirement: 停止、恢复与配置回退不重复已完成操作

#### Scenario: 部分完成后的取消或恢复（S5）
- **WHEN** 一段执行在产生部分结果后被取消、超时或遇到进程重启
- **THEN** 已完成、失败及未知部分保持可区分；后续继续先核对实际结果，不自动整体重跑。

#### Scenario: 配置文件回退（S5）
- **WHEN** 用户在配置文件中为指定 owner 显式选择 native
- **THEN** 普通执行会话在安全边界恢复 native；Dreaming 整合按新配置启动后续批次，当前批次的完成或取消沿用既有规则。保留会话、文件和历史依据，不改其他 owner 的设置。

### Requirement: 效率结论以同等任务质量的对照为依据

#### Scenario: 核对效率收益（S1、S5）
- **WHEN** 交付本期验证结果
- **THEN** 同时提供同条件普通调用与 PTC 的任务正确性、证据完整性、总消耗和耗时对照，计入相关审核开销。
- **AND** 如实报告无收益或回归，不因此擅自改回默认 native，也不扩大到例外 Agent；不得仅用工具调用次数减少宣称省 token 或费用。

## 范围与非目标

在范围：普通独立执行 Agent 和 Global/PA 的非 fork 普通 worker 默认 PTC；Dreaming 整合默认 PTC、提炼模式及能力不变；配置文件 native 回退；审核边界；原生子调用证据进入经验采集和受控回查；取消、重启；隔离环境代表性对照。

非目标：不分角色全量切换；Global/PA 主会话切换；fork 前缀契约调整；Workflow 的程序或冻结配置子执行改造；Dreaming 提炼或审核器自身 PTC 化；无工具 LLM 分类器改造；新增轨迹分析系统；持久 REPL/Computer Use；IM 网页设置选项；生产切换及自动部署。

本期有用户面：同一任务的结果质量、权限处理、委派交付、记忆整合和可恢复性。因此不能只验模型看到的工具名称；具体接口及运行证据见 [design.md](design.md)。
