# feat-770: 普通执行 Agent 的 PTC 试用与兼容边界

## 原始需求

> 我想把我们的agent的模式切换到PTC mode。DSH本来就支持。然后因为codex也默认是。而且codex的computer use 也是用的连续PTC？从而很省token？所以我想切换。你帮我预调研一下，并告诉我我们是应该全部切还是说有的agent不能切。因为我们有dreaming，有auto mode做工具审核的agent，等等。所以我不确定是否应该都切。另外我也不确定codex是不是都是PTC。

> 那就按你的建议，先把普通执行 Agent 切 PTC 的方案整理出来

## 澄清记录

2026-11-15：用户接受上一轮分类型推进的建议，要求先整理普通执行 Agent 的方案；没有授权实施、生产配置切换或部署。

Agent 解读：本 unit 提供普通执行 Agent 的可选择 PTC 路径，首先验证批量工具编排、权限不变、经验可追溯和实际收益。Global/PA 主 Agent、Dreaming、审核器保留原模式，Computer Use 持久环境不在本期。首次上线保持未选择者的既有行为，不凭 PTC 名称宣称节省比例。具体首批资格、调用方式和技术取舍由 design 明确；这些是方案选择，不冒充用户原话。

## 用户场景

S1：用户让一个普通执行 Agent 查询多份材料、筛选记录并生成结果。Agent 能组合查询和处理数据，最终保留任务需要的答案、原始出处和未完成项。用户不需要把任务改写成程序，也不需要重复接收中间大结果。

S2：用户继续通过 Global/PA 派出执行者。执行者能完成原任务并将结果交回主 Agent；切换不会使它代替主 Agent 收取聊天或对外发送。未参加试用的 Agent、Dreaming 和审核流程继续工作。

S3：任务中既有读取，也有写文件、运行命令或对外操作。用户原来的权限与审批策略继续约束这些实际效果。拒绝不会因换一种调用形式而失效；执行过一部分的任务不能在重试时被描述成全部没执行。

S4：执行者压缩中间输出后，用户随后要求解释做过什么，或后台整理长期经验。仍可追到实际执行的操作和结果，区分原始依据、助手整理、失败和未执行部分；不会把不完整材料说成完整经历。

S5：试用出现错误、任务取消、进程重启，或者用户决定停止试用。任务保留已有真实成果与记录，后续执行能恢复原调用方式；不得通过自动重跑含副作用程序制造重复操作。用户可用同等任务结果比较试用前后的实际消耗与时间。

## 验收标准

### Requirement: 普通任务可以选择程序化工具编排

#### Scenario: 多来源查询与结果筛选（S1）
- **WHEN** 用户在已选试用的普通执行 Agent 上提交多来源查询、筛选和汇总任务
- **THEN** 得到符合任务要求的结果、必要出处和缺失说明，不要求用户手写调用程序。
- **AND** 不以省略必要依据或降低完整性换取更小的输出。

#### Scenario: 未选对象保持既有工作方式（S2）
- **WHEN** 同一节点上的选定执行者开始试用
- **THEN** 未选 Agent、Global/PA 主 Agent、Dreaming 和审核器的工作职责保持不变。
- **AND** 未获得通用代码执行能力的受限 Agent 不因试用而获得该能力。

### Requirement: 委派结果继续由原有负责人交付

#### Scenario: Global/PA 委派普通执行者（S2）
- **WHEN** 主 Agent 派出已选试用的普通执行者完成任务
- **THEN** 执行者将结果和未完成项交回主 Agent，由原负责人处理对外回复。
- **AND** 执行者不能因为调用方式变化而获得主 Agent 专属操作权限。

### Requirement: 程序化执行保留实际动作的权限约束

#### Scenario: 审批与拒绝（S3）
- **WHEN** 程序请求有副作用、需审核或已经被拒绝的操作
- **THEN** 适用的自动审核、人工批准或无人值守拒绝继续生效；拒绝的操作不产生对应副作用。
- **AND** 不因使用代码直接操作或包装工具而绕过原有授权边界；后台执行者不新增向用户索取批准的通道。

#### Scenario: 权限设置和审核异常（S3）
- **WHEN** Auto 被关闭、用户明确选择跳过权限，或审核模型不可用
- **THEN** 分别遵循现有人工审批、显式跳过和审核故障处理规则，不把 PTC 当作新的免审授权。

### Requirement: 原始操作依据可恢复且不改变其来源身份

#### Scenario: 中间结果未全部交给执行模型（S4）
- **WHEN** 执行者筛选输出后，后台提炼经验或根据来源引用回查
- **THEN** 可在该次任务已获准的历史范围内取得原始操作、参数、结果和错误状态，助手汇总不会变成用户授权或原始工具证据。
- **AND** 超出范围或不能取得的原文明确不可用；不扩展实时聊天读取权限。

### Requirement: 停止、恢复与退出试用不重复已完成操作

#### Scenario: 部分完成后的取消或恢复（S5）
- **WHEN** 一段执行在产生部分结果后被取消、超时或遇到进程重启
- **THEN** 已完成、失败及未知部分保持可区分；后续继续先核对实际结果，不自动整体重跑。

#### Scenario: 退出试用（S5）
- **WHEN** 用户关闭选定执行者的试用
- **THEN** 在当前执行安全结束后恢复既有调用方式，保留会话、文件和历史依据，不改其他 Agent 的设置。

### Requirement: 效率结论以同等任务质量的对照为依据

#### Scenario: 核对试用收益（S1、S5）
- **WHEN** 交付本期试用结果
- **THEN** 同时提供同条件普通调用与 PTC 的任务正确性、证据完整性、总消耗和耗时对照，计入相关审核开销。
- **AND** 收益不足或出现回归时保持显式试用，不自动扩大范围；不得仅用工具调用次数减少宣称省 token 或费用。

## 范围与非目标

在范围：普通独立执行 Agent 和 Global/PA 的非 fork 普通 worker 的选择性试用；审核边界；原生子调用证据进入经验采集和受控回查；取消、重启、退出试用；隔离环境代表性对照。

非目标：全局强制切换；Global/PA 主会话切换；fork 前缀契约调整；Workflow 的程序或冻结配置子执行改造；Dreaming 或审核器自身 PTC 化；无工具 LLM 分类器改造；持久 REPL/Computer Use；新设置界面；生产切换及自动部署。

本期有用户面：同一任务的结果质量、权限处理、委派交付和可恢复性。因此不能只验模型看到的工具名称；具体接口及运行证据见 [design.md](design.md)。
