## 原始需求

> 那就把轮次和token都改成是累计的，而不是所选的时间的，时间只是过滤期间活跃的agent是哪些。理解吗

## 澄清记录

此前用户询问“如果改为同agent所有token会遭成很大负担吗”。对话中的建议是从已保存轮次回填，之后增量更新。禅自身的口径跨新旧主会话，派工自身各算各的。

## 用户场景

用户用活动范围查看近期派工，想同时知道每个 Agent 自己已经执行了多少轮、累计用了多少 token。切换范围时，一个仍出现的节点应继续显示同一份历史累计。

## 验收标准

### Requirement: 派工活动筛选与历史累计独立

#### Scenario: 切换活动范围
- **WHEN** 用户切换「最近 2 小时」和「最近 3 天」
- **THEN** 对应窗口内活动的派工会话及必要路径可见，主 Agent 保留；两次都可见的卡片显示各自同一历史累计。

#### Scenario: 查看历史累计
- **WHEN** 用户查看主 Agent 和各派工节点
- **THEN** 主 Agent 累计各代主会话已结束轮次，派工节点累计自身会话已结束轮次。
- **AND** token 加总已报告的轮次，部分报告时显示覆盖比例。没有报告时显示「Token 未报告」，真正报告的 0 可见。
- **AND** 仅作派工路径的祖先也显示自身历史累计及路径说明。

## 范围与非目标

- 范围为 Web Agent 工作页的派工图。累计从可用的已保存 Work 记录计算。
- 模型计费、其他页面的指标及原生客户端在范围之外。
