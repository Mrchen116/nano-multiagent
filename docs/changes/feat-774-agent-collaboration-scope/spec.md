# feat-774 · Agent 协作范围与消息提醒

## 原始需求

> 现在我们的agent有个问题，包括pa获得我的对话，包括agent自己收到消息，太频繁了。只要有消息都会在下一轮llm请求收到。我觉得应该分级分类。\
> \
> 个人消息和@消息，被引用自己消息的消息，这些是高优先级的，应该还是现在这样，但是其他群消息，应该累计到下一次收到高优消息的时候，或者定期，比如10分钟。通过这两个机制来做到token消耗和实时性的平衡。理解不？澄清需求

## 用户场景

创建者选「仅限本人」时，可以在一对一私聊中使用自己的 Agent。选「团队协作」时，同事也能直接找它。全局 Agent 在多个群工作，A 群持续讨论时，B 群的一条直接提问可以让它同时看到待处理的消息。单会话 Agent 在各自聊天中处理该聊天的背景。

PA 还会观察主人允许的聊天。别人找主人时，PA 可以及时了解情况；主人在群里与同事闲聊时，PA 可以稍后了解。消息实际发给谁、PA 以什么身份看到，关系到它如何理解消息。

## 验收标准

### Requirement: 每个 Agent 有一个协作范围

#### Scenario: 创建与编辑

- **WHEN** 用户通过支持的入口创建 Agent，或编辑现有 Agent 的收件偏好
- **THEN** 协作范围提供「仅限本人」和「团队协作」两个选择，取代旧群回复策略；新建默认「团队协作」，十分钟为统一批次间隔。

#### Scenario: 私人使用

- **WHEN** 创建者私聊「仅限本人」的 Agent，其他人也向它发私聊，或有人在群里 @ 它、引用它（包括创建者本人）
- **THEN** 只有创建者直接发给该 Agent 的私聊作为新消息送达。其他输入不会出现在其收件内容或提醒中。若它是 PA，通过主人身份旁观的聊天也不送达。

### Requirement: 团队协作按收件对象与紧迫程度通知

#### Scenario: 直接找 Agent

- **WHEN** 有人私聊团队 Agent，或在群里实际 @ 它、回复或引用它发出的消息
- **THEN** 空闲时可及时开始处理，忙时在下一次模型请求前得知，不打断已经开始的请求或工具执行。

#### Scenario: 群里连续讨论，另一群有人提问

- **WHEN** A 群积累多条普通消息，全局 Agent 在十分钟内收到 B 群的一条高优消息
- **THEN** A 群消息即时可读，积累期间即使 Agent 连续工作也不逐条主动提醒。高优消息到达后，一次提醒同时呈现 B 群请求和 A 群积压，原到期时间不重复提醒已带出的这一批。
- **AND** 单会话 Agent 以原聊天为范围处理积压，一个聊天的正文不进入另一个聊天。

#### Scenario: 等到批次到期

- **WHEN** 第一条待提醒的普通消息到达后持续有新消息，期间没有高优消息
- **THEN** 连续来信不推迟十分钟期限。到点时有积压，空闲 Agent 被唤醒一次，忙碌 Agent 在下一次模型请求前收到一次合并提醒。没有新增待提醒内容时保持安静。

#### Scenario: 有人找 PA 的主人

- **WHEN** 在获准观察的聊天中，别人私聊主人、@ 主人或回复或引用主人发出的消息
- **THEN** 团队协作的 PA 按高优通知，保留消息发给主人及 PA 的观察身份。主人主动发给他人的普通消息按背景积累。提醒本身不构成主人交办或授权。

### Requirement: 存量 Agent 一次性过渡

#### Scenario: 部署新版本

- **WHEN** 部署人员按本 unit [部署提示词](deployment-prompt.md) 迁移升级前的 Agent
- **THEN** 这些 Agent 的协作范围统一为「团队协作」，之后创建者可以改成「仅限本人」。后续启动或部署保留用户已作的选择。

## 范围

覆盖 PA 与普通 Agent 的聊天收件、提醒，以及创建与编辑入口。沿用既有聊天访问权限、PA 观察来源排除及发言授权。旧群策略转换仅由部署人员一次性执行。PA 群聊逐条输入审核成本单独跟踪。[Issue #533](https://github.com/Mrchen116/nano-multiagent/issues/533)
