# gateway/global-agent Specification (delta for feat-774)

## MODIFIED Requirements

### Requirement: 依据配置接收信号，并自主安排读取

#### Scenario: 忙碌期间有其他聊天的新请求
- **GIVEN** 全局主 Agent 正在处理工作
- **WHEN** 其他聊天发来符合接收条件的新请求
- **THEN** 新请求保留供其读取，不因收到请求就强制中断当前工作
- **AND** 范围内直接找 Agent 的新输入或已到期的普通消息在主 Agent 下一次模型请求前提供 Inbox 系统提醒，不必等当前任务结束；已开始的模型请求和工具执行不被硬中断
- **AND** 下一次模型请求前积累的多条应提醒的新输入合并为至多一条新的 Inbox 系统提醒；各条消息正文仍完整保留供 Inbox 读取
- **AND** 合并提醒直接提供各未读会话的名称、私聊/群聊类型、可读取引用、未读消息数和实际 @ 本 Agent 的消息数；计数来自未读消息元数据，不把私聊、回复或找主人的消息等同于 @ 本 Agent
- **AND** 提醒与主动 check 逐会话展示本次可见未读消息中最晚的原始发送时间，时间明确时按新到旧排列，未知时间不冒充新消息。
- **AND** 提醒进入模型上下文后，再到达的新输入可以在后续模型请求中触发新提醒
- **AND** 提醒不包含新消息正文或代表真人授权，正文与来源仍通过 Inbox 主动读取；原发送前复核继续生效
- **AND** Agent 可直接使用提醒中的会话引用按需 read，或继续当前工作；check 仅在需要刷新摘要时主动调用，不是读取正文的前置要求
- **AND** 用户能在工作视图中查看其后续读取和处理过程

#### Scenario: 空闲时收到符合触发条件的输入
- **GIVEN** 全局主 Agent 空闲
- **WHEN** 收到符合该 Agent 触发配置的输入
- **THEN** 它能开始处理，不要求用户额外操作才能唤醒

#### Scenario: 普通群聊更新遵循各 Agent 配置
- **WHEN** 群内有未提及某个全局 Agent 的普通更新
- **THEN** 团队协作下立即可读，遇到下一条高优消息或自首条积压起十分钟，先到者触发一次合并提醒。无新增不唤醒，持续来信不延后期限。仅限本人时不收群消息
- **AND** PA 自己参与的群聊同样遵守该规则。

#### Scenario: PA 通过主人观察未参与聊天
- **WHEN** PA 通过主人权限接收自己未参与聊天的更新
- **THEN** 它们按 [personal-agent](personal-agent.md) 的主人目标和背景规则保存和通知，保留旁观身份；主人直接请求仍及时通知且可读取相关背景。
