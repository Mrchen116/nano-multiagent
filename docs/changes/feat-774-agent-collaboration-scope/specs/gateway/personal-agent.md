# gateway/personal-agent Specification (delta for feat-774)

## MODIFIED Requirements

### Requirement: PA 双身份消息保留可信来源

以下自动收件限于当前协作范围；主动历史查询继续受来源访问控制。

#### Scenario: 合并历史与新消息
- **WHEN** 查询或接收主人授权聊天和 PA 自己聊天的消息
- **THEN** 当前权限有效的两者并集可见，重复消息只处理一次，主人发出的消息也摄入，PA 自发消息不引起循环。
- **AND** 保留真实发送者、主人身份、原会话类型、渠道、时间、内容以及 PA 参与或观察该会话的事实，不预先将主人原话分类为指令或事实。

#### Scenario: 同一主人在不同聊天发言
- **WHEN** 主人在 PA 私聊、共同群聊和 PA 未参与的聊天中发言
- **THEN** 主人身份一致；实际是否向 PA 交办由原话和对话上下文判断，其他人自称主人不能改变身份。

#### Scenario: 观察者接入不等于直接请求
- **WHEN** PA 通过主人权限看到自己未参与的聊天
- **THEN** Inbox 来源与读取结果的会话上下文明确观察关系，主人和他人的收发均可读，但不自动成为 PA 的任务、控制命令或对外发送授权。
- **AND** 普通观察内容不被当作对 PA 的直接请求进行逐条请求检查或自动向原聊天发送拒绝警告；当前来源访问和对外披露约束继续生效。

### Requirement: PA 观察聊天即时可读并按十分钟合并通知

#### Scenario: 首批与后续节奏
- **WHEN** 团队协作下，获准观察的聊天有新的普通背景消息
- **THEN** 消息立即持久保存并可读取，首批从第一条积累消息起十分钟后通知；后续按下一批首条积压起算；有高优输入时提前合并，连续输入不推迟截止。
- **AND** 到点无需下一条来信；无新增未读不空通知。
- **AND** 提醒直接提供待读会话名称、可读取引用、未读数、实际 @ 本 PA 的消息数及 participant / observer 关系；可直接按需 read，check 仅用于主动刷新，摘要本身不消费正文或授予任务。

#### Scenario: 忙碌与重启
- **WHEN** 背景期限已到但 PA 正忙，或节点在等待期间重启
- **THEN** 保留累计消息与已确定期限，空闲且可用时唤醒；忙碌时在下一次模型请求前合并通知，不硬中断当前工作、不逐批补发过时通知、不从重启重新计十分钟。

#### Scenario: 主人提前来信
- **WHEN** 主人直接请求，或他人私聊主人、实际 @ 主人、回复或引用主人的消息
- **THEN** 及时合并提醒并允许立即读取积压；主人主动与别人聊天属于背景。提醒区分消息发给谁与 PA 的观察身份，已带出的同一批不在原到期时重复提醒。

#### Scenario: 提醒与消费独立
- **WHEN** 已提醒但尚未完整持久摄取消息
- **THEN** 消息仍未读；来源撤销后停止新读取与通知，不因曾经提醒而标成完成。
