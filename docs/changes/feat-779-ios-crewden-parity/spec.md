# feat-779 · Crewden iPhone 体验更新与登录后能力对齐

## 原始需求

> 我们web 上做了大量的前端提升，以及功能更新。但是ios版本很久没更新了。需要更新前端更现代化，更活泼。同时同步新的能力过去。先做代码仓研究吧

## 澄清记录

问：「这次 iOS 更新，你希望做到『日常使用完整』，还是『登录后 Web 能做的事，手机也都能做』？」选项 B 包含日常使用，也覆盖 PA 的观察范围与联系人限制、完整派工关系、用量和详细执行轨迹。同一用户应能完成同一任务，交互按 iPhone 重新组织。

用户原话：「B吧。」

问：只涉及 Web Work 中 DSH「原生轨迹」详细查看器，手机要复用还是重做？用户先问「这个指原生轨迹还是我们的」，确认对象后答：「这个手机上还真可以没有」。

关于手机界面的视觉参照，用户提供了微信聊天长按截图（会话附件 Photo 1.jpg，仅作交互参考），并说明：「你把web的缩窄就是基本好看的了」「你重做的部分要好看，更符合用户交互才有必要啊」「所以其实ios的需求有必要做原型吗，你的原型还是html的，会和实际ios有差距」。

作者解读：iPhone 可省去 DSH 原生轨迹查看器。Crewden 自己的 Work 仍覆盖回复定位、工作记录、父子执行、派工与用量。先交付用户每天都会走的路径，整个变更按 B 验收。沿用现有 Crewden Web 窄屏的视觉与信息层级，平台特有的交互改进在实际 SwiftUI 界面验证。下文以调研时的 `origin/develop@b405a96a7` 为能力对照基线。

## 现状依据

- [Web 首次使用与角色形象](../archive/feat-773-crewden-first-use/spec.md)覆盖了工作区，未包含原生 UI。Web 的[角色头像](../../../src/IM/frontend/src/features/chat/components/assistant-portrait.tsx)区分 PA 和专业 Agent，支持选定造型和稳定默认形象。[原生共用头像](../../../src/IM/ios/NanoIM/UI/CommonViews.swift)与[原生现行契约](../../specs/im/ios-client.md)仍使用名称缩写与固定配色。本次需更新 Agent 身份展示约定，保留私聊改名后的身份连续性。
- iOS 已有[PA 绑定读取](../../../src/IM/ios/NanoIM/Features/Agents/AgentsView.swift)、[设备绑定](../../../src/IM/ios/NanoIM/Features/Me/SettingsBindingView.swift)与[模型管理](../../../src/IM/ios/NanoIM/Features/Me/ModelServicesView.swift)。Web 还把这些步骤串到[创建、恢复与首次聊天](../../../src/IM/frontend/src/features/onboarding/onboarding-page.tsx)，并提供 [PA 专属管理](../../../src/IM/frontend/src/features/personal-agent/personal-agent-settings.tsx)。
- iOS 的[聊天列表](../../../src/IM/ios/NanoIM/Features/Chat/ChatListView.swift)按标题和末条预览筛选，[消息菜单](../../../src/IM/ios/NanoIM/Features/Chat/ConversationView.swift)有复制和分支。[Web 聊天](../../../src/IM/frontend/src/features/chat/chat-api.ts)另支持历史正文搜索与引用回复。
- [原生 Work](../../../src/IM/ios/NanoIM/Features/Agents/AgentWorkView.swift)已有执行轮次、工具详情和关联子执行。[Web Work](../../../src/IM/frontend/src/features/settings/agents/agent-work-panel.tsx)还提供从具体回复定位、合并时间线、派工关系和轨迹查看。此处的“轨迹”指 Agent 的执行记录。

## 用户场景

1. 新用户从 iPhone 注册并完成准入，有电脑和模型服务后创建自己的 PA。中途切走再回来，能继续当前步骤；第一次进入私聊能从一个任务草稿开始。老用户打开手机则直接认出自己在 Web 建好的团队并继续昨天的对话。
2. 群里有人问到过去的决定，用户搜索原话、检查前后文、引用并回复。随后点开 Agent 的头像确认它在忙什么，再从某一条回复查看产生这次交付的工作。
3. 负责人需要追查委派给哪个子 Agent、用了多少资源、结果在哪里，也需要管理任务、人员和设备。主人可在手机上调整 PA 对聊天的观察范围、处理风险提醒；普通成员和只读观察者仍按各自权限工作。

## 验收标准

### Requirement: 主要页面体现活泼亲和的 Crewden 身份，适合在 iPhone 上连续使用

#### Scenario: 从登录到日常工作
- **WHEN** 用户从应用图标、登录或注册进入聊天，依次打开任务、Agent、Work 和我的
- **THEN** 品牌名称与视觉表达连贯。用户能辨认当前页面、主要内容和下一步操作；单手往返列表与详情、调出键盘或展开长内容时，主要操作仍可达。

#### Scenario: 跨设备辨认同一个助手
- **WHEN** 用户在任一端创建 PA 或专业 Agent 并选择形象，再在另一端查看列表、私聊、群消息与成员详情
- **THEN** 各处能认出同一个助手，也能区分真人、PA 和专业 Agent。已有助手有稳定默认形象，重命名会话后仍能认出对方，PA 代发仍可识别。

### Requirement: 从首次设置到交办可以在手机上连续完成

#### Scenario: 首次设置或中途返回
- **WHEN** 获准用户从空账号开始，连接执行任务的电脑、配置模型、命名并创建 PA，或中途离开后回来
- **THEN** 能看见已完成的步骤、下一步由手机还是电脑操作，以及如何继续。结果未确认时可以恢复，同一次创建只得到一个 PA；已有 PA 的用户能直接进入原私聊。

#### Scenario: 从空白私聊开始合作
- **WHEN** 主人第一次打开自己的 PA 或 Global Agent 的空白对话
- **THEN** 能按角色获得相应的开始提示，查看适用的合作约定引导，编辑草稿并自行决定是否发送。已有输入得到保留，开始聊天后正文优先。

### Requirement: 聊天支持找回原文、引用回复和连续阅读

#### Scenario: 从旧消息继续讨论
- **WHEN** 用户搜索一条已不在会话预览中的历史消息，点开命中结果、引用回复，再从引用返回
- **THEN** 能看到有权阅读的原文和相邻消息；双方在 Web 和手机上看到一致的引用对象。原文不可访问时有明确反馈。

#### Scenario: 已有会话在更新后继续使用
- **WHEN** 老用户离线打开有缓存的聊天，恢复联网后上翻历史、编辑交互卡片或处理未确认发送
- **THEN** 可先读原有内容；恢复后阅读位置、按会话保存的草稿、消息回执、附件与交互卡片仍可用。待确认发送可核对、显式重试，访问被撤销的内容按现行规则清理。

### Requirement: 从聊天看当前活动，并追到某次交付的完整 Work

#### Scenario: 区分现在的活动和历史回复
- **WHEN** 用户查看 Global Agent 头像，再从一条较早回复打开工作记录
- **THEN** 头像说明当前已知活动；回复入口定位产生该条回复的执行。可以检查此前和此后的工作，并返回原聊天的阅读位置。

#### Scenario: 查派工、用量和工作明细
- **WHEN** 有查看权限的用户检查含子执行的工作，沿派工关系打开某次执行并返回父级
- **THEN** 能查到对应时间线、父子关系、已报告用量与 Crewden 工作记录中的执行明细。节点离线、用量未报告或记录仍在补齐时，已保存部分仍可读，各处清楚说明哪些信息有待确认。

### Requirement: 登录后管理与协作任务达到同一账号在 Web 上的能力范围

#### Scenario: 主人管理自己的 PA
- **WHEN** 主人更改 PA 观察的会话、处理风险事件，或查看和解除联系人限制
- **THEN** 在手机上能看懂作用对象、作出与 Web 相同的选择，重新进入任一端可核对结果。提交失败时清楚说明结果，保留恢复入口。

#### Scenario: 从手机完成工作区任务
- **WHEN** 用户按下表进入对应业务，并以有权或只读身份执行同一项 Web 任务
- **THEN** iPhone 可找到相应入口，读到相同业务含义，完成允许的操作并在两端核对结果。只读、权限不足或设备离线时显示实际可用的操作与状态。下表覆盖整个范围，已具备的能力可沿用。

| 业务范围 | 用户可核对的任务 |
|---|---|
| 聊天与协作 | 发现联系人和公开群、创建和管理会话、阅读只读协作网、收发与定位消息、操作附件与交互卡片、查看回执和授权请求、使用命令与会话操作 |
| 任务 | 从会话或任务页查看任务结构、负责人及状态，按权限创建、编辑、交办，并返回相关讨论 |
| PA 与专业 Agent | 创建与辨认助手，维护角色约定、协作范围、模型及能力、Skills、定时任务和外部通道，查看实际生效状态，按权限管理生命周期 |
| Work | 从聊天和 Agent 页查活动、工作记录、派工、用量及关联来源 |
| 我的与工作区管理 | 管理账号与语言、成员与公司策略，连接和管理电脑与模型服务，查看设置结果、设备更新和恢复入口 |

完整能力按基线的 [Web 路由](../../../src/IM/frontend/src/app/router.tsx)、各页面可用操作及 [IM 业务契约](../../specs/im/spec.md)逐项核对。表中列的是用户任务，同一业务内的低频操作也在范围内。

## 范围与非目标

- 覆盖整个原生 App 的视觉更新，以及基线 Web 登录后的业务能力，DSH 原生轨迹查看器为已确认的例外。保留原生客户端已有的缓存优先、受保护媒体、辅助访问、会话隔离和阅读连续性。
- 手机沿用适合其屏幕和输入方式的导航。桌面多栏布局、鼠标悬停和快捷键可有等价的触屏入口；公共营销网站的整页演示不属于登录后业务。电脑安装与执行仍发生在相应电脑上。
- 本次需求描述产品行为。界面原型、具体实现、构建安装与生产发布安排另行处理。
