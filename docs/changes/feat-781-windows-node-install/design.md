# feat-781 Windows 电脑端安装与运行

对应[已确认的用户场景和七个验收场景](spec.md)。用户从 IM 下载，双击后回原页面连接，继续用浏览器完成账号确认和聊天。小型安装器为当前 Windows 用户准备私有运行环境，首次配置和后续更新复用相同的下载缓存。

## 架构总览与关键决策

1. **按用户安装的小型在线 EXE。** 网页和模型本来就需要联网，首版采用单个原生启动/安装入口，仅内含连接界面、固定协议处理、HTTPS 下载、SHA-256 校验及解包能力。用户双击后会看到「回到原网页，连接这台电脑」；网页唤起并确认来源后，原生窗口显示准备进度或可重试的失败原因。一次下载完整离线包会把低频使用的大依赖也提前交给每位用户。在线方式仍要对首次聊天的总传输量负责。[微软对小型在线安装器的说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution) · [按用户安装](https://jrsoftware.org/inno-setup/documentation/topic_setup_privilegesrequired.htm)
2. **同一份 EXE 服务多个 IM。** Inno Setup 按当前用户安装启动器、开始菜单入口和专用 URI 处理程序；下载动作指向固定 GitHub Release 资产。用户回到发起下载的网页点连接，浏览器唤起电脑端，在本机显示要连接的 IM 域名，由用户确认后执行现有设备绑定。这样可复用同一包，既无需用户填写地址，也无需 IM 重新打包或转发二进制。
3. **任务计划程序负责登录和重启。** 每个已绑定配置对应一个当前用户、普通权限、交互登录令牌的任务。任务直接运行该配置的 Windows 宿主，前台 Gateway 是宿主的被监护子进程。登录触发，异常结束交给 Task Scheduler 的 RestartOnFailure；设置允许电池运行、无固定运行时限和重复启动忽略。主动停止和更新切换先让宿主进入正常退出路径；关闭自启移除该配置的登录触发/恢复，保留开始菜单手动启动。以任务实际注册状态和 Gateway ready/online 分别判断是否启用、是否能工作。[微软任务重启设置](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-restartcount)
4. **同一套更新事务。** 每个平台选择一个明确资产。首装与更新读取同一份不可变的 Windows 版本描述文件；该文件的 SHA-256 是 Windows 节点登记和比较的发布身份。现有 Unix TGZ 和 Windows 版本描述文件即使版本号相同也各有自己的哈希。旧 IM 或尚无 Windows 资产时仅揭示确实可用的平台。不改变模型提示词、历史或工具权限。

## 接口与数据流

**构建、发布和选择。** 保留 Unix 的 `manifest.json` 和旧脚本。Windows x64 任务在相同源码和 lockfile 上产出四项：小安装器 `Crewden-Setup-x64.exe`、版本描述文件 `windows-x64.json`、运行环境归档、Nano 应用归档。描述文件列出后两项的固定文件名、字节数和 SHA-256，以及 build SHA、版本、协议、自包含所需的最小启动器协议。Windows 清单 `manifest.win32-x64.json` 记录平台、version、source_commit、协议、data_epoch、安装器及描述文件的 URL、哈希与字节数；其中 update target 的顶层 sha256 指向描述文件，避免运行环境单独变化时被视为同一版本。资产 URL 只允许相同产品仓库、指定 tag 和固定资产名；发布工作流一次创建版本，匿名回读并比对全部资产再生成 IM 清单。没有工件时不暴露下载入口，普通部署不改变版本。首次引导向既有 install 对象追加可空 windows_x64 材料；节点首次注册/心跳将受管平台与版本身份一起上报。view、begin 和 request_install 依认证节点选择平台并保存不可变 target；未带平台的历史节点仍选择 TGZ，显式未知平台不可更新。CPU/浏览器检测只用于提出初始选择，用户可手动选平台。

**哪些字节必须送达。** 构建从 apps/node 的生产调用入口及公开 DSH profile 出发，按 win32-x64 打包并物化动态加载的插件、原生库、包元数据、许可证、业务 JS 与内置 skills。相对稳定的私有 node.exe、运行依赖和现有功能实际消费的 pnpm 放入运行环境归档；经常变化的 Nano 代码、资源放入应用归档。两个归档可独立校验和缓存，固定排序、时间戳与不含 release 标签的运行环境归档可跨版复用；CI 在相同运行依赖的纯业务变更中检查运行包哈希相同。用户无需系统 Node、全局 PATH 或安装工具。浏览器、IM 服务端、开发依赖、其余平台二进制不进入下载集。Office、媒体类等大的传递依赖先查明「启动加载 / 首次真实调用 / 不可达」，覆盖 DSH 声明式插件加载；只有现有公开接口支持并能验证原能力时才延迟装载，不能仅看包名裁剪必需模块。若重依赖确属启动必需，计入真实总量并列明来源。首版复用两个归档，无二进制差分或独立包管理服务。

**大小基线与检查。** v2.0.0 已发布 nano-node.tgz 为 3,111,410 字节，未含客户端随后安装的 Node 与生产依赖。锁定工具链对应的官方 Node v24.22.1 win-x64 压缩发行物为 23,756,953 字节（7z）或 37,748,064 字节（zip），不是新的 Windows 产品包实测。安装器设计预算为 5 MiB 以内，超出要查发布构成。每个候选记录 EXE 大小、干净快照从点击下载到第一条真实回复的产品资产总传输（含重定向后实际包）、安装后占用、应用代码单独升级与重复安装的传输；前两大归档列体积最大的生产依赖并说明必要性。不为尚未构建的完整包许诺某个 MB 数。纯业务更新下载变化的应用归档及小型元数据，缓存命中时同 SHA 的归档不重复传输。[Nano 发行基线](https://github.com/Mrchen116/nano-multiagent/releases/tag/v2.0.0) · [Node 发行物](https://nodejs.org/dist/v24.22.1/)

**下载、确认和首次上线。** 以当前用户的 LocalAppData 放置受管程序和以描述文件哈希命名的受管版本目录和按归档哈希寻址的已解包缓存；现有用户目录下 connections、凭据、DSH home 和工作区归原配置所有。双击时以实际 EXE 哈希保存候选及随带的版本化启动器。首次、确无已有入口时才注册当前用户的引导入口；已有 URI、开始菜单、自启、各配置 active 完全保留。v1 引导器仅在用户确认的 IM 清单指定相同 SHA 时才分派候选。电脑端启动器可在开始菜单重新打开，显示已连接电脑、启动/停止及登录自启开关；未绑定时明确指引回 IM 点击连接。网页以用户手势调用 `crewden://connect?origin=...`，仅传部署配置中的 HTTPS origin，不带 token、路径、命令或本地文件；处理程序严格解析单一参数，固定动作且不用 shell。原生确认目标域名后，先从该 IM 的固定路径取 Windows 清单，由引导器核对候选原始 EXE 的 SHA 与当前 IM 清单、启动器协议及指定的描述文件哈希，再取缺失的运行环境与应用；以固定版本与 SHA 校验每个对象、检查可用后才写成可启动的完整版本。完整但非目标的旧包不替换任何既有入口，提示重下；同 SHA 的现有引导器可直接复用。成功准备后才提交新手动/URI 入口，每个配置的自启仍由其更新事务决定。同源 bind URL 经系统默认浏览器打开。沿用账户、设备双方的确认；正常重跑不触发整机转移，涉及转移仍需本机明确确认。用户拒绝或取消可从原页面再试。成功由绑定后实际在线的节点决定，多电脑账号应匹配本次绑定的 node_id（从既有绑定完成页带回该账号的 onboarding 草稿并从服务读取），不能借任一旧电脑已在线而跳过绑定。网页下载只表示已发起，把安装/绑定失败留在能观察它的一端，并给重新下载、重新打开入口。

**节点平台边界。** node 的 Windows 生命周期适配提供启动、停机、进程出生标识及本次系统启动标识；复用配置级锁和状态文件。用 Windows 进程句柄读取创建时间并验证所有权；用当前系统 LastBootUpTime 的稳定值区分重启与进程重启。宿主以当前用户权限管理 Gateway 子树，Job Object 生命周期涵盖 DSH；先通过当前用户限定的本机管道通知 Gateway 走既有 drain/stop，再对已确认归属的残留子树进行有界收拢。宿主在 Gateway 意外退出后返回失败码触发系统恢复，正常停止返回成功码。更新 worker 必须由宿主在 Gateway 的 Job Object **之外**启动并继承既有租约，确保替换旧 Gateway 不会带走协调者；先结束旧树再启动新树。Windows 的配置、私钥和状态使用当前用户专用目录 ACL，临时文件同目录 flush 后原子替换；共享写入及配置持久化均走相同 Windows 语义，Unix 保留原写入语义。DSH 集成在 Windows 用绝对目录 junction 管理两个已知 bundle 入口，重连只替换可证明归本产品管理的链接。验证含空格、中文、普通用户的路径，平台原生依赖和适用的默认工具经公开 DSH 接口加载。[Win32 Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

**更新与回退。** 首装和受管更新复用同一套准备操作：以独立暂存目录下载缺失对象，验证描述文件及每份资产的哈希、长度、源版本和协议，校验成功才纳入私有缓存。仅提取版本描述覆盖的普通文件与相对目录，路径限定在暂存目录；缓存对象同卷原子发布；检查成功标记与真实目录，重复请求或中断重试复用已完成部分。应用内的工作区解析相对于版本目录，受管版本通过当前用户可创建的目录 junction 关联匹配的 runtime，私有 pnpm 解析改为读取已验证的版本布局；Unix 继续使用原布局。关闸前验证候选 node.exe + 应用可解析同一套 DSH；保留上一个健康版本及其引用的缓存，以当前配置、回滚记录和在途操作为引用集，删缓存仅限本产品无引用的旧下载。每个配置持有已激活版本，启动器只解析该配置的 active 指针；首装与更新可共用版本文件，各配置独立决定启用版本。worker 经原有屏障等待空闲、claim_switch，记录旧路径，停止旧进程；以候选自己的 node.exe 和 entry 启动并验证实际 birth、DSH ready 和 IM 登记的哈希。新版本、配置指针和自启启动目标同步提交；切换中通过现有操作日志加持久化的旧/目标哈希，使重新登录或重启的宿主只接续有主的切换，失去协调者时恢复最后确认版本并报告 interrupted/recovery_required。下载/校验错误不触碰原进程；新版失败恢复原 node.exe/entry 和自启指针，再验证原身份。稳定入口仅分派平台 v1 的已知动作，塞进版本目录的运行中 EXE/DLL 不作原地覆盖。

## 风险与回退

首个候选优先在干净 Windows 中证明包可搬移、DSH 能加载并完成模型调用，再扩大到更新和重启。发布前保留安装包大小、系统/浏览器实际提示与适用发布者签名信息；系统阻止执行或要求关闭系统保护时记录阻塞，不能据此认定普通用户能安装。撤回 Windows 安装入口只撤该平台清单；已安装电脑保持原身份和当前可用版本。无一次性生产数据迁移。

## Runbook for Reviewer

1. 接手时从 GitHub 读取已推送的同一 commit、源码 SHA 和两个候选的 SHA-256。通过 Codex 向现有 Grok Bot 队友 Bbot 派测。它提供隔离 Windows 虚拟机、浏览器与可重启的桌面，按 Windows 10/11 x64 顺序运行，保存干净快照。实测前读取 winver、系统类型和 PATH，确认默认用户权限、无系统 Node.js/WSL，并验证重启后可重新登录。2026-11-21 Bbot 已回执确认读到 889207db0 的原文，在已有 KVM 搭建任务追加两版官方评估镜像、快照、双击、重启及登录预检。此回执是任务已受理的证据；桌面真正就绪需有操作证据。
2. 实施 worktree 的隔离 IM/Web 以 `python3 scripts/e2e-preview.py up` 启动，`status` 核对地址与 commit，完成用 `down` 回收。只在测试实例配置本轮候选、独立账号和测试模型；若现有模型只在私网可达，可在 VM 所在宿主运行能独立产生回复的真实模型服务，供客体经隔离网络接入。用测试会话实际模型请求与回复核对，凭据不经协作消息传递。下载物必须由与 IM 分离的测试资产服务提供。无正式 release 时，VM 快照内用测试 DNS/TLS 把固定发布资产主机映射至测试镜像，服务指定的版本、路径、SHA、IM 的生产白名单与被测 EXE 均不变；仅精确匹配本轮资产，测试结束还原快照。该证据验证下载/校验/失败和真实使用，正式公开资产仍按仓库既有手动授权发布规程验证。
3. 启停电脑端走「开始 → Crewden → 启动/停止」；登录恢复用客体系统菜单重启，异常退出用任务管理器结束已确认的 Gateway，然后验证同一个节点再次在线。清理只关闭本轮隔离 VM 和 IM，保留所需的最小截图、工件哈希和操作结果。若平台、真实模型或桌面操作无法取得，报告具体缺项；无需用户在个人电脑上点操作。
