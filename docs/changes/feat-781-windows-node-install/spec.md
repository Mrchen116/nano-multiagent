# feat-781 Windows 用户接入 Nano

## 原始需求

> 我现在还想支持windows用户，并且可以不装node环境能用

## 当前体验

从 IM 的「连接电脑」入口取得的命令用 Bash 执行安装脚本。在没有可用 Node.js 环境的电脑上，脚本可以为 macOS 或 Linux 下载运行环境，对 Windows 用户则提示使用 WSL。现有首次接入契约覆盖绑定本人电脑、连接模型和通过助手完成真实聊天。[安装入口](../../../apps/im-server/src/install.ts) · [安装脚本](../../../apps/im-server/assets/install.sh) · [首次接入契约](../../specs/im/agents-nodes.md)

## 澄清记录

- Agent 理解：用户希望把自己的 Windows 电脑接入 Nano，并且能够在没有预装 Node.js 的情况下使用。
- 问：Windows 用户第一次把自己的电脑接入 Nano，你希望他们怎么安装？两种方式都可以做到无需预装 Node.js 或 WSL。
- 用户原话：「从 IM 下载后双击安装（推荐，普通用户不用打开终端）」
- 问：首版需要在哪些 Windows 电脑上验收从双击安装到助手回复的完整流程？
- 用户原话：「Windows 10 和 11 的 x64 电脑（推荐，覆盖常见 Intel／AMD 机型）」
- 问：电脑重启、用户重新登录 Windows 后，助手应该怎么恢复工作？
- 用户原话：「mac是啥体验？」
- 对照依据：Mac 默认随当前用户登录在后台启动，异常退出后由系统尝试恢复。可以关闭登录自启。[电脑端操作说明](../../operations/gateway.md) · [后台启动实现](../../../apps/node/src/lifecycle.ts)
- 问：Windows 是否沿用 Mac 的后台体验？
- 用户原话：「跟 Mac 一样（推荐，默认登录自启、异常退出后恢复，可关闭自启）」

## 用户场景

小林在一台没有 Node.js、npm、pnpm 或 WSL 的 Windows 电脑上打开 IM。她在「连接电脑」一步下载 Windows 安装包，双击运行，看到要连接的账号和电脑，确认后回到同一个 IM。即使还没有配置模型，她也能看见自己的电脑已上线。她随后连接模型、创建助手，在聊天里发出第一条消息并收到这个助手的回复。整个过程无需打开终端或手动配置开发环境。

第二天，小林重启电脑并登录原来的 Windows 账号。打开 IM 时，她可以继续找昨天的助手工作。后台程序偶尔异常退出后也能自动恢复。如果她关闭登录自启，下次登录时电脑保持离线，直到她主动启动 Nano。

如果安装包下载中断或校验失败，小林能看懂如何重试。如果这台电脑已经接入过，重新安装或从 IM 更新后，她还能使用原来的助手和工作文件。

## 验收标准

### Requirement: Windows 用户可从 IM 双击安装并完成首次接入

#### Scenario: 在干净的 Windows 电脑上完成第一次对话

- **GIVEN** 分别使用 Windows 10 x64 和 Windows 11 x64，均未安装 Node.js、npm、pnpm 或 WSL，用户有可用的模型服务。
- **WHEN** 用户从当前 IM 的「连接电脑」下载适用于自己电脑的安装包，双击运行并确认账号和电脑。
- **THEN** 该电脑出现在发起安装的 IM 中并显示在线，用户可以继续连接模型、创建助手，发送消息并收到该电脑上助手的真实回复。
- **AND** 从下载到收到回复，用户无需打开终端、复制命令、安装开发工具或配置系统环境变量。

### Requirement: Windows 电脑能随用户登录恢复工作

#### Scenario: 默认登录自启

- **GIVEN** 用户已完成首次接入，并已关闭安装窗口。
- **WHEN** 用户重启电脑并登录原来的 Windows 账号。
- **THEN** 在网络和 IM 可用时，原电脑自动上线，原助手能继续在已有聊天里回复，用户无需再打开 Nano 或确认绑定。

#### Scenario: 后台程序异常退出

- **GIVEN** 用户已登录，自启采用默认设置，网络和 IM 可用。
- **WHEN** 正在运行的 Nano 后台程序意外退出，故障原因已消失。
- **THEN** 原电脑自动恢复在线，助手能再次响应消息，无需用户重新登录或手动启动。

#### Scenario: 用户关闭登录自启

- **WHEN** 用户关闭并应用登录自启设置，随后重启电脑并登录。
- **THEN** 该电脑保持离线；用户主动启动 Nano 后，同一台电脑和原助手恢复可用。

### Requirement: Windows 安装与更新延续已有电脑身份和数据

#### Scenario: 重新安装或更新已绑定电脑

- **WHEN** 用户重复运行同版本安装包，或通过已有 IM 更新入口完成指定版本的更新。
- **THEN** IM 中仍是原来的电脑，用户无需重新绑定或配置模型，可以在原聊天继续使用已有助手，原工作文件仍可访问。

#### Scenario: 获取指定版本失败后重试

- **WHEN** 首次安装或更新时，当前 IM 指定的版本无法下载或校验失败。
- **THEN** 用户看到失败原因和重试方法；已有安装仍可使用，原数据保留。恢复后重试可以继续完成安装或更新。

## 范围与非目标

首版覆盖 Windows 10 x64 和 Windows 11 x64 的用户电脑、IM 下载入口、接入已有 IM 后的真实助手对话，以及上述后台运行和受管更新体验。安装与运行所需依赖由 Nano 准备，具体分发方式留给设计。沿用现有[固定版本分发与首次设置契约](../../specs/im/agents-nodes.md)和[受管电脑更新契约](../../specs/gateway/service-lifecycle.md)。

Windows ARM64、32 位 Windows、在 Windows 上部署 IM 服务端，以及独立的 Windows 桌面聊天客户端均在本次范围之外。
