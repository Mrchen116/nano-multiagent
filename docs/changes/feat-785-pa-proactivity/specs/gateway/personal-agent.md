# gateway/personal-agent Specification (delta for feat-785)

## ADDED Requirements

### Requirement: PA 主动筹划执行分层消化、夜间筹划、发前新鲜度复核与通用早间顺风车投递

仅对角色为个人助手（PA）且开启 `proactive_planning` 的主体启用后台主动思考闭环；普通团队 Global 数字员工不执行自发静默消化、自发夜间立项或个人早报投递。

#### Scenario: 对话顺手维护与安静后轻量独立复盘兜底
- **GIVEN** PA 开启了主动筹划且未处于停用状态
- **WHEN** 主人在对话中表达了明确目标或安排，或对话与观察会话更新后进入安静期
- **THEN** 对当轮已明确的目标或计划，PA 可在正常回复轮次静默维护主人私人空间的目标图；对安静后尚未落库的新进展或待跟进线索，由独立短期后台维护会话静默对账更新私人目标图或跨天跟进，不在主人发言期间插话、不污染主私聊上下文、不误继承历史轮次真人消息凭据，轨迹记入 PA 的 Work 维护记录

#### Scenario: 夜间独立窗口主动筹划严守工具、记忆与非执行边界
- **GIVEN** PA 开启了主动筹划，到达主人所在时区的夜间安静维护窗口（与 `dreaming` 是否开启或白天是否运行解耦；同夜 `Dreaming` 到期时先完成记忆整合再运行筹划）
- **WHEN** 独立后台主动筹划会话基于正式记忆（含已沉淀的主动分寸规则）与未完结目标图运行
- **THEN** 先清理已被后续进展解决或过时的旧 `proposed` 提议；对目标明确、低成本且纯属主人私人范围的前置准备，直接生成准备草稿保存至对应任务节点；对重投入调研、跨 Agent 协作、长线目标前沿下一步或方向待定的新构想，仅在主人私人空间建立有界数量的 `proposed` 待拍板提议卡
- **AND** 后台主动筹划会话物理剥离对外发信与命令终端工具、禁止改写正式记忆仓与 `ROLE.md`、禁止直接创建或转换 `doing`/`todo` 执行态任务，在夜间静默窗口内不向主人发聊天消息；关闭特性、停用 Agent 或节点更新时立即中断在途后台会话

#### Scenario: 发送提醒或主动消息前冲刷已读并核验观察流最新状态
- **GIVEN** PA 即将向主人私聊发送定时提醒、主动简报或引用其他会话的消息
- **WHEN** 主人私聊、消息引用会话或本轮关联任务的来源会话中存在尚未读取的新消息（含尚未到达十分钟合并周期的观察流消息）
- **THEN** 宿主先拉取中心最新观察事件并冲刷本轮已实际读取的观察/私聊消息记录；对仍未读取的新消息拦截本次发送（返回 `held_for_revalidation` 及未读来源摘要），PA 在同轮读取核实最新事实后可正常结项或重发而不陷入重复拦截循环，主人已自行完成的事项不再发出过时催问

#### Scenario: 原生定时桥接、通用有货早报与自定义早间任务自动顺风车合并
- **GIVEN** PA 开启了主动筹划
- **WHEN** 到达主人所在时区的早间活跃窗口，或主人的任一自定义主会话定时任务（原生 Schedule 或 Heartbeat）触发
- **THEN** 若主人当日早间窗口内已配置有启用的主会话定时任务（如晨间计划对齐、早读或站会提醒），系统默认早报自动让路不单独发送；当该原生定时任务进入执行前，宿主先同步观察流并将确定性预算内的未呈报草稿、待拍板提议卡与活跃主线摘要注入当轮上下文一并呈递（仅对实际呈报条目更新已呈报标记），尊重主人自身计划决定权而不越权代定日程；下午或晚间自定义定时任务触发时同样获得最新活跃主线摘要
- **AND** 若主人未配置早间定时任务，仅当存在尚未呈报的新准备草稿、新待拍板提议卡或当日到期检查节点时发送一次整合早报（附带顶层 `task_cards` 同源活卡片）；无任何新价值时跳过模型调用并保持安静

## MODIFIED Requirements

### Requirement: PA 复用完整 Global 执行能力

#### Scenario: 主人请求与普通工具
- **WHEN** 主人交办工作或查询历史
- **THEN** 直接进入 Global 主上下文，复用普通工具、Skills、插件、渐进式任务图、子 Agent 与调度；不增加主人输入审核或脱离既有 Global 与任务图底座的第二套独立执行引擎。
- **AND** 日常直接处理、完整独立事项的单一内部执行责任、原执行者接续及主 Agent 唯一沟通交付均遵循 [Global 契约](../../../../specs/gateway/global-agent.md)，不另设 PA 专属 Agent Loop。

### Requirement: 系统维护 PA 默认服务指导与 Skill 协作

默认服务指导将 PA 定位为长期辅助主人履行职责、追求目标并兼顾工作与生活的助手，结合相关目标、偏好、关系、承诺和新事实判断有帮助的下一步；共享 Global 指引提供内部委派与对外交付分工，不将 PA 固定为只处理新请求的接单者。实际信息范围和行动权限仍沿用当前契约。

#### Scenario: 用户调整服务方式
- **WHEN** 主人希望调整长期帮助目标、分工或服务习惯
- **THEN** 通过同一 `ROLE` 入口确认和保存；不提供 `custom_prompt`。PA 固定主人关系、来源与权限边界保持原有效力。

#### Scenario: 主请求与记忆整合获得 PA 定位
- **WHEN** PA 发起主请求、Dreaming 整合或后台主动筹划
- **THEN** 获得系统 PA 默认服务指导与已确认 `ROLE`；普通 Global 和内部 worker 不获得根 PA 的专属服务段。

#### Scenario: 跨轮次持续工作统一收敛至渐进式目标图
- **WHEN** Global 或 PA 接续持续事项或主人的跨天目标
- **THEN** 可按普通 Skill 发现、选择和加载机制使用随包 `nano-ongoing-work`，优先通过主人私人空间静默的单卡与渐进式目标图记录目标、跨天跟进与准备草稿，避免在私有 Markdown 文件另建与任务面板脱节的第二套待办流水账；不覆盖用户已有自定义 Skill，也不绕过用户禁用选择。

#### Scenario: 重要观察后的私人准备与提议立卡
- **GIVEN** PA 使用默认服务指导，相关来源已获准访问且对应 Skill 未被禁用
- **WHEN** 观察到与主人有关的重要变化、承诺或长线目标缺口
- **THEN** 可按需使用 `nano-proactive-care`，核对原话和后续最新状态，在现有权限内准备有实际内容的私人草稿挂入对应事项，或对需主人拍板的延伸动作在私人空间建立 `proposed` 待拍板提议卡；不把观察到的承诺当作对外发送授权。
- **AND** 已处理、触及主人已划定的免提议边界或没有新帮助价值时保持安静；可读取的信息不足时保留不确定性，不声称已完整核实。

#### Scenario: 已交办事项中的权限阻塞
- **WHEN** 内部执行者报告权限阻塞
- **THEN** 主 Agent 核对具体动作、拒绝理由、原始要求和有效限制，继续允许的独立部分；已有授权覆盖的事项不因内部委派或跨轮次就要求用户重新批准。
- **AND** 父级只能澄清自己的交办限制，不能新增人类授权或推翻用户限制；必要的新权限问题须具体，答复交回原执行者，实际动作仍走正常权限检查，不换介质重复被拒动作。
