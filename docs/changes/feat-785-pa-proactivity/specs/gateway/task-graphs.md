# gateway/task-graphs Specification (delta for feat-785)

## ADDED Requirements

### Requirement: Agent SHALL 按事件单次唤醒推进本人 doing 任务

#### Scenario: 各合法入口边沿唤醒开工与提议态隔离
- **WHEN** 任一合法入口（包括真人在界面点击批准、对话同意后更新状态、领取、在 `doing` 下改派给该 Agent 或解除暂停恢复）产生新的 `doing` 责任跃迁且负责人为 Agent
- **THEN** 宿主按 `(graph_id, node_id, assignee_id, doing_wake.revision)` 边沿水位向该 Agent 发起一次事件唤醒以推进该任务（单轮内可连续调用所需工具或委派后台子 Agent）；当该轮执行自然结束变为 `idle` 时，宿主不再无条件自拍醒空转，同图其他无关节点编辑、断线重连或 Agent 在本轮内自行写入的 `doing` 变更也不会重复触发第二轮唤醒；后续推进由新消息、子任务回报、新的 `doing` 跃迁或原生 `schedule` 到期事件驱动，`proposed`、`todo`、`backlog` 均不自动开工
- **AND** 责任涵盖跨图和各层级直接分配给本人的任务，可查看他人任务不等于负责

#### Scenario: 多项责任与结束条件
- **WHEN** Agent 因任务事件或定时提醒处理现有责任
- **THEN** 可获全部本人 `doing` 与 `waiting` 的区分清单及北极星顶层目标脉络，正文及讨论按需读取，自主安排推进顺序
- **AND** `proposed`、`backlog`、`in_review`、`done`、`paused`、`closed` 不触发任务执行唤醒；返工注明原因并恢复 `doing`；子结果不自动完成父任务或启动后继依赖

#### Scenario: 改派
- **WHEN** 任务改变负责人
- **THEN** 状态保持，旧负责人不再因该节点被唤醒，新负责人若承接 `doing` 任务则按新 `doing` 边沿水位获得一次事件唤醒；关联定时器的 `waiting` 由新负责人按需调整后续安排，`paused`、`backlog` 与 `proposed` 不自动恢复

### Requirement: waiting SHALL 支持可选原生定时安排或静默待人并允许主动恢复

#### Scenario: 定时复查等待与免闹钟待人等待保存校验
- **WHEN** 人或 Agent 为当前需等待未来时间点、外部条件或真人答复的任务提交 `waiting`
- **THEN** 系统核实非空等待原因；若提交了 `schedule_id`，系统要求负责人为 Agent 并核实该原生 Schedule 归属当前负责人与根会话、处于启用状态且下次执行时间在未来有效范围内（支持跨天及多周周期，上限放宽至 180 天，不再拒绝超过一小时的合理间隔），过期或无效 Schedule 明确拒绝且任务保持原状；若任务是在等待真人答复或外部事件而未提供 `schedule_id`，系统允许人或 Agent 负责并直接保存等待原因与可选待决问题（指定 `asked_user_id` 时校验其属于所属会话有效真人成员），不强制要求绑定轮询定时器
- **AND** 未获送达确认不能声称已向用户发出提问；不设最少交互轮数或独立阻塞审核模型

#### Scenario: 安静等待与可选定时器状态核查
- **WHEN** 任务处于 `waiting` 且无新的外部消息或到期定时事件
- **THEN** Agent 保持安静空闲；未绑定 `schedule_id` 的静默等待不触发定时器巡检报错，已绑定的原生 `Schedule` 若被显式删除则在详情查询中如实反映安排已失效而不触发自动修复唤醒风暴

#### Scenario: 提前答复与定时复查
- **WHEN** 相关答复、协作结果或关联的原生定时提醒实际到达
- **THEN** Agent 读取当前状态与外部事实判断是否恢复 `doing`，重新考虑阻塞必要性和授权内替代路径；定时到期不是授权或默认同意，仍需定时等待时按真实任务周期安排下一次检查（无实质变化时保持聊天静默）
- **AND** 离开 `waiting` 清除关联，旧定时输入不能重新打开 `paused`、`backlog`、`proposed`、`closed`、`done` 或 `in_review`

### Requirement: 任务事件与定时复查唤醒 SHALL 保留原有产品交付与审批链

#### Scenario: SingleThread 任务事件或定时复查唤醒轮
- **WHEN** SingleThread 因任务新进入 `doing` 或关联的 `waiting` 定时安排到期唤醒并产生人工权限请求、成果或运行故障
- **THEN** 在绑定聊天中可见真实审批、成果或故障，使用原有投递身份恢复而不重复创建消息或审批卡
- **AND** 没有新结果的例行定时复查可保持安静，但不会吞掉已经展示的审批或故障；Global 仍沿用显式发送和既有授权

### Requirement: 任务事件与定时复查唤醒 SHALL 包含必要行动规则及北极星目标概要

#### Scenario: 任务事件或关联定时唤醒注入北极星目标锚点
- **WHEN** 主会话因任务新进入 `doing`（或重连恢复未完成的首次事件唤醒）或关联的 `waiting` 原生 Schedule 到期而唤醒执行
- **THEN** 获得本人 `doing`／`waiting` 概要、所属顶层北极星大目标标题与终局目标摘要、上级路径、任务详情与讨论入口，以及核对当前事实、围绕顶层大目标一致行动且完成前检查整个目标的必要指导
- **AND** 暂停和被拒绝动作的限制保留，提醒不构成新授权；普通新消息与无变化内部重建不因此追加整份任务提示，任务完整正文和历史讨论按需读取

## MODIFIED Requirements

### Requirement: Agent 可按讨论结果维护持久任务图

#### Scenario: 创建、查询和增量修改
- **WHEN** 用户要求已配置任务工具的 Agent 保存或调整讨论好的计划、独立单卡或探索结构
- **THEN** Agent 能建立、读取并修改对应任务图，返回同一图的稳定入口。
- **AND** 保存不按图结构自动调度后继节点；分配和结果等协作系统消息遵循既有群接收策略。
- **AND** 节点以图内稳定短编号（如 `n1`、`n2`）读取和更新；改名、排序、原位展开模式或状态变化不改变编号，不要求 Agent 反复传递节点 UUID。
- **AND** 图本身也使用短且稳定的引用（如 `tg_a1b2c3d4`）；不同图不会因短 ID 重名而覆盖彼此，工具与 Web 链接使用同一个图 ID。

#### Scenario: 配置任务图特性
- **WHEN** 用户在 Agent 配置中合法开启或关闭默认开启的“任务图”特性并保存
- **THEN** 该 Agent 下一轮回复按最新配置采用任务图能力，当前正在回复的一轮不切换，已有聊天历史和任务图记录保留；关闭有效任务能力后不新增任务事件唤醒，开启后按当前未消费责任重新检查。
- **AND** 开启 Task 通过界面联动选中 `task_graph` 和完整 Cron Feature（支撑可选跨天 `waiting` 定时复查）；Task 关闭且工具单独选中时普通任务调用仍可用，任务事件唤醒与定时复查注入仍要求 Task Feature，预览采用同一配置。
- **AND** 关闭某个 Agent 的特性不撤销用户按所属会话读取既有任务图的 Web/iOS 访问权，也不改变其他 Agent 或输入渠道的权限。

### Requirement: 任务工具公布动作与参数契约

#### Scenario: Agent 获取任务工具定义
- **WHEN** 已启用任务工具的 Agent 获取模型可见的 `task_graph` 定义
- **THEN** 工具及参数描述明确五动作字段归属：`create` 默认创建轻量独立单卡根（`mode: "none"`），同时支持显式建立 `dag` 或 `explore` 根并可选附带初始原子 `operations`；支持 `proposed`、`backlog` 等九种状态、提议说明元数据以及可选关联原生 `schedule` 或记录待决问题的 `waiting` 参数
- **AND** `update`（`apply`）支持在保留原节点标识与记录的前提下将无子节点的 `mode: "none"` 节点原位展开为 `dag` 或 `explore`；变更说明字段必填，普通修改允许空说明，重新开启已完成工作仍要求原因
- **AND** 批内节点定义与引用、仅引用此前定义的节点，以及依赖 `from` 为前置、`to` 为后续的方向有就近说明与可用示例
- **AND** 描述不改变资源归属、权限、原子修改或幂等；图依赖不自动调度后继，直接分配给 Agent 的节点新进入 `doing` 时按边沿事件触发一次执行唤醒，`proposed`、`todo` 与 `backlog` 绝不自动触发开工

### Requirement: Task 恢复 SHALL 尊重真实运行边界

#### Scenario: 中断与换窗
- **WHEN** 重启或断线恢复可执行性
- **THEN** 按当前真相与持久边沿唤醒水位重新核对尚未完成的首次 `doing` 事件唤醒及有效 `waiting` 定时安排，保留用户暂停及范围边界，不靠旧提示或已消费的 `doing` 状态重复行动
- **AND** 正常上下文换窗不改变状态、不额外创建无事件触发的自拍续跑

#### Scenario: 运行故障与非热循环保证
- **WHEN** 执行期间遇到读取失败、持久化异常或模型运行故障
- **THEN** 不增加 Task 专属轮数、token 或费用上限；真实运行错误如实显示，读取失败不当空责任集，同一不可恢复原因不热循环调用模型，不将故障伪装成完成或用户暂缓

### Requirement: Task 等待与结果反馈 SHALL 交付到固定所属聊天

#### Scenario: 跨聊天与 Agent 派发
- **WHEN** Task 成功进入 `waiting` 或提交结果
- **THEN** 反馈回到 Task 固定所属聊天；等待说明包含实际进展、阻塞、已尝试路径与所需协作（关联了原生 `Schedule` 时一并说明下次检查时间，无定时器静默等待时说明待谁答复或何种外部条件而不虚构检查时间）；Global 以 `send_message` 实际交付
- **AND** 相同已确认反馈不重复发送；发送失败/未知不伪造送达、不改变真实 `waiting`，其他独立工作继续

#### Scenario: SingleThread 已确认显式交付
- **WHEN** SingleThread 本轮 `send_message` 已确认送达本轮绑定聊天，模型以 `NO_REPLY` 收尾
- **THEN** 不公开哨兵；其他聊天、未确认发送或可见审批不被该交付标记吞掉

#### Scenario: 直聊 Task 系统通知的静默收尾
- **WHEN** SingleThread 一轮仅处理宿主生成的 Task 系统通知，模型以 `NO_REPLY` 收尾且没有可见审批
- **THEN** 静默结束，不把哨兵显示成聊天正文；实际任务照常处理，有意义的正文仍可交付
- **AND** 不将真人消息或其他来源仅凭相同文案识别为 Task 系统通知

#### Scenario: 停止优先于旧排队输入
- **WHEN** 真人 `/stop` 已暂停 Task，但原生 inbox 仍有停止前收到的答复或定时输入
- **THEN** 解除停止隔离前将受信停止事实持久化，并保证首次后续模型步可见；模型与独立审批均区分原消息时序，旧输入不能被视为停止后的恢复授权
- **AND** 停止后新的明确真人恢复仍可作用于对应 Task；通知持久化失败保持 stop pending，不伪报完成

### Requirement: 停止后的上下文同步 SHALL 不自行启动执行

#### Scenario: 停止通知延迟消费
- **WHEN** 真人 `/stop` 已中断并持久暂停作用范围内的 Task
- **THEN** 将可信停止事实持久投递到下一模型步骤，但解除停止保护、通知本身和停止前积压输入不触发新的模型请求
- **AND** 后续有效新输入或调度触发时一并读取；旧答复不能恢复 `paused`，明确的新恢复或新责任不会被待处理通知阻挡
- **AND** 停止引发的同一 Agent 任务消息只同步上下文，不自行唤醒；重启后最新未消费的可信停止事实仍在下一次有效唤醒中可见，已消费事实不重复注入

#### Scenario: 外部变更与离线恢复
- **WHEN** 人或 Agent 修改正文、责任、状态或关系（含在 PA 私聊或群聊产生 `proposed`、`backlog`、`todo`、`closed` 等任务系统通知），删除任务，或系统因群解散／成员资格变化收缩任务处理资格
- **THEN** 受影响 Agent 通过对应所属聊天系统消息在最近下一模型步骤被动获知业务变化，所有 `task_graph` 系统消息均不触发聊天收件箱主动唤醒（无论负责人是人还是 Agent），不为同一事实另生成一份私下责任快照
- **AND** 消息明确任务及可用详情入口，要求变化时提示读取最新正文；失去访问资格的主体只获得必要撤销事实，不获取失权内容
- **AND** 离线期间任务已撤回，恢复后首个有效输入也能消费尚未消费的撤回消息；空闲且无未唤醒的新 `doing` 边沿责任时不为同步单独启动
- **AND** 连接就绪或当前责任查询成功不代替业务消息追平；尚未完成必要同步时不沿旧责任推进，已注入但尚未消费的失权内容不会随新输入进入模型

#### Scenario: 内部对象重建而事实未变
- **WHEN** 内部对象释放重建或宿主重连，但无尚未唤醒的新 `doing` 边沿跃迁且模型已有信息仍有效
- **THEN** 不据此生成新的 Task 提醒或重复唤醒；首次事件唤醒确因中断未完成时按正常恢复规则补齐单次唤醒

### Requirement: Task 操作成功后 SHALL 提醒具体任务的实际交付

#### Scenario: 保存等待说明或提交结果
- **WHEN** Agent 成功登记 `waiting` 或提交 `in_review`／`done` 的任务结果
- **THEN** 提醒明确本次任务和固定所属聊天；`waiting` 说明实际进展、阻塞、已尝试路径及需要谁提供什么（绑定了 `Schedule` 时附下次检查时间，无定时器待人答复时不强制要求定时器），`in_review`／`done` 交付核验后的成果
- **AND** Global 根 Agent 实际发送到该聊天，内部 child 向父 Agent 汇报并附固定聊天，由根 Agent 公开交付；不因最近处理其他聊天而改变目标，不用任务系统消息或私有结束语冒充成果交付

#### Scenario: 续期、回执重放与发送未确认
- **WHEN** 相同反馈已确认送达、无新内容续期、回执重放或发送失败／未知
- **THEN** 先核对较新状态及消息，已确认内容不重复发送，失败／未知如实处理；不撤销已保存 `waiting` 或删除已绑定的有效 `Schedule`，其他可执行责任继续
