# feat-794: 微信外部通道（WeChat Channel）

## Relations

- Related: `feat-447`, `feat-464`, `feat-786`

本单元在 `feat-447`（外部通道与内部 IM 影子会话机制）、`feat-464`（IM 托管外部通道配置与节点密文凭据同步）及 `feat-786`（IM 通用文件附件安全上传与受控下载）基础上，为 Personal Agent 与普通 Agent 新增个人微信外部聊天通道（`wechat`）。

## 原始需求

### 用户原话（来自上游会话，原样保留）

> 首先增加一个wechat channel很有必要。我能转发东西给他就解了燃眉之急了。和飞书channel一样，新建一个会话在我们内部IM。具体怎么做你可以看你参考的东西，文章，聊天记录，语音，肯定是支持越多越好。你开一个unit做这个吧。其他记忆，注入之类的我慢慢问，慢慢对齐，不着急。请直接调用 T3 MCP 的 create_threads 工具（不要用 invoke_subagent），新开一个顶层 thread 并填入详细任务 prompt 启动（特别是你调研到的参考产品persona，玩出花来，能支持这么多东西，但是我们交互上先不用做喂进 `<persona-context>`，只要能收到并理解我转发的东西，一个聊天channel）。你开完这个thread再继续你的研究。

### 发起会话 Agent 拆解说明（非用户原话，单独标注）

上游线程在创建本工作会话时附带了如下目标拆解（作为需求背景参考，其中涉及外部协议与参考实现的假设已在下方「现状与参考」逐项核实）：

1. **产品定位与边界**：与飞书通道对齐的标准外部聊天通道；收到微信消息后在内部 IM 自动创建并同步独立影子会话（如 `<Agent 名> · wechat`），遵循「触发源决定回复去向」、「可见回复镜像」、「控制命令（`/new`、`/stop`、`/compact`）同步」、「IM 托管配置与节点密文凭据缓存 / 单轮询生命周期回收」；本单元不做 `<persona-context>` 注入，也不做跨会话知识库后台归档重构。
2. **协议与参考实现**：采用腾讯官方公开 iLink Bot 协议（个人微信扫码绑定专属机器人，1:1 本人私聊），参考 `nwverse/persona` / `nwverse/persona-extensions` 的 `wechat` 扩展与腾讯官方 `@tencent-weixin/openclaw-weixin`。
3. **期望覆盖的能力面**：IM 通道页扫码绑定（含过期刷新、已扫码待确认、跨区重定向、数字验证码、凭据与游标保护、令牌被顶替自动解绑、单轮询先停再起）、仅绑定者本人门禁、合并转发聊天记录解析、公众号文章/网页链接卡片解析、语音双层处理（自带转写优先 + 原始音频兜底）、原图/截图入站与图片出站、文件与视频附件、引用消息还原（含全文引用与局部选中引用）、正在输入状态，以及微信侧文本回复审批与内部 IM 审批卡双向同步互斥。

## 现状与参考

### 本仓现行契约与实现基线

1. **外部通道与影子会话契约（[external-channels.md](../../specs/gateway/external-channels.md)、[agents-nodes.md](../../specs/im/agents-nodes.md)、[gateway-relay.md](../../specs/im/gateway-relay.md)）**：
   - 节点本地维护外部连接，中心 IM 服务只保存托管期望状态与经节点公钥密封的凭据，不直连外部平台、不回显已保存凭据；节点与中心服务断连期间仍可凭本地受保护缓存继续处理外部通道对话，恢复连接后补建并追平内部 IM 影子会话。
   - 外部消息按稳定身份映射为内部 IM 独立影子会话，触发源决定回复去向，可见回复镜像同步到内部 IM，`/new`、`/stop`、`/compact` 在外部聊天与内部影子会话间共享同一底层对话上下文。
   - **外部内容获取安全边界**：通道入站预处理仅获取受控消息媒体并受超时与体积上限约束，**不在通道预处理阶段自动抓取任意外部网页地址**；公开文章或网页正文由 Agent 在会话中通过受控网页读取能力按需获取。
2. **多通道扩展缺口与客户端现状**：
   - 现行通道配置校验、Personal Agent 主人外部私聊绑定与前端通道列表目前仅接入飞书；通道模型本身支持同一 Agent 按不同通道类型各绑定一个外部通道。
   - 原生 iOS 客户端当前通道页硬编码了飞书名称、表单字段与飞书开放平台权限链接，尚未适配多通道状态展示。

### 外部参考源码与上游真实能力核实

经核查 `nwverse/persona-extensions` 微信扩展与腾讯官方 `@tencent-weixin/openclaw-weixin`（含最新验证码登录流程与社区问题单），明确以下真实能力边界：

1. **个人微信官方机器人通道原生支持的能力**：
   - **自助扫码绑定与手机验证码**：无需手工在开放平台创建应用，直接获取绑定二维码、同步扫码状态、支持跨区域服务切换、手机端显示数字验证码二次确认、二维码过期自动刷新，以及在微信侧解绑或重新扫码顶替旧连接时自动停止旧轮询并提示重新绑定。
   - **富媒体与引用能力**：原生支持文本、原图/截图、语音（支持微信侧转写文本及原始加密语音流双层获取）、通用文件、视频、引用回复（支持引用历史整条消息及局部选中文字片段）、正在输入状态与出站图片发送。
2. **关于「合并转发聊天记录」与「公众号/网页分享卡片」的真实差异**：
   - **参考实现核实**：`nwverse/persona` 的合并转发聊天记录展开实际仅在其飞书扩展中实现，其微信扩展未实现合并转发字段解析。
   - **上游微信客户端灰度现状**：在个人微信中向机器人直接粘贴公众号或网页链接、单条转发文字/图片/文件/视频、发语音、引用回复均可稳定送达；而微信客户端在「多选合并转发」选人列表中显示机器人、以及部分分享卡片向机器人推送结构化负载目前仍处于腾讯客户端灰度放量阶段——已放量场景可送达结构化卡片或合并聊天记录内容，未放量或特殊卡片（如表情包、视频号、小程序等）可能仅送达不可识别条目（官方参考实现当前会静默忽略此类条目导致无响应）。
   - **本单元产品取舍**：一方面完整解析直接发送的链接，以及微信送达的分享卡片（标题、摘要、来源链接）和合并转发聊天记录（递归展开子消息的发送者、时间、文字及内嵌媒体/链接说明）；另一方面对未携带有效负载或暂不支持的特殊条目**绝不静默丢弃**，在微信与内部 IM 影子会话同步返回明确可读提示与替代发送建议。

## 用户场景

1. **在电脑 Web 端扫个码，一分钟把微信接进 Personal Agent 或专业助手**
   用户在电脑上打开 Web IM，进入 Personal Agent（或某个普通 Agent）的「外部通道」页面，点击添加通道并选择「微信」。无需去任何开放平台建应用或填密钥，页面直接展示绑定二维码；用户拿起手机微信扫一扫，若手机微信弹出数字验证码则在页面填入验证码确认，通道即刻显示「已连接」与绑定标识摘要（同一 Agent 可同时保留飞书与微信两个独立外部通道）。后续在手机 iPhone App 打开该 Agent 的外部通道页时，也能干净地看到微信通道的绑定摘要与实时连接状态，随时执行停用、启用、重连或删除；若日后在微信里解绑或在别处重扫顶掉了连接，通道会自动停止旧接收并清晰提示「登录已失效，请重新扫码绑定」，不会在后台死循环报错。

2. **在微信随手把文章、聊天记录、语音、截图、文件丢给助手，内部 IM 同步留痕**
   日常刷微信时看到一篇深度公众号长文、一段同事讨论的聊天记录、几条长语音、一张报错截图或一份 PDF/表格文件，用户无需切应用搬运，直接在微信私聊转发或发给自己的助手：
   - **公众号/网页文章**：无论是直接粘贴文章链接，还是转发带标题和摘要的分享卡片，内部 IM 对应的 `<Agent 名> · wechat` 影子会话都会同步记录清晰的文章卡片信息或链接，助手随即读取公开文章正文并回传精炼总结或回答追问。
   - **合并转发聊天记录**：当微信送达合并转发的聊天记录时，每条子消息的发言人、时间、文字以及内嵌图片/文件/链接说明都会被完整展开为易读的对话记录，内部 IM 影子会话和助手都能看清来龙去脉；若遇到当前微信版本暂不推送内容的特殊卡片（如表情包、视频号等），助手不会装死不回，而是立刻礼貌说明该类型暂无法直接解析，并提示可以改发链接、复制文字或发截图。
   - **语音消息**：说话发语音或转发语音时，微信自带转写文字则直接识别；即便某条语音没有附带转写，通道也会自动取回语音音频交给助手理解，确保句句有回应。
   - **原图/截图、文件与视频**：发过去的高清截图、原图在内部 IM 影子会话直接显示为图片（不塞多余的 `[图片]` 文字），助手直接看图解答；发过去的 PDF、Office 文档、代码、压缩包或视频安全落盘，助手直接读取分析；若助手生成了图表或长篇代码解答，长文会自动按序分段且不劈裂代码块，生成的图片也会直接作为微信图片发回手机。

3. **像自然微信聊天一样局部引用追问、看正在输入提示、随手回句话完成权限审批**
   对话变长后，用户在微信里长按助手前面某条长回复，甚至只框选其中一句话做「局部引用」追问“这一段展开讲讲”，助手能准确还原被引用的原话或媒体上下文接上话茬。助手思考和调用工具期间，微信顶部自然显示“正在输入…”。当助手需要执行受控操作请求人工审批时，内部 IM 影子会话弹出标准审批卡片的同时，微信也会收到简明可读的待审批说明与回复口令（例如直接回“允许”或“拒绝”）——无论用户顺手在微信回一句，还是切回电脑在内部 IM 点按钮，先操作的一端立即生效，另一端状态自动同步锁死，绝不重复执行；想清屏重来或紧急叫停时，在微信或内部 IM 影子会话发 `/new`、`/stop`、`/compact` 同样双向生效。

## 验收标准

### Requirement: Web 端支持扫码与验证码绑定微信通道，Web 与原生 iOS 端支持一致的通道状态与生命周期管理

#### Scenario: 在 Web 端扫码并完成验证码确认绑定微信通道
- **GIVEN** 目标 Agent（Personal Agent 或普通 Agent）所属节点在线，且该 Agent 尚未绑定微信通道
- **WHEN** 主人在 Web 端打开该 Agent 的外部通道页，选择添加微信通道，用手机微信扫描二维码，并在需要数字验证码时于页面输入对应验证码完成确认
- **THEN** 微信通道创建成功并进入已连接状态，页面展示微信通道标识摘要与已连接状态，任何已保存凭据均不在界面回显
- **AND** 该 Agent 即使已绑定飞书通道也可同时绑定并独立运行微信通道；已有微信通道时添加列表将微信标为已添加，并可通过编辑入口重新扫码更换绑定

#### Scenario: 二维码过期自动刷新、扫码中途取消与验证失败恢复
- **WHEN** 扫码等待期间二维码超时过期、主人在绑定完成前关闭或取消弹窗，或提交的数字验证码未通过校验
- **THEN** 二维码过期时页面自动刷新或提供重新获取二维码入口；中途取消时立即停止本次等待且不创建半成品通道；验证失败时显示明确原因并允许重试或重新扫码

#### Scenario: 微信侧解绑或连接凭据被顶替失效时自动停用接收并提示重绑
- **GIVEN** 某 Agent 的微信通道处于已连接状态
- **WHEN** 绑定者在微信侧解除授权或在别处重新扫码导致当前连接凭据失效
- **THEN** 通道自动停止后台接收，状态更新为连接失败并明确提示登录失效需重新扫码绑定，不在后台持续死循环重试，已有内部 IM 影子会话历史完整保留

#### Scenario: Web 与原生 iOS 端查看状态及执行启停、重连、删除与离线只读保护
- **GIVEN** 某 Agent 已绑定微信通道
- **WHEN** 主人在 Web 端或原生 iOS 端查看外部通道列表，或依次执行停用、重新启用、重连、删除操作
- **THEN** 两端均准确展示「微信」通道名称、绑定标识摘要与真实连接状态；原生 iOS 端不显示飞书专属字段、飞书编辑表单或飞书权限外链，也不提供手机端二维码编辑入口
- **AND** 停用后保留绑定凭据并停止微信收发；启用或重连后恢复单一活动连接，不出现新旧连接并存抢消息；删除通道在确认节点停止连接后移除绑定并清理本地会话缓存，同时保留内部 IM 聊天历史；节点离线时两端统一只读并展示最后已知状态与更新时间

### Requirement: 微信通道严格执行绑定者本人准入，并与内部 IM 影子会话双向同步消息与会话控制

#### Scenario: 绑定者在微信发消息自动创建并同步内部 IM 影子会话
- **GIVEN** 某 Personal Agent 或普通 Agent 的微信通道已连接
- **WHEN** 扫码绑定的微信主人向该微信机器人发送消息
- **THEN** 内部 IM 自动创建并展示对应的独立微信影子会话（标题可清晰辨认为该 Agent 的微信会话），主人的入站消息与 Agent 的可见回复在微信与内部 IM 影子会话中一致呈现
- **AND** 目标为 Personal Agent 时，绑定者本人的微信私聊按主人本人外部私聊语义处理；目标为 Global Agent 或 Personal Agent 时，内部 IM 1:1 影子会话中的主人消息按模型提醒送达与 `inbox` 实际读取事实同步推进待送达、已送达与已读双勾回执

#### Scenario: 触发源决定回复去向且控制命令在微信与内部 IM 影子会话间同步生效
- **GIVEN** Agent 的微信私聊与内部 IM 影子会话已建立且已有对话上下文
- **WHEN** 主人在微信发消息触发回复、随后在内部 IM 影子会话直接发消息，或在任一端发送 `/stop`、`/compact`、`/new`
- **THEN** 微信触发的回复发回微信并镜像到内部 IM 影子会话；内部 IM 影子会话直接发起的消息回复仅保留在内部 IM 而不外发至微信
- **AND** `/stop` 立即中止当前正在执行的轮次，`/compact` 压缩双方共享上下文，`/new` 切出全新对话上下文且双端后续消息均在新上下文中继续

#### Scenario: 非绑定微信用户消息被拒绝且不污染会话上下文
- **WHEN** 非扫码绑定者本人的其他微信用户向该机器人发送消息
- **THEN** 消息不进入内部 IM 影子会话、不触发 Agent 模型调用或长期记忆写入，发送方仅收到受频控的拒绝提示

#### Scenario: 中心 IM 暂时断连期间节点本地继续服务微信并在重连后追平影子会话
- **GIVEN** 节点已在本地保存有效的微信通道凭据，且中心 IM 服务暂时断开连接
- **WHEN** 绑定者在微信向该 Agent 发送消息并收到回复，随后节点与中心 IM 服务恢复连接
- **THEN** 断连期间微信侧对话正常完成，恢复连接后内部 IM 影子会话自动创建或补齐断连期间的往来消息记录

### Requirement: 微信转发或发送的文章链接、分享卡片与合并聊天记录可被展开理解，不支持条目给出明确反馈

#### Scenario: 发送文章链接或转发分享卡片由 Agent 安全读取正文并回答
- **WHEN** 绑定者在微信粘贴公众号文章或公开网页链接，或转发包含标题、摘要与链接的分享卡片并提出阅读或总结请求
- **THEN** 内部 IM 影子会话展示清晰可读的链接或分享卡片标题、摘要与来源地址，通道不在入站预处理阶段盲目抓取外部网页，Agent 使用自身受控网页读取能力读取公开正文并给出准确回答

#### Scenario: 转发合并聊天记录时递归展开子消息对话结构
- **WHEN** 绑定者在微信转发一段合并聊天记录且微信送达了记录内容
- **THEN** 内部 IM 影子会话与 Agent 输入均呈现展开后的结构化对话（包含各条子消息的发送者、时间、文字正文及内嵌媒体、链接或嵌套转发说明），不直接裸露原始结构标记或仅留空壳标题

#### Scenario: 收到无有效负载或暂不支持的特殊微信消息类型时返回可读提示
- **WHEN** 绑定者在微信发送表情包、视频号或小程序等未携带可解析正文的特殊条目
- **THEN** 微信与内部 IM 影子会话均收到明确可读提示，说明该消息类型暂不支持直接解析并提示改用链接、文字、截图或文件发送，不静默丢弃消息

### Requirement: 微信语音、原图/截图、通用文件与视频入站及图文长回复出站完整可用

#### Scenario: 语音消息在有无现成转写文本时均能进入理解或给出明确兜底反馈
- **WHEN** 绑定者在微信发送或转发带现成语音转写文本的语音消息，或发送未附带转写文本的原始语音消息
- **THEN** 附带转写文本时，可读语音文本同步展示在内部 IM 影子会话并交给 Agent 理解回复；未附带转写文本时，通道自动获取并还原音频内容交给 Agent 处理（若当前模型不支持音频识别则在双端返回明确可读说明，绝不无响应）

#### Scenario: 原图与截图入站在内部 IM 直接展示图片并进入多模态理解
- **WHEN** 绑定者在微信发送 16 MiB 以内的原图或截图并提问（同轮或紧随其后发文字）
- **THEN** 内部 IM 影子会话直接以图片附件展示而不在正文中插入冗余 `[图片]` 占位文本，具备看图能力的 Agent 直接依据画面内容作答

#### Scenario: 通用文件与视频附件安全读取及超限失败提示
- **WHEN** 绑定者在微信发送大小合规的文档（如 PDF、Office、代码、文本、压缩包）或视频附件并要求分析，或发送超出体积限制的附件
- **THEN** 合规附件在内部 IM 影子会话可见且 Agent 可在受控目录读取文件内容完成分析；超限或获取失败的附件在微信与内部 IM 影子会话均给出明确原因提示

#### Scenario: 出站长文本安全分段不截断代码块，且出站图片直接发回微信
- **WHEN** Agent 回复包含微信不支持的排版标记、超过微信单条长度上限的长文本（内含多行代码块），或在回复中附带生成的图片
- **THEN** 微信收到去除不兼容标记后的整洁文本，超长内容按序拆分为多条消息且跨段代码块保持完整闭合与重开，附带图片在微信中作为真实图片消息展示，同时内部 IM 影子会话完整保留回复文本与图片

### Requirement: 引用消息上下文自动还原、处理中显示正在输入状态、工具审批支持双端互斥确认

#### Scenario: 全文引用或局部选中文字引用回复时准确还原被引用上下文
- **GIVEN** 微信私聊中已有历史往来消息
- **WHEN** 绑定者在微信引用某条历史消息全文，或仅框选历史消息中的局部文字片段进行回复追问
- **THEN** 内部 IM 影子会话与 Agent 均能看到被引用片段或原消息摘要与当前追问的对应关系，Agent 据此准确回应指代内容；当微信通道被删除或解绑时，本地保存的近期引用记录同步清除

#### Scenario: Agent 运行期间维持微信正在输入状态并在结束时停止
- **WHEN** 微信消息触发 Agent 运行直至最终回复发出、被 `/stop` 中止或运行出错
- **THEN** 运行期间微信聊天窗口显示“正在输入…”状态，轮次结束、中止或报错后该状态及时结束

#### Scenario: 微信文本回复审批与内部 IM 影子会话审批卡双向同步且严格互斥
- **GIVEN** 微信触发的轮次中 Agent 请求执行需要人工确认的受控工具操作
- **WHEN** 内部 IM 影子会话生成待审批卡片且微信同步收到待审批操作说明与文本回复指引，主人在微信回复允许/拒绝指令，或在内部 IM 影子会话点击批准/拒绝按钮
- **THEN** 先提交的一侧立即生效并驱动 Agent 继续执行或拒绝操作，另一侧审批状态同步收敛为已处理；此后在任一侧重复回复或点击均不再重复触发或改变既有审批结论

## 范围与非目标

- **在范围**：
  - 为 Personal Agent 与普通 Agent（SingleThread 及 Global 模式）新增个人微信外部通道（`wechat`），纳入现有托管外部通道配置、节点密封凭据同步、离线本地缓存恢复与单活动轮询连接生命周期管理；
  - Web 端 Agent 外部通道页新增微信扫码绑定、二维码过期刷新、已扫码待确认、数字验证码确认、重新扫码重绑及状态管理交互；原生 iOS 端外部通道页适配微信通道状态、绑定标识摘要及启用/停用/重连/删除管理，修复现行硬编码飞书字段与链接的问题；
  - 绑定者本人（owner-only）私聊准入、内部 IM `<Agent 名> · wechat` 影子会话自动映射、触发源回复路由、可见回复镜像，以及 `/new`、`/stop`、`/compact` 跨端同步；
  - 入站全面支持文本、公众号/网页链接与分享卡片解析（由 Agent 受控工具按需读公开正文，通道层不盲抓任意外链）、合并转发聊天记录递归展开、不支持条目明确提示（不静默丢弃）、语音双层处理（现成转写优先 + 原始语音音频兜底）、16 MiB 内原图/截图、通用文件与视频附件、全文与局部文字引用还原；
  - 出站支持微信正在输入状态、不兼容排版净化、约 3500 字代码块安全切分、图片回传微信，以及微信侧文本回复工具审批与内部 IM 审批卡的双向同步互斥；
  - 提供隔离环境可控微信协议测试桩跑通 PR 前自动化与独立审查真栈验收，并在提交 PR 前提供真实上游隔离预览环境供用户亲自扫码实测。
- **非目标**：
  - 不在本单元引入参考产品的 `<persona-context>` 提示词注入机制，也不做跨会话知识库后台自动归档重构；
  - 不在原生 iOS 客户端实现手机本机保存二维码到相册再跳转微信扫码的移动端绑定流程（扫码绑定统一在 Web 端完成）；
  - 不支持微信群聊机器人接入或非绑定者多用户共用同一个人微信机器人；
  - 不在通道入站预处理或出站渲染层直接抓取任意公网 URL（严守防 SSRF 边界），也不绕过微信客户端自身尚未放量的客户端转发选人限制。
