## 澄清记录

- Q1: 产品定位对齐确认（200 字以内）
  A: 用户认可如下定位并授权全权推进交互设计与实现：
  “我们不是个人 Bot 控制台，而是**以 IM 为协作与工作主体的组织级人机共事平台**。组织里**真人同事**、懂主人全局上下文并在授权内辅助与代为协作的**个人助手（PA）**，以及不依附单人、独立承担长期职能的**专业数字员工**共同工作。长期 Agent 借助记忆主动感知变化、多事项并行并对结果负责；IM 则是全员找人、找数字同事、沟通决策与交付成果的日常办公现场。”
  **Agent 解读**：本次需围绕“组织级人机共事 IM”补齐找人与人机关系发现的完整前端交互链路（一级同事目录、侧栏搜索穿透通讯录与快捷键、侧栏「同事」筛选直达、群聊与详情上下文人物名片、选人与建群弹窗的人本分组及身份清晰度），完成后保留隔离测试服务供用户亲自体验并提供多场景实测截图；因尚待用户亲自试验验收，本轮保持 unit 为 active 状态，待用户确认后再归并归档。

## 用户场景

1. **新成员或日常办公浏览团队同事（宏观目录）**
   林夏进入 Crewden 工作区，左侧主导航（及手机底栏）除了「聊天」「任务」「智能体」外，还有对等的一级「同事」入口。点开「同事」后，她能一目了然看到团队里所有在岗真人同事的姓名与 `@用户名`，还能直接看到每位同事绑定的公开个人助手（PA）以及其负责管理的专业数字员工，点击「发消息」即可与该同事开启私聊，点击其数字员工也能查看对应工作与资料。若当前登录者是公司管理员，页面头部还提供直达「公司成员」审批页的入口；若用户尚未加入团队（仅使用个人空间），页面清楚说明状态并引导前往账号页查看或申请加入团队。

2. **在聊天侧栏搜名字或切「同事」Tab 即刻开聊（零心智负担找人）**
   陈明想找从未私聊过的同事赵敏沟通接口方案。他在桌面端按下 `⌘K`（或点击左侧搜索框），输入“赵敏”或 `zhao`。即使两人之前没有任何会话或消息记录，搜索结果也会在「联系人」分组直接召回赵敏（显示 `@zhao` 及其公开助手信息），点击或按回车即可立即进入与赵敏的私聊。若陈明没搜名字，而是直接点击侧栏的「同事」筛选胶囊，上方列出已有的同事私聊，下方直接列出尚未建立私聊的其他团队同事，一点即聊，不再撞上冷冰冰的「暂无会话」。

3. **从群聊讨论或数字员工资料顺手找到真人（上下文毛细血管）**
   在「产品研发群」阅读讨论时，陈明看到王五发了一条消息，或在别人的消息里看到 `@王五` 的提及标签。他直接点击王五的消息头像或 `@王五` 标签，就地弹出一个轻量的个人名片卡：展示王五的头像、姓名、`@wangwu`、他的个人助手及负责的数字员工，并提供醒目的「发消息」主按钮与群内「`@` 提及」快捷按钮。打开群设置成员列表点击某位真人同事，或者在查看某个专业数字员工公开资料时点击「管理员」处的同事姓名，同样可以一键发起与该同事的私聊。外部渠道同步进来的未绑定外部发言者则保持只读身份展示，不伪装成可站内私信的同事。

4. **发起新聊天、新建群聊与群加人时的人本秩序**
   当用户通过侧栏「＋」打开「新聊天」或「新建群聊」时，候选列表支持按类别筛选并默认把「同事」分组排在「助手」之前；每位真人同事清晰展示 `@用户名`（不再只显示一个模糊的「人」字，也不会在建群列表里裸露原始内部 ID）。群详情顶部的头像簇真实反映群内成员构成，不再因为群里有一个 Agent 就隐藏所有真人头像。

## 验收标准

### Requirement: 一级导航提供团队同事目录并展示人机协作关系

#### Scenario: 团队成员浏览同事目录并发起私聊
- **GIVEN** 当前用户为已获批的有效团队成员，团队内有其他有效真人成员及公开可见的个人助手、专业数字员工
- **WHEN** 用户在桌面导航栏或手机底部导航点击「同事」进入同事目录
- **THEN** 页面列出团队内所有可见真人成员（含本人标识），展示头像、显示名、`@用户名`，以及每位成员关联的公开个人助手和所管理的专业数字员工入口
- **AND** 对其他同事点击「发消息」可直接打开或创建与该同事的一对一私聊；支持按显示名或 `@用户名` 实时筛选同事，无匹配时显示明确空结果提示

#### Scenario: 管理员与未加入团队的个人空间用户访问同事目录
- **WHEN** 有效公司管理员查看同事目录
- **THEN** 页面头部提供进入「公司成员」准入管理页的快捷入口
- **WHEN** 尚未加入团队的个人空间用户查看同事目录
- **THEN** 页面清晰说明当前仅启用个人空间，并提供前往账号设置申请或查看团队资格的入口，不展示任何团队成员数据

### Requirement: 聊天侧栏支持通讯录穿透搜索、快捷键唤起与同事筛选直达

#### Scenario: 搜索尚未建立私聊的同事或助手并直接发起会话
- **GIVEN** 当前用户与团队同事「赵敏」尚未建立一对一私聊
- **WHEN** 用户在桌面端按下 `⌘K` / `Ctrl+K` 唤起聊天侧栏搜索（或直接点击搜索框）并输入「赵敏」或其用户名片段
- **THEN** 搜索视图在保留匹配会话与历史消息分组的同时，在「联系人」分组列出赵敏（展示 `@用户名`）且真人排在 Agent 之前；已在「会话」分组命中的一对一私聊对象不在「联系人」分组重复出现
- **AND** 点击该联系人（或在无会话命中时按回车选择首个匹配联系人）立即打开或创建对应一对一私聊；仅当会话、联系人与历史消息均无匹配时才显示统一无结果提示

#### Scenario: 切换「同事」筛选直接发现未私聊同事
- **GIVEN** 团队中存在尚未与当前用户建立一对一私聊的其他有效真人同事
- **WHEN** 用户在聊天侧栏点击「同事」筛选标签
- **THEN** 列表在已有同事私聊下方（或尚无同事私聊时直接）展示可直接联系的团队同事列表，点击任一同事即可打开或创建一对一私聊，不把仍有可联系同事的团队显示为单纯的「暂无会话」

### Requirement: 群聊消息、提及标签、群成员与 Agent 资料支持就地联系真人同事

#### Scenario: 在群聊点击真人头像或提及标签打开个人名片
- **GIVEN** 用户正在查看包含其他有效团队真人成员的群聊或只读观察会话
- **WHEN** 用户点击其他真人成员的消息头像，或点击消息正文中的 `@成员` 提及标签
- **THEN** 就地弹出轻量个人名片，展示该成员的头像、显示名、`@用户名` 以及可见的个人助手与负责的数字员工摘要，按 `Escape` 或点击外部可关闭
- **AND** 点击名片中的「发消息」立即进入与该成员的一对一私聊；在可发言群聊中点击「`@` 提及」可将该成员提及插入当前输入框并聚焦

#### Scenario: 外部来源未映射发送者不提供站内私聊名片
- **GIVEN** 影子会话中包含未映射为站内真实用户的外部渠道发送者消息
- **WHEN** 用户查看该外部发送者的消息气泡
- **THEN** 保持展示其外部发送者名称，不提供站内个人名片或发私信操作

#### Scenario: 从群设置成员列表与 Agent 公开资料联系对应真人
- **WHEN** 用户在群聊详情的成员列表中点击非本人的有效真人成员
- **THEN** 可直接打开个人名片或进入与该真人的一对一私聊
- **WHEN** 用户在他人管理的 Agent 公开资料页查看「管理员」字段并点击该同事
- **THEN** 直接打开或创建与该管理员同事的一对一私聊

### Requirement: 新聊天、新建群聊与群详情清晰呈现真人身份与优先分组

#### Scenario: 新聊天与新建群聊优先展示同事并显示用户名
- **WHEN** 用户打开「新聊天」弹窗或「新建群聊」弹窗
- **THEN** 候选列表将「同事」分组排在「助手」分组之前（新聊天支持按全部、同事、助手筛选），真人条目展示 `@用户名` 而非笼统的「人」字或内部 UUID，Agent 条目保持展示归属信息、设备名与在线状态

#### Scenario: 群详情头部头像簇与添加成员忠实反映人机共事
- **GIVEN** 群聊同时包含真人成员与 Agent 成员
- **WHEN** 用户打开群聊详情或其中的「添加成员」面板
- **THEN** 顶部头像簇按群实际成员顺序展示（不因存在 Agent 而剔除真人头像），添加成员面板使用涵盖人与助手的中英文标题并优先列出可添加的同事

## 范围与非目标

- **在范围**：
  - Web IM（及复用同一前端的 Desktop 客户端）的一级「同事」目录页、桌面与移动端导航入口；
  - 聊天侧栏通讯录穿透搜索、桌面 `⌘K` / `Ctrl+K` 唤起快捷键、「同事」筛选 Tab 未私聊同事直达；
  - 群聊消息头像、`@mention` 标签、群详情成员列表的真人轻量名片（`PersonPopover`）及 Agent 公开资料页联系管理员入口；
  - `/im/v1/contacts` 为可见真人补充公开 `username` 字段与 `username` 搜索匹配；
  - 「新聊天」「新建群聊」「群详情」的人本分组排序、真人 `@username` 展示、群头像簇与遗留文案修正；
  - 中英文双语文案完整覆盖。
- **非目标**：
  - 不修改多租户与空间权限模型（未加入公司的个人账号仍不可见公司成员，管理员停用/审批权限不变）；
  - 不新增真人实时在线状态心跳或组织架构树/部门层级管理；
  - 不改动原生 iOS 客户端页面布局（iOS 新建聊天已具备「同事 / 助手」分组，服务端 `contacts` 新增可选 `username` 字段保持向后兼容）；
  - 不改变任何 Agent 系统提示词、工具 schema 或模型可见上下文。
