## MODIFIED Requirements

### Requirement: 用户可从聊天列表搜索历史消息

#### Scenario: 查找并定位原消息
- **WHEN** 登录用户在聊天侧栏搜索关键词（或在桌面端无活动弹窗及非提炼模式下通过 `⌘K` / `Ctrl+K` 聚焦搜索框输入关键词）
- **THEN** 保留会话匹配，对尚未在匹配站内一对一会话中出现的可见联系人按「真人优先于 Agent」展示在「联系人」分组（默认最多预览前 5 条，超出时可原地展开全部；点击或无会话匹配时按回车直接打开或创建一对一私聊），并分组展示其可访问的已同步消息，按时间从近到远，显示来源、发送人、时间及片段；点击消息结果定位原消息及上下文。
- **AND** 非当年消息显示年份；窄屏从原消息返回搜索视图时恢复搜索词、分类、已加载页和位置以继续查看结果。
- **AND** 匹配卡片初始视图中的公开标题、文字、表格和图形标签时，结果显示命中的卡片文字并定位原卡片；动作参数、私有交互状态和沙箱运行内容不参与搜索。

#### Scenario: 独立搜索视图
- **WHEN** 用户进入搜索
- **THEN** 移动端展示独立搜索页面，桌面端侧栏切换为搜索视图；普通会话列表和固定 PA 入口不与结果同时展示。
- **AND** 清空关键词仍留在搜索视图，主动退出后恢复普通列表；PA 会话在搜索中与其他会话一样参与匹配。
- **AND** 有匹配时按会话、联系人与消息分组显示结果和关键词，三类均无匹配时显示统一空状态；消息命中可定位原文。

#### Scenario: 权限、分页和状态
- **WHEN** 结果分页、权限变化或搜索失败
- **THEN** 续页只包含当前用户可访问的消息，加载、无结果及失败可区分；搜索不改变未读。

### Requirement: Web IM 移动端底部导航使用统一产品图标

#### Scenario: 切换移动端入口
- **WHEN** 用户在 Chat、People、Tasks、Agents 与 Me 之间切换
- **THEN** 各入口在不同系统上保持一致、可辨的图标和文字标签，当前路由只选中对应入口。未读提示保留在所属入口并保持可见。

#### Scenario: 移动端具体聊天隐藏全局底栏
- **WHEN** 用户进入移动端具体会话
- **THEN** Chat、People、Tasks、Agents、Me 底栏隐藏，消息输入区占据底部并保留安全区留白
- **AND** 返回聊天列表后恢复底栏；返回和设置按钮各保留 44px 点击区域

### Requirement: 聊天身份与群聊选择信息清楚可辨

用户进入对话时应能看懂自己正在和谁协作，回到列表时应能找到最近的工作进展。消息正文与真实摘要优先；常规运行详情按需查看，需要用户处理的状态在相关操作处可见。身份提示随读者视角变化：同一伙伴跨入口可辨，群聊、旁观和代发仍能辨认实际参与者及发言归属。角色形象的选择与一致性见 [Agent 身份头像](agents-nodes.md#requirement-创建助手时可选择统一且可辨认的角色头像)。

#### Scenario: 新建聊天分类筛选并区分真人同事与跨团队 Agent
- **WHEN** 用户打开新聊天
- **THEN** 提供「全部 / 同事 / 助手」分类筛选，默认列表将真人同事分组排在 Agent 之前；真人条目展示显示名、`@username` 及关联公开 PA 提示（若有），Agent 条目展示名称、在线状态、归属信息与已知设备名（同事公开 PA 不暴露节点 ID）

#### Scenario: 新建群聊选择真人同事与本人候选 Agent
- **WHEN** 用户打开新建群聊或查看群详情成员
- **THEN** 新建群聊将真人同事分组排在本人 Agent 之前；真人候选展示显示名与 `@username`（不暴露内部用户 ID），本人 Agent 候选第一行显示名称及本地化在线状态、第二行显示 Agent ID 与所属机器名（机器名缺省时回退 node ID）
- **AND** 描述不占用额外行，机器归属不依赖描述内容；群详情顶部头像簇按实际群成员展示（不因群内存在 Agent 而忽略真人成员），群内非本人真人成员与加人列表同样展示 `@username`，且加人列表支持按姓名或 `@username` 搜索过滤并保留已选成员

#### Scenario: 私聊与群聊减少重复身份信息
- **WHEN** 用户查看 PA、普通 Agent、真人私聊或群聊
- **THEN** 标题栏不叠加会话类型标签，私聊不重复罗列参与者；正常电脑名称在 Agent 头像详情中查看，头像保留在线状态，需处理的电脑更新提示仍可见。
- **AND** 普通私聊消息省略重复署名和 PA 角色标签；群聊及旁观会话保留发送者姓名，代发和委托来源继续明确展示。

#### Scenario: 群聊标题栏保持轻量
- **WHEN** 用户查看群聊标题栏
- **THEN** 群头像与成员数表达群聊身份，不再重复显示群聊类型标签；设置和任务入口使用统一无描边图标按钮，保留可访问名称、悬停提示与键盘焦点反馈，移动端点击区域不小于 44px。

### Requirement: 协作入口沿用现有 IM 导航和语言设置

#### Scenario: 桌面和移动端寻找协作者
- **WHEN** 用户通过桌面主导航（Chat、People、Tasks、Agents）或移动端底栏进入一级「同事（`/people`）」目录、切换聊天侧栏「同事」筛选、打开新聊天/建群/群成员入口，或在群聊/旁观会话点击真人成员头像与正文 `@mention` 标签
- **THEN** 一级「同事」目录（支持直连与刷新）列出团队可见真人同事、`@username`、公开 PA（点击发起协作会话）与管理的专业数字员工（点击查看资料与工作）并支持一键私聊（管理员可跳转成员管理，加载失败可重试，未加入团队的个人空间用户可见团队资格引导）；已获批团队成员即使暂无会话或未绑定电脑仍可见聊天侧栏，侧栏「同事」筛选在常规浏览态下直接展示尚未建立站内私聊的团队同事（超出 6 位预览上限时收敛并提供跳转「同事」目录入口）；群聊正文与成员入口可打开轻量真人名片发起私聊或在可写群聊保留原草稿追加 `@` 提及（外部渠道未映射代记发送者不提供站内私聊）；原有聊天、消息操作与附件能力继续可用。

#### Scenario: 新增协作界面跟随中英文切换
- **GIVEN** 用户正在编辑未发送内容
- **WHEN** 从桌面头像菜单或手机“我的”切换中英文，随后刷新
- **THEN** 界面文案及反馈使用所选语言，刷新后保留语言选择；切换当下不清空未发送内容，聊天正文、名字和原始 Work 内容不被翻译。
