# im/conversations-messages.md (delta for feat-796)

## MODIFIED Requirements

### Requirement: 群会话按成员关系管理，解散限创建者

前端经 `/im/v1/conversations/{id}*` 对一个已存在的群会话管理其成员与元数据：向群添加参与者（Actor）、移除某个参与者、修改群名、解散整个群。操作要求当前用户是群成员（非成员 404）。真人成员可改名、添加真人或自己管理的 Agent、移除非创建者成员或自己退出；创建者不可被移除。含「私有」（`owner_only`）Agent 的群聊必须保持私密且仅限同一创建者本人及其名下 Agent 共处，不允许混入外部成员。解散仅仍在群内的创建者可执行，非创建者被拒。这些能力让用户在内置 Web IM 里完成基本群治理，无需重建群。

#### Scenario: 向已存在的群会话添加参与者
- **GIVEN** 终端用户参与一个群会话，且账号下存在尚未加入该群的可用 Agent（若群内已有其他真人成员，该 Agent 须处于「团队公开」；若群内仅有本人及本人名下 Agent 且群为私密，可添加本人「私有」Agent）
- **WHEN** 前端 `POST /im/v1/conversations/{id}/participants` 带一组 Actor（`{type:"agent", id:"<agent_id>"}`）
- **THEN** 200 返回该会话快照，其 `participants` 含新加入的 Agent；此后该 Agent 能收发该会话后续消息，加入的真人成员可回看群已有历史

#### Scenario: 含私有助手的群聊拒绝混入外部成员或加入外人群
- **WHEN** 用户或调用方尝试向已包含任一「私有」Agent 的群会话添加其他真人成员，或尝试将「私有」Agent 添加到已含其他真人成员或公开可见的群会话
- **THEN** 服务端返回 409 拒绝且群成员保持不变

#### Scenario: 助手切换为私有时自动退出含外部成员的群聊
- **GIVEN** 某 Agent 已加入含其他真人成员（或公开可见）的群会话 G1，同时加入了仅含主人本人及同主人名下 Agent 的私密群 G2
- **WHEN** 主人将该 Agent 配置保存为「私有」（`owner_only`）
- **THEN** 该 Agent 自动从 G1 的 `participants` 移除并向原成员推送成员变更事件（G1 历史消息保留可读，若有关联未消费任务上下文同步按既有规则撤销），而在私密专属群 G2 中的成员身份保持不变

#### Scenario: 重复添加已在群的参与者保持幂等
- **GIVEN** 某 agent 已是该群成员
- **WHEN** 前端再次 `POST /participants` 提交同一 agent
- **THEN** 成员不重复出现，会话快照参与者集合不变（不报 500）

#### Scenario: 添加请求为空或 agent 无法解析被拒
- **WHEN** 前端 `POST /participants` 提交空列表或无法解析为已知 agent 的 id
- **THEN** 400 拒绝，会话成员不变

#### Scenario: 非成员添加参与者返回 404
- **WHEN** 用户对自己未参与的会话 `POST /participants`
- **THEN** 404，不泄漏该会话存在

#### Scenario: 修改群名生效，空名被拒
- **WHEN** 前端 `PATCH /im/v1/conversations/{id}` 提交非空 `title`
- **THEN** 200 返回更新后的会话，会话列表与详情显示新群名
- **AND** 提交空 `title` 时不接受为新名（会话名保持原值）

#### Scenario: 会话参与者带 user_id 供成员管理
- **WHEN** 前端读取会话（`GET /conversations` 或写操作返回的快照）
- **THEN** 每个 participant 带 `user_id`（agent participant 的 `id` 是 agent_id，`user_id` 是其稳定 IM 用户标识），前端据 `user_id` 调移除端点

#### Scenario: 移除参与者后该成员从群消失
- **GIVEN** 群里有多个 agent 成员
- **WHEN** 前端 `DELETE /im/v1/conversations/{id}/participants/{user_id}` 指定某 agent 的 `user_id`
- **THEN** 204；该会话快照参与者集合不再含该成员，该成员不能再发言或接收成员消息流；私密群也不能再读取，公开群仍可按公司资格主动读取；可一直移除到只剩创建者，群仍存在

#### Scenario: 仅创建者可解散群，非创建者被拒
- **WHEN** 会话创建者 `DELETE /im/v1/conversations/{id}`
- **THEN** 204，该会话移出日常列表，消息与任务保留为历史只读；未完成任务关闭，done/closed 保持；历史按解散前冻结的成员与可见范围授权
- **AND** 非创建者发起同一请求时 403，会话不被解散

#### Scenario: 跨账号添加真人及自己的 Agent
- **GIVEN** 三个账号拥有不同的 Gateway 或没有 Gateway
- **WHEN** 群成员添加同事，各管理者添加自己管理的「团队公开」Agent
- **THEN** 成员跨账号、跨 Gateway 加入同一群；普通成员不能把他人管理的 Agent 加入群。

#### Scenario: 移除后在线与重连界面收敛
- **GIVEN** 用户被移出群或群已解散
- **WHEN** 用户在线收到更新或断线后重新连接
- **THEN** 该聊天从其已加入列表移除，客户端清理旧授权缓存并重读资格；私密群移出者不能继续读取，公开群访客可主动读取。解散后不产生新的群消息，具有历史资格者可从任务的历史入口回看。

### Requirement: 群类型具有明确默认值、加入方式与切换资格

新建群默认公开，可选私密；包含个人空间成员或「私有」（`owner_only`）Agent 的新建群固定为私密；旧群升级时默认私密。公开群允许公司内有资格的人和「团队公开」Agent 自行加入，私密群需邀请。公开／私密双向切换仅限已加入该群的公司管理员，且群内存在「私有」Agent 时不可切换为公开。

#### Scenario: 创建和加入
- **WHEN** 人或 Agent 新建群，或希望参与已有公开群
- **THEN** 普通公司群新建时默认公开且能选择私密，含「私有」Agent 的群强制私密；公开群可供有资格成员与「团队公开」Agent 自行加入（「私有」Agent 调用加群或创建含外人/公开群均被拒绝），私密群不提供自行加入；人有界面入口，Agent 有工具入口。

#### Scenario: 从已有会话入口发现公开群
- **WHEN** 用户在聊天列表的“＋”菜单选择发现公开群
- **THEN** 搜索框与会话列表保持原有布局；弹窗沿用聊天界面的遮罩、标题栏、群头像及可点击列表行，按内容决定高度，长列表在弹窗内滚动，手机使用对应底部面板。
- **AND** 能关闭或按 Escape 返回原会话，选择群进入原有访客查看／加入流程，不因浏览而入群。

#### Scenario: 更改可见范围
- **WHEN** 已入群的公司管理员把不含「私有」Agent 的群改为公开或私密
- **THEN** 群消息和所属任务一起采用新范围，已有成员与内容保留。
- **AND** 若群内当前包含「私有」Agent，尝试改为公开时返回 409 拒绝；非管理员群创建者或普通成员不能仅凭创建／改名权限切换；未入群的公司管理员也不能直接切换。

#### Scenario: 外部影子会话保持原可见范围
- **WHEN** Gateway 同步外部 channel 并创建影子会话
- **THEN** 不因内置群默认公开而公开外部聊天；影子会话仍按成员范围访问。

#### Scenario: 公司内读取与成员写入分离
- **WHEN** 有效公司成员或「团队公开」Agent 发现并浏览公开群
- **THEN** 可读取详情、消息与会话附件；默认聊天列表仍显示已加入会话，查看不自动加入。发言、上传与任务维护需加入未解散会话；私密群、私聊及解散历史采用各自权限。
- **AND** 改范围后，详情、消息、附件、任务、Agent 查询和待投递消息重试使用当前资格；不宣称撤回已被接收者读取的内容。

## ADDED Requirements

### Requirement: 外部成员与私有助手的历史一对一私聊保持只读且可逆恢复

#### Scenario: 助手切换为私有后历史同事私聊双向封禁但保留历史
- **GIVEN** 同事 B 与主人 A 名下的助手 X 曾建立一对一私聊并存在历史消息，随后 A 将 X 切换为「私有」（`owner_only`）
- **WHEN** B 读取会话列表、该会话详情或消息时间线，或 B / X 尝试向该会话发送新消息
- **THEN** B 仍可读取该会话与既有消息记录，会话快照标记 `can_write: false` 与 `write_blocked_reason: "agent_private"`；B 与 X 向该会话发送新消息均返回 403 拒绝。

#### Scenario: 助手重新切换回团队公开后历史私聊自动恢复
- **GIVEN** 上述一对一私聊因助手 X 处于「私有」而只读封禁，且 A 与 B 仍为有效团队成员
- **WHEN** A 将 X 重新切换回「团队公开」（`team`）
- **THEN** 该会话自动恢复 `can_write: true`（清除 `write_blocked_reason`），B 与 X 可继续在原会话内双向收发消息而无需重建会话。
