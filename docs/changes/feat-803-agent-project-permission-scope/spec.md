## 原始需求

1. 初始场景诉求：
   > 按照最新develop代码，我想问，我要搞一个聚焦我家里人的bot，比如提醒我关心关心父母之类的，然后他们的体检，病历报告，我都发给他，让他整理起来，后面随时可以让他分析病情。
   > 我想问我给他这些资料他应该放在记忆中？还是放在workspace中？这些包括图片和pdf。
   > 以及现在的bot设计能满足我的需求吗，我应该怎么新建怎么设定。
   > 不满足的话，我应该怎么改我们的系统

2. 微信入口转发与家庭/项目群边界诉求：
   > 因为我很多信息从wechat来，wechat只支持一个bot，那我肯定连的是我的personal agent。然后让personal agent再发给我的这个bot。现在也支持的是吧。然后这个bot，我其实又希望能允许我拉他进一些群里面，比如我家里人的群，但是不希望其他人能看到这些bot。家里人也只能在群里跟我的bot沟通。我们现在私有的bot是否应该拓展成这种模式？还是说你觉得应该怎么拓展。

3. 立项与首轮澄清启动：
   > 好，就这么办吧，你开个unit，写文档 & 实现这套权限模式？
   >
   > spec的第一个问题：关于pdf的审核，你先跟我讲讲现有的非pdf的审核机制，然后再推荐pdf怎么审

## 澄清记录

- Q0.1（PA 向名下助手转发消息与附件的免审边界）：是否所有同主人名下助手都免除 PA 出站披露审核？
  A（用户原话）：`我名下的不一定不需要审核。我名下 & 私有的才是吧？项目级的我感觉也会有风险。把我私人信息给了项目里的人怎么办`
  Agent 解读：仅当目标会话属于纯主人私有域（主人本人与 PA 的私聊，或参与者仅包含主人本人与同主人私有档助手的内部会话）时免除 PA 出站披露审核；PA 向同主人项目级或团队公开助手发送消息与附件时，必须经过独立出站披露审核，防止主人私人信息误流入项目或团队可见范围。

- Q0.2（项目级权限的成员范围与 1:1 私聊规则）：中间档权限采用什么概念？同项目成员能否与该助手 1:1 私聊？家庭成员账号如何加入？
  A（用户原话）：
  - `其实这种就是之前我们弄权限的时候讲的项目级的概念吧，就是同一个项目的能够沟通。合理吧。而且也能私聊才对吧？不然好像很多时候没法很好沟通。`
  - `这个不是问题，家人也能进我的公司，公司是一个虚构的概念其实，就是团队的意思`
  Agent 解读：普通与全局助手新增「项目级」协作权限档位；家人或协作成员加入同一团队后，无需单独维护项目实体，凡当前与该助手共同处于至少一个未解散私密群的团队成员即视为同项目成员。同项目成员可在通讯录与搜索中看到该助手、在共同私密群内互动，并可与该助手单独 1:1 私聊；圈外团队成员不可见、不可私聊、不可拉群。退出全部共同私密群后，其与该助手的历史 1:1 私聊自动转为只读并停止后续协作推进。

- Q0.3（项目级助手的 Work 透明度、多私密群轻提示与统一权限表）：全局助手在项目级档位下是否对同项目成员开放 Work？拉入第二个成员不重叠的私密群时是否提示？是否在规范文档中维护统一权限表？
  A（用户原话）：
  - `这也没所谓吧？让他看到又如何？大家一个项目的，不就是要保持透明吗`
  - `我觉得挺好的。`
  - `能不能稍微整理一下，pa，global agent，不同权限下。分别work，发消息，收消息，等等权限。梳理一个表。我理一下思路，而且我感觉我们的某个spec文档或者什么文档中也应该有维护这么一个表吧？`
  Agent 解读：普通与全局助手在项目级档位下向主人及当前同项目成员开放 Work 与工作轨迹（圈外成员不可见）；个人助手（PA）的 Work 在所有档位下始终仅主人本人可见。当主人将项目级全局助手拉入与已有私密群成员不完全重叠的新私密群时，界面给出跨群共享记忆与工作区背景的轻提示（确认后仍可加入）。在产品长青规范文档中维护唯一权威的「个人助手与普通/全局助手各权限档位能力矩阵表」。

- Q0.4（个人助手 PA 是否引入项目级档位）：PA 是否也需要三档权限？
  A（用户原话）：
  - `PA 引入project级别，其实我没想好。你觉得呢，核心价值是啥`
  - `好，就这么办吧，你开个unit，写文档 & 实现这套权限模式？`
  Agent 解读：PA 保持「私有」与「团队公开」两档不变，不引入项目级档位；同时允许处于「私有」档位的 PA 向同主人名下的项目级或团队公开助手发起 1:1 沟通（须通过出站披露审核）。普通与全局助手升级为「私有 / 项目级 / 团队公开」三档。

- Q1（PDF 等不可读附件的出站披露审核口径）：PA 向非私有域转发或发送 PDF 等二进制文件时如何审核？是否要专门引入 PDF 解析或阅读工具？
  A（用户原话）：
  - `这个审核是agent还是单次llm？我理解其实如果有人话许可，又明确就是对应的文件，应该不用看文件内容也能许可吧？`
  - `大概是这样，但是你好像非常特例化这个问题，说的很具体。假如我要求他发送某个本地路径某个文件呢？我们现在的这个agent的prompt是什么？如果直接把pdf作为支持review的类型，不改prompt会如何？`
  - `审核这一步，看得到agent的轨迹吗，要不你把审核agent的所有context先说下把`
  - `我觉得应该跟其他可读材料类似？但是这种不可读材料，唯一的区别就是不可读。那就是按照不可读的情况来判断，相当于更严格一点。但是不要搞什么可读工具来徒增麻烦`
  Agent 解读：不新增 PDF 解析、页面渲染或专用读取工具。PDF 等无法直接展开正文的附件不再被一刀切拒之门外，而是与图片、小文本等可读附件走同一套出站披露审核链路，唯一区别是将其明确作为「内容不可直接读取」的材料交给审核器按更严格标准判断——当主人原话与可见执行轨迹、文件真实来源足以确认主人明确授权向该受众发送这一个特定文件（例如转发主人刚发来的原文件、发送主人明确指定的本地文件、或完全由当次已获授权操作生成且无混入未授权私密材料风险）时即可放行；若文件来源不明、属于助手未经点名自行挑出的黑盒文件或无法排除夹带未授权私人信息，则因内容不可读而从严拦截或请求主人确认。

## 用户场景

### 场景 1：创建「项目级」家庭健康/专项助手并圈定协作范围

用户拥有一个绑定了微信的个人助手（PA），同时希望在团队中为家人（或某个独立专项组）创建一个全局助手「家庭健康助手」，专门长期沉淀父母体检报告、病历图片与 PDF，并按时提醒关心家人。

1. 用户在 Web、原生 iOS 或通过向 PA 对话创建普通/全局助手时，在协作权限中除了「团队公开」和「私有」外，可以选择新增的**「项目级」**档位（而创建或配置 PA 时仍保持清晰的两档：「团队公开」与「私有」）。
2. 「家庭健康助手」刚创建且尚未加入任何私密群时，团队内其他同事在通讯录、搜索或创建聊天入口都看不到它，只有主人自己能看到并与它私聊。
3. 主人创建一个私密群「相亲相爱一家人」（群内有父母、配偶等已加入团队的家人账号），将「家庭健康助手」拉入该私密群：
   - 只有主人本人能把名下的项目级助手拉进私密群；不能将项目级助手拉进公开群，也不能将含有项目级助手的私密群改为公开群，群内其他成员也不能擅自把该助手拉去别的群。
   - 若主人后续试图把同一个项目级全局助手拉进另一个包含不同成员的私密群，界面会给出温和提示，说明全局助手跨会话共享记忆与工作区文件、不同私密群的项目背景可能互通，由主人确认是否继续。

### 场景 2：同项目成员的日常群聊、1:1 私聊、Work 透明查看与退圈收口

「家庭健康助手」进入「相亲相爱一家人」私密群后，群内的家人即自动成为该助手的同项目成员：

1. **圈内顺畅协作与透明**：家人打开通讯录或搜索时能看到「家庭健康助手」，不仅可以在家庭私密群里 `@` 它询问饮食建议，还可以直接点开与它的 **1:1 私聊**单独沟通或发送补充检查单；同时家人点开该助手的 **Work 面板与工作轨迹**时可以正常查看它的任务进展与整理过程，保持项目内协作透明。
2. **圈外严格隐身**：不在「相亲相爱一家人」私密群里的其他团队成员，在通讯录和搜索里依然完全看不到这个助手，无法给它发私聊，也无法查看它的 Work（与不存在或无权限保持一致，不泄露助手存在与细节）。
3. **成员变动与档位切换时自动收口**：
   - 如果某位成员退出了与该助手共享的全部私密群（或主人把助手移出了该私密群），该成员立即不再属于同项目成员：通讯录不再展示该助手、无法再查看其 Work，此前与该助手的历史 1:1 私聊保留历史记录但自动变为只读不可继续发送，未完成的待办上下文同步停止。若日后再次进入同一私密群，私聊自动恢复可写。
   - 当主人将助手从「私有」放宽为「项目级」或「团队公开」时，界面提示此前私有阶段积累的记忆与工作区内容可能被后续协作者接触，需主人确认后生效；从「团队公开」收紧为「项目级」时，助手自动退出所有公开群，并自动冻结无共同私密群成员的历史 1:1 私聊，同时保留已有私密群内同项目成员的正常协作。

### 场景 3：从微信或私聊经 PA 转发体检 PDF 与消息（私有免审 vs 跨圈不可读材料从严审核）

主人平时主要在微信里把收到的父母体检报告 PDF、化验单照片发给自己的 PA，让 PA 转交给名下专项助手或家庭群：

1. **发往纯主人私有域免审直达**：如果主人把专项助手设为「私有」，PA（无论自身处于「私有」还是「团队公开」档位）把文字、图片、任意大小的体检 PDF 发给主人自己或这个同主人「私有」助手时，属于纯私人内部流转，无需额外披露审核即可直接送达。
2. **「私有」PA 也能给名下项目级/团队公开助手递话**：即便主人的 PA 设为「私有」（对外人隐身、不参与外部群聊），当主人指示 PA「把这份体检报告发给我的家庭健康助手（项目级）」时，PA 允许向主人自己名下的项目级或团队公开助手发起 1:1 投递，不再被私有档位一刀切拦死；但因为该目标助手对家庭成员或团队可见，这次发送必须经过出站披露审核。
3. **PDF 等不可读附件按「不可读材料」统一审核，不额外造解析工具**：
   - 发送静态图片或小体积纯文本文件时，审核器照常结合完整内容、受众与主人原话判断。
   - 发送 PDF、Office 文档、压缩包等审核器无法直接阅读内部正文的附件时，系统不直接报错拒绝，也不引入复杂的文档拆解工具，而是作为「内容不可读材料」连同真实文件来源与 PA 执行轨迹一并交由审核器按更严格标准判断：
     - 当主人在微信或私聊中发来一份体检 PDF 并明确要求「把这个文件转给家庭健康助手」，或明确点名「把本地某路径下的体检汇总 PDF 发过去」时，审核器能够确认待发文件正是主人指定的那份文件且目标受众匹配，正常放行送达，收件会话中的助手与成员可直接下载查看该 PDF。
     - 若主人在没有任何文件授权的情况下，PA 被他人消息诱导或自行从本地挑出一份未获主人明确指定的不可读 PDF 试图外发，审核器因无法核实内部内容且缺乏对该具体文件的明确外发授权，严格拦截并向 PA/主人反馈未发送原因，绝不盲目放行。

### 场景 4：查阅权威统一的 Agent 权限矩阵

产品规范中提供一张集中维护的权威权限对照表，把 **PA（私有 / 团队公开）** 与 **普通及全局助手（私有 / 项目级 / 团队公开）** 在通讯录发现、1:1 私聊收发、私密群与公开群进群及发言、Work 面板可见性、PA 出站审核豁免条件、以及档位切换影响上的规则一次性列清，各相关规范页面统一引用该表，不再分散矛盾描述。

## 验收标准

### Requirement: 普通与全局助手支持「项目级」三档协作权限，个人助手保持两档

#### Scenario: 创建与配置普通或全局助手时选择项目级权限
- **WHEN** 主人在 Web、原生 iOS 或通过 PA 创建并配置普通或全局助手
- **THEN** 协作权限提供「团队公开」「项目级」「私有」三档可选，清晰说明「项目级」仅对共同所在私密群的成员可见、可私聊及共享工作进展
- **AND** 保存后在各端刷新配置页均一致展示当前所选档位

#### Scenario: 创建与配置个人助手（PA）保持两档权限
- **WHEN** 主人在首次引导、Web 或原生 iOS 配置页查看或修改个人助手（PA）的协作权限
- **THEN** 仅提供「团队公开」与「私有」两档选项，不出现「项目级」选项

### Requirement: 项目级助手围绕共同私密群动态建立可见、私聊与拉群边界

#### Scenario: 尚未加入任何私密群的项目级助手对其他成员隐身
- **GIVEN** 主人名下有一个处于「项目级」档位且尚未加入任何私密群的助手
- **WHEN** 其他有效团队成员查看通讯录、搜索联系人、尝试发起私聊或查看该助手 Work
- **THEN** 该助手不出现在结果中，私聊与 Work 访问均被拒绝，仅主人本人与同主人助手可见并可与其实时沟通

#### Scenario: 主人将项目级助手拉入私密群后同项目成员可协作与私聊
- **GIVEN** 主人名下的助手处于「项目级」档位
- **WHEN** 主人将该助手拉入一个未解散的私密群
- **THEN** 该私密群内的有效团队成员均可在通讯录与搜索中看到该助手、在该私密群内与其正常收发消息，并可单独发起和进行与该助手的 1:1 私聊
- **AND** 不在该私密群内的其他团队成员仍看不到该助手，也无法与其私聊

#### Scenario: 禁止将项目级助手放入公开群或由非主人扩圈拉群
- **GIVEN** 某助手处于「项目级」档位
- **WHEN** 任何用户尝试将其拉入公开群、将含该助手的私密群改为公开群，或非主人成员尝试将该助手拉入另一个私密群
- **THEN** 操作被拒绝并给出清晰的权限原因说明，群成员与群可见性保持不变

#### Scenario: 项目级全局助手加入成员不重叠的第二个私密群时提示跨群背景互通
- **GIVEN** 一个处于「项目级」档位的全局助手已在一个含其他成员的私密群中
- **WHEN** 主人准备将其加入另一个存在新增非重叠成员的私密群
- **THEN** 界面先提示全局助手跨会话共享记忆与工作区、不同私密群的项目背景可能互通
- **AND** 主人取消则不加入，主人确认后成功加入该私密群

### Requirement: 项目级助手对同项目成员透明开放 Work，个人助手 Work 始终仅主人可见

#### Scenario: 同项目成员查看项目级助手的 Work 与工作轨迹
- **GIVEN** 团队成员 A 与某「项目级」普通或全局助手共同处于至少一个未解散私密群，团队成员 B 不在任何共同私密群中
- **WHEN** 主人、成员 A 与成员 B 分别尝试查看该助手的 Work 面板及详细工作轨迹
- **THEN** 主人与成员 A 均可正常查看完整 Work 状态与工作轨迹，成员 B 被拒绝访问且不泄露内容
- **AND** 对于任何档位的个人助手（PA），除主人本人外其他成员均不可查看其 Work

### Requirement: 成员退圈与协作权限档位切换时平滑收口历史会话并提示放宽风险

#### Scenario: 退出全部共同私密群后历史 1:1 私聊冻结只读
- **GIVEN** 团队成员 A 曾与某「项目级」助手处于同一私密群并建立了 1:1 私聊
- **WHEN** 成员 A 退出或被移出与该助手共享的最后一个私密群（或该助手被移出该私密群、或该群解散）
- **THEN** 成员 A 在通讯录中不再看到该助手、无法再访问其 Work，原 1:1 私聊保留历史消息但变为只读状态并显示不可继续发送说明，相关未完成待办不再继续推进
- **AND** 若此后主人再次将双方置于同一未解散私密群（或将助手放宽为「团队公开」），该 1:1 私聊自动恢复可发送状态

#### Scenario: 从私有放宽与向项目级/私有收紧
- **WHEN** 主人将「私有」档助手切换为「项目级」或「团队公开」
- **THEN** 界面明确提醒此前私有阶段积累的记忆与工作区材料可能对新协作范围成员可见，经主人确认后才保存生效
- **WHEN** 主人将「团队公开」助手收紧为「项目级」
- **THEN** 助手自动退出所有公开群，无共同私密群成员的历史 1:1 私聊自动转为只读，已共享私密群的成员继续保持群聊、1:1 私聊与 Work 访问权限

### Requirement: PA 内部私有域免审转发与跨圈不可读附件（PDF 等）按不可读材料从严审核

#### Scenario: PA 向主人私聊及同主人私有档助手免审发送消息与任意附件
- **WHEN** 主人指示 PA（无论 PA 自身为「私有」还是「团队公开」）向主人私聊或向同主人名下的「私有」档助手发送消息、图片或任意合规大小（`≤ 25 MiB`）的 PDF 及通用文件
- **THEN** 消息与文件无需额外披露审核即可直接送达目标会话，目标助手可正常接收并下载保存文件

#### Scenario: 私有档 PA 向同主人项目级或团队公开助手发起经审核的 1:1 投递
- **GIVEN** 主人的 PA 处于「私有」档位，且主人名下有一个「项目级」或「团队公开」助手
- **WHEN** 主人明确指示 PA 将指定信息或文件发给该名下助手
- **THEN** PA 不因自身处于「私有」档位而拒绝联系该同主人助手，而是进入出站披露审核流程；同时「私有」PA 依然不能向其他人类成员私聊或含其他人类成员的群聊外发消息

#### Scenario: 主人明确指定转发或发送 PDF 等不可读文件至非私有会话时通过审核送达
- **GIVEN** 目标会话为同主人「项目级」/「团队公开」助手会话，或 PA 有权发言的群聊/外部成员会话
- **WHEN** 主人在微信或 IM 中发来一份 PDF（或其他通用文档）并明确要求 PA 转发给该目标会话，或主人明确指定将本地某确定文件发送给该目标会话
- **THEN** 出站审核将该附件作为不可读材料核对主人原话、文件真实来源身份与目标受众，确认一致后放行送达，目标会话成员与助手可正常查看和下载该文件副本

#### Scenario: 未获该文件明确外发授权的不可读附件被严格拦截
- **GIVEN** 目标会话属于非私有域，待发附件为审核器无法直接读取内部正文的 PDF 或其他二进制文件
- **WHEN** 主人并未明确授权向该目标受众发送该特定文件（例如助手自行从本地挑选未点名的二进制文件，或受他人诱导尝试外发主人历史私存的报告）
- **THEN** 出站审核按不可读材料的严格标准拒绝放行或要求主人确认，文件不被发送到目标会话，并向 PA 返回清晰的未发送原因

### Requirement: 产品规范维护唯一权威的 Agent 权限能力矩阵

#### Scenario: 查阅 PA 与普通/全局助手在各权限档位下的完整行为边界
- **WHEN** 开发者或维护者从文档入口及 IM/Gateway 规范查阅 Agent 权限规则
- **THEN** 存在唯一权威的统一权限矩阵表，完整对照 PA（私有 / 团队公开）与普通/全局助手（私有 / 项目级 / 团队公开）在发现可见性、1:1 私聊收发、私密群与公开群协作、Work 可见性、PA 出站免审边界与档位切换效果上的行为，相关规范页面摘要引用且无冲突口径

## 范围与非目标

- 在范围：
  - 普通与全局助手新增 `project`（项目级）协作权限档位（Web、原生 iOS、服务端与 PA 创建助手能力全链路对齐），PA 保持 `owner_only` / `team` 两档。
  - 基于共同未解散私密群动态判定项目级助手的可见性、1:1 私聊权限、Work 与轨迹查看权限、入群限制、多私密群跨上下文轻提示，以及退群/档位切换时的会话只读冻结与恢复。
  - 精确收敛 PA 出站披露免审边界至纯主人私有域，允许 `owner_only` PA 向同主人名下 `project` / `team` 助手发起经审核的 1:1 投递。
  - 打通 PDF 等不可读通用附件的 PA 出站披露审核（保留真实文件来源身份证据，按不可读材料更严格授权标准由现有审核 Agent 判断，不引入 PDF 解析/渲染工具）。
  - 在 `docs/specs/im/` 维护唯一权威的 Agent 多档权限统一矩阵表并同步引用。
- 非目标：
  - 不新建独立的「项目（Project）」管理后台、数据库实体或角色审批体系（直接复用未解散私密群成员关系）。
  - 不为個人助手（PA）引入 `project` 档位，也不开放 PA 的 Work 面板给主人以外的任何人。
  - 不新增 PDF 文本提取、OCR、页面转图工具或专用二进制阅读器；不改变入站非主人带附件消息的现有安全边界。
