## MODIFIED Requirements

### Requirement: 登录用户可发现人和 Agent，管理配置保持个人归属

#### Scenario: 从目录直接发起聊天
- **WHEN** 有效账号按名字、用户名或稳定 ID 搜索联系人
- **THEN** 可辨认自己名下全部可用 Agent（含「团队公开」「项目级」与「私有」）；获批的有效团队成员还可辨认其他有效团队成员（含公开 `@username`）、其设为「团队公开」的普通/全局 Agent 与已激活 PA、以及当前与本人共同处于至少一个未解散私密群的「项目级」普通/全局 Agent（无论该管理者是否同时启用了个人空间）并直接私聊，不要求已有 Gateway、好友申请或额外逐人授权；他人设为「私有」的 Agent 与 PA 以及未与本人共享未解散私密群的他人「项目级」Agent 不出现在目录或单联系人查询结果中；无匹配时显示空结果。

#### Scenario: 公开与同项目 Agent 资料与配置分开
- **GIVEN** 另一位有效团队成员管理的普通/全局 Agent 处于「团队公开」，或处于「项目级」且查看者当前与其共享至少一个未解散私密群，或已激活 PA 处于「团队公开」
- **WHEN** 有效团队成员浏览该 Agent 资料
- **THEN** 能看到名字、管理者、在线状态、协作范围标识及工作模式（普通/全局 Agent 显示已知设备名，全局普通 Agent 可进入 Work；他人公开 PA 不暴露设备名与私人 Work），能向该 Agent 发消息；当管理者对应的用户为当前可见非本人团队成员时，还可从管理者字段直接向该真人同事发起私聊；不能读取完整配置、凭据或保存管理修改
- **AND** 若该他人 Agent 处于「私有」档位、或处于「项目级」但查看者不在任何共同未解散私密群中、或属于他人「私有」PA，非管理者访问其资料或全局 Work 均返回不可访问。

#### Scenario: 一个人多 Gateway，单台离线
- **WHEN** 用户绑定多台 Gateway，其中一台离线
- **THEN** 可辨认各 Agent 所属设备与在线状态，其余设备和人际沟通正常；设备及其 Agent 仍只有原管理者管理。

### Requirement: Agent 协作范围决定哪些聊天新消息可以送达

各角色与档位的完整能力边界遵循 [统一权限矩阵](auth-tenancy.md#requirement-agent-与个人助手按统一权限矩阵控制发现会话轨迹与披露审核)。

#### Scenario: 创建、保存与查看
- **WHEN** 用户在 Web、Desktop、原生 iOS 创建或编辑普通/全局 Agent，或通过主 PA 代建普通/全局 Agent
- **THEN** 权限档位提供「团队公开」（`team`，默认）、「项目级」（`project`，仅共同未解散私密群成员可见、可私聊及查看 Work）与「私有（仅自己与名下助手）」（`owner_only`）三档，支持创建时直接选择任意一档，单纯切换该档位不在既有聊天时间线插入运行配置缓存分界线
- **WHEN** 用户在首次设置引导、聊天弹窗、Web 或原生 iOS 配置页创建或编辑个人助手（PA）
- **THEN** 仅提供「团队公开」（`team`，默认）与「私有（仅自己与名下助手）」（`owner_only`）两档；尝试为 PA 提交 `project` 档位返回 422 拒绝。

#### Scenario: 项目级档位的动态圈内协同与圈外隔离
- **WHEN** 普通或全局 Agent 处于「项目级」（`project`）
- **THEN** 在尚未加入任何含其他成员的私密群时仅创建者本人及同创建者名下 Agent 可见可联系；当创建者本人将其拉入未解散站内私密群后，共同处于该私密群的有效团队成员可在该私密群内及一对一私聊中与其双向沟通并查看其全局 Work；禁止将其拉入公开群、禁止将含该助手的私密群改为公开群、禁止非创建者将其拉入其他群，且该助手在非主人外部渠道单聊外不接收无项目归属的外部消息。

#### Scenario: 私有档位的内部协同与对外双向隔离
- **WHEN** 普通 Agent 或 PA 处于「私有」（`owner_only`）
- **THEN** 对其他团队成员隐藏目录、个人名片关联展示、公开资料与全局 Work；允许接收创建者本人、同一创建者名下其他 Agent 发来的一对一私聊（及已绑定创建者的飞书/微信单聊），以及仅含同一创建者本人与其名下 Agent 的私密专属群消息与话题回复，并允许在上述内部会话中正常回复与主动发言（其中私有 PA 向同创建者名下 `project` 或 `team` 助手发送消息与附件须经出站披露审核）
- **AND** 其他团队成员无法向其新建私聊或将其拉入含外部成员的群聊；该助手（含 PA 自身发言与代表主人发言）向任何外部成员或含外部成员的会话发送消息、创建外部会话或加入公开群均被拒绝；私有 PA 对主人已参与且未排除会话的静默旁观能力按 [personal-agent](personal-agent.md#requirement-双向主人消息可用于协助) 保持有效。

#### Scenario: 放宽风险确认与收紧/恢复范围
- **WHEN** 主人将已处于「私有」（`owner_only`）的助手切换为「项目级」或「团队公开」
- **THEN** 界面按助手类型给出准确提示（全局普通助手说明此前私有阶段积累的记忆、工作区与全局 Work 将对同项目或团队成员可见；单线程普通助手说明将开放对应范围成员发现、对话及后续运行涉及的工作区内容；个人助手说明将开放团队成员发现与联系而私人 Work 与记忆仍仅主人可见），服务端要求携带显式放宽确认后才保存生效；取消确认则保持「私有」不变
- **WHEN** 设置成功从「团队公开」收紧为「项目级」
- **THEN** 该助手自动退出所有既有公开群，保留已加入的私密群；当前未与其共享任何未解散私密群的外部成员历史一对一私聊转为只读并停止递送未消费积压与待办上下文，已共享私密群的成员继续保持群聊、一对一私聊与 Work 访问
- **WHEN** 设置成功从「团队公开」或「项目级」收紧为「私有」
- **THEN** 该助手自动退出所有包含其他团队成员（或公开可见）的既有群聊，仅保留主人与同主人名下 Agent 的私密专属群；越出私有范围且尚未交给模型的外部积压消息停止递送，恢复后也不补发；此前与其他团队成员建立的一对一私聊保留历史可读但双向禁止继续发消息，后续重新共享私密群（处于「项目级」时）或切回「团队公开」后该一对一私聊自动恢复可收发。
