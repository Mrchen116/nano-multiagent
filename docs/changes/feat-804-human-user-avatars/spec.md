## 用户场景

1. **在 Web 与桌面客户端上传、裁剪预览、更换或移除个人头像**
   林夏在日常协作中希望同事在群聊和通讯录里一眼认出自己。她从桌面端右上角个人菜单（或手机浏览器底栏「我的」身份卡）进入「账号」设置页，在个人身份区点击头像旁的上传/更换入口选择一张日常照片。界面弹出简洁的圆形取景裁剪预览，她拖动调整构图并滑杆缩放后确认保存，无需再额外点击下方的显示名保存按钮，账号页、右上角菜单与手机「我的」卡片立即换上新头像；如果她当时正在修改显示名但尚未提交，未保存的显示名草稿也完好保留。之后她想换一张近照，重新上传后全站各处立即更新为新照片，不会因为缓存卡在旧图；若她选择「移除头像」，确认后立即恢复为原有的首字母柔和色圆章。当她误选了超大原图、动图或非图片文件时，页面当场给出清楚的原因提示，原有头像保持不变且可重新选择。

2. **在 iPhone 原生客户端管理与查看个人头像**
   陈明习惯用手机端 Crewden 处理消息。他打开「我的」Tab，看到顶部展示自己当前的圆形头像，点进「个人资料与语言」后，可以在资料区直接点击更换头像从系统相册选图、调整方形/圆形取景构图并保存，或者将已有自定义头像移除恢复首字母圆章。整个头像操作独立生效，不会冲掉他正在编辑的显示名或语言偏好草稿；网络报错时停留在当前页提示原因，原头像不受损。

3. **团队全场景认人与清晰的人机视觉秩序**
   在「产品研发群」这种真人同事、个人助手（PA）与专业数字员工混排工作的群聊里，已上传头像的真人同事显示圆形照片头像，尚未上传的同事继续显示稳定的首字母柔和色圆章，而 PA 与专业数字员工继续显示各自标志性的角色剪影——成员扫一眼消息流就能分清“哪条是真人同事说的、哪条是数字员工交付的”。无论在一对一私聊列表、群聊消息、消息引用、话题参与者、已读回执、`@` 提及候选、侧栏穿透搜索、一级「同事」目录、点击真人头像或 `@` 标签弹出的个人名片、公司成员管理页，还是个人助手设置里的屏蔽联系人与隐私风险事件列表中，同一位真人都呈现一致的最新头像；私聊改会话名或本人修改显示名都不会弄丢已上传的自定义头像。同事更新或移除头像后，其他客户端在刷新、重连或重新打开对应视图后都能看到更新后的结果。

4. **受保护访问、弱网平滑回退与退出隔离**
   真人头像属于受保护的组织与个人资料，不生成免登录可随意抓取的公开链接：未登录访客无法访问任何真人头像，尚未加入团队的纯个人空间账号也无法窥探团队内其他成员的头像。当客户端处于离线、弱网或头像图片加载中/加载失败时，原位保持该真人的首字母柔和色圆章兜底，不出现裂图图标、空白闪烁或布局跳动。当用户在公共电脑或手机上退出登录、切换账号或切换服务地址后，上一账号显示过的自定义头像不会残留在新会话画面或本机受保护缓存中。

## 验收标准

### Requirement: 真人用户可在 Web、Desktop 与 iOS 账号资料页上传、更换与移除自定义头像

#### Scenario: 在 Web 或 Desktop 选图裁剪并立即生效
- **GIVEN** 已登录真人用户进入 Web 或 Crewden Desktop 的账号设置页
- **WHEN** 用户选择一张受支持的静态图片，在圆形裁剪预览中调整位置与缩放并确认保存
- **THEN** 新头像立即保存并在账号设置页、导航栏个人菜单及移动端「我的」身份卡同步展示，无需额外提交显示名表单
- **AND** 若用户同时有未保存的显示名修改草稿，头像保存或取消裁剪均不覆盖该草稿

#### Scenario: 在 iOS 原生端选图上传与更换
- **GIVEN** 已登录真人用户进入 iPhone 客户端「我的」或「个人资料与语言」页面
- **WHEN** 用户在资料页从系统相册选择静态图片、确认构图并上传，或对已有自定义头像再次更换新图片
- **THEN** 资料页与「我的」页顶部身份区立即更新为新头像，且不影响未保存的显示名、默认入口设备或语言草稿

#### Scenario: 移除自定义头像恢复默认首字母圆章
- **GIVEN** 真人用户当前已设置自定义图片头像
- **WHEN** 用户在 Web、Desktop 或 iOS 账号资料页执行移除头像操作
- **THEN** 自定义头像被清除，全站该用户的头像立即回退为按其显示名生成的首字母柔和色圆章，且移除入口随之收起

#### Scenario: 拒绝不受支持或超限文件并保留原状态
- **WHEN** 用户尝试上传非图片文件、损坏图片、动态图片或超出大小上限的图片，或上传请求因网络故障失败
- **THEN** 界面给出明确的可读失败提示，不覆盖用户当前已生效的头像，用户可直接重新选择或关闭预览

#### Scenario: 注册与首次引导不增加头像前置步骤
- **WHEN** 新用户完成账号注册或进入首次设备与个人助手引导流程
- **THEN** 流程不新增强制或前置的真人头像上传步骤，账号默认以首字母柔和色圆章展示，用户可随时在账号资料页按需设置

### Requirement: 全站真人身份统一展示自定义头像并保持人机视觉区分

#### Scenario: 多端核心协作场景一致呈现真人头像与人机区分
- **GIVEN** 团队中部分真人成员已上传自定义头像、部分真人成员未上传头像，且会话中同时存在个人助手与专业数字员工
- **WHEN** 用户在 Web、Desktop 或 iOS 查看会话列表、一对一私聊、群聊消息、消息引用、话题回复与参与者、已读回执、`@` 提及候选、聊天搜索联系人结果、同事目录、群内个人名片、公司成员列表或个人助手关联的真人记录
- **THEN** 已设置头像的真人成员在所有位置一致显示其圆形自定义头像，未设置的真人成员显示首字母柔和色圆章，个人助手与专业数字员工继续显示各自的角色剪影，三类身份视觉形态清晰可辨

#### Scenario: 修改显示名或更换头像后的跨端一致性
- **GIVEN** 真人成员已设置自定义头像
- **WHEN** 该成员修改显示名，或更换为另一张新头像、移除头像
- **THEN** 仅修改显示名时自定义头像保持不变；更换或移除头像后，本端立即显示最新结果，其他已授权客户端在重新同步联系人或会话后显示更新后的头像，不残留旧头像画面

### Requirement: 真人头像遵守访问授权、弱网回退与退出隔离

#### Scenario: 未登录或无可见权限时拒绝读取真人头像
- **WHEN** 未登录访客请求任意真人头像，或未加入团队的纯个人空间账号请求其他团队成员的头像
- **THEN** 请求被拒绝，不返回目标用户的头像图片内容；仅本人、同处有效团队的成员、管理成员准入的有效公司管理员，或共享可访问会话的授权查看者可读取对应真人头像

#### Scenario: 加载中、离线或读取失败时平滑回退首字母圆章
- **WHEN** 真人自定义头像正在加载、设备处于离线状态或图片请求失败
- **THEN** 头像位置稳定展示该真人的首字母柔和色圆章且尺寸与圆角不变，不出现破损图片图标、空白占位或版面抖动

#### Scenario: 退出登录或切换账号与服务后清理头像缓存
- **GIVEN** 用户曾在当前浏览器、Desktop 或 iOS 设备查看过本人或同事的自定义头像
- **WHEN** 用户退出登录、切换到另一账号或切换连接的 IM 服务地址
- **THEN** 旧会话缓存的自定义头像立即失效并释放，新会话或离线重开时不会展示上一账号或上一服务的受保护头像内容

## 范围与非目标

- **在范围**：
  - 真人账号自定义静态图片头像的服务端安全校验、标准化裁剪缩放、持久化存储、版本化更新与删除；
  - 真人头像的登录鉴权与组织/会话可见性保护；
  - Web IM、Crewden Desktop 与原生 iOS 客户端账号资料页的选图、圆形取景裁剪预览、更换与移除交互；
  - Web IM、Crewden Desktop 与原生 iOS 全站真人身份入口（导航栏菜单、「我的」、账号设置、会话列表、消息流、引用、话题、回执、`@` 提及、搜索、同事目录、个人名片、公司成员、PA 屏蔽/风险事件真人条目）的统一头像渲染、内存/本地缓存复用、弱网圆章回退与退出清理。
- **非目标**：
  - 不改变个人助手（PA）与专业数字员工现有的 24 种角色剪影形象与选择器；
  - 不为真人新增卡通预设头像库或手动配色选择器；
  - 不支持动态 GIF / 动态 WebP 头像（统一只接受静态图像并在服务端剥离元数据）；
  - 不在注册页或首次电脑/助手引导（Onboarding）中插入头像设置步骤；
  - 不为外部渠道未绑定的影子发送者（如飞书/微信外部联系人 `shadow:*`）提供站内头像上传管理。
