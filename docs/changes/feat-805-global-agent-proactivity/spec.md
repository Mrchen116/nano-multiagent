## 澄清记录

- Q1: Global Agent 主动生成的「待拍板提议卡（`proposed`）」与「主动跟进」落在哪里、找谁拍板？
  A(原话): 你看看raft的设计。看他的Agent有没有主动性？他把这些问题是怎么解决的？我感觉你把它放到个人的聊天里面，不太合理。 / 我有个想法，一个agent，他开的proposed，或者task，其实都是绑定的一个聊天会话的对不对。我们的任务系统就是这么设计的。那么他绑定的哪个会话，proposed自然就是发到哪里去啊，比如我私聊跟他说的任务，其实和群里无关，那后面他关于这个事情的主动性就是回到这个私聊。对不对，这么理解
  Agent 解读: 完全遵循 Nano 任务系统「事项绑定所属会话」的第一性原理统一闭环——**事项上下文从哪个会话来，围绕它的主动性（静默记账、待拍板提议卡、后续备料与跟进）就原路回到哪个会话去，既不生硬塞进管理者的个人私聊，也不把私聊事项外溢到群聊**：
  1. **已有对话或目标图延伸的主动事项（群归群、私聊归私聊）**：在某个项目群讨论或建立的目标，后续静默记账、前沿待拍板候选卡与跟进全部绑定回该群（及对应话题），拍板人指向该事项或目标的业务负责人（群成员在群任务中透明可见）；某位成员在 1 对 1 私聊中与该 Global Agent 交办或探讨的独立事项，任务与待拍板卡绑定在该私聊，后续围绕此事的主动提议与备料只回到该私聊，并自动进入该私聊对端成员的「待你拍板」焦点台，绝不外溢到群聊。
  2. **无既有对话源头、纯由长期角色约定自发识别的新事项**：绑定到该职责所服务的目标协作群（如角色约定中的主场业务群）；仅当该职责未关联任何群聊（如私有范围数字员工或管理者私下约定的专项职责）时，归属与绑定管理者的私聊。

- Q2: 夜间深度筹划后，Global Agent 第二天早上要不要像 PA 一样主动发消息（早报）？以及该特性是否对所有 Global Agent 默认开启？
  A(原话): OK
  Agent 解读: 采纳推荐方案——**对所有全局模式数字员工默认开启主动筹划，且次日触达比个人助手更克制（防多员工并发刷屏）**：
  1. **开启范围**：所有全局工作模式的数字员工默认开启「主动筹划」（配置页可独立关闭；单会话模式小助手不暴露、不开启）；当天无任何新增会话或任务动态时保持零唤醒、零消耗。
  2. **次日触达边界**：若目标会话本身已有约定的固定周期汇报定时安排（如每日巡检或晨会简报），则顺路合入同一条消息发出；若无固定定时安排，夜间推演出的常规待拍板候选卡仅静默挂入对应会话的任务面板等待翻牌（不单设早报闹钟刷群或私聊），仅当产出了对方近期任务急需的实质备料成果、或发现职责内有明确时效风险与阻塞时，才挂工作时段的一次性定时安排发往原会话（群聊优先回原话题）。

- Q3: 多人、多会话协作下，不同成员的反馈怎么校准 Global Agent 的主动性记忆偏好？是写进每个人的记忆页，还是形成 Agent 自己的行为准则，还是两者结合？
  A(原话): 这个我真抓不准应该是把不同人的偏好写到memory中对每个人memory中，还是形成你说这种agent自己的行为准则，还是说both？ / ok
  Agent 解读: 采用按模型可见时机切分的**「两层单源配合（主干归岗位常驻准则，协作细节归人物/项目页）」**，既避免二级页面“未触发先盲目”，又防止多人偏好撑爆常驻首页或单人误关全局职责：
  1. **常驻首页（「主动性与介入偏好」四分栏）写「岗位自身主动性准则 + 极短触发级例外指针」**：主干记录该数字员工围绕自身专业岗位的通用触发、挂卡、禁区与触达规则；当特定协作者或群聊存在必须提前获知才能决定“动或不动”的触发/禁触发边界时，仅在对应分栏保留一行带对象或会话范围限定的短条件，并附指向对应协作者或项目记忆页的链接。
  2. **协作者与项目专属页写「触发之后怎么配合」的详细画像**：具体成员偏好的汇报结构、证据颗粒度、负责模块与沟通习惯归入各自的协作者或项目页面，数字员工在决定向该对象提卡或触达后再按需读取，不在首页重复抄写。
  3. **多人反馈的作用域护栏**：绑定管理者的整体职责要求（或跨项目、跨成员多次印证的岗位经验）沉淀为岗位通用准则；单个普通协作者在私聊或针对提给自己的候选卡给出的显式要求或连续两次及以上同向拍板反馈（经后台抗噪观察池计数），仅形成针对该协作者或对应会话的局部边界与人物页更新，不越权封杀数字员工对团队及其他成员的正常岗位主动性。

## 现状与参考

### 当前现状与缺口

[产品愿景](../../product/vision.md) 将个人助手（PA）与承担专业职能的全局数字员工（Global Agent）并列为长期在岗主体：两者均拥有稳定身份、长期角色约定、文档记忆与渐进式目标图，都应在职责和授权范围内主动感知变化、提前准备并跟进事项。

经 `feat-785` 与 `feat-793` 落地后，个人助手已跑通「平时安静后轻量记账 + 凌晨统一记忆整理后深度筹划 + 待拍板候选卡 + 四档常驻主动性偏好与两次成规抗噪校准」的完整闭环；普通全局数字员工也已共用长期角色约定、九状态渐进式目标图及凌晨自然日记忆整理底座，但在主动性闭环上仍存在四处缺口：

1. **主动筹划能力仅对个人助手开放**：当前全局数字员工缺少对话安静后的自动记账与夜间围绕岗位职责向前推演的机制，一旦没有新消息或人工预设的定时任务唤醒，便停留在纯被动应答状态。
2. **缺少脱离“单一主人私聊”的多会话原路归属引导**：个人助手的所有候选提议与早报固定投向主人私聊；而全局数字员工同时参与多个项目群并与不同团队成员保持 1 对 1 私聊。另外，现行焦点台对非个人助手的 1 对 1 私聊中未显式指定拍板人的待拍板卡，尚未像个人助手私聊那样自动归入对端真人的「待你拍板」列表。
3. **缺少面向团队多数字员工并发场景的低噪触达约束**：若照搬个人助手“无固定早间任务时自动挂早报闹钟发消息”的做法，团队内多位数字员工会在清晨集中向项目群和成员私聊推送早报，造成严重噪音。
4. **专家记忆缺少主动性常驻校准结构与多人作用域隔离**：普通全局数字员工的核心记忆首页尚未维护结构化的主动性校准分区与后台抗噪观察池，无法区分“岗位全局准则”与“某位协作者在私聊中的个人免打扰边界”。

### 外部参考对照

- **Raft（源码与手册基线 `5214e34e`）**：强调团队 Agent 的工作与主动进展必须留在事项所属的业务频道与原讨论话题（Channel-first & Thread-first），不把公开项目工作转移进个人私聊；主动巡检强调先完成只读复现与证据打包（Evidence-first），区分可逆职责内直接准备与不可逆事项找领域负责人确认。但 Raft 本身没有待拍板候选卡状态与宿主内置的安静复盘/夜间筹划机制，Agent 主动立项只能先在频道发公开消息再建待办。
- **DSH Super-agent（`6337fc82`）与 Linger（`c8564edc`）**：提供推断候选事项“立项与执行分离”以及对话安静后原会话复盘、两次同向反馈成规的抗噪思路。
- **本单元取向**：复用 Nano 已验证的主会话两阶段静默运转、渐进式目标图待拍板卡与两速记忆校准底座，结合任务图天然绑定会话的设计，建立「从哪来回哪去」的多会话原路闭环、团队静默挂板策略以及「岗位主干准则 + 协作者局部画像」的分层记忆机制。

## 用户场景

### 场景一：项目群目标与同事私聊事项双轨并行，各自原路闭环且低噪触达

团队中有一位承担质量保障职能的全局数字员工 **Q**，其长期角色约定明确负责核心链路回归把关、发版风险预警与自动化用例补齐。白天 **Q** 同时在两个互不相关的会话中协作：

1. **在「#nano-发版群」中**：项目负责人 **Alice** 牵头推进长线目标 **🎯《桌面端 1.2 发版验收》**（前两阶段已完成），群内傍晚讨论了新合入的跨源权限改动。
2. **在与工程师 Bob 的 1 对 1 私聊中**：**Bob** 私下找 **Q** 一起排查自己手头一个实验脚本的偶发超时（此事与发版群无关），并提到“这周四前我得把这个脚本跑稳”。

- **傍晚对话安静后（轻量记账，零打扰）**：两边对话安静下来后，**Q** 静默把「#nano-发版群」刚确认的阶段进展和 **Bob** 私聊里的周四检查节点分别原位更新到各自会话绑定的任务与定时安排中，不在群里或私聊多嘴刷屏。
- **凌晨休息时段（记忆整理 + 岗位深度筹划，原路建卡不串线）**：凌晨夜间记忆整理完成后，**Q** 结合角色约定、最新核心记忆与两边未完结事项向前推演（全程不发半夜消息）：
  - **针对「#nano-发版群」**：围绕《桌面端 1.2 发版验收》只读核查最新合入改动，发现跨源重定向缺少断网恢复回归覆盖，于是在**发版群的该长线目标图前沿**挂出一张待拍板候选子节点 *《补齐跨源重定向断网恢复回归验证》*（指定目标负责人 **Alice** 拍板），同时将梳理好的高风险回归检查点备妥；由于发现一处可能直接阻塞次日预发包启动的配置冲突风险，安排工作时段向发版群原讨论话题发出一条精炼风险提示。
  - **针对「与 Bob 的私聊」**：围绕 **Bob** 私聊提到的脚本超时问题，在**该 1 对 1 私聊**建立一张待拍板候选卡 *《压测复现实验脚本并发超时并整理日志对比》*——这张卡严格留在 **Bob** 与 **Q** 的私聊中，绝不出现在发版群或其他成员视野里。
- **次日白天（焦点台翻牌 + 仅实质风险发消息，防马后炮）**：
  - **Bob** 早上没有收到任何机械早安问候；当他打开任务焦点台的「待你拍板」时，直接看到私聊里的那张提议卡，顺手点下 **「批准开工」**，**Q** 随即在后台单次启动压测复现并将结果回传到该私聊。
  - **Alice** 在自己的「待你拍板」和发版群目标全景图里看到前沿新芽卡片；而在 **Q** 的工作时段风险提醒发出前，若发版群里凌晨已有同事修复并说明了该配置冲突，**Q** 在唤醒时先核实群内最新消息，自动收起过时提醒，绝不发马后炮警告；若风险仍在，则在原话题发出精炼证据摘要并附上待拍板活卡片。

### 场景二：无前序聊天时基于长期角色职责自发提议，归属对应业务群

某天某项巡检并非源自某条具体聊天交办，而是 **Q** 对照自身长期角色约定（负责监控「#nano-研发群」关联主干的质量健康度）在周期检查与夜间推演中识别出某核心套件耗时翻倍。由于该职责明确服务于「#nano-研发群」，**Q** 直接在「#nano-研发群」建立待拍板提议卡（而不是塞进绑定管理者的私人聊天）；仅当另一位数字员工被配置为仅限本人使用的私有专项助手且未加入任何业务群时，其自发提议才落在与绑定管理者的私聊中。

### 场景三：多人协作下的分层记忆演化——「岗位准则是主干，个人习惯归人物页」

随着团队持续使用 **Q**，不同成员给出了各自的反馈：

- **绑定管理者划定岗位全局边界**：管理者在对话中向 **Q** 明确交代：*“未打提测标签的个人实验分支一律不要主动建回归任务卡；但只要涉及登录鉴权链路改动，主动盯紧并提醒 Alice。”* 次日夜间记忆整理后，这两条规则直接写入 **Q** 核心记忆首页的「主动性与介入偏好」（分别归入「免打扰禁区」与「积极盯紧与提前备料」，并链向 **Alice** 的协作者页面），对整个岗位持久生效。
- **协作者 Bob 的局部偏好不污染团队全局**：后来 **Bob** 在私聊中对 **Q** 提给他的候选卡先点了一次 **「不采纳」**——次日 **Q** 的常驻记忆并未草率封杀私聊提议（仅记入后台观察记录）；当 **Bob** 第二次在私聊点拒同类提议（或直接在私聊说*“咱们私聊排查时我随口提的脚本小毛病你别主动建卡，问啥答啥就行”*）后，夜间整理在核心记忆首页「免打扰禁区」仅增加一行带明确范围的短边界（*“与 Bob 私聊的临时脚本排查：仅答疑不主动立卡，协作细节见 Bob 页面”*），并将 **Bob** 偏好的简短命令行回复风格写入其个人协作页。与此同时，**Q** 在「#nano-发版群」以及与 **Alice** 协作时的主动提卡与风险预警丝毫不受影响。
- **正向触发后按需衔接人物详情**：当后续出现登录鉴权变更命中首页常驻的盯紧条件时，**Q** 顺着链接读取 **Alice** 的协作者页面（得知她希望提醒时直接附上最小复现命令与影响范围），按其习惯准备好实质摘要发往对应话题。

### 场景四：多端设置页查看与独立启停全局数字员工的主动筹划

绑定管理者在 Web IM、桌面客户端或 iPhone App 打开全局数字员工 **Q** 的配置页时，可以看到默认开启的「主动筹划」开关。当团队在特殊冻结期希望 **Q** 暂时停止自动记账与夜间提议立卡时，只需关闭该开关并保存——待执行的自动复盘与夜间筹划立即停止，已有的任务图、历史记忆、长期角色约定与人工设置的固定定时任务完整保留；单会话模式的普通问答助手配置页则不显示该开关。

## 验收标准

### Requirement: 全局数字员工围绕岗位职责两阶段静默运转，主动事项按所属会话原路闭环

#### Scenario: 对话安静后静默更新事项状态，夜间围绕角色职责推演待拍板提议
- **GIVEN** 全局模式数字员工已启用主动筹划，且当天在参与的群聊或私聊中产生了新的协作对话或事项进展
- **WHEN** 相关会话进入安静状态，以及随后到达夜间休息时段并完成当夜自动记忆整理
- **THEN** 平时对话安静后，数字员工静默将已明确的事项进展与时间节点更新到对应会话的任务与定时安排中，不在成员连续交流时插话打断
- **AND** 在夜间记忆整理完成后，数字员工结合长期角色约定、最新核心记忆与未完结目标做无外部副作用的查证准备，生成有界的待拍板提议卡，夜间全程不主动发送聊天消息打扰成员

#### Scenario: 群聊目标与私聊事项各自回到原会话并进入对应成员焦点台
- **GIVEN** 同一全局数字员工既在项目群参与团队目标协作，又与某位成员在 1 对 1 私聊中沟通与群无关的独立事项
- **WHEN** 数字员工围绕两处上下文分别生成待拍板提议卡或跟进准备
- **THEN** 源自项目群目标或群讨论的待拍板提议卡归属该群及对应目标图，指向相关业务负责人拍板（出现在该负责人的「待你拍板」焦点台且群成员可在群任务中查看）
- **AND** 源自 1 对 1 私聊事项的待拍板提议卡与后续跟进严格留在该私聊中，自动出现在该私聊对端成员的「待你拍板」焦点台，不泄露或串入任何群聊与其他成员视图

#### Scenario: 无前序对话时按长期角色职责归属目标协作会话
- **WHEN** 全局数字员工依据长期角色职责自发识别出尚无具体前序对话的候选事项
- **THEN** 待拍板提议卡归属该职责所服务的目标业务群；仅当该数字员工或该项职责未关联任何协作群聊时，归属与绑定管理者的私聊

#### Scenario: 无新增动态或仅日常寒暄时保持零唤醒与克制
- **WHEN** 全局数字员工全天无新增对话或协作动态，或当天仅有日常寒暄而无职责相关缺口与新线索
- **THEN** 无新增动态时夜间不产生深度筹划唤醒；仅日常寒暄时不强行生成待拍板提议卡

### Requirement: 常规提议静默挂板防刷屏，实质成果或时效风险按原会话低噪触达

#### Scenario: 无固定汇报安排时常规提议静默挂板，实质备料或高优风险按需触达
- **GIVEN** 目标会话未设置固定周期汇报定时任务，且全局数字员工在夜间筹划中产出了候选结果
- **WHEN** 产出仅为非紧急的常规待拍板提议卡，或产出包含近期目标急需的实质准备材料与职责内明确时效风险
- **THEN** 常规待拍板提议卡仅静默挂入对应会话的任务面板等待相关负责人翻牌，不发送个人式早安问候或例行早报消息刷屏
- **AND** 仅在存在急需的实质准备成果或明确时效风险与阻塞时，才安排在工作时段向原会话（群聊优先回到原讨论话题）发送精炼说明并附带可交互任务卡片

#### Scenario: 目标会话已有固定周期汇报安排时顺路合并送达
- **GIVEN** 目标会话已设置固定周期汇报定时任务，且夜间筹划针对该会话产出了实质准备材料或待拍板提议卡
- **WHEN** 到达该固定周期汇报的触发时间
- **THEN** 数字员工在同一条汇报消息中顺路呈递准备好的要点、文件附件或待拍板任务卡片，不重复建立额外的早间提醒

#### Scenario: 定时触达前核实原会话最新进展，避免过时催办
- **GIVEN** 全局数字员工有即将触发的定时跟进或风险提醒
- **WHEN** 团队成员此前已在原群聊、话题、私聊或任务面板中先行处理、更新或关闭了该事项
- **THEN** 数字员工在发言前核实会话与任务的最新状态并静默收口，不再发送滞后的马后炮提醒或重复询问

#### Scenario: 双端翻牌处理待拍板提议且未获批前不越权执行
- **GIVEN** 全局数字员工在群聊或私聊中生成了待拍板提议卡
- **WHEN** 相关成员在 Web IM、桌面客户端或 iPhone App 点击「批准开工」「先存着」或「关闭」，或在原会话中用自然语言明确同意或拒绝
- **THEN** 批准且由该数字员工负责、前置条件已满足的事项立即单次启动推进；「先存着」安静留存不再催问；关闭后移出待拍板区；未经批准前不自动执行对外发送、修改共享外部资源或代人承诺，已被后续对话解决或过时的旧提议自动收起

### Requirement: 多人协作反馈按「常驻岗位准则 + 协作者专属页面」分层校准且作用域隔离

#### Scenario: 绑定管理者明确规矩或跨事项共识沉淀为常驻岗位准则
- **WHEN** 绑定管理者针对全局数字员工的整体职责明确提出主动性边界或触达时机要求，并完成夜间记忆整理
- **THEN** 核心记忆首页的「主动性与介入偏好」四类标准分栏直接收录该岗位级规则，在后续跨窗口对话、安静记账与夜间筹划中持续生效

#### Scenario: 单个协作者的反馈抗噪计数并按作用域隔离，不关停团队全局职责
- **GIVEN** 某位协作者在 1 对 1 私聊或针对提给自己的待拍板提议卡给出反馈
- **WHEN** 该协作者仅单次点击「不采纳」，或随后明确提出个人免打扰边界 / 跨事项累计两次及以上给出同向拍板操作并完成夜间记忆整理
- **THEN** 单次未采纳操作仅进入后台观察记录，不立即封杀同类提议
- **AND** 明确个人边界或累计满阈值后，核心记忆首页仅记录带该协作者或该会话限定条件的简短触发边界，详细的个人沟通与交付偏好归入该协作者的专属记忆页；该数字员工在其他项目群及对其他成员的正常岗位主动性保持不变

#### Scenario: 命中常驻正向触发条件后按需读取协作者或项目详细约定
- **GIVEN** 核心记忆首页记录了某类事项或模块的正向盯紧条件，并链接到对应协作者或项目记忆页
- **WHEN** 全局数字员工观察到匹配的变化并准备推进备料、建卡或发送提醒
- **THEN** 数字员工按链接读取对应协作者或项目页面中的具体交付要求与沟通习惯，并据此组织准备材料与提醒内容

### Requirement: 全局数字员工默认开启主动筹划并支持在多端设置页独立启停

#### Scenario: 全局模式默认开启与设置页启停控制，单会话模式不启用
- **WHEN** 管理者创建或打开全局模式数字员工的配置页（Web IM、桌面客户端或 iPhone App），或切换其「主动筹划」开关并保存
- **THEN** 满足任务图能力前提的全局模式数字员工默认开启「主动筹划」并与任务图特性保持依赖联动；关闭并保存后立即取消待执行的自动静默记账与夜间深度筹划，停止后续自动提议立卡，同时完整保留已有任务图、正式记忆、长期角色约定与显式定时任务；重新开启后按最新状态恢复
- **AND** 单会话模式的助手不显示且不启用「主动筹划」能力；当所属节点离线时，设置页保持只读状态保护，不允许写入未校验变更

## 范围与非目标

- **在范围**：
  - 将「主动筹划」能力从个人助手扩展至所有全局工作模式（`global`）的数字员工（默认开启，多端设置页可独立启停，存量配置平滑兼容）；
  - 全局数字员工主会话的两阶段静默运转（对话安静后轻量记账 + 凌晨记忆整理后围绕长期角色约定与活跃目标深度筹划）；
  - 按事项所属会话（项目群、话题、1 对 1 私聊）原路闭环建立待拍板提议卡与跟进安排，补齐与全局数字员工 1 对 1 私聊中待拍板卡自动进入对端成员「待你拍板」焦点台的体验；
  - 团队低噪触达策略（常规待拍板卡静默挂板、有固定汇报定时任务顺路合发、仅实质急需备料或明确时效风险在工作时段发原会话/话题，唤醒前核实最新未读防马后炮）；
  - 全局数字员工记忆库的「主动性与介入偏好」四档常驻专区、后台抗噪观察池、结构卫生校验，以及「岗位全局准则 vs 协作者/会话局部作用域 + 协作者/项目详情页」的分层演化规则。
- **非目标**：
  - 不为单会话模式（`single_thread`）助手开启跨会话主动筹划；
  - 不赋予普通全局数字员工类似个人助手的跨人私密会话旁观权限（全局数字员工仅基于自身有权限参与或访问的会话、任务与工作区运作）；
  - 不改变现有正式记忆单写者边界，也不在本单元处理长会话无摘要换窗与凌晨记忆整理之间的通用白天记忆衔接问题（归属既有独立议题 `#557`）。
