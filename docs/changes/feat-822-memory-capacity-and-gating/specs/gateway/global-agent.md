# gateway - Global Agent Delta Specification

> Target: `docs/specs/gateway/global-agent.md`

## MODIFIED Requirements

### Requirement: 全局数字员工围绕岗位职责执行两阶段静默运转、原会话归属与低噪触达

对工作模式为 `global`、非个人助手（`!personal`）且启用 `proactive_planning` 的数字员工，宿主复用同一主会话执行平时对话安静后的轻量记账与凌晨标准 `Dreaming` 之后的每日一次岗位深度筹划，不拆脱离主会话上下文的孤立短期小会话，也不授予个人助手专属的跨人私密会话旁观或代表用户发言权限；新建全局模式数字员工（含配置页、REST 接口省略技能列表及 PA 聊天创建）默认启用内置 `nano-proactive-care` 供根主会话按需加载，当关闭 `proactive_planning` 或用户显式禁用该 Skill 时同步隐藏该 Skill 及其加载提示。日常协作与主动唤醒全程遵守常驻 `MEMORY.md` 中受配额保护的「主动性与介入偏好」四档校准（含岗位通用准则与带协作者/会话范围限定的局部触发边界，复杂岗位主动细则可下沉至 `knowledge/proactivity-policy.md`，具体人物与项目详情按需读取 `entities/` 或 `projects/`），且不读取后台观察池 `knowledge/proactivity-signals.md`。

#### Scenario: 平时对话安静后按来源会话原位轻量记账，零自激循环
- **GIVEN** 全局数字员工启用了主动筹划且未处于停用状态
- **WHEN** 其在参与的群聊、话题或 1 对 1 私聊中收到范围内的新增真人消息或需关注的同级 Agent 协作消息，随后进入安静空闲期
- **THEN** 宿主在安静满静默窗口时向其主会话提交轻量记账隐藏唤醒 `proactive_review`（主会话忙碌时保留水位待空闲重试；主动唤醒自身回合、被动 `task_graph` 系统通知、定时与记忆维护轮次不推进活动水位，全天无新增协作动态时保持零唤醒；尾部唤醒消息按需附带较窗口首轮快照有更新的 `MEMORY.md` 与已保存的 `knowledge/proactivity-policy.md` 正文）
- **AND** 主会话仅将已明确达成的事项进展或具体检查时间原位更新至各自事项所属会话（`conversation_id`）的 `task_graph` 与原生 `schedule` 中，对常驻免打扰禁区（含特定协作者或会话禁区）保持零记账，不做发散立项；除有效非安静时段内发现约一小时内紧急阻塞/冲突可向原会话简短提示一句外，保持静默结束

#### Scenario: 凌晨紧随标准夜间 Dreaming 之后围绕岗位职责与原会话建立待拍板提议
- **GIVEN** 全局数字员工启用了主动筹划且未处于停用状态
- **WHEN** 进入有效时区凌晨休息窗口（默认 `03:00–06:00`），自上次夜间筹划以来存在新增协作活动且距最近活动已满夜间安静门禁
- **THEN** 若该数字员工启用了自动 `dreaming` 且当夜自然日槽位的标准 `Dreaming` 尚未完成检查（含实际完成整合，或因未满最小增量门槛静默延后并标记当夜检查完成），在连续失败未达上限且重试时间未越过凌晨窗口截止前，宿主非阻塞等待当夜 `Dreaming` 先完成当夜周期评估（关闭 `dreaming` 或重试越界时直接降级放行），随后提交每日最多一次的 `proactive_nightly` 唤醒并在尾部按需附带较窗口首轮快照有更新的最新 `MEMORY.md` 正文与已存在的 `knowledge/proactivity-policy.md` 策略细则
- **AND** 主会话结合已确认 `ROLE.md`、最新 `MEMORY.md`（及附带的 `proactivity-policy.md`）与活跃目标图做无外部副作用的只读核查与工作区备料，先收起已解决或过时的旧 `proposed` 卡（不伪造人类未采纳反馈），再按事项来源原路建立有界数量的 `proposed` 待拍板提议卡：源自项目群目标或群讨论的候选卡绑定回该群及对应目标图并指向相关业务负责人（`proposed_for_user_id`）；源自与某成员 1 对 1 私聊的独立事项严格绑定在该私聊而不外溢至群聊；无前序对话、纯依据 `ROLE.md` 长期职责识别的新事项绑定至该职责服务的目标业务群，仅当该职责或该数字员工未关联任何协作群聊时归属与绑定管理者的私聊；当日仅有日常寒暄而无职责缺口时建立零张提议卡，夜间全程不调用 `send_message`

#### Scenario: 团队低噪次日触达与已有周期汇报顺路合并
- **GIVEN** 全局数字员工完成了夜间深度筹划
- **WHEN** 目标会话已存在固定周期汇报定时任务，或目标会话未设置固定周期汇报定时任务
- **THEN** 若目标会话已有固定周期汇报 `schedule`，主会话不另建提醒闹钟，而是将夜间准备好的要点摘要、工作区文件路径与 `task_cards` 引用按目标会话记入持久 `notes` 交接项，在该周期汇报触发时顺路合入同一条消息发出并清理交接项
- **AND** 若目标会话无固定周期汇报安排，常规 `proposed` 待拍板提议卡仅静默挂在对应会话的任务面板等待相关负责人翻牌（不发送个人式早安问候或例行早报消息刷屏）；仅当产出了近期活跃任务急需的实质准备成果或发现职责内明确时效风险与阻塞时，才创建工作时段一次性 `schedule` 发往原会话（群聊优先回到原讨论话题 `<chat_id>:<root_id>`）

#### Scenario: 定时触达前核实未读收件箱与任务最新状态，避免马后炮提醒
- **GIVEN** 全局数字员工的主会话由原生 `schedule` 定时唤醒准备发送跟进或风险提醒
- **WHEN** 团队成员此前已在原群聊、话题、私聊（含尚未到达十分钟普通群合并提醒窗口的新消息）或任务面板中先行修复、回复或完结了该事项
- **THEN** 宿主在进入模型首步前刷新本地未读收件箱摘要，并在存在未读会话或话题时提示主会话先读取相关未读内容；配合目标会话/话题自身的发送前复核（`held_for_revalidation`），主会话核实最新进展后原位收口对应任务并静默结束，不发送滞后的马后炮提醒
