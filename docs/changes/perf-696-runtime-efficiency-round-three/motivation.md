# perf-696：第三轮运行开销修复

## 来源与目标

用户要求完成三轮独立检查、批量修复、验收与合并；每轮从前轮合并后的 main 开始，第三轮合入后再核对最终主干。本轮基线为第二轮 PR #449 合并后的 0e8c468019a909ad362dd338958f8921108c4729。继续保持产品契约，复用已有查询与职责，不为假设边界增加长期状态。本次后台优化沿用用户仅对本次授权的工程验收，不改变通用流程。

## 已确认的剩余热点

| 场景 | 实测问题 | 本轮范围 |
|---|---|---|
| 300 条已完成知识整理记录、1,000 会话绑定 | 下一次 turn-end 仍解码 300,000 绑定，Work 无新增 | 复用 bindingForSession |
| 20 工作流结果、3,000 旧输入、1,000 绑定 | 20,000 绑定及 60,000 输入解码，78.5 MB JSON | 定点绑定与来源 ID 查询，保留最早入站与旧会话 |
| 普通工具未启动子 Agent | 1 万旧事件、25 次工具执行产生 25 个完整快照 | 仅在实际 child start 时计算原工具序号 |
| 正常成功且无 fallback | 25 轮额外遍历 250,650 事件检查 tool | 仅可能重试时检查已执行工具 |
| 10 万已处理 PA 来源事件、100 次 message.delta | 每次发布全扫描来源历史，共约 181 ms | 来源 event ID 索引 |
| 其他 root 累积 50 万 Work 事件 | 目标仅1轮，完整 view 约13.3 ms | root 索引 |
| 100 次成员变更 | 100 次列表请求；最旧回包可将移除聊天写回缓存 | 合并突发，读取期间新变更要求更新的权威结果 |

量级为隔离合成数据，不能作为生产时延或规模声明。前两轮修复已由三路审计复核，计数仍有效。

## 明确保留的边界

Work.query 固定 snapshot 续页仍重新物化当前消息 ID；5 万消息、返回20条约48 ms。已测得开销，但安全改法涉及固定快照、当前资格、part/around 语义，本轮不将其扩成查询重构，不宣称它已解决。Heartbeat 重复 ensure 与其他全历史恢复读也不因表面重复而删除。没有确认新增运行资源泄漏；不冒充故障演练或生产验收。

## 成功标准

原始来源、消息/分页次序、权限、交付回执、fallback 与轨迹因果不变；成员缓存遵守已有最新权限契约。定向与适用完整验证、独立 code/context review、远端 CI 通过后合入，并在最终 main 复核三轮改动。
