# 聊天历史使用轻量过程摘要

## 方案

- 浏览器历史页显式请求 `view=summary`。旧默认仍完整返回；已结束回复的摘要返回过程条数、运行状态、已裁定允许/拒绝数和回复过程分类型计数。中心查询只投影这些轻量字段，不把工具正文或思考过程装入 JS。普通消息正文、附件、引用、互动卡、时间线分界、投递和审批卡仍返回。运行中的消息保留实时合并所需的完整过程。
- 增加 `GET /im/v1/conversations/:conversation_id/messages/:message_id`。经同一会话 read 鉴权后按会话 ID 和消息 ID 联合定位，返回同一条完整消息及执行清理 revision。Web 在现有折叠面板首次展开时读取，加载态、失败与重试保留该行及摘要，收起后可以复用当前权限和 revision 下的已加载详情。旧客户端历史默认与新详情权限写入 [消息契约增量](specs/im/conversations-messages.md)。
- 当前 URL 的会话详情与消息请求独立启动，不等侧栏。当前详情的拒绝优先于任何旧侧栏缓存，未获当前读取资格或在切换时不渲染先到的消息页。写入仅使用当前详情提供的写权限，订阅仍受既有恢复资格约束。详情缓存按账号、会话、消息与执行清理 revision 隔离，撤权或清理后取消并清除对应请求和缓存，丢弃旧 revision 的迟到响应。相同 revision 的摘要刷新保留已获取的完整过程与更新的实时片段。

## 验证安排

独立代码审查校验 DTO、普通浏览器历史、消息审批、跨会话权限与实时合并。隔离 E2E 对照 50 条普通与工具富消息的响应字节、首次消息请求启动与工具展开请求。覆盖老客户端、只读观察者、审批卡、控制分界线、滚动分页、旧侧栏与详情拒绝交错、执行清理、刚完成消息遇到摘要刷新和过期详情迟到。前端自检看折叠统计、加载、失败重试和收起后的显示。
