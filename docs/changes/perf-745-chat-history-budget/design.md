# 聊天历史使用轻量过程摘要

## 方案

- 浏览器历史页显式请求轻量视图。兼容入口保留完整返回；中心轻量查询不把已完成回复的工具正文或思考过程装入 JS。消息正文、附件和引用、互动卡、消息顺序、分界线、投递和权限卡继续按既有格式返回。用明确的过程存在标记驱动既有折叠入口。运行中消息保留实时过程合并所需的数据。
- 展开时由已鉴权的会话消息详情入口读取同一条消息的完整过程。按会话和消息 ID 缓存，保留刷新、权限收回、实时消息合并和折叠后的状态。完整工具过程按现有面板呈现，不新增界面。
- 当前 URL 的会话详情和历史请求通过现有独立授权接口启动，无需等侧栏。渲染、订阅和写入仍遵守实际读写资格，拒绝访问、换会话和取消时不能显示错误会话的已缓存数据。侧栏本轮保持原有可操作范围，不替换成员授权契约。此项为现有历史契约的性能实现，无 canonical delta。

## 验证安排

独立代码审查校验 DTO、普通浏览器历史、消息审批、跨会话权限与实时合并。隔离 E2E 对照 50 条普通与工具富消息的响应字节、首次消息请求启动与工具展开请求。覆盖老客户端、只读观察者、审批卡、控制分界线和滚动分页。前端自检看展开入口及加载态。

| Milestone | 依赖 | 文件范围 | 退出标准 |
|---|---|---|---|
| M1-history | 无 | 中心历史 API、Web 聊天/面板、消息 DTO 与回归 | [reviewer] 侧栏慢时当前聊天可读、过程完整可展开。[worker] 历史页工具负载不含明细，旧入口兼容，权限和实时更新回归。 |
