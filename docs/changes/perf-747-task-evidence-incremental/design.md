# 模型前置只确认新 Task 证据

## 方案

- DSH TaskContextDriver 保持每个当前 Agent 会话最后一次已确认的 native cut 和开放轮上下文，只用该 cut 之后的事件派生原有精确证据。只有 Gateway 已完成消费对账的 prepare 或 commit 才推进。授权不可用、取消和失败不能推进；重复按现有 input ID、原文摘要和消费位置去重。首次冷进程从原生历史恢复，冷前缀按页发内部确认，随后稳定步只读增量，页大小有字节和事件预算。
- 保留 Gateway 对原始 Task 消息、权限和撤销的检查；同一 Agent 的授权同步只合并在同一 authority cut 发出前到达的调用，cut 开始后抵达的调用进入下一个 cut。每个会话单独校对输入、消息来源和生命周期。禁止用时间 TTL 绕过撤权。内部确认和新增模型上下文分开，确保晚到撤销仍能移除已领取但未执行的输入。
- 消费者仍是下一模型步及独立审批。模型继续收到同样的原文、来源、撤销和停止事实，变化仅在宿主确认和网络传输；启动或断线不得漏发原有待消费事实，无 canonical delta。

## 验证安排

结合性能、独立代码与 Agent Context 审查。跑真实 DSH 模型 fixture 验证旧历史、跨页、撤权、落盘、重启、ACK 丢失和并行同 Agent 请求。对照相同历史的每步 RPC 字节和调用次数，分别记录冷恢复和热步。

| Milestone | 依赖 | 文件范围 | 退出标准 |
|---|---|---|---|
| M1-task-cut | 无 | DSH TaskContextDriver、Gateway TaskContext 及测试 | [reviewer] 原文和最新撤权在正确模型步出现。[worker] 历史不会在稳定热步重发，失败不丢失确认、重连重放幂等。 |
