# 节点按可恢复义务激活会话

## 方案

- 单线程入口先处理 Agent 级未完成控制，再按本地已持久的未提交/未核验输入、未终结交付和审批收据识别候选。真实义务继续走现有 ensure、提交和去重，外部重连限定当前 channel；已停用保持不可激活。新输入走现有按需 ensure。
- 对仅在 DSH 落盘、Gateway 尚未知道的原生触发，保留可发现的持久证明。利用原生持久会话查询冷检查必要的未知状态，不以进程内 opaque revision 跨重启比较或仅以文件字节数判定。优先选择可从实际触发的持久责任表安全枚举的候选；未获证明的旧绑定走只读补核，限制并发且不挡新请求，只有存在恢复事实才激活。实现独立核对原生定时、Task、审批和状态端点。
- 继续复用现有投递状态、持久身份、过期/中断和停用语义。历史可读，未完成执行是否继续仍由现有原生生命周期控制，无 canonical delta。

## 验证安排

独立代码审查与恢复旅程验证。构造千个 idle 绑定和少量在途输入、失去 ACK 的交付、审批和原生触发，分别记录 reconnect、cold restart 到接新请求、ensure 数、读入字节和堆。核对历史按需访问、重试、权威证明缺失、外部范围和停用。

| Milestone | 依赖 | 文件范围 | 退出标准 |
|---|---|---|---|
| M1-recovery | 无 | Node 恢复入口、PA 状态查询和 DSH 冷观测测试 | [reviewer] 节点能接新输入，历史可读、真实恢复义务无遗漏。[worker] 空闲绑定不批量 activate，证明缺失和重试失败边界有实证。 |
