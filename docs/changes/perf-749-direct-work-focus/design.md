# 直接展开真实 Work 轮次

## 方案

- 中心保留已授权的 Work 消息映射，支持 opt-in 返回确切目标轮次的轻量摘要。按根 Agent、消息 ID、revision 使用 message_sent 部分索引；目标摘要复用正常轮次摘要序列化并携带其原生展示顺序位置。资格撤销及已删除映射仍使用现有路由检查。
- Web 用首次 Work 响应定位。目标不在已加载列表时，将其摘要与当前列表按持久位置合并并展开，复用现有按轮次读取明细。缓存已访问的锚点，在加载普通分页时按会话和轮次去重。连续的分页游标只由普通列表计算，旧锚点不会跳过中间历史。历史主执行仍打开关联执行区域。没有锚点时可随原有刷新取得后续关联。
- 保留正常最新优先顺序、普通更早按钮和轨迹切换时阅读位置。该行为兑现既有 Work 锚点契约，无 canonical delta。仅当隔开数页的已定位轮次与普通列表同时可见时，标出尚未加载的中间位置；继续用普通分页。没有新增交互路径。

## 验证安排

独立代码审查核对锚点、旧主执行、鉴权和未完成同步。性能使用至少 1,000 轮的隔离 Work fixture，比对 HTTP 次数和返回摘要数量。Web 回归覆盖新旧锚点互跳、折叠、常规分页与精确目标。前端体验自检关注跳转后目标和中间记录可达性。

| Milestone | 依赖 | 文件范围 | 退出标准 |
|---|---|---|---|
| M1-focus | 无 | 中心 Work 查询、Web Work 面板、相关测试 | [reviewer] 老回复立即展开正确轮次，其他历史可正常翻阅。[worker] 请求数与锚点深度解耦并保留权限、折叠、缓存去重。 |
