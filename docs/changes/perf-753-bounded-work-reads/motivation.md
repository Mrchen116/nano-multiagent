# perf-753 · 有界 Work 首屏与旧记录回看

## 原始诉求

> 一个gateway大概最多有50个agent。不考虑单thread模式的agent。用户大概1000人，轨迹就非常大了，一个agent可能持续运行一年。这个过程中自然也会开无数的subagent。我觉得你要以这个基准去考虑问题，去考虑优先级。
>
> 那就按这个优先级开始修，三个 P0 都要解，怎么拆 PR、怎么排节奏你自己定

## 现状和目标

中心在每个主轮次 summary 中复制所有关联执行；10 万关联执行、主轮次 20 条的隔离样本得到 17.8 MB。Web 更新会重新请求所有加载过的历史页。常规首屏只交付可见摘要，历史关联执行独立分页并能按真实 ID 定位，实时更新只请求工作区当前需要的头部或详情。大记录上传作为同一个 P0 的独立交付，不耦合客户端改动。

### Requirement: 历史与实时 Work 同时可检查

#### Scenario: 查看历史量很大的 Agent
- **WHEN** 用户打开 Work、向前翻轮次或从委派工具跳到旧子执行
- **THEN** 可以逐步看完整记录，准确进入相应执行且权限保持不变，单次读无需传输整个目录。

#### Scenario: 阅读旧轮次期间到达更新
- **WHEN** Agent 产生新事实且用户停在旧轮次
- **THEN** 新事实继续可见，已读历史和展开位置保留。
