## 已有决定与范围解释

- 本次直接在独立 worktree 更新并提 PR，沿用用户明确授权，不重新启动 Skill 工作流。
- 附件要求审计工作区内所有 Skill 及支持材料；不能只假设某个固定目录，也不能只给建议。
- 本次补写 spec 是对既有需求的记录，不授权扩大产品功能、修改全局 Skills、合并 PR 或部署。
- 下文用户场景与验收条目是对上述原话及附件的整理，不是新增澄清答复。

## 背景与目标

工作区 Skill 同时承担触发选择、领域知识和执行约束。历史入口中的重复提醒、固定推理步骤、无条件文档加载和固定模型/代理配方，会让能力更强的模型仍按冗长流程工作，也增加误触发和上下文开销。

本次希望使用者仍能获得原有能力和真实约束，同时让模型自主选择实现路径。入口主要表达目标、激活边界、关键不变量、完成条件和按需资源；领域知识保留，通用微操要求删除或精简。不为追求字数更少改变 Skill 的能力含义，也不预设缩减比例或模型效果指标。

## 用户场景

1. 维护者希望一次看清工作区实际存在的 Skill、别名、副本和配套资源，知道每项被修改、保留或排除的原因，而不是只得到常见目录的局部检查。
2. 使用者提出一个具体任务时，模型能选中与对象和动作匹配的 Skill；普通代码修改、当前 Gateway 会话回复等任务不会因为宽泛关键词而启动无关流程。
3. 模型进入某个 Skill 后，能从精简入口得到当前任务所需约束。只有遇到相应对象、操作或问题时才加载详细知识；无需先读全部参考、固定写计划或反复核验已有效的结果。
4. 涉及生产、数据、权限、兼容性或仓库交付要求时，精简后的 Skill 仍保留这些真实边界。维护者可以从 PR 和审计报告核对它们，而不是靠“强模型会自行处理”的假设。
5. 维护者通过一个可审查 PR 接收更新，能查看每个入口的前后尺寸、删除内容、知识迁移和残留问题；已有工作不被覆盖，也不把静态验证冒充模型效果实验。

## 验收标准

### Requirement: 完整清点实际工作区 Skill 体系

#### Scenario: 存在多个入口、支持目录与副本

- **WHEN** 审计工作区 Skill。
- **THEN** 清点涵盖所有发现的 SKILL.md、引用材料及所属 references、scripts、assets、模板、示例和辅助文档；相关 AGENTS 仅用于核对触发或执行约束。
- **AND** 能区分维护源、软链接别名、其他 checkout 副本、运行态和归档材料，不将重复路径计为独立能力。

#### Scenario: 某项内容不适合直接改写或提交

- **WHEN** 发现本地定制、运行态副本或冻结历史。
- **THEN** 报告列出该项的处理方式与理由，不静默遗漏，也不将它擅自提升为新的维护源。

### Requirement: 触发边界明确且不无故改变能力

#### Scenario: 相邻 Skill 对同一领域有不同职责

- **WHEN** 检查 name、description 和入口。
- **THEN** description 说明具体能力及激活情境，区分容易重叠的对象与动作；不会仅因宽泛领域关键词触发。
- **AND** 保留已有能力、身份和兼容性要求；确需改变能力含义时，有明确理由并在报告中说明。

### Requirement: 入口按需披露，减少不必要上下文

#### Scenario: 正常调用只需要部分领域知识

- **WHEN** 模型使用某个 Skill。
- **THEN** 入口提供目标、重要约束、完成条件及可发现的资源指引，并说明何时需要相应参考。
- **AND** 不要求无条件加载全部文档，也不把移出的微操指令改成另一份每次必读的大文件。

#### Scenario: 需要具体参数、模板或确定性操作

- **WHEN** 当前任务确实需要详细知识或工具。
- **THEN** 原有有价值的领域知识、模板、示例和脚本仍可访问；迁移后不存在失效的实际文件导航。
- **AND** 可靠重复逻辑优先复用确定性工具；不为替代简单说明而新增脚本。

### Requirement: 删除微操，保留真实边界

#### Scenario: 指令只是在固定模型的推理方式

- **WHEN** 发现强制详细计划、固定探索顺序、反复提醒、重复验证、固定模型/代理配方或历史补救性要求。
- **THEN** 无真实项目依据的部分被删除或改写为结果约束，执行路径由模型按任务决定。
- **AND** 与改动相关的验证通过、请求行为已满足后可以结束，不为固定轮次或假想问题反复审查。

#### Scenario: 限制对应安全、产品或用户要求

- **WHEN** 某条限制承载真实安全边界、架构、兼容性、数据完整性、仓库惯例、不可逆操作保护或用户明确的流程要求。
- **THEN** 精简后仍保留它；无法确定是领域约束还是模型补救时，优先保留并写清，必要时列为待判断项。

### Requirement: 交付可审查且证据不过界

#### Scenario: 完成更新与提交

- **WHEN** 交付本次需求。
- **THEN** 改动位于独立 worktree 并通过 PR 提供，保留原主仓的无关 tracked/untracked 内容。
- **AND** 每个改写入口经过复读，检查触发、上下文加载、约束、资源可达性与重叠；完成适当的语法、文档、契约和打包验证。

#### Scenario: 维护者查看结果

- **WHEN** 阅读审计报告和 PR。
- **THEN** 能查看修改清单、每个入口的近似前后尺寸、删除要求、迁移去向、触发变化、保留约束及需人工判断的遗留项。
- **AND** 尺寸写明统计口径；未进行的真实调用、模型对照或触发率实验不被声称已通过。

## 范围与非目标

**在范围：** 工作区 Skill 及支持材料的发现、审计、直接改写、触发收窄、按需拆分、去重与矛盾处理、引用修复、适当验证、结果报告、PR，以及本次追加的 unit spec。

**非目标：** 新增业务能力；无依据改变 Skill 语义；以强模型为由删除真实约束；新建巨型共享必读规则；修改应用源码（维护已有 Skill 脚本确需的情况除外）；更新用户全局 Skill 安装；生产部署或 PR 合并；承诺未经实验的 GPT-6 效果提升。

## 已实施范围与证据关系

首轮审计发现 54 个不同入口，改写其中 46 个维护源，其他 8 个本地/运行态/归档入口保留并列出原因。这是本轮实现的实际处理选择，不是把原始“审计全部”要求改成“只审计已跟踪文件”。

审计报告中的 86.9% 是入口 UTF-8 字节的实测缩减；34 项相关测试、文档检查和首轮 PR CI 是对应提交的验证结果，均不是新的需求门槛，也不能替代尚未进行的真实模型效果实验。后续提交与 CI 状态以 PR 最新记录为准。
