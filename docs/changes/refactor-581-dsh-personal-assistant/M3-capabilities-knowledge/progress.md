- `/new` now reserves a new native Session identity in the same product chat, cancels the current turn, preserves old history and its delivery target, advances the canonical heartbeat binding, and records the command identity so a duplicate does not reset twice. The command is not submitted as model input. The regression failed against the former prompt-only behavior and passes after the change.

- Explicit empty-tool selection failed in a real DSH profile test (30 tools remained). Native inherited-tool restrictions and the controlled native filesystem Skill provider are being wired to the per-Agent configuration.
- Node runtime now maps both selections and the existing workspace/global/compatibility Skill roots. Candidate catalogs remain independent of selected runtime views; HTTP capabilities and draft prompt preview passed against the isolated running Node + DSH + IM (`capability-smoke-evidence.json`). Preview applies draft configuration in a disposable native Agent and does not mutate the live Agent.
- Owner `~/.nanoassistant/plugins.json` and workspace `.nanoassistant/plugins.json` declare native Cordis modules/configuration. Shared plugins mount once on the host; workspace plugins mount under the Agent preset. Actual same-name override, Agent isolation, native `UNKNOWN_TOOL`, PTC SDK subset dispatch and cold recovery pass in an unmodified official profile. Empty selections also withdraw the reserved PTC transport using the native presentation API. These are trusted native declarations; third-party Skill contributors must use the selected-provider adapter rather than registering an unrestricted provider.
- A real busy-turn regression proves revocations apply before idle, including cached Skill catalogs; additions and prompt changes wait for idle. Full workspace build and 42 tests passed before the additional PTC assertion; the updated real-profile capability tests passed afterward. Final integration validation remains pending.

- The single Nano Auto consumer selects Nano's pinned two-stage rules or DSH's pinned risk rules, using the configured approval model through native LLM/pre-execute/approval APIs. Delegated review context is captured at creation and persisted instead of rereading a changing parent.
