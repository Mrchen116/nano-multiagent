## 已确认的目标（汇总）

- DSH 承担通用 Agent 运行与工具能力；减少本仓重复开发和维护这些能力的负担。
- DSH源码零改动：仅使用公开插件/服务接口，不维护上游fork、源码patch或运行时私有方法替换。
- 现有Feature分别具有可独立启停、撤销影响的插件生命周期；关闭保留已有数据。
- 后续只迁移、发展个人助手产品，停用自研 Coding CLI。
- 优先复用 DSH 原生机制；小幅体验差异集中说明并确认，避免为可接受差异重新造轮子。实质功能/保证变化仍须用户确认。
- Workflow 的暂停／继续、指定运行中子任务重启、完成前缀复用、共享 output-token 预算必须保留。
- Workflow脚本采用DSH的JavaScript，不再另维护受限Python Workflow执行器。
- Workflow保存/发现/按名调用与原有一层嵌套继续保留。
- LLM Auto默认沿用Nano当前审批规则，并支持通过配置切换DSH默认规则。
- 自建工具接入选A：DSH标准格式，全局共享/workspace局部两层都保留，同名workspace优先。
- 记忆与Skill自动整理必须迁移保留，包括现有管理、使用记录、自动维护与生成启用的行为；复用DSH执行基础，迁移Nano策略。
- 当前是开发态，旧聊天兼容不纳入迁移交付门槛；新DSH会话从新上下文开始。
- 定时任务采用DSH原生主对话投递，沿用主对话上下文，不建立独立任务会话；过期一次性提醒按DSH恢复后补发。
- 本次工作为需求对齐与设计；尚未执行迁移、部署或生产配置修改。

#### Scenario: S01 普通聊天及图片追问

- **THEN** 助手理解当前输入，回复回到正确聊天，后续能引用本次图片内容；工具过程、等待审批与最终完成状态可辨认。

#### Scenario: S02 两节点及身份隔离
- **GIVEN** 多个数字人分配在两个节点，并存在不同owner/公司/聊天资格
- **WHEN** 用户给这些数字人聊天或查看工作状态
- **THEN** 各数字人使用自身workspace、能力和身份；消息、文件和审批不会因为共享运行时而串到另一个owner或无权聊天。

### Requirement: R2 global Inbox及群发言规则继续成立

#### Scenario: S03 全局助手并行处理多个聊天
- **WHEN** 多个聊天持续产生新消息，global助手正在处理已有工作
- **THEN** 新消息保留正确来源并可在后续读取；内部思考和普通草稿不自动发给用户，正式发送归属明确且能看到实际结果。

#### Scenario: S04 发出旧答复前收到更正
- **WHEN** 群聊中的更正已被接收，而旧答复尚未提交发送
- **THEN** single_thread的普通正文、同群发送工具、后台结果，以及global正式发送，都在对应发言边界考虑更正；不让已知过时稿直接越过它。

### Requirement: R3 通用工具可继续完成工作且扩展有两层归属

#### Scenario: S05 现有工作能力与已有工具
- **WHEN** 用户让助手读写文件、执行命令、检索网页、读取网页或使用已有专项工具
- **THEN** 对应工作仍能完成，使用已有模型/搜索服务和专项工具能力；不得因换核擅自引入付费替代服务或删去功能。

#### Scenario: S32 原生工具及后续升级
- **WHEN** 助手使用可替代的原生工具，或维护者升级受支持的DSH版本
- **THEN** 工具保持DSH原生命名及用法，已有Skill仍能完成对应工作；可获得上游工具更新，不被旧名字/旧参数兼容副本固定在旧实现。
- **AND** 大文件截断明确可继续读取，后台结果由原生输出工具读取后正常交付，不要求用户手动操作内部工具。
- **AND** Nano使用未修改的DSH依赖，通过公开插件/服务接口接入；升级不需要重放Nano的DSH源码补丁。

#### Scenario: S06 全局共享与workspace私有工具
- **GIVEN** 一个全局共享工具和workspace A中的同名局部工具，另有workspace B
- **WHEN** A的不同会话及B的会话使用该工具，并在服务重启后再次使用
- **THEN** A使用局部版本、B使用共享版本，A的私有工具不泄漏到B；Agent仍可创建、启用和共享工具。

#### Scenario: S07 工具及Skill显式禁用
- **WHEN** 用户给某数字人选择工具/Skill子集或显式空集合
- **THEN** 仅选中项可见并可执行，workspace、共享、运行时生成及社区来源不会绕过选择；更新的实际生效状态可见。

#### Scenario: S33 Feature独立启停与撤销影响
- **WHEN** 用户在某Agent的Features中开启、关闭并重新开启一项能力，或在关闭后重启节点
- **THEN** 该能力的工具/提示/命令及未来后台触发按有效配置出现或撤销，其他Agent和其他Feature不受影响；已有任务、记忆与Skill保留，重新开启不重复注册或重复触发。
- **AND** 已开始工作依该Feature原有契约收口；卸载未完成时不伪报已生效，也不宣称逆转已完成写入/外发。

### Requirement: R4 内部子Agent和后台任务继续可用

#### Scenario: S08 委派、追加与后台完成
- **WHEN** 助手派发多个内部子Agent，向尚存子任务追加要求，或让长工具后台继续
- **THEN** 子任务在正确身份和能力范围内执行；主对话仍可继续，结果可读取、归因并在需要时通知，不把尚未获得的结果伪装成完成。

#### Scenario: S09 停止等待中的工作
- **WHEN** 用户停止正在等待模型、长工具或审批的运行
- **THEN** 对应运行结束并可继续聊天；迟到文本、审批答复及子任务结果不会复活已取消工作或污染新请求。

### Requirement: R5 保留已确认的完整Workflow能力

#### Scenario: S10 JavaScript、并行与流水线
- **WHEN** 用户明确启动Workflow，在脚本中并行执行任务并把结果传给后续阶段
- **THEN** 使用JavaScript编排，多个实际子Agent完成工作，后续阶段取得真实前序结果；非Workflow对话不被强制转成编排任务。

#### Scenario: S11 保存命名与一层嵌套
- **WHEN** 助手保存个人或项目Workflow、按名带参数运行，并调用一个已保存的子Workflow
- **THEN** 对应定义可发现和复用，同名项目定义按既有优先级生效；支持一层嵌套且不绕过父流程限制。

#### Scenario: S12 暂停、继续及重启指定子任务
- **WHEN** 用户暂停Workflow、继续它，或仅重启一个选中的运行中子任务
- **THEN** 暂停阻止新的派发且已有任务可收口；继续恢复派发；重启只替换选中任务，旧尝试的迟到结果不覆盖新结果。

#### Scenario: S13 完成前缀复用
- **WHEN** 用户在同一主会话恢复已有Workflow，脚本及前面调用与已完成部分一致
- **THEN** 已完成的相同前缀可复用，后续从变化点继续；修改中间调用不会错误复用其后结果，重启服务后已保存结果仍可显式恢复。

#### Scenario: S14 父子共享输出预算
- **WHEN** 一个主轮次中的父Agent、多个Workflow及其子任务共享用户设置的输出token预算
- **THEN** 实际消耗共同累计，重放结果不重复计费，预算耗尽阻止新的子任务；未设置预算时不擅自施加该上限。

### Requirement: R6 Auto审批保留Nano规则并可切换DSH规则

#### Scenario: S15 默认规则及独立审核模型
- **WHEN** 迁移后的助手在Auto模式请求工具权限
- **THEN** 默认采用当前Nano判定规则和配置的独立审核模型；真人、他人消息、引用、后台通知和定时输入保持不同授权含义。

#### Scenario: S16 切换判定规则
- **WHEN** 用户把Auto规则配置改成DSH默认规则并完成配置生效
- **THEN** 后续审核使用DSH规则，同时保留独立审核模型、可信来源、人工确认和无人值守回退；已发出的审批仍对应原请求。

#### Scenario: S17 人工确认及Workflow审批
- **WHEN** Web/iOS/飞书上的用户批准或拒绝助手及Workflow子任务发起的审批
- **THEN** 决定只作用于相应调用；Workflow审批回到原启动消息；已取消请求的迟答不执行工具。

#### Scenario: S18 global短确认与自动任务
- **WHEN** global助手等待确认时用户给出短回复，或只有Heartbeat/Cron/后台事件到达
- **THEN** 真人短回复按现有来源与确认规则处理；系统事件不会成为人工同意，拒绝阈值、无判定与无人值守情况按原产品规则分流。

### Requirement: R7 记忆和Skill自动维护完整迁移

#### Scenario: S19 记忆维护
- **WHEN** 助手根据现有规则整理长期记忆或用户请求查看/修改记忆
- **THEN** 受控读写和后续使用继续有效，未成功写入不宣称已记住，真实更新能按现有方式通知。

#### Scenario: S20 Skill使用、维护与启用
- **WHEN** Skill使用达到维护条件，或助手生成、review、归档新的Skill
- **THEN** 使用记录、阈值触发、维护、归档和生成启用继续发生；前台回复结束后后台成功产物仍完成配置调和，后续会话可用。

### Requirement: R8 定时任务采用DSH原生主对话语义

#### Scenario: S21 在原主对话到期执行
- **WHEN** 用户在主对话设置定时任务并到达触发时间
- **THEN** 任务回到创建它的同一主对话，沿用对话上下文；不建立独立任务会话，结果可在该对话继续追问。

#### Scenario: S22 过期一次性提醒补发
- **GIVEN** 一次性提醒在机器停止期间到期
- **WHEN** 服务恢复并成功恢复对应主对话
- **THEN** 按DSH原生行为补发该提醒；不沿用Nano旧的过期跳过策略。

#### Scenario: S23 周期、开关、手动运行与历史
- **WHEN** 用户设置多条定时任务、查询/修改/删除、关闭对应能力、手动运行，或恢复错过多个周期的任务
- **THEN** 对应任务按配置生效；周期任务只补最近一次而不逐次刷屏；立即运行可确认已接收；历史区分实际执行成功、失败和仅入队，不能以调度收件记录冒充执行完成。

### Requirement: R9 Heartbeat维持现有主动策略

#### Scenario: S24 静默、忙碌与活跃时段
- **WHEN** Heartbeat到点，但助手正忙、处于活跃时段外或没有可行动内容
- **THEN** 按原规则跳过或静默，不向用户刷无意义消息；可行动时在正确主上下文处理，任务内容和子节律仍来自现有配置/HEARTBEAT文件约定。

### Requirement: R10 配置、模型与新历史连续可用

#### Scenario: S25 配置下一轮生效与模型备用
- **WHEN** 用户修改模型、推理设置或能力，或主模型在尚未产生真实公开输出前发生可用性失败
- **THEN** 配置在规定边界生效并如实展示状态；备用链、粘性和切换说明继续有效，聊天/Heartbeat/Cron均适用，不能在已公开输出后拼接另一个模型的答案。

#### Scenario: S26 新历史压缩、分支与蒸馏
- **WHEN** 用户对迁移后形成的会话手动压缩并指定重点、从某条消息分支，或从该历史生成Skill
- **THEN** 压缩重点与幂等查询、消息之前的正确分支内容和配置、受控历史读取/蒸馏可用；服务重启后新会话可继续。

#### Scenario: S27 开发态切换
- **WHEN** 迁移到新的运行路径
- **THEN** 从新会话开始，不承诺旧聊天上下文、旧消息分支或旧历史蒸馏兼容；现有workspace、记忆、Skill、工具和非聊天配置资产仍可接入。

### Requirement: R11 任务图、消息与配置的产品事实继续可靠

#### Scenario: S28 保存任务图和显式发送
- **WHEN** 用户讨论并保存共享任务图，或助手明确向另一个有权聊天发送消息
- **THEN** 保存任务图不自动启动执行；更新冲突和访问资格保留，实际发送能区分成功、失败与未知，不因工具返回或断线重放重复发送。

#### Scenario: S29 断线与运行时重启
- **WHEN** IM连接或执行运行时在接收、执行、审批、结果回传或实际发送期间断开并恢复
- **THEN** 已接收输入、处理中断、已完成未交付和外发未知状态可辨认；能补读已持久结果，不盲目重放有副作用操作。

### Requirement: R12 产品运维入口保持可用，旧Coding CLI退出

#### Scenario: S30 启停、登录自启和能力就绪
- **WHEN** 运维者用个人助手启停/状态命令或登录自启启动节点
- **THEN** 节点、执行运行时和渠道状态如实显示；可停止自己管理的进程，模型/代理及节点配置仍按实际生效值运行。

#### Scenario: S31 CLI退役及终态服务
- **WHEN** 用户安装最终版本并查看使用入口
- **THEN** 个人助手、IM管理和既有三个客户端可用；旧Coding CLI不再是运行/维护入口，说明指向个人助手；终态后端语言变化不改变上述产品功能。
