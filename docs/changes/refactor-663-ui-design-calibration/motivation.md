## 现状痛点

[跨 unit 复盘](retro-pipeline-rootcause.md)与[原话索引](feedback-evidence.md)显示：功能覆盖常代替信息组织；已有界面虽被读取却未被完整继承；独立 reviewer 也曾认可后来被用户否定的布局；整体反馈被局部修补。当前共同体验标准已经要求避免这些问题，因此重复增加同义原则不能直接解释或解决失效。

## 目标与不变性

目标是减少用户亲自纠正整体布局、信息架构和交互语义的负担，并保持现有开发流程轻量。以下是已经明确的约束；具体校准资料、接入位置和验证方式仍属于建议。

### Requirement: 保持现有流程轻量

#### Scenario: 前端增量开发

- **WHEN** Agent 按现有 change 流程完成前端任务
- **THEN** 不因本次优化要求用户新增固定 UI 审批、增加额外 Reviewer 或重复提交一套设计文档。

### Requirement: 保持需求语义和产品范围

#### Scenario: 参考历史设计经验

- **WHEN** Agent 借鉴相似界面或用户历史纠正
- **THEN** 仍以当前需求与产品约束为准，不将经验变成一律隐藏按钮、禁止卡片、删除说明或禁止重新设计的规则。

### Requirement: 诚实区分建议与效果

#### Scenario: 有限试用后汇报

- **WHEN** 优化完成有限样本验证
- **THEN** 说明实际观察到的改善与剩余问题，不把材料存在、规则被读取或一次试用通过宣称为今后一次设计成功的保证。

## 影响范围

拟影响开发 Agent 的 UI 设计、自检与审查指导；本轮只写本 unit 文档。产品代码、当前产品交互、生产环境、运行时 Intelligent UI 提示词均未修改。

## 迁移与回滚边界

本轮没有运行数据或产品迁移。后续若修改 Skill，将影响开发 Agent 消费的上下文，应在既有设计/审查环节承接 Context Review，不新增独立门禁。使用现有文档权威与引用关系；若验证无收益或引入机械套用，回退对应指导变更，保留历史证据。
