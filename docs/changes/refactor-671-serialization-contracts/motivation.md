# refactor-671: 序列化职责与字节契约

## 原始诉求

> 请完整盘点这些实现及真实调用者、输入域、持久指纹和协议兼容要求，确定合理能力归属与清晰命名/interface，落地去除 Channels/配置对 Task 领域的不合理依赖。该共享的复用，该保留不同字节语义的明确区分；不要机械合成一个带大量选项的万能 serializer。

>
> 你仅处理序列化职责、命名、导入及必要调用更新，不全局改 Row/ImContext 或分拆 Gateway。

## 澄清记录

用户已明确授权合理架构的设计、实施、独立门禁和 PR/CI；普通实现选择自主处理。采用 Full refactor，不采用快速开发。不写共享主仓，不合并、部署或发布安装包。无未决产品语义。

## 现状痛点

Channels 从 Task 模块导入通用编码；同名 canonicalJson 的 Unicode、排序和对象遍历语义不同，调用者不能从名称判断持久字节。现有差异证明错误替换会有兼容风险，不证明当前有效凭据已无法解密。

## 目标状态

纯序列化按真实字节语义有明确职责和命名，调用方不再为序列化依赖 Task 领域。保留现有配置指纹、发送/交互幂等身份、任务恢复比对、凭据信封与设备证明的字节含义；保留有意不同的实现，不扩展为通用序列化框架。

## 用户侧验收标准（不变性）

无新增或修改的用户可观察表面：本次仅搬移纯函数、清晰命名和等价接线，不改变 HTTP/WS 字段、存储模型、配置归一化、加密算法、授权或操作流程。兼容性是内部协议的严格字节不变量，由固定向量和实际加解密接口验证；不需要重新走飞书或模型旅程。若实施发现必须改变字节，则退出此范围并重新对齐，不能借重构修复已存在的协议差异。
