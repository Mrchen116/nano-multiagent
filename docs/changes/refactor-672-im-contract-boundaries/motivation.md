## 用户侧验收标准（不变性）

### Requirement: 配置编辑与空间权限保持

#### Scenario: owner 保存与刷新
- **WHEN** owner 读取、修改并刷新自有 Agent 配置
- **THEN** 保存的公开字段、版本与现有行为一致；未授权用户不能读写，旧版本不能覆盖新值。

### Requirement: 配置未知结果可恢复

#### Scenario: 应用确认丢失或节点不可达
- **WHEN** 节点已应用配置但确认丢失，或节点在操作期间断连
- **THEN** 保留原 operation 身份确认结果，未确认时仍显示待确认，不重复创建工作区、不伪装保存成功；新离线修改仍被拒。

### Requirement: 节点消息归属不变

#### Scenario: 连接更换与迟到结果
- **WHEN** 原连接的迟到结果到达，或同类请求并发
- **THEN** 每个结果只完成对应连接的对应请求；节点身份、生命周期检查与现有行为一致。

## 影响范围

IM 控制配置路径、内部节点 RPC、Work 与聊天生产/传输/持久投影，必要的共享产品类型和既有调用者。界面、数据库 schema、消息内容、Task 业务规则和序列化算法不变。会话/联系人/Channel 管理、Work 聊天查询和命令路由不做全面类型迁移。

## 迁移与回滚策略

无数据迁移、无协议版本切换。保留现有字段缺省/空值、指纹和恢复顺序。编译检查加现有配置、权限、节点连接测试与隔离真实 HTTP/WS 验收。回退代码即可继续读取原数据；禁止重置待确认 operation。

## 本 PR 范围扩展：Work 完整事件链

用户补充原话：

> **下一项先做 Work 的完整事件链。** 本pr内做

据此在同一 PR #426 / unit 增加 M3；已归档文档恢复到 active，保留先前门禁及其版本。实现选择仍按已授权的 Full 事前设计流程自主推进。当次 M3 追加不包含聊天和 Channel；聊天由后续 M4 授权单独纳入，Channel 管理仍不扩大。

Work 的产品事件从 PA runtime projection、GlobalAgent、InboxStore 本地日志，经独立 HTTP WorkSync（以及保留的 WS append 入口）进入 IM 的事务日志与工作视图。当前多个边界退化为 string/Record/Row；同一 Work 类还持有整个 ImContext。目标是贯通已知事件类型与字段、固定记录及公开投影，明确生产、传输和落盘/投影职责；动态工具参数/结果及未知扩展事件保持原值。

### Requirement: Work 记录从生成到刷新保持真实完整

#### Scenario: 主子执行与工具明细回看
- **WHEN** 主执行和关联子执行产生开始、工具、正文、权限及结束事实，用户读取并刷新工作记录
- **THEN** 事件顺序、父子归属、工具原始参数/结果、真实状态与已报告统计保持一致；未报告数据不补造，不把开始当完成。

### Requirement: Work 同步与重放保持同一身份

#### Scenario: 中断、重复与中心恢复
- **WHEN** 已保存在本机的事件通过批量或分段同步经历中断、重复和恢复
- **THEN** 中心只确认完整且已提交的事件，不重复投影；缺口仍返回应补位置，身份冲突被拒，原始字段/内容不被规范化后改写；普通聊天不等待该同步。

### Requirement: Work 契约边界不扩大访问权限

#### Scenario: 畸形事件与无权来源
- **WHEN** 来源不匹配，或稳定字段形状无效的事件抵达接收边界
- **THEN** 不提交该批事件或推进确认位置；合法旧事件别名和省略字段继续可读，未知扩展事件及工具动态内容保持原有保存/展示语义。

## 本 PR 范围扩展：聊天发送与流式更新

用户在确认聊天链仍使用 Row、需要完整链路治理后明确授权：

> 好，在本pr完成该治理

在同一 PR #426 增加 M4。范围包括普通 HTTP 发送、Agent 显式发送、单会话流式事实、持久消息及公开投影，并承接外部 shadow 的同一消息契约。会话管理、联系人、Channel 管理及执行运行时不做全面重构。

### Requirement: 发送重试仍对应同一真实消息

#### Scenario: 用户与 Agent 发送及重试
- **WHEN** 合法用户或 Agent 发送消息，并因结果未知用原身份重试
- **THEN** 正文、附件、发送者、目标和既有交互内容保持，原有幂等规则不产生重复消息或转发；冲突身份及无权来源不能冒充发送。

### Requirement: 实时过程与持久回看保持一致

#### Scenario: 流式正文、工具、审批与结束
- **WHEN** 回复经历开始、正文增量、工具/思考/审批及结束，随后重连或刷新
- **THEN** 已接受的正文和过程仍可回看，重复增量不重复拼接，终态后的正文增量不会重新打开回复；真实状态、顺序、统计及动态工具内容保持原值。

### Requirement: 边界拒绝不破坏消息与投递事实

#### Scenario: 畸形流事件及失效身份
- **WHEN** 稳定消费字段形状错误、来源不匹配或旧生命周期事件到达
- **THEN** 不写入无效消息/过程、不消费该增量幂等键、不发布成功事件；合法省略字段、现有恢复身份与外部 shadow 原值继续兼容。
