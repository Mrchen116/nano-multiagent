## 用户侧验收标准

### Requirement: 解散保持历史只读与完成事实
#### Scenario: 创建者解散有多种状态任务的群
- **WHEN** 创建者解散群，成员随后从任务历史读取
- **THEN** 未完成任务关闭，done/closed 状态及成果保持；创建者、负责人、任务 ID 和层级保持；历史只读，聊天移出日常列表。
- **AND** 被关闭候选不再作为当前选项，但原选项说明保留；无需变更的已完成节点不改修改记录。
#### Scenario: 非创建者及失败操作
- **WHEN** 非创建者请求解散，或解散保存失败
- **THEN** 拒绝请求；群、任务及已有消息投递状态不被部分改变。

### Requirement: 解散的任务修改准确归因
#### Scenario: Agent 修改后的任务被真人解散关闭
- **WHEN** 真人解散群后重新读取任务详情和总览
- **THEN** 这次发生修改的任务显示该真人和解散时刻，最新变更说明指明群已解散；不继续携带旧等待/恢复推进信息。
- **AND** 图级修改者与任务修改事实一致；仅选项被清空的节点也记录真人修改，完成状态与结果保持。

### Requirement: 解散不产生新的任务协作消息
#### Scenario: 群包含任务或没有任务
- **WHEN** 创建者解散群
- **THEN** 不新增任务消息或投递，已排队/发送/接收的投递取消；在线读取者在提交后得到失效更新，可重新读取已关闭任务，失败时不发布成功更新。

## 影响范围

IM 会话解散、任务持久记录及读投影。HTTP/工具请求格式、Web/iOS 组件不变。不改 Row/ImContext 总体类型、序列化算法、Skill 统计或前端结构，不合并/部署/发布。

## 迁移与回滚策略

无 schema 或生产数据迁移。修正此版本以后解散的记录；历史不反推真人，不批量清理历史字段。回滚代码无需转换数据，但会重新暴露旧缺陷。
