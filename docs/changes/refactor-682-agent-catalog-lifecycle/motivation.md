## 现状痛点

报告记载：节点在线但多个 Agent settings 请求约 10 秒超时；其他 RPC 仍正常，重启后恢复。30 次真实读取均成功，但 preview 目录从 1311 增至 1341。隔离 catalog 约 595–837 ms，不能归因为 workspace 扫描太慢。具体 DSH 内部锁未证实。

已核代码：settings GET 在配置串行锁中等待恢复和 catalog；Node RPC 超时不取消底层；DSH preview 注册 preset、创建 Agent/Session，dispose 未删除持久 session。共享运行态无法可靠终止任意挂起的 plugin 初始化/卸载。DSH 已锁定版本的公开 Agent API 需要 Session，持久化 API 无删除方法；不能靠扩大发现范围或修改上游实现解决。

## 目标状态

- 已确认目录复用缓存，并合并同一版本并发刷新；普通重复 GET 不创建 preview/session。
- 目录构建有独立执行与资源所有权，任何构建卡住后都能终止、回收，并允许后续请求成功；不重启聊天执行进程。
- 设置读取不占有配置写入的串行锁，保留已有已提交配置、权限检查和 last-known 展示。
- 成功、失败、超时、断连及 Node 重启后的遗留临时目录都有明确回收路径；只处理本功能拥有的临时状态。
- 记录跨层 request_id、构建耗时/结果、活动构建和清理失败，可做并发与长时验证。

## 用户侧验收标准（不变性）

### Requirement: 设置读取与恢复

#### Scenario: 在线打开与连续刷新
- **WHEN** 用户打开在线 Agent 设置页并连续刷新
- **THEN** 与既有正常行为一致，已保存配置、候选能力和编辑权限准确；重复读取迅速完成，不要求重启节点。

#### Scenario: 目录异常后重试
- **GIVEN** 节点在线，之前成功读取过设置
- **WHEN** 一次目录构建卡住、失败或执行进程退出
- **THEN** 页面继续通过现有提示展示最后确认内容及只读状态；异常解除后现有刷新入口恢复正常，其他 Agent 与聊天执行不被中断。

#### Scenario: 离线与权限变化
- **WHEN** 节点断连、绑定变化或用户失去访问权限
- **THEN** 沿用既有离线只读与权限拒绝；旧连接、旧 workspace、旧 owner 的迟到结果不能成为当前目录。

### Requirement: 配置及独立资源不回归

#### Scenario: 保存配置与下一轮生效
- **WHEN** 用户保存模型、工具或 Skill 选择，再重新读取
- **THEN** 沿用现有版本冲突和配置校验，候选缓存不扩大实际执行权限，配置与下一轮实际能力一致。

#### Scenario: 独立分区继续可用
- **WHEN** 目录不可用而用户访问插件、任务、统计或渠道
- **THEN** 这些分区仍按自身连接和读取状态判断，与现有分区隔离规则一致。
