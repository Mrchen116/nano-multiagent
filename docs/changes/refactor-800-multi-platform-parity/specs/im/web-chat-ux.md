## MODIFIED Requirements

### Requirement: Web 应用内新消息提醒按会话类型标识来源

Web IM SHALL 在会话外的新消息弹窗中用会话名标识来源，群聊额外展示该消息发送者的可读名称，并保留消息摘要与进入来源会话的操作。静音会话 SHALL NOT 弹出普通新消息提醒，明确提及当前用户的消息除外；外部渠道镜像会话的入站对端消息 SHALL 与普通新消息遵循同一提醒资格。全局导航入口的未读总数提示 SHALL 仅汇总未静音会话的未读数，静音会话在其列表行内仍保留自身的未读数与静音标识。

#### Scenario: 私聊提醒沿用会话名
- **WHEN** 用户在其他页面收到未静音真人、外部渠道对端或 Agent 私聊的新消息提醒
- **THEN** 弹窗显示该私聊的会话名，包括已保存的自定义名称，并展示消息摘要。

#### Scenario: 群聊提醒同时标识群和发送者
- **WHEN** 用户在其他页面收到未静音群聊中真人或 Agent 的新消息提醒，或在已静音群聊中被明确 `@提及`
- **THEN** 弹窗同时显示群名、发送者的可读名称和消息摘要；只有两个成员的群仍按群聊展示。
- **AND** 点击查看进入该消息所属的群聊（若属于已关注话题回复则进入对应话题）；静音会话中的非提及普通消息不弹出提醒。

#### Scenario: 全局入口未读汇总排除静音会话
- **WHEN** 用户同时拥有未静音会话和已静音会话的未读消息
- **THEN** 全局导航入口显示的未读总数仅汇总未静音会话，会话列表中的已静音会话行继续显示其静音标识与未读计数。

#### Scenario: 纯 UI 新消息
- **WHEN** 用户在其他页面收到一条已交付的纯 UI 消息
- **THEN** 提醒使用本地化的「互动卡片」标签，并遵守既有来源显示和去重规则。

#### Scenario: 尚未加载聊天列表或名称暂不可得
- **WHEN** 用户停留在设置等页面时收到新消息提醒
- **THEN** 不要求先打开聊天列表才能显示来源名称；名称暂不可得时显示可读通用称谓，不将内部 ID 作为名称兜底。
