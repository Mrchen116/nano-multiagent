## 用户场景

- **U1 临时服务故障**：用户让全局 Agent 创建、安装并调用 workspace 插件。审核服务短暂限流、503或明确传输失败时，系统在同一待审动作内恢复；主 Agent 无需为这次技术故障反复重调安装工具。恢复成功后动作只执行一次。
- **U2 慢判断与混合失败**：服务恢复后模型仍可能需要完整时间才能判定。用户接受等待延长到几分钟，但不接受无限重试、不同故障各送一套新额度，或最后一次被旧窗口挤得无法完成。一次超时、一次格式失败、一次网络失败也必须遵守同一边界。
- **U3 两种策略与安全**：无论用户为 Agent 选 CC 还是 Codex，均获得恢复能力；已有 CC 两阶段和 Codex 风险/授权流程、只读调查与上下文恢复的意义不变。真实拒绝不能靠“恢复”反复刷到允许，恢复不能换模型或升级权限。
- **U4 停止与耗尽**：用户点击停止或取消时审核立即开始收束，不继续等待/重试或晚到执行。无法恢复时，普通有人值守聊天仍走原审批入口，Global/子任务仍交回阻断原因，无人值守仍遵守既有配置，包括允许的 fallback。
- **U5 可解释与可验收**：用户和维护者能在可检查的执行/审核记录中分辨一次工具动作内部的恢复与主 Agent 的再次调用，知道实际审核模型、原因、耗时及可得用量。真实插件完整旅程与可重复的受控故障证据分别呈现，不能把供应商偶然可用等同于重试机制已验证。

## 验收标准

### Requirement: 临时失败在同一待审动作内有界恢复

#### Scenario: 短暂故障后放行（U1）
- **GIVEN** CC 或 Codex 正在审核一个需要模型判断的动作，尚未执行工具体
- **WHEN** 先遇到429限流、503或明确可恢复传输失败，随后在允许的恢复机会中得到有效 allow
- **THEN** 不要求主 Agent 重新调用同一工具即可继续，工具体恰好执行一次
- **AND** 恢复等待期间不执行该工具体，不产生重复的安装、写入或外部发送副作用。

#### Scenario: 混合失败共享额外两次额度（U2）
- **WHEN** 同一动作先后发生临时服务失败、单次审核超时或格式失败的任意组合
- **THEN** 符合恢复条件的失败总共最多获得2次额外恢复，不能按故障类别或 CC 阶段重新领取额度
- **AND** 原判定流程所需的正常阶段、Codex只读调查或上下文恢复不被冒充为服务故障重试，也不把额外2次额度乘法放大；额度用尽后的失败立即进入原有失败分流。

### Requirement: 每次恢复保留正常完整判断预算

#### Scenario: CC 恢复后的完整阶段判断（U2、U3）
- **WHEN** CC 的一次审核因可恢复故障或该次判断超时而开始恢复
- **THEN** 恢复后的判断保留对应正常阶段完整预算：第一阶段30秒、第二阶段60秒
- **AND** 先前失败与退避不扣减这次判断预算；正常两阶段含义不变，也不把阶段推进计为故障恢复。

#### Scenario: Codex 恢复后的完整审核判断（U2、U3）
- **WHEN** Codex 的一次审核因符合条件的失败而获得恢复机会
- **THEN** 新的审核尝试保留正常90秒预算，不因先前尝试耗时而天然无法完成
- **AND** 该正常尝试内既有的准备、只读调查及上下文预算恢复仍有界；不能借上下文重建再领取一组服务故障恢复额度。

#### Scenario: 等待可以延长但不会无限延长（U2）
- **WHEN** 多次失败用掉完整判断时间并发生退避
- **THEN** 用户可经历几分钟的审核等待，而不是被强行限制在首次审核的旧总窗口
- **AND** 次数与退避均有界；任何额外整体保护必须容纳获准的完整尝试及退避，不能让末次机会只剩残余判断时间。

### Requirement: 空白或非法判定仅获得共享额度内的一次恢复

#### Scenario: 首次格式失败后有效判定（U2）
- **WHEN** 审核完成却没有可用判定，包括空白或非法格式，且总恢复额度尚有剩余、此前未使用格式恢复
- **THEN** 最多获得1次格式恢复，该机会同时占用额外2次总额度
- **AND** 得到有效 allow 后工具只执行一次；得到有效最终 deny 则按原拒绝处理。

#### Scenario: 再次格式失败或总额度先耗尽（U2、U4）
- **WHEN** 已用过格式恢复后再次出现空白/非法判定，或格式首次失败时总恢复额度已耗尽
- **THEN** 不再因为格式错误获得恢复，进入原有技术不可用分流
- **AND** 可检查记录区分格式失败、服务失败和超时，不把非法判定冒充有效 deny 或503。

### Requirement: 技术恢复不改变授权、策略与最终拒绝

#### Scenario: CC 两阶段与最终拒绝（U3）
- **WHEN** CC 第一阶段产生有效非 allow 判定
- **THEN** 继续原本需要的第二阶段，而不是把该判定当技术失败重试
- **AND** 有效最终 deny 仍按原风险、拒绝计数和必要升级分流处理，不通过故障恢复反复寻求 allow。

#### Scenario: Codex 风险、授权与检查约束（U3）
- **WHEN** Codex 连续、并发或上下文恢复中的动作发生服务故障并恢复判断
- **THEN** 每个判定仍只适用于其对应动作，继续按原风险与可信授权判定，旧判定不成为新授权
- **AND** 审核只读检查的权限不扩大，待审动作和授权约束不被删去以换取成功。

#### Scenario: 有效拒绝与永久错误不作故障恢复（U3、U4）
- **WHEN** 得到有效最终 deny，或遇到认证失败、永久配置错误等非临时故障
- **THEN** 不消耗时间反复进行无意义故障重试，分别按原拒绝或技术不可用路径处理
- **AND** 不自动换回执行 Agent 模型复审，不新增免审、提权或技术失败自动放行。

### Requirement: 主动取消优先于超时恢复

#### Scenario: 请求中或退避期间停止（U4）
- **WHEN** 用户或父执行在审核判断或退避等待中主动停止/取消
- **THEN** 中断该审核与等待，不再启动后续恢复，不进入等待人工审批的新流程
- **AND** 被取消动作的工具体不执行，晚到审核结果不能复活它；主动取消不被记为可重试的单次超时。

#### Scenario: 非主动取消的单次超时（U2、U4）
- **WHEN** 一次审核判断达到自己的正常超时，而父执行仍有效且额外额度尚有剩余
- **THEN** 可以获得共享额度内的恢复，并得到新的完整正常判断预算
- **AND** 连续超时同样受额外最多2次的边界约束，耗尽后不再恢复。

### Requirement: 耗尽严格沿用既有模式与配置分流

#### Scenario: 有人值守聊天审核不可用（U4）
- **WHEN** 普通有人值守聊天的审核恢复耗尽
- **THEN** 以技术不可用原因进入既有人工审批路径，而不是伪造安全拒绝或自动 allow
- **AND** 只有原有审批流程最终允许才可执行，恢复本身不导致工具重复执行。

#### Scenario: Global 与子任务审核不可用（U4）
- **WHEN** Global 或子任务的审核恢复耗尽
- **THEN** 按既有 return_to_agent 路径返回准确阻断原因，不新增子任务人工审批卡
- **AND** 不因无人值守允许配置而扩大子任务权限，该次阻断动作的工具体不执行。

#### Scenario: 无人值守的 allow 与 deny 配置（U4）
- **GIVEN** 当前是既有路由认定的无人值守执行，包括 schedule/heartbeat
- **WHEN** 审核恢复耗尽
- **THEN** fallback 配置为 deny 时动作不执行；配置为 allow 时仅按既有 fallback 允许执行一次
- **AND** 原因明确是技术审核不可用及既有配置分流，而非模型有效 allow；不将本功能描述成“耗尽后一律零执行”，也不新增 fail-open。

### Requirement: 审核恢复可追踪并以真实旅程验证

#### Scenario: 一次动作与再次工具调用可区分（U5）
- **WHEN** 用户或维护者检查一次经历恢复的执行/审核记录
- **THEN** 能区分同一动作内部各次审核尝试与主 Agent 后来重新发起的工具调用，了解实际审核模型、每次原因、最终结果与路由、耗时和可获得的模型用量
- **AND** 未取得的用量不伪造为零或完整统计，技术不可用不冒充安全拒绝或有效放行。

#### Scenario: 真实全局插件旅程与受控证据分别交付（U1、U5）
- **WHEN** 在隔离环境验收全局 Agent 自主创建 workspace 插件、安装并用两组数据实际调用
- **THEN** 留下用户可检查的 Work 轨迹，核对真实安装与两次调用结果，没有因内部审核恢复重复执行工具
- **AND** 分别报告 CC/Codex 覆盖及实际审核模型；确定性故障注入对短暂成功、持续失败、混合次数、格式子额度、完整预算、取消、最终拒绝和各模式 fallback 的证据，与真实模型服务可用性结论分开，不能以单次真实服务成功替代故障恢复验证。

## 范围与非目标

- 在范围：CC/Nano 与 Codex Auto 的429/503、明确瞬时传输失败、单次审核超时及有子额度的空白/非法判定恢复；完整正常预算、共享次数、可取消退避、原判定流程和 fallback 回归；可追踪审核记录及独立安全回归矩阵。
- 在范围：设计确认共享 classifier 的 legacy DSH 路径兼容性，不因内部复用破坏其单阶段语义、独立审核模型或既有分流；不把它升级成另一套审批产品。
- 非目标：#330 根聊天最新授权刷新、插件 API/创建页 preview、供应商服务可用性治理、主 Agent 通用防循环、审核策略准确率重写、新免审名单、变更用户既有 fallback 或全局切换审核模型。
- 技术恢复粒度、退避与整体保护的具体数值、公开上游能力接入方式、审计载体和测试切分由 design 决定；仅允许既有 DSH 公开能力边界内接入，不通过 private import、运行时 fork/patch 或第二套 Agent loop 实现。
- 本首文档不选择“外层重跑整个 Guardian”等未经验证的方案；不得用生命周期实现便利压缩用户已确认的预算或乘法放大次数。
- 本 unit 仍须完成 Full 设计、独立 Gate 2、实施及适用验证门禁再交付 Ready PR；不授权自动 merge、生产部署或发布。
