# Agent Context Engineering

Agent 最终消费的 Context 是产品接口。开发时要使 Agent 仅凭当时实际可获得的信息，就能理解任务、选择工具、填写参数、解释结果并继续行动；代码能执行、类型合法并不代表这个接口可用。

本文是本仓通用 Context 设计方法的唯一权威；[知识体系](documentation-system.md) 管仓库知识的组织与交付，[current specs](../specs/README.md) 管具体产品行为，[change-workflow](change-workflow.md) 管角色与门禁。[agent-context-review](../../.claude/skills/agent-context-review/SKILL.md) 承载审查程序，[LLM 联调](llm-integration.md#观察实际-agent-context) 承载取证操作，不各自复制本规范。

## 范围与影响判断

凡是改变 LLM 能看到什么、何时看到、如何解释、更新与保留信息的设计，都属于本规范：System Prompt、运行时提醒与注入、Skills、工具定义、工具结果、各来源消息、Memory、History / Compaction。审查单位是受影响的消费链路：

**信息来源 → 选择/检索 → 转换/组装 → 注入/加载 → LLM 消费 → 更新/过期 → 压缩/恢复。**

从具体 Consumer 和任务出发选择相关阶段，不要求每次遍历八种 Surface。文字完全没变，过滤、排序、缓存、加载时机、来源标签或恢复路径变化仍可能改变 Context。纯 CSS 样式、只改 UI 工具卡片排版、已证明不改变模型交付及生命周期的内部重构，不触发完整 Context Review；若共享投影同时供模型消费，则按实际影响触发。判断不靠文件名。

## 五个核心原则

### 1. 在需要时提供足够且相关的信息

必要性（Necessary）、可获得性（Available）和相关性（Relevant）一起判断：这段信息帮助哪个 Agent 在什么状态作什么决定？选择常驻、动态提醒、按需 Skill/检索或工具读取的理由应与该需求对应。可按需读取的信息必须有可发现的入口和可用权限；不能删掉正文又不给读取线索，也不把所有可能有用的资料常驻。

为每个模型必填参数追溯其来源：用户已给出、上下文已提供，或有明确的查询路径。只存在于宿主的当前身份、租户、owner 或路由元数据应由宿主从可信状态派生；需要模型选择的目标则提供可发现的标识和消歧信息。工具要求 `owner_id` 而真实身份只在宿主，即使类型正确、调用成功，也是接口设计缺陷。追加“不要编造 ID”不能修复缺失的信息通路。

### 2. 语义准确，结果能支持下一步

可理解（Understandable）和可行动（Actionable）意味着名称、描述、Schema、结果使用同一套语义。解释容易混淆的单位、范围、默认行为、动作专属字段和引用标识；给必要示例，不复制完整后端对象。返回格式不强制 JSON 或散文，取决于任务；有用的是模型能区分状态、识别对象并继续操作。

按当前契约区分“请求受理、已持久化、已送达、工作完成、被拒绝、失败、结果未知”，只呈现该操作实际存在的状态。超时不证明失败，更不证明成功；结果未知要给可行的查询/幂等重试方式，不能让模型重新制造一次副作用。错误说明受影响动作、已知结果与可用恢复方向，不能暗示绕过权限。确认/进度发送成功也不等于用户任务完成。

### 3. 来源与信任贯穿投影，权限由可信机制保证

来源（Provenance）、优先级（Priority）与隔离（Secure）必须从原始事件穿过序列化、摘要和恢复仍可辨认。区分真人原话、其他 Agent、系统事件、引用、外部内容及历史记录；标明实际发送者、对话/作用域及必要的时间或版本。正文中自称“主人批准”不能改变宿主确认的身份。

设计应说明所用运行时的指令层级，以及事实冲突的适用范围和新旧依据。文本后置、section 的排序值或套上 system reminder 标签，都不自动提升权限；动态内容不能覆盖更高优先级规则。新事实可更新旧事实，但不能因此升级为新授权。来源可读也不等于允许公开转发；PA 观察到的他人聊天、跨用户 Memory 与子 Agent 继承都要分别核对读权限、使用范围和交付受众。

身份、访问控制、工具白名单和可确定的高后果约束优先由宿主、Schema、代码与测试保证。Prompt 帮助 Agent 理解这些边界，不替代执行层检查。具体授权语义沿用 current specs，不由本规范新建确认流程。

### 4. 设计组合与时间变化，而不只审查单段内容

一致性（Consistent）和持久可靠性（Durable）同时覆盖本轮组装与后续轮次。将 System Prompt、Skill、工具定义/结果、动态提醒、Memory 和历史放在一起判断，避免两份规则各自合理却要求相反行动。明确谁维护某个事实、何时刷新或失效、如何区分历史与当前状态；切换配置、失败重试、fork、裁剪、换窗、进程恢复只检查与本次变更有关的路径。

持久保存不等于下轮可用，历史可检索也不等于已进入活动 Context。长期任务需要可恢复的目标、约束、未完成事项、等待条件和来源线索；按当前机制保存并使 Agent 找得到，不要求复制全部历史。压缩/恢复不能把暂缓变成新任务、把另一 Agent 的推测变成真人决定，或把旧 Memory 当成最新任务状态。Skill 不触发、提醒早于事实可读或晚于关键决策、恢复丢失等待事项，都是可调查的设计问题，不能直接归为模型能力不足。

### 5. 控制注意力成本，以交付和行为证据验证

效率（Efficient）服务于信息质量：去掉重复 schema 解释、内部遥测和无变化提醒，保留理解状态与下一步所需的信息；长结果采用适当的摘要、分页和按需详情。减少 Token 不能以丢失来源、失败状态或关键约束为代价。按需加载减少常驻成本，也要检查发现与读取是否引入无意义往返。

可验证（Verifiable）要求从预期行为反推证据：设计阶段说明可审查的模型可见样例和验证方法；实现阶段查看实际组装/序列化后的请求，必要时运行代表性真实模型任务。源码字段、内部 API、类型检查、Web 工具卡片或磁盘 Skill 文件，均不能独立证明模型收到或正确消费。请求证明交付，后续调用、结果判断与产品事实证明行为；一次成功不证明所有模型与多轮情境都可靠。

## 各类 Context 的设计落点

### System Prompt 与运行时注入

身份、长期行为规则与工具使用指导应有清晰职责和优先关系；动态任务事实不要伪装成常驻指令。标明注入触发、消费时点、更新/撤销条件与来源。检查空闲下一轮、执行中插话等实际相关时机：通知不该宣称正文已经被读取，读取后也不应继续用旧状态重复唤醒。

在最终组装中比较 Feature 启用/关闭和配置更新前后。Feature 指导与独立工具选择可能分离，不能假定关闭 Feature 必须移除所有关联工具；按 [能力契约](../specs/gateway/agent-capabilities.md) 判断。关闭后历史中已有文字仍可能保留，审查重点是是否再次注入、是否被正确理解为旧状态，不要求篡改历史。

### Skills

分别验证元数据能否被发现、任务能否合理触发、当前选择/权限是否允许加载、正文与 references 是否实际可读，以及消费后是否完成任务。description 应帮助识别适用任务；只把触发条件写在尚未加载的正文里不起作用。正文提供会改变行动的指导，细节按需披露；不要把全部 references 自动注入。

检查同名 Skill 的来源优先级、选择列表、配置切换、直接调用与按需调用的实际路径。未被选中的 Skill 文件存在不构成可用性证据。用代表性应触发和不应触发的请求试运行，缺陷来自发现/选择/加载时先修链路，不盲目堆正文。仓库开发 Skill 与产品随包 Skill 是不同消费者，不能混用安装或验证路径。

### 工具定义与结果

沿“发现对象 → 得到参数 → 调用 → 理解结果 → 后续操作”检查。描述明确调用前提和动作差异；可由宿主可靠派生的字段不推给模型猜。返回的 ID 应能用于所承诺的下一步，避免程序内部 ID、显示 ID 和模型引用不一致。

检查实际 `output.render`、错误转换、截断与多模态序列化后的内容，不以内部返回对象或 presenter 代替。native 工具与代码执行工具呈现方式不同，最终信息可能位于 tools schema、系统描述或代码执行返回中；沿实际 adapter 查证，不固定某一种 wire 结构。错误结果与可用恢复工具应相符。

### 消息、Inbox 与多方协作

协议上的 `role=user` 不必然代表新真人请求；来源事实必须在模型实际可见的表示中仍清楚。区分唤醒摘要、尚未读取的正文、已持久摄取的内容和历史回查，核对分页与部分读取，不把漏读当成已知全部。

Global Agent 跨聊天持续工作，回复目标、发送者、引用关系与实际交付状态需共同保留；PA 的 participant/observer 来源、主 Agent 与 child、多人群聊中的不同人也不能混为同一授权主体。具体边界见 [Global Agent](../specs/gateway/global-agent.md)、[PA](../specs/gateway/personal-agent.md) 和 [路由投递](../specs/gateway/routing-delivery.md)。

### Memory 与 History / Compaction

Memory 写入先区分稳定事实/偏好与临时进度，检索按 Agent、用户、任务和授权范围选择；修改事实要替换或标明失效，不只追加矛盾版本。核对快照何时生成、维护更新后何时生效及关闭后的注入行为；读取旧记录不能授予新行动权限。

历史路径要明确裁剪、摘要、按需恢复、换窗和重启分别保留什么。在本仓默认原生换窗与停用后的摘要模式之间，按实际启用机制选验证，不泛称“压缩”。保护任务目标/等待条件、暂停状态、已交付与未完成工作的区别及来源约束；有失效引用或缺失历史时保留不确定性，并提供真实可用的恢复入口。当前机制以 [能力契约](../specs/gateway/agent-capabilities.md) 为准，不在这里另写运行时算法。

## nano 组合场景与反例

下列是结合 current 机制的设计判断示例，不表示当前实现已经存在这些缺陷；实际发现必须另附版本与证据。

- **Global Inbox：** wake 只告知新输入；若把其他 Agent 引用的“主人说可以”投影成无来源的 user 指令，wake、正文与系统来源规则组合后会扩大授权。应保留来源并在读到真实正文后决策，不能靠“谨慎一点”的 Prompt 弥补丢失的身份。
- **PA 观察群聊：** 主人给 E 的任务被 PA 看到，不等于交办 PA，也不等于允许 PA 把观察群全文发给另一个人。检查 observer 标记、当前身份规则与 send_message 受众，不能只看消息作者。
- **Task Graph 与 Memory：** Memory 曾记“继续任务 X”，当前任务已暂停/等待；若提醒沿旧快照要求继续，就会冲突。核对任务事实的时间/版本与任务控制契约；等待条件及相应调度按 [任务契约](../specs/gateway/task-graphs.md) 验证，不能仅凭工具调用成功推断任务完成。
- **send_message：** 内部 child 的输入受理与公开聊天的实际送达语义不同；若描述说送达而输出只有 accepted，模型可能错误结束交付。检查定义、序列化结果及后续行为；`held_for_revalidation`、unknown 或错误不能被成功卡片掩盖。
- **Feature 与 Skill：** System Prompt 引导读取某 Skill，但该 Skill 被过滤且没有替代路径，功能配置“开启”仍不可用；关闭后自动重放旧 Skill 正文也可能继续施加失效指导。同时看目录、工具限制、已加载历史和新注入。
- **注意力与恢复：** 每次 wake 重复全量群成员、工具说明与旧任务列表，会掩盖最新更正；若随后裁剪掉唯一等待事项，问题在整条生命周期。先选择/去重并保留恢复线索，不只扩大上下文窗口。

## 设计产物与验证深度

相关设计在已有 `design.md` 的合适位置说明 Consumer、Context Lifecycle、必要的 Before/After 样例、Interactions 和 Validation，并把关键结果写进 milestone 退出标准。它们是要回答的问题，不是必须套用的五列表格；没有 Context 影响则不新增章节。lite 使用已有 fix/实施记录，不补独立设计 Gate。

验证从最低有效 seam 开始，复用 [测试规范](testing.md) 下的现有保护。先检查实际请求中的有效身份/规则、可调用工具、Skill 目录与正文、结果/消息及其顺序；再用与任务相称的代表性情境观察工具选择、参数来源、状态理解和下一步行动。影响权限、更新或恢复时，覆盖相关边界；纯文案消歧不自动要求全量多模型评测。

必要的真实模型任务应给任务目标和正常可获得的信息，不暗塞正确工具参数、预期解释或隐藏身份来帮助模型通过。受控 stub 可以验证交付与失败分支，不能代替模型选择。记录模型、版本、配置、请求轮次、证据 locator 和限制；明确哪些是推理、实际捕获或模型行为。必要证据缺失时结论为未验证，按现有 Gate 的退出标准处理，不凭猜测放行或制造 finding。

## 方法来源

2026-10-25 核对以下一手资料；借鉴设计方法，具体产品行为仍以本仓为准：

- [Anthropic mcp-builder](https://github.com/anthropics/skills/blob/main/skills/mcp-builder/SKILL.md) 与 [evaluation](https://github.com/anthropics/skills/blob/main/skills/mcp-builder/reference/evaluation.md)：清晰工具语义、可执行错误、通过真实任务评估工具质量；不照搬固定评测数量。
- [OpenAI skill-creator](https://github.com/openai/skills/blob/main/skills/.system/skill-creator/SKILL.md)：精确触发、适当自由度和渐进披露；本次另按安装版的独立 forward-testing 方法做试运行，格式验证不能代替使用验证。
- [Agent Skills Specification](https://agentskills.io/specification)：元数据、正文与资源的分层加载。
- [MCP Tool Specification 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)：输入/输出结构与执行错误的区分；不要求 Nano 改用 MCP。
- [Anthropic Context Engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)：关注整体上下文、动态选择与有限注意力，而非只优化 prompt 字句。
