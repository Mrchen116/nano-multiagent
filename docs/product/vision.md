# Product Vision

## 产品定位

nano-multiagent 是一个以 IM 为协作与工作主体的组织级 Agent 平台，让真人、每个人的 Personal Agent，以及承担专业职能的 Global Agent 数字员工共同工作。

我们希望组织中的 Agent 像长期在岗的同事一样：有稳定身份、明确职责和持续的工作认知，主动感知相关变化，在协作中发现并推进需要做的事，同时承担多个事项，并从长期经历中积累理解与经验。人与 Agent 通过共同的 IM 工作环境沟通、协调和交付成果。

本文描述产品希望成为的样子与长期取舍。具体能力是否已经具备、当前有哪些限制，以 [current specs](../specs/README.md) 及相应验证为准；愿景本身不代表所有场景已经实现或验收。

## 组织中的人和 Agent

### 真人与专业数字员工共同承担工作

组织中的真人和专业 Agent 按各自的职责与能力协作。专业 Global Agent 是持续存在的数字员工，有独立的专业方向、职责范围和交付目标；它可以接收不同成员、PA 和其他数字员工的协作请求，汇合多个聊天中的相关信息，并按职责安排工作。

例如，承担质量保障职能的数字员工应持续关注相关项目的质量、发现需要验证的变化、协调问题处理并跟进结果。某次检查完成或某位请求者结束聊天，不意味着这项职能结束。这个例子说明岗位方向，不表示产品已内置并验收了该岗位的全部能力。

数字员工的职能归属、谁提出某项请求、谁管理其配置，是不同的问题。它围绕长期职能工作，而各项实际行动仍遵守明确的职责分工与权限；能够联系其他人或 Agent，不自动意味着能够向对方派工或读取其私人资料。

### 每个人有自己的 Personal Agent

Personal Agent（PA）的长期职责是辅助主人，帮助主人更好地履行职责、完成目标，并兼顾工作与生活。它从主人的角度理解事情，持续了解主人的目标、偏好、关系、承诺、当前工作和重要变化，协助处理主人承担的事项。

目标是让 PA 能理解主人的整体上下文，包括主人与他人的沟通、相关任务与资料，以及 PA 自己参与的协作，减少主人反复搬运背景的负担。具体感知范围由主人授权和实际接入能力决定；未接入、未读取或被排除的信息，应如实说明。主人与别人交流提供的是需要理解的背景，是否需要 PA 采取行动要结合长期职责、已有委托和实际语境判断。

PA 可以主动核对变化、准备材料、提出有依据的建议，并在授权内代表主人沟通和推进工作。主人已经完成或纠正的事情应影响它的后续判断；私人信息不会因为参与组织协作而自动向其他成员公开。个人可以先独立使用 PA，加入组织后沿用同一服务关系与私人上下文。

PA 与专业数字员工按服务对象和责任区分。当前 PA 复用完整的 Global 执行能力；“Global”同时是跨聊天执行模式的名称，不意味着所有使用该模式的 Agent 都具有组织专家角色。

### subagent 是内部执行者

长期 Agent 是组织成员可以识别、持续交流和协作的主体。subagent 是其内部按需组织的执行者，承担具体事项或其中的一部分。内部委派不转移长期 Agent 对外的职责、协调和交付责任，也不让每次任务自动产生一个新的组织成员。

## 长期工作的共同原则

### 职责持续存在，主动感知与行动服务于职责

PA 和专业数字员工都承担长期职责。Agent 应持续关注与职责有关的人、项目、消息和工作变化，结合已有目标判断需要做什么；在没有新指令时，也能发现遗漏、风险、机会或待接续的工作，并在职责与授权范围内主动推进。

主动性应体现为有价值的准备、行动与结果。需要人判断时，带着相关事实、已经完成的准备和具体问题沟通；无新帮助价值时保持安静。长期职责不要求持续占用算力或频繁发消息，等待外部条件时保留后续安排，条件变化后接续。

### 多个事项并行推进，交流保持可用

一个长期 Agent 能同时承担多个独立事项，在推进已有工作时继续接收新请求、理解背景变化和协调协作。一项工作等待资料、回复或执行结果时，其他有条件推进的工作仍可继续。

不同事项保留各自的目标、进展和结果；补充、更正、停止与后续反馈作用于相应事项，避免遗失工作、重复执行或误停其他事项。主 Agent 统筹相关上下文和对外沟通，按需要组织内部执行者；简单交流和小事可以直接处理。用户无需管理内部执行细节才能获得成果。

### 长期记忆支撑持续理解和主动判断

Agent 的职责跨越消息、任务与上下文窗口，长期记忆因此是基础辅助能力。它应帮助 Agent 记住长期负责什么、重要背景、事项的演变和做事得到的经验，在后续判断与行动中实际使用这些积累，减少重复解释和重复试错。

PA 的记忆围绕主人展开，逐步理解其目标、偏好、关系、承诺和生活工作变化；专业数字员工的记忆围绕领域、项目、合作关系和履职经验展开。两者可以共用记忆机制，知识内容与私人信息边界按各自角色维护。

沟通获得的背景与执行获得的经验都应进入适当的长期积累。记忆应能追溯来源、区分事实与判断，并随新事实修正；当前交流中的纠正应立即影响行为。记忆辅助理解，不能自行创造授权，也不能把旧结论当成永远有效的事实。正式记忆的维护与 Dreaming 机制由 [能力契约](../specs/gateway/agent-capabilities.md)定义，愿景不另立一套写入机制。

### IM 承载协作、工作推进和成果交付

IM 是人、PA 和数字员工共同工作的场所。私聊与群聊承载需求、讨论、协调、决定、进展和成果；任务帮助参与者理解哪些事情在做、哪些在等以及由谁负责，工作视图帮助理解某位数字员工整体在做什么，并按需检查内部执行。

聊天呈现面向该受众的交流与交付，完整工作轨迹按 Agent 和执行归属查看。需要比较、选择、编辑或理解动态过程时，Agent 可以使用合适的交互表达，帮助参与者直接判断和行动；简单沟通保持简洁。

Web IM 与原生 iPhone App 承载日常协作，飞书等外部通道扩展触达范围。用户无需先接入第三方 IM 才能开始，跨入口仍应保持可理解的身份、上下文和成果去向。

### 工作对结果负责，行动可见且可控

承担一项工作意味着持续跟进到约定结果，或明确说明尚缺的条件。接单、委派、工具调用成功、产物生成和成果实际交付是不同事实；状态和反馈应让参与者理解目前完成了什么、还在等什么、哪里需要决定。

用户能够了解工作、提出更正、调整安排及停止相应行动。Agent 在已有职责和授权内自主处理常规步骤，超出范围时提出具体决定；协作、长期记忆与主动性都遵守真实身份、资源归属和信息边界。加入组织不公开私人 PA 的聊天与 Work，查看组织数字员工的 Work 也不自动授予原聊天或配置的访问权限。

## 实现方向与当前契约

用户节点承载 Agent 执行、workspace 与能力，中心 IM 承载账号及协作协调；节点主动连接中心。中心暂时不可达时，本地可运行路径和已接入外部通道尽可能保持自治。DSH 提供唯一执行运行时，Nano 通过公开能力装配产品身份、权限、协作与主动工作；具体职责和边界只在 [架构总纲](../../SPEC.md)维护。
