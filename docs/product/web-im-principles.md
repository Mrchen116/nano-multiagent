# Web IM Principles

Web IM 是真人、个人 PA 和专业数字员工共同协作与工作的默认界面。产品角色与长期工作方向见 [产品愿景](vision.md)。以下原则约束跨版本体验取舍；具体页面行为由 [`docs/specs/im/`](../specs/im/spec.md) 定义。

## Crewden 的视觉风格

这轮设计里，用户给出的方向是“灵动活泼但简洁”。从官网、注册、首次设置到日常聊天，沿用同一套品牌标识、角色形象和文字层级。各页的表现力随任务变化：

- **官网用场景讲协作。** 用具体的一件事串起人、PA 和专职 Agent，让访客看懂谁接到了任务、谁需要作决定、最后交付了什么。品牌标识用 SVG 将对话框与机器人意象结合；角色动作和图形变化用来讲清协作过程。
- **首次设置把下一步放在眼前。** 连接电脑时突出正在连接的设备、真实进度和可执行的操作。插画可以让陌生的步骤更亲切；说明就近放在需要它的步骤，用户开始聊天后首次引导退场。
- **日常工作区以浅色、易读为主。** 白色和浅中性色承载消息与长时间阅读，品牌紫用于主操作，柔和的点色集中在角色或局部提示。大面积深黄、绿色块或通篇紫色都会削弱内容主次。
- **用轮廓和表情赋予角色个性。** PA 的轮廓柔和，专职 Agent 的轮廓更几何化；在聊天列表的小头像尺寸上也应能区分。用户选择的形象跨页面保持一致，避免统一机械面罩只能靠标签辨认。
- **让必要信息出现在需要的位置。** 群聊保留发送者姓名，私聊省去重复署名；标题栏显示群成员数，完整名单在群详情里看。常用操作随手可达，电脑信息在需要排查时从头像打开。

用户反馈与具体页面的验收范围见[首次使用体验需求记录](../changes/archive/feat-773-crewden-first-use/spec.md)。

## 对话优先

主路径围绕“找到协作对象、读懂上下文、讨论与推进工作、看到结果”。私聊与群聊承载沟通和交付，任务帮助理解工作安排，Work 帮助查看数字员工的整体活动。配置、诊断和运行信息服务于这条路径，不应让用户先理解内部架构或管理内部执行者才能开展工作。

## 高信息密度，但保持清晰层级

会话、消息、工具过程、响应指标和状态可以同时存在，但主要对话内容优先。次要过程按层级和需要展开，避免把运行遥测与用户可见回复混成同一种信息。

## 桌面与手机使用各自自然的导航

桌面端可以同时呈现会话列表和当前消息流；手机竖屏以列表与详情之间的单栏切换为主。响应式设计围绕设备上的实际任务重组信息，而不是把桌面页面等比缩小。

## 在用户操作前说明当前是否可用

节点未绑定、Gateway 离线、数据加载失败或配置尚未应用时，界面应在对应操作点显示状态和下一步。输入区、保存按钮或危险动作的可用性与真实后端状态一致，提交失败时尽可能保留用户尚未完成的内容。

## 历史与实时事件组成一条连续时间线

刷新、分页、断线重连和配置切换不能让用户误以为消息消失、重复或属于另一段会话。实时事件最终与持久历史收敛；用户上滚阅读历史时，新事件不应无故夺走阅读位置。

## 会话身份必须可辨认

用户与 Agent 单聊、Agent 间会话、群聊、系统 feed 和外部通道影子会话具有不同语义。列表、标题、参与者和操作入口帮助用户理解“谁在和谁说话”以及回复会去哪里。

## 配置展示期望状态，也展示实际运行状态

用户通过 Web IM 管理 Agent、节点和外部通道时，保存成功只说明期望配置已经提交；节点是否在线、能力是否可用、通道是否真正连接需要独立呈现。前端不猜测节点本地能力，以节点当前上报和校验结果为准。

## 动效和视觉装饰服从阅读效率

消息出现、页面切换和状态变化可以使用克制的过渡，但不干扰文本选择、滚动、复制或连续阅读。视觉差异用于表达发送者、层级和状态，而不是增加无含义的装饰。
