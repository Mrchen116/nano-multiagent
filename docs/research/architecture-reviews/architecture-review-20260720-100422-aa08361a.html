Candidate 01

收拢 permission request 的完整生命周期

Strong in-process

src/agent/core/agent/runtime.py · src/agent/platform/permissions/broker.py · src/agent/sdk/kernel.py · tests/unit/test_permission_requester_cancel.py

Problem

约 200 行 async closure 同时拥有 future 注册、双路竞态、liveness、事件发布和取消，却又直接穿透 PermissionBroker._lock/_pending。

Solution

让一个内部 deep module 拥有完整 wait/resolve/cancel 事务；产品决策与事件发布继续作为注入协作者。

Benefits

  • locality: exactly-once 决策
  • tests 走真实生命周期
  • 删除复制 race 算法
  • interrupt 与 cancel 同测
约束：保持 core 不 import platform；在现有注入方向内加深 module，不反转 SPEC.md 的层次依赖。

Candidate 02

完成 RunDeliveryContext 的 typed cutover

Strong in-process

src/personal_assistant/gateway/runtime_delivery/context.py · observer.py · lifecycle.py · stream.py · src/personal_assistant/main.py

Problem

typed context 已是 production owner，却还同步维护 legacy dict、19-key MutableMapping adapter 和 dict | store 双路径。

Solution

让 runtime delivery 全程直接消费 typed context，删除 legacy mirror、magic-key 转换和兼容分支。

Benefits

  • locality: bubble 不变量
  • 单一 typed test surface
  • 删除双写与漂移
  • cleanup 状态一次验证

Candidate 03

让 CLI event pipeline 真正拥有 run consumption

Strong in-process

src/coding_cli/commands.py · src/coding_cli/events/event_pipeline.py · tests/unit/test_cli_structure.py · tests/unit/test_cli_text_sse.py

Problem

NormalizedSessionEvent、dedupe、perf、phase 和 consume surface 没有 production caller，真实行为仍堆在 _send_message_async。

Benefits

  • tests 命中 production path
  • 删除存在性测试
  • commands 只做 composition

Candidate 04

深化 IM↔Gateway RPC correlation

Strong ports & adapters

src/IM/ws/gateway_handler.py · src/IM/ws/gateway_protocol.py · src/IM/api/routes/agents.py · src/IM/api/routes/nodes.py · tests/im_service/unit/test_gateway_handler.py

Problem

GatewayHandler 维护 11 个 typed waiter dict；每个 RPC 重复 future 注册、push、timeout、cleanup，result handler 再重复 lookup 与完成。

Solution

把 correlation 生命周期集中进一个内部 deep module；各 domain RPC 只保留 payload 语义与协议校验。

Benefits

  • locality: timeout / cleanup
  • late response 一处处理
  • leverage: 11 个 RPC
  • domain tests 只验语义
现有远端 owned seam 保留：Gateway↔IM 的 WebSocket frames 不变；production WebSocket adapter 与 in-memory test adapter 让该 seam 成立。

Candidate 05

收回 managed channel composition ownership

Strong ports & adapters

src/personal_assistant/main.py · gateway/channel_manager.py · gateway/channel_manifest_store.py · gateway/agent_config_sync.py · ws/im_connection.py · channels/feishu/

Problem

build_runtime() 用 25 个 closure 实现跨 owner 的 channel control policy，并穿透 IMAgentConfigSync private API；main namespace 又被 38 个测试文件当 service locator。

Solution

把 managed channel 的 credential、manifest、provider construction、status/retry/reconcile 收进一个 deep module；composition root 只负责构造和连接。其余已成形的 deep module 原样迁出。

Benefits

  • locality: channel control 不变量
  • leverage: 新 provider 复用
  • 测试命中真实 interface
  • main 只做 composition
  • 删除 test-only re-export
不是笼统拆大文件：GatewayRuntime 已把启动、关闭、资源顺序与 deadline 封装成深模块；process lifecycle 也有连贯边界。删除测试表明它们应该整体迁移并保留，而不是继续拆散。
延续 refactor-461 / refactor-463 的决策：保留现有 runtime shutdown graph 与已抽出的 state owners；只收回仍滞留在 composition root 的跨 owner integration policy。这是 personal_assistant/main.py 专项的首选候选。

Top recommendation

先收拢 permission request 生命周期

它同时具备最强的删除测试证据与跨产品 leverage：core 正在穿透 broker 的 private state，测试又复制同一套竞态算法。把 exactly-once resolution、interrupt、cancel 和 liveness 放回一个 owner，可直接把最危险的并发不变量变成稳定 test surface；同时不需要改变公开 SDK 或产品行为。
