Candidate 01

让 permission request 拥有一个完整事务 owner

Strong in-process

src/agent/core/agent/runtime.py:1232–1434 · src/agent/platform/permissions/broker.py:102–226 · src/agent/sdk/kernel.py:1456–1537 · tests/unit/test_permission_requester_cancel.py:27–225

Problem

PermissionBroker 声称独占 pending state，但约 190 行 runtime closure 又拥有 register-before-publish、双路 race、liveness、loser drain 与 resolved ordering，并直接穿透 _lock/_pending。

Solution

让既有 broker 用独立 supervisor 吞下 register 到 resolve/cancel/publish/cleanup；新增 loop-neutral 本地交互 port，既有三参数 callback 保持兼容。

Benefits

  • locality: exactly-once 决策
  • run-scoped cancel 同测
  • 删除复制 race 测试
  • CLI / Gateway leverage
约束：保持 core 不 import platform；只在现有注入方向内增加 depth，不反转 SPEC.md 的层次依赖。

Candidate 02

给 CLI 一个 session stream owner

Strong in-process

src/coding_cli/commands.py:541–584, 894–1086 · src/coding_cli/events/background_runs.py:8–50 · src/coding_cli/events/event_pipeline.py:40–318 · src/agent/core/events/hub.py:178–239

Problem

REPL 的 persistent subscriber 与每轮 _send_message_async 同时订阅同一 session；foreground 事件被再次送入 background processor，user-run pending state 不会清理。与此同时，normalize/dedupe/phase interface 基本没有 production caller。

Solution

让一个 CLI event-consumption deep module 独占 session stream、replay/dedupe、foreground/background routing、interrupt 与 terminal finalization；删除未接入的平行设计。

Benefits

  • 单一 subscription owner
  • bounded background state
  • tests 命中真实路径
  • commands 只做 composition
删除测试：当前大部分 event_pipeline.py 可删除而不搬走 production complexity；反过来删除任一 subscriber 又会破坏一条 routing path。这正是 shallow module 与分裂 ownership 同时存在的证据。

Candidate 03

深化 owned IM↔Gateway control-plane seam

Strong ports & adapters

src/IM/ws/gateway/control.py:18–787 · src/IM/ws/gateway/runtime.py:143–180 · src/personal_assistant/ws/im_connection.py:250–348, 843–1335 · src/IM/api/routes/agents.py:639–650

Problem

IM 侧 11 类 RPC 重复 request-id/Future/send/timeout/finally lifecycle；PA 侧 transport constructor 与 listen loop 又知道每种 domain operation、filesystem 访问和回复 shape。新增一项 control RPC 必须同时扩张两个宽 interface。

Solution

在既有 owner 内增加 depth：IM 侧集中 correlation lifecycle，PA 侧把 typed domain dispatch 从 wire/FIFO/reconnect transport 中收回；WebSocket frame contract 保持不变。

Benefits

  • leverage: 11 类 RPC
  • late reply 一处处理
  • transport tests 更窄
  • 新增 operation 不扩 wire
继承 refactor-472：GatewayControl 仍是唯一 waiter owner 并保留 shared lock；不拆成 per-RPC module，不新增 target-node 校验，不改变 timeout / empty fallback。
继承 refactor-470：IMConnectionManager 仍独占 wire、FIFO、ACK、reconnect 与 close ordering；不引入 generic untyped event bus 或第二条 queue。

Candidate 04

让 skill-batch review 生命周期只实现一次

Strong in-process + local adapter

src/agent/platform/tools/builtins/skill_view.py:141–180 · src/agent/core/agent/runtime.py:861–930 · src/agent/sdk/kernel.py:1749–1785 · src/coding_cli/product.py:157–266 · src/personal_assistant/gateway/runtime.py:86–113, 494–618

Problem

Candidate 06

拆开 Gateway 本地配置的六个变化轴

Strong durable + runtime

src/personal_assistant/config/local_store.py:1–1390 · src/personal_assistant/main.py · gateway composition · reconnect/token/config write paths

Problem

schema、serialization、durability、process snapshot、runtime connection facts 与领域 mutation 同处一个类；一次 token rotation 或 model no-op 都可能重写整份 YAML。

Solution

建立 config-scoped writer lease 与 durable store；runtime URL/token overlay、model/Feishu mutation 走各自 owner，并用明确 durability warning 处理远端已提交、本地落盘失败。

Benefits

  • 唯一 durable writer
  • no-op 零写盘
  • token 不回退
  • 变化轴可独立测试

Top recommendation

先收拢 permission request 的完整事务

这是当前最危险、也最容易用删除测试证明的 ownership split：runtime 穿透 broker private state，Kernel 的 interrupt/cancel 又各自知道 pending policy，测试还复制 production race。把 exactly-once resolution、liveness、run-scoped cancel、跨 loop 本地交互与 cleanup 放回一个 owner，可同时提高 CLI 与 Gateway 的 correctness locality。既有三参数 SDK callback 保持不变，仅为可取消 CLI 交互新增可选 SDK-owned port。
