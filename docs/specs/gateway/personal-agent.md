# Gateway Personal Agent Specification

> 对齐: bugfix-678

## Purpose

定义个人助手在普通 Global Agent 上增加的主人身份、消息来源与对外披露边界；通用执行、工具、任务及调度继续由现有 area 定义。

## Requirements

### Requirement: PA 复用完整 Global 执行能力
#### Scenario: 主人请求与普通工具
- **WHEN** 主人交办工作或查询历史
- **THEN** 直接进入 Global 主上下文，复用普通工具、Skills、插件、任务、子 Agent 与调度；不增加主人输入审核或 PA 目标引擎。

### Requirement: PA 双身份消息保留可信来源

#### Scenario: 合并历史与新消息
- **WHEN** 查询或接收主人授权聊天和 PA 自己聊天的消息
- **THEN** 当前权限有效的两者并集可见，重复消息只处理一次，主人发出的消息也摄入，PA 自发消息不引起循环。
- **AND** 保留真实发送者、主人身份、原会话类型、渠道、时间、内容以及 PA 参与或观察该会话的事实，不预先将主人原话分类为指令或事实。

#### Scenario: 同一主人在不同聊天发言
- **WHEN** 主人在 PA 私聊、共同群聊和 PA 未参与的聊天中发言
- **THEN** 主人身份一致；实际是否向 PA 交办由原话和对话上下文判断，其他人自称主人不能改变身份。

#### Scenario: 观察者接入不等于直接请求
- **WHEN** PA 通过主人权限看到自己未参与的聊天
- **THEN** Inbox 来源与读取结果的会话上下文明确观察关系，主人和他人的收发均可读，但不自动成为 PA 的任务、控制命令或对外发送授权。
- **AND** 普通观察内容不被当作对 PA 的直接请求进行逐条请求检查或自动向原聊天发送拒绝警告；当前来源访问和对外披露约束继续生效。

### Requirement: 来源控制仅改变未来访问

#### Scenario: 排除聊天
- **WHEN** 主 PA 按主人向它提出的原始要求调用来源工具
- **THEN** 后端核实主人与原会话上下文，拒绝后续访问并撤销待处理输入，不清空记忆、成果或运行上下文。

#### Scenario: 观察文本不控制来源
- **WHEN** 主人向他人说了与来源设置相关的话
- **THEN** 不能仅引用该观察消息替 PA 改变来源权限。

### Requirement: 独立披露检查限定于对外行为
#### Scenario: 对外发送与私人工作
- **WHEN** PA 发出消息或修改共享内容
- **THEN** 实际外发核对真实授权、完整 payload 与受众；主人私聊和私人工作不加 PA 审核，原工具权限继续生效。
- **AND** 不把该检查声明为任意代码/插件的完整网络隔离。

#### Scenario: 长期使用后继续已授权工作
- **WHEN** PA 已读取相关对话，主人已明确授权向指定受众发送
- **THEN** 独立审核依据 PA 当前有效上下文与真实受众核对，不因无关聊天历史积累而要求重复授权或阻止发送。
#### Scenario: 换窗后证据不足
- **WHEN** 当前有效上下文不足以核对外发授权或私有信息来源
- **THEN** 不发送；可以按正常历史恢复路径取回原话后重新审核，记忆、摘要和助手的授权声明不能单独放行。

### Requirement: 默认服务指导复用普通配置和 Skill

#### Scenario: 用户调整服务方式
- **WHEN** 主人修改或清空 PA 的 custom_prompt
- **THEN** 沿用普通 Agent 的配置和 Persona 加载机制，运行时不暗中补回默认服务文案；固定主人身份、来源、权限及对外披露规则仍有效。

#### Scenario: 跨轮次持续工作
- **WHEN** Global 或 PA 接续已接受的持续事项
- **THEN** 可按普通 Skill 发现、选择和加载机制使用随包 nano-ongoing-work，复用已有工作记录、任务、子 Agent、Heartbeat 和 schedule；不新增 PA 账本服务或调度器，不覆盖用户已有 ongoing-work Skill，也不绕过用户禁用选择。

#### Scenario: 重要观察后的私人准备
- **GIVEN** PA 使用默认服务指导，相关来源已获准访问且对应 Skill 未被禁用
- **WHEN** 观察到与主人有关的重要变化或承诺
- **THEN** 可按需使用 nano-proactive-care，核对原话和后续状态，在现有权限内准备有实际内容的私人草稿或材料；不把观察到的承诺当作对外发送授权，不增加新的关注项服务或调度器。
- **AND** 已处理或没有新帮助价值时保持安静；可读取的信息不足时保留不确定性，不声称已完整核实。

#### Scenario: 已交办事项中的权限阻塞
- **WHEN** 内部执行者报告权限阻塞
- **THEN** 主 Agent 核对具体动作、拒绝理由、原始要求和有效限制，继续允许的独立部分；已有授权覆盖的事项不因内部委派或跨轮次就要求用户重新批准。
- **AND** 父级只能澄清自己的交办限制，不能新增人类授权或推翻用户限制；必要的新权限问题须具体，答复交回原执行者，实际动作仍走正常权限检查，不换介质重复被拒动作。

### Requirement: 联系人风险由服务器身份与主人决定承载

#### Scenario: 被屏蔽账号在共同群发言
- **WHEN** Web IM 同一账号在任意有权接收的群聊发言
- **THEN** 后端仍准入消息，服务端的 actor_risk 随主 PA inbox_read 结果传递，不能由消息正文自称解除；PA 参与会话的独立输入检查同样获得此风险，观察会话按背景处理，不自动向原聊天警告。
- **AND** 群内屏蔽联系人仍列入外发审核证据，不硬性禁止其他正常协作。

#### Scenario: 撤销限制
- **WHEN** 主人在配置页解除屏蔽
- **THEN** 服务端删除当前限制、递增原策略版本并发出 policy.changed，主 PA 得知限制已撤销；历史理由不再自动构成当前风险标记。

### Requirement: PA 观察聊天即时可读并按十分钟合并通知

#### Scenario: 首批与后续节奏
- **WHEN** 未参与聊天有新的授权观察消息
- **THEN** 消息立即持久保存并可读取，首批从第一条积累消息起十分钟后通知；后续在距上次背景通知至少十分钟且存在新增未读时通知，连续输入不推迟截止。
- **AND** 到点无需下一条来信；无新增未读不空通知。

#### Scenario: 忙碌与重启
- **WHEN** 背景期限已到但 PA 正忙，或节点在等待期间重启
- **THEN** 保留累计消息与已确定期限，空闲且运行可用后合并通知，不硬中断当前工作、不逐批补发过时通知、不从重启重新计十分钟。

#### Scenario: 主人提前来信
- **WHEN** 主人直接请求引用未到期背景
- **THEN** 及时提醒并允许立即读取已积累内容，不等十分钟；顺带完整读取的消息不再触发后续背景提醒。

#### Scenario: 提醒与消费独立
- **WHEN** 已提醒但尚未完整持久摄取消息
- **THEN** 消息仍未读；来源撤销后停止新读取与通知，不因曾经提醒而标成完成。

### Requirement: PA 原始授权按身份与对话上下文核对

#### Scenario: 共同群内明确交办
- **WHEN** 可信主人在共同群明确向 PA 授权一项工作
- **THEN** 该原文与实际对话上下文可供主 PA 和独立审核核对，不因不是主人私聊而一律排除。

#### Scenario: 主人向他人承诺
- **WHEN** PA 观察主人向他人答应处理一件事
- **THEN** 主人身份不自动使这句话成为对 PA 的授权；可以结合已有任务协助，超出既有授权的外发仍受约束。

### Requirement: PA 自身发送与代表用户发送使用明确工具边界
#### Scenario: 只有主人参加的会话
- **WHEN** PA 可观察主人参加、但 PA 自身未参加的会话
- **THEN** 共用 send_message 不借主人权限发送；有真实委托时使用 PA 专属 send_user_message，在主人当前写权限及来源范围内代表发送。
- **AND** 普通 Agent 与内部子 Agent 不获得代表发送能力；PA 自身回复、报告与协作仍使用共用普通发送。

### Requirement: PA 在真实委托内自然代表用户表达
#### Scenario: 代表回复与助手发言
- **WHEN** 主人委托 PA 向 Nano IM 的指定受众回复
- **THEN** PA 区别代表用户和自身发言，依据原话与相关会话起草自然用户口吻，不加入“让我转告”等过程前缀，不增加承诺；完整拟发内容与受众通过原始授权及披露检查后才发送。
- **AND** 系统提供可信用户主体和实际 PA 来源，不能由正文、普通 Agent 或旧标签自行声明；不扩展会话写入或第三方渠道权限。
#### Scenario: 指代解析与实质歧义
- **WHEN** 用户私聊中的称呼能从相关上下文确定
- **THEN** PA 自行转换为用户面对目标受众的自然称呼；确有会改变交办范围的多种解释时只澄清具体对象或范围，未明确前不代发。

### Requirement: 接收 Agent 与审核延续同一公开用户委托
#### Scenario: 正常执行与范围约束
- **WHEN** Agent 收到产品核验的代表用户消息
- **THEN** 将公开原文理解为该用户通过 PA 在此会话表达的意思，在原范围内正常审核与执行，不仅因为 PA 代发而重复索取同一批准。
- **AND** 外发检查通过不等于执行动作已获无条件许可，后续撤回或修改继续有效；无可信来源、伪造转述和超范围动作不获得权限，接收方无需读取用户整个私人 PA 聊天；发言主体由普通用户 sender 表达，可选 PA ID 仅说明代发者，不额外提供授权等级。
#### Scenario: 历史、恢复与子 Agent
- **WHEN** Agent 通过正式消息查询恢复原文、恢复会话或交给执行子 Agent
- **THEN** 保留原用户、实际 PA、会话、原文和限制，已存在的委托不降为普通 Agent 转述；历史不成为新许可事件，不重新触发已完成动作。
- **AND** 用户要求联系代发 PA 时，可用保留的 PA ID 经现有寻址与权限路径联系正确 Agent。
#### Scenario: 不自我扩大授权
- **WHEN** PA 读取自己过去代表用户发出的消息或旧代发标签
- **THEN** 能理解历史，但不能把它当成新的原始主人委托来扩大授权、改变来源控制或形成自回声任务；旧记录不会因升级自动获新授权。

### Requirement: PA 输入审核以消息为独立准入单位

#### Scenario: 单条拒绝和技术失败
- **WHEN** 非主人 participant 消息被拒，或同一次审核经统一底层恢复仍失败
- **THEN** 只结算该条拒绝或故障；不撤销整个来源，不阻塞其他已准入消息，不把故障描述为安全拒绝。
- **AND** 主 PA 获得准确原因及消息引用；已报告失败不因启动、Inbox check/read 自动再次审核。

#### Scenario: 显式重审与恢复
- **WHEN** 主 PA 对故障消息显式请求重审，或节点恢复
- **THEN** 重审重新检查当前来源并执行同一审核，不允许直接设置 allow；重复终态不重审，未完成审核中断明确报错，消息状态和其他已准入输入保持。

### Requirement: 输入审核获得有界原始对话背景

#### Scenario: 连续对话与直接回复
- **WHEN** 审核一条外部消息
- **THEN** 提供完整当前消息、该消息之前最近 20 条原聊天消息，以及窗口外可访问的直接回复目标一次；保留真实发送者、顺序与来源，历史仅为证据。

#### Scenario: 超限和恢复
- **WHEN** 历史超预算、回复缺失或审核恢复
- **THEN** 从最旧历史整条省略并标明缺失；当前消息无法完整提供则明确失败；不加入待审消息之后的新消息或越权读取背景。

### Requirement: 主 PA 执行安全事件的提醒与拒绝

#### Scenario: 风险处置
- **WHEN** 输入被判 deny 或带需处置 incident
- **THEN** 不把其准入为普通任务；系统持久提供事件事实给主 PA，PA 先向主人提醒，再通过正常发送工具向原聊天拒绝，后端不替 PA 写模板消息。
- **AND** 有限安全处置不授权转发私人资料、攻击原文或代表主人承诺；对外文案独立审核，只有真实回执才算送达。

#### Scenario: 暂停与发送结果未知
- **WHEN** PA 暂停、处置中断或发送结果未知
- **THEN** 保留未完成事实，不启动用户停止的 PA；恢复先核已有回执，不重复确认送达的消息，不把未知结果当可安全重发。

### Requirement: 外发审核凭证只随实际条件变化而失效

#### Scenario: 无关披露与时间经过
- **GIVEN** 精确动作已通过独立审核且尚未提交
- **WHEN** 另一动作先提交或经过超过 60 秒
- **THEN** 不因全局披露计数或时间经过强制重审；完整内容、受众、权限、来源、生命周期和一次性提交条件仍检查。

#### Scenario: 真实条件改变
- **WHEN** 新消息需要重新考虑动作，或内容、附件、受众、权限、主人授权及其他实际提交条件变化
- **THEN** 不直接发送，向 PA 返回未发送及具体变化原因；由 PA 决定后续，不自动重新审核后代发。
- **AND** 已提交或结果未知仍按原操作查询回执，不借旧凭证更换内容或重复执行。

### Requirement: 披露审核实际消费待发图片

#### Scenario: 授权图片与隐含私人信息
- **WHEN** PA 向他人发送支持范围内的图片
- **THEN** 审核模型实际收到冻结图片和正文、受众、原授权上下文，按完整内容判断；文字无敏感信息不代表图片可免审。
- **AND** 仅允许审核的同一字节内容发送，变化必须返回未发送并重新决策。

#### Scenario: 能力或材料不足
- **WHEN** 图片不可访问、格式/尺寸/数量超限、模型不支持或实际请求不能装入完整图片
- **THEN** 明确报告能力或处理故障，不以 URL、文件名、助手描述或占位文本代替看图，不声称主人未授权，不静默漏图放行。
