# Gateway Personal Agent Specification

> 对齐: feat-805

## Purpose

定义个人助手在普通 Global Agent 上增加的主人身份、聊天创建独立 Agent、消息来源与对外披露边界；通用执行、工具、任务及调度继续由现有 area 定义。

## Requirements

### Requirement: PA 复用完整 Global 执行能力

#### Scenario: 主人请求与普通工具
- **WHEN** 主人交办工作或查询历史
- **THEN** 直接进入 Global 主上下文，复用普通工具、Skills、插件、渐进式任务图、子 Agent 与调度；不增加主人输入审核或脱离既有 Global 与任务图底座的第二套独立执行引擎。
- **AND** 日常直接处理、完整独立事项的单一内部执行责任、原执行者接续及主 Agent 唯一沟通交付均遵循 [Global 契约](global-agent.md)，不另设 PA 专属 Agent Loop。

### Requirement: PA 双身份消息保留可信来源

以下自动收件限于当前协作范围；主动历史查询继续受来源访问控制。

#### Scenario: 合并历史与新消息
- **WHEN** 查询或接收主人授权聊天和 PA 自己聊天的消息
- **THEN** 当前权限有效的两者并集可见，重复消息只处理一次，主人发出的消息也摄入，PA 自发消息不引起循环。
- **AND** 保留真实发送者、主人身份、原会话类型、渠道、时间、内容以及 PA 参与或观察该会话的事实，不预先将主人原话分类为指令或事实。

#### Scenario: 同一主人在不同聊天发言
- **WHEN** 主人在 PA 私聊、共同群聊和 PA 未参与的聊天中发言
- **THEN** 主人身份一致；实际是否向 PA 交办由原话和对话上下文判断，其他人自称主人不能改变身份。

#### Scenario: 观察者接入不等于直接请求
- **WHEN** PA 通过主人权限看到自己未参与的聊天
- **THEN** Inbox 来源与读取结果的会话上下文明确观察关系，主人和他人的收发均可读，但不自动成为 PA 的任务、控制命令或对外发送授权。
- **AND** 普通观察内容不被当作对 PA 的直接请求进行逐条请求检查或自动向原聊天发送拒绝警告；当前来源访问和对外披露约束继续生效。

### Requirement: 独立披露检查限定于对外行为

PA 与普通/全局 Agent 各档位的协作与免审边界遵循 [IM 统一权限矩阵](../im/auth-tenancy.md#requirement-agent-与个人助手按统一权限矩阵控制发现会话轨迹与披露审核)。

#### Scenario: 纯主人私有域免审与跨圈强制审核
- **WHEN** PA 向主人专属私聊（Web PA 私聊或已绑定的飞书/微信主人单聊），或向仅含主人本人与同主人「私有」（`owner_only`）助手的纯主人私有会话发送消息、任意合法图片与通用附件（含 GIF、超长图、PDF 等文件，图片 `≤ 10 MiB`、通用文件 `≤ 25 MiB`，不受多模态审核图片帧数/像素上限限制）或修改任务内容
- **THEN** 无需独立披露审核直接提交送达并落库确认，原工具权限继续生效
- **WHEN** PA 向任何非纯主人私有域会话（包括同主人名下的「项目级」`project` 或「团队公开」`team` 助手会话、含外部成员的群聊或外部成员私聊）发出消息、附带附件或修改共享任务内容
- **THEN** 实际外发强制核对真实主人授权、完整 payload 与真实受众（当收件方包含非 PA 的 `project` 或 `team` 助手时，冻结受众证据显式标明该助手协作档位及下游可见的项目私密群成员或团队成员范围）
- **AND** 出站审核的交互卡片保留待发的完整源码和替换引用，省略渲染协议字段；不把该检查声明为任意代码/插件的完整网络隔离。

#### Scenario: 长期使用后继续已授权工作
- **WHEN** PA 已读取相关对话，主人已明确授权向指定受众发送
- **THEN** 独立审核依据 PA 当前有效上下文与真实受众核对，不因无关聊天历史积累而要求重复授权或阻止发送。
#### Scenario: 换窗后证据不足
- **WHEN** 当前有效上下文不足以核对外发授权或私有信息来源
- **THEN** 不发送；可以按正常历史恢复路径取回原话后重新审核，记忆、摘要和助手的授权声明不能单独放行。

### Requirement: 系统维护 PA 默认服务指导与 Skill 协作

默认服务指导将 PA 定位为长期辅助主人履行职责、追求目标并兼顾工作与生活的助手，结合相关目标、偏好、关系、承诺和新事实判断有帮助的下一步；共享 Global 指引提供内部委派与对外交付分工，不将 PA 固定为只处理新请求的接单者。实际信息范围和行动权限仍沿用当前契约。

#### Scenario: 用户调整服务方式
- **WHEN** 主人希望调整长期帮助目标、分工或服务习惯
- **THEN** 通过同一 `ROLE` 入口确认和保存；不提供 `custom_prompt`。PA 固定主人关系、来源与权限边界保持原有效力。

#### Scenario: 主请求与记忆整合获得 PA 定位
- **WHEN** PA 发起主会话请求（含平时安静后轻量记账与夜间深度筹划唤醒）或 Dreaming 整合
- **THEN** 获得系统 PA 默认服务指导与已确认 `ROLE`；普通 Global 和内部 worker 不获得根 PA 的专属服务段。

#### Scenario: 跨轮次持续工作统一收敛至渐进式目标图
- **WHEN** Global 或 PA 接续持续事项或主人的跨天目标
- **THEN** 可按普通 Skill 发现、选择和加载机制使用随包 `nano-ongoing-work`，优先通过单卡与渐进式目标图记录目标与跨天跟进，避免在私有 Markdown 文件另建与任务面板脱节的第二套待办流水账；不覆盖用户已有自定义 Skill，也不绕过用户禁用选择。

#### Scenario: 重要观察后的私人准备与提议立卡
- **GIVEN** PA 或启用主动筹划的全局数字员工使用默认指导，相关来源已获准访问且对应 Skill 未被禁用
- **WHEN** PA 观察到与主人有关的重要变化、承诺或长线目标缺口（或全局数字员工识别到岗位职责相关的跟进缺口）
- **THEN** 可按需使用共享随包 `nano-proactive-care`：PA 按主人私聊闭环核对原话和后续最新状态，在现有权限内准备要点或工作区草稿文件于提醒时递交，或对需主人拍板的延伸动作在私人空间建立 `proposed` 待拍板提议卡（普通全局数字员工则遵循 [Global 岗位主动性契约](global-agent.md#requirement-全局数字员工围绕岗位职责执行两阶段静默运转原会话归属与低噪触达) 按原会话闭环与静默挂板规则行动）；不把观察到的承诺当作对外发送授权。
- **AND** 已处理、触及持久记忆中划定的免提议边界或没有新帮助价值时保持安静；可读取的信息不足时保留不确定性，不声称已完整核实。

#### Scenario: 已交办事项中的权限阻塞
- **WHEN** 内部执行者报告权限阻塞
- **THEN** 主 Agent 核对具体动作、拒绝理由、原始要求和有效限制，继续允许的独立部分；已有授权覆盖的事项不因内部委派或跨轮次就要求用户重新批准。
- **AND** 父级只能澄清自己的交办限制，不能新增人类授权或推翻用户限制；必要的新权限问题须具体，答复交回原执行者，实际动作仍走正常权限检查，不换介质重复被拒动作。

### Requirement: 联系人风险由服务器身份与主人决定承载

#### Scenario: 被屏蔽账号在共同群发言
- **WHEN** Web IM 同一账号在任意有权接收的群聊发言
- **THEN** 后端仍准入消息，服务端的 actor_risk 随主 PA inbox_read 结果传递，不能由消息正文自称解除；PA 参与会话的独立输入检查同样获得此风险，观察会话按背景处理，不自动向原聊天警告。
- **AND** 群内屏蔽联系人仍列入外发审核证据，不硬性禁止其他正常协作。

#### Scenario: 撤销限制
- **WHEN** 主人在配置页解除屏蔽
- **THEN** 服务端删除当前限制、递增原策略版本并发出 policy.changed，主 PA 得知限制已撤销；历史理由不再自动构成当前风险标记。

### Requirement: PA 观察聊天即时可读并按十分钟合并通知

#### Scenario: 首批与后续节奏
- **WHEN** 无论 PA 处于「团队公开」还是「私有」，主人获准观察的未排除聊天有新的普通背景消息
- **THEN** 消息立即持久保存并可读取，首批从第一条积累消息起十分钟后通知；后续按下一批首条积压起算；有高优输入时提前合并，连续输入不推迟截止。
- **AND** 到点无需下一条来信；无新增未读不空通知。
- **AND** 提醒直接提供待读会话名称、可读取引用、未读数、实际 @ 本 PA 的消息数及 participant / observer 关系；可直接按需 read，check 仅用于主动刷新，摘要本身不消费正文或授予任务。

#### Scenario: 忙碌与重启
- **WHEN** 背景期限已到但 PA 正忙，或节点在等待期间重启
- **THEN** 保留累计消息与已确定期限，空闲且可用时唤醒；忙碌时在下一次模型请求前合并通知，不硬中断当前工作、不逐批补发过时通知、不从重启重新计十分钟。

#### Scenario: 主人提前来信
- **WHEN** 主人直接请求，或他人私聊主人、实际 @ 主人、回复或引用主人的消息
- **THEN** 及时合并提醒并允许立即读取积压；主人主动与别人聊天属于背景。提醒区分消息发给谁与 PA 的观察身份，已带出的同一批不在原到期时重复提醒。

#### Scenario: 提醒与消费独立
- **WHEN** 已提醒但尚未完整持久摄取消息
- **THEN** 消息仍未读；来源撤销后停止新读取与通知，不因曾经提醒而标成完成。

### Requirement: PA 原始授权按身份与对话上下文核对

#### Scenario: 共同群内明确交办
- **WHEN** 可信主人在共同群明确向 PA 授权一项工作
- **THEN** 该原文与实际对话上下文可供主 PA 和独立审核核对，不因不是主人私聊而一律排除。

#### Scenario: 主人向他人承诺
- **WHEN** PA 观察主人向他人答应处理一件事
- **THEN** 主人身份不自动使这句话成为对 PA 的授权；可以结合已有任务协助，超出既有授权的外发仍受约束。

### Requirement: PA 自身发送与代表用户发送使用明确工具边界
#### Scenario: 只有主人参加的会话
- **WHEN** 「团队公开」PA 可观察主人参加、但 PA 自身未参加的会话
- **THEN** 共用 send_message 不借主人权限发送；有真实委托时使用 PA 专属 send_user_message，在主人当前写权限及来源范围内代表发送。
- **AND** 普通 Agent 与内部子 Agent 不获得代表发送能力；PA 自身回复、报告与协作仍使用共用普通发送。

#### Scenario: 私有 PA 允许联系同主人名下助手但禁止向外部会话发言或代发
- **WHEN** 处于「私有」（`owner_only`）的 PA 向主人私聊或同主人名下的任意可用助手（含 `owner_only`、`project`、`team`）发送消息或附件
- **THEN** 均允许发起投递（其中发往 `owner_only` 助手免审，发往 `project` 或 `team` 助手须通过独立披露审核）
- **WHEN** 处于「私有」（`owner_only`）的 PA 尝试向含外部成员的群聊、与外部同事的私聊或非主人外部渠道调用 `send_message` 或 `send_user_message`
- **THEN** 发送在服务端与网关边界被拒绝，不产生任何对外消息，并向模型返回 `not_sent` 及明确私有范围说明，引导其改为在主人私聊或主人内部专属会话中汇报。

### Requirement: PA 在真实委托内自然代表用户表达
#### Scenario: 代表回复与助手发言
- **WHEN** 主人委托 PA 向 Nano IM 的指定受众回复
- **THEN** PA 区别代表用户和自身发言，依据原话与相关会话起草自然用户口吻，不加入“让我转告”等过程前缀，不增加承诺；完整拟发内容与受众通过原始授权及披露检查后才发送。
- **AND** 系统提供可信用户主体和实际 PA 来源，不能由正文、普通 Agent 或旧标签自行声明；不扩展会话写入或第三方渠道权限。
#### Scenario: 指代解析与实质歧义
- **WHEN** 用户私聊中的称呼能从相关上下文确定
- **THEN** PA 自行转换为用户面对目标受众的自然称呼；确有会改变交办范围的多种解释时只澄清具体对象或范围，未明确前不代发。

### Requirement: 接收 Agent 与审核延续同一公开用户委托
#### Scenario: 正常执行与范围约束
- **WHEN** Agent 收到产品核验的代表用户消息
- **THEN** 将公开原文理解为该用户通过 PA 在此会话表达的意思，在原范围内正常审核与执行，不仅因为 PA 代发而重复索取同一批准。
- **AND** 外发检查通过不等于执行动作已获无条件许可，后续撤回或修改继续有效；无可信来源、伪造转述和超范围动作不获得权限，接收方无需读取用户整个私人 PA 聊天；发言主体由普通用户 sender 表达，可选 PA ID 仅说明代发者，不额外提供授权等级。
#### Scenario: 历史、恢复与子 Agent
- **WHEN** Agent 通过正式消息查询恢复原文、恢复会话或交给执行子 Agent
- **THEN** 保留原用户、实际 PA、会话、原文和限制，已存在的委托不降为普通 Agent 转述；历史不成为新许可事件，不重新触发已完成动作。
- **AND** 用户要求联系代发 PA 时，可用保留的 PA ID 经现有寻址与权限路径联系正确 Agent。
#### Scenario: 不自我扩大授权
- **WHEN** PA 读取自己过去代表用户发出的消息或旧代发标签
- **THEN** 能理解历史，但不能把它当成新的原始主人委托来扩大授权、改变来源控制或形成自回声任务；旧记录不会因升级自动获新授权。

### Requirement: PA 输入审核以消息为独立准入单位

#### Scenario: 参与群背景消息按唤醒批次合并送审
- **WHEN** 「团队公开」下，PA 参与的含外部成员群收到无需立即唤醒的非主人消息
- **THEN** 消息记录原始到达期限并暂存待审，不在抵达时逐条请求审核模型，也不在审核完成前进入可读 Inbox、通知摘要或主 PA 主动消息查询结果；在首批积压满十分钟、高优唤醒合并、主 PA 主动执行 `inbox` check/read 或消息历史查询/搜索、向该会话外发消息前重验，或同一会话待审积压满 20 条时，按会话合并送审并逐条独立结算。
- **AND** 送审前该会话访问权被撤销、被主人排除，或因协作范围收紧为「私有」退出该外部群时，该外部参与者待审积压直接清退，不再发起审核模型请求（若主人本人仍在群内且未排除该群，后续新消息按 `observer` 旁观规则处理）。

#### Scenario: 单条拒绝和技术失败
- **WHEN** 非主人 participant 消息在单条或会话批量审核中被拒、单条不再可访问，或经统一底层恢复仍失败
- **THEN** 只结算该条拒绝、单条不可访问或故障；不撤销仍可访问的整个来源，不阻塞同批或同会话其他已准入消息，不把技术故障或单条失权描述为安全拒绝。
- **AND** 主 PA 获得准确原因及消息引用；已报告失败不因启动、Inbox check/read、消息查询或后续新消息批量审核而自动再次审核。

#### Scenario: 显式重审与恢复
- **WHEN** 主 PA 对故障消息显式请求重审，或节点恢复
- **THEN** 显式重审仅针对指定故障消息重新检查当前来源并执行审核，不允许直接设置 allow；重复终态不重审，未完成审核中断明确报错，尚未开始审核的待审背景消息保留原到期时间并在到期或读取边界按当前来源权限送审，其他已准入输入保持。

### Requirement: 输入审核获得有界原始对话背景

#### Scenario: 连续对话、批量时间线与直接回复
- **WHEN** 审核同一会话的一条或一批（最多 20 条）外部待审消息
- **THEN** 提供每条待审消息的完整内容、首批待审消息之前最近 20 条可访问原聊天消息、批次内穿插的有界可访问对话上下文（最多 20 条），以及窗口外可访问的直接回复目标（去重）；保留真实发送者、顺序、待裁决标识与来源，历史与穿插非待审消息仅为证据。
- **AND** 输入审核所见的交互卡片保留完整源码和适用的消息替换引用，省略渲染协议字段。

#### Scenario: 超限和恢复
- **WHEN** 历史或穿插背景超预算、多条合并超审核窗口、回复缺失或审核恢复
- **THEN** 先从最旧前序历史与非待审穿插背景整条省略并分别标明缺失原因，必要时省略窗口外回复目标；多条待审合并超出审核模型窗口时拆分为更小批次重试，仅单条本身无法完整装入窗口或待审项带不支持投影的入站附件时将该条明确记为失败；不加入本批最后一条待审消息之后的新消息或越权读取背景。

### Requirement: 主 PA 执行安全事件的提醒与拒绝

#### Scenario: 风险处置
- **WHEN** 输入被判 deny 或带需处置 incident，且该事件未触发系统自动拉黑
- **THEN** 不把其准入为普通任务；系统持久提供事件事实给主 PA，PA 先向主人提醒，再通过正常发送工具向原聊天拒绝，后端不替 PA 写模板消息。
- **AND** 有限安全处置不授权转发私人资料、攻击原文或代表主人承诺；对外文案独立审核，只有真实回执才算送达。
- **AND** 同一联系人每条新拒绝消息均独立交付与处置；重复投递同一消息不重复处置，联系人摘要聚合不复用其他消息的提醒或拒绝回执。

#### Scenario: 通知对象可辨认
- **WHEN** 主 PA 向主人发送首次、后续风险提醒或自动屏蔽通知
- **THEN** 使用当前可核验的联系人显示名与聊天名称/类型，说明本次风险与实际处置，不以模糊代词代替已知对象；跨聊天累计不误写为同一群累计。
- **AND** 来源失权或名称缺失时说明无法核实，不从正文自称猜测身份或访问已撤销材料；姓名和聊天名不构成权限或指令。

#### Scenario: 自动拉黑通知例外
- **WHEN** 第五条风险输入触发系统自动拉黑
- **THEN** 主 PA 仅在主人专属私聊告知已执行的屏蔽及当前状态，不再向原聊天发送该事件的拒绝；该事件以真实主人通知回执为完成条件，不等待对方回执。
- **AND** 黑名单的私聊拒收与群聊风险提示立即生效，不依赖通知送达。

#### Scenario: 暂停与发送结果未知
- **WHEN** PA 暂停、处置中断或发送结果未知
- **THEN** 保留未完成事实，不启动用户停止的 PA；恢复先核已有回执，不重复确认送达的消息，不把未知结果当可安全重发。

### Requirement: 外发审核凭证只随实际条件变化而失效

#### Scenario: 无关披露与时间经过
- **GIVEN** 精确动作已通过独立审核且尚未提交
- **WHEN** 另一动作先提交或经过超过 60 秒
- **THEN** 不因全局披露计数或时间经过强制重审；完整内容、受众、权限、来源、生命周期和一次性提交条件仍检查。

#### Scenario: 真实条件改变
- **WHEN** 新消息需要重新考虑动作，或内容、附件、受众、权限、主人授权及其他实际提交条件变化
- **THEN** 不直接发送，向 PA 返回未发送及具体变化原因；由 PA 决定后续，不自动重新审核后代发。
- **AND** 已提交或结果未知仍按原操作查询回执，不借旧凭证更换内容或重复执行。

### Requirement: 披露审核实际消费待发图片与可审阅文本附件

#### Scenario: 可审阅图片与文本附件按内容审核外发
- **WHEN** PA 向非纯主人私有域会话发送支持范围内的静态光栅图片，或可审阅的严格 UTF-8 文本附件（`text/plain`、`text/markdown`、`text/csv`、`text/tab-separated-values`、`application/json`、`text/yaml`、`application/yaml`、`text/xml`、`application/xml`，严格 UTF-8 编码、不含 NUL 字节且单文件 `≤ 256 KiB`）
- **THEN** 本地待发文件须先经 `pa.action.status` 写权限预检并私密暂存至主人私聊；审核模型实际收到冻结图片或完整文本正文、受众与原授权上下文，按完整内容判断；文字无敏感信息不代表附件可免审
- **AND** 仅允许审核通过的同一字节内容复制到目标会话发送，内容或受众变化必须返回未发送并重新决策。

#### Scenario: PDF 等不可读通用附件按不可读材料结合来源与轨迹从严审核
- **WHEN** PA 向非纯主人私有域会话发送审核器无法直接展开内部正文的合法非光栅通用附件（如 `application/pdf`、Office 文档、压缩包或超 256 KiB 数据文件，单文件 `≤ 25 MiB`）
- **THEN** 系统不新增专用文档解析或二进制读取工具，而是在冻结证据中显式标记该附件内容不可直接读取（`content_review = "unreadable"`），并一并附带服务端核实的文件哈希、本地上传规范路径（若有，且落库公开消息时不向接收方暴露该路径）及可读会话内同哈希原消息附件来源；`download_attachment` 同步返回文件 `sha256` 供轨迹对照
- **AND** 独立披露审核 Agent 按不可读材料的更严格标准判断：仅当主人原始原话结合真实文件来源与可见执行轨迹能够确认主人明确授权向当前受众发送该特定文件（或该文件在可见轨迹中完全由获准面向该受众的材料生成、无未审阅私有来源混入风险）时才放行并复制同一字节内容投递；否则返回拒绝或需主人确认，绝不仅凭文件名放行。

#### Scenario: 损坏图片或审核能力缺失保持 fail-closed
- **WHEN** 发往非纯主人私有域会话的附件不可访问、哈希在准备与提交间变化、声明为光栅图片但解码失败或尺寸/数量超限、需审阅图片但审核模型不支持图像输入，或模型请求无法装入必要审核证据
- **THEN** 明确返回不可审阅/处理故障，不静默漏审放行
- **AND** PA 参与群接收非主人发来附件时的输入安全审核保持既有 fail-closed 边界不变。

### Requirement: 系统累计五次输入风险自动屏蔽联系人

#### Scenario: 阈值与去重
- **WHEN** 同一PA的同一可信联系人累计五条独立注入或恶意套话判定
- **THEN** 系统立即沿用现有黑名单屏蔽；前四条、重复投递、普通授权不足和技术故障不会触发该阈值，Agent不获得黑名单修改工具。

#### Scenario: 自动屏蔽通知
- **WHEN** 系统触发自动屏蔽
- **THEN** 主PA在主人专属私聊说明累计五次及已执行的屏蔽，真实回执确认送达；失败不回退屏蔽，暂停与恢复保留未完成事实，不重复发送，不要求向被屏蔽对象额外发信。
- **AND** 主人已解除时，迟到通知准确说明历史动作和当前已解除状态；来源失权不阻断系统动作告知，但不携带已不可访问的原文。

#### Scenario: 计数重置与升级
- **WHEN** 主人解除屏蔽或将事件标为误判
- **THEN** 解除后从零累计，误判事件退出当前计数；历史证据与回执保留，旧消息重投不重新计数，已生效屏蔽仍通过主人解除入口处理。
- **WHEN** 新规则启用或运行恢复
- **THEN** 新规则从启用后确认的风险开始累计，不追溯旧事件；新计数与自动触发事实跨重启保留。

### Requirement: 来源控制停止后续访问与文档记忆采用，保留原始历史

#### Scenario: 排除聊天
- **WHEN** 主 PA 按主人向它提出的原始要求调用来源工具
- **THEN** 后端核实主人与原会话上下文，拒绝后续访问并撤销待处理输入，不清空原始上下文、成果、Git 或备份。
- **AND** 用户明确提出的停止采用要求当轮及后续适用回答立即遵守，不调用遗忘工具、不登记持久停用名单；Dreaming 从聊天原文理解适用范围并修改正式记忆；来源设置生效与持久记忆清理分别报告，不因保存配置就宣称清理完成。

#### Scenario: 观察文本不控制来源
- **WHEN** 主人向他人说了与来源设置相关的话
- **THEN** 不能仅引用该观察消息替 PA 改变来源权限。

#### Scenario: 外部来源变化和重新允许
- **WHEN** 当前访问资格因成员或来源政策变化而撤销，或主人以后重新允许访问
- **THEN** 权威资格同步覆盖已消费来源，不以未读队列代替完整来源；后续读取和后台整理仍核对当前资格。
- **AND** 重新允许未来访问不自动解除明确的停止使用要求。

### Requirement: 主 PA 按主人明确交办创建长期 Agent

#### Scenario: 创建前对齐并交付
- **WHEN** 主人明确要求 PA 创建独立 Agent
- **THEN** PA 按需取得创建指导和目标电脑真实选项（其中 `collaboration_scope` 默认 `team`，支持按主人要求直接设为 `project` 项目级或 `owner_only` 私有），在聊天中与主人确定配置后执行；已有选择不重复询问，主人可接受推荐值。
- **AND** 默认推荐 PA 所在电脑，不擅自替换主人指定的电脑；真实成功后说明 Agent、职责、电脑和使用入口。

#### Scenario: 讨论与执行边界
- **WHEN** 用户只是讨论需求、PA 提出建议、观察聊天出现相关内容，或用户在提交前撤回
- **THEN** 不据此创建；普通 Agent 和内部子 Agent 不获得该管理入口。

#### Scenario: 固定工具定义与按需细节
- **WHEN** 主 PA 查询选项、提交创建或确认原创建结果
- **THEN** 使用同一固定短工具入口，详细指导与配置选项按需读取；不因加载 Skill 或操作进度动态增删工具定义。
- **AND** Skill 选择与工具执行权限继续生效，无法取得指导或选项时如实说明。

#### Scenario: 配置页独立关闭与重新开启
- **WHEN** 主人打开 PA 配置页管理创建工具
- **THEN** 新建 PA 默认选中该工具，主人可单独关闭或重新开启；关闭后不可调用，Skill 选择独立生效。
- **AND** 关闭沿用既有运行能力生效及占用保护规则；不撤销已经接受的创建操作。

### Requirement: 未关注的话题不进入 PA 的十分钟观察批

#### Scenario: 观察中的群话题
- **GIVEN** PA 获准观察一个群，但没有关注其中某条话题
- **WHEN** 该话题出现没有 @ 它、也没有引用它的回复
- **THEN** 不写入观察事件，这条回复不进入观察 Inbox，也不触发十分钟合并通知
- **AND** PA 此后有权读取该聊天时，仍可按话题根读到这些消息

#### Scenario: 被点名的话题及时可读
- **WHEN** 观察或参与的话题里 @ 了 PA，或引用了它，或它已经关注
- **THEN** 按高优及时可读，不并进普通背景的十分钟批

### Requirement: PA 主动筹划执行主会话平时轻量记账、夜间深度筹划、实质早报触达与唤醒前观察流同步

对角色为个人助手（PA）且开启 `proactive_planning` 的主体，宿主围绕主人全盘目标与获准观察流执行个人化主动思考与实质早报闭环（普通团队全局数字员工的岗位主动筹划与低噪挂板规则见 [Global Agent 规范](global-agent.md#requirement-全局数字员工围绕岗位职责执行两阶段静默运转原会话归属与低噪触达)）。PA 的两类主动唤醒均直接作用于自身主会话（不拆与主会话记忆脱节的孤立短期小会话），夜间睡眠时段顺接在自身标准凌晨 `Dreaming` 之后执行每日一次深度筹划。在日常对话与观察唤醒轮中，PA 依据常驻 `MEMORY.md` 的「主动性与介入偏好」四档校准识别需积极盯紧与提前备料的事项（触发后按需顺链接读取相关背景页）并严守免打扰禁区，且全程不读取后台观察池 `knowledge/proactivity-signals.md`。

#### Scenario: 平时对话安静后主会话轻量记账，不抢发或反复重做早报
- **GIVEN** PA 开启了主动筹划且未处于停用状态
- **WHEN** 主人在 PA 私聊或已获准观察的会话中交流计划、进展或具体时间安排，随后会话进入安静空闲期
- **THEN** 实时对话轮次优先自然快速回复；当存在尚未记账的主人私聊消息或已准入主人相关观察事件且安静满静默窗口时，宿主向 PA 主会话自身提交轻量记账隐藏唤醒 `proactive_review`（到点若主会话正忙则保留未记账水位待空闲后重试；主动唤醒自身回合与被动任务系统通知不推进活动水位，无新增真人活动时零唤醒且不自激），由主会话原位更新已说定的明确任务状态与具体事项跨天 `schedule`，对常驻 `MEMORY.md` 免打扰禁区话题保持零记账，不做重度发散筹划也不折腾明早早报列表（睡前多次补充仅做原位更新）
- **AND** 非免打扰时段（若 `MEMORY.md` 的「触达时机与汇总方式」记录了主人自定义安静时段则优先按该时段判定）仅在发现约一小时内紧急冲突时可简短提醒一句，其余情况及免打扰时段保持聊天静默，轨迹记入 PA 的 Work 记录

#### Scenario: 凌晨紧随标准夜间 Dreaming 之后执行主会话深度筹划并安排实质早报触达
- **GIVEN** PA 开启了主动筹划且未处于停用状态
- **WHEN** 进入本地凌晨睡眠窗口（默认 `03:00–06:00`），自上次夜间筹划以来存在新增主人私聊对话或已准入观察动态，且距最近一次真人活动已满夜间静默时长门禁（防止熬夜跨凌晨连续发言时抢占主会话；全天无新活动或白天开盖时零筹划唤醒）
- **THEN** 若 PA 启用了 `dreaming` 特性且同一有效时区当夜周期的标准 `Dreaming` 尚未完成，在连续失败未达上限（如 3 次）且下次重试未超出凌晨窗口截止时间前，宿主非阻塞返回忙态等待标准凌晨 `Dreaming` 先吸收当日对话与人类任务面板拍板反馈并将最新四档主动性校准落盘至 `MEMORY.md`（用户关闭 `dreaming` 特性或当夜重试越界时直接降级放行，不整晚阻塞），随后向 PA 主会话提交每日最多一次的夜间深度筹划隐藏唤醒 `proactive_nightly`
- **AND** 在 `proactive_nightly` 轮中，宿主在尾部唤醒消息中直接附带较窗口首轮快照有更新的最新 `MEMORY.md` 正文（含最新「主动性与介入偏好」四档规则，不依赖可选文件工具、不静默重写系统提示词前缀，且不加载后台观察池 `knowledge/proactivity-signals.md`），主会话严格遵守免打扰禁区、低打扰挂卡与触达汇总规则，统揽全天对话围绕长线大目标做必要的零副作用查证，准备次日有实质信息量的参考要点或工作区草稿文件，先收起已解决或过时的旧 `proposed` 提议（不标为人类未采纳负反馈），再对符合主动边界的重投入调研、跨 Agent 协作、长线目标前沿下一步或新构想在私人空间建立有界数量的 `proposed` 待拍板提议卡（若主人已有固定早间定时任务，同步将待早间顺递摘要与卡片引用记入跨上下文压缩持久保留的固定笔记工具供次日早间消费）；夜间全程不主动发聊天消息吵人；关闭特性、停用 Agent 或节点更新时立即拦截待触发并取消运行中的 `proactive_review` 与 `proactive_nightly` 唤醒

#### Scenario: 原生定时实质早报顺路触达、准备材料解耦与无干货零唤醒
- **GIVEN** PA 开启了主动筹划
- **WHEN** 夜间深度筹划完成并决定次日早间触达方式，或主人配置的早间、午后、晚间主会话原生定时任务触发
- **THEN** 若主人已配置早间固定定时任务，夜间筹划不另设闹钟，次日早间定时触发时在同一条消息中主动与主人对齐其自身今日计划并顺路附上夜间备好的实质要点、普通工作区文件附件或顶层 `task_cards` 活卡片供参考，尊重主人自身计划决定权而不越权代定日程（准备提纲或文档不耦合进任务图数据结构）
- **AND** 若主人未配置固定早间定时任务，仅当夜间筹划确实产出了有实质信息量的新准备干货或待拍板卡时，由主会话建立一个早间一次性原生 `schedule` 送达实质早报；无任何实质新价值时不建闹钟、保持零唤醒且绝不发送“暂无更新”类空洞早报

#### Scenario: 定时唤醒前同步观察流最新动态并保留私聊未读暂扣
- **GIVEN** PA 的原生定时任务或心跳即将唤醒主会话
- **WHEN** 主人此前已在获准观察的群聊或私聊中发出了尚未满十分钟合并周期的最新消息
- **THEN** 宿主在定时唤醒进入模型首步前等待完成中心待处理观察事件拉取并同步至本地收件箱，对存在未读观察来源的定时轮次向模型提示先读取最新收件箱记录，配合既有的私聊自身未读消息发送暂扣（`held_for_revalidation`），使 PA 在发提醒前能读取最新进展并静默结项已完成事项，避免发出马后炮催问
