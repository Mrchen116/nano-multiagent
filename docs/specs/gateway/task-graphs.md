# gateway - Task Graphs Specification

> 对齐: bugfix-678
> 上级: [gateway Specification](spec.md)

## Purpose

约束 Agent 在任意输入渠道下通过工具维护同一份持久任务记录的行为。

## Requirements

### Requirement: Agent 可按讨论结果维护持久任务图

#### Scenario: 创建、查询和增量修改
- **WHEN** 用户要求已配置任务工具的 Agent 保存或调整讨论好的计划或探索结构
- **THEN** Agent 能建立、读取并修改对应任务图，返回同一图的稳定入口。
- **AND** 保存不按图结构调度执行；分配和结果等协作系统消息遵循既有群接收策略。
- **AND** 节点以图内稳定短编号（如 `n1`、`n2`）读取和更新；改名、排序或状态变化不改变编号，不要求 Agent 反复传递节点 UUID。
- **AND** 图本身也使用短且稳定的引用（如 `tg_a1b2c3d4`）；不同图不会因短 ID 重名而覆盖彼此，工具与 Web 链接使用同一个图 ID。


#### Scenario: 配置任务图特性
- **WHEN** 用户在 Agent 配置中合法开启或关闭默认开启的“任务图”特性并保存
- **THEN** 该 Agent 下一轮回复按最新配置采用任务图能力，当前正在回复的一轮不切换，已有聊天历史和任务图记录保留；关闭有效任务能力后不新增 Task 自动续跑，开启后按当前责任重新检查。
- **AND** 开启 Task 通过界面联动选中 task_graph 和完整 Cron Feature；Task 关闭且工具单独选中时普通任务调用仍可用，自动责任注入、恢复和续跑仍要求 Task Feature，预览采用同一配置。
- **AND** 关闭某个 Agent 的特性不撤销用户按所属会话读取既有任务图的 Web/iOS 访问权，也不改变其他 Agent 或输入渠道的权限。

### Requirement: 图操作使用真实会话与账号归属

资源空间资格是前提，任务访问由固定所属会话决定；私人 Agent 仅访问本人私人空间，公司 Agent 须保持 owner 的公司资格。账号归属核实真实主体，不替代会话权限。加入公司不发布私人会话或其任务。

#### Scenario: 真实身份与公司能力
- **WHEN** 有效成员交办已启用任务工具的真实注册 PA Agent 维护任务
- **THEN** 可跨 owner/Gateway 在所属会话范围内读取同一持久图，写入要求会话成员资格；不接受模型指定身份、未核实内核 child、停用 owner 或过期机器连接。
- **AND** 工具选择及既有身份权限生效，普通任务操作不要求 Task Feature 开启；工具不按任务依赖调度执行；协作系统消息按原群策略处理。

#### Scenario: 外部渠道复用现有主人与 Agent 资格
- **WHEN** 飞书等外部渠道的 Agent 调用任务工具
- **THEN** 复用既有 ownerOpenId 及交办规则；IM 校验 Agent/Gateway 的有效身份、目标空间资格与任务能力，不要求外部发言人另行关联 IM 登录账号。
- **AND** 私人 Agent 不要求公司资格但只能读写自身私人任务；公司 Agent 的管理者未加入公司、待批准或停用时无权读写公司任务；ownerOpenId 不替代这些检查，也不自动转换成外部发言人的 IM user_id。
- **AND** 飞书私聊/群的正常沟通、背景与回复去向保持，无全群核验、关联页面或仅发链接限制。

#### Scenario: IM 不可达时任务调用如实失败
- **WHEN** 飞书 Agent 正常对话期间无法连接 IM 任务服务
- **THEN** 普通渠道继续既有本地自治；任务工具明确返回不可用或结果未知，不宣称任务已保存、不创建本地替代图。

#### Scenario: 来源与无来源操作
- **WHEN** Agent 创建或更新节点
- **THEN** 普通绑定会话采用真实聊天，全局会话只记录可核实来源；显式来源未映射时明确失败，不猜测聊天或创建本地影子图。
- **AND** 创建必须解析所属会话，无绑定来源时显式指定已有会话；编辑可不指定讨论来源，但仍需所属会话写入资格，不伪造用户；每次仅更新实际受影响节点的来源和群活动关联，重试保持原记录。

#### Scenario: 返回稳定入口
- **WHEN** Agent 返回任务图及更新结果
- **THEN** 图与节点短 ID 稳定，外部链接指向既有 IM 公开入口；打开后仍验证资源空间资格、所属会话及受保护来源。

### Requirement: 工具确认、失败与结果未知按真实情况返回

#### Scenario: 过时修改或无效图
- **WHEN** Agent 提交与新版本冲突或破坏图结构的修改
- **THEN** 得到可操作的错误，旧请求不会覆盖新图或落下部分修改。

#### Scenario: 写入结果未知后重试
- **WHEN** 一次写入未取得确认，Agent 以同一请求身份核实或重试
- **THEN** 不重复创建图或节点；无法核实时不声称已保存。

### Requirement: 图查询与记录不改变既有执行语义

#### Scenario: 查询或标记完成
- **WHEN** Agent 查询图或按用户要求更新一个节点的待确认、完成、暂缓、关闭或选定记录
- **THEN** 不消费聊天Inbox，不以此自动执行依赖任务、开子Agent或宣布目标验收通过。

### Requirement: 删除任务遵守真实用户明确要求与既有图一致性

#### Scenario: 删除或自主工作
- **WHEN** 成员明确要求删除已指定范围或确认 Agent 说明的范围
- **THEN** Agent 按会话上下文和统一工具权限流程判断授权，工具授权且实际 Agent 为目标创建者（或真人调用主体为有写资格的公司管理员）时删除该范围并报告真实结果；笼统整理、解散群或主动调度不等于删除授权。
- **AND** 用户无需重复任务标题、ID 或固定确认口令；工具获准后，不要求本轮重新读取真人消息或重新收集删除授权。统一权限拒绝时不执行删除。
- **AND** stale revision、非法结构与结果未知继续按既有冲突/回执契约处理，不能无条件覆盖或重复删除。

### Requirement: Agent 使用真实身份分工并遵循协作状态引导

#### Scenario: 创建、分配与领取
- **WHEN** 真实 Agent 创建、分配或领取任务
- **THEN** 创建者固定为实际 Agent；新子任务默认未分配，负责人可为所属会话成员中的人或 Agent；分配不改状态、不自动入群，领取只允许无负责人或自己负责的任务并表示开始推进。
- **AND** 改派不改创建者，负责人不独占修改权限，工具不能伪造真人或继承其管理者的管理员角色。

#### Scenario: 结果提交与逐层反馈
- **WHEN** Agent 完成任务或收到父任务暂缓、关闭通知
- **THEN** 引导完成工作先标待确认供人核对，但允许直接完成；父子状态不自动联动，通知不强停其他任务、不自动遍历子树执行。
- **AND** 系统消息的事件与有效 @ 对象遵循 [IM 任务协作契约](../im/task-graphs.md)，无独立任务线程、私信或回执审批。

### Requirement: Agent 可发现、创建与自行加入内置群

#### Scenario: 真实主体创建或加入
- **WHEN** 具有既有产品会话工具资格的真实 Agent 列出公开群、创建群或自行加入
- **THEN** 公司内公开群可读；新建群默认公开且可选私密；加入仅作用于 Agent 自己，私密群不允许自行加入。
- **AND** 此能力不授权模型指定其他 Agent 身份，不绕过内部 child 的既有工具限制，不把 Agent owner 身份转换为群管理员。

### Requirement: 任务工具公布动作与参数契约

#### Scenario: Agent 获取任务工具定义
- **WHEN** 已启用任务工具的 Agent 获取模型可见的 task_graph 定义
- **THEN** 工具及参数描述明确五动作字段归属：create 只建根，图内节点与关系使用后续 apply，不混用动作参数。
- **AND** apply 的变更说明字段必填，普通修改允许空说明，重新开启已完成工作仍要求原因。
- **AND** 批内节点定义与引用、仅引用此前定义的节点，以及依赖 from 为前置、to 为后续的方向有就近说明与可用示例。
- **AND** 描述不改变资源归属、权限、原子修改或幂等；图依赖不自动调度后继，直接分配给 Agent 的节点进入 doing 则承担持续推进责任。

### Requirement: Agent SHALL 持续推进全部本人 doing 任务

#### Scenario: 各合法入口开工
- **WHEN** 任一合法入口使任务进入 doing 且负责人为 Agent
- **THEN** 该 Agent 按产品会话范围承担持续推进责任，一轮回复结束仍有下一步时继续；待办分配不自动开工。
- **AND** 责任涵盖跨图和各层级直接分配给本人的任务，可查看他人任务不等于负责。

#### Scenario: 多项责任与结束条件
- **WHEN** Agent 再次推进现有责任
- **THEN** 可获全部本人 doing 与 waiting 的区分清单，正文及讨论按需读取，自主安排推进顺序。
- **AND** in_review、done、paused、closed 不要求该项自动续跑；返工注明原因并恢复 doing；子结果不自动完成父任务或启动后继依赖。

#### Scenario: 改派
- **WHEN** 任务改变负责人
- **THEN** 状态保持，旧负责人不再续跑，新负责人承担 doing；waiting 保留且由新负责人核对并修复不属于自己的后续安排，paused 不自动恢复。

### Requirement: waiting SHALL 关联有效原生安排并允许主动恢复

#### Scenario: 首次等待及校验失败
- **WHEN** Agent 已完成必要提问或交办并核实实际送达，为无可执行下一步的任务建立安排后提交 waiting
- **THEN** 系统核实真实安排的负责人、根会话、启用及未来执行有效性，成功后原子保存等待原因及关联。
- **AND** 无效或无法核实则明确拒绝并保留原状态；未获送达确认不能声称正在等用户答复；不设最少交互轮数或独立阻塞审核模型。

#### Scenario: 安静等待与安排失效
- **WHEN** 没有 doing 且所有 waiting 均有有效安排
- **THEN** Task 允许暂时空闲，其他 doing 存在时仍继续工作；关联后来失效须触发处理或明确显示运行限制，不静默失联或重复刷屏。

#### Scenario: 提前答复与定时复查
- **WHEN** 相关答复、协作结果或定时提醒实际到达
- **THEN** Agent 读取当前状态判断是否恢复 doing；定时到期不是授权或默认同意，仍需等待时先安排有效的下一次检查。
- **AND** 离开 waiting 清除关联，旧定时输入不能重新打开 paused、closed、done 或 in_review。

### Requirement: 用户停止 SHALL 阻止同范围自动续跑

#### Scenario: 停止范围与确认
- **WHEN** 有资格用户发出 /stop，或通过已核实的本 Agent mention 定向发出 /stop
- **THEN** 停止当前执行并暂缓对应范围内本人 doing 与 waiting；Global 主会话涵盖其跨聊天责任，single_thread 仅当前聊天，范围外不变。
- **AND** 重启或连接恢复不能越过尚未确认的停止控制，任务暂缓未确认时如实报告；已经完成的外部副作用不回滚。

#### Scenario: 运行中单项变更
- **WHEN** 用户在 Agent 同轮推进多项工作时暂缓、关闭或改派其中 A
- **THEN** 最近的下一原生可中断边界使该 Agent 获知最新责任并停止发起 A 的后续动作，仍归它负责的 B 不被无条件停止。
- **AND** 已经进入执行的动作按真实结果保留，不把通知当作副作用回滚。

#### Scenario: 明确恢复
- **WHEN** 用户对 paused 表达恢复意图或操作恢复推进
- **THEN** 无需固定命令即可恢复 doing；普通新消息、条件变化及定时器均不能自行解除用户暂缓。
- **AND** 认证真人 UI 恢复事实进入执行与审批上下文，只撤销该 Task 的旧暂缓，不成为额外工具许可；Agent 写入或自称恢复不能伪造该事实。

### Requirement: Task 恢复 SHALL 尊重真实运行边界

#### Scenario: 中断与换窗
- **WHEN** 重启或断线恢复可执行性
- **THEN** 按当前真相重新判定 doing、有效 waiting 和待修复 waiting，保留用户暂停及范围边界，不靠旧提示重复行动。
- **AND** 正常上下文换窗不改变状态、不额外创建 Task 续跑。

#### Scenario: 多轮与运行故障
- **WHEN** 多轮后仍有合法有效下一步，或遇到真实运行限制
- **THEN** 除连续短跑的宿主自动续推限制外，不增加 Task 专属轮数、token 或费用上限；真实运行错误如实显示，按既有恢复条件接续，不伪装成完成或用户暂缓。
- **AND** 读取失败不当空责任集，同一不可恢复原因不热循环调用模型。

#### Scenario: 连续短跑与触顶
- **WHEN** 同一 Agent 被宿主自动续推后，主会话不足 3 个原生执行步便再次结束
- **THEN** 连续短跑计数加一；在当前执行进程内达到 256 次后停止该 Agent 的宿主自动续推，任务状态保持，其他 Agent 不受影响。
- **AND** 同一 Agent 的绑定主会话共享计数，子 Agent 步骤与模型请求重试不计入；未触顶时连续执行达到 3 步清零，短的外部执行不清零。

#### Scenario: 触顶后的独立唤醒
- **WHEN** 触顶停推的 Agent 被用户消息、Inbox、Heartbeat、Schedule 等其他机制实际唤醒并进入执行
- **THEN** 清零并恢复被自动续推的资格，不要求该次外部执行满 3 步；后续是否续推仍由当前任务责任、审批与用户停止规则决定。
- **AND** 单纯责任或配置刷新、内部上下文同步、投递重校验、消息入队不解除停推；不制造 waiting、paused 或完成状态。

### Requirement: 自动续跑 SHALL 保留原有产品交付与审批链

#### Scenario: SingleThread 自动第二轮
- **WHEN** SingleThread 因 Task 责任继续执行并产生人工权限请求、成果或运行故障
- **THEN** 在绑定聊天中可见真实审批、成果或故障，使用原有投递身份恢复而不重复创建消息或审批卡。
- **AND** 没有新结果的例行自动检查可保持安静，但不会吞掉已经展示的审批或故障；Global 仍沿用显式发送和既有授权。

### Requirement: Task 自动推进 SHALL 以当前事实与可验证结果为准

#### Scenario: 阻塞前与等待复查
- **WHEN** Agent 推进 doing 任务或到期检查 waiting
- **THEN** 检查当前状态与工具结果，尝试授权内替代途径及独立部分，重新判断原阻塞是否必要；完成须有可验证结果。
- **AND** Schedule 唤醒不提供新授权，不重开 paused/closed/done/in_review。

### Requirement: Task waiting 的下次复查 SHALL 在未来一小时以内

#### Scenario: 新增与续期
- **WHEN** 提交新增或变更 waiting 关联
- **THEN** 校验原生 Schedule 的真实下一执行时间在未来一小时以内；超限拒绝且任务保持原状，无统一默认等待间隔。
- **AND** 通用 Schedule 可使用更长时间。

### Requirement: Task 等待与结果反馈 SHALL 交付到固定所属聊天

#### Scenario: 跨聊天与 Agent 派发
- **WHEN** Task 成功进入 waiting 或提交结果
- **THEN** 反馈回到 Task 固定所属聊天；等待说明包含实际进展、阻塞、尝试、所需协作与下次检查；Global 以 send_message 实际交付。
- **AND** 相同已确认反馈不重复发送；发送失败/未知不伪造送达、不改变真实 waiting，其他独立工作继续。

#### Scenario: SingleThread 已确认显式交付
- **WHEN** SingleThread 本轮 send_message 已确认送达本轮绑定聊天，模型以 NO_REPLY 收尾
- **THEN** 不公开哨兵；其他聊天、未确认发送或可见审批不被该交付标记吞掉。

#### Scenario: 直聊 Task 系统通知的静默收尾
- **WHEN** SingleThread 一轮仅处理宿主生成的 Task 系统通知，模型以 NO_REPLY 收尾且没有可见审批
- **THEN** 静默结束，不把哨兵显示成聊天正文；实际任务照常处理，有意义的正文仍可交付。
- **AND** 不将真人消息或其他来源仅凭相同文案识别为 Task 系统通知。

#### Scenario: 停止优先于旧排队输入
- **WHEN** 真人 /stop 已暂停 Task，但原生 inbox 仍有停止前收到的答复或定时输入
- **THEN** 解除停止隔离前将受信停止事实持久化，并保证首次后续模型步可见；模型与独立审批均区分原消息时序，旧输入不能被视为停止后的恢复授权。
- **AND** 停止后新的明确真人恢复仍可作用于对应 Task；通知持久化失败保持 stop pending，不伪报完成。

### Requirement: 自动失败屏障 SHALL 与 Task 业务状态分离

#### Scenario: 故障与修复
- **WHEN** 读取、持久化或主执行模型故障发生
- **THEN** 停止受影响的无效自动重复，不伪造业务状态；相关运行恢复后可重新评估。普通参数与版本错误允许模型修正。
- **AND** 审核子调用的技术故障交回执行 Agent，不据此建立任务或整批任务的隐藏续跑限制。

#### Scenario: 拒绝与新输入
- **WHEN** 审批拒绝后出现新输入、心跳或其他工具成功
- **THEN** 不存在由该次拒绝推导的任务续跑屏障；新输入与合法独立工作仍可处理，Agent 自主决定下一步或显式任务状态。
- **AND** 该动作及等价影响仍通过原审批链，通知和其他工具成功不授予被拒影响的权限。

### Requirement: 停止后的上下文同步 SHALL 不自行启动执行

#### Scenario: 停止通知延迟消费
- WHEN 真人 /stop 已中断并持久暂停作用范围内的 Task
- THEN 将可信停止通知持久注入下一模型步骤，但解除停止保护、通知本身和停止前积压输入不触发新的模型请求。
- AND 后续有效新输入或调度触发时一并读取通知；旧答复不能恢复 paused，明确的新恢复或新责任不会被待处理通知阻挡。
- AND 停止引发的同一 Agent 任务通知只同步上下文，不自行唤醒；正常重启后最新未消费的可信停止事实仍在下一次有效唤醒中可见，已消费通知不重复注入。

#### Scenario: 外部变更与冷恢复
- WHEN 人或 Agent 修改、改派、删除责任，或系统因群解散关闭任务
- THEN 受影响负责人在下一模型步骤对齐最新责任；空闲且无可执行任务时不为同步单独启动。
- AND 离线期间任务已撤回，恢复历史后的首个普通输入也附最新空责任事实，不沿用历史责任。

### Requirement: 有 doing 或 waiting 责任 SHALL 阻止关闭 Task

#### Scenario: 按负责人跨会话判断
- **GIVEN** 本 Agent 在任一会话仍负责 doing 或 waiting 节点
- **WHEN** 用户关闭 Task
- **THEN** 关闭被拒，任务、安排与配置保持不变，并提示先暂停或结束这些责任
- **AND** 其他 Agent 的任务、todo/paused/in_review/done/closed 不阻碍本 Agent 关闭

#### Scenario: 没有责任时关闭
- **GIVEN** 本 Agent 没有 doing/waiting 责任，也无其他 Feature 依赖 Task
- **WHEN** 用户关闭 Task
- **THEN** 允许关闭，既有记录与用户访问权限保留，Cron 不自动关闭；后续重新开启只沿既有任务恢复规则处理

### Requirement: Agent 停用造成的旧任务冻结必须由真人明确恢复

#### Scenario: 停用后重新启用
- **GIVEN** Agent 停用时仍有未完成任务及相关等待计划
- **WHEN** 主人重新启用 Agent
- **THEN** 正在推进或等待的任务保留暂停，其他旧未完成任务不自动开始；相关等待计划不自动续跑
- **AND** Agent、自身工具或迟到的旧输入不能解除该冻结

#### Scenario: 指定任务恢复
- **WHEN** 有权限的真人在重新启用后明确恢复指定旧任务
- **THEN** 只恢复指定范围，并重新确认需要的执行和审批；其他冻结任务保持原状
- **AND** 普通 `/stop` 保留既有作用范围，不被解释为 Agent 永久停用

### Requirement: 单次动作拒绝不建立隐藏任务续跑限制

#### Scenario: 可替代步骤与其他任务
- **WHEN** 工具权限拒绝、人工审批未获准或审核技术故障返回 Agent
- **THEN** 不从该结果推断当前任务或整批任务停止续跑；Agent 可继续获准替代与独立工作，原动作权限限制保持。

#### Scenario: 需要暂停或等待
- **WHEN** Agent 判断任务当前无法继续
- **THEN** 经正常 task_graph 状态和原因显式表达，调度遵循既有状态/安排与用户停止规则，不从单次拒绝猜测任务去留。
