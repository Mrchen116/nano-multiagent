# IM - Agent Work Specification

> 对齐: bugfix-669
> 上级: [IM Specification](spec.md)

## Purpose

全局 Agent 的主工作轨迹、关联子执行、实际过程明细与已报告统计的展示及持久回看契约。

## Requirements

### Requirement: 聊天沟通与全局工作轨迹分开呈现

#### Scenario: Agent 向聊天报告进展或结果
- **WHEN** 主 Agent 选择向某个群聊或单聊发送进展、问题或结果
- **THEN** 消息出现在它明确选择的聊天中
- **AND** 不附带与该聊天无关的整段全局执行轨迹

#### Scenario: 查看员工整体工作
- **WHEN** 对该 Agent 所在空间有访问权的已登录用户进入全局 Agent 的工作视图
- **THEN** 可以查看主 Agent 跨聊天的连续工作轨迹，辨认其读取、执行及委派过程

#### Scenario: 深入查看 subagent 工作
- **GIVEN** 主 Agent 已委派 subagent
- **WHEN** 用户查看这次委派对应的执行过程
- **THEN** 可以查看 subagent 的工作轨迹及当前结果，并辨认其与主 Agent 委派的关联，不要求是 Agent 管理者

#### Scenario: Work 内容完整可见，原聊天仍按会话范围访问
- **GIVEN** 主执行和子执行记录包含查看者未参与的聊天内容
- **WHEN** 有该 Agent 资源空间资格的用户查看 Work，或从中点击来源聊天及受保护附件
- **THEN** Work 的已有内容不按来源聊天过滤或遮盖；原聊天和受保护附件仍按当前会话读取资格判定；有效公司成员可读公开群，私密群和普通私聊仅成员可读，双方 Agent owner 按统一会话资格只读观察其协作私聊，Work 可见不额外授予来源访问权。

#### Scenario: 非管理者持续查看工作进度
- **GIVEN** 用户打开有权访问的公司全局 Agent Work
- **WHEN** Agent 产生新的过程记录，或用户刷新、恢复可见页
- **THEN** 可继续看到更新后的完整记录；节点离线及尚未知的执行状态可辨认。

### Requirement: 工作轨迹保留可检查的执行明细

#### Scenario: 查看主 Agent 与关联子 Agent 的具体执行
- **GIVEN** 全局 Agent 已读取消息、调用工具并委派子 Agent
- **WHEN** 用户展开工作轮次及对应子轨迹
- **THEN** 可以查看实际工具名称、调用参数、已有结果、状态、耗时，以及实际正文与可展示的思考
- **AND** 委派、补充和返回关联到真实子执行，工具调用完成不被误认为子任务完成或消息已发送

#### Scenario: 模型上下文裁剪后回看已完成工具
- **GIVEN** 工具已按原始执行开始和完成事实保存结果与耗时
- **WHEN** 模型上下文随后裁剪或替换该工具的历史输出
- **THEN** Work 不将上下文替换当作再次执行完成，不覆盖原始结果、状态或耗时
- **AND** 实时查看与历史重放、刷新后回看保持一致；模型侧上下文裁剪仍正常生效

#### Scenario: 查看轮次统计及未完成状态
- **WHEN** 用户查看主或子 Agent 的工作轮次
- **THEN** 可以展开该轮的 token、上下文占用及其统计口径，主、子统计分别展示
- **AND** 没有报告的数据明确显示未知或未报告；等待授权、拒绝、失败、中断与节点离线可辨认，不伪造输出或完成状态

#### Scenario: 辨认 PA 定期了解主人的近期沟通
- **WHEN** 用户在 Web 或原生 iOS 工作记录中查看 PA 合并读取主人其他聊天消息所触发的轮次
- **THEN** 标题显示“近况同步”，可辨认这类工作用于了解主人的近期沟通；即时 Inbox 消息仍使用自己的触发分类。

#### Scenario: 刷新后回看同一执行过程
- **GIVEN** 某轮执行已有保存的过程记录
- **WHEN** 用户刷新工作页或重新打开关联子轨迹
- **THEN** 可以回看相同的工具参数、结果、已报告统计和归属关系，不因实时连接结束退化为一句最终结果

#### Scenario: 权限决定的确认迟到
- **GIVEN** 用户已提交某项权限决定
- **WHEN** 节点尚未及时返回确认
- **THEN** 界面说明决定尚未确认、可能已经生效，不将等待确认报成请求已结束
- **AND** 后续收到真实权限完成记录时，工作视图反映实际结果

### Requirement: Work 提供工作记录与原生轨迹两种查看方式

#### Scenario: 查看当前主执行或关联执行的原生轨迹
- **GIVEN** 全局 Agent 的 Work 已有主执行或关联执行
- **WHEN** 有该 Agent 空间权限的用户在 Work 内切换到原生轨迹并选择一次执行
- **THEN** 在原页面看到所选执行的原生轨迹及明确归属，可以检查已有记录的输入、输出、时间和已报告统计。
- **AND** 切回工作记录保留原有查看位置；切换执行不会混入迟到的其他执行内容。

#### Scenario: 保留官方轨迹检查能力
- **WHEN** 用户使用原生轨迹
- **THEN** 可以使用时长切换、轮次／调用折叠和搜索，以及输入／模型／工具时间概览与记录选择联动。
- **AND** 系统提示词、用户、上下文注入、助手（含仅工具调用）、工具／嵌套调用和压缩按原生事实显示；相应检查器保留原文／来源、当时的提示词与工具目录、参数／结果／Schema、请求选项／用量／计时。
- **AND** 历史缺失不借当前配置补造；桌面和窄屏均能检查完整内容。

#### Scenario: 尚无可查看执行
- **WHEN** 用户进入尚未产生执行的 Agent 原生轨迹
- **THEN** 显示无可查看执行，不因此新建或启动 Agent。

### Requirement: 原生轨迹在查看时读取，连接状态如实呈现

#### Scenario: 按需读取历史并接收新增记录
- **WHEN** 用户进入原生轨迹并向前查看历史
- **THEN** 加载该执行所在节点的真实记录，支持继续读取更早内容和接收真实更新。
- **AND** 新增内容不强行改变检查旧记录的位置；离开视图后停止该视图的更新读取。

#### Scenario: 子执行刚启动但继承历史较大
- **GIVEN** fork 子执行继承了父级的上下文快照、模型和工具记录
- **WHEN** 用户打开该子执行的原生轨迹并继续向前读取
- **THEN** 可以完整检查继承历史和本次新增记录，不因单页内容总量较大而中断。
- **AND** 大型单条记录保留完整内容；离开或失去访问资格时停止读取并清理未完成内容。

#### Scenario: 节点不可读取或更新中断
- **WHEN** 打开时节点不可读取，或查看中连接中断
- **THEN** 显示相应不可用或中断状态，已加载内容不被误认为正在更新，已保存的工作记录仍可回看。
- **AND** 恢复读取不会重新执行任务，也不伪造完成、耗时或未报告的统计。

### Requirement: 原生轨迹是既有 Work 权限下的只读检查

#### Scenario: 非管理者查看共享工作
- **GIVEN** 查看者是该公司 Agent 的有效公司成员但不是其管理者
- **WHEN** 查看该全局 Agent 的原生轨迹
- **THEN** 可以查看其真实主／关联执行；不会取得发送指令、审批、取消或配置权限。
- **AND** 原聊天和受保护附件仍按统一会话读取资格处理，不因原生记录中存在附件副本而绕过。

#### Scenario: 当前查看者失去访问资格
- **WHEN** 查看者退出登录、切换账号或被停用
- **THEN** 已打开的轨迹停止更新并清除该账号的显示内容，后续轨迹和附件读取被拒绝。

#### Scenario: 检查执行读取的工作区图片
- **GIVEN** 原生执行使用读图工具成功读取了所属工作区内的图片，且该图片确实被所选执行引用
- **WHEN** 有效 Work 查看者在原生记录中预览该图片
- **THEN** 可以查看图片；这类工作区来源不要求不存在的原聊天成员关系。
- **AND** 仅存在路径文本或来源无法证明时，不返回图片字节。

### Requirement: 从真实发起位置进入子 Agent 的本次执行

#### Scenario: 主动委派和后台维护
- **GIVEN** 主执行真实发起普通子 Agent、fork、记忆整理、技能复盘或记忆与技能联合复盘
- **WHEN** 用户阅读该发起位置
- **THEN** 能辨认用途、普通／fork、主动／后台及真实状态，并直接进入对应本次执行，不依赖顶部名称列表。
- **AND** 后台用途来自真实发起事实，不从内部标签或 UUID 猜测。

#### Scenario: 并行、重复唤起与嵌套
- **WHEN** 用户从并行发起点或同一子会话的不同唤起记录进入，或继续进入下一层委派
- **THEN** 按真实执行身份区分各次范围及父级来源；驻留期间继续收信不被虚构为新的执行。
- **AND** 刷新后仍可从持久发起记录进入同一次执行。

#### Scenario: 联合复盘的用途和范围
- **WHEN** 用户从联合复盘的发起位置进入子执行，或刷新后重新进入
- **THEN** 入口与导航显示“记忆与技能复盘”，指向同一次真实后台 fork 及其执行范围，不拆成两个虚构执行。
- **AND** 用途名称不表示两类知识均已更新；执行状态来自真实运行记录，知识更新只按实际写入报告。

### Requirement: 本次范围忠于真实执行且保留完整检查

#### Scenario: 默认聚焦一次执行
- **WHEN** 用户进入已有真实边界的子执行
- **THEN** 同一个原生派生轨迹视图的时间概览自动选中本次起止，关联本次输入、模型请求、工具、输出与结束状态，可直接定位起止。
- **AND** 进入子执行时加载完整会话轨迹，保留 fork 继承历史及其他执行；仅以原生时间轴选区和区间外淡化标识本次范围，不过滤记录。

#### Scenario: 运行与异常状态
- **WHEN** 子执行正在运行、完成、失败、取消，或边界缺失、连接中断
- **THEN** 依据真实记录呈现状态；启动工具返回不代表执行结束，未报告的终点或结果不推测。
- **AND** 运行中范围延伸到真实最新记录，不强制移动旧记录的阅读位置；中断不被显示为实时更新，恢复读取不重跑任务。

#### Scenario: 检查全部原生明细
- **WHEN** 用户在原生派生视图中在完整轨迹中检查本次选区或其他历史
- **THEN** 保留既有官方轨迹检查能力，完整明细可达，来源与当前查看范围明确。
- **AND** 使用同一套原生组件，用户可直接调整或清除选区；顶部当前执行同步所查看的会话。

### Requirement: 父子导航保持阅读上下文与只读边界

#### Scenario: 返回发起位置
- **WHEN** 用户从子执行返回父级或从多层嵌套逐级返回
- **THEN** 恢复对应父级发起位置，以及原滚动、缩放和选择，可以继续原上下文。

#### Scenario: 跨屏与身份变化
- **WHEN** 桌面或窄屏的有效 Work 查看者进入、检查并返回子执行
- **THEN** 均能完成完整只读旅程，不要求为 Agent 管理者，不取得执行控制或额外附件权限。
- **AND** 离开 Work、退出登录、切换账号或访问资格失效时，相应读取停止并清除旧身份内容。

### Requirement: 工作记录补传与聊天沟通独立且恢复后完整可查

#### Scenario: 大结果在中断后恢复回看
- **WHEN** 受支持大小的工具参数或结果经历分段同步、中断、重复传输和恢复，用户重新打开 Work
- **THEN** 可以回看完整正文、真实顺序及父子归属，不新增重复条目或把未完成的记录报为完整。

#### Scenario: 工作记录暂未同步
- **WHEN** 工作记录仍在补传而实时聊天可用
- **THEN** 聊天消息与必要操作照常进行，普通聊天不增加同步实现、确认阶段或运维诊断信息；用户仍可主动打开现有 Work。

#### Scenario: 单条记录超过同步协议支持范围
- **WHEN** 同步调用方提交超过 16 MiB 的单条完整事件
- **THEN** 取得明确的 `event_too_large`，该条及后续记录保留本机待处理；不把正文截断后声称中心完整
- **AND** 普通聊天继续，既有本机原生轨迹读取入口保持可用，不增加聊天中的同步诊断标签。

### Requirement: 已保存工作记录直接读取，节点恢复只补缺口

#### Scenario: 完成历史增长后普通重启
- **GIVEN** 主子执行的工作记录已保存且中心已确认
- **WHEN** 节点普通重启，用户查看 Work 和更早分页
- **THEN** 用户直接看到中心保存的工具过程、主子关系、轮次与已报告统计；不为展示恢复全量重建不变的完成历史。

#### Scenario: 崩溃后补齐未处理事实
- **WHEN** 原生事实已持久化但产品记录或中心确认尚未完成时节点崩溃并恢复
- **THEN** 处理和传输各自从持久位置补齐，主子执行均无遗漏、重复或虚构完成；在途执行、审批和交付按真实状态恢复。

#### Scenario: 查看尚未补齐的记录
- **WHEN** 用户查看尚在补齐的 Work，或节点未确认最新记录位置
- **THEN** 已保存内容与分页立即可用，并分别提示正在补齐或最新进度尚未确认；补齐不阻塞新输入及必要控制。
- **AND** 页面持续接收工具开始/结束及真实新记录；新用量未报告时仍展示最近已报告统计。

### Requirement: 系统维护保留独立可回溯轨迹

系统维护不进入模型管理目录时，SHALL 继续在既有轨迹发起位置保留用途、父会话、本次起止范围、状态和真实会话入口；轨迹访问遵守既有 Work 权限。

#### Scenario: 维护效果不佳后回溯

- **GIVEN** 维护执行已完成、取消或失败，运行资源已经释放
- **WHEN** 用户在重启后从维护记录打开该次轨迹
- **THEN** 可按需查看继承上下文、维护输入、模型与工具记录、输出和结束事实。
- **AND** 查看不恢复执行，不需要先遍历全部维护历史或使用 `list_agents` 找到它。
