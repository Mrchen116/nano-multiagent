# IM - Auth and Tenancy Specification

> 对齐: bugfix-818
> 上级: [IM Specification](spec.md)

## Purpose

账号鉴权、私人空间、公司准入与停用、认证限流、聊天成员可见性、资源管理归属和系统策略的 IM 契约。

## Requirements

### Requirement: 程序客户端轮换 refresh，浏览器通过稳定 Cookie 续期，两类会话均可撤销

程序客户端经 `/im/v1/auth/*` 注册/登录获得一对令牌(短期 access + 长期 refresh);浏览器通过明确的浏览器会话模式取得内存 access 与稳定的 HttpOnly 会话 Cookie；程序 refresh 一次性轮换，浏览器续期只延长会话期限；退出后对应会话立即失效。错误凭证大声失败(401/拒绝),不静默成功,也不泄漏用户是否存在。

#### Scenario: 注册返回令牌对且密码经哈希,弱口令/重名被拒
- **WHEN** 程序客户端 `POST /im/v1/auth/register {username,password,display_name,locale?}`
- **THEN** 201 返回 `{access_token, refresh_token, user}`,`user` 含 `id/username/display_name/owner_id`且不泄漏密码哈希;注册密码至少 8 个字符且最多 72 UTF-8 字节，超出边界或用户名重复时注册失败(不创建用户)；浏览器在本地阻止可判定的无效输入，服务端相同拒绝映射为密码字段的本地化修正提示，不误报服务故障

#### Scenario: 登录凭证错误返回 401 且不区分"用户不存在"与"密码错"
- **WHEN** 终端用户以错误密码或未知用户名 `POST /im/v1/auth/login`
- **THEN** 401(同一种失败语义,避免存在性预言机);凭证正确时按客户端会话模式返回登录结果

#### Scenario: 程序 refresh 轮换令牌,旧 refresh 失效;登出吊销 refresh
- **WHEN** 程序客户端 `POST /im/v1/auth/refresh` 用合法 JSON refresh
- **THEN** 返回新 access+refresh,且原 refresh 再次使用被拒;`POST /im/v1/auth/logout` 后该 refresh 也被拒

#### Scenario: 保留运行身份不可用于真人注册
- **WHEN** 用户注册时，用户名去除首尾空白后等于 `system`，或以 `agent:`、`shadow:` 开头
- **THEN** 注册被拒且不创建账号，不能通过注册取得系统、Agent 或外部影子发送者身份；普通用户名继续按原注册规则处理。

#### Scenario: 注册不等于取得公司资格
- **WHEN** 新真人账号注册成功
- **THEN** 返回令牌、可用的个人空间和公司 none 状态；个人数据与绑定立即可用，公司资源在主动申请并获批前不可见；系统、Agent 和 shadow 身份不经真人公开注册取得公司资格。

#### Scenario: refresh 并发、登出与重启
- **WHEN** 程序客户端同一 refresh 并发消费、登出后使用或服务正常重启后重试已消费令牌
- **THEN** 至多一次轮换成功，已消费或吊销状态持久保持；登出后的对应会话不能继续读公司数据。

#### Scenario: 浏览器令牌保存与页面恢复
- **WHEN** 浏览器以 `X-IM-Session: browser` 和许可 Origin 调用注册、登录或刷新
- **THEN** 响应仅含 access_token 与 user，refresh 通过 host-only、HttpOnly、SameSite=Strict Cookie 传送；HTTPS 部署带 Secure，页面可读持久存储不保存任何会话令牌。
- **AND** 刷新页面及同源多标签续期通过 Cookie 恢复有效会话，保留稳定 Cookie、退出、成员停用和临时故障重试语义。
- **AND** 同源其他标签页冻结休眠长期阻塞跨标签会话协调，或运行在缺少跨标签锁/广播/本地存储能力的非安全上下文（如受控内网明文 HTTP）时，当前标签页在有界时间内降级完成会话恢复、登录、续期与退出，且延迟响应不覆盖或撤销期间更新的会话身份。

#### Scenario: 登录页恢复已有会话
- **WHEN** 用户打开或刷新 /login，未主动退出且浏览器保留有效会话
- **THEN** 自动恢复并进入 /chat；账号需准入处理时进入 /membership。没有有效会话才显示登录表单，临时服务故障显示重试入口，主动退出显示登录表单。
- **AND** 会话恢复或受保护路由身份核验请求无响应时在有界时间内中止并展示可重试提示，不永久停留在恢复等待或空白页。

#### Scenario: 三十天滚动续期与成功登录记录
- **WHEN** 用户登录或成功续期
- **THEN** refresh 有效期与浏览器 Cookie 有效期从本次成功起为 30 天，短期 access 保持原有效期，已有有效会话在下次续期时取得新期限。
- **AND** IM 持久保存每账号最近 10 次密码登录成功的时间及客户端 User-Agent（最长 512 字符）。注册、失败登录和自动续期不产生成功登录记录；设备信息缺失时保存空字符串，不阻断登录。

#### Scenario: 浏览器 Cookie 的跨站与原生接口边界
- **WHEN** 非许可或缺少 Origin 的浏览器模式请求试图登录、注册、刷新或登出
- **THEN** 拒绝且不更改 Cookie 会话；无浏览器标记的程序接口只接受显式提供的 refresh，不读取 Cookie、不设置 Cookie，继续使用 JSON token pair。

#### Scenario: 浏览器续期响应丢失后恢复
- **WHEN** 有效稳定 Cookie 发起续期，响应丢失或页面关闭，随后刷新页面或其他标签页用原 Cookie 重试
- **THEN** 继续恢复会话，无需输入密码；每次成功续期保持凭据不变，并将服务端及浏览器期限延长为 30 天。

#### Scenario: 稳定会话重启与失效
- **WHEN** 沿用同一数据库和配置重启 IM，浏览器再次打开 /login
- **THEN** 有效 Cookie 自动恢复 /chat；主动退出、撤销、认证 epoch 变化、过期或篡改的 Cookie 被拒绝。

#### Scenario: 已有浏览器 JWT Cookie 升级
- **WHEN** 当前仍有效的旧 JWT Cookie 首次续期，或升级响应丢失后重试
- **THEN** 返回相同稳定 Cookie；已被消费、过期或撤销的旧凭据保持拒绝，此类浏览器需要重新登录一次。
- **AND** 稳定 Cookie 及已升级会话的旧 JWT 均不能通过程序 JSON refresh 接口消费。

### Requirement: Web 官网首页提供可直接进入注册的产品介绍

#### Scenario: 访客与已有会话的入口
- **WHEN** 未登录用户打开 `/`
- **THEN** 展示 Crewden 官网首页，说明人与个人助手、专业数字员工的协作方式，并提供真实 `/register` 和 `/login` 入口。
- **AND** `/` 恢复有效会话后，个人空间可用或有效公司成员进入 `/chat`，其余账号进入 `/membership`；`/about` 始终允许查看官网介绍。

#### Scenario: 协作示例与真实工作明确区分
- **WHEN** 访客查看团队协作示例或打开示例中的发布计划
- **THEN** 页面明确标识演示。访客能跟随同一项团队工作，看懂个人 PA 怎样为主人跨聊天协调、专职 Agent 怎样持续负责其中一项工作，以及哪项成果交还给谁确认。操作仅影响本地示例，不发送消息、创建任务或执行发布。
- **AND** 访客可暂停、重播或逐步查看。演示离开视区或页面转入后台时暂停；启用减少动态效果时由访客手动推进。键盘可关闭详情并返回触发位置。

#### Scenario: 注册前理解条件并连续进入产品
- **WHEN** 访客从首页了解产品并选择创建账号
- **THEN** 首页说明运行助手需要连接电脑和模型服务，注册入口进入真实注册页。注册成功沿用首次设置和绑定深链；认证页可返回产品介绍。
- **AND** 首页和认证入口沿用 Crewden 身份，用户可用键盘切换中英文。窄屏仍能访问内容与入口，移动导航支持章节跳转及键盘关闭。

#### Scenario: 官网多端下载自动识别当前设备并如实展示各端可用状态
- **WHEN** 访客或已登录用户打开 `/`、`/about` 或从工作区菜单进入客户端下载区域
- **THEN** 首页按当前访问系统自动优先推荐匹配的客户端下载操作并保留网页直接使用/创建账号入口，同时在客户端下载专区并列展示 macOS Desktop、Windows Desktop、iOS 客户端与轻量后台节点接入说明
- **AND** 某桌面平台尚未部署有效安装包清单时如实展示暂未发布状态而不暴露失效链接；未配置有效的 `https://` iOS 下载地址（`IM_IOS_DOWNLOAD_URL`）时 iOS 入口如实展示「即将上线」，配置后自动点亮跳转

### Requirement: Web 认证入口在提交前说清规则并给出可行动反馈

注册与登录页在未登录状态下提供一致、可本地化的表单反馈；能在当前字段修正的问题不伪装成笼统服务失败，服务异常也不伪装成输入错误。

#### Scenario: 认证入口延续当前 Web IM 设计语言
- **WHEN** 用户在桌面或手机打开注册或登录页
- **THEN** 从官网到注册、首次设置和聊天，用户始终能认出 Crewden，能辨认当前要完成的动作并进入下一步。注册时只需理解账号要求，连接电脑、接入模型和建立助手职责的说明分别在相应任务中提供。
- **AND** 手机窄屏优先呈现认证表单，较矮视口可滚动到主操作和页脚。工作区的账号设置可找到语言切换；入场和悬停反馈尊重系统减少动态效果偏好。
- **AND** 未选中会话时，用户可以打开个人助手或发起聊天。已有 PA 聊天记录时显示真实近况；小任务入口只填入草稿，替换已有草稿或附件须经用户确认，取消后原内容仍在。首次交办与长期职责引导见[首次建立合作约定](personal-agent.md#首次建立合作约定)。

#### Scenario: 注册规则在输入前可见
- **WHEN** 未登录用户打开注册页
- **THEN** 页面明确区分必填项和可选显示名，并在密码附近告知至少 8 位
- **AND** 用户可主动显示或隐藏密码，而不改变已输入内容

#### Scenario: 可本地判定的输入问题原位反馈
- **WHEN** 用户提交必填项为空的认证表单，或提交包含短密码的注册表单
- **THEN** 页面在对应字段原位告知修正方式，将焦点放到第一个问题，且不发出必然失败的认证请求
- **AND** 用户编辑有误字段后，与旧值相关的反馈消失

#### Scenario: Unicode 输入按服务端字符限制处理
- **WHEN** 用户在认证字段输入包含 Unicode 字符的内容
- **THEN** 页面按与服务端一致的字符语义判断长度，限制内的输入不会被浏览器提前截断
- **AND** 超过服务端字符上限时才在对应字段原位反馈，并阻止必然失败的认证请求

#### Scenario: 认证拒绝与服务异常可区分
- **WHEN** 注册用户名重复、登录凭据错误，或认证服务无法完成请求
- **THEN** 重名在用户名原位反馈，错误凭据不区分用户名与密码，服务异常则显示不同的可重试提示
- **AND** 失败不清空其他已输入内容

#### Scenario: 服务端拒绝可修正的输入
- **WHEN** 认证服务拒绝一项可由用户修正的输入
- **THEN** 页面使用当前语言在受影响字段告知修正方式
- **AND** 不向用户直接暴露服务端内部错误原文

#### Scenario: 未登录用户切换语言
- **WHEN** 用户在注册或登录页切换中文与英文
- **THEN** 规则、反馈和提交状态立即改用新语言，已输入内容保留
- **AND** 新语言在后续打开认证页时继续生效

#### Scenario: 辅助技术定位认证输入错误
- **WHEN** 键盘或辅助技术用户提交无效认证表单
- **THEN** 字段状态、可见文案和焦点变化使用户能定位第一个问题
- **AND** 密码显隐与提交状态有明确的可读名称

#### Scenario: 认证请求处理中
- **WHEN** 一份有效认证表单正在提交
- **THEN** 页面清晰告知处理状态，并阻止重复提交
- **AND** 用户仍可切换语言，处理状态立即使用新语言

#### Scenario: 注册成功进入个人首次设置
- **WHEN** 服务成功创建账号
- **THEN** 页面保存新会话并进入首次设置，无需再次输入凭据；因设备绑定而注册时保留绑定深链，确认后可继续设置；注册与登录入口互相切换时也保留该安全站内返回位置

#### Scenario: 登录成功返回原始深链
- **GIVEN** 用户因访问带查询条件或页内锚点的受保护位置而进入登录页
- **WHEN** 用户成功登录
- **THEN** 个人空间可用或有效公司成员返回完整的安全站内原始位置，路径、查询条件与页内锚点都保留；无个人空间的旧待批准或停用账号先显示本人状态，不提前显示公司缓存

#### Scenario: 暂时冷却可以恢复
- **WHEN** 认证请求被限流
- **THEN** 当前语言告知等待时间和重试方法，保留已填写的非敏感表单状态，不伪装成密码错误或永久禁用。

### Requirement: 系统级策略(policies)可读可改,字段集稳定

有效公司成员可读取 `/im/v1/policies`；仅有效公司管理员可 PATCH。字段集合与既有语义保持。

#### Scenario: 字段及管理权限
- **WHEN** active 成员 GET policies
- **THEN** 响应键为 `{default_model,max_turn_per_run,max_attachment_size_mb,retention_days,audit_level,rate_limit_per_min}`。
- **WHEN** 普通成员尝试 PATCH
- **THEN** 拒绝且原策略不变；管理员使用同结构 PATCH 可保存并回显。

### Requirement: Agent 与个人助手按统一权限矩阵控制发现、会话、轨迹与披露审核

系统以单一权威权限矩阵定义个人助手（PA，固定两档：`owner_only` / `team`）与普通及全局 Agent（三档：`owner_only` / `project` / `team`）的能力边界。其中「同项目成员」动态定义为当前与该 `project` 档助手共同处于至少一个未解散站内私密群（`visibility = "private"`）的有效团队成员，不单独维护静态项目成员名单：

| 权限维度 | PA · 私有 (`owner_only`) | PA · 团队公开 (`team`) | 普通/全局 Agent · 私有 (`owner_only`) | 普通/全局 Agent · 项目级 (`project`) | 普通/全局 Agent · 团队公开 (`team`) |
|---|---|---|---|---|---|
| **通讯录、搜索与名片可见性** | 仅主人本人可见 | 主人 + 有效团队成员可见 | 仅主人本人可见 | 主人 + 当前同项目成员可见；圈外团队成员不可见 | 主人 + 有效团队成员可见 |
| **1:1 私聊收发** | 仅主人私聊（含已绑定外部单聊）及与同主人名下 Agent 的 1:1 会话；拒绝外部真人私聊 | 主人、同主人 Agent 及未屏蔽的有效团队成员均可双向私聊 | 仅主人（含已绑定外部单聊）及同主人名下 Agent；外部历史私聊只读（`agent_private`） | 主人、同主人 Agent 及当前同项目成员可双向私聊；无共同私密群的外部成员不可新建且历史私聊只读（`agent_project_restricted`） | 主人、同主人 Agent 及有效团队成员均可双向私聊 |
| **私密群（`private`）加入与收发** | 仅可加入纯同主人内部私密群（仅主人与同主人 Agent）；拒绝含外部成员的群 | 仅主人可将其拉入私密群，可在群内正常收发 | 仅可加入纯同主人内部私密群；拒绝含外部成员的群 | 仅主人可将其拉入私密群（全局模式跨非重叠成员私密群入群前提示上下文互通）；同群成员可正常收发，非主人不可将其拉入其他群 | 仅主人可将其拉入私密群，群内成员可正常收发 |
| **公开群（`public`）加入与收发** | 禁止加入、读取（非旁观路径）或将所在群改为公开 | 可加入公开群并在群内收发 | 禁止加入、非成员读取或将所在群改为公开 | 禁止加入、非成员读取或将所在群改为公开 | 可加入公开群并在群内收发 |
| **主人会话静默旁观（`observer`）** | 保持对主人已参与且未排除会话的静默旁观，仅对内汇报/拟稿 | 保持对主人已参与且未排除会话的静默旁观，可按委托代发或外发 | 不适用（无双身份旁观） | 不适用（无双身份旁观） | 不适用（无双身份旁观） |
| **Work 与原生轨迹可见性** | 严格仅主人本人可见（他人 404） | 严格仅主人本人可见（他人 404） | 仅主人本人可见（他人 404） | 主人 + 当前同项目成员可见（圈外成员 404，失权即时断开实时轨迹连接） | 主人 + 有效团队成员可见 |
| **作为 PA 出站目标时的披露审核** | 主人私聊免审 | 不适用（同主人仅一个 PA） | 免除披露审核（属纯主人私有域） | **强制经过独立披露审核**（审核证据显式标注项目成员下游可见范围） | **强制经过独立披露审核**（审核证据显式标注团队成员下游可见范围） |
| **退群或档位切换联动** | 从 `team` 收紧时自动退出外人群、冻结外部私聊；放宽至 `team` 时需主人确认 | 恢复外部同事私聊可写 | 从更宽档位收紧时自动退出外人群、冻结外部私聊；放宽至 `project`/`team` 需主人确认历史私有材料暴露风险 | 从 `team` 收紧时自动退出公开群并冻结非同项目私聊；成员退出全部共同私密群或群解散时自动冻结其 1:1 私聊并撤销待办上下文，重入共同私密群后自动恢复可写 | 从收紧档位放宽至 `team` 后历史外部 1:1 私聊自动恢复可写 |

#### Scenario: 按角色与档位一致执行发现、沟通与 Work 权限
- **WHEN** 主人、同项目私密群成员与圈外有效团队成员分别访问某 PA 或普通/全局 Agent 的联系人目录、1:1 私聊、群聊管理及 Work/原生轨迹接口
- **THEN** 各项可见性、读写放行、拒绝状态码及实时事件推送严格符合上述统一权限矩阵，不存在跨端或跨接口口径冲突

#### Scenario: PA 跨档位内部转发遵循纯私有免审边界
- **WHEN** 主人的 PA（无论处于 `owner_only` 还是 `team`）分别向同主人 `owner_only` 助手与同主人 `project` / `team` 助手发送消息或附件
- **THEN** 发往同主人 `owner_only` 助手免除出站披露审核直接送达；发往同主人 `project` 或 `team` 助手均允许发起（即使 PA 自身为 `owner_only`），但必须经过包含目标助手下游受众范围的独立出站披露审核

### Requirement: 数据面按登录身份、聊天成员与资源管理归属确定访问

普通真人请求中，除 `/im/v1/auth/*` 外,所有数据面路由(`me` / conversations / messages / agents / nodes 等)要求合法 Bearer access token 和有效账号（个人空间可用或公司 active），再核对资源空间;缺失或非法 token 返回 401。默认聊天列表按成员关系及双方 Agent owner 的只读观察资格；详情、消息、历史与受保护附件同时核对资源空间及会话可见范围：有公司资格的用户可读公司空间公开群，私密群和普通私聊仅成员可读；恰含两个可协作 Agent 的私聊允许双方有效真人 owner 只读观察；一个 PA 与一个真人的私聊允许该 PA 主人按 [personal-agent](personal-agent.md) 只读观察，无资格返回 404；写入还须未解散会话的成员资格，且一对一对象为他人「私有」Agent 或当前无共同未解散私密群的他人「项目级」Agent 时禁止写入；Agent／Gateway 配置保持 owner 管理归属。联系人目录返回本人及本人名下全部可用助手，获准加入公司的有效成员还可按 [统一权限矩阵](#requirement-agent-与个人助手按统一权限矩阵控制发现会话轨迹与披露审核) 发现其他有效公司成员、其设为「团队公开」的普通 Agent 与已激活 PA、以及与查看者共同处于至少一个未解散私密群的「项目级」普通 Agent（隐藏他人「私有」助手及圈外「项目级」助手）；全局 Agent Work 的完整读取以 [agent-work](agent-work.md) 为准，不因此放开原聊天或管理操作。Gateway 机器数据入口另接受绑定当前已注册连接的运行凭据，范围见 [gateway-relay](gateway-relay.md)，不能用于真人账号／配置管理。请求主体身份取自服务端验证的 token,不接受 `?user_id=` 之类的查询参数作为信任锚。

#### Scenario: 无 token 的数据面请求返回 401
- **WHEN** 浏览器前端未带 Bearer 调 `GET /im/v1/me` / `/im/v1/conversations` / `/im/v1/agents` / `/im/v1/nodes`
- **THEN** 全部 401(无 `?user_id=` 捷径)

#### Scenario: 身份取自 token 而非查询参数
- **GIVEN** 已授权用户 alice
- **WHEN** alice `GET /im/v1/me`(或 `PATCH /im/v1/me`,即使带 `?user_id=` 也忽略)
- **THEN** 返回/更新的恒是 token 主体 alice 自己

#### Scenario: 聊天列表按成员关系过滤，读取区分可见范围
- **GIVEN** alice 与 bob 各自注册并获准加入公司、各建一个私聊或私密群
- **WHEN** alice `GET /im/v1/conversations`
- **THEN** 可见 alice 参与或有 Agent owner 观察资格的会话；若 bob 既不在 alice 的会话中也无观察资格，bob `GET /im/v1/conversations/{alice 的会话 id}` 返回 404, 向其发消息也 404

#### Scenario: 跨账号成员可以读取同一个群
- **GIVEN** alice 与 bob 是同一群的成员
- **WHEN** 两人分别用自己的 token 打开群
- **THEN** 都能读取同一群并发言，未入群用户只有在公开群中可读，仍不能发言。

#### Scenario: 公司资格不扩大对象权限
- **WHEN** 已登录但 pending 或 suspended 的真人访问公司数据，或失去资格的 owner 名下机器继续请求
- **THEN** 被拒绝；批准成为 active 后仍按会话可见范围、成员写入资格、Agent 团队公开/项目级/私有档位及配置 owner 判断，管理员也不自动取得他人私聊与设备管理权。

### Requirement: 公司成员资格由管理员批准和停用

#### Scenario: 准入与管理边界
- **WHEN** 真人完成普通公开注册
- **THEN** 立即使用个人空间并绑定自己的设备；从账号/团队入口主动申请后才等待公司管理员批准，批准前不能读取公司联系人、Work、任务；不要求邀请或 Cloudflare 登录。
- **WHEN** active 管理员批准 pending 成员
- **THEN** 成员取得公司资格；普通成员不能批准或停用他人。

#### Scenario: 停用立即覆盖真人与机器
- **WHEN** 管理员停用成员
- **THEN** 撤销其后续公司请求及现有浏览器会话、公司实时访问；旧令牌不能恢复访问。个人空间用户重新登录后可继续个人资源；机器资格按所在资源空间判定，原公司 Agent 不因 owner 还有私人空间而继续公司接入。
- **AND** 保留历史记录和配置，不关机、不自动接管资源；公司空间的 Agent 暂不可用，个人空间的 Agent 保持私人边界，已授权的其他公司成员可继续查看历史共享记录。

### Requirement: 公网认证限制来源与目标账号滥用

#### Scenario: 分散尝试与共享网络
- **WHEN** 同一来源大量注册/认证，或多个来源持续猜测同一账号
- **THEN** 来源、来源与账号组合以及短时目标账号预算均可触发有界冷却，不因伪造代理头绕过；拒绝不会无限续期，反馈包含重试时间。

#### Scenario: 不跨来源继承长时间失败封禁
- **WHEN** 一个来源对账号连续输错密码后，另一来源尝试正确凭据
- **THEN** 后者不继承该来源约 15 分钟的失败冷却，只受短时目标节流与服务计算容量约束；已登录合法会话不因匿名失败被注销。

### Requirement: 慢认证和已派发控制等待不串行阻塞无关用户

#### Scenario: 密码计算与无关读取
- **WHEN** 并发密码校验尚未完成，另一已登录用户读取本人或有权访问的公司数据
- **THEN** 读取不必等待校验完成，超出计算容量的认证请求被有界拒绝。

#### Scenario: 等待结果期间撤销
- **WHEN** Gateway 控制命令已发出但结果未返回，管理员停用发起者
- **THEN** 停用和无关读取不必等待控制结果；停用后旧请求不能继续提交新的受保护 IM 副作用或返回受保护结果，已发出的远端动作可能完成；同资源并发不形成互锁。服务内部可在 gate 内清除本请求预建、仍无消息且尚未完成历史复制的空 fork 半成品；此例外不允许删除已有分支或用户内容，不允许复制历史或派发新命令。

### Requirement: 生产浏览器入口提供集中安全响应策略

#### Scenario: HTTPS 页面与资源正常工作
- **WHEN** 用户访问生产 HTTPS Web IM
- **THEN** 前端 HTML 限制脚本、连接与嵌入来源，不允许第三方框架嵌入；响应提供 nosniff、防嵌入和仅当前主机的 HSTS，同时保留正常字体、图片、附件和实时连接。
- **AND** loopback HTTP 开发仍可使用，不通过放宽生产脚本执行或信任任意 Origin 支持开发。

### Requirement: 资源空间固定且叠加原有对象权限

会话、Agent 和任务图创建时取得私人或公司范围，附件继承会话。团队批准不迁移私人聊天历史、受保护附件、私有任务图或 PA Work；有效团队成员名下设为「团队公开」的普通 Agent 与 PA 可在公司空间被其他有效成员发现并参与公司会话，设为「项目级」的普通 Agent 在主人拉入私密群后可由共同处于该未解散私密群的有效团队成员发现、私聊并按 [agent-work](agent-work.md) 查看 Work，设为「私有」的 Agent 与 PA 则对其他成员隐藏且仅允许在同一 owner 内部会话通信；成员被停用公司资格后，其个人空间的 Agent 立即收回团队与项目可见及联系权，但本人在个人空间内仍可继续使用。显式整机交接仍是改变绑定归属的唯一路径，见 [设备绑定](agents-nodes.md)。

#### Scenario: 两个私人账号
- **WHEN** 一个用户查找、读取、修改或订阅另一私人空间的资源
- **THEN** 拒绝或不返回，不泄露内容；自己的资源正常可用。已有 owner、聊天成员和媒体权限继续叠加。

#### Scenario: 旧库升级与团队批准
- **WHEN** 既有库升级，或一个个人用户获批进入团队
- **THEN** 旧资源保留原空间范围、身份与成员状态；新用户的私人聊天历史与私有任务图仍私有，其设为「团队公开」的助手对团队成员开放协作，设为「项目级」的普通助手仅对共同所在未解散私密群的成员开放协作与 Work，设为「私有」的助手保持仅本人及本人名下助手可访问。旧 pending/suspended 用户不因升级自动恢复。

### Requirement: 已有原生客户端兼容个人账号准入

原生 iOS 使用个人空间或公司 active 判断账号可用，个人账号可以继续聊天和管理自己的账号/设备；公司菜单仍只向 active 公司成员展示。Web 首次设置向导不因此复制到原生客户端。

#### Scenario: 个人账号与旧账号登录原生端
- **WHEN** 个人空间启用的用户在公司 none、pending 或 suspended 状态登录 iOS
- **THEN** 可以进入个人聊天与设备功能；公司未 active 时不展示公司管理入口。
- **AND** 不带个人空间字段的旧账号仍按原公司成员状态判断准入。

### Requirement: 真人账号可管理受保护的自定义静态图片头像

IM SHALL 支持真人账号上传、替换与移除单张自定义静态图片头像，对上传字节执行格式、帧数、尺寸上限与重新编码校验并剥离元数据，不提供免登录公开头像外链，且不在注册或首次设备/助手引导流程中强制设置头像。账号未设置或已移除自定义头像时，客户端按显示名回退首字母柔和色圆章。

#### Scenario: 上传与更换合法静态图片头像并同步版本标识
- **WHEN** 已认证真人客户端以合法静态 PNG、JPEG 或 WebP 图片字节调用 `PUT /im/v1/me/avatar`（体积不超过上限且像素尺寸合法）
- **THEN** IM 将头像标准化收敛为正方形静态图片保存、替换并清理该账号此前的旧头像文件，生成新的非空 `avatar_version`，并在当前账号资料（`GET/PATCH /im/v1/me`、`GET /im/v1/auth/me` 及登录/刷新返回）、可见联系人目录、公司成员列表及聊天参与者/消息身份中返回最新 `avatar_version`，同时通过用户实时流通知可见对端刷新
- **AND** 用户仅通过 `PATCH /im/v1/me` 修改显示名、默认入口设备或语言时，已保存的自定义头像与 `avatar_version` 保持不变

#### Scenario: 移除自定义头像恢复空版本
- **WHEN** 已认证真人客户端调用 `DELETE /im/v1/me/avatar`
- **THEN** IM 清除该账号的 `avatar_version` 并删除对应存储文件（本身无自定义头像时幂等成功），后续身份投影不再携带自定义头像版本并通知可见对端回退至首字母圆章

#### Scenario: 拒绝超限、动态、伪造类型或损坏文件且保留原头像
- **WHEN** 客户端上传空字节、超过单文件体积上限的数据、非支持媒体类型、动态多帧图片（如 GIF 或动态 WebP）、文件头与内容不匹配或无法解码的损坏图片
- **THEN** 请求返回 4xx 拒绝且不写入新文件，账号原有自定义头像与 `avatar_version` 保持不变

#### Scenario: 读取真人头像受登录与组织及会话可见性约束
- **WHEN** 调用方请求 `GET /im/v1/users/:user_id/avatar`
- **THEN** 未携带有效真人访问令牌（含未登录访客或机器中继凭据）返回 401；已认证真人仅在目标为本人、双方同为有效团队成员、当前调用方为管理准入的有效公司管理员（目标处于申请/有效/停用团队状态），或调用方对至少一个包含该目标真人的会话具备读取权限时返回头像图片字节（附带 `nosniff` 与私有缓存头）
- **AND** 目标不存在、为运行时保留身份（`system`、`agent:*`、`shadow:*`）、未设置头像，或调用方不满足上述可见性条件时统一返回 404，不暴露未授权账号是否存在或是否设置头像

### Requirement: Web 账号设置分清个人资料、空间资格与关联管理

Web 账号页以个人身份、自定义圆形图片头像管理与显示名编辑为主，账号 ID 和加入时间按需查看；个人空间与团队资格分别显示，电脑由摘要和入口导向既有电脑管理。注册与首次引导不增加真人头像前置步骤。

#### Scenario: 修改资料、管理个人头像和查看资格
- **WHEN** 用户进入账号页
- **THEN** 可查看当前圆形头像并通过选图与圆形裁剪预览上传或更换头像、在已有自定义头像时移除恢复首字母圆章，修改显示名，辨认当前登录用户名与个人/团队资格，并按资格找到加入申请、申请状态或管理员成员管理入口。
- **AND** 头像的确认保存与移除立即生效并同步导航栏个人菜单与移动端「我的」身份卡，无需额外提交显示名表单；尚未连接电脑时可继续助手设置，已有电脑时通过摘要进入电脑管理，不重复设备详情。

### Requirement: Web 策略设置区别实际容量与未接入执行的预设

有效公司成员可按分组阅读策略预设及其说明；仅管理员可编辑，预设明确标注尚未接入执行。管理员可独立查看实际附件容量与成员用量，不从预设值推断实际容量限制。

#### Scenario: 管理员与只读成员
- **WHEN** 管理员查看策略页
- **THEN** 实际服务占用、上传中、剩余与上限先于预设显示，成员用量按需查看，容量未知有重试而不显示为零。
- **WHEN** 普通有效成员查看策略页
- **THEN** 看到只读预设，无保存操作或管理员容量明细。

### Requirement: Web 账号与策略编辑反馈清楚且保留未提交内容

两页表单未修改或输入不合法时不可保存，提交期间防止重复操作，保存成功有明确反馈。保存失败与后台重新读取不覆盖当前草稿；账号页头像上传、取消裁剪或移除操作独立于显示名表单，不覆盖未提交的显示名草稿；离页不承诺保留草稿。

#### Scenario: 失败、刷新、头像操作与放弃
- **WHEN** 用户编辑显示名后保存失败、页面后台重新读取，或期间打开/取消裁剪预览、上传更换头像、移除头像及遇到头像上传校验/网络错误
- **THEN** 未提交的显示名草稿保持可见，头像失败给出明确原因且保留当前已生效头像；放弃修改恢复显示名已存值而不回滚已独立生效的头像，成功保存显示名退出未保存状态。
- **WHEN** 页面读取失败
- **THEN** 对应区域显示失败与重试入口，不阻断其他已加载区域。

### Requirement: 用户时区由前台客户端自动报告并持久同步到所属 Gateway

浏览器和 iOS SHALL 在打开、回前台以及发送消息时读取系统时区，SHALL NOT 要求用户填写 timezone；后台不持续覆盖账号时区。IM SHALL 保存最近报告的合法时区，只有值变化时写入并通知所属节点；Gateway 重连能取得最新值并缓存供离线渠道和 Heartbeat 使用。

#### Scenario: 多设备切回原设备
- **GIVEN** 上海设备曾报告上海，另一设备随后报告东京
- **WHEN** 用户回到上海设备前台
- **THEN** 即使其系统时区未变化，也重新报告上海，IM 和所属 Gateway 使用上海
- **AND** 相同值再次报告不产生数据库更新或通知。

#### Scenario: 关闭客户端后继续工作
- **GIVEN** 用户系统时区已经成功同步
- **WHEN** 浏览器或 iOS 关闭，飞书输入或 Heartbeat 到达
- **THEN** Gateway 使用保存的用户时区，不以 Gateway 所在地代替。

#### Scenario: 消息时间快照
- **WHEN** 用户发送消息后改变时区或重试同一幂等发送
- **THEN** 原消息保留创建时的发生时间和时区，不因当前账号时区改变而重写。

### Requirement: 双方 Agent owner 对协作私聊有只读观察权

#### Scenario: 有效 owner 读取
- **WHEN** 两个 Agent 的有效 owner 查看其私聊
- **THEN** 双方均可读取，不需要加入成员；管理员和无关账号不因此可读。

#### Scenario: 观察不授权写入
- **WHEN** owner 尝试发送、上传或修改协作聊天
- **THEN** 请求被拒绝，参与者和消息不改变。

#### Scenario: 观察资格失效
- **WHEN** 账号、空间资格或实际 owner 关系失效
- **THEN** 后续读取及实时交付不继续放行。
