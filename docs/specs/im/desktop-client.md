# IM - Desktop Client Specification

> 对齐: refactor-800
> 上级: [IM Specification](spec.md)

## Purpose

Crewden Desktop 独立桌面客户端（macOS Apple Silicon 与 Windows 10/11 x64）的零命令行首次接入、已有节点平滑接管、登录自启与常驻通知、多服务与账号隔离（含官方公网严格 HTTPS 与受控私有化预设/唤起确认）、桌面视口一屏化认证与首次引导、本机原生轨迹与工作区文件直达以及本机节点图形化运维（含日常 Chrome 引导配对）契约。

## Requirements

### Requirement: Desktop 客户端支持零命令行首次接入与已有后台节点平滑接管

IM 与产品桌面发行包 SHALL 提供支持 macOS 15.0 及以上的 Apple Silicon（`arm64`）与 Windows 10/11 `x64` 的独立桌面客户端（Crewden Desktop）。用户在未预装 Node.js、npm、pnpm 或 WSL 的电脑上打开客户端即可连接指定 IM 服务、在应用内完成本机绑定并准备受管运行环境，或平滑接管本机已安装的后台节点。

#### Scenario: 下载正式 Mac 客户端
- **WHEN** 用户从下载页或电脑安装引导选择 Mac 桌面客户端
- **THEN** 页面展示 Apple Silicon 和最低 macOS 版本，磁盘映像内的应用声明与宿主、种子运行时的系统要求兼容
- **AND** 默认对外分发的 DMG 在下载前及发行说明中标注「未经 Apple 公证」，可与 Windows、Node 一起发布。内测候选单独标记且发布器拒绝上传。显式选择公证版时，应用和 DMG 必须通过 Developer ID 签名、Apple 公证、装订票据和 Gatekeeper 检查；任一步失败即停止发布

#### Scenario: 在干净电脑上零命令行完成首次接入与真实回复
- **GIVEN** 电脑为未安装 Node.js、npm、pnpm 或 WSL 的 macOS Apple Silicon 或 Windows 10/11 x64，且用户拥有可用的模型服务
- **WHEN** 用户从 Web IM 唤起打开或直接启动 Crewden Desktop，确认或输入 IM 服务地址、登录账号，并在应用内确认绑定当前电脑、配置模型与助手后发送消息
- **THEN** 当前电脑在目标 IM 服务中显示在线，用户在 Desktop 内收到该电脑上助手的真实回复
- **AND** 全程无需打开终端、复制执行安装脚本、安装系统开发工具或切回外部浏览器做二次绑定确认；本机受管运行环境完整包含内置工具与 Web 能力所需依赖，启动后正常激活全部内置能力

#### Scenario: Windows 安装向导默认勾选桌面快捷方式并支持运行中平滑覆盖升级
- **WHEN** 用户在 Windows 10/11 上运行 Crewden Desktop 安装向导
- **THEN** 安装选项页默认勾选「创建桌面快捷方式」；保持默认完成安装后同时在用户桌面与开始菜单生成启动快捷方式，取消勾选后仅保留开始菜单快捷方式而不强制写入桌面图标
- **AND** 当旧版客户端或本机受管后台节点正在运行期间执行新版安装包覆盖升级时，安装程序优雅停止运行实例并完成替换，重新启动后自动切换至新版内置运行环境并完整保留既有登录会话、节点身份、模型配置与本地工作区

#### Scenario: 首次启动即时呈现准备进度并保证单实例唤醒与原路由保持
- **GIVEN** 用户首次安装完 Crewden Desktop 尚未解包内置运行环境，或应用已停留在准备页、登录页或首次设置引导页
- **WHEN** 用户启动应用，或在首启极短窗口及运行期间再次双击桌面/开始菜单快捷方式（未携带深链目标路径）
- **THEN** 首次准备内置运行环境期间立即展示「正在准备运行环境…」进度窗口并注册菜单栏/系统托盘图标，准备完成后自动进入应用界面；重复启动请求不会并发争抢归档文件、弹出锁冲突错误或强制改跳其他页面，而是唤醒置顶现有主窗口并保留当前所在页面

#### Scenario: 接管本机已安装的后台节点身份与工作区
- **GIVEN** 当前电脑此前已通过命令行脚本或 Windows 轻量后台安装器绑定至同一 IM 服务，存在已有助手、模型凭据与本地工作区文件
- **WHEN** 用户打开 Crewden Desktop 登录原所属账号并确认接管本机节点
- **THEN** 客户端复用原电脑节点身份、已配置模型凭据、已有助手与原工作区文件，可在原会话继续对话并访问原工作区内容
- **AND** 原独立后台启动入口平滑移交，本机不会同时运行两个竞争同一节点配置的后台实例
- **AND** 当本机现有节点已绑定于其他账号时，默认仅进入聊天而不暴露或改动原账号的本机配置、运行日志与私人工作区；仅在用户明确二次确认整机设备转移后才变更设备归属

#### Scenario: 准备运行环境、宿主启动或节点启动失败时快速可诊断且保态
- **WHEN** 首次启动准备运行环境、访问指定 IM 服务或提交电脑绑定时发生网络错误、地址不可达、校验失败或本机后台节点确定性启动崩溃
- **THEN** 当前界面在数秒内结束等待并明确展示具体失败原因与重试、修改服务地址或查看本机日志入口，后台守护进程按退避策略抑制死循环刷屏，且不损坏本机已有配置与工作区数据
- **AND** 若桌面宿主在窗口就绪前遇到归档损坏、目录不可写或本地回环服务无法绑定等致命启动错误，将带时间戳的详细原因追加写入本机用户数据目录下的宿主日志文件并弹出系统原生错误提示框，不静默退出

### Requirement: Desktop 客户端保持系统登录自启、菜单栏或系统托盘常驻与受管更新

#### Scenario: 默认登录自启与后台异常退出恢复
- **GIVEN** 用户已通过 Crewden Desktop 完成本机绑定并保持默认的开机登录自启设置
- **WHEN** 用户重启电脑并重新登录同一系统账号，或运行期间本机后台节点意外退出且故障已消除
- **THEN** 在网络与 IM 服务可用时，Crewden Desktop 自动驻留菜单栏（macOS）或系统托盘（Windows）并使原电脑恢复在线，原助手可继续正常回复

#### Scenario: 关闭主窗口保持后台在线并支持多入口唤起
- **GIVEN** Crewden Desktop 正在运行且本机节点在线
- **WHEN** 用户关闭主聊天窗口
- **THEN** 客户端继续驻留菜单栏或系统托盘，本机节点执行、消息接收与系统通知保持在线
- **AND** 点击 Dock / 任务栏图标、菜单栏/托盘打开项或系统原生通知时，主窗口恢复显示

#### Scenario: 手动启停本机节点与开关登录自启
- **WHEN** 用户在菜单栏/托盘或应用内本机管理页主动停止本机后台节点
- **THEN** 本机节点进入离线并保持停止，直至用户手动再次启动，或在仍启用登录自启时重新登录系统
- **WHEN** 用户关闭开机登录自启设置并重启电脑重新登录
- **THEN** 该电脑保持离线且不自动拉起后台运行；用户手动打开并启动后，原电脑身份与助手恢复可用；设置未能生效时界面如实展示实际状态与恢复提示

#### Scenario: 受管更新保留登录会话、电脑身份与工作区
- **GIVEN** 已绑定的 Crewden Desktop 存在目标 IM 服务指定的新版本
- **WHEN** 用户发起并完成受管更新（存在在途本机任务时等待任务排空或按用户确认处理后再切换）
- **THEN** 更新后延续原服务登录态、电脑节点身份、已有助手与本地工作区文件；下载、校验或切换失败时回退保留原可用版本并展示原因

### Requirement: Desktop 主窗口保持既有 IM 业务权限、原生通知直达与按服务及账号隔离

#### Scenario: 主窗口完整承载既有 IM 业务并支持原生通知直达
- **WHEN** 用户在 Crewden Desktop 主窗口操作聊天、渐进式任务、Agent Work、助手与外部通道设置、模型服务、电脑管理、账号及公司空间
- **THEN** 各项业务能力、访问权限、乐观锁与离线只读语义同既有 IM 契约一致；外部网站链接通过系统默认浏览器打开且不携带 IM 凭据
- **AND** 收到符合提醒资格的新消息（含外部渠道对端入站消息与已关注群话题回复，排除账号拥有者本人在外部渠道发出的镜像消息）、已静音会话中的明确 `@提及`、会话内待决工具权限审批或本人管理助手处于等待权限确认（`waiting_permission`）的 Work 更新时，应用图标/托盘按未静音会话汇总更新未读状态（随已读与静音变更实时同步），并在窗口未聚焦目标视图时弹出桌面通知（或发送系统原生通知）；点击通知唤醒主窗口并定位到目标聊天、对应群话题或助手 Work 入口；静音会话的非提及消息、权限结案回写与重连历史回放不弹出重复通知

#### Scenario: 官方与公网严格保持 HTTPS，受控支持私有化预设地址、内网 HTTP 与外部唤起切服确认
- **WHEN** 用户在服务切换栏输入，或通过外部唤起链接（含客户端冷启动、Windows 二次进程转发与 macOS 协议打开事件）传入官方域名或公网非私网地址的明文 `http://` 形式
- **THEN** 客户端拒绝切换至该不安全地址、保持当前已生效服务不变，并唤醒主窗口向用户明确提示官方及公网服务必须使用加密 `https://`（本机回环开发地址除外）
- **AND** 企业内部独立部署打包预设了默认内部 IM 地址与受信自托管发布源时，首次打开客户端默认连接该预设 IM 地址并支持从该受信源完成应用内受管更新；内网私网 `http://` 地址仅在严格满足 RFC1918/RFC4193 私网 IP 字面量或 `.local` 主机范围校验时允许接入
- **AND** 无论客户端处于未运行冷启动还是后台常驻状态，凡由外部唤起链接请求切换到与客户端当前已保存服务不同的新 IM 服务地址时，客户端唤醒主窗口并弹出服务切换确认提示（展示当前服务与目标服务地址；目标为明文内网 `http://` 时显著标示未加密风险），用户取消时保留原服务与会话不变，仅在确认后才执行切换

#### Scenario: 切换 IM 服务地址或账号时隔离数据，短暂断网不误退登录
- **WHEN** 用户重新打开客户端、切换账号或切换到另一 IM 服务地址
- **THEN** 重开时恢复上次有效会话与当前服务的待恢复发送记录；切换服务地址后，界面按服务隔离会话、草稿、受保护媒体与轨迹视图并保留原服务待恢复的未确认消息发送记录；退出或切换账号时清除上一账号在该服务下的本地数据，迟到的旧响应不会写回新语境
- **AND** 遇到短暂断网或服务暂时不可达时，保留已确认界面内容并展示重连状态，不退回登录页；仅当服务端明确拒绝凭据或账号停用时才清除内容并要求重新登录

### Requirement: Desktop 对本机节点所属 Agent 提供原生轨迹与工作区文件本地直读，并兼容远端节点与多端同步

#### Scenario: 本机已绑定节点 Agent 的原生轨迹与大输出本地直读
- **GIVEN** 当前登录账号具备某 Agent 的 Work 查看权限，且该 Agent 归属在当前 Desktop 所托管并已绑定至同一 IM 服务的本机节点上
- **WHEN** 用户在 Desktop 查看该 Agent 主执行或关联子执行/fork 的原生轨迹，检查历史批次、超过中心单条同步上限的大体积工具输出或该执行实际读取过的工作区图片
- **THEN** 客户端直接从本机读取并完整展示轨迹记录、完整工具原文及工作区图片，无浏览器跨域或混合内容错误，也不因中心同步上限截断正文
- **AND** 时间概览选区联动、搜索、折叠、子执行范围聚焦及返回父级恢复阅读位置均保持可用；无该 Agent Work 查看权限或失去访问资格时拒绝并停止读取，聊天来源的受保护附件仍遵守原会话访问权限

#### Scenario: 远端节点透明回退与多端同步保持一致
- **WHEN** 用户在 Desktop 查看运行在远端节点上的 Agent Work 与原生轨迹，或在其他端（Web / iOS）查看本机节点 Agent 的会话与已同步工作记录
- **THEN** 远端节点 Agent 自动经 IM 通路正常读取，无需手动切换模式；本机节点 Agent 的聊天消息与受支持工作记录继续同步至中心 IM

#### Scenario: 一键在本地打开本机工作区文件与目录
- **GIVEN** 聊天消息、工具过程或工作视图中关联了本机已绑定节点所属 Agent 工作区内的真实文件或目录
- **WHEN** 用户在 Desktop 触发「在文件管理器中显示」或「打开文件」动作
- **THEN** 系统调用 macOS Finder 或 Windows 资源管理器定位该路径，或使用系统默认应用直接打开原文件，无需经中心服务下载副本
- **AND** 可执行脚本或应用后缀仅支持在文件管理器中定位显示而不直接运行；非本机节点路径或本机已不存在的路径不执行无效本机打开，分别走常规远端附件入口或提示本机路径不存在

### Requirement: Desktop 提供本机节点运行状态、运行日志与本机专属配置的图形化管理

#### Scenario: 图形化查看本机节点状态与运行日志
- **WHEN** 用户在 Desktop 打开菜单栏/托盘摘要或电脑管理中的「这台电脑」区域（包括本机节点处于已停止或启动失败状态时）
- **THEN** 可直接查看本机节点连接状态、后台执行运行时健康状态、开机自启状态及当前版本号，并可查看、按关键字搜索过滤、刷新和复制最近的本机运行日志与错误摘要

#### Scenario: 图形化修改本机代理、一级委派 Worker、环境变量与专用审批模型并平滑重启生效
- **WHEN** 用户在「这台电脑」管理区查看本机一级委派 Worker 可用探测状态（内置运行时、Codex、Claude Code、Antigravity），修改本机网络代理、一级 Worker 选择、运行环境变量或专用自动审批模型并保存
- **THEN** 需要重启本机后台节点生效的变更明确提示影响范围（存在在途任务时提示等待或确认），并在确认后完成受管平滑重启，恢复上线后新配置实际作用于后续执行

#### Scenario: 在「这台电脑」引导配对与断开日常 Chrome
- **WHEN** 当前登录账号为本机已绑定节点的拥有者，并在 Desktop「这台电脑」管理区操作日常 Chrome 连接
- **THEN** 客户端通过本机受控管理桥（校验当前 `owner_id`）展示 Chrome Profile 与配对状态、拉起扩展安装/Token 页面引导、保存手动粘贴的 Token 至本机私有配置或断开连接，无需重启后台节点即可生效；非本机拥有者账号不暴露或修改原账号的浏览器配对配置

#### Scenario: 本机配置校验失败或重启未就绪时保留原可用状态
- **WHEN** 用户提交非法代理/环境变量格式、选择了未注册的专用审批模型，或重启后新配置未能使节点正常就绪
- **THEN** 界面明确展示失败原因并保留编辑草稿，不将未生效配置显示为当前生效值，并保持或自动回退至原先可用的节点运行状态

### Requirement: Desktop 客户端登录、注册与首次设置引导适配桌面视口一屏呈现

#### Scenario: 标准桌面窗口与常见高分屏缩放视口下免整页滚动完成认证与首次引导
- **GIVEN** 用户在 Crewden Desktop 默认窗口尺寸（`1280×840`）或常见高分屏缩放后的桌面视口（宽度 `≥1024px`、高度 `≥720px`）中打开应用
- **WHEN** 用户查看登录页（含服务地址栏及原地展开编辑态）、注册页、首次欢迎页、三步设置引导页各步骤初态及聊天空态欢迎页
- **THEN** 页面采用紧凑桌面软件视口布局一屏呈现核心说明、表单输入与底部主操作按钮，外层页面容器不出现整页垂直滚动条，桌面顶栏品牌标识保持在应用内而不跳往浏览器长营销介绍页
- **AND** 当设置引导步骤（如展开自定义模型 API 表单）内容高度超出卡片可用高度时，仅卡片内容区内部滚动且左侧步骤栏与底部主操作按钮（含返回与验证/继续/创建）始终固定可见；普通浏览器官网首页与窄屏响应式布局保持既有体验
