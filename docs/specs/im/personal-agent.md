# IM Personal Agent Specification

> 对齐: feat-785

## Purpose

定义固定个人助手的身份、聊天访问、聊天创建独立 Agent、原聊天协助与风险通知；普通 Agent 配置和 IntelligentUI 行为复用相应现有 area。

## Requirements

### Requirement: 固定个人助手保持原 IM 体验
#### Scenario: 聊天列表中的固定个人助手
- **WHEN** 主人查看 Web 聊天列表
- **THEN** PA 保留独立的置顶聊天入口，使用普通聊天行呈现最新消息摘要、消息时间与未读数，不用告警式底框或固定角色说明覆盖已有消息。
- **AND** 摘要与普通聊天使用相同的 mention、卡片和系统通知呈现，收到更新与已读变化时同步刷新；尚无消息时可显示角色说明。固定入口与工作区欢迎页使用会话当前标题，手动命名不被助手配置保存覆盖。

#### Scenario: 工作电脑保持固定
- **WHEN** 主人打开 PA 配置页
- **THEN** 不提供跨电脑迁移入口；PA 专用换机接口不可用，不能借该接口改变现有绑定、工作区或聊天归属
- **AND** 已有 PA 的日常配置、聊天访问控制与当前运行位置继续沿用

#### Scenario: 创建、改名和配置
- **WHEN** 用户创建或配置自己的 PA
- **THEN** 固定主人关系与私聊入口保持，使用原 Agent 设置与导航；他人可联系 PA，但不能读取主人私人配置和 Work。
- **AND** 已创建PA的聊天配置入口直接进入现有Agent配置页；名字、模型、指令、技能与聊天访问范围在同一页维护，不另设PA设置浮窗。来源勾选明确立即生效；创建与未完成创建的恢复仍使用原设置流程。

#### Scenario: 创建与第一条消息分开
- **WHEN** 用户在首次设置或聊天入口创建 PA
- **THEN** 只需填写助手名字，头像按[角色头像约定](agents-nodes.md#requirement-创建助手时可选择统一且可辨认的角色头像)预选。创建成功后进入尚无消息的主人私聊，不收集或自动发送首个任务。
- **WHEN** 主人第一次进入已确认没有历史的 PA 聊天，且输入框为空
- **THEN** 先展示可尝试的小任务，背景介绍与长期职责入口按[首次建立合作约定](#首次建立合作约定)按需展开；点击提示仅填入并聚焦普通输入框，由用户编辑后发送。
- **AND** 发出第一条消息后隐藏整个引导，已有历史的聊天不再显示；已有草稿或附件时不覆盖，查看他人的 PA 时不显示主人职责引导。

#### Scenario: 刷新后恢复未完成的创建
- **WHEN** 电脑尚未确认 PA 创建，用户刷新首次设置页面
- **THEN** 页面显示可重试的准备状态，恢复同一助手与原电脑，不打开尚未建立的聊天；只有确认创建完成才进入私人对话。

#### Scenario: 注册后创建并沿用同一个 PA
- **WHEN** 新用户注册并在首次设置中连接电脑、确认可用模型和创建助手
- **THEN** 创建的是该用户固定的 PA 与主人私聊，个人使用无需等待公司批准。
- **WHEN** 用户随后申请加入公司并获批
- **THEN** PA、绑定与主人私聊身份保持，既有消息、配置和工作上下文继续沿用；不再要求创建第二个 PA，也不把私人聊天与 Work 发布给公司。

### Requirement: 历史查询同时覆盖主人和 PA
#### Scenario: 双身份查询
- **WHEN** 主人询问跨聊天进展
- **THEN** 查询当前可访问的主人与 PA 参与聊天并集，保留真实作者与出处，不增加任意日期窗口。

### Requirement: 双向主人消息可用于协助

下列新消息观察场景适用于团队协作；仅限本人时仅接收主人亲自给 PA 的私聊。历史查询与单聊天来源排除仍遵循其访问规则。

#### Scenario: 主人先回复
- **WHEN** 主人亲自在原聊天回复
- **THEN** PA 能接收该消息并避免重复回复，读取不改变主人的已读状态。

#### Scenario: 观察主人与他人沟通
- **WHEN** 主人和他人在 PA 未参与的授权聊天里沟通
- **THEN** 双方原话可供 PA 理解背景，主人向对方交办或承诺、对方向主人请求均不自动变成 PA 的新任务；PA 可以按既有目标与授权继续协助。
- **AND** 普通观察消息不触发 PA 向该聊天自动发送拒绝警告。

### Requirement: PA 回复草稿复用 IntelligentUI
#### Scenario: 编辑并采用
- **WHEN** 主人编辑 PA 提供的回复草稿并采用
- **THEN** 编辑内容进入正确的原聊天输入框，主人确认发送后才向对方发布；采用使用与普通 Agent 相同的通用交互动作，不绑定原消息；采用不自动发送。
#### Scenario: PA 代发
- **WHEN** PA 按真实委托在原聊天代表用户发送
- **THEN** 以用户为发言主体，保留实际 PA 的可辨认来源，发送成功以真实回执为准；受众、完整内容和原始委托范围仍经正常外发检查。

### Requirement: 来源限制与风险提醒明确
#### Scenario: 来源排除与恢复
- **GIVEN** PA 所属节点在线且设置页已刷新当前范围
- **WHEN** 主人调整 PA 的聊天访问范围
- **THEN** 对新消息和历史查询实际生效，不承诺抹除已读内容，不展示全局暂停观察开关。
#### Scenario: 可疑套取
- **WHEN** 对方反复越界索取且有原消息证据
- **THEN** 阻止披露并通知主人，未触发自动屏蔽的事件在真实通知送达后才告知对方；自动屏蔽的主人专属通知及计数规则见 [Gateway PA 契约](../gateway/personal-agent.md#requirement-系统累计五次输入风险自动屏蔽联系人)，不增加常规人工审批。

#### Scenario: 默认职责由系统提供
- **WHEN** 首次创建或使用PA
- **THEN** 服务方式、持续推进和Skill默认指导由系统提供，不向custom_prompt或ROLE写入默认文案。用户长期个性约定通过ROLE维护。
- **AND** 旧用户配置只在获授权部署时按一次性提示词迁移，不自动覆盖现有ROLE或Skill选择。
#### Scenario: 简洁的隐私知情提醒
- **WHEN** 主人看到已拒绝的越界请求
- **THEN** 默认展示一条紧凑保护摘要，按联系人合并重复提醒，展开后查看原因和原消息；界面跟随应用语言，原始证据保持原文。
- **WHEN** 主人选择“知道了”
- **THEN** 仅收起本次已看到的提醒，不改变访问权限、联系屏蔽或披露策略，不把知情当成放行。
- **WHEN** 主人主动展开后续协作并拒收此人请求
- **THEN** 沿用现有联系屏蔽机制，同步收起该联系人已有的未处理提醒；明确拒收私聊请求，群聊保留消息并提示风险，不影响主人与对方聊天。失败保留未成功的提醒并允许重试。

#### Scenario: 按人屏蔽并可撤销
- **WHEN** 主人屏蔽某人的请求
- **THEN** 对 Web IM 的同一账号拒收私聊请求；共同群聊仍正常接收，并向 PA 提供服务端可信的联系人风险提示，不因群内有该人而禁止正常群务回复；对外披露继续检查真实受众。
- **WHEN** 主人打开 PA 的现有 Agent 配置页
- **THEN** 看见当前已屏蔽联系人、原因与可打开的证据链接，在节点在线且已刷新当前状态时可解除屏蔽；失败时保留原状态并允许重试。
- **WHEN** 主人解除屏蔽
- **THEN** 私聊请求恢复、新消息不再带当前屏蔽提示，并通知主 PA 当前限制已撤销；历史事件保留供回看，不自动形成永久信用标签，不承诺删除已进入上下文的信息。
- **WHEN** 主人查看自己的 PA 与他人的原私聊
- **THEN** 复用会话只读观察权限，不加入会话、不允许发送；私人群仍按原权限判断，无权查看时链接到已交付的主人风险通知。

#### Scenario: 独立启停 PA 主动筹划并与运行特性统一保存联动
- **GIVEN** PA 所属节点在线且设置已确认同步
- **WHEN** 主人在 Web 或原生 iOS 的 PA 运行特性配置中开启或关闭「主动筹划」并保存
- **THEN** 界面以单一可编辑开关清楚说明开启与关闭后果（关闭后停止对话安静后的自动静默复盘与待拍板提议立卡，主人明确交办的任务与自行设定的定时提醒照常运行），仅对本人 PA 展示该特性、不对普通团队数字员工展示
- **AND** 开启主动筹划时与「任务图」特性保持同一页面可见的依赖联动与轻提示，沿用现有配置乐观锁保存与生效确认，未经节点确认生效前不将状态伪装为已生效

#### Scenario: PA 设置页离线只读
- **GIVEN** PA 所属节点不可达
- **WHEN** 主人查看 PA 配置、主动筹划状态、来源范围或已屏蔽联系人
- **THEN** 已保存信息、原因和有权查看的证据仍可阅读，改名、主动筹划切换与保存、来源调整与解除限制统一禁用，服务端拒绝这些新设置写入
- **AND** 恢复连接后先刷新再开放，不自动提交未保存内容；聊天内既有隐私提醒和风险保护流程不受此设置页条件改变

### Requirement: Agent 列表突出本人的 PA 配置入口
#### Scenario: 双端查找
- **WHEN** 已有 PA 的主人打开 Web 或原生 iOS Agent 列表
- **THEN** 本人的 PA 位于可辨认的优先区，沿用普通助手行样式，整行打开现有配置，无额外 Configure 按钮；其他用户 PA 不获得此入口或管理权限；搜索保留原联系人匹配字段，从有草稿的配置页切换时先确认是否放弃。
#### Scenario: 无 PA 或读取失败
- **WHEN** 尚无 PA 或读取暂时失败
- **THEN** 普通 Agent 列表保持可用，失败可重试且不当作未创建。

### Requirement: 代表用户的消息在各端保持同一身份
#### Scenario: 双方与后续查看
- **WHEN** 用户本人或其他成员在 Web 桌面、移动端及原生 iOS 查看群聊/私聊中的代发消息
- **THEN** 展示该用户的主头像与姓名、相邻的“PA 代发”标记，用户本人侧沿用本人消息归属；正文不依赖代发前缀说明身份。
- **AND** 刷新、历史、现有引用、搜索及会话预览中出现的发送者身份一致，完整消息保留实际代发来源；不向成员暴露私人 PA 工作上下文。
#### Scenario: 自身发言与旧记录
- **WHEN** PA 以自身身份发言、报告或提供草稿，或客户端显示升级前的旧 PA 消息
- **THEN** 保留 PA 的身份与原文；旧代发标记不会自动提升为用户发言或授权，草稿不自动对外发送。

### Requirement: PA 创建使用原主人来源与既有节点创建边界

#### Scenario: 创建可在现有产品中使用
- **WHEN** 可信主 PA 根据主人向它提出的原始创建要求完成创建
- **THEN** 新 Agent 出现在本人的现有列表，可长期聊天并经现有配置页维护；创建仍遵守本人绑定节点、在线校验及实际工作区和能力校验。
- **AND** 观察内容、他人消息或 PA 自己代发的消息不能成为新的主人创建依据。
- **AND** 首次提交配置操作前，即使经过排队或能力查询等待，主 PA 的绑定、原执行代次和主人来源仍须有效；已接受操作继续按原回执确认实际结果。

#### Scenario: 同次请求恢复与冲突
- **WHEN** 同一次创建遇到断线、重启或结果尚未确认
- **THEN** 按同一请求确认原操作，不重复创建，未确认时不宣称成功。
- **AND** 请求标识被用于不同目标或配置时拒绝混用；离线、权限、ID/路径或配置冲突均明确说明，不静默换机。

### 首次建立合作约定

PA 创建时可按 [Agent 身份头像](agents-nodes.md#requirement-创建助手时可选择统一且可辨认的角色头像)选择形象，创建后直接进入主人私聊。已确认无历史的首屏优先提供理清想法、安排一周、找到第一步等小任务；点击仅填入空输入框并聚焦，由主人修改并发送，已有草稿或附件时不可覆盖。背景介绍与长期职责引导放在可展开的可选入口；选择稍后只隐藏职责引导，仍可选择小任务或自由输入。背景按正常对话／记忆流程处理，不能把发送成功表示为永久记忆成功。

同一入口也覆盖绑定管理者与 Global 数字员工的私聊，内容转为工作背景、负责结果、交付标准及分工；Global 创建成功直接打开私聊，打开失败则落到已创建的设置页提示重试，不重复创建。普通联系人、群聊和单线程 Agent 不显示职责引导。

引导只在已确认没有历史消息的主人／管理者私聊中展示。用户发出第一条消息后移除整个引导，不继续展示职责讨论状态、保存状态、继续入口或 ROLE 正文；刷新和返回已有聊天也不再展示。职责入口仅通过现有 role API 判定是否已有职责，创建时已保存职责的 Global 不重复引导；不轮询角色状态，读取失败或离线时不展示职责引导，个人助手的小任务草稿入口仍可用，不表示助手已在线。职责讨论、确认与保存结果由正常对话承接，角色文档仍在原设置页维护。
