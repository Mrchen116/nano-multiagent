# IM Personal Agent Specification

> 对齐: feat-616

## Purpose

定义固定个人助手的身份、聊天访问、原聊天协助与风险通知；普通 Agent 配置和 IntelligentUI 行为复用相应现有 area。

## Requirements

### Requirement: 固定个人助手保持原 IM 体验
#### Scenario: 创建、改名和配置
- **WHEN** 用户创建或配置自己的 PA
- **THEN** 固定主人关系与私聊入口保持，使用原 Agent 设置与导航；他人可联系 PA，但不能读取主人私人配置和 Work。
- **AND** 已创建PA的聊天配置入口直接进入现有Agent配置页；名字、模型、指令、技能与聊天访问范围在同一页维护，不另设PA设置浮窗。来源勾选明确立即生效；创建与未完成创建的恢复仍使用原设置流程。

#### Scenario: 创建与第一条消息分开
- **WHEN** 用户在首次设置或聊天入口创建 PA
- **THEN** 只填写助手名字，创建后进入空白主人私聊；不收集或自动发送首个任务。
- **WHEN** 主人第一次进入已确认没有历史的 PA 聊天，且输入框为空
- **THEN** 显示几条简短任务示例；点击仅填入并聚焦普通输入框，允许编辑，用户点击发送后才发送。
- **AND** 有历史、已有输入或查看他人的 PA 时不显示这些首次示例，不覆盖原有草稿。

#### Scenario: 注册后创建并沿用同一个 PA
- **WHEN** 新用户注册并在首次设置中连接电脑、确认可用模型和创建助手
- **THEN** 创建的是该用户固定的 PA 与主人私聊，个人使用无需等待公司批准。
- **WHEN** 用户随后申请加入公司并获批
- **THEN** PA、绑定与主人私聊身份保持，既有消息、配置和工作上下文继续沿用；不再要求创建第二个 PA，也不把私人聊天与 Work 发布给公司。

### Requirement: 历史查询同时覆盖主人和 PA
#### Scenario: 双身份查询
- **WHEN** 主人询问跨聊天进展
- **THEN** 查询当前可访问的主人与 PA 参与聊天并集，保留真实作者与出处，不增加任意日期窗口。

### Requirement: 双向主人消息可用于协助
#### Scenario: 主人先回复
- **WHEN** 主人亲自在原聊天回复
- **THEN** PA 能接收该消息并避免重复回复，读取不改变主人的已读状态。

### Requirement: PA 回复草稿复用 IntelligentUI
#### Scenario: 编辑并采用
- **WHEN** 主人编辑 PA 提供的回复草稿并采用
- **THEN** 编辑内容进入正确的原聊天输入框，主人确认发送后才向对方发布；采用不自动发送。
#### Scenario: PA 代发
- **WHEN** PA 按已有授权在原聊天代发
- **THEN** 对方能辨认 PA 实际身份及代发标记，发送成功以真实回执为准。

### Requirement: 来源限制与风险提醒明确
#### Scenario: 来源排除与恢复
- **WHEN** 主人调整 PA 的聊天访问范围
- **THEN** 对新消息和历史查询实际生效，不承诺抹除已读内容，不展示全局暂停观察开关。
#### Scenario: 可疑套取
- **WHEN** 对方反复越界索取且有原消息证据
- **THEN** 阻止披露并通知主人，真实通知送达后才告知对方；不增加常规人工审批。

#### Scenario: 默认职责复用可编辑补充指令
- **WHEN** 首次创建 PA
- **THEN** 把服务方式、持续推进和按需使用共用 Skill 的默认指导保存到现有 custom_prompt，用户可在原 Agent 设置查看、修改或清空；创建页面无需新增配置。
- **WHEN** 已有 PA 重试创建、恢复或升级
- **THEN** 保留已有补充指令和 Skill 选择，不自动补写或覆盖用户内容。

#### Scenario: 简洁的隐私知情提醒
- **WHEN** 主人看到已拒绝的越界请求
- **THEN** 默认展示一条紧凑保护摘要，按联系人合并重复提醒，展开后查看原因和原消息；界面跟随应用语言，原始证据保持原文。
- **WHEN** 主人选择“知道了”
- **THEN** 仅收起本次已看到的提醒，不改变访问权限、联系屏蔽或披露策略，不把知情当成放行。
- **WHEN** 主人主动展开后续协作并拒收此人请求
- **THEN** 沿用现有联系屏蔽机制，同步收起该联系人已有的未处理提醒；明确拒收私聊请求，群聊保留消息并提示风险，不影响主人与对方聊天。失败保留未成功的提醒并允许重试。

#### Scenario: 按人屏蔽并可撤销
- **WHEN** 主人屏蔽某人的请求
- **THEN** 对 Web IM 的同一账号拒收私聊请求；共同群聊仍正常接收，并向 PA 提供服务端可信的联系人风险提示，不因群内有该人而禁止正常群务回复；对外披露继续检查真实受众。
- **WHEN** 主人打开 PA 的现有 Agent 配置页
- **THEN** 看见当前已屏蔽联系人、原因与可打开的证据链接，可解除屏蔽；失败时保留原状态并允许重试。
- **WHEN** 主人解除屏蔽
- **THEN** 私聊请求恢复、新消息不再带当前屏蔽提示，并通知主 PA 当前限制已撤销；历史事件保留供回看，不自动形成永久信用标签，不承诺删除已进入上下文的信息。
- **WHEN** 主人查看自己的 PA 与他人的原私聊
- **THEN** 复用会话只读观察权限，不加入会话、不允许发送；私人群仍按原权限判断，无权查看时链接到已交付的主人风险通知。
