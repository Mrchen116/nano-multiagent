# im - Task Graphs Specification

> 对齐: feat-569
> 上级: [im Specification](spec.md)

## Purpose

约束任务图的成员可见性、持久记录语义与 Web IM 浏览体验。

## Requirements

### Requirement: 任务图入口与其来源聊天共享成员可见性

#### Scenario: 成员查看任务
- **WHEN** 当前成员从聊天或任务入口查询关联的图
- **THEN** 能获取该图与其内部层级，并辨认关联聊天；关联聊天可以是原生或既有外部映射会话，输入渠道不另行改变图的可见性。
- **AND** 聊天入口显示当前成员可见的图数量；任务列表可按标题搜索和分页。

#### Scenario: 访问已撤销
- **WHEN** 非成员或已被移除的成员通过任务入口查询图或搜索摘要
- **THEN** 后续请求不返回标题、结构或结果；页面发现权限撤销后清除当前受保护内容。
- **AND** 不承诺撤回成员在有权期间已经读取或自行保存的信息。

#### Scenario: Work 内容可读不授予原图访问权
- **GIVEN** Agent 已将任务内容记录在工作轨迹中，登录用户不是来源聊天的成员
- **WHEN** 该用户查看 Work，再从中打开原任务图或原聊天
- **THEN** Work 中已有内容按现有 Work 规则展示，原任务图和原聊天仍按当前成员关系拒绝访问。

### Requirement: 计划依赖与探索衍生具有不同语义

#### Scenario: 计划图
- **WHEN** 用户查看计划式任务图
- **THEN** 连线表示前置依赖，分叉、汇合和跨列的直接依赖均可辨认；节点详情可查直接前置和后续，记录完成不会自动执行后续节点。

#### Scenario: 探索图
- **WHEN** 用户查看由 X 衍生 Z 的探索记录
- **THEN** 能辨认来源关系、负结果、保留或放弃的方向与显式选项，衍生线不被解释为必须完成的前置任务。

### Requirement: 图节点可按任一模式继续细分

#### Scenario: 两种模式嵌套
- **WHEN** 用户逐层打开计划节点里的探索，再打开方向里的验证计划
- **THEN** 每层展示对应关系、节点与面包屑，返回外层不丢结构。

### Requirement: 记录更新不等于执行或验收

#### Scenario: 更新状态、选项或结果
- **WHEN** 图记录被明确更新
- **THEN** 对应节点反映新内容，不自动改变无关节点、父目标或关联执行状态。
- **AND** 完成可继续修改，界面不将记录描述为已独立验收。
- **AND** 节点保留最近一次变更说明；从完成恢复进行中时必须附返工原因，可在详情查看，不形成历史版本系统。

### Requirement: 图数据持久且修改失败不会损坏已有结构

#### Scenario: 重读与正常重启
- **WHEN** 已保存图被刷新或在同一持久数据上重启服务后读取
- **THEN** 目标、层级、边、当前选项和结果保持一致。

#### Scenario: 不合法或过时的更新
- **WHEN** 修改会制造循环、错误跨层关系或覆盖更近的修改
- **THEN** 明确拒绝且不部分更新原图。

### Requirement: 任务图入口在桌面与手机保持可操作

#### Scenario: 空、加载、错误与已加载图
- **WHEN** 用户进入任务入口或节点详情
- **THEN** 能区分无任务、加载、失败、旧数据与当前记录，并能够重读和逐层导航。
- **AND** 手机不裁切关键操作，现有聊天与Agent入口不被替换。
