# im - Task Graphs Specification

> 对齐: feat-569
> 上级: [im Specification](spec.md)

## Purpose

约束账号及其名下 Agent 共享目标的访问边界、持久记录语义与 Web IM 浏览体验。

## Requirements

### Requirement: 账号及其名下 Agent 共享持久目标

#### Scenario: 账号内共享与跨账号隔离
- **WHEN** 用户或其名下已启用任务能力的Agent查询任务图
- **THEN** 能访问该账号所有目标，不要求加入相同聊天或被分派为负责人；分页摘要和名称搜索使用相同账号边界。
- **AND** 其他账号即使是来源聊天成员，也不能读取或修改图、摘要或重放写入回执；Work已有内容不扩大原图权限。

#### Scenario: 可选来源与独立生命周期
- **WHEN** 图没有来源聊天，或来源聊天被删除
- **THEN** 图的内容、ID和后续读写仍保持，聊天删除仅移除来源关联。
- **AND** 节点最近更新聊天的标题与跳转仍按其成员权限展示，图访问权不授予聊天访问权。

#### Scenario: 从任意聊天继续讨论
- **WHEN** 用户从顶部任务入口进入任务页，或希望把某个节点交给另一个Agent讨论
- **THEN** 任务页展示账号目标，聊天中的图链接仍可直达节点；节点引用可复制并粘贴到任意聊天，有权访问时回所选节点最后更新的聊天并追加引用，保留已有草稿且不自动发送。

#### Scenario: 每个节点独立记录最后更新聊天
- **WHEN** 节点在不同聊天中被更新
- **THEN** 每个节点只回到最后更新自身的聊天，更新其他节点不覆盖它的回聊位置；没有对应聊天的最后更新不指向更早聊天。
- **AND** 重试同一写入不改变原记录的更新聊天；已删除或当前不可访问的聊天不展示跳转，图仍可读写。

### Requirement: 计划依赖与探索衍生具有不同语义

#### Scenario: 计划图
- **WHEN** 用户查看计划式任务图
- **THEN** 连线表示前置依赖，分叉、汇合和跨列的直接依赖均可辨认；节点详情可查直接前置和后续，记录完成不会自动执行后续节点。
- **AND** 任务按依赖从左到右分层，放在满足前置后的最早一列；同列没有相互依赖，表示可并行处理，不表示自动开工或必须等待上一整列完成。

#### Scenario: 探索图
- **WHEN** 用户查看由 X 衍生 Z 的探索记录
- **THEN** 能辨认来源关系、负结果、保留或放弃的方向与显式选项，衍生线不被解释为必须完成的前置任务。

### Requirement: 图节点可按任一模式继续细分

#### Scenario: 两种模式嵌套
- **WHEN** 用户逐层打开计划节点里的探索，再打开方向里的验证计划
- **THEN** 每层展示对应关系、节点与面包屑，返回外层不丢结构。

### Requirement: 记录更新不等于执行或验收

#### Scenario: 更新状态、选项或结果
- **WHEN** 图记录被明确更新
- **THEN** 对应节点反映新内容，不自动改变无关节点、父目标或关联执行状态。
- **AND** 完成可继续修改，界面不将记录描述为已独立验收。
- **AND** 节点保留最近一次变更说明；从完成恢复进行中时必须附返工原因，可在详情查看，不形成历史版本系统。

### Requirement: 图数据持久且修改失败不会损坏已有结构

#### Scenario: 重读与正常重启
- **WHEN** 已保存图被刷新或在同一持久数据上重启服务后读取
- **THEN** 目标、层级、边、当前选项和结果保持一致。

#### Scenario: 不合法或过时的更新
- **WHEN** 修改会制造循环、错误跨层关系或覆盖更近的修改
- **THEN** 明确拒绝且不部分更新原图。

### Requirement: 任务图入口在桌面与手机保持可操作

#### Scenario: 空、加载、错误与已加载图
- **WHEN** 用户进入任务入口或节点详情
- **THEN** 能区分无任务、加载、失败、旧数据与当前记录，并能够重读和逐层导航。
- **AND** 手机不裁切关键操作，现有聊天与Agent入口不被替换。
