# im - Task Graphs Specification

> 对齐: feat-587
> 上级: [im Specification](spec.md)

## Purpose

约束真人和具备能力的 Agent 在所属会话内协作任务的访问边界、持久记录语义，以及 Web 与原生 iOS 的分层浏览和维护体验。

## Requirements

### Requirement: 计划依赖与探索衍生具有不同语义

#### Scenario: 计划图
- **WHEN** 用户查看计划式任务图
- **THEN** 连线表示前置依赖，分叉、汇合和跨列的直接依赖均可辨认；节点详情可查直接前置和后续，记录完成不会自动执行后续节点。
- **AND** 任务按依赖从左到右分层，放在满足前置后的最早一列；同列没有相互依赖，表示可并行处理，不表示自动开工或必须等待上一整列完成。

#### Scenario: 探索图
- **WHEN** 用户查看由 X 衍生 Z 的探索记录
- **THEN** 能辨认来源关系、负结果、保留或放弃的方向与显式选项，衍生线不被解释为必须完成的前置任务。

### Requirement: 图节点可按任一模式继续细分

#### Scenario: 两种模式嵌套
- **WHEN** 用户逐层打开计划节点里的探索，再打开方向里的验证计划
- **THEN** 每层展示对应关系、节点与面包屑，返回外层不丢结构。

### Requirement: 记录更新不等于执行或验收

#### Scenario: 更新状态、选项或结果
- **WHEN** 图记录被明确更新
- **THEN** 对应节点反映新内容，不自动改变无关节点、父目标或关联执行状态。
- **AND** 完成可继续修改，界面不将记录描述为已独立验收。
- **AND** 节点保留最近一次变更说明；从完成恢复进行中时必须附返工原因，可在详情查看，不形成历史版本系统。

### Requirement: 图数据持久且修改失败不会损坏已有结构

#### Scenario: 重读与正常重启
- **WHEN** 已保存图被刷新或在同一持久数据上重启服务后读取
- **THEN** 目标、层级、边、当前选项和结果保持一致。

#### Scenario: 不合法或过时的更新
- **WHEN** 修改会制造循环、错误跨层关系或覆盖更近的修改
- **THEN** 明确拒绝且不部分更新原图。

### Requirement: 任务图入口在桌面与手机保持可操作

#### Scenario: 空、加载、错误与已加载图
- **WHEN** 用户进入任务入口或节点详情
- **THEN** 能区分无任务、加载、失败、旧数据与当前记录，并能够重读和逐层导航。
- **AND** 手机不裁切关键操作，现有聊天与Agent入口不被替换。

### Requirement: 有效成员和具备能力的有效 Agent 共享公司任务

资源空间资格是访问前提，具体范围跟随固定所属会话；公司会话仍要求公司资格，私人会话要求本人的私人空间资格。原公司无差别共享规则由以下规则替代。

公开群及其任务对公司内有资格的人和 Agent 可读；私密群及其任务仅成员可读；私聊任务仅参与者可读。公开不等于互联网匿名公开。领取、修改等写操作仍要求所属会话写入资格。

#### Scenario: 公开可读、加入后操作

- **WHEN** 公司内有资格的人或 Agent 尚未加入公开 A 群
- **THEN** 可读取公开群及其任务，自行加入后才能领取、修改；仅查看不会自动加入。
- **AND** 任务读取按需发生，不把全量任务自动注入上下文；不由此取得其他 Agent 配置及本机资源权限。

#### Scenario: 私密群和私聊

- **WHEN** 非成员尝试读取私密群或非参与者尝试读取私聊任务
- **THEN** 不因同公司、知道任务链接、管理某 Agent 或拥有公司管理员身份就取得读取资格；私密群参与需邀请。

#### Scenario: 在另一群讨论公开任务

- **WHEN** A 群任务在 B 群被引用、讨论或由具备 A 群写入资格的主体更新
- **THEN** 两处打开同一任务，任务归属和可见范围仍由 A 群决定；不复制任务、不按最后讨论群改变归属，也不产生局部子树共享权限。

#### Scenario: 资格失效或借用身份
- **WHEN** 调用者无目标资源的空间权限，或调用公司 Agent 的管理者未获准公司资格、Agent 未注册、机器失效、工具未启用
- **THEN** 拒绝相应访问，不能通过模型自报身份、旧连接、已知链接或飞书 ownerOpenId 绕过调用主体检查；外部发言人不另行关联 IM 账号。

### Requirement: 公司任务可共同维护且删除须明确授权

#### Scenario: 所属会话成员共同维护
- **WHEN** 所属会话有写入资格的人或真实 Agent 创建、修改或明确删除任务
- **THEN** 可共同维护相同任务；真人可通过 Web 和原生 iOS 直接操作，Agent 使用工具。每节点保留真实创建者及独立负责人；不增加交办人角色、不伪造主体。删除仅允许目标创建者或已入群真人公司管理员，负责人身份不单独授予删除权。
- **AND** 来源聊天及受保护附件继续按对象权限投影，不能借变更信息泄漏其原文。

#### Scenario: 明确删除与冲突重试
- **WHEN** 用户明确指定删除范围或确认 Agent 说明的删除范围
- **THEN** 经 [Gateway 统一工具权限流程](../gateway/task-graphs.md) 获准后，仅删除相应图或子树，其他任务不变；旧链接明确不可用。
- **AND** IM 继续核实调用主体与资源访问资格，不通过用户消息的措辞或本轮消息是否存在再次裁决删除授权。
- **AND** 写操作保持原子 revision 检查，过时请求不覆盖更新，同一写入重试不重复执行或改写原来源，删除回执也可核实。

### Requirement: 群任务视图记录本群创建及编辑的节点

#### Scenario: 从任意群聊天进入本群任务
- **WHEN** 成员在某个群聊天点击“任务”
- **THEN** 展示当前群新建或编辑过的任务节点，在同时有权读取任务所属会话时打开同一张任务图，并能返回原群；切换到另一群时采用新群上下文，不固定示例群。
- **AND** 全局 Tasks 沿用原列表/图/详情入口，按固定所属会话限制可见范围；本群活动不变成全局页的固定群筛选，回聊继续保留草稿和引用、不自动发送。

#### Scenario: 跨群分解与协作
- **WHEN** 公开 A 群创建总目标及分解，已加入 A 群的主体从 B 群更新其中子任务
- **THEN** A/B 各自保留相应图与节点的活动入口，打开同一持久图，不复制任务或用最后编辑群覆盖前群关联。
- **AND** 群过滤只对有权查看该群者开放；任务本身仍要求源会话访问资格；源群收紧范围后，B 群入口不能泄漏任务摘要、数量或内容。

#### Scenario: 独立生命周期与最后更新聊天
- **WHEN** 成员退群或群被解散
- **THEN** 任务及 ID 保留，访问按固定所属会话当前范围判断；解散群按冻结的成员与可见范围提供历史只读入口，未完成关闭、已完成保持，不再接受写入。
- **WHEN** 节点从另一个聊天或无来源处被更新
- **THEN** 每节点的快捷回聊指向实际最后更新的有权访问聊天，无来源则留空；不覆盖其他节点的回聊位置，也不删除此前有效群活动关联。

#### Scenario: 保留原图浏览与讨论入口
- **WHEN** 成员打开任务深链或把节点交给另一 Agent 讨论
- **THEN** 既有层级图、面包屑、节点引用复制和回聊追加引用行为保持；保留聊天草稿，不自动发送；手机也可操作。

### Requirement: 每个拆分层级提供结构与完成情况视图

保留现有计划依赖图、探索衍生树及二者嵌套。在同一层级切换结构图与完成情况视图，共用任务和状态；完成情况展示当前层的直属子任务，按待办、进行中、待确认、已完成、已关闭五组呈现；暂缓任务并入待办组，卡片仍标明“暂缓”，不更改其状态。 全局 Tasks 首屏提供根任务总览，只按可访问根节点的自身状态分组；进入某个任务后再展示其直属子任务。总览与各层使用有明确外框、列头和计数的五个状态分组，手机以对应纵向分组呈现。

#### Scenario: 比较根任务并进入下一层

- **WHEN** 用户打开全局 Tasks
- **THEN** 默认看到根任务总览，所有可访问根任务按自身状态分组，不自动选中第一棵任务树，也不混入深层任务。
- **AND** 卡片可打开详情，并通过独立子任务入口进入下一层；面包屑可回总览或任一祖先。
- **AND** 根任务及子任务的直属完成数量单独标明，不作为工作量百分比、不改变父任务自身状态；打开/关闭详情不挤窄看板或丢失当前浏览位置。


#### Scenario: Web 五列独立自然加载

- **WHEN** 总览或负责人结果中各状态数量悬殊，用户滚动其中一列
- **THEN** 每列从自己的完整匹配结果读取首批任务，滚动接近本列底部自动追加后续任务；没有整页上一页／下一页，不要求先翻完待办才能看到已完成。
- **AND** 列头显示该状态组的真实总数，待办包含暂缓；加载、失败重试及到底反馈只影响该列，已有卡片与其他列的位置保持。
- **AND** 搜索或负责人变化同时重置五列；窄屏 Web 各状态组有有界滚动区，长待办不会无限推远后面的组。任务内已取得完整图的直属层不新增服务端分页。

#### Scenario: 查看大任务并逐层进入

- **WHEN** 用户进入大任务或其中一个可拆分节点并切换视图
- **THEN** 当前层的直属子任务按状态呈现，深层后代不会混入本层看板；可进入下一层并通过面包屑返回。
- **AND** 节点展示自身状态及直属子任务状态数量摘要，摘要标明范围，不显示未经定义的工作量完成百分比。

#### Scenario: 探索与计划嵌套

- **WHEN** 用户在探索方向及其验证计划间导航
- **THEN** 仍能辨认当前选择、方向结果和相应结构关系；关闭的方向不计为成功完成，未选方向不自动变成必做工作。

### Requirement: 每个节点独立记录创建者与负责人

实际创建任务的人或 Agent 是创建者；负责人可以是人或 Agent，和创建者独立。新建子任务默认未分配，可在创建时指定，不继承父负责人。不新增交办人权限角色。

#### Scenario: 同一任务树由不同主体负责

- **WHEN** Agent A 创建父任务并把两个子任务分别分给 Agent B 和小王
- **THEN** 各节点显示各自创建者、负责人；未指定的子任务仍未分配，父负责人不被自动复制到后代。

#### Scenario: 经 Agent 创建及后续改派

- **WHEN** 小王让 A 创建任务，再将其负责人从 B 改为 C
- **THEN** 创建者仍为实际创建者 A，负责人变为 C；任务不会因真人交办、改派或最近修改者变化而改写创建者。

### Requirement: 人与 Agent 在相同权限原则下维护任务

Web、原生 iOS 提供创建大任务／当前层子任务、领取、调整负责人、编辑标题／描述／结果／状态和有权限删除等基础操作。Agent 工具提供对应能力，按实际调用主体鉴权。有所属会话写入资格的成员可共同维护，负责人不独占编辑。

#### Scenario: 人直接操作及成员共同维护

- **WHEN** 小王直接创建任务，或群内有写入资格的成员修改他人负责的任务
- **THEN** 操作按对应主体记账并反映到同一份任务；人直接创建记小王为创建者，修改者可辨认；不要求通过 Agent 才能完成基础操作。

#### Scenario: 先入群再分配

- **WHEN** 为任务选择负责人
- **THEN** 只能选择任务所属会话中的人或 Agent；非成员需先按群规则加入，分配操作不会自动拉人入群。

#### Scenario: 分配与领取分离

- **WHEN** 任务被分配或改派给某负责人
- **THEN** 分配本身不代表该负责人已经开工，也不把通知投递当作进行中；领取才表示接手开始推进。
- **AND** 其他主体不能通过领取直接抢占已有负责人任务，转交通过明确改派完成。

### Requirement: 删除采用独立权限并包含所选节点整个子树

任务创建者或公司管理员可删除，仍须满足所属会话访问与写入条件。负责人身份本身不授予删除权。删除是真正移除记录，与关闭保留记录不同。

#### Scenario: 删除父任务

- **WHEN** 有删除资格的主体明确删除一个父任务
- **THEN** 删除范围包含该节点及整个下属子树，包括其他主体创建或负责的后代，界面／工具清楚呈现范围，不逐个请求子任务创建者审批。
- **AND** 沿用既有明确范围的删除授权及工具权限流程；范围已明确时不额外要求重复确认，不将笼统整理或普通状态更新当作删除授权。

#### Scenario: 只有编辑权或只有管理员身份

- **WHEN** 非创建者普通成员尝试删除，或公司管理员尝试删除其无访问／写入资格的会话任务
- **THEN** 删除被拒绝，任务及子树保持；管理员名下的 Agent 不自动继承管理员角色。

### Requirement: 六种状态表达进展，验收采用引导而非强制门禁

状态为待办、进行中、待确认、已完成、暂缓、已关闭。Agent 引导采用做完先提交待确认供人验证、确认后完成；系统仍允许直接完成，不增加必经审批、专属验收人或第三种任务权限角色。

#### Scenario: 提交结果

- **WHEN** Agent 完成工作并按协作引导提交结果
- **THEN** 可以标为待确认，展示结果并等待反馈；有资格的成员可调整状态，系统不强制每次完成都经过真人审批。

#### Scenario: 普通父子状态变化

- **WHEN** 子任务全部完成，或父任务被暂缓、关闭、重新打开
- **THEN** 未明确指定的其他节点状态保持，父任务不会因子任务完成自动完成；状态变化不直接启动或停止 Agent 执行。
- **AND** 显式调整整个子树时保留已完成节点的完成事实；普通父状态变化不等于整棵子树状态操作。

### Requirement: 任务协作通知使用所属会话的一条系统消息

不引入任务专属讨论区、关注名单、重复私信或额外交接回执。群内系统消息对全体成员可见，以下 @ 为系统识别的有效成员提及，不只是普通名字文本。

| 事件 | 同一条系统消息中的 @ 对象 |
|---|---|
| 首次分配 | 新负责人 |
| 改派 | 原负责人和新负责人 |
| 取消分配 | 原负责人 |
| 父任务暂缓／关闭 | 直属下一层子任务已分配的 Agent |
| 任务进入待确认／已完成 | 本任务创建者及直属父任务负责人（若有） |

同一主体在一条消息中只需提及一次；根任务没有父负责人，结果通知只提醒创建者。消息说明发生变化的任务及变化内容，能回到原任务查看结果和上下文。接收资格沿用会话成员规则，不为通知授予额外访问权限。

#### Scenario: 改派双方获知

- **WHEN** 小王把「修复登录失败」从 A 改派给 B
- **THEN** 所属群出现一条类似“小王将「修复登录失败」从 @A 改派给了 @B”的系统消息，其他成员也可看见，不另发一轮通知。

#### Scenario: 暂缓／关闭逐层传达

- **GIVEN** 任务有 A → B → C 三层
- **WHEN** A 暂缓或关闭
- **THEN** 所属会话的一条系统消息 @ B 层已分配的 Agent，不跨层主动 @ C；只有 B 的实际处理形成相应变更时，才按同一规则继续通知下一层。
- **AND** 不自动修改 B／C 状态，不终止被通知 Agent 的其他无关工作。

#### Scenario: 结果向上反馈

- **WHEN** 子任务进入待确认或已完成
- **THEN** 一条系统消息 @ 该任务创建者及直属父任务负责人；他们能查看结果并继续协调，但不因此成为系统强制验收角色，也不自动修改父状态。

### Requirement: 负责人视图跨层汇总其直接负责的任务

#### Scenario: 一人负责多棵树的深层节点

- **WHEN** 用户在全局任务入口按某个人或 Agent 筛选负责人
- **THEN** 汇总所有可访问任务树、所有层级中该主体直接负责的节点，显示所属会话与父级路径，点击返回原节点所在层级。
- **AND** 父子同属该负责人时都可出现；不会将他负责的父节点全部后代都当作他的任务。此视图不改变每层完成情况仅展示直属子任务的规则。

### Requirement: 任务与协作系统消息保存成功后重试不重复交办

#### Scenario: 保存失败、通知离线与重复提交
- **WHEN** 任务写入失败，或写入成功后接收 Agent 离线，或调用方以相同请求重试
- **THEN** 写入失败不留下对应通知；成功则任务和一条对应系统消息持久保留，离线不把已保存任务报告为失败，重试不再生成同一通知。
- **AND** 后续实际处理沿用 [群接收与投递契约](../gateway/routing-delivery.md)，通知已保存不等于 Agent 已开工。

### Requirement: 原生任务流程保持统一的信息与编辑体验

iOS 任务总览、逐层浏览、详情和创建/编辑 SHALL 以任务正文、状态和负责人为主要信息，身份审计与危险操作为次级；编辑字段 SHALL 有持续标签和随内容增长的输入区。状态和负责人 SHALL 使用具名、可关闭、带选中反馈的选择面板，负责人可搜索并区分真人与 Agent。选择仅修改草稿，保存必须明确提交。

#### Scenario: 查看、编辑与离开
- **WHEN** 用户查看任务后编辑内容、选择状态或负责人并离开
- **THEN** 未提交修改不会自动保存；有修改时取消应可选择继续编辑或明确放弃，防止滑动关闭丢失草稿；保存成功回到更新后的详情。
- **AND** 保持所属会话成员资格、六状态、层级、领取、删除、结果和通知契约，长内容/大字体仍可操作。

#### Scenario: 原生逐字段处理并发修改
- **WHEN** 原生编辑保存因 revision 过期失败，用户读取最新内容
- **THEN** 保留本地修改；远端独有修改纳入待保存稿，同字段不同修改具名比较并要求用户选择我的或最新；必须明确确认后才以最新 revision 保存。
- **AND** 再次冲突仍保留草稿重新比较，删除或失去权限不得覆盖或重建任务；新建子任务冲突保留输入，刷新父图后明确重试。

### Requirement: 会话任务继承固定资源空间边界

任务的固定所属会话同时决定其私人/公司资源空间；个人账号无需公司审批即可在自己的私人会话中保存、查看和维护任务。加入公司不发布原私人任务，停用公司资格不阻断仍有效的私人空间。公司公开群的读取与入群后写入仅在公司资格有效时可用。Agent 仍受自己的固定资源空间约束，不能借 owner 加入公司而跨空间操作。

#### Scenario: 私人任务与公司协作共存
- WHEN 用户保存私人会话任务后加入公司、再退出或停用公司资格
- THEN 原私人会话和任务的成员范围不变，公司成员与管理员不能因此读取；公司任务仍按公司资格和所属会话权限判定。
