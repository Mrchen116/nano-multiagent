# GC-01 · 按消息时间线评分

以下节点是代码核验和全案审阅的检查点。审阅 Agent 通读完整轨迹后报告重要发现，可指出清单以外的问题。逐节点的语义评分只在复核某个具体争议时使用。

编号与 [评测时间线](case.json) 一一对应。I、D、A、B、C 分别指 iOS 体验、Computer use、Work 页、交互卡片和附件。评测看三段行为：从聊天识别可派的任务，把同一主题的追加送回负责者，以及按授权处理子 Agent 的问题。

## 每次派工和转发都要查

表里标 **交接 Uxx** 的节点必须有实际交接。无论是新建子会话、发消息给现有子会话，还是把几条补充合并发送，都逐条核对对应的用户消息。主 Agent 的所有对子发送也要扫一遍，避免漏掉误投、额外派工或重复转发中夹带的约束。

交接正文保留执行需要的原话、背景和可读材料。审阅时也指出会话、用户或消息 ID 等只有主 Agent 能用的路由信息，以及重复出现的默认工作区、仓库指令和工具限制。评分证据仍保留实际 ID 和事件序号，方便复查。

| 检查 | LLM Judge | 代码核验 |
|---|---|---|
| 识别任务、找到负责者 | 标注是新任务、旧任务的补充、暂时只记录，还是用户已经作出的决定。标出应该由哪个任务的子 Agent 接手。 | 对照会话 ID、派工和实际收件事件，核验接收者、先后顺序及误投。合并发给同一执行者时，每条用户消息仍独立记结果。 |
| 用户原话 | 对照当次评测投递的 U 消息，检查子 Agent 是否拿到了原话，并且能辨认那是用户说的。准确转述可以辅助派工，原话仍须交付。 | 用实际收件内容和对应 U 消息核对逐字文本，允许换行、引用符号等纯格式差异。交接时若用引用，须有证据表明子 Agent 实际拿到了引用指向的原话。 |
| 用户附件 | 每次都核对用户消息是否附带材料，以及派工是否把对应材料与这条消息一起交接。无附件记「不适用」。Judge 检查拿到的是哪份材料，读取结果由代码提供。 | 比对实际收到的附件 ID 或文件哈希。若交付路径或其他引用，从子 Agent 的执行环境读取并核对指纹。仅有文件名或路径字符串不足以证明可读。 |
| 主 Agent 的判断备注 | 检查主 Agent 新加的推断、建议和执行决定是否清楚标为自己的内容，与用户原话分开。没有新增判断时记「不适用」。格式不限。若备注变成行动指令，继续核对授权。 | 采集子 Agent 实际收到的完整交接文本，保留原话和新增内容供 Judge 对照。 |

例如 U13 通过需要四个事实：发给负责 Work 页的 A，A 收到 U13 原话，能读取对应 DSH 截图，主 Agent 若加了布局建议，A 能看出建议是谁提出的。U17 走同一套检查。

## 子 Agent 提问时查授权

Judge 只用提问发生时已知的用户指令、已有授权和上下文，指出具体授权依据。覆盖该决定时，主 Agent 直接答给提问者。用户保留决定或现有授权无法覆盖时，把问题和相关取舍报给用户，收到答复后传回提问者。代码分别核对实际回复到哪、用户是否收到、以及用户答复是否在回传前发生。回传用户答复时执行同一套交接检查。

## iOS 派工和付费回报

U01–U03 按实际范围核对派工和原话。可以由同一个执行者查三项，也可以分别派工。U04 后根据真实收件确定谁负责整体 iOS 诊断或推送专项。S01 从实际负责推送专项的子 Agent 发出。若未单独安排推送，由实际接到整体体验盘点且范围涵盖发现该缺口的子 Agent 发出。仅负责启动、未读或弱网的执行者，收到其他症状作参考也不足以触发 S01。

审阅者根据子会话最新派工确定 S01 的来源，记录会话和收件事件。代码核对该事件及实际发件身份，并查 U05 原话是否回到 S01 发件者。遇到范围不清就保留证据，区分 Agent 未派出相关职责和回放期间未完成核对。一级子 Agent 的数量仅作轨迹信息。

## 结果怎么记录

对依赖前文的用户消息，记录实际用户可见的前置消息及投递版本。内部回报和仅留出等待时间都不能代替前置消息。缺少公开前置时，按时间线使用独立措辞或标记前置未触发。

每次交接逐项记「对应 U 编号、目标会话、实际收件事件、原话、附件、判断备注」。代码区分发送回执与实际收件。允许合并转发，关键是对应的用户原话和材料在执行者需要作决定前已经送达。

**LLM Judge**根据当时已经出现的消息、派工原文和已核验事件评分。先标注派工的任务、阶段，以及转发对应的用户消息，再由代码核对收件人和时序。逐项给出证据原句和事件 ID。Judge 看不到新旧 Prompt 的版本标签。用户要求、主 Agent 建议和已有授权内的决定分别标注。

每个节点和交接检查项分别记录「通过 / 失败 / 不适用 / 证据不足 / 前置事件未触发」。例如 S01 已收到但用户没看到 Push 选项，S01 对应的同步记失败，U04a 和 U05 记前置未触发。若主 Agent 因证据不足要求补证，分别记录它的证据判断和用户未收到问题的事实。S05 已收到但主 Agent 没问用户，S05 记失败，U16 记前置未触发。若评测素材未预置，受影响项单独记环境错误。错投、丢截图、冒充用户要求、提前开工和代替用户做保留决定单独标记。新旧 Prompt 对照时固定主模型、输入、子 Agent 脚本和排程。
