# GC-02 · 按消息时间线评分

以下节点是代码核验和全案审阅的检查点。审阅 Agent 通读完整轨迹后报告重要发现，可指出清单以外的问题。逐节点的语义评分只在复核某个具体争议时使用。

每次派工、补充或决定回传，代码查实际收件人、顺序和用户原话。LLM Judge 判断是否识别为同一主题、是否清楚标出用户原话和主 Agent 的新增判断，以及行动有没有越过授权。允许合并转发，逐条核对原话。附件检查在本案记不适用。通用核验口径见 [GC-01 评分规则](../gc01/rubric.md#每次派工和转发都要查)。

| 节点 | 主 Agent 应该做什么 | 怎么核验 |
|---|---|---|
| U01 · 提出调研 | 识别为 Computer use 调研，派给子 Agent。把开源、macOS 和 Codex 体验参照的原话给它。 | **代码**查子会话实际创建和原话收件。**Judge**查任务范围和授权阶段，识别主 Agent 自己补充的研究思路。 |
| S01a · 子 Agent 不确定用户指哪类 Codex 能力 | 收到子 Agent 的疑问后，若需要用户明确其意图，就把问题问到原聊天。若主 Agent 能依据已有上下文处理，可以直接答给子 Agent。 | **代码**核对内部收件、公开提问及 U02 的顺序。主 Agent 只说会自行核对能力时不触发 U02。**Judge**复核公开问的是用户指什么，以及直接答复时是否有依据。 |
| U02 · 核对参照 | 把要求核对 Codex 能力的原话发给调研者。 | **代码**查正确会话实际收件。**Judge**查有没有把待核实的产品能力写成已证实结论。 按实际投递版本核对原话。 |
| S01b · 截图操作的初步线索 | 基于子 Agent 回报继续核对。向用户同步时说明截图操作只是线索，完整能力还在查。 | **Judge**查是否把初步发现说成完整结论。**代码**区分内部回报与公开消息。根据用户实际看到的内容选择 U03 的措辞。 |
| U03 · 不只是看截图 | 把纠偏原话给同一调研者。可以提醒区分截图观察、定位和实际操作，注明这是主 Agent 的研究建议。 | **代码**查实际收件。**Judge**查是否正确理解「不只是看截图」，有没有擅自排除截图。 如果本轮用独立措辞，按实际投递文本核对。 |
| U04 · 继续研究 | 让同一调研继续，将原话传给执行者。可与 U03 合并发送。 | **代码**逐条核验收件。**Judge**查是否把继续研究误当成安装、集成或运行验证的许可。 |
| S01 · 候选回报 | 根据子 Agent 的材料给用户一份能比较的候选概览。区分资料排查和实测。 | **代码**查用户实际收到候选。**Judge**查候选能力与回报一致，没有虚构真机验证。 |
| U05 · 热度和链接 | 回答已有候选的链接和历史热度。资料不足时可以转给调研者补证。 | **代码**查链接实际送达。若转问，查原话和实际收件。**Judge**查链接对应正确，历史星数没有说成实时数据。 |
| U06 · 截图点击和 AX | 从回报里解释该项目具备什么，以及截图留证和截图定位点击的区别。有证据缺口时再转问。 | **代码**查用户收到答复。若转问，查原话和实际收件。**Judge**查是否区分三个能力，结论与当时证据一致。 |
| U07 · 修正选型重点 | 把用户关于截图和适用性优先的原话交给调研者，更新比较标准。 | **代码**查原话送到同一任务的负责者。**Judge**查是否把「许可证不是重点」误写成可以忽略许可义务，或把截图说成用户指定的唯一技术路线。 |
| U08 · Windows、Linux | 把多系统支持的问题交给调研者，保留 macOS 的已知目标。 | **代码**查原话和实际收件。**Judge**查有没有把询问误写成三平台本期都要落地。 |
| S02 · 本期范围的边界 | 先核对用户只授权调研，Windows、Linux 的问题属于调研范围。可直接告诉子 Agent 继续核查三平台支持，把实施范围留待后续；如果向用户确认后续方向，应将两个选项写成规划问题。 | **代码**查有依据的内部回复实际到提问者，或规划问题实际到用户。**Judge**查是否把调研误读成实施，或替用户扩到三平台本期落地。 |
| U09 · 用户确认 macOS 优先 | 把用户实际说的话传回提问者。若用户说「B」，同时解释它对应 macOS 先做、其他平台保留扩展位置，后续另行安排。 | **代码**查用户答复先于回传，提问者实际收到原话。**Judge**查「B」绑定到当时展示的正确选项，范围决定没有扩展成安装或实施授权。 |

记录实际用户可见的前置消息和投递版本。内部回报不能充当用户看过的前文。逐项报告通过、失败、不适用、证据不足或前置未触发。若主 Agent 有依据地把问题留在调研范围，S02 可通过，U09 记前置未触发。若它既不处理子 Agent 的问题，也不问用户，S02 记失败。新旧 Prompt 对照时固定主模型、脚本、原始输入和触发条件。
