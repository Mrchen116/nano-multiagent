# Intelligent UI case 集

本版先建立可复用 case，复用[公共评测页面](../ui/README.md)查看输入、参考图、操作步骤和判定标准。不新增正式运行器、模型裁判或自动优化；页面不会发起模型调用。候选模型生成源码、页面成功渲染、实际操作成功和人工视觉通过是不同证据。

| Case | 输入 | 主要检查 |
|---|---|---|
| hotel | 用户酒店参考图、明确标注的演示照片 URL | 酒店卡片、按钮、照片拼贴、收藏/照片操作及窄屏阅读 |
| dashboard | 用户看板参考图 | KPI、散点、居中示意漏斗、筛选/阶段数值及窄屏阅读 |
| meeting-confirmation | 固定的演示会议选择请求 | 编辑不自动发消息；确认携带最新选择；Agent 实际收到并回复 |
| ad-analysis | 预置于全新Agent工作区的固定CSV与自然分析请求，无呈现提示 | 是否主动调用UI（客观二元）；实际UI呈现质量（人工主观） |

`dataset.json` 是版本 4 的固定输入与判定材料，`assets/` 是固定输入资产（参考图与CSV），不是运行截图缓存。酒店与看板图片来自本次用户提供的界面参考；广告分析CSV是固定合成演示数据，含两周、三个地区、两个渠道共12行，不含联系人、聊天或账号内容。照片素材为替代演示 URL，不声称对应真实酒店，远端返回可能变化；本版不评估图片搜索质量。

当前保持四个 case，不为每个场景扩充显式/隐式配对。酒店、看板检查明确使用能力时的视觉和绘图；广告分析检查没有UI、图表或交互提示时是否主动调用能力，以及实际界面好不好看、好不好读。会议保留为简短的真实消息回路检查。

版本 3 用 ad-analysis 替换版本 2 的 activity-budget；版本 4 将CSV改为预置到全新Agent工作区，不经聊天附件链路，总数仍为四个；原三个 case 输入和判定不变，试算材料保留在Git历史，不进入当前全量集。不同版本的第四题结果不混作同一基线。

## 每个 case 从零开始

每次运行、每个 case 都应分配全新 IM 数据、测试身份、聊天、Agent workspace、DSH home 和活动 session；开始前核对消息数为零。仅仅隐藏聊天或新开 Web 标签不满足要求。不复制前次 Memory、Skill 产物、Inbox 或恢复笔记。

只发送该 case 的固定初始输入。酒店、看板不追加“改小间距”“改漏斗”等纠错提示；保留首次生成及工具失败记录。会议确认允许操作步骤内那一次真实确认及 Agent 后续回复，因为这就是被测旅程。改变 prompt、照片输入、判定规则或交互步骤应更新 dataset version，不能把新旧结果混作同一基线。

## 判定边界

- 视觉检查必须打开实际页面对照原图，分别查看桌面和手机。无页面溢出不代表文字可读。
- 收藏、图片、筛选等本地操作不应意外产生公开消息或业务动作。
- 会议选择固定为周四下午3点、60分钟、备注“带上预算草案”。确认前公开用户消息应仍只有初始请求；确认后核对真实消息内最新 state/fields，以及随后 Agent 的公开回复。禁止以按钮回调或 HTTP 成功代替实际交付证据。
- 广告分析将 `assets/ad-regional-funnel.csv` 按原文件名复制到全新Agent工作区根目录并核对字节一致，然后只发送固定自然任务，不上传聊天附件，不附看板参考图、不追加呈现提示。CSV各行按周、地区和渠道给出曝光、点击、落地页访问、留资、成交及花费；只需本地文件，不把附件下载能力混入UI主动性评测。
- 广告分析只评两个维度：① 本case实际 `send_message` / `send_user_message` 调用是否携带非空字符串 `interactive.source`，二元是/否；只加载Skill、写代码或普通消息不算；② 人工评价实际UI的视觉呈现。调用失败仍算调用，呈现失败单独记录；没有调用时视觉项未适用，未执行或轨迹缺失记未判定。分析、计算、业务归因正确性均不评分，不额外调用裁判模型。
- 图片不可用、模型不可用、候选生成错误、未执行、未判定分别记录。没有人工检查的视觉项不判通过。
- 这是公开回归 case 集，不是未知题盲测。判定和操作控制材料不应进入候选 prompt；只传固定 prompt、适用的参考图、照片素材或按 `workspaceFiles` 预置的工作区文件，不传本页面的操作步骤和判据。
