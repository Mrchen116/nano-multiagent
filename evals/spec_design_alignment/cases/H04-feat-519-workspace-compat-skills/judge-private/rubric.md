# H04 private rubric — workspace-compatible Skills

Keep this directory out of candidate exports. Historical answers are semantic oracles, not instructions to reproduce exact classes, fields, component names or test files.

## 1. Decision handling and user burden

D01-D03 are material product forks and should be surfaced together as a compact review package. D05 delegates interaction detail to design: a strong arm proposes a grounded inline control and asks for review, not a blank preference question. D04 and D06 are intentionally marked P because the owner regarded missing optional directories and speculative rolling compatibility as matters the Agent should resolve from current behavior and scope. Asking either serially is negative burden. D07-D10 are repository facts and must be self-resolved with evidence.

## 2. Spec oracle

A strong spec:

- covers PA/IM and Coding CLI with the exact requested compatible workspace/global roots while retaining native sources;
- defines deterministic same-name precedence and one winner across list, preview, runtime and tools;
- distinguishes default discovery from explicit saved selection so a new Skill cannot silently expand an existing Agent;
- makes group selection compact, stateful and compatible with individual selection on desktop and mobile;
- treats absent/empty optional roots as normal and rejects speculative protocol-version scope;
- preserves existing chats, next-response activation and package boundaries.

Omitting one product, changing saved capability silently, or leaving same-name resolution inconsistent is critical. A visually vague but behaviorally bounded group control is a design weakness, not automatic spec failure.

## 3. Design oracle

Judge the proof across the full path: product composition → public SDK → shared resolver/registry → capability projection → IM persistence and selector → session runtime. The design must preserve omitted/default/explicit-nonempty/explicit-empty states through every configuration writer, not only the main form. Node capability discovery must not accidentally treat the repository root as an Agent workspace. Delta specs must preserve unchanged canonical scenarios.

Equivalent designs pass if they establish one ordered-root authority and one durable selection-state authority. Penalize duplicated frontend discovery, product imports of kernel internals, two competing precedence implementations, or compatibility machinery unsupported by current deployment.

## 4. Hidden downstream probes

Probe both products with collisions across all roots, missing roots, invalid entries, saved explicit empty/nonempty/default modes, hidden Agent writers, list/preview/runtime consistency, create/detail UI group selection, narrow layout and next-response behavior. Import contracts and canonical delta mergeability remain mandatory.

## 5. Verdict

Report decision handling, user burden, spec, design, downstream feasibility and cost separately. Do not award historical-symbol matching; award semantic closure grounded in the cutoff repository.
