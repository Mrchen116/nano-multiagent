# feat-515: Agent Workspace Root Selection

## 原始需求

> [http://100.88.34.122:8011/settings/agents/new](http://100.88.34.122:8011/settings/agents/new) 不能选择workspace root的位置，我希望加上

## 澄清记录

- Q1: 你希望怎么选 workspace root？
  A(原话): 使用默认目录 / 自定义路径，需要有这两个功能，但是怎么设计，这是你后面做设计的问题。
  Agent 解读: 创建 Agent 时提供默认目录与自定义路径两种用户可选模式；实现交由设计阶段决定。
- Q2: 这期只在“新建 Agent”页提供选择，还是也允许编辑已有 Agent 的 workspace root？
  A(原话): 不支持编辑已有，以后也不会支持。因为Workspace固定之后，就会有一些东西沉淀在里面，改变这个会有很多问题。
  Agent 解读: workspace root 仅在创建时确定；已有 Agent 永久不提供编辑或迁移入口，以保护工作区中的沉淀内容。
- Q3: 自定义路径若已经存在，也允许把它直接作为 workspace root 吗？
  A(原话): 倒是可以校验一下父级目录。父级目录应该是存在的。
  Agent 解读: 自定义 workspace root 可在创建时新建，但其父目录必须存在；创建时需校验父目录可用，并在不可用时明确失败。
- Q4: 如果自定义路径本身已经存在（例如已有项目目录），允许直接把它作为该 Agent 的 workspace root 吗？
  A(原话): 允许，但是我觉得应该要给用户一个提醒。要提醒提醒他，这是一个已有目录。
  Agent 解读: 已有目录可以被采用为 workspace root；创建前必须向用户清晰提示目标目录已存在。
- Q5: 同一个 workspace root 能否被多个 Agent 选择？
  A(原话): 应该不能吧
  Agent 解读: 同一个 workspace root 只能绑定一个 Agent，避免记忆、会话和运行状态混杂。
- Q6: 这个“一目录一 Agent”的限制，是否只在同一个节点内生效？
  A(原话): 那肯定是啊，这么无脑的问题。
  Agent 解读: 唯一性按所属节点的文件系统边界校验；不同节点上同字符串路径互不冲突。
- Q7: 第一版把默认目录和自定义路径做成两个并排的大选项卡，是否符合创建页体验？
  A(原话): 这个设计太丑了。丑到没边了，完全是一个Demo级别的设计，只考虑了功能，没有考虑整个用户体验。
  Agent 解读: 不能为了暴露两个功能而让 Workspace 选择抢占页面主层级；创建页需要保持克制、连续，默认行为不应要求用户先理解“模式”。
- Q8: 将两个大选项卡压缩成紧凑的二选一控件是否可以？
  A(原话): 你真正要做到很克制，又能够把这个功能做好呀。你这么雷霆的搞两个大按钮，是个傻逼设计。
  Agent 解读: 问题不只是控件尺寸，而是交互模型本身；不能继续用显式“默认 / 自定义”选择器，只缩小视觉体积。
- Q9: 创建页应该怎样呈现默认和自定义路径？
  A(原话): 还是很丑很丑很丑。我给个建议，你就显示一个默认路径，用户想改呢，能直接点，然后改不就完了吗？
  Agent 解读: 初态直接显示所选 Gateway 按 Agent ID 解析出的真实默认路径；整行可点击修改，点击后原地切换为自定义路径输入，不出现模式选择器。
- Q10: 用户点击修改后，自定义路径输入框的初始值是什么？
  A(原话): 当他要编辑的时候，就不能预填一下他原本的路径吗？因为用户可能就是想在默认路径做一些修改而已。
  Agent 解读: 编辑态预填刚才显示的默认路径并自动聚焦，让用户可以只改父目录或末段，而不是从空输入框重新输入完整路径。

## 用户场景

用户在“新建 Agent”页选择一个在线节点并填写 Agent ID。Workspace 区默认直接显示该节点为这个
Agent 解析出的真实默认路径，不要求用户先做模式选择。若用户想改变位置，点击这一行即可原地
进入编辑态；输入框预填当前默认路径并自动聚焦，用户可以只修改其中一段。目标目录可以尚未存在，
但它的父目录必须已经存在且可用。

当用户把一个已有项目目录交给 Agent 时，创建页不会把它当成空目录：在真正创建前会显著提醒
它已经存在。用户确认后，Agent 可以使用该目录；同一节点的其他 Agent 不能再采用该目录。创建
完成后，workspace root 是该 Agent 的长期归属，设置页不会提供编辑或迁移功能，以免割裂该目录
中持续沉淀的内容。

## 验收标准

### Requirement: 创建 Agent 时默认展示节点路径，并可原地修改

#### Scenario: 不修改默认路径直接创建 Agent
- **GIVEN** 用户已填写 Agent ID，页面显示所选节点解析出的真实默认路径
- **WHEN** 用户不点击修改并完成创建
- **THEN** Agent 创建成功，并显示节点分配的 workspace root

#### Scenario: 基于默认路径修改为自定义路径
- **GIVEN** Workspace 区正在显示所选节点解析出的默认路径 P
- **WHEN** 用户点击该路径或“修改”
- **THEN** 原地显示自动聚焦的自定义路径输入框，且初始值为 P

#### Scenario: 使用修改后的路径创建新的 workspace
- **GIVEN** 用户选定节点上的目标路径 P 尚不存在，且 P 的父目录存在并可用
- **WHEN** 用户把预填路径修改为 P 并完成创建
- **THEN** Agent 创建成功，workspace root 为 P

#### Scenario: 自定义路径的父目录不可用
- **WHEN** 用户选择自定义路径，但其父目录不存在或不可用
- **THEN** 创建不成功，页面在路径处明确说明原因

### Requirement: 采用已有目录前须提醒用户

#### Scenario: 自定义路径是已有目录
- **GIVEN** 用户选择的自定义路径已经存在
- **WHEN** 用户准备创建 Agent
- **THEN** 页面在创建前明确提醒该路径是已有目录，用户确认后才能继续创建

### Requirement: 同节点 workspace root 只可归属一个 Agent

#### Scenario: 同一节点的路径已被另一个 Agent 使用
- **GIVEN** 节点 N 上的 Agent A 已使用 workspace root P
- **WHEN** 用户尝试在节点 N 上创建 Agent B 并选择 P
- **THEN** 创建不成功，页面明确说明该目录已经归属 Agent A

#### Scenario: 不同节点的同字符串路径
- **GIVEN** 节点 N1 上的 Agent A 使用路径 P
- **WHEN** 用户在另一节点 N2 上创建 Agent B 并选择同字符串路径 P
- **THEN** 路径不会因 Agent A 而被判定为冲突

### Requirement: 创建后 workspace root 固定

#### Scenario: 查看已有 Agent 的设置
- **GIVEN** Agent 已创建并拥有 workspace root P
- **WHEN** 用户打开该 Agent 的设置页
- **THEN** 用户可以看到 P，但没有修改或迁移 workspace root 的操作

## 范围与非目标

- 在范围：在新建 Agent 页展示节点默认路径并允许原地修改；为修改后的路径校验父目录、提示已有
  目录并防止同节点的目录重复归属。
- 非目标：编辑、迁移或重新分配已有 Agent 的 workspace root；让多个同节点 Agent 共用一个
  workspace root。
