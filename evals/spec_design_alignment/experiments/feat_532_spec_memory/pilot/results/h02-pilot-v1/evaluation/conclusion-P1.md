# feat-507: 统一工具调用审批模型

## 用户场景

个人助手运维者已在 Gateway 本地运行配置中维护 LLM provider 与模型目录，各 Agent 可以按用途选择不同的运行模型。现在，某个工具调用进入自动审批分类时，分类请求会复用该轮的运行模型，使审批的成本、延迟和稳定性随 Agent 选模型而变。

运维者需要在现有 Gateway 配置与模型目录中显式选定一个审批模型。Gateway 重新启动后，个人助手中任意 Agent、任意会话或触发来源只要进入自动工具审批分类，都使用这个选定模型。各 Agent 的普通对话、工具执行完成后的后续回复，以及不需要模型分类的固定权限规则，仍保持原有行为。

如果运维者没有选定审批模型，系统不自动改用产品默认模型，而是继续让每次审批分类复用触发它的运行模型。如果选定了模型但它不在当前个人助手模型目录中，Gateway 在启动时明确指出配置错误，不以其他模型静默代替。

## 验收标准

### Requirement: 个人助手可显式统一自动工具审批分类模型

#### Scenario: 不同 Agent 的审批分类使用同一选定模型
- **GIVEN** 个人助手的模型目录包含模型 C，Gateway 配置已显式将 C 选为审批模型，Agent A 与 Agent B 分别使用其他运行模型
- **WHEN** A 与 B 的工具调用分别进入自动审批分类
- **THEN** 两次审批分类都使用 C

#### Scenario: 不同个人助手触发来源使用同一选定模型
- **GIVEN** Gateway 配置已显式选定审批模型 C
- **WHEN** Web IM、外部通道或无人值守任务触发的工具调用进入自动审批分类
- **THEN** 对应的审批分类使用 C，不随触发它的 Agent 运行模型变化

### Requirement: 审批专用选择不改变 Agent 运行模型

#### Scenario: 普通对话与工具后续接保持运行模型
- **GIVEN** Agent A 的当前一轮使用模型 A，Gateway 选定的审批模型是 C
- **WHEN** 该轮发生自动工具审批分类、执行工具并继续回复
- **THEN** 只有审批分类使用 C，审批前的普通对话与工具后的续接仍使用 A

#### Scenario: 不调用模型的权限路径保持现有行为
- **GIVEN** Gateway 已选定审批模型
- **WHEN** 一次工具调用由现有固定权限规则直接放行、拒绝或进入人工确认，没有进入自动模型分类
- **THEN** 该路径的用户可见决策与当前一致，不为了使用审批模型而新增模型请求

### Requirement: 未配置与无效配置具有明确语义

#### Scenario: 未显式选择时保留现有随 run 选模型行为
- **GIVEN** 个人助手配置未显式选择审批模型
- **WHEN** 任意 Agent 的工具调用进入自动审批分类
- **THEN** 该次分类复用触发它的 Agent 或当前 run 模型，不回退到产品默认模型

#### Scenario: 显式选择未登记模型时启动失败
- **GIVEN** Gateway 配置显式选择了不在个人助手模型目录中的审批模型
- **WHEN** 运维者启动 Gateway
- **THEN** Gateway 拒绝启动，明确指出审批模型未登记，且不静默改用其他模型

### Requirement: Coding CLI 的审批选模型行为保持不变

#### Scenario: Coding CLI 不采用个人助手的审批模型选择
- **GIVEN** 个人助手 Gateway 已显式选定审批模型 C
- **WHEN** Coding CLI 中的工具调用进入审批分类
- **THEN** Coding CLI 继续按变更前的规则选择分类模型，不使用个人助手的选定值

## 范围与非目标

- 在范围：个人助手 Gateway 在现有本地运行配置和 LLM 模型目录中支持显式选择一个审批模型；选定后统一用于所有个人助手 Agent 的自动工具审批分类；未选定时保留现有行为；显式选择无效模型时启动报错。
- 非目标：不改变 Coding CLI；不改变 Agent 普通对话或工具后续接的运行模型；不改变现有权限规则、审批结果、人工审批交互或无人值守回退语义；不新增第二份个人助手配置文件、每 Agent 审批模型选择或 IM 配置 UI。
