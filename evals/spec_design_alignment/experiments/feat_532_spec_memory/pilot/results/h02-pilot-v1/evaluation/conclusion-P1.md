# feat-507: 统一审批模型

## 用户场景

一个 Personal Assistant 部署可以同时运行多个 Agent，每个 Agent 或 run 可能选用不同模型。当前自动工具权限分类会复用触发调用的 Agent／run 模型，因此同一套权限规则会分散到不同模型上执行，运维者无法为整个 PA 部署稳定指定一个专用分类模型。

变更后，运维者可以在 Personal Assistant 的 Gateway 配置文件中显式选择一个已登记在 PA 模型目录中的模型，作为该部署统一的自动工具权限分类模型。配置生效后，只要 PA 运行真正进入自动分类链路，无论来源是普通对话、子 Agent、heartbeat、cron 还是后台 fork，分类请求都使用这个统一模型。安全工具快速放行、工具自身规则直接裁决等原本不调用分类模型的路径保持不变。

统一配置只改变“谁来做自动权限分类”。Agent 的正常回复、工具调用获准后的继续执行，以及子 Agent 和无人值守任务的业务推理仍使用各自 run 模型；既有的自动允许、自动拒绝、询问用户、无人值守兜底及失败处理语义均不改变。

运维者也可以不配置统一模型。此时系统完全保持现有路由：每次自动权限分类继续复用触发它的 Agent／run 模型。显式配置必须指向 PA 模型目录中已登记的模型；配置错误应在 Gateway 启动时明确失败。指定模型运行时不可用时，系统不静默切换到 Agent 模型或其他模型，而是沿用现有重试和权限失败处理流程。

## 验收标准

### Requirement: PA 可配置统一的自动工具权限分类模型

#### Scenario: 不同 Agent 的分类请求使用同一个显式配置模型
- **GIVEN** PA 模型目录登记了模型 C，Gateway 配置将 C 选为统一自动权限分类模型，且两个 Agent 分别以模型 A 和模型 B 运行
- **WHEN** 两个 Agent 的工具调用分别进入自动权限分类链路
- **THEN** 运维者可观察到两次分类请求都使用模型 C
- **AND** 两个 Agent 的普通回复及工具调用后的继续执行仍分别使用模型 A 和模型 B

#### Scenario: 未配置时保持现有按 run 复用模型的行为
- **GIVEN** Gateway 未配置统一自动权限分类模型，两个 Agent 分别以模型 A 和模型 B 运行
- **WHEN** 两个 Agent 的工具调用分别进入自动权限分类链路
- **THEN** 运维者可观察到分类请求分别使用模型 A 和模型 B，而不是统一改用 PA 全局默认模型

### Requirement: 统一模型覆盖 PA 中所有实际进入自动分类链路的来源

#### Scenario: 有人值守与无人值守来源统一使用配置模型
- **GIVEN** Gateway 已配置统一自动权限分类模型
- **WHEN** 普通对话、子 Agent、heartbeat、cron 或后台 fork 中的工具调用实际进入自动权限分类链路
- **THEN** 对应分类请求均使用配置的统一模型
- **AND** 各来源原有的权限策略、无人值守兜底和用户交互行为保持不变

#### Scenario: 原本无需自动分类的工具调用不新增分类请求
- **GIVEN** Gateway 已配置统一自动权限分类模型
- **WHEN** 某次工具调用按既有安全快速路径放行，或已被工具自身权限规则直接裁决
- **THEN** 该调用仍不产生自动权限分类请求

### Requirement: 显式配置错误或模型不可用时不静默换模型

#### Scenario: 配置模型不在 PA 模型目录中
- **GIVEN** Gateway 配置的统一自动权限分类模型未登记在 PA 模型目录中
- **WHEN** 运维者启动 Gateway
- **THEN** Gateway 以明确的配置错误启动失败，并指出所配置模型不可用

#### Scenario: 配置模型在运行时不可用
- **GIVEN** Gateway 已成功启动并显式配置统一自动权限分类模型
- **WHEN** 一次自动权限分类调用该模型失败，且既有重试仍未恢复
- **THEN** 系统进入现有权限分类失败处理流程
- **AND** 不静默改用触发请求的 Agent／run 模型、PA 全局默认模型或目录中的其他模型

### Requirement: Coding CLI 产品行为保持不变

#### Scenario: Coding CLI 的工具权限分类不采用 PA 配置
- **GIVEN** Personal Assistant 配置了统一自动权限分类模型
- **WHEN** 用户在 Coding CLI 中触发工具权限分类
- **THEN** Coding CLI 仍按变更前的模型选择与权限行为运行，不读取或采用 PA 的统一模型配置

## 范围与非目标

- 在范围：Personal Assistant 的 Gateway 配置文件可显式选择一个部署级统一自动工具权限分类模型。
- 在范围：PA 普通对话、子 Agent、heartbeat、cron 和后台 fork 中实际进入自动分类链路的调用采用统一配置。
- 在范围：配置省略时保持按 Agent／run 模型分类的现有行为。
- 在范围：配置模型目录校验，以及运行时不可用时不静默切换模型。
- 在范围：底层可以提供产品中立的分类模型选择与省略能力，具体形态由设计阶段决定。
- 非目标：改变 Agent 正常回复、工具获准后继续执行或其他业务推理所用的 run 模型。
- 非目标：改变 allow / deny / ask、无人值守兜底、人工审批交互、重试或现有权限失败处理语义。
- 非目标：让原本由安全快速路径或工具自身规则直接裁决的调用进入模型分类。
- 非目标：为 Coding CLI 增加统一审批模型配置或改变其现有行为。
- 非目标：在 IM Agent 配置界面提供每 Agent 的审批模型选择；本能力是 PA 部署级统一配置。
