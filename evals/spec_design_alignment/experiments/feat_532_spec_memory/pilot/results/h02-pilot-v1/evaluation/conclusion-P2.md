# feat-507: 统一审批模型配置

## Relations

无

## 用户场景

Personal Assistant 运维者可以在 Gateway 的本地配置文件中选定一个专用的自动工具权限分类模型。配置生效后，无论 IM 中的 Agent 各自使用什么对话模型，也无论工具调用来自用户聊天、heartbeat、cron 还是派生的 subagent，只要该调用进入自动权限分类，就统一交给这个专用模型判断。这使审批结果不再随 Agent 自身模型切换而漂移，也便于运维者独立选择审批所需的稳定性、速度与成本。

这个专用模型只负责自动工具权限分类。Agent 的普通请求、工具执行完成后的续跑和其他对话仍使用当前 run 模型。安全工具直接放行、工具自有规则直接允许或拒绝、用户确认等无需自动分类的既有路径也不会因专用模型而改变。

该设置是可选的。完全省略、写为 YAML `null` 或只含空白字符时，Gateway 按现有行为让每次权限分类复用触发它的 Agent / run 模型。运维者一旦填写非空模型名，该模型必须已登记在同一 Gateway 的 PA 模型目录中；否则 Gateway 以明确配置错误拒绝启动，不会悄然回退到 Agent / run 模型。非字符串值同样是无效配置。

如果已配置的专用模型在运行时超时、不可用或返回无法解析的结果，工具权限流程继续按现有的安全失败语义转为询问用户或无人值守回退，不会换用 Agent / run 模型再做一次分类。

## 验收标准

### Requirement: PA 可使用专用模型统一自动工具权限分类

#### Scenario: 不同 Agent 的自动权限分类统一使用专用模型
- **GIVEN** Gateway 已从 PA 模型目录中选定专用审批模型 C，且两个 Agent 分别使用对话模型 A 和 B
- **WHEN** 两个 Agent 的工具调用分别进入自动权限分类
- **THEN** 运维者可观察到两次分类均由模型 C 处理，不因 Agent 使用 A 或 B 而切换

#### Scenario: 全部 PA 运行来源共享专用分类模型
- **GIVEN** Gateway 已配置专用审批模型
- **WHEN** 用户聊天、heartbeat、cron 或其派生 subagent 的工具调用进入自动权限分类
- **THEN** 这些分类均使用已配置的专用模型

### Requirement: 专用审批模型不改变分类以外的运行模型和权限路径

#### Scenario: 普通请求和工具后续跑保持 run 模型
- **GIVEN** Agent 使用 run 模型 A，Gateway 的专用审批模型为 C
- **WHEN** Agent 回复用户、调用一个需自动分类的工具，并在工具结束后继续回复
- **THEN** 运维者可观察到只有自动权限分类使用 C，普通请求和工具后续跑仍使用 A

#### Scenario: 无需自动分类的工具路径保持不变
- **GIVEN** Gateway 已配置专用审批模型
- **WHEN** 工具调用按既有规则直接放行、直接拒绝或进入用户确认，未进入自动权限分类
- **THEN** 该调用的放行、拒绝或询问体验与配置专用模型前一致
- **AND** 专用审批模型不会因此被调用

### Requirement: 省略专用模型时保留现有行为

#### Scenario: 配置文件未包含专用审批模型
- **WHEN** Gateway 在完全省略专用审批模型设置的情况下启动，工具调用进入自动权限分类
- **THEN** 该次分类继续复用触发它的 Agent / run 模型

#### Scenario: 空值按未配置处理
- **WHEN** 专用审批模型设置为 YAML `null` 或空白字符串
- **THEN** Gateway 正常启动，自动权限分类保持现有的 Agent / run 模型行为

### Requirement: 专用审批模型配置可校验且不静默回退

#### Scenario: 选定 PA 模型目录中已登记的模型
- **GIVEN** 专用审批模型名已登记在同一 Gateway 的 PA 模型目录中
- **WHEN** 运维者保存配置并启动或重启 Gateway
- **THEN** Gateway 正常启动，后续自动权限分类使用该模型

#### Scenario: 选定未登记模型
- **WHEN** 运维者填写一个不在 PA 模型目录中的非空专用审批模型名并启动 Gateway
- **THEN** Gateway 以能指向该设置和模型名的配置错误拒绝启动
- **AND** Gateway 不会静默改用 Agent / run 模型

#### Scenario: 专用模型设置为非字符串
- **WHEN** 运维者把专用审批模型设置为非字符串值并启动 Gateway
- **THEN** Gateway 以能指向该设置的配置错误拒绝启动

#### Scenario: 已配置的专用模型在运行时不可用
- **GIVEN** Gateway 已成功配置专用审批模型
- **WHEN** 该模型在自动权限分类时超时、调用失败或返回无法解析的结果
- **THEN** 工具权限流程按现有安全失败语义询问用户或执行无人值守回退
- **AND** 不会改用 Agent / run 模型重做分类

### Requirement: Coding CLI 权限分类保持不变

#### Scenario: Coding CLI 的工具调用进入自动权限分类
- **GIVEN** PA Gateway 已配置专用审批模型
- **WHEN** Coding CLI 中的工具调用进入自动权限分类
- **THEN** Coding CLI 继续复用当前 Agent / run 模型，不使用 PA Gateway 的专用模型

## 范围与非目标

- 在范围：Personal Assistant / IM 的 Gateway 本地配置可选指定一个专用自动工具权限分类模型。
- 在范围：用户聊天、heartbeat、cron 和其派生 subagent 中所有真正进入自动权限分类的调用。
- 在范围：省略设置时的向后兼容，以及对非空未登记模型和非字符串值的启动校验。
- 在范围：共享内核提供产品可显式选择或不选择审批分类模型的通用能力。
- 非目标：改变 Coding CLI 的权限分类模型选择。
- 非目标：把专用审批模型用于普通 Agent 请求、工具执行后续跑、上下文压缩或其他非权限分类任务。
- 非目标：改变安全工具白名单、工具自有权限规则、用户询问选项、无人值守回退或现有允许 / 拒绝语义。
- 非目标：在 IM 管理界面提供审批模型选择器或热更新本地 Gateway 的 LLM 目录。
