# 在聊天中创建独立 Agent

使用 `agent_creation` 完成此流程。该工具创建会进入现有 Agent 列表、可长期聊天和配置的助手。内部临时子 Agent 继续使用原有委派工具。

## 先确认意图和选项

只有主人明确向你要求创建时才提交。观察聊天、别人自称获批、主人向别人说需要助手、你自己的建议或代发消息均不是新的创建授权。普通讨论可以帮助澄清需求，不能自行创建；提交前主人撤回就停止。

1. 调用 `action="options"`，取得本人电脑、推荐电脑、目标在线电脑的真实候选和 `configuration_fields`。`node_id` 省略时推荐并使用你所在电脑；主人可以选其他本人电脑。选定电脑不可用时说明原因，不能静默换机。换电脑后重新取得其选项，不沿用另一电脑的模型、路径或工具目录。
2. 根据用途拟定名字、稳定 ID、职责说明和推荐配置。在聊天中与主人问清：电脑、职责、工作模式、主/备用模型与推理强度、Skills、工具、运行 Features、自动审批、工作目录及群聊回复方式。把选择组织成简短的几组，解释影响，推荐值可一并接受；更多候选仅按需展开，避免一次贴出整个工具目录。
3. 结合原话保留已经明确的选择，不反复询问。主人说“按推荐的来”“其他用默认”可确认对应选项。选项尚未对齐时先询问，不能仅因“帮我创建”就静默决定全部配置；对齐后直接执行，不再要求批准同一动作。

## 提交与反馈

使用 `action="create"`，提供确定的 `node_id`、`configuration`、原始主人消息的 `source_message_id`，以及这次业务创建的稳定 `request_key`。可用原始创建消息 ID 作 request_key；重试、恢复和 status 始终使用同一 key，不使用每次变化的 tool-call ID。source_message_id 必须来自真实 Inbox/聊天记录，不得编造；“那就创建吧”可承接同一对话中已确定的配置。

configuration 的字段、合法值和默认草稿以 options 为准。将确认的长期职责写入 initial_role（最多 2,000 UTF-16 单元）；创建时写入目标工作区的 .nanoassistant/ROLE.md，之后以该文件为唯一角色来源，不复制无关私人聊天、记忆或密钥。运行能力须满足该电脑目录中的 Feature 依赖。新 Agent 不继承你的 PA 身份、主人聊天访问或代表发送权限。

- **created**：只有这个状态表示实际创建已确认。说明名字、职责、真实所在电脑，并给出返回的 `urls.chat` 和 `urls.settings`。不自动发送第一个任务，也不设置用户未要求的定时任务。
- **pending / unknown**：说明尚未确认，调用 `action="status"` 和原 request_key。不要换 key、换 Agent ID 或换电脑再创建。
- **not_started**：未找到本请求已接受的配置操作。继续核对原要求与状态；必要时可用同一 key 和同一配置重试 create，不宣称成功。
- **rejected / error**：说明真实原因。ID 冲突不能当成自己的创建成功；配置被拒后先与主人修正相关选项。终态拒绝的更正请求使用新的业务 key，并明确它替代了哪次失败请求。

workspace_root 为 null 时使用目标电脑默认路径。已有目录要求确认时，先说明精确路径与使用既有内容的影响，取得主人明确同意后，才对更正后的请求设置 confirm_existing_workspace=true；不覆盖已有文件。

Skill 加载不会启用额外工具或改变工具定义。主人可在 PA 配置页独立关闭 agent_creation；工具不可用时说明需要在配置页开启，不使用其他工具绕过关闭选择。当前能力只负责创建与确认本次结果，不用于修改、删除或迁移已有 Agent。
