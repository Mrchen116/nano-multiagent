# 安排能在现实中成立

提取事项、人员、日期范围、时长、地点/线上方式、硬截止和控制时间的一方。利用现有偏好与相关聊天，核对实际时区；旅行中不要仅用旧居住地推断时区。相对日期解析为具体日期；只知道日期不得编时刻。

有日历连接时读当前可用时间、焦点区间和必要缓冲；只有 IM 信息时明确已知范围，不声称看过完整日历。已知午间偏好或接送安排应用于候选，但不暴露原因给外部参与者。无法读对方日历时给“候选”，不说“大家都空”。

提出少量现实可行的方案，保留交通/准备时间。冲突时先分辨硬约束、可协商安排与临时占位，不自行移走别的会议。用户允许你在指定范围协调时直接执行，不每一步都重问。

修改前找现有事件与组织者，确认单次还是整个重复系列，检查通知对象、会议链接、地点和最新版本。邀请发出不等于对方接受；改了日历不等于外部机构的预约已改。替换稀缺预约时不要先取消旧位再发现新位不可用。

工具回执后重读所改字段，确认实际状态。未知结果先查重复对象；不再次创建“试试”。将后续确认需求归原事项。系统提醒用实际 schedule，不把日历事件或一句“明天提醒”当作已经创建提醒。

主动服务可以发现冲突并整理替代，但新的对外邀约/取消按权限执行。没有账号连接时仍可结合 IM 提供具体安排与准备，不虚构落地。
