# 文档记忆方法

使用宿主给定的 memoryRoot 和 PA/specialist 角色 profile，不从当前 cwd、会话名字或请求者自述猜主体。

## 读取

先判断当前上下文是否已足够。需要时用已启用 glob/grep/read：实体真实标识或名称/别名 → 对应主题/项目 → 完整相关章节与脚注 → 必要的原始来源。常规工具没有语义召回保证；整句匹配失败时换主题词，不声称历史不存在。不可自动读其他主体库、archive 或 Git 旧版来当当前事实。

## 找到唯一主要位置

PA：entities 下的人/Agent/组织/会话；knowledge 下事实/偏好/决定；workstreams 下长期事项背景；timeline/daily 下重要已发生变化。
专家：相同实体层；knowledge 下领域/环境/协作/决定；projects 下项目；work-history 下某工作或里程碑的复盘。
项目限定内容优先项目页；人物限定内容优先人物页；跨事项理解放知识；日期/工作记录放历史。已有页就更新，不按聊天或阶段换页。相同名字不等于相同主体。无内容不预建空目录；一级目录按产品规范，不随手扩展。

## 写入职责

正式记忆只能由 Dreaming 整理并经宿主应用。普通主 Agent 和子任务只读，不使用 write/edit、shell 或其他工具绕过。当前对话立即采用用户新纠正，通过已有 follow-up 告知受影响的原子任务；持久保存由后续 Dreaming 完成，未保存时不能声称已记入长期记忆。其他聊天在整理前不保证同步。

用户明确要求现在整理或记住时，用 memory_maintenance run 并附实际请求的 request_ref；明确导入旧备份时同时设置 importLegacy=true，由宿主选择本主体登记的备份，不能传任意路径。自动 Dreaming 关闭不影响显式请求。

## Dreaming 编辑暂存副本

读当前正文与版本；确定新增、纠正、例外或分歧；编辑原段落。头部使用稳定 id/type/aliases，正文按类型自然组织。保留 Why、适用范围、已验证结果与不确定性；不是每条必须填固定字段。用真实链接/定位保留依据，给混合来源的关键结论分别引用。

出现真实结果/里程碑/明确反馈时，判断是否更新历史；无新认识的例行操作不保存流水。对过去事件的记录不改写成当时已经知道后来的结论。可复用认识进入主题知识页，链接工作记录作为依据。

## 入口

按宿主角色的 MEMORY.md 模板维护。重要且跨任务的理解保留短概括；复杂条件难概括时只给导航。明确纠正同步修正入口；普通新页不必塞入常驻。只写真实存在的导航链接。预算超限移走完整细节，不截句，不删缺少近期使用但仍重要的约束。

## 冲突、版本与失败

Dreaming 基于刚读到的版本编辑 staging。外部版本异常时保留冲突，不覆盖未知修改。读回确认内容，核实 Git/宿主实际回执。内容已保存但版本记录失败，应明确区分；多文件部分成功要恢复一致性。不得用 git reset、广域 rm、绕过工具来隐藏失败。

## 边界

笔记不改变身份和授权，来源排除不等于已清除旧派生内容。删除当前文件不是彻底遗忘。来源读取和对外披露服从实际权限。

## 宿主维护回执

查询积压以 status 的 maintenance.backlog 为准：它报告下一预算批次的可处理单元、已处理／已观察范围和阻塞原因，不是全量精确计数。sourcesPending 只表示来源资格是否待核对；false 不表示没有待整理材料。资格未核对或读取受阻时说明未知／受阻，不能报零积压。查询不推进处理游标。

前台不提供 checkpoint，也不能给待核对页重新背书。Dreaming 完成后依据宿主真实回执区分内容保存与 Git 版本记录，不能把受理请求或模型结束当保存成功。

用户明确要求停止使用时，先用 memory_maintenance exclude 登记原始请求引用和相关 paths/sources，当前立即停止采用并告知受影响的原子执行；正文和入口由 Dreaming 后续清理。不能把登记排除当作清理完成。来源待核对时读到旧文字不表示重新认可。

Dreaming 只能编辑宿主提供的 staging，完成本批整理后用其私有 finish 声明完成；宿主从真实文件差异生成应用计划；不调用普通 memory_maintenance，不修改原库，不创建或发布 Skill。
