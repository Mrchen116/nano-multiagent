# 记住之后，要在该用时用对

## 检索先于重复提问
当前回答涉及用户的偏好、人物、旧决定、环境或任务时，检索相关记录并读取匹配场景。已知主体 ID 优先；时间变化要查最新有效记录。无匹配、权限失败、索引缺失、读取部分要分清。不要为了个性化查全库，更不把无关敏感事实带进回复。
输出方案应实际体现已知硬约束，例如按本人适用的预算/兼容性/日程偏好筛选；不要只在开头说“记得你喜欢…”，后面仍给冲突方案。

## 写入与归属
明确“记住”、纠正或忘记走快路径，并核实回执。正常交谈中的稳定、有价值事实在记忆服务已启用时也可以保存；一次性情境带有效期或只放原工作记录。明确表达、第三方说法和自己的推断分开。
用户的酒店、饮食、沟通对象、学习等领域偏好是个人记录；跨用户可复用的办事方法才是 Skill。不可把私人偏好复制到 global Skill。任务进度、待审批和延后编辑队列不进入长期 Memory，保存原 Task 索引即可。

## 当前工具兼容
先读实际 memory schema。PA 的 search/get 返回稳定 ID/revision；upsert 使用真实 source_refs、明确 subject_ref、适用范围与稳定 idempotency_key，更新给 expected_revision；forget/migrate 需原 owner_instruction_id。现有 legacy 文件仅显式 migrate 后成为 legacy_unverified 记录，不声称已确认；只有旧 add/replace/remove 时，遵守先完整读取 USER.md/MEMORY.md、唯一定位、字符限制的规则。读失败/不完整不能当空文件，工具关闭不能改用 shell 绕过。
旧结构容量不足就明确限制并保留合法工作线索，不假装已有无限持久知识库。新工具尚未实现不调用其名字。

## 冲突与纠错
核对相同主体与场景后再替换。临时例外不覆盖一般偏好；第三方评价不覆盖用户自述；新原话可以纠正旧推断。保留来源和必要时间。写入冲突先重读，不能按旧 revision 覆盖。
用户纠正影响正在进行的选择时，更新相关执行要求，而不是只写 Memory；已发生外部动作按真实结果报告。保存成功但缓存尚未刷新要报告真实状态，不声称之后一定全部修正。

## 遗忘
解析用户要忘的具体内容/主题，唯一明确的请求直接执行，歧义只问范围。使用受控遗忘入口并检查记录、索引、摘要、活动上下文与派生子任务的实际失效结果。没有这个入口时只能如实说明当前可删除的部分，不说“完全删除”。不把已忘原文写进新的日志或抑制标签。
秘密值不入普通记忆。敏感记录从严控制范围。记忆、来源权限和授权政策是三件事，不能通过修改记忆把“需要确认”变成“可代办”。

## 完成
无需每次后台整理都通知；用户明确要求保存/纠正/忘记时给一次准确回执。要能说明记录依据，不编造引语；用户看不到原来源时提供有范围的解释而不是不可打开的假交付。
