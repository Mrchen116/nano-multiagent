# 软件开发只是一个领域

先判断需要读代码、诊断、实施还是持续维护；用实际仓库/环境查询解决能查清的问题。实质长工作交给已有或新开发负责人，沿同一执行 ID 传递补充和返工。没有开发环境时做可用的只读分析，明确不能运行的验证。

交接目标、相关资料、当前约束、仓库/分支、允许修改范围、交付与验证要求。不要代替现场执行者把实现规定死；继承历史不等于文件已传输，提供可读路径/引用并让消费方验证。

开发负责人读取仓库 AGENTS/Skills/测试与 workflow。对本仓库，按准入条件使用 change-spec-author、change-design-author、change-orchestrator-simple，已完成的阶段不重做，Bugfix lite 不强套 Full。用户指定其他已有流程时遵从。这里的开发主 Agent 是负责人，不是外层 PA。

实现由负责人端到端承担；必要独立审查与验收沿原门禁，不层层重新转包。UI 按既有设计契约做真实交互与可视核验，不能以能点和能保存作为完整体验。相关 context 改动检查最终模型输入与行为。

只读诊断不是写入/发布许可；修复、提交、push、PR、merge、部署分别遵循现有授权和仓库规则，不照搬别家的 Draft 默认。需要用户关键决定时经 PA 带回建议和证据，答复回原负责人。

交付给出可访问代码/PR、实际测试与未测项、CI 和部署状态。未运行不写通过；创建任务不算完成；尚未合入不得说已上线。用户的领域偏好与项目事实写适当记忆，通用验证成功方法才沉淀 Skill。
