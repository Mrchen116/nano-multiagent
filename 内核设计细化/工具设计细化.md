# 工具设计细化（给 LLM 的 description + 参数设计）

## read
- Source: `/Users/czj/Repos/opencode-hub/pi-mono/packages/coding-agent/src/core/tools/read.ts`
- Description（原文）:
```text
Read the contents of a file. Supports text files and images (jpg, png, gif, webp). Images are sent as attachments. For text files, output is truncated to ${DEFAULT_MAX_LINES} lines or ${DEFAULT_MAX_BYTES / 1024}KB (whichever is hit first). Use offset/limit for large files. When you need the full file, continue with offset until complete.
```
- Parameters:
  - `path` (string, required): Path to the file to read (relative or absolute)
  - `offset` (number, optional): Line number to start reading from (1-indexed)
  - `limit` (number, optional): Maximum number of lines to read
- 功能逻辑（开发指导）:
  - 路径先解析到工作目录，读取前做可读性检查。
  - 自动识别图片类型；图片返回 `text + image` 两段内容。
  - 默认支持图片自动缩放（最大约 2000x2000），并在文本里附尺寸提示。
  - 文本读取支持 `offset/limit` 分段拉取；`offset` 越界直接报错。
  - 文本输出统一做行数+字节双重截断，并在返回文本追加“下一次 offset 提示”。
  - 极端长单行（超字节阈值）不直接返回整行，返回引导语让模型改用 `bash/sed` 分段读取。
  - 支持 abort 中断；中断后返回 `Operation aborted`。
- 返回给 Agent 的字符串（`content[].text`）:
  - 文本文件：`content = [{ type: "text", text: outputText }]`，其中 `outputText` 形如（末尾提示按情况出现）：
    ```text
    <文件内容（可能被截断）>

    [Showing lines {start}-{end} of {total}. Use offset={nextOffset} to continue.]
    ```
    - 若触发字节截断：提示会变为：
      ```text
      [Showing lines {start}-{end} of {total} (50.0KB limit). Use offset={nextOffset} to continue.]
      ```
    - 若用户传了 `limit` 且未截断、但文件还有剩余：会追加：
      ```text
      [{remaining} more lines in file. Use offset={nextOffset} to continue.]
      ```
    - 若 `offset` 指向的“首行本身”超过 50KB：直接返回单行引导（无文件正文）：
      ```text
      [Line {lineNo} is {size}, exceeds 50.0KB limit. Use bash: sed -n '{lineNo}p' {path} | head -c 51200]
      ```
  - 图片文件：`content = [{ type: "text", text: textNote }, { type: "image", data: <base64>, mimeType: <mime> }]`，其中 `textNote` 形如：
    ```text
    Read image file [image/png]
    [Image: original {ow}x{oh}, displayed at {w}x{h}. Multiply coordinates by {scale} to map to original image.]
    ```
    第二行仅在发生自动缩放（resize）时出现。

## bash
- Source: `/Users/czj/Repos/opencode-hub/pi-mono/packages/coding-agent/src/core/tools/bash.ts`
- Description（原文）:
```text
Execute a bash command in the current working directory. Returns stdout and stderr. Output is truncated to last ${DEFAULT_MAX_LINES} lines or ${DEFAULT_MAX_BYTES / 1024}KB (whichever is hit first). If truncated, full output is saved to a temp file. Optionally provide a timeout in seconds.
```
- Parameters:
  - `command` (string, required): Bash command to execute
  - `timeout` (number, optional): Timeout in seconds (optional, no default timeout)
- 功能逻辑（开发指导）:
  - 命令在指定 cwd 执行，可注入 `commandPrefix` 和 `spawnHook` 调整执行上下文。
  - 合并 stdout/stderr 流，维护滚动缓冲；输出过大时切换到临时文件持久化全量日志。
  - 对外主输出采用“尾部截断”策略，重点保留最新日志。
  - 若提供 `onUpdate`，会持续推送当前截断后的增量文本。
  - 非 0 退出码作为错误返回，并附加退出码说明。
  - 超时/手动中断分别转成明确错误文案（`timed out` / `aborted`）。
  - 截断时在文本里附“显示范围 + fullOutputPath”提示，便于后续追日志。
- 返回给 Agent 的字符串（成功时 `content[0].text`）:
  - 成功时：返回 `stdout+stderr` 合并后的文本（可能为空，空则为 `(no output)`）；若发生截断，会在末尾追加可执行提示：
    ```text
    <stdout+stderr 的尾部输出（可能被截断）>

    [Showing lines {start}-{end} of {total}. Full output: {tempFilePath}]
    ```
    - 若触发行数截断：如上（无 KB 说明）。
    - 若触发字节截断：提示会变为：
      ```text
      [Showing lines {start}-{end} of {total} (50.0KB limit). Full output: {tempFilePath}]
      ```
    - 极端情况：若“最后一行本身”超过 50KB，会追加：
      ```text
      [Showing last {shownBytes} of line {end} (line is {lineSize}). Full output: {tempFilePath}]
      ```
  - 失败时（以 tool error 形式抛出，错误 message 就是下面这串文本）：
    - 非 0 退出码：在成功输出末尾再追加一段并抛错：
      ```text
      Command exited with code {exitCode}
      ```
    - 手动中断：在已有输出后追加 `Command aborted` 并抛错。
    - 超时：在已有输出后追加 `Command timed out after {timeoutSecs} seconds` 并抛错。

## edit
- Source: `/Users/czj/Repos/opencode-hub/pi-mono/packages/coding-agent/src/core/tools/edit.ts`
- Description（原文）:
```text
Edit a file by replacing exact text. The oldText must match exactly (including whitespace). Use this for precise, surgical edits.
```
- Parameters:
  - `path` (string, required): Path to the file to edit (relative or absolute)
  - `oldText` (string, required): Exact text to find and replace (must match exactly)
  - `newText` (string, required): New text to replace the old text with
- 功能逻辑（开发指导）:
  - 路径解析后先校验文件读写权限；文件不存在立即失败。
  - 读入内容后处理 BOM 与换行符（统一到 LF 进行匹配，落盘时恢复原换行风格）。
  - 匹配策略是“先精确、再 fuzzy”；找不到时返回明确错误。
  - 若匹配结果不唯一（出现多处），强制失败，要求调用方补充上下文。
  - 执行替换后若内容未变化，也视为失败（避免无效编辑）。
  - 成功后返回统一 diff 和 `firstChangedLine`，便于 UI 高亮定位。
  - 支持 abort 中断。
- 返回给 Agent 的字符串（成功时 `content[0].text`）:
  ```text
  Successfully replaced text in {path}.
  ```
  统一 diff / `firstChangedLine` 不在字符串里，而是在 tool result 的 `details.diff` / `details.firstChangedLine`。

## write
- Source: `/Users/czj/Repos/opencode-hub/pi-mono/packages/coding-agent/src/core/tools/write.ts`
- Description（原文）:
```text
Write content to a file. Creates the file if it doesn't exist, overwrites if it does. Automatically creates parent directories.
```
- Parameters:
  - `path` (string, required): Path to the file to write (relative or absolute)
  - `content` (string, required): Content to write to the file
- 功能逻辑（开发指导）:
  - 路径解析到 cwd 后，先递归创建父目录，再执行写入。
  - 写入行为是“存在即覆盖，不存在则创建”，不做 merge。
  - 成功返回写入字节数文本（`Successfully wrote ... bytes ...`）。
  - 支持 abort 中断；中断时停止后续处理并返回错误。
- 返回给 Agent 的字符串（成功时 `content[0].text`）:
  ```text
  Successfully wrote {byteCount} bytes to {path}
  ```

## task
- Source: `/Users/czj/Repos/opencode-hub/oh-my-opencode/src/tools/delegate-task/tools.ts` (`delegate_task`，重命名为 `task`)
- Description（原文）:
```text
Spawn agent task with category-based or direct agent selection.

MUTUALLY EXCLUSIVE: Provide EITHER category OR subagent_type, not both (unless continuing a session).

- load_skills: ALWAYS REQUIRED. Pass at least one skill name (e.g., ["playwright"], ["git-master", "frontend-ui-ux"]).
- category: Use predefined category → Spawns Sisyphus-Junior with category config
  Available categories:
${categoryList}
- subagent_type: Use specific agent directly (e.g., "oracle", "explore")
- run_in_background: true=async (returns task_id), false=sync (waits for result). Default: false. Use background=true ONLY for parallel exploration with 5+ independent queries.
- session_id: Existing Task session to continue (from previous task output). Continues agent with FULL CONTEXT PRESERVED - saves tokens, maintains continuity.
- command: The command that triggered this task (optional, for slash command tracking).

**WHEN TO USE session_id:**
- Task failed/incomplete → session_id with "fix: [specific issue]"
- Need follow-up on previous result → session_id with additional question
- Multi-turn conversation with same agent → always session_id instead of new task

Prompts MUST be in English.
```
- Parameters:
  - `load_skills` (string[], required): Skill names to inject. REQUIRED - pass [] if no skills needed, but IT IS HIGHLY RECOMMENDED to pass proper skills like ["playwright"], ["git-master"] for best results.
  - `description` (string, required): Short task description (3-5 words)
  - `prompt` (string, required): Full detailed prompt for the agent
  - `run_in_background` (boolean, required): true=async (returns task_id), false=sync (waits). Default: false
  - `category` (string, optional): Category (e.g., ${categoryExamples}). Mutually exclusive with subagent_type.
  - `subagent_type` (string, optional): Agent name (e.g., 'oracle', 'explore'). Mutually exclusive with category.
  - `session_id` (string, optional): Existing Task session to continue
  - `command` (string, optional): The command that triggered this task
- 功能逻辑（开发指导）:
  - 入参硬校验：`run_in_background`、`load_skills` 必填，`load_skills=null` 明确禁止。
  - continuation 分支优先：提供 `session_id` 时，直接走“续跑”逻辑（同步/异步两条路径）。
  - 新任务分支：`category` 与 `subagent_type` 二选一；同时给或都不给都报错。
  - 任务前会解析并注入技能内容，解析失败直接返回错误。
  - `category` 模式会做类别到 agent/model 的解析，并支持不稳定模型时强制后台执行分支。
  - `subagent_type` 模式直接按指定 agent 执行（仍保留模型解析结果）。
  - 最终根据 `run_in_background` 决定返回 task_id（异步）或直接返回结果（同步）。
- 返回给 Agent 的字符串（`task(...)` 的直接返回值）:
  - `run_in_background=true`（新任务，异步）：
    ```text
    Background task launched.

    Task ID: {taskId}
    Description: {description}
    Agent: {agent}{ (category: {category})? }
    Status: {status}

    System notifies on completion. Use `background_output` with task_id="{taskId}" to check.

    <task_metadata>
    session_id: {sessionId | pending}
    </task_metadata>
    ```
  - `run_in_background=true` + `session_id=...`（续跑，异步）：
    ```text
    Background task continued.

    Task ID: {taskId}
    Description: {description}
    Agent: {agent}
    Status: {status}

    Agent continues with full previous context preserved.
    Use `background_output` with task_id="{taskId}" to check progress.

    <task_metadata>
    session_id: {sessionId}
    subagent: {agent}
    </task_metadata>
    ```
    `subagent: ...` 这一行仅在能解析出 agent 时出现。
  - `run_in_background=false`（新任务，同步等待）：
    ```text
    Task completed in {duration}.

    Agent: {agent}{ (category: {category})? }

    ---

    {agentOutputText}

    <task_metadata>
    session_id: {sessionId}
    </task_metadata>
    ```
    当子 agent 没有任何 text 输出时，`{agentOutputText}` 会是 `(No text output)`。
  - `run_in_background=false` + `session_id=...`（续跑，同步等待）：
    ```text
    Task continued and completed in {duration}.

    ---

    {agentOutputText}

    <task_metadata>
    session_id: {sessionId}
    subagent: {resumeAgent}
    </task_metadata>
    ```
    `subagent: ...` 这一行仅在能从 session 历史中解析出续跑 agent 时出现。
  - 失败时：直接返回错误字符串（不一定抛异常），常见格式为：
    ```text
    {Operation} failed

    **Error**: {message}
    ...
    ```
    其中可能带 `**Arguments**:` 与（最多 10 行的）`**Stack Trace**:` 代码块，便于定位问题。
